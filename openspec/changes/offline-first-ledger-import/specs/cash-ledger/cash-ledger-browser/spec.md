## MODIFIED Requirements

### Requirement: 收支账本展示关系处理后的投影

系统 MUST 让每条活动现金流水恰好归属一个当前投影；没有已确认关系的正式流水独立显示，同笔支付只展示一次，退款抵扣原消费，部分退款和部分平台退回只抵扣剩余金额。列表、分析及金额汇总 MUST 使用当前投影；内部转账显示但不计入外部收入、支出和月度汇总。全额退款及全额平台退回 MUST 在导入预览展示净额 0；收支账本保留该投影和详情证据，是否出现在列表由“隐藏0元流水”筛选决定，关闭该筛选时必须可见，且不另算退款收入；余额校准的既有业务隐藏规则保留。主页默认展示正式及草稿，待处理项显示具体原因，普通已确认项不显示状态标签；确认状态由草稿、当前问题及未确认关系派生，不能独立编辑。草稿排除全部统计；未确认关系不合并，正式端点分别统计。其他业务隐藏项有活动待处理事项时优先展示，不越过权限、工作区、逻辑删除及显式筛选边界。列表及其成员、关系、选项、待确认计数和金额汇总 MUST 使用同一读取快照；每项返回该快照的发布版本。分页 MUST 使用稳定排序位置及投影标识，未知日期不伪造为发生日期，发布版本变化要求重载。端侧 MUST 只为当前已登录成员的选定工作区派生和展示投影。收支投影 MUST 由端侧基于单一已同步版本的本地规范事实及共享规则派生，MUST NOT 依赖服务端返回物化投影；在线与离线使用相同规则。

#### Scenario: 浏览同笔支付

- **WHEN** 两条正式现金流水通过已确认 `payment_mirror` 表示同一笔消费
- **THEN** 收支账本 MUST 只显示一个消费结果，并在详情中保留相关记录

#### Scenario: 浏览银证转账

- **WHEN** 当前结果对应已确认现金—投资资金调拨关系
- **THEN** 列表和详情 MUST 显示银证转账及现金与投资账户两端金额，不计入外部收支

#### Scenario: 浏览已确认平台退回

- **WHEN** 平台退回与原始出账通过已确认 `refund_offset` 形成全额冲销
- **THEN** 预览 MUST 展示净额 0 的一项；收支账本保留净额 0 的投影和两条关联流水及来源证据，是否显示该行由“隐藏0元流水”筛选决定，且不把退回另算收入

#### Scenario: 待确认回主页

- **WHEN** 导入保存草稿和未确认关系后返回主页
- **THEN** 用户可以找到并打开相关项补充，无独立关系管理产品

#### Scenario: 全额退款按筛选展示

- **WHEN** 消费被已确认退款全额抵扣
- **THEN** 预览 MUST 展示净额 0；收支账本 MUST 保留该净额 0 项，筛选开启时默认隐藏、筛选关闭时显示；没有当前问题时为已确认，有问题时为待确认，解决后状态随当前问题更新；用户明确的金额、日期和状态筛选仍生效

#### Scenario: 旧显示结果升级

- **WHEN** 升级前当前全额退款结果被标为隐藏
- **THEN** 系统 MUST 更新相关派生显示标志及发布版本，旧游标失效，原始流水、关系、净额和统计资格保持原值，其他业务隐藏规则不变

#### Scenario: 未知日期草稿翻页

- **WHEN** 草稿没有发生日期且与其他草稿创建时间相同
- **THEN** 发生日期仍为空，按创建时间及投影标识稳定翻页，不遗漏或重复；用户明确的日期筛选仍排除未知日期

#### Scenario: 翻页期间账本变化

- **WHEN** 客户端使用旧发布版本的游标翻页
- **THEN** 端侧返回可识别的 `read_snapshot_changed`，不能混合新旧流水及成员

#### Scenario: 离线浏览与在线一致

- **WHEN** 使用者在离线状态下浏览已缓存账本
- **THEN** 展示的投影、金额与月份汇总 MUST 与同一事实及规则版本的在线派生结果一致

### Requirement: 投影发布和分页保持一致

收支投影 MUST 以工作区账本版本为边界保持一致：端侧 MUST 基于单一已同步版本派生投影，MUST NOT 在同一视图混用不同版本的记录。分页游标必须绑定账本版本、规则版本、排序键和筛选条件；账本版本、规则版本或筛选变化后，旧游标必须明确失效。

#### Scenario: 连续翻页

- **WHEN** 账本版本、规则版本和筛选条件均保持不变
- **THEN** 连续翻页 MUST 不重复或遗漏同一排序范围内的投影条目

#### Scenario: 账本版本更新后继续翻页

- **WHEN** 使用者在账本版本更新后继续提交旧游标
- **THEN** 端侧 MUST 使旧游标失效并从当前版本重新读取，不得沿用旧版本数据

#### Scenario: 规则更新但事实未变

- **WHEN** 本地共享规则版本变化且工作区规范事实未发生写入
- **THEN** 端侧 MUST 重新派生结果并使旧游标失效，MUST NOT 为该派生变化推进服务端 `ledger_seq`

### Requirement: 双后端返回相同浏览合同

PostgreSQL 与 SQLite MUST 对相同工作区账本和关系输入返回等价的快照事实、精确金额、时间值和账本版本；端侧 MUST 基于等价事实与服务端一致的规则确定性派生等价投影、筛选树、证据详情和分页顺序。

#### Scenario: 比较双后端浏览结果

- **WHEN** 两个后端使用相同去标识化账本与关系夹具，端侧分别基于其快照派生
- **THEN** 除内部代理键外，投影、筛选树、证据详情和分页顺序 MUST 等价

### Requirement: 筛选树由当前可见投影生成

端侧 MUST 从当前工作区同一完整事实快照派生的基础可见账本生成经济类型与派生业务标签筛选树。该集合按本规格的基础可见性规则确定，MUST 包含有活动待处理事项而优先可见的项目；MUST NOT 因当前日期、账户、分类、金额、币种、经济类型、业务标签、确认状态、隐藏 0 元等列表筛选或分页而缩小。一级筛选项只包含该全局集合实际存在的经济类型，二级筛选项只出现在所属内部转账类型下；前端不得写死与数据不一致的标签清单。完整收支分类目录仍按收支分类筛选合同提供。

筛选协议 MUST 以 `business_label` 代替 `transfer_subtype`，保留信用还款、换汇、跨境汇款、普通转账及银证转账的筛选能力；业务标签不得参与关系确认校验。

#### Scenario: 当前只有普通内部转账和银证转账

- **WHEN** 当前活动投影不包含换汇或信用账户还款
- **THEN** 筛选树 MUST 只在内部转账下提供普通转账和银证转账业务标签

#### Scenario: 切换一级筛选

- **WHEN** 使用者从内部转账切换到消费
- **THEN** 已选择的内部转账业务标签 MUST 被清除或禁用，不得继续影响消费查询

#### Scenario: 当前筛选不缩小全局类型选项

- **WHEN** 完整基础可见账本包含收入、支出与内部转账，而当前账户或其他列表筛选只匹配支出，或没有匹配结果
- **THEN** 收入、支出与内部转账及其实际存在的业务标签 MUST 仍然可选，MUST NOT 按当前结果或当前页缩小选项

#### Scenario: 全额退款在隐藏零金额时保留类型选项

- **WHEN** 基础可见账本中的全额退款净额为 0，当前“隐藏0元流水”筛选排除了该行
- **THEN** 类型与业务标签选项 MUST 仍按完整基础可见集合生成，MUST NOT 因该行被显式列表筛选排除而消失

## ADDED Requirements

### Requirement: 现金流水发生时间限定为公元1900至2100年

现金流水的非空发生时间 MUST 在转换为 UTC 后位于 `1900-01-01T00:00:00Z`（含）至 `2101-01-01T00:00:00Z`（不含）。录入、导入、编辑和服务端写集校验 MUST 使用同一范围，超限 MUST 按对应入口的无效发生时间合同拒绝，MUST NOT 截断至边界、改为其他日期或静默保存。既有缺少发生时间的草稿资格 MUST 保持。该限制 MUST NOT 扩展到投资事件、系统创建时间、原始账单文本、覆盖证明或浏览筛选日期。

#### Scenario: 首尾日期均可保存

- **WHEN** 现金流水的 UTC 发生时间为 1900 年首日零时或 2100 年末日的合法微秒时刻
- **THEN** 录入、导入和写集校验 MUST 接受该时间范围

#### Scenario: 按转换后的UTC时间判断

- **WHEN** 带偏移的现金发生时间转换到 UTC 后越过 1900 年首日或 2100 年末日
- **THEN** 系统 MUST 按转换后的 UTC 时刻判断是否超限，不得仅检查输入文本的年份

#### Scenario: 绕过端侧也不能写入超限时间

- **WHEN** 请求直接向服务端提交超出范围的现金发生时间
- **THEN** 服务端 MUST 拒绝该写入并保持原子提交边界，不得保存部分结果

### Requirement: 账本关键词按普通文字包含且忽略大小写

端侧账本 MUST 在同一筛选范围内按对方或备注包含关键词返回结果，MUST 忽略大小写，MUST 将 `%`、`_` 与反斜杠等字符作为普通文字而非 SQL 通配符或转义操作。关键词仍沿既有输入合同去除两端空白；空关键词不限制结果。两字段分别匹配，MUST NOT 因拼接对方与备注而生成跨字段命中。该规则只影响账本关键词筛选，MUST NOT 改变导入商户归一或关系匹配。

#### Scenario: 大小写不同的普通关键词

- **WHEN** 对方为 `Cafe`，使用者搜索 `cafe`
- **THEN** 该条目 MUST 命中，且同一关键词出现在备注时也能命中

#### Scenario: 输入实际的百分号下划线与反斜杠

- **WHEN** 使用者搜索 `%`、`_` 或反斜杠
- **THEN** 系统 MUST 仅命中对应字段含该实际字符的条目，MUST NOT 将其解释为任意内容或转义命令

#### Scenario: 对方与备注的边界

- **WHEN** 对方为 `ab`、备注为 `cd`，使用者搜索 `bc`
- **THEN** 该条目 MUST NOT 命中

### Requirement: 金额筛选范围有界且不改变金额

端侧账本的金额下限和上限 MUST 各自为有限十进制，整数部分最多 20 位、小数部分最多 18 位。系统 MUST 按指数展开后的表示检查位数，MUST 在展开前拒绝超限输入并返回 `invalid_filter`，MUST NOT 截断或舍入使其符合范围。整数前导零不增加数值位数；负号和小数点不计入位数，小数尾随零计入小数位数。该限制只适用于金额筛选参数，MUST NOT 降低现金事实、派生金额或全范围汇总的既有精度。

#### Scenario: 完整边界金额保持精确

- **WHEN** 金额筛选使用整数 20 位、小数 18 位的上下限
- **THEN** 系统 MUST 精确执行比较，保留各位数值，不按二进制浮点、截断或舍入处理

#### Scenario: 极端指数在展开前拒绝

- **WHEN** 输入 `1e2147483647`、`1e-2147483647`、21 位整数或 19 位小数
- **THEN** 系统 MUST 在构造展开文本前返回 `invalid_filter`，不得尝试无界内存分配

#### Scenario: 汇总超过筛选输入范围

- **WHEN** 多笔合法记录的合计超过单笔金额或筛选输入的范围
- **THEN** 系统 MUST 继续按原精确累计合同返回完整汇总，不把筛选参数限制应用到统计结果
