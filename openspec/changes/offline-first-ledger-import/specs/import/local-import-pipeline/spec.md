## Purpose

定义账单导入在端侧完成解析、归一化、查重、账户归属、操作计划、候选召回与关系配对，并以完整写集提交给服务端校验落库的行为，确保端侧计算与服务端校验的边界清晰、幂等且可复算。

## ADDED Requirements

### Requirement: 端侧执行导入阶段一至七

端侧 MUST 在本地完成账单解析、行归一化与类型分类、对缓存账本查重、账户归属、操作计划、候选召回与关系配对，并基于本地缓存事实得出预览结论；MUST NOT 依赖服务端执行这些计算。

#### Scenario: 离线完成预览

- **WHEN** 端侧在无网络时导入一份受支持的 CSV 或 XLSX 账单
- **THEN** 端侧 MUST 得出与在线一致的行归一化、查重、账户归属与关系配对预览

#### Scenario: 相同输入确定性

- **WHEN** 相同账单、账户映射与缓存事实重复计算
- **THEN** 端侧 MUST 得出相同的行决策、来源身份与关系结果

### Requirement: 平台原文字段读取局限于来源适配

微信、支付宝等平台专用导入或匹配规则 MUST 优先读取既有标准化映射后的字段，仅在标准化字段缺失时按该来源的明确映射回退读取原始 JSON。通用候选召回与关系配对 MUST 消费标准化结果，MUST NOT 自行探测原始 JSON 的平台字段或依赖数据库隐式类型转换解释编号。

#### Scenario: 标准化编号优先

- **WHEN** 平台记录的标准化交易号或商户单号与原始账单字段同时存在
- **THEN** 平台适配 MUST 使用标准化编号，不得用原文字段覆盖它

#### Scenario: 平台字段缺失时回退

- **WHEN** 平台专用规则需要的标准化编号缺失，且该来源定义了原文字段映射
- **THEN** 来源适配 MAY 从该映射读取原始 JSON 并生成标准化结果
- **AND** 通用匹配逻辑 MUST 仅接收该结果，不读取 JSON

#### Scenario: 通用规则不猜测平台字段

- **WHEN** 通用候选或配对规则处理未提供标准化编号的流水
- **THEN** MUST NOT 通过搜索原始 JSON 的交易号、商户单号等字段补出编号

### Requirement: 端侧提交完整写集

端侧 MUST 以单个原子请求提交完整写集，覆盖本次导入产生的现金流水与组成项、交易关系与候选、entry 与成员、待处理问题、账单账户映射与来源绑定。服务端 MUST 全成功或全失败，MUST NOT 产生部分导入。

#### Scenario: 完整写集一次落库

- **WHEN** 端侧提交一份多行账单的写集
- **THEN** 服务端 MUST 在同一事务内写入全部对象，任一失败 MUST 整体回滚

### Requirement: 服务端只校验不重算

服务端 MUST 校验写集的结构与业务不变量，包括权限、账户资格、修订号、金额与币种精度、引用完整性、关系图合法性以及工作区隔离；MUST NOT 重跑匹配启发式或改写端侧的关系结论。

#### Scenario: 非法关系集被拒绝

- **WHEN** 写集中的关系违反工作区关系图不变量
- **THEN** 服务端 MUST 拒绝整个写集并返回可识别错误
- **AND** MUST NOT 静默降级、补齐或改写关系

#### Scenario: 金额精度校验

- **WHEN** 写集金额不是合法的精确十进制值
- **THEN** 服务端 MUST 拒绝写集，不得以二进制浮点承载账务结果

### Requirement: 数据层幂等

写入 MUST 由来源身份与确定性指纹保证幂等：现金流水按来源绑定身份去重，交易关系按关系类型、成员来源键与关联金额指纹去重。重复提交同一事实 MUST NOT 产生重复记录。

#### Scenario: 重叠账单重复导入

- **WHEN** 两份重叠账单产生相同来源身份的流水
- **THEN** 服务端 MUST NOT 创建重复流水

#### Scenario: 相同关系重复提交

- **WHEN** 两个设备提交同一条已存在的关系（指纹相同）
- **THEN** 服务端 MUST 视为已应用并幂等成功，且 MUST NOT 创建第二条关系

### Requirement: 提交层幂等与结果核实

提交 MUST 接受调用方幂等键，并以用户、工作区与幂等键确定一次提交。相同幂等键的重试 MUST 返回第一次结果；结果未知时系统 MUST 能按原幂等键核实是否已提交，已成功内容 MUST NOT 重复写入。新写集提交的永久收据 MUST 保留该次提交的 `ledger_seq`，并以精确十进制字符串返回；按原键核实或读取旧收据 MUST 保留原提交版本，MUST NOT 代换成读取时的最新版本。旧入口的历史收据可不含该字段。

#### Scenario: 断网重试不重复写入

- **WHEN** 提交请求结果未知，客户端以同一幂等键重试或核实
- **THEN** 服务端 MUST 返回稳定结果，且 MUST NOT 重复写入业务数据

### Requirement: 基线过期拒绝与稳定输入重派

提交 MUST 携带端侧计算所用的工作区基线版本。基线过期时服务端 MUST 整批拒绝并返回可识别错误；端侧 MUST 基于稳定输入（账单文件、账户映射以及按稳定引用寻址的行、entry 与配对决策）在最新缓存上重派并复用决策，结论指纹一致时 MUST 静默重提交，不一致时 MUST 提示重新核对。

#### Scenario: 无关变更后静默重提交

- **WHEN** 冲突仅来自与本导入无关的变更，且重派结论与使用者已核对的一致
- **THEN** 端侧 MUST 直接重提交，不得要求使用者重新核对

#### Scenario: 结论变化或决策失效

- **WHEN** 重派后行、entry 或配对结论发生变化，或某决策的稳定引用已失效
- **THEN** 端侧 MUST 提示已发生变更并要求重新核对，且 MUST NOT 静默丢弃使用者决策

### Requirement: CSV/XLSX 端侧解析与 PDF／旧 XLS 服务端 parse-only

端侧 MUST 支持 CSV 与值型 XLSX 的本地解析。XLSX 公式不在本轮支持范围；当前选中的账单工作表含任意公式单元格时，端侧 MUST 拒绝整份文件并返回 `statement_unreadable`，MUST NOT 使用公式缓存值、把公式正文当账单值、跳过该单元格或回退服务端计算。以等号开头但没有公式标记的普通字符串 MUST 保留原文。对 PDF，服务端 MUST 提供只解析并返回归一化行的无状态 parse-only 入口；对当前受支持的旧 XLS，服务端 MUST 只返回已解码的原始文档，字段归一、类型分类、查重和配对 MUST 在端侧完成。PDF 与旧 XLS 解析需要联网，服务端 MUST NOT 建立导入会话、读取账本或写入任何业务数据，且 MUST 在返回前重新校验原用户与工作区权限；密码与原始账单 MUST NOT 进入日志或持久化。

#### Scenario: 公式工作表不发布部分账单

- **WHEN** 当前选中的账单工作表含普通、共享、数组或其他公式单元格，即使同时保存了看似有效的数字缓存
- **THEN** 端侧 MUST 返回 `statement_unreadable` 且不发布该文件的任何解析行
- **AND** MUST NOT 求值、使用缓存值或请求服务端公式解析

#### Scenario: 普通字符串不被误当公式

- **WHEN** 工作表中的普通字符串以等号开头但没有公式标记
- **THEN** 端侧 MUST 按原字符串读取，不以该文本作为拒绝文件的依据

#### Scenario: PDF 走 parse-only

- **WHEN** 使用者导入受支持的 PDF 账单
- **THEN** 服务端 MUST 只返回归一化行，后续查重、归属与配对 MUST 由端侧完成
- **AND** 服务端 MUST NOT 写入任何业务数据

#### Scenario: 旧 XLS 走 parse-only 后端侧归一

- **WHEN** 使用者导入受支持的旧 XLS 账单
- **THEN** 服务端 MUST 在受限的解析进程中只解码并返回完整原始文档，保留来源、原始字段、位置、计数、覆盖证明与原有错误语义
- **AND** 端侧 MUST 继续字段归一、类型分类、查重、账户归属与关系配对
- **AND** 服务端 MUST NOT 读取账本、创建导入暂存或写入业务数据

#### Scenario: PDF 或旧 XLS 无网络

- **WHEN** 使用者在无网络时请求解析 PDF 或旧 XLS
- **THEN** 客户端 MUST 明确说明该格式解析需要联网，且 MUST NOT 将文件标记为已解析或已导入

#### Scenario: 解析期间权限失效

- **WHEN** PDF 或旧 XLS 解析期间原用户／工作区权限失效或请求取消
- **THEN** 服务端 MUST NOT 返回已解析文档，且 MUST 清理本次请求的文件资源

#### Scenario: 密码不留存

- **WHEN** 加密 PDF 需要密码
- **THEN** 密码 MUST 只用于当前受限请求，不得写入响应、日志、缓存或业务数据

### Requirement: 导入结果不因入口或数据库后端不同而不同

相同工作区、相同账单、相同账户映射与相同规则版本下，端侧导入的归一化、来源身份、关系结果与落库结果 MUST 与规则一致，且 PostgreSQL 与 SQLite MUST 得出等价的落库事实、精确金额与幂等结果。

#### Scenario: 比较双后端落库结果

- **WHEN** 两个后端处理相同去标识化账单与账户映射写集
- **THEN** 落库的流水、关系、来源身份、精确金额与幂等结果 MUST 等价
