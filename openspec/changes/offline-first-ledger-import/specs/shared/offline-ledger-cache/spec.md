## Purpose

定义端侧在离线优先前提下缓存账本规范事实、按工作区版本判断并整包替换快照，以及在本机派生投影与聚合时的可观察行为，确保离线与在线浏览结果一致，且不引入第二事实源。

## ADDED Requirements

### Requirement: 端侧缓存全历史规范事实

端侧 MUST 在本地持久化当前工作区的全部账本规范事实，包括账户、账户别名、账单账户映射、收支分类与目录版本、现金流水与组成项、来源绑定与来源证据、交易关系与候选、待处理问题、entry 与成员，并为导入匹配与浏览建立本地索引。端侧 MUST NOT 把服务端物化投影或余额快照作为缓存的事实来源。投资只纳入只读资金关系，以及已接受且生效关系所关联资金记录的账户、币种和原资金金额；MUST NOT 因此缓存完整投资账本或运行投资计算或估值。

#### Scenario: 首次进入工作区建立缓存

- **WHEN** 使用者在已认证工作区首次打开账本
- **THEN** 端侧 MUST 拉取全量快照并原子写入本地库
- **AND** 本地记录的版本 MUST 等于快照锁定版本

#### Scenario: 离线浏览账本

- **WHEN** 端侧无网络且已有缓存
- **THEN** 使用者 MUST 仍能浏览已缓存流水，并看到与在线一致的投影与月份汇总

#### Scenario: 离线查看银证转账

- **WHEN** 已缓存的现金收支对应已接受且生效的银证转账关系
- **THEN** 端侧 MUST 使用关联资金记录的最小只读字段还原投资端账户、币种与金额，并与现金端一同展示
- **AND** 未关联的投资事件与投资原始正文 MUST NOT 进入本地现金缓存

### Requirement: 按工作区版本判断并整包替换

端侧 MUST 记录已同步的工作区账本版本，并在刷新时先查询服务端当前版本；仅当版本变化时才重新拉取全量快照，并以快照版本原子替换本地缓存。替换期间 MUST NOT 混入上一版本的记录。

#### Scenario: 版本未变化

- **WHEN** 刷新时服务端账本版本与本地已同步版本相同
- **THEN** 端侧 MUST 复用本地缓存，不得重新下载账本

#### Scenario: 版本变化后替换

- **WHEN** 刷新时服务端账本版本已变化
- **THEN** 端侧 MUST 拉取新快照并原子替换本地缓存
- **AND** 替换后展示的流水与月份汇总 MUST 全部来自新版本

### Requirement: 端侧派生投影与聚合

浏览、筛选、分页、月度汇总与聚合 MUST 由端侧使用共享规则从缓存事实派生，MUST NOT 依赖服务端物化投影，并 MUST 使用与服务端一致的规则版本。

#### Scenario: 内部转账与退款不计入收支

- **WHEN** 缓存中出现已确认的内部转账或退款关系
- **THEN** 端侧 MUST 显示内部转账但不计入收入、支出和月度汇总，并让退款冲抵原消费

#### Scenario: 规则版本变化后重新派生

- **WHEN** 共享规则版本发生变化
- **THEN** 端侧 MUST 用新规则重新派生投影，不得展示按旧规则算出的结果

### Requirement: 缓存加密与登出清理

端侧缓存 MUST 以加密形式落盘。Android／iOS 密钥 MUST 取自平台安全存储；Web MUST 使用浏览器持久密钥自动解锁，MUST NOT 要求额外缓存密码，MUST NOT 把数据库密钥以明文保存到 localStorage 或 IndexedDB。Web 不保证抵御完整浏览器配置文件复制或同源恶意脚本。使用者登出、认证失效或工作区不再可访问时，端侧 MUST 清除对应缓存与密钥；密钥不可用或损坏时 MUST NOT 静默创建替代密钥或降级为明文缓存。

#### Scenario: 重新打开网页自动解锁

- **WHEN** 使用者仍处于有效登录范围且重新打开已有加密缓存的网页
- **THEN** 网页 MUST 使用该范围的浏览器持久密钥解锁缓存，不要求额外密码
- **AND** 服务地址、使用者或工作区不同的缓存 MUST NOT 共用数据库密钥

#### Scenario: 浏览器密钥不可用

- **WHEN** 已有缓存的密钥读取或解密失败
- **THEN** 网页 MUST 报告失败，MUST NOT 静默重建密钥、读取不匹配缓存或保存明文事实

#### Scenario: 登出后清理

- **WHEN** 使用者登出账号
- **THEN** 端侧 MUST 删除本地缓存与缓存密钥
- **AND** 在重新登录前 MUST 无法读取任何账本记录

### Requirement: 断网重启恢复本机账本访问

已成功登录且缓存过账本的设备 MUST 能在断网重启后，使用上次成功验证的身份读取对应本机缓存，无需再次联网登录。恢复材料 MUST 绑定原本机登录令牌、服务地址、使用者与工作区；MUST NOT 因更换令牌或范围而读取旧身份缓存。身份恢复材料中的邮箱、名称及历史角色 MUST 随缓存加密保存，MUST NOT 把完整登录令牌复制进账本缓存。

仅已识别的网络不可达或超时可进入离线访问恢复；程序错误、损坏材料、密钥错误或明确的服务端拒绝 MUST NOT 被伪装为离线成功。恢复联网后 MUST 核验登录和工作区权限；已知认证失效、退出或失去工作区访问权时 MUST 清除对应缓存、恢复材料与密钥。离线期间不保证即时获知远端撤权；本机恢复 MUST NOT 代替服务端写入鉴权和数据校验。

#### Scenario: 已缓存设备断网重启

- **WHEN** 本机仍保存原登录令牌及匹配身份的已缓存账本，且重启后的登录核验因网络不可达或超时失败
- **THEN** 端侧 MUST 恢复该身份与工作区的本地浏览，不要求重新输入登录信息
- **AND** 未缓存的账本 MUST NOT 被伪造为空账本并授予离线访问

#### Scenario: 离线设备恢复联网后发现失效

- **WHEN** 离线访问恢复后，联网核验确认登录或工作区访问权已失效
- **THEN** 端侧 MUST 封闭对应本机读取并清除其缓存、身份恢复材料与密钥

#### Scenario: 更换登录或恢复材料损坏

- **WHEN** 本机令牌与恢复材料不匹配，或材料、密钥及身份范围校验失败
- **THEN** 端侧 MUST 拒绝用该材料恢复离线访问，不创建替代密钥或猜测使用者

### Requirement: 工作区隔离

端侧缓存 MUST 按工作区隔离；切换工作区后 MUST 只展示目标工作区的数据。

#### Scenario: 切换工作区

- **WHEN** 使用者从工作区 A 切换到工作区 B
- **THEN** 端侧 MUST 只展示 B 的缓存数据，A 的记录不得出现在页面
