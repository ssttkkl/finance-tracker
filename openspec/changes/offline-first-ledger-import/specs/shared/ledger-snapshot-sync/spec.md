## Purpose

定义服务端为端侧离线缓存提供的账本版本与全量快照合同，使端侧能在明确的版本边界上一致地取得全部规范事实，并保证前后端对"账本是否变化"达成一致。

## ADDED Requirements

### Requirement: 工作区账本版本单调递增

服务端 MUST 为每个工作区维护单调递增的账本版本，每次对规范事实的写入 MUST 使其加一，且 MUST 与写入在同一事务内推进。

#### Scenario: 提交成功后版本推进

- **WHEN** 一次写集提交成功
- **THEN** 该工作区账本版本 MUST 严格大于提交前的值

#### Scenario: 提交失败不推进版本

- **WHEN** 一次写集提交因校验失败而整体回滚
- **THEN** 工作区账本版本 MUST 保持不变

### Requirement: 轻量版本查询

服务端 MUST 提供只返回当前工作区账本版本的轻量查询接口，且 MUST 只对当前已登录成员的选定工作区返回。

#### Scenario: 查询当前版本

- **WHEN** 端侧查询账本版本
- **THEN** 服务端 MUST 只返回版本值，不得返回账本事实
- **AND** 非成员或未选定工作区 MUST 被拒绝

### Requirement: 全量快照一致读

服务端 MUST 提供全量事实快照接口，在单个只读事务内锁定版本 `V` 并返回该工作区的全部规范事实；返回的每一类事实 MUST 属于同一版本 `V`。

#### Scenario: 快照携带一致版本

- **WHEN** 端侧请求全量快照
- **THEN** 响应 MUST 携带版本 `V`
- **AND** 返回的账户、流水、关系、映射与来源证据 MUST 全部对应版本 `V`

#### Scenario: 分页快照不跨版本

- **WHEN** 账本规模导致快照需要分页返回
- **THEN** 全部分页 MUST 属于同一版本 `V`，不得混入其他版本的记录

### Requirement: 快照与版本遵守工作区隔离与权限

快照与版本接口 MUST 只返回当前已登录成员选定工作区的事实，MUST NOT 泄露其他工作区数据。

#### Scenario: 跨工作区访问被拒绝

- **WHEN** 使用者请求不属于自己的工作区快照
- **THEN** 服务端 MUST 拒绝请求且不得返回任何事实

### Requirement: 双后端返回等价版本与快照

PostgreSQL 与 SQLite MUST 对相同工作区返回等价的账本版本、快照事实、精确金额与时间值。

#### Scenario: 比较双后端快照

- **WHEN** 两个后端使用相同去标识化账本夹具
- **THEN** 除内部代理键外，版本值与快照响应 MUST 等价
