# shared/kotlin-backend-parity Specification

## MODIFIED Requirements
### Requirement: 保留存储与安全不变量

Kotlin 后端 MUST 保持现有认证会话和密码可用、工作区隔离、角色、来源证据、修订冲突、TTL/CAS、永久幂等收据、审计和完整组合同。认证会话读取 MUST 只把读取时仍是成员的工作区作为活动工作区返回：持久会话指向已移除的成员资格时返回空活动项，该只读归一不得回写会话行，也不得自动改选其他工作区。数据库 MUST 显式选择 PostgreSQL 或 SQLite，并满足现有运行时数据库主规格；不得自动升级真实数据库、静默回退或双写。

#### Scenario: 提交响应丢失
- **WHEN** 一次提交已经成功但客户端未收到响应
- **THEN** 原幂等键核实 MUST 返回原成功收据，且不得重复财务写入

#### Scenario: 中途失败
- **WHEN** 任一写入或投影发布前发生拒绝或内部错误
- **THEN** 该命令的所有业务写入 MUST 原子回滚，不能产生失败子集或自动拆分重试

#### Scenario: 类型化持久化适配
- **WHEN** Kotlin 后端通过 jOOQ 在 SQLite 或 PostgreSQL 18 执行业务查询和写入
- **THEN** 表和字段 MUST 来自当前基线 schema 的可校验生成结果，且仅由后端持久化层消费；金额不得经浮点转换，原事务、保存点、空值及 UTC 微秒合同 MUST 保持

#### Scenario: 重新生成数据库类型
- **WHEN** 开发者重新生成后端数据库类型
- **THEN** 生成器 MUST 仅使用显式指定的匿名 `_test` 数据库，普通构建和功能测试不得自动创建、启动或升级数据库

#### Scenario: 旧现金新增响应无法编码
- **WHEN** 旧现金新增的成功响应包含不能编码为 UTF-8 的日期原文
- **THEN** Kotlin 后端 MUST 在提交前拒绝，并回滚该操作的全部财务写入；不得返回失败却保留新流水或余额

#### Scenario: 投资命令成功响应无法编码
- **WHEN** 投资命令即将成功写入，但完整成功响应无法通过 JSON 序列化和 UTF-8 编码
- **THEN** Kotlin 后端 MUST 在提交前拒绝，并原子回滚投资事件和持仓快照；不得返回失败却保留余额变更；正常可编码的 Unicode 日期仍按既有合同成功

#### Scenario: 旧会话访问
- **WHEN** 使用原后端产生的有效登录令牌访问 Kotlin 后端
- **THEN** 认证会话读取 MUST 依据兼容的摘要和有效期返回用户、可访问的活动工作区值及工作区列表，允许无工作区；持久指向不可访问工作区时返回空活动项，不写回会话行也不改选其他工作区；业务接口另行校验当前成员和活动工作区，不信任请求指定的身份或角色

#### Scenario: 有效用户没有可访问工作区
- **WHEN** 有效会话尚未加入任何工作区或原成员资格已经移除
- **THEN** 会话读取 MUST 保持当前成功响应并把活动工作区返回为空，而需要活动成员资格的业务读取 MUST 按既有合同拒绝

#### Scenario: 成员被移除后读取会话
- **WHEN** 管理员移除某成员，而该成员的持久会话仍指向被移除的工作区
- **THEN** 该成员后续的会话读取 MUST 返回剩余可访问工作区与空活动工作区，不得返回已移除的工作区，不得写回会话行，也不得由服务端自动选中其他工作区（客户端仍按 `workspace-entry` 的既有规则选择首个可访问工作区后进入）；该用户对已移除工作区的账本读取 MUST 继续拒绝

### Requirement: 后端运行时保持全部现有合同

Kotlin 后端 MUST 覆盖全量迁移盘点中的现有能力，保持 HTTP 路径、方法、状态、请求类型、字段、省略与 `null`、默认值、分页、SSE、错误及停用入口合同；已授权差异为 `authentication/user-workspace-access` 定义的注册/登录字符串凭据要求，同步修复分类移动后代深度以保持既定树结构和五层限制、旧现金新增及投资命令写入的响应编码失败整笔回滚、手工转账双端编辑保留公共编辑动作及字段差异，以及认证会话读取只把仍可访问的工作区作为活动工作区返回（已移除成员返回空活动项，不回写会话行，不由服务端自动改选）；同步凭据配置错误统一使用固定安全错误，不回显服务器文件路径或解析诊断。未完成项 MUST 明确标记，且不得以代理旧后端或局部实现宣称全量迁移完成。

#### Scenario: 原客户端请求
- **WHEN** 原客户端对已移植能力发送相同合法、非法或重复请求
- **THEN** Kotlin 后端 MUST 返回等价的响应及数据库结果；已停用路径保持停用

#### Scenario: 交易所连接器的已知限制
- **WHEN** 迁移 Kraken 成交分页、OKX 资金类型与历史窗口或 Binance 默认现货同步
- **THEN** 本次 MUST 保持原请求、结果及失败行为并用实际 SDK 验证，明确记录分页截断、类型拒绝及不支持的调用限制；修复留待迁移完成后的独立变更，等价迁移通过不得描述为完整同步可用

#### Scenario: 同步凭据配置错误不泄露路径
- **WHEN** 同步接口读取凭据时遇到缺失文件、无效配置或缺少必要字段
- **THEN** Kotlin MUST 返回 `400 sync_configuration_invalid` 和固定安全提示，不在响应的代码、消息或详情中包含服务器文件路径、配置内容及解析诊断

#### Scenario: 手工转账备注与双端财务补丁同时提交
- **WHEN** 使用者修改手工转账的公共备注，并提交双端金额及现金部分补丁，无论财务值是否改变
- **THEN** Kotlin 后端 MUST 保留备注的公共编辑、修改动作及字段差异；预览与保存结果 MUST 报告实际公共修改，财务补丁不得将其覆盖为没有变化；全部字段未修改时保留原无变化结果
