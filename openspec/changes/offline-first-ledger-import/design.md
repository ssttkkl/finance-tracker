## Context

本变更以迁移后的 Kotlin 架构为基线：服务端 `compose/backend`（Ktor + jOOQ，PostgreSQL 与 SQLite 双后端，schema 由 Kotlin 资源中的基线 SQL 定义），共享模块 `compose/business-contracts`（线路 DTO）与 `compose/business-domain`（纯规则），客户端 `compose/shared`（Compose Multiplatform，Android/iOS/Web）。Python 运行时在本变更生效前已废弃，不在讨论范围。动机见 `proposal.md`。

当前约束：客户端无本地数据库（仅内存分页 + token/恢复指针）。导入解析、归一化、查重、账户归属、操作计划、候选召回、关系配对与投影派生全部在服务端；浏览依赖服务端物化投影（`cash_projection_*`）与版本绑定游标。余额由服务端 `ledger_snapshots` 增量维护。关系匹配依赖较宽的既有账本状态（流水与组成项、来源绑定与来源证据、关系与候选、别名、账单账户映射、待处理问题、entry 与成员）。

### 阶段 1 探索结论：共享规则下沉边界与测试基线

**可下沉的纯规则**（`compose/backend` 中不依赖 SQL/jOOQ/session 的实现），按职责分组：

- 行归一化与类型分类：`CashStatementRowNormalization`、`CashRecordClassification`、`CashRecordTypes`、`CashRecordPolicy`。
- 来源身份与查重：`CashSourceIdentity`、`CashSourceResolver`、`CashSourceResolutionPolicy`、`CashSourceRows`、`CashSourceBatch`。
- 资金归属：`CashImportFunding`/`CashImportFundingEngine`。
- 候选召回索引：`CashFactCandidateIndex`。
- 关系配对：`CashRelationPipeline`、`CashMirrorMatch`、`CashTransferMatch`、`CashRefundMatch`、`CashRefundHardKey`、`CashRefundSignals`/`CashRefundDiamond`、`CashPlatformRefund`、`CashRelationPlanning`、`CashRelationGeometry`、`CashRelationCore`。
- 关系图与策略：`CashRelationGraph`、`CashRelationPolicy`。
- 投影派生与余额：`CashProjectionRules`、`CashRelationProjection`。

**留在 `compose/backend` 的耦合层**（读写仓储与服务编排）：`CashImportSourcePlanner`、`CashImportOperationPlanner`、`CashImportBusinessPlanBuilder`、`CashImportCandidateRepository`、`CashImportRelationDiscovery`、`CashRelationService`、`CashProjectionService`、`CashProjectionRepository`、`CashProjectionSourceRepository`、`CashSnapshotRepository`/`CashBalanceService`、`CashFundingMappings`/`CashImportAccountMappings` 等。共享层 MUST NOT 依赖 jOOQ、数据库连接或 Ktor。

**已在 `business-domain` 的共享面**（新迁移应与之一致）：`LedgerDecimal`/`DecimalRepresentation`、`AllocationBalance`、`CashComponentRules`、`CategoryRules`、`DecimalCharacterData`。

**测试基线现状与缺口**：backend 已有大量 `Cash*` 测试类可作为等价性 oracle（各能力分组的 `*GoldenTest`/`*OriginalTest`）。`business-domain`/`business-contracts` 只声明了 `commonTest`，构建脚本的 `check` 未显式接线测试任务；执行任务 1.1 前必须先确认共享模块的测试任务确实可运行，否则"测试先行"无法验证。

**已验证的基线结果（阶段 1 实测）**：

- `:business-domain:jvmTest` 可运行，现有共享规则测试通过——JVM 侧可作为共享层的验证入口。
- `:business-domain:check` 初次失败于 JS/Wasm 依赖 `androidx.paging:paging-common-js:3.5.3` 解析不到。核实后确认**镜像与官方源均可正常下载该构件**，实际是 Gradle 缓存了上一次失败的解析结果（负缓存）。执行一次 `--refresh-dependencies` 后 `:kotlinNpmInstall` 成功，`:shared:compileKotlinWasmJs` 与 `:shared:compileKotlinJs` 均编译通过。
- 结论：JS/Wasm 目标在本环境可用，任务 9 与 11.2 无镜像阻塞。共享层验证仍以 `jvmTest` 为主，避免每轮拉起 npm 与浏览器测试。
- **下沉的前置阻塞（实测发现）**：上列"纯规则"只对数据库解耦，仍依赖 JVM 专有原语——`sourceDigest` 经 `tokenDigest` 使用 `java.security.MessageDigest`，`sourceJson` 使用 `java.math.BigDecimal`，多处使用 `String.codePointCount` 与 Java 浮点文本格式化。移入 `business-domain`（KMP：`jvm/android/ios/js/wasmJs`）前 MUST 先提供多平台等价原语（SHA-256 摘要、码点计数与迭代、Python 浮点文本、`LedgerDecimal` 十进制表示）。此项已登记为任务 1.6，是 1.3 的硬前置。
- **前置原语的依赖链**：摘要／码点／空白与稳定 JSON 结构已共享；浮点文本使用 binary64 位模式构建精确十进制值及相邻浮点的中点区间，按最短有效位、最近值与偶数规则选择表示，再应用 Python 的固定／科学计数边界。专用私有整数算术仅服务浮点格式化，不扩展 `LedgerDecimal` 的账务范围，不增加通用任意精度依赖。backend 委托共享实现，旧 `BigDecimal` 版本仅保留在 JVM 差分测试。时间解析使用共享 `kotlin.time.Instant` 与纯日历运算，保留现有接受／拒绝、微秒和偏移合同；backend 适配 JVM 时间对象并保持既有错误类型。`CashSourceCoverage` 及来源身份实体的迁移归入任务 1.3。
- **多平台字符串化的硬约束**：任何进入 digest 或派生的数值/时间文本 MUST 由共享实现产生，MUST NOT 依赖 `Double.toString()`、平台 `Instant` 格式化或 JVM 默认文本，否则三端与服务端会漂移。

逐行投影算法在共享 `CashProjectionRules<I,T>` 内完成：标识和时刻仍由平台原语解释，金额计算复用内部 `LedgerArithmeticValue`，逐次加法维持原 80 位 HALF_EVEN，不把中间累计强塞回单字段范围。native 保留原 create／存储标识桥并委托共享算法；原代表选择使用的 JSON 文本排序及退款分配键合并保持。跨平台黄金向量由现有 backend oracle 生成，检查生成内容而不维护第二套预期。

金额图以共享 `CashRelationGraphRules<I,T>` 复用端点／角色规则、精确累计及同一投影器；平台仅解释严格整数和文本 ID，联合决定修订及原始容器边界也保留。本阶段仍不包含端侧浏览接线。

关系计划的上下文／外部依赖摘要及虚拟快照 ID 也迁入共享层，复用原稳定引用、标量编码和非法 UTF-16 的问号替换；虚拟 ID 保持 SHA-256 高 8 字节清符号位、正值及冲突顺延，不改来源身份或用户确认指纹语义。

提案的虚拟投影上下文、局部受影响子图、整批合法性与缓存复核收敛到 `CashRelationValidationRules<A,I,T>`；它复用同一来源引用、投影工厂和金额图。上下文金额逐项精确相加，保留原无舍入累计；图内累计仍遵循自身 80 位规则。平台桥只解释原始十进制、时刻、ID 和开放值编码，不复制校验决定；Phase A→D 计划总入口由 `CashRelationPlanningRules<A,I,T>` 组合已共享匹配器、索引、序列化、摘要和 validator；原始行解析及精确金额原语继续由当前 native 桥提供，客户端生产配置另行接入。

现有 Python Unicode 14 大小写表与上下文 Sigma 小写逻辑迁入共享层，仍由原生成器维护；backend 以只读单码点查询和同一小写函数复用，不开放可变映射表。此步骤不把原商户匹配器的 JVM Unicode 正则／lowercase 自动换成 Python 口径，两者仍按各自旧合同迁移。

来源解释、支付方式与商户归一共用 `CashSourceEffects` 规则。其既有 Python 空白／数字字符类和 UNIX_LINES 正则语义以本文件限定的共享模式构造保留，ASCII／中文品牌词的忽略大小写显式包含原 I/K/S 特殊等价字；补充平面数字使用字符类外完整字符分支，规避 Wasm Regex 的范围解释差异；不依赖宿主 Unicode 版本。原现金来源备注优先级提为同一纯函数供字段策略和来源解释复用。原始 `RawCashRow`／`CashStatementDocument` 合同共享至 business-contracts，保留已有字段及默认值，读取器与 PDF 进程用同一模型；共享模型不包含读取器实现。

完整平台／银行／工行行归一决定复用 `CashStatementRowNormalizationRules<A>`，同一金额适配组隔离原 BigDecimal 符号、绝对值／取负及表示；来源时区、日期、原始值、原生正则、分类／账号和观察快照由当前 native 薄桥提供。原始行 skip／issue 与覆盖证据失效在共享规则内完成，数值零与来源负零文本分开保留；`normalizeLocalCashStatement` 已以模块内精确累计值、零文本、共享时间、分类／账号及有限原生正则适配组装生产入口，输入为已解码的共享文档，返回同一 parsed 模型；计算标量不向公开合同泄漏。字符串来源 payload 的严格 UTF-8 摘要仅接受已解码文档的字符串键／单元格。裸 JVM 数字类保持 ASCII，显式来源数字／空白仍取冻结集合；行归一使用 JVM 默认行终止语义，来源解释仍保留 UNIX_LINES。文件字节读取器及完整导入接线仍待完成。

平台表头、CSV／TSV 记录、声明覆盖和行预算由共享 `CashPlatformStatementTextReader` 处理；UTF-8／GB18030 byte 解码已由共享 `decodeCashStatementText` 复用，工作簿读取仍在平台边界，后端先复用同一文本规则。空白行保持原 Kotlin/JVM 字符集合，元数据模式保持默认 ASCII 数字／空白与原多行起点；预算 UTF-8 计数沿用原无效 UTF-16 问号替换，不借迁移更改输入语义。

来源计划准备由 `CashImportSourcePlanningRules` 处理，当前事实／单据证明读取和批次解析分别通过窄端口提供。保持先读取当前候选、合并文件／已存／候选证明，再提升有证明覆盖或降级旧无证明标志，最后解析批次的顺序；不写绑定，不跨提交缓存计划。native 仍在原工作区与事务中读仓储，端侧快照候选读取通过 `prepareLocalCashImportSources` 的只读适配接入：只选当前 import／legacy 事实，可靠绑定直接召回，非微信保留原同时间候选；微信不以旧编号或原文补身份。绑定、组件及认证空页都来自同一传入快照；缓存事务与落盘仍由缓存层负责。微信仅使用已有可靠绑定，不恢复旧编号、原文或时间候选兼容。

端侧来源查重复用 `resolveLocalCashSourceRows`／`resolveLocalCashSourceFile`／`resolveLocalCashSourceBatch` 的生产配置，不使用 fixture 的值适配。内容规范摘要和 payload 整数／浮点区别保持；索引金额按数值相等，时刻截为微秒。provider 行身份由稳定来源键分配，无 provider 的 UUID 在新意图生成一次并须由调用方持久化后重试。`prepareLocalCashImportSources` 在单一完整快照上按既有仓储资格选择候选、绑定与文档证明，不以任意全缓存记录替代查询合同。缓存层仍须保证选定工作区与原子发布；来源修订直接保留完整 Long，最终写集合同另行收敛。

本地投影入口 `buildLocalCashProjections` 从单个完整快照读取非删除流水、来源排序键、待处理标记和只读投资资金对应。已确认关系先按原组件图验证并转换为父流水关系，再交给同一逐行投影规则；不要求与已确认子图无关的流水具备图组件。草稿和无关系流水仍保留原派生口径。现有客户端账本读取 DTO 移入 business-contracts，shared 通过 typealias 保留消费方 API、字段和默认值。本地读取视图由同一快照组合稳定条目、账户、分类路径、来源类型、当前问题和接受关系摘要；普通转账按原关系序号取第一组组件，银证转账读取已批准的最小投资端事实。公共字段不覆盖来源成员；读取版本明确取 ledger_seq，不沿用物化 projection_version。用户已确认经济类型／业务标签保持全局可选：选项从同一完整工作区快照的基础可见集合生成，不随当前筛选或分页缩小。完整分类目录按原 category_path／排序号／身份排序，币种和经济类型及内部转账业务标签沿原 native options 口径；有当前问题的隐藏项按原基础可见规则进入集合，不从完整投资事件扩展。浏览 delta 明确该选择，替换主规格“当前筛选范围”的冲突口径。此入口只组装现有读取模型，不进行筛选、分页或页面接线。本地浏览的条目组合入口从同一快照读取已持久化的 cash_entries／members，为完整派生分组提供明确稳定 entry 引用；公开显示分类、备注和对方信息取条目，来源成员原值保持。它不创建条目、不从流水编号猜 entry ID；必要成员映射缺失、组内不一致或重复公开身份时停止发布不完整结果。该入口只产出派生结果，不写缓存、条目或服务端；列表过滤／分页及页面接线继续在后续边界完成。月度统计和连续月份位置由共享累计器处理有序、已筛选的完整结果；月份映射由浏览时区适配提供，不读取本机默认时区。 适配显式接收时区标识，由平台时区库给定时刻的秒级偏移；年月计算继续使用共享公历算法，不依赖本地语言或 Foundation 的历法格式。JS／Wasm 以完整秒的整数文本传入 Intl，再构造精确的整数毫秒时刻查询偏移，避免 64 位身份互操作或微秒舍入跨界；EST／MST／HST 沿既有固定偏移语义。未知日期仍占列表位置，转账可形成空统计月份，只有具备统计资格的收入／支出参与精确无舍入累计；合计不受单笔 NUMERIC(38,18) 限制。原生查询先复用同一累计器，端侧筛选、时区适配及页面接线另行完成。

本地操作生产入口 `prepareLocalCashImportOperations` 在同一个完整快照上组合来源准备、选择校验、资金决定与操作规则。账户／分类／目标／问题及条目成员只读；条目依赖摘要直接按原持久 JSON token 排序编码，不借来源 JSON 的浮点显示规则重写。账户修订保持 JSON 整数，条目修订与标识保持 64 位整数精度；完整错误目录和字段提示由同一共享 issue builder 提供。缓存发布／权限／提交校验仍由各自边界负责，不在本地规划中写入。

逐流水操作计划以 `CashImportOperationRules` 共享，账户／来源／条目版本与快照／当前目标和问题／分类读取由 `CashImportOperationRead` 提供；读模型只包含计划实际读取的条目标识和修订，避免依赖可变持久化实体。字段归一、相等、复制和一致性通过同一 `CashRecordValues` 边界提供；native 保留原值及每 prepare 的 posting 缓存，本地配置复用现有生产值桥。保留先验证输入、再来源／资金／条目／目标／分类读取和逐行决定的顺序，不新增读取期写入或更改合法缺项草稿／固定字段／人工决定语义。

导入选择输入的结构校验复用 `CashImportInputRules`，保留引用、重复项、动作、公共字段、继承标志和正整数账户修订的原边界。native 注入原整数／深复制／字段策略，本地 JSON 入口保留数值 token 并复用生产字段策略；这一步不迁移分页／会话视图，也不改变既有用户决定语义。

资金分组／扫描／决定模型共享到 `CashFundingModels`，显式 JSON 保留同一字段、null 和默认值，开放字段值编码由原 native `sourceJson` 注入，不新增线路 DTO。账户选择、可用性／币种检查、同账户合并、分摊完整性、符号及入账就绪决定由共享 `CashFundingResolutionRules<A>` 执行；金额原语、严格 revision 类型、字段深复制及每次 resolve 新建的入账验证缓存由 native 薄桥维持。原 protected total 仍按实例动态分派，未知内部异常不转成可跳过行。来源分组／支付拆分决定和标签遮蔽已由 `CashFundingScanRules` 共享；NFC 与来源账户生产配置已共享；`resolveLocalCashFunding` 已连接真实共享入账策略。JSON 选择／账户输入保留整数词法，使修订号与 1.0／1e0、布尔及字符串在 JS／Wasm 仍有严格区分；整数不经 Double。输出 ordinal 通过已知生成整数标记保持 JSON 类型，native 默认整数不变。local 逐次真实验证，暂不带成功缓存；native 原每 resolve 的缓存保留，性能基线使用两者实际路径。

来源账户及支付宝组件决定由共享 `CashSourceAccountMappingRules<A>` 执行，复用同形 `SourceAccountGroup`／`SourceRowIssue` 与原失败类型；native 仅解释原 BigDecimal、文本／真假／整数、大小写、Regex 和稳定摘要。分摊守恒仍精确相加，不套用资金 resolve 的 80 位累计；金额解析只捕获原 NumberFormatException。支付方式、完整卡号及组顺序与原规则一致，decimal 字符归一复用内部数字表避免每字符复制公开表。`LocalCashSourceAccountMapping` 已组合生产金额、标量、大小写、词法与摘要。金额构造仅归一原 BigDecimal 接受的 BMP 数字，不删除空白／下划线；最终 scale 可容纳时正指数允许超过 IntMax，分配不强制套用持久化单笔范围。已知生成整数显式解包，归一流水的金额及身份为字符串，不代表任意 JVM 对象字符串化在端侧受支持。

来源账户有限词法由 `CashSourceAccountTextPatterns` 提供，原 Java Unicode word／Nd 冻结在私有数据中，不混用 Python 14 字符表。金额边界按完整前码点检查并保留原最左分支，长数字不逐后缀尝试；数字子串交金额适配处理。native 与本地生产配置已复用。

资金扫描共享来源组身份、文档账户选择、微信会话昵称、支付来源分拆、币种／行引用收集及标签遮蔽；native 保留原宿主适配；`scanLocalCashFunding` 已以共享精确金额、`LocalCashSourceAccountMapping`、严格 UTF-8 身份摘要、NFC 及归一容器深复制组合本地生产入口。扫描与后续 resolve 均有本地生产入口；resolve 的 posting 桥复用完整 `LocalCashRecordValues`；`prepareLocalCashRecord` 接收 JSON 当前记录与 patch，保留整数／浮点词法、精确二进制浮点比较及严格字段验证。编码仅解释闭合 JSON／归一记录值树，生成整数显式标记，不支持任意 JVM 对象图，也不执行服务端权限／当前修订检查。protected parts／支付组件解析保持实例覆盖能力，内部失败不污染其他实例。资金原模式的 `(?U)` 使用 Java Unicode White_Space，明确排除 Python 多出的四个 C0 字符；邮箱仍沿原 Python 完整空白集合，码点截取保留代理对及原长度边界。

微信来源昵称 NFC 复用共享 `normalizeCashNfc`，保持规范分解／组合，不做兼容归一或原文裁剪。生成器从迁移基线 JVM 提取私有规范分解、合法组合及 combining class，韩文按既有公式处理；工具期 JDK 内部 CCC 读取不进入运行时依赖。非法 UTF-16 按原 Normalizer 保留，组合阻塞／排除项和相同 class 的稳定顺序保持；长非 starter 串采用有界插入或线性排序，避免新增不受限平方开销。冻结数据更新须核对差异并评估 `CASH_RULES_VERSION`，不随终端 OS 或浏览器版本静默改变。

工作簿数值文本保留迁移基线 Java 21 的 binary64 最短表示，而非复用 Python 显示文本或端侧 Double.toString。共享现有精确中点区间选择器，Java 口径最短长度为 1 时从 1／2 位候选共同选最近偶数，再使用原科学计数边界与大写 E；最小次正规数仍为 `4.9E-324`。平台导出仅在绝对值小于 1e16 的有限整数去小数；CCB 对所有有限整数沿原 Long 饱和转换。这两种来源口径分开复用，不能借迁移扩大或统一金额／身份语义。以实际 JDK 21 全指数邻值、确定性位模式及原工作簿文档对照保护原行为；此原语不代表完整二进制读取器可用。[Java 21 数值文本合同](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Double.html#toString(double)) 是表示规则依据，不复制 OpenJDK 实现。

日期单元格保留 POI 5.4.1 的无时区 serial 日历口径：1900／1904 窗口由工作簿明确传入，1900 年的虚构闰日与次日沿原规则映射；先按 Java 21 最短十进制值计算，再舍入到毫秒；整日加窗口修正的 Int 溢出发生在扩为 Long 之前，仍按原次序处理。平台沿 LocalDateTime 的省秒／三位毫秒文本，CCB 沿固定秒文本，不读取设备时区。超常但有限的 serial 也保留原 BigDecimal intValue／longValue 截断及溢出语义，不借移植悄悄改成饱和转换或只接受年 9999 前的数据；最终业务日期资格仍由归一层校验。共享公历文本仅为该 raw 工作簿边界扩展，不决定现金发生时间资格；现金归一采用本 change 的独立 UTC 范围；日期样式识别单独复用固定内置编号与原可接受格式语言，保留转义、语言／颜色前缀、第一格式分段及 elapsed-time 规则；用独立字符状态扫描表达，不扩成通用 Excel 格式化器，不依赖平台正则默认锚点或进程缓存。原生以实际 POI 格式判定做完整内置／组合／随机差分后复用，日期值资格仍先按原非负 binary64 门检查。值型 XLSX 的 ZIP／XML 解码已连接本地入口，旧 OLE 保持服务端 parse-only；完整文件调度仍待接线。[POI 5.4.1 日期实现](https://github.com/apache/poi/blob/REL_5_4_1/poi/src/main/java/org/apache/poi/ss/usermodel/DateUtil.java) 用作行为 oracle，独立实现不依赖其 JVM 日期类。

银行记录表头、原文／位置、序号及声明覆盖由共享 `CashBankStatementTextReader` 复用；CCB 工作簿只保留 native OLE／POI 与单元格读取，工银亚洲 UTF-16 TSV 具有共享 byte 入口。UTF-16 保留原 Java REPLACE 及坏高代理项消费两个单元的行为，不改成严格拒绝或通用 UTF-8 口径。银行日期保持年 0 与年 9999 的翌日边界，覆盖证明仍按原上海时区转换，两来源不改成各自默认时区；文本 trim／空白及元数据正则保持原 JVM 字符集合。

字节文本按原 native 顺序严格尝试 UTF-8、再 GB18030，两个都失败返回不可读，不替换坏字节；仅去一次开头 BOM。平台 CSV 的 byte 入口复用原来源资格、100 MiB 输入预算和编码失败顺序，再交给同一 CSV 文档读取器；本地 CSV 与工银亚洲文本工厂把实际 byte 文档连接到本地逐行归一，不上传文件。工作簿仍由独立二进制读取器处理，不把 CSV 工厂当成完整文件分派。GB18030 的 23,940 个两字节位置与四字节空间由现有 JVM Charset 穷举，四字节映射压缩为 222 个线性区间，数据私有并带内容校验；各端不依赖浏览器／系统字符集。字节／ZIP 预算仍由读取器负责；工作表深度、物理行、单元格坐标和列边界独立共享，由原生 StAX 入口复用。该守卫不替代 XML 语法解析、工作簿单元格解码或完整文件调度。编码表变化须显式重生成、比较并评估规则版本，不能随宿主版本静默变化。

工作簿预算预检须以实际解压字节计数，在累计 100 MiB＋1 字节即停止，不能先无限制 readBytes 后再判断。当前 native 的 64 KiB 片段 XML 校验会误拒合法大表，亦无法对片段后的真实坐标给出正确预算错误；恢复为预算内完整工作表 XML 交给同一守卫与 StAX，非工作表部件只限量排空不保留；100 MiB 只约束实际解压累计，工作表缓冲扩容／复制和后续 POI 仍有额外堆开销，不将其称作总内存上限。目录项即使使用未知大小的数据描述符，也按实际内容拒绝非空目录；成员数、重复名、后缀、DTD／实体、坐标及解析内容预算保持，源数据与期望不改。该修复为后续端侧 ZIP 读取保留同一安全边界，不将 native 预检缺口当作应复制的格式限制。

来源时区仅需现有上海、香港两套有限历史规则；将迁移基线 JVM ZoneRules 的全部切换点固化到模块私有数据，由生成器与独立 `LocalDateTime.atZone` 向量核对。既有时区均无未来循环规则，生成器遇到循环规则时拒绝更新并要求重新评估；不增加通用时区引擎或平台依赖。共享转换保持夏令时缺口前移、重叠选较早偏移及未知来源 UTC；数据变化按同一规则版本治理。

关系端点／角色与关联闭包规则迁入共享 `CashRelationPolicy`，后端保留类型别名及 JVM 数值输入桥接。该规则只需精确符号、数值相等和绝对值相等，不引入新的财务运算或舍入口径；图分配仍由现有后端规则校验，后续独立下沉。稳定分组复用共享码点顺序，返回集合保留不可修改快照语义。

来源流水匹配视图与核心谓词／稳定标识／顺序使用共享 `RelationFact<A>` 和 `CashRelationCoreRules<A>`；唯一数值参数保留迁移期后端 BigDecimal，端侧使用 CashAmount。符号与旧 JVM 时间值由薄适配传入，不复制领域判断；匹配算术、日期候选索引及图分配仍按独立切片下沉。共享 UTC 时间文本由纯日历运算生成，不依赖平台字符串格式。

候选索引按 UTC 日期文本分桶并使用共享来源流水视图；金额只生成精确绝对值键，未做二进制金额转换。后端传入原 BigDecimal 键和 JVM 时间／日期适配，端侧使用 CashAmount 与共享时间／纯日历运算。退款候选仍采用现有 15 天加 1 天索引宽限，实际匹配窗口仍归匹配器；无日期的转账候选回退与同输入顺序保持。日期范围仍按原 ISO 文本比较；索引仍保留原 ISO 文本比较；现金业务范围已限定 UTC 1900..2100，合法事实的扩展窗口不会触及 `+10000`。通用索引的宽域原语测试不代表支持范围外现金事实。

配对提案与证据模型、退款文本门和菱形链路匹配共用共享 `CashRefundSignals`／`CashRefundDiamondRules<A>`。后端保留精确金额余量比较和原时间差适配；端侧使用 NUMERIC(38,18) 的精确整数位串比较 `|支出| + 0.0001 >= |退款|`，不引入二进制金额或新的舍入口径。证据中的退款金额保留原十进制表示的尾零。旧内部 Map 序列化口径保留；共享 `toJsonValue` 在字段类型尚可知时编码证据的整数计数和时间差，避免 JS 的 Any 数字擦除把 0／1 写成 0.0／1.0；开放 extras 仍由调用方值适配器编码。

标准转账、定向转账与个人购汇的 Phase C 迁入共享 `CashTransferMatchRules<A>`，复用既有流水、候选索引及提案模型。后端保留 BigDecimal 数值／时间桥接，端侧以精确金额比较与十进制位串差值保留证据 scale；匹配窗口、贪心占用顺序、账户标识歧义及 seed 选择语义不变。账号中的正则空白明确采用原 JVM ASCII 集，避免 JS 的 `\s` 扩大识别范围。


关系几何规则共享日期证据优先级、UTC 业务日、卡尾、镜像代表与连通分量；后端保留 JVM 时间／日期对象边界，端侧使用既有共享时刻与纯日历函数。保留原小数点截断后再解析业务日期、原年 0 短日期和无效日期信号语义，不在迁移中修订匹配规则。卡尾英文 ending 显式包含原 JVM 忽略大小写支持的 `İ/ı`，避免 JS 默认匹配范围变窄；非金融原始 Any 值仍沿调用方输入适配合同，不能据此宣称任意对象字符串化已跨端统一。


关系计划模型与提案稳定引用／摘要键迁入共享层，摘要只编码既有字符串、null 与候选引用数组，保留排序与重复候选。后端仍适配原始行值、时间与退款余量。原 JVM SHA-256 的 UTF-8 不合法代理替换保持为问号，合法 Unicode 按码点顺序与标准 UTF-8 编码，避免平台默认替换字符造成提案键分叉。


完整镜像配对迁入共享 `CashMirrorMatchRules<A>`，复用共享事实、几何与候选索引；数值仅需精确等值、绝对差文本和去尾零金额键，不增加舍入。后端保留 BigDecimal、时刻与原对象文本适配，端侧默认以 CashAmount 精确运算及等价 BigDecimal 金额文本构建比较对象。镜像证据 lag 仍是整数，端侧生产边界以 `SourceJsonInteger` 类型标记显式保存整数语义，避免 JS Any 进入 Double 分支；不修改全局来源浮点规则。


平台退款编排使用共享 `CashPlatformRefundRules<A,T>`：A 为原始金额适配后的精确值，T 为原始时间适配后的时刻。状态门、平台硬键、金额比较、窗口、最近唯一及重复占用规则单份实现；backend 保留 BigDecimal 原始值解析、原 LocalDateTime 宽松格式与 Duration 纳秒／溢出语义。端侧原始值适配仍需单独核对，不能把测试适配器视作生产日期解析已迁移。


Phase A 平台硬键汇总使用共享 `CashRefundHardKeyRules<A,T>`，复用同一平台退款规则与来源流水模型。来源身份分组、订单／商家键优先、冻结解冻、投资流出例外、剩余额度递减和微信退回组合保持原序；金额适配仍由当前宿主提供，不把 test-only 原始值入口纳入生产。


商户退款排序迁入共享 `CashRefundMatchRules<A,T>`，保留强弱证据、额度、事件折叠、最近候选与 open-leg 决定。精确金额值实现 Comparable，与既有数值等值一致；时刻差以宿主精确纳秒输入，保持原 Duration.toNanos 的溢出和正区间整秒。商户文本正规化仍保留 JVM 适配，端侧生产配置尚未接入。独立差分确认单标量映射一致，但 Java ROOT lowercase 的 Σ 取决于 UTF-16 偏移和有状态边界查询；不能改用 Python／浏览器 lower，也不能把静态词分组当作等价实现。失败的近似已退出生产源码，完整 21,309 原样 oracle 向量与全标量摘要、反例和原型保存在仓库外；后端行为未改变。后续只验证过滤后字符域的私有边界查询模型，保持每个 Σ 的查询次序和缓存；不复制 OpenJDK 源码或转换表，不为过测试缩减样本。


关系发现总管线迁入 `CashRelationPipelineRules<A,T>`，统一复用已共享镜像、转账、菱形与商户退款规则。上下文及剩余额度按同一 A 传递；加减、原始金额解释与零值由精确数值适配提供，不能把中间累计额强制压入事实字段的 NUMERIC(38,18) 限制。后台继续使用任意精度 BigDecimal；端侧生产累计值适配须另行完成，规范夹具的 CashAmount 测试适配仅证明编排等价。

关系计划的稳定引用序列化、事实明细形状和退款余量初始化迁入共享规则。原始行转义／平台对象解析仍由既有 backend 适配；递归 cache 容器逻辑共享，标量值保留宿主解释。计划内已知整数在 common JSON 出口显式编码，不能因 JS Any 类型擦除把 version、候选数和秒数变成浮点文本。

缓存计划的稳定引用解码、决定复用、组成项展开、别名索引和退款全额剩余额度迁入共享 `CashRelationPlanCacheRules<A>`。整数与真假等原始值解释保持宿主适配；图合法性仍使用现有 planning／projection 校验，待图迁移后整体接入端侧。摘要或引用失效继续抛出原重新核对错误，不静默复活决定。

投影累计使用模块内 `LedgerArithmeticValue`，与持久化字段 `CashAmount` 分工：前者仅承担计算中的精确加减、比较及原 80 位 HALF_EVEN 舍入，不定义新事实、DTO 或存储字段；后者继续独占 NUMERIC(38,18) 边界。复用 `DecimalRepresentation` 和位串算术，保留原 scale 与 BigDecimal 风格文本；端侧关系汇总接收 CashAmount 事实并返回精确金额字符串，避免把超过单笔范围的合计再次强制转为 CashAmount。原始平台字符串解析不借此放宽。

投影共有枚举／失败类型、确定性连通分组、单根树校验、转账标签及来源排序迁入共享层，native 用类型别名和薄函数复用；图标识保持泛型原比较器，不把任意长数字转 Double。此处只迁移原拓扑与排序规则，不新增图输入接受范围，也不替代金额／组成项图校验。

逐行投影模型使用共享 `CashProjectionFact<I,T>`／`CashProjectionRelation<I>`／`CashProjection<I,T>`，I、T 只隔离平台精确标识与时刻表示，金额继续为同一 CashAmount。私有构造与私有 copy 保持；创建时通过 `CashProjectionValues<I,T>` 校验平台标识、时刻并正规化币种，共享层负责原业务状态与金额条件。backend 用 BigInteger／java.time.Instant 类型别名和 companion 扩展保持原 create 调用；不建立第二套投影事实。只修改注意状态和公共文字的受控方法不能改变已校验的标识、时刻、金额和状态。

## Goals / Non-Goals

**Goals:**

- 端侧在无网络时能浏览账本并完成导入预览与提交。
- 服务端不再承担导入启发式计算与投影物化，只保存规范事实、校验不变量并同步。
- 三端（Android/iOS/Web）与共享模块使用同一份领域规则，避免多份漂移。
- 在多设备共用同一账本时，冲突以可识别的拒绝暴露，不产生静默认。

**Non-Goals:**

- 不做变更日志/增量差量（本期以版本 + 全量快照替代，仅保留可升级形状）。
- 不引入 CRDT、现成同步引擎或自动合并。
- 不砍余额能力，不纳入投资导入与估值算法。
- 不做多人协同编辑。
- schema 生命周期沿当前 Kotlin 运行时：空库加载基线 SQL，非空库严格校验，不恢复 Python／Alembic。

## Decisions

### D1 一致性模型：服务端权威，自研最小同步

**决定**：本期采用“服务端权威 + 端侧完整事实缓存”，以版本查询和一致性全量快照完成同步。查重、配对、投影与统计在端侧运行，服务端校验不变量并原子落库。

金额、关系端点及退款额度的并发决定沿用本变更的基线校验和重新核对合同，不引入自动合并。CRDT 本期不作为账本的合并机制；若后续具体能力需要协作编辑，应先定义该能力的冲突语义，再评估合适机制。现成同步引擎本期不接入，PowerSync 保留为改造完成后的实验备选。自研变更日志本期亦不实现，避免提前承担日志、保留窗口与剪枝。

**PowerSync 实验边界**：改造完成后，另拉分支和临时环境比较自研最小同步与 PowerSync。实验可使用 PostgreSQL 单源，也可尝试实验性的 Web／Wasm 支持；若减少代码复杂度，可以接受更高的服务端算力／存储开销。这些取舍已获用户认可，不作为启动实验的否决条件。本期主线仍按现有双后端合同实现，实验不提前改变主线存储范围。

实验前固定本期完成实现的基线、同一组合成账本与客户端环境。至少覆盖 1 万／5 万条流水的首次同步、单条变更后刷新、批量导入后刷新、离线恢复、多设备收敛与断网重试，记录延迟、流量、客户端和服务端资源。自研版本查询命中与版本变化后的整包刷新分开测量；不预设增量方案在所有场景都更快。

比较同时核对领域写集的原子性、服务端拒绝后的本地恢复、基线冲突重派、原键核实、工作区隔离、金额精度与静态加密。自动回滚、上传批次和拒绝传播等行为以实验所用版本的实际结果为证据，不预先假定 SDK 已满足。Sync Rules 等同步配置与 Kotlin schema 生命周期分别核对，记录额外维护面，不把同步配置视为 schema 所有权冲突。

报告列明同步／缓存适配代码的实际增减、领域代码是否受侵入、服务部署和运行成本，以及实测性能与合同缺口。切换判据依据本期基线和可接受的用户流程耗时制定，不以单一性能数字自动决定。实验结论用于后续方案选择，本 change 不维护两套同步实现，也不要求先出现性能故障或等待 SDK 稳定才开展实验。

### D2 同步机制：工作区版本 + 全量快照

**决定**：服务端为每个工作区维护单调递增的账本版本，与写入同事务推进。端侧记录已同步版本；刷新时先查版本，仅当变化才拉取全量快照，并以快照版本原子替换本地缓存。快照在单个只读事务内锁定版本 `V`，分页也不跨版本。

**理由**：在已放弃差量的前提下，这是实现最简且语义最强的状态同步；版本号同时服务于并发基线与"是否需要重下"判断。

**备选**：时间戳轮询（时钟/删除语义不可靠，否决）；整包无版本盲拉（无法判断是否需要，否决）。

**回滚/升级形状**：端侧保留 `last_synced_seq`、服务端保留版本与快照接口；将来加增量只需新增接口，不动既有契约。

账本版本保存在 `workspaces.ledger_seq`，初始为 0，保持非负有符号 64 位整数；现有工作区锁继续承担写序列化。托管事务按工作区合并版本标记，首次标记与事实写入共用连接；事务回滚一并恢复。托管连接记录具名／JDBC 保存点处已有的版本标记，回滚时恢复该保存点状态并丢弃内层状态，释放时清理对应保存点。保存点后首次取得的行锁可能因回滚释放，因此不能把重读的相同版本值推断成自己的推进；回滚后重做首次标记须重新锁行并基于当时版本推进。业务版本读写使用生成的 jOOQ 字段，SQL 词法识别仅用于跟踪事务及保存点边界。未触及规范事实的读取、会话和收据写入不标记；各规范事实写入口必须显式接入，不根据 SQL 文本或任意 `Database.write` 猜测。元数据列纳入两套 Kotlin 基线 SQL，版本统一为 20261104_54；jOOQ 从同版本专用 PostgreSQL 18 库生成。启动只初始化空库，不自动升级已有 53 库；已有库须显式升级并校验字段及约束，不仅修改版本号。

目录事实入口分别复用自身的既有事务边界：账户命令在收据重放与修订核对后、实际写入前标记；分类目录在修订推进处标记，多行移动仍共享一次账本版本；别名写入和账单账户映射发布在真实插入／更新时标记。映射同值重发和分类边界重排不标记；明确拒绝及晚期失败由外层事务回滚事实、版本与收据。其余现金事实仓储仍按任务 2.2 逐项接入，不以目录入口覆盖代表全写入面完成。

版本查询端点为 `GET /api/v1/ledger/version`，仅返回 `ledger_seq` 十进制字符串，避免 Web 数字精度损失；不接受任意工作区作为数据选择器。沿当前会话选定工作区鉴权，并核对路由捕获的用户／工作区与实际读取及返回前上下文一致；viewer 可读取，失效或未选定工作区拒绝。版本读取不写入缓存、收据或任何业务表。新增 Kotlin API 元数据在 `compose/backend/openapi-additions.json` 维护，并与已提交运行时资源保持一致；旧 Python 导出器已退役，后续元数据更新以 Kotlin 资源及 OpenAPI 契约测试核对；重复路径／组件显式失败，避免重新生成时丢掉新增 API，不改变运行时文档的单一资源入口。

全量读取端点为 `GET /api/v1/ledger/snapshot`，响应封装选定的 workspace_id、ledger_seq 与类型化事实集合。代理键、修订和金额以十进制字符串传输，UTC 时间保留微秒；不透传数据库记录或账户私有 metadata。集合覆盖账户、别名、账单映射、分类及目录修订、全部现金流水（含草稿与删除标记）及组成项、来源绑定／空页证据、关系／候选、问题／候选、entry／成员和只读资金对应。来源文档证明复用绑定 coverage 与空页，不构造不存在的文档表；完整投资事件、余额、物化投影、收据与会话不输出；已接受且生效的资金关系附带所关联资金事件的最小只读字段，见 D12。

双库快照合同以同一份固定合成输入和完整期望对象验证全部事实集合；ID、时间、金额与 JSON 不做输出归一化，工作区仅在会话 fixture 中替换。私有元数据与完整投资事件仍不进入现金事实快照，关联资金事件只复制 D12 指定字段。

首个实现返回单份全量响应，不开放分页游标或独立实体拉取；数据库读取在同一事务完成，PG 使用 REPEATABLE READ，SQLite 使用同一 WAL 读快照。读取 V 之后其他设备提交也只返回 V 的事实，返回前复核会话后才交给 HTTP 序列化。后续按既定规模基线判断分页／流式需求，若引入分页须保留同一快照边界，不逐页重新读取当前版本。

快照响应额外携带 `rules_version`，取共享 `CASH_RULES_VERSION`，与事实版本 `ledger_seq` 分别表达规则语义和数据状态。轻量版本查询仍只返回账本版本；应用自身共享规则版本变化也须使本地派生失效，不依赖再次下载相同事实。

候选召回的查询规划提取为共享纯规则：候选类型、合并的 ±61 天窗口、纯负消费门及按来源／账户范围／现金账户聚合的硬键请求共用一个定义。backend 继续执行原 SQL、工作区资格和来源分类；端侧入口只生成同形查询，不把查询规划误记为已完成本地候选读取。来源行存在且账户范围为空时不能回退操作范围；元数据显式 null 不使用平台编号回退。支付宝订单拆分前缀和原始交易号前缀查询分别保留，硬键路径不受时间窗约束。SQL JSON 字段取值及本地事实查询另验，不在此片擅自统一数据库行为。

关系选择的失效保留与 generation 推进由共享纯规则执行，backend 保留原 BigInteger 解析／递增／摘要表示薄桥。generation 是选择失效次数，不是账本版本或金额；本片纯 applyChoices 核心沿用原 BigInteger 槽，不追加 Long 或金额筛选的 20／18 位限制。端侧使用已有精确计算值及 JSON 整数词法，验证超过 64 位的核心运算／摘要保真；既有 CashImportChoiceContext.validated 仍要求非负且严格小于 Long.MAX_VALUE，本片不修改该上游范围，也不宣称完整保留上下文或预览接受无界计数。当前提案消失／候选变化时继续记录失效选择并推进来源 generation，不能因原指纹再出现自动复活旧选择；同一轮用户新选择仍优先。JSON 入口复制当前组后返回结果，不修改之前核对的计划。图应用由 D7 的独立共享规则验证；完整关系组生成和端侧预览接线仍待完成。

本地关系上下文读取从同一完整事实快照建立既有确认关系闭包：只有确认且生效的双向边扩展父流水，草稿边仍进入上下文但不扩展闭包；显式决定组包含其全部历史成员。保留草稿／已删除父项的修订和组成项元数据，正式投影事实只来自未删除 posted 项。资金、问题、来源排序和 entry 依赖沿原资格及精确文本读取，不因全量缓存读取无关流水或改写用户字段。本地入口不写事实，也不进行完整预览／建议或最终落库。

关系上下文的只读模型共享到 domain，以投影标识／时刻类型参数保留 native 值适配，修订、组成项、资金对应、问题及 entry 快照仍是原有精确 Long／字符串。上下文 token 只记录原顺序的依赖元数据，使用原 ASCII 字符串转义和紧凑列表文本；不混入种子、事实展示或运行对象。backend 以 typealias／薄委托复用，SQL 闭包读取、权限与事务仍在原仓储。模型及 token 本身不负责读取事实，也不新增网络 DTO；本地读取由前述快照入口承担，完整预览仍待接线。

计算值预览摘要继续与来源摘要分开：CashAmount／CashDecimalLiteral 使用原 Decimal 字符串（保留小数位与负零），时刻使用原 UTC 微秒文本并以空格分隔日期时间；递归处理原 Map／List，其余值仍交既有来源摘要。共享实现及端侧生产适配不把计算值先渲染成通用 JSON 再猜类型。预览虚拟标识继续以来源摘要的前 128 位加 2^64，精确整数文本仅隔离端侧缺少 BigInteger，不改原摘要空间或持久标识。backend 通过原时间和 sourceDigest 薄桥复用，原预览／关系组全量结果须保持。

核对页公共字段选择的目标索引、稳定 edit_ref、依赖摘要与补丁应用下沉同一 `CashImportEntryChoiceRules`。backend 保留原 BigInteger 边排序、值归一／深复制和 import digest 薄桥，继续复用现有调用点；端侧 JSON 补丁入口使用既有本地值策略，先复制完整计划再应用，不修改上一次用户确认结果。编辑仍限制公共字段，目标或依赖变化拒绝，分类资格由当前范围目录判断，不通过重算静默丢弃用户选择。完整端侧目标组装／计划生成仍另验，此规则迁移不代表核对页已接通，也不改变既有清空或保护语义。

现金输入校验的 UI 范围仅为原表单错误反馈：信息架构、日期／时间选择器、保存动作、布局和 token 沿现有 Compose 页面，不新增说明区域或删除字段。已通过真实 Chrome 阅读 Material 3 [Text fields overview](https://m3.material.io/components/text-fields/overview) 与 [specs](https://m3.material.io/components/text-fields/specs) 正文，采用可辨认状态及准确、可操作的校验反馈；本片不替换组件 API。Hallmark 按既有 FinanceTheme／FinanceTokens 与表单范围审查，不做页面结构或主题重设计；源码预检发现原日期提示未覆盖年份范围，修正后仍需实际浏览器检查错误呈现与修正恢复。

### D3 计算边界：端侧执行导入阶段 1–7，服务端承担 8–10

端侧 XLSX 的 ZIP 遍历在保留部件前完整验证每个 XML／rels；是否应用工作表坐标预算只由该部件根元素的 localName 决定，不由路径或活动表选择决定，与现有服务端预检一致。未选中及非标准位置的工作表同样受行列预算保护；普通 XML 的 row／c 同名元素不冒充工作表。公式仍仅在消费选中账单工作表时按既定不支持口径拒绝，不扩大到未消费部件的业务解释。

来源持久化先从旧 writer 抽取内部 `CashRecordValueWriter`，只保存已由调用方准备的父流水及组成项，不自行执行条目编辑、类型关系维护、来源绑定、问题清理或候选失效。组成项删除前的引用修复作为必填回调保留，旧入口仍在原时点调用原修复逻辑；不得用空回调绕过确认关系保护。旧入口保持真实父项读取、来源变化判断、父项保存、C、组成项、类型维护、绑定、问题和候选失效的原顺序。该内部 SQL 原语不是公开写集合法性或授权边界；新提交服务仍须在同事务内读取真实旧事实并组合完整校验及后续阶段。

**决定**：端侧完成解析、行归一化与类型分类、对缓存账本查重、账户归属、操作计划、候选召回、关系配对，并以**单个原子写集**提交；服务端校验结构与业务不变量、落库、发收据，**不重跑启发式**。

新写集入口只承接文件导入及其核对选择。无文件的来源事项采用／保留、身份草稿合并、删除及主动关系拆分继续沿既有后端命令执行；本轮只移除这些命令的物化投影依赖，不迁移其计算入口。原文件来源读取只允许 live 的 import／legacy；已正式的金额、类型和组成项受固定策略保护，核对的关系组只增加候选决定，不提供当前关系 remove 命令。新入口须从真实事实重新执行这些边界，不能仅信任客户端声明；现有通用 writer 的 type_changed 分支并不证明正常文件导入可以拆分旧确认组。共享辅助规则和 DTO 能表达维护动作，不代表新入口允许执行它们。 范围门先复用引用与固定字段校验，再拒绝父项删除、无文件来源事项／拆分决定及已有关系重写；被更新的父项须是 live import／legacy，不把这条来源资格套用到只读关系端点或上下文。来源绑定不能从另一 live 父项迁移，已软删旧父项的绑定仍按原复用资格处理。该门只核文件动作范围，不替代来源真实性、候选证明、账户、保护字段、完整图与最终条目效果。

写集入口独立于旧暂存计划的信任边界。旧 CashImportCommitWriter 依赖服务端重新生成并比较完整计划；CashRecordWriter 本身只归一字段，不能直接接收客户端声明的 current、type_changed、manual_fields、账户或修订证明。新服务在重新鉴权、同键收据重放和同事务基线守卫后，批量读取本工作区的真实事实、组成项、账户、来源证明、当前问题和完整关系闭包，从数据库构造变更前状态，再校验允许的字段变化、修订、账户可用性／类型／币种、现金时间及正式／草稿完整性。余额影响只取实际变更前后值，不能从客户端旧值或统计结果计算。

客户端引用必须在单份写集中单义解析：新建父项和组成项不能有重复引用、重复 ordinal、映射碰撞、错父组成项或悬空虚拟引用。关系决定必须与边状态、成员、锚点、候选证明和证据一致，再用已有纯图校验和真实闭包验证角色、额度、占用及联合组完整性；把客户端同一份关系同时充当旧 plan 和 fresh 不构成校验。候选修订／资格变化不能通过跳过候选或更新其预期修订静默变为有效。entry／成员及公共编辑须核对客户端预期修订和目标依赖、完整成员、本工作区分类及字段白名单，不能用刚从数据库读出的修订替换客户端预期值。

写集传输模型独立于只读事实 DTO。请求只包含基线、规则版本和最终增量，不包含原文件、服务端暂存计划或客户端统计；幂等键沿请求头传入。引用显式区分已有 ID 和本次新建引用，所有 ID／修订／版本保持字符串，不能把完整虚拟 ID 压入 Long 或 Double。新建引用仅在该提交内解析，不作为已有数据库 ID；服务端仍须检查类型、唯一性及引用闭包。

原键收据重放及基线守卫后，服务端仍须按数据层幂等规则解析已应用创建的来源／关系身份，再对最终增量执行引用与图校验。只有证明同一事实时才能解析新建引用并去除无变化写入，异值同键不能自动合并，也不能给原有目标补造客户端预期修订。引用预检的唯一键拒绝不替代“相同关系指纹已应用并幂等成功”；该身份解析、收据与原子写入仍须由完整提交服务另行实现和验证。

引用预检按实体类型建立本次声明和存量索引，已有对象只能从服务端该工作区事实中解析。已有目标／交易依赖核对规范正 Long 修订，新建声明／依赖不得伪带已有修订；写入与删除不能重复声明同一目标。组成项核对原父归属及规范非负 ordinal，保持既有 Int.MAX_VALUE 上限；更新父项后按最终完整组成项集合检查本批显式关系及候选的端点，不能继续引用已移除部分。未修改存量关系／候选的完整引用闭包仍须由后续服务的数据库闭包和图校验覆盖。账户、分类和条目成员也按各自实体范围检查，不用一个无类型字符串映射解析所有对象。来源绑定、映射、问题的自然键及成员归属从存量中扣除明确更新／删除／解决的对象，再加入最终值；未修改对象仍占用其键，不能只对请求内集合去重。该纯预检只接收调用方提供的事实，不能承担鉴权、基线锁或证明事实可信；服务必须在同事务内从真实数据库取得事实。预检通过不代表金额、角色、状态、保护字段或最终关系图合法，不能作为直接落库凭据。

交易写入携带完整最终值和组成项，组成项随父交易修订受保护；关系及其候选、问题及其候选、条目及其完整成员分别表达，来源绑定、空页证明与账户映射纳入同份增量。非条目的删除／解决以带预期修订的显式目标表达，不以遗漏列表项猜测跨实体删除；条目的退休集合按完整业务分组与旧依赖由服务端协调产生。创建／更新时间、操作者、工作区、实际修订与账本版本均由服务端生成，传输模型不开放这些可写字段；候选的预期交易修订属于依赖证明，不能与服务器生成的实际修订混同。开放的来源／证据 JSON 继续使用既有精确数字序列化器，公共金额／时刻保持文本。仅完成 DTO 不能视为已完成输入校验、合法性校验、落库或写集端点。

最终写集的金融值归一复用既有记录值与组成项规则：所有已提供的现金金额、币种和时刻均先校验，草稿允许缺值但不能包含相互矛盾的已知值；正式流水要求完整账户／类型／组成项。归一结果返回同一写集类型，金额以精确十进制定点文本、时刻以 UTC 微秒文本供后续写入使用，不能校验后又保存未经归一的原文本。负零和小数尾零按既有存储文本边界保留；关系关联金额只在本层验证精度与归一，角色、符号和额度由完整图校验判断。来源／证据 JSON、引用及其他非金融字段原样保留。这一纯函数没有调用方事实，不能证明账户资格、来源与保护字段、状态迁移、关系图或写权限合法，也不作为完整命令验证凭据。

固定字段预检从可信存量流水和组成项构造原值，按原 CashRecordPolicyRules 核对创建方式／来源身份，以及正式导入或历史流水不可修改的金融字段与类型；不能以客户端声称的新创建方式改变原对象的可编辑范围。金额和时刻按既有语义比较，不能因等价文本格式不同误判修改；组成项标识仍参与冻结判断，新建引用不能假扮已有组成项。导入新建对象的创建方式固定为 import，不能携带手工转账组标识。固定约束通过后，既有正式流水仍不允许退回草稿，保留原导入及当前维护的状态方向；草稿保存及转正式保留同一身份。该预检不决定手工标记、来源保护、转正式所需问题处理或账户资格，也不把完整最终 JSON 当作本次明确手工操作；这部分仍须结合真实调用与显式意图另行校验。

交易的 `edited_fields` 仅表达来源流水自身的明确编辑，条目的同名集合表达协调完成后的公共编辑，值分别取各自最终字段。行核对的前置公共补丁另由交易写项的可选 `entry_edit` 保留 patch 原值与 presence，不能从来源最终值、最终条目或成员独立值反推；公共补丁不写回来源事实。其 entry 字段必填且可空：已有对象引用须带真实旧修订，并与该父项的真实旧成员归属一致；显式空值表示此前没有条目，必须由服务端事实验证，新建父项不能冒用已有条目。 写集传输必须显式保留必填 nullable 字段的 JSON null，不沿用会省略这些观察值的客户端通用 JSON 配置。前置 patch 仅允许非空的五公共字段子集，明确分类引用按当前工作区目录核对；历史成员独立分类的只读豁免不适用于这次新编辑。明确空值／空文本也属于编辑。字段集合来自本次稳定用户选择，不从最终 `manual_overrides`／`manual_fields` 差集猜测：旧备注及保护标记不变而备注值改变，既可能是明确再编辑，也可能是错误自动覆盖。服务端按真实旧状态和字段白名单处理明确编辑，正式流水公共编辑仍落条目；最终保护标记只作为待核对的结果，实际标记由旧事实、合法编辑与既有公共值合并／拆分规则推导，不能直接保存客户端 JSON。成员独立公共值与人工标记同样须与真实原状态及合并／拆分规则核对。

关系选择的合并前公共补丁与行前置 entry_edit、归并后条目 edited_fields 分开表达。写集用单一有序 relation_groups 列出本次所有新关系选择组及其完整关系引用分区；不只列 accepted 组，也不让 relations 数组隐式承担另一份执行顺序。每组的 common_fields 是端侧已完成核对计算后实际生效的部分公共补丁 B，包含明确选择和原规则自动继承的结果。原始用户补丁继续由端侧稳定输入保留，用于刷新后重新核对，不让服务端重选默认值。缺省与空对象都表达生效补丁为空，对象本身不得为 null，内部五字段仍允许明确清空；仅 accepted 组允许非空公共补丁。即使最终公共值相同，也不能由最终条目反推这份选择或省去原合并前的执行次数。

服务端先验证新关系引用完整覆盖、无重复或跨组重叠、无存量关系混入，以及组内边状态一致并由其推导动作。文件新关系必须保持 active=true；accept、defer、ignore 仅改变状态，不借此入口创建失效历史关系。公共选择只作用于该组实际边的两端父项，沿原排序去重；旧确认闭包用于图和联合分批，不扩大公共编辑父集合。联合批次由可信旧确认关系、全部本次边及选择组边分区按原纯分组规则重建，不信客户端 decision_group_id 直接指定批次；按有序组的首次批次位置及批次内原组序执行。服务端核同一联合批次全部 accepted 组的归一化 B 字段集合、presence 和值一致；从真实旧条目及行前置编辑 C 推导公共人工字段集合，要求 B 覆盖该批次原扫描范围内全部正式多成员投影的这些字段，包括明确清空后仍保留的人工标记。任一这些字段缺失即拒绝，不能以最终条目自证或省略原批次传播；集合为空时才允许生效空补丁。额外合法公共字段作为本次 B 明确选择。服务端不重选自动继承首值，仍按每个接受组及其真实端点执行原 chooseCommon，不合并执行次数。该过程只校验已给出的关系与编辑，不重跑发现或配对；不能把不合法选择降为部分成功。相同关系整批精确幂等命中时，连同其公共选择一起消费，不重复执行 chooseCommon 或留下无新关系的公共编辑入口。原键收据重放仍先于这些处理。内部 prepareCashImportWriteSetRelationBatches 已复用同一纯联合分组规则，以私有 typed 引用键隔离新旧标识、保留全部边及选择组分区，再按明确组顺序排列批次；不分配存储 ID，不计算公共值继承，也未接事务。内部 prepareCashImportWriteSetCommonChoices 另组合输入归一、同一最终确认图及可信旧 owner 的 post-C 人工字段索引，核每批接受组 B 一致且完整；新父和无旧 owner 的补丁按类型化父引用隔离，同一旧 owner 的前置编辑传播给其全部成员。按投影整数索引去重，每个命中投影只遍历一次，不反复 hash 完整成员集合；仅返回已归一选择批次，不写入、分配身份或证明完整效果。

条目结果校验先复用原 CashEntryRepository.reconcile 的纯协调规则：稳定身份选择、原公共值及人工值合并／拆分、成员独立值恢复、修订推进与共同字段冲突保留单一实现。条目／成员模型的流水标识参数化，存量读取继续为 Long，端侧新建对象可保留精确虚拟整数；不改变存储或 wire 类型。协调核心复用已有 CashProjection，并注入原生存储标识与精确标识转换，保留原正值／溢出错误边界及求值顺序；新成员缓存登记回调保持在原创建时点，避免后续冲突或 savepoint 恢复时丢失已知对象。SQL 读取、插入、flush、拆分标记清除和空条目清理仍由原仓储按原顺序执行。协调输入的成员集合仍仅限原 forTransactions(ids) 返回的选中成员，不扩大为条目全量成员，也不因新成员登记回写本轮旧成员索引。协调器沿原语义原地修改条目／成员对象，后续期望结果校验必须传入与真实仓储缓存脱离的副本；结构及公共值变化可分别推进修订，保留 Math.addExact 的溢出异常，不合并成一次推进。原文件计划将同一旧条目的行公共补丁合并并拒绝冲突；新写集须先对全部原始前置编辑验证真实旧归属、旧修订及不存在观察，再用写前成员 owner 合并至首个有补丁的交易写项；后续同 owner 补丁移除，但旧依赖读集、交易顺序和来源值保留。新建及原无 owner 父项各自独立，不能按 null 或最终条目归并。相同字段按已归一值及 presence 判冲突，分类明确 null 仍算已提供；与原操作规则共用小型补丁合并原语，保留原逐补丁处理及失败时点。内部 prepareCashImportWriteSetEntryEdits 已按此返回归一副本；mergeCashImportEntryPatch 由原操作规则和写集准备共用，原操作的逐项 entry_edit_group 标记及整组成功后移除后续编辑的时点不变。准备器不执行 applyEdit，也不接实际写集事务。前置编辑在实际流水保存后、关系公共选择及协调前按原 applyEdit 执行，新父项的批量创建路径保持相同顺序。协调后的 entry_choices 继续后置执行。来源备注 S、行公共补丁 C、归并后的公共备注 D 可以合法不同：最后来源仍为 S，多成员条目为 D，对应成员独立备注为 C。服务端必须重放这份明确前置意图，不从客户端提交的独立结果反授权。共享协调器仅为合法性校验提供期望公共值和标记，不生成浏览物化投影，也不把客户端最终人工标记直接作为权威。公共字段显式编辑同时复用原仓储 patch 的修订检查、字段归一、人工标记合并与单成员独立值更新规则；已有同值及明确清空行为保持原合同，不在共享迁移中改变保护语义。成员查询仍由仓储在实际变更且条目更新之后执行，溢出及查询故障的原对象状态与事务回滚责任保持；本地期望值验证使用独立副本。

通用模型中的 `entry_split_choices` 与共享拆分恢复规则保留既有无文件维护语义，不作为新文件导入入口能力。该入口不删除正式父项或主动拆分旧确认组；旧稳定对象的完整成员及身份锚点须在同一最终组内继续存活。此约束由真实旧确认图及完整成员核对，不能用请求中的选中成员或最终字段自证。

现有通用传输模型的 `issue_resolutions` 能表达 apply_source、keep_existing、create_independent 和 merge_into；这些无文件来源事项动作不属于新文件导入入口，不能仅凭带修订引用而开放。既有维护命令继续从同事务真实问题及正文验证动作资格，导入写集中的 resolved_issues 只表达经本次合法导入证明的问题退役效果。新入口接线前须收敛其公开可写合同并测试拒绝越界动作，不为复用现有 DTO 扩大用户范围。

来源事项补丁准备复用共享 CashSourceIssueResolutionRules：保留正文 presence、问题实例与修订、动作资格、先固定／结构校验再显式冲突裁决、组成项归属及 ordinal 唯一性。原生层仅注入字段值／JSON 复制及原摘要实现，并将明确的问题变化异常映回既有 ReceiptConflict；不捕获程序异常，不把 merge_into 的身份转移与完整效果校验混入该准备器。端侧生产桥使用同一 LocalCashRecordValues、精确数字词法及正文摘要，准备出的 patch 仍可能含受保护候选字段，后续必须按既有策略应用，不能直接落库。共享规则不代表写集动作与最终增量已建立对应关系，事务服务仍须真实读取问题并核对效果。

文件来源准备须按真实 OperationRules／writer 的决定收敛：五公共字段的明确编辑（含草稿）分流到 C；已有正式行的 source edited_fields 必须为空，草稿仅表达合法非公共来源编辑，不能把自动原文更新当用户直接编辑。普通文件操作的 manual_fields 实际为空，合法旧来源 manual_overrides 保留、新建为空对象；最终客户端标记只作结果断言，不得把 edited_fields 或 C／B／D 机械并入来源 manual_overrides，也不将旧 flags 接入 protected 参数自创长期保护规则。类型／金额／原文的明确来源编辑按原 prepareCashSourceEffects 验证，不重跑匹配。既有组成项的 label／source_key／metadata_json 按数据库旧值保留，新组成项为默认空文本／空对象；父项 source_fingerprint 按旧值保留，新父指纹为 null；这些 DTO 同名字段不能开放任意写入。真实 current、type_changed、sourceChanged、修订及余额 before／after 由数据库状态和原规则重算，来源写阶段与 C 执行分离。草稿允许原合同的合法缺项，已知金融值仍须自洽；转正式及账户资格另验。自动 relation_metadata 可核闭合字段／类型、手工 effects 与已有身份约束，但最终 S 不足以证明原文 provenance，不能把解释 JSON 当账户或作用域授权。源保护读取缺口及完整证明／去重仍须在后续服务接线时核对，不以这段规划宣称已实施。

当前原生及本地来源读取构造 SourceRecord 时均未填 protectedFields，普通 OperationRules 的 manual_fields 仍为空；不能把策略形参能力写成已经实际实施了人工保护。实施前独立复核据此要求明确导入编辑意图与真实标记推导，落实已有人工公共值及固定字段合同，不新增资金／类型的长期保护政策。完整提交服务未接入前不得将现有最终标记或 resolved_issues 直接作为写入授权。

生效确认图预检在引用校验与金融值归一后，叠加流水、完整组成项、关系及来源绑定的最终值，并保留未修改的存量确认关系；删除或转草稿的父项不能继续支撑确认关系。复用同一 CashRelationGraphRules 检查角色、额度、退款累计、镜像／转账占用及图形，不仅检查本次新增边。未修改存量镜像／退款的零关联金额保持既有读取默认语义，不写回计算值；本批新增或替换关系的显式零必须原样交图规则判断，不能解释成默认全额。新建引用在私有计算中按实体映射到超过 Long 的精确临时整数，与全部存量 ID 隔离，不截断、不替换线上的引用或生成实际数据库 ID。排序所需来源键取最终绑定；有效银证资金组成项继续占用，不能经改写组成项绕过。该预检不物化投影、不保存推导结果；只覆盖最终生效确认图，草稿／失效边及候选状态、锚点、联合决定完整性、来源资格、权限和保护字段仍由后续完整服务验证。

新入口只复用相称的规范事实仓储和不变量校验，不沿用旧 ready 投影锁、逐行物化及依赖物化数据的结果定位。客户端的 row_decisions、summary、outcome 和 ledger_seq 都不作为服务器已提交结果；收据由实际 DML／幂等命中和真实事务版本生成。任何结构、引用、修订或最终图校验失败均整体回滚，不进入旧关系写入器 skip／failed 后继续的部分成功分支。事实与永久收据同事务保存，返回前重新核对原身份。以上边界不要求重新解析、来源召回或匹配启发式；完整 wire 定义及所有来源／资金分支仍需对应攻击回归后才能宣称接通。

**理由**：兑现"服务端只写最终增量"与降算力目标；匹配所需的账本状态已被端侧全量缓存覆盖。

**备选**：仅端侧做解析、匹配留服务端（不满足主目标，否决）；服务端重跑匹配做二次确认（费算力且引入"信谁"的分叉，否决）。

条目协调的内部输入只保留原投影标识、根流水、完整选中成员及经济根；原 `reconcile` 入口将既有投影转为这一内部计算结构，求值、排序和修订次序不变。该结构没有发生时间，也不生成虚假的草稿创建时间；后续写集效果核对可由已验证的最终确认图和有效草稿单成员组构造同一输入。它不是新的公开 DTO、分组合法性校验或完整写入授权，旧成员选取范围和闭包遗漏检查仍由调用方负责。

合并前的公共字段选择复用原 `chooseCommon`，与合并后的普通 `patch` 分开。先过滤公共字段并完整归一，再检查非空分类，空补丁直接返回且不 flush；按父项首次出现顺序惰性取得条目，每个不同父项各自改公共值、人工标记并推进修订，即使两父项同属一个条目或字段值没有变化。成员独立值保持原状；原仓储仍负责类别查询、缺条目时的单成员创建及末尾 flush，后续父项读取或溢出失败的内存状态和事务恢复责任不变。原仓储固定新旧条目标识的对照已证明：没有人工值冲突时，新父项预建条目仍可能改变最终稳定身份；不能仅将冲突字段前置而省略原公共选择。普通后置 patch 仍须保留，否则同值会令单成员独立值更新失效。此处已验证原身份与独立值的顺序依赖，完整写集的重放、标识解析和最终效果比较仍待实现。

条目最终拓扑复用同一次最终确认图构建及精确引用映射，正式组保留原根和完整成员，有效草稿为不依赖时间的单成员组。受影响种子包含交易、确认关系、来源绑定新旧父项及显式条目分组；按旧条目完整成员和最终图组展开闭包。提交的业务分组须与实际完整成员和根相符、组间不重叠，所有受影响最终组均须覆盖，全部受影响旧条目须提供真实修订依赖。文件入口另核每个旧完整组及身份锚点在一个最终组内存活，不从选中成员推断。客户端不提交退休指令，实际协调不能漏清空旧对象，也不强制修复范围外原本未物化的事实。内部拓扑门已按业务分组核对，并要求完整受影响旧条目修订读集；不证明公共值、人工标记、独立值、动作授权或事务。文件专用内部门已组合动作范围与拓扑，再核全部受影响旧成员及身份锚点存活且位于同一个已验证最终组；真实事务仍须调用此门并读取完整可信事实。

最终条目值的输入边界复用既有五个公共字段及原值归一规则，不增加文本长度或 Unicode 处理政策。成员独立值沿原迁移和来源构造的完整五字段对象，人工字段与本次编辑字段仅允许原公共字段集合；人工字段按字段集合去重并按 Python 顺序归一，不据此认定其来源可信。合法旧数据的标记可能因分类清理追加而未排序，后续旧值效果比较须按相同字段集合解释，不能将历史列表顺序判为损坏。新文件入口不提供最终 split_inherit 或主动拆分选择，临时协调标记不作为可写条目字段。成员历史分类只校验值类型，不在此层要求当前分类可用，恢复为公共值时再执行工作区分类资格。归一返回同一写集类型，引用、来源／证据 JSON 和输入对象不改；此层不证明人工意图或最终效果，实际写入必须使用归一结果及后续真实旧值核对。

条目写集声明完整业务结果，不让客户端预先指派哪个旧 UUID 存续、实际数字身份锚点或退休对象。服务端在同一确认事务内分配真实流水标识及条目 UUID，按原 chooseCommon／reconcile／patch 顺序决定实际条目 ID、身份锚点、修订及空对象退休；不新增分配服务、客户端 UUID 协议或按请求顺序取代原存储规则。完整业务断言仍包含根、全成员、五公共值、人工字段及每成员独立值，服务端不能为使校验通过而重跑匹配或更改这些结论。

传输条目以最终根流水定位其完整分组，不再带可写的 target／identity_transaction／split_inherit 或客户端决定的 deleted_entries。`entry_dependencies` 单独列出全部受影响旧条目的带修订引用，包括最后退休的旧对象；前置 entry_edit 的原归属／修订依赖仍须核对。不能用刚读到的修订补造客户端依赖，不能因不再接受退休指令而漏清空对象。收据按本次原键保存实际身份映射及退休结果，核实重放同一结果；本地成功后以服务端完整快照发布实际身份。

最终业务效果核对以实际协调和后置公共编辑后的完整规范事实为依据，不再用模拟 UUID 预测存储对象。按服务端引用解析逐条核实际根、完整 owner 成员、五公共值、人工字段集合和每成员完整独立值／标记；同一实际成员或条目不得经多份逻辑引用重复声明。旧人工标记按集合解释，不因历史顺序不同拒绝；实际持久字段不重新归一以掩盖差异。核对器只检查明确声明的结果，完整受影响范围由前置拓扑门保证；调用方必须读取所选实际 owner 的全部成员，不能只按请求成员构造所谓实际结果。它不执行公共编辑，不验证用户授权或取代原事务，真实服务须在同事务所有阶段完成后调用，失败整体回滚。旧修订依赖及拓扑必须先用写前事实核对，不能用写后修订替补；结果门只消费写后事实。内部 validateCashWriteSetEntryResults 已实现上述对照，实际条目及其全部成员按 owner 一次索引，引用解析须使用服务端真实分配映射，不使用客户端预览标识。它不处理未声明退休／孤立对象，不关闭完整服务任务。

真实前置编辑阶段在同一受管事务中、来源事实写入后且任何 B／协调前调用共享准备器；先验证全部原始 C 的旧观察并归并，再解析所有保留 C 的真实父项，拒绝非正数或别名后逐项调用原 applyEdit。旧 owner 使用原验证的 entry expected_revision，空观察交原仓储创建单成员并内部取得新修订，wrapper 不用当前值修补旧依赖。来源 writer 必须尚未执行 C；旧 CashRecordWriter／CashImportNewRowsRepository 已自行执行，未来接线不能原样叠接造成重复。若 before 之后旧修订或条目存在性已变，由原 applyEdit 拒绝并外层回滚；C 前 owner 不被同修订重挂由外层同事务基线／依赖与禁止提前协调保证，不声称 applyEdit 独立检查 UUID。该阶段不消费 B、不代替来源写入、完整授权／幂等或最终结果核对。

首次关系公共选择的真实事务阶段在 C 后、协调前，先复用有效 B 一致性／post-C 人工覆盖与原联合批次准备，再一次解析全部接受组的实际父项，核正数及逻辑引用别名，最后按原批次／组序逐组调用 chooseCommon。每组端点去重后按服务端实际 Long 的十进制文本排序，不跨组或按旧 owner 去重；同 owner 的不同父项仍各推进修订。有效 B 已固定且批内一致、完整旧组不拆前提下，父序仅影响服务端 UUID／身份存续及具体 checked 失败先后，不改变成功公共值或 standalone；真实异常整事务回滚，不改选对象。该内部入口显式仅适用于外层已确认整联合批次首次写入；同意图关系的整批去重须先完成，已存在批次连同选择消费，不能再次调用它。完整分类、来源／关系身份与幂等服务未接通前不开放端点，不以此阶段声称幂等完成。

真实条目收尾阶段在外层受管写事务内执行，先要求有效事务 stamp；调用方须已完成写前授权／依赖及 C／B，提供同一最终可信图的完整投影。全部根和成员先经服务端实际分配映射一次解析并缓存，核对正数范围、两侧重复／交叠及完整根成员分区，任何不符均在条目 DML 前拒绝。随后仅复用原 reconcile、按明确 edited_fields 执行普通 patch D（使用协调后的真实当前修订），flush 后用同连接完整事实核对声明结果；不能用 chooseCommon 代替 D 或用真实当前修订补造客户端旧依赖。结果失败／修订溢出／解析程序故障由外层 db.write 整体回滚，不内部提交、吞错或依赖物化投影 ready。初片复用 LedgerSnapshotRepository.facts 的一次全工作区 15 集合读取，明确其 O(事实量) 成本，后续整服务性能验收须覆盖；不是只读 entries 的窄查询。该阶段不构成完整文件提交、收据或身份映射交付。

此简化限于文件导入：同事务必须核完整旧条目成员和旧确认事实，并保证每个受影响旧条目的所有成员及身份锚点仍存活、整体落入一个最终组。不得仅核请求选中成员或某个锚点，亦不得将该结论套用到无文件拆分／删除。这个条件排除旧可变条目对象在多个最终组间共享；成功派生时 human 及每成员独立值由完整旧组、来源和三阶段编辑决定，candidate 只决定存储元数据。纯协调分配对照已验证五公共值、人工集合和完整独立值，并分别断言 UUID 存续、数字锚点和组序可不同；真实仓储回归验证三阶段值分离，均不代替完整文件提交验证。这个结论限于生效公共选择 B 已确定之后；原 DecisionRules 按 cash:<rootId> 扫描投影并向联合批次共享 decisions 首次填值，不能假定虚拟／实际标识更换不影响自动首值。端侧仍执行原预览规则，传输已生效 B；服务端核批次一致性及 post-C 人工字段完整覆盖，再执行原选择，不以实际新 ID 重新计算自动首值。原旧提交在 writer 前会重建完整计划，不能描述为原系统已信任客户端 B；新入口以五字段明确选择、完整效果及事务约束建立新的信任边界，不重跑匹配。此安排无需新增 wire 或改变既有用户编辑能力；真实写集服务仍待接入。

实际分配仍沿原 checked 修订推进、唯一性及故障传播；不同候选可能到达不同的修订溢出点，不能承诺客户端虚拟计算与服务端所有异常路径相同。服务端真实协调失败时整事务回滚，不吞错、改选 winner 或补随机身份以对齐预览。自动重试的业务结论指纹排除纯服务端分配字段，但保留真实成员、金额、角色、公共值、人工标记与成员独立值变化；原键结果未知仍先核实。wire 已改为业务结果与独立旧条目依赖，引用及拓扑测试保留完整范围断言；旧 target／identity／split_inherit 和 deleted_entries 由严格解码拒绝。完整效果重放、实际身份映射、退休及原键结果绑定仍待事务服务接入。


### D4 投影：服务端不物化，端侧派生（C1）

浏览迁移保留当前零金额筛选、草稿、待处理优先、精确统计和稳定收支身份合同；仅改变计算与读取位置。delta 的 MODIFIED／REMOVED 名称对应迁移完成后的主规格真实 requirement，不能以新标题遗漏替换原要求。规则变化使派生视图及游标失效，不为纯派生变化推进事实账本版本。

本地分页游标由共享规则编码与解释，绑定工作区、精确账本版本、当前共享规则和投影规则版本、完整规范筛选映射，以及排序时刻和稳定收支标识。版本以十进制字符串传递，不能经 JS Number；规则身份取实际派生所用的客户端规则，不直接沿用快照中的服务端规则声明。解码先完整核对格式、工作区和筛选，格式或范围不符为 `invalid_cursor`；同一查询下账本或任一派生规则版本变化为 `read_snapshot_changed`。降序续页先比较真实排序时刻，再按 Python 码点顺序比较稳定标识；未知日期由投影提供创建时间作为排序键，不更改发生日期。游标本身不是授权凭据，登录／工作区访问与完整筛选执行仍由本地读取边界负责。

**决定**：删除 `cash_projection_*` 物化与 `GET /cash-projections`、详情/证据、`operations/projections` 等读取面；浏览、筛选、分页、月度汇总与聚合由端侧用共享规则派生。服务端本期不保留聚合接口。

**理由**：端侧已有完整事实，派生是同事实的纯函数；删物化直接省存储与重建复杂度。若未来出现端侧算不动的重聚合，再按具体名单补服务端按需聚合。

**备选**：保留服务端物化（与主目标冲突，否决）；服务端物化 + 端侧派生并存（两份实现与在线离线不一致，否决）。

浏览日期筛选的日期文本归一复用共享公历／ISO 周日期原语，保留四位年扩展／紧凑日期、ISO 周及缺省周一、年 1..9999 和原非法日期拒绝；不以 UTC 的日期计算替代选定时区的起日边界。后端从同一归一结果继续使用原 ZoneId 起日转换；本地时区边界及完整查询接线另验。账本关键词按用户确认统一为普通文字包含且忽略大小写，%／_／反斜杠均为文字，分别搜索对方与备注，不跨字段拼接。端侧复用已有冻结 Unicode 14 casefold，仅做大小写等价和原关键词两端空白处理，不去重音、改标点或改导入商户规则。原 SQL LIKE 的数据库差异不作为新查询的政策；旧服务端读取面在退役前保持原行为，本次端侧新合同单独验证。

日期范围以选定时区中指定日期的首个有效时刻为起点，以结束日期翌日的首个有效时刻为开区间终点；午夜缺失、重复或整日跳过时保持原 `LocalDate.atStartOfDay` 合同，不把日历日固定成 24 小时。采用平台薄桥：Android 保留 java.time；iOS 使用 [kotlinx-datetime 0.8.0-0.6.x-compat](https://github.com/Kotlin/kotlinx-datetime/tree/v0.8.0) 的公历／时区转换（沿用既有 Ktor 的实际兼容版依赖，桥接结果仍为 kotlin.time.Instant，不强制降级）；JS／Wasm 使用 [Temporal polyfill 0.5.1](https://github.com/js-temporal/temporal-polyfill) 的 `PlainDate.toZonedDateTime`（不传 plainTime），读取浏览器本身的时区规则。Web 桥仅传 ISO 字符串，返回后转换为 kotlin.time.Instant，不经 JS Number 传秒数。三个旧固定时区别名单独保留。名字资格复用 Temurin 21.0.6 原 `ZoneId.getAvailableZoneIds` 的精确集合；生成器固定宿主版本，仅冻结名字，不复制时区转换数据，防止 Intl／iOS 将大小写变体或动态 offset 扩成新输入。平台缺少合法名字时仍明确拒绝；时区数据更新需兼容复核。未知时区明确拒绝，不回退 UTC；只有已识别的时区输入异常成为筛选错误，库的未知异常继续传播。

仓库外相同 Kotlin 编译器探针中，kotlinx-datetime 0.8.0＋js-joda core 3.2.0／timezone 2.23.0 在 Europe/Berlin 9999-07-01 缺少预期夏令时；不将这个已失败组合接入浏览。所选 Web 薄桥与 JVM／iOS 薄桥的 16 个真实 JDK 起日对照已通过 JVM、JS／Wasm Node 与 Chrome，iOS 测试编译通过；该探针不替代正式构建；正式三目标测试、iOS 两架构编译、Android APK 与 Web 开发分发资源核对见 tasks 的日期范围证据。客户端日期归一继续用已共享原语，结束日期 9999-12-31 保留既有明确溢出错误边界。Android minSdk 24 在实际应用构建中启用官方 core library desugaring，覆盖 java.time；新增库的准确许可与对应源码信息随应用资源分发。时区库／平台时区数据库版本差异保留可观察风险，本期不修改存量发生时间或投影经济规则。

本地查询从同一完整快照一次派生条目与列表视图，按真实 sortAt／公共条目标识降序排列，完整筛选后才分页；全局选项独立于筛选。账户条件检查代表账户及全部现金成员组成项，不将银证转账投资端账户混入现金条件；分类按目录祖先关系包含子类，不解释 SQL 通配符。关键字使用公共 entry 字段；未知金额保留 null，日期筛选不以 createdAt 填充未知日期。首次无版本查询计算完整月度统计，带版本序号页省略月份信息；总数、待处理数量与全部汇总共享同一筛选和版本。只读核心消费共享工厂构造的规范筛选／日期边界；原始筛选复用现有 CashFiltersDto，不增加第二份协议。公共工厂与原生 parser 对照，完整 page 对照使用各自真实游标续页，仅按已定协议替换版本与游标文本；shared 内部读取适配将原始 CashFiltersDto、选定时区的真实起日与月份函数交给同一查询，持有一次快照派生；缓存持有者与页面接入另验，不把查询测试视为端到端完成。规范输入在构造时保存私有筛选快照，公开 getter 仅返回副本，查询内部复用固定快照，避免外部 Map 修改使金额、筛选和游标脱钩。金额上下限按用户确认限制整数最多 20 位、小数最多 18 位，使用十进制系数长度与指数预判展开范围，在构造普通十进制文本前拒绝超限；不改流水／汇总精度，不截断或舍入。规范输出保留预算内小数零和负零；超过 18 位的小数表示即拒绝，包括尾随零，避免以规范输出保真重新引入无界展开。零值的正指数不产生整数填充，规范为零；非法或超范围输入统一 invalid_filter，不延续旧 SQL 解析的内部错误。正整数账户参数超出存储标识范围时不命中本地事实，不模拟旧 SQL 执行层的连接／内部错误；非法词法仍按原规则拒绝。

共享内部浏览 owner 固定一个登录／工作区范围，组合现有 LedgerSnapshotSync 与 LocalCashLedgerReader。每次分页先取得同步层已提交缓存，再按事实版本和快照规则声明复用当前派生读取器；刷新不持有派生锁，完整新事实原子落盘后后续页才消费新版本，旧游标明确失效。无缓存返回缺省状态，不伪造空账本；网络／存储失败仍可读取旧完整缓存。关闭资格复用同步层的同一个状态，分页呈现前后均核对；不另存一份可能落后于撤权的 owner 状态。close 立即封闭旧 owner，再等待缓存清理并释放派生内存；迟到刷新不得发布或清除新 owner 的同范围缓存。该组合不创建明文驱动、不选择 Web 密钥策略，也不代表应用会话或页面已接入，实际驱动及登录生命周期仍另验。

原 CashFiltersDto 移至 contracts，shared 用同形 typealias 复用，不新增第二套筛选协议。公开入口先调用规范化工厂，构造器保持模块内；工厂沿用原账户整数／布尔／分类／金额／标签词法，金额范围按本节已确认的 20 位整数／18 位小数限制；筛选比较继续用计算型精确十进制，不将输入范围限制套到投影或累计结果。日期边界模型位于纯领域层，时区能力仍经 shared 薄桥提供，不把平台日期库带进 domain。币种三字符的字母资格固化原 JDK Character.isLetter 属性，仍复用已有大小写原语；在已批准金额范围内，以原生完整规范筛选／拒绝结果独立对照；新增范围以独立边界用例验证，不用新实现生成预期。

### D5 并发：v1 整工作区基线（L1）+ 稳定输入重派

**决定**：写集提交携带基线版本；服务端在同一事务内做等价于 CAS 的校验，基线过期即整批拒绝。端侧基于稳定输入（文件、账户映射以及按稳定引用寻址的行、entry 与配对决策）在最新缓存上重派并复用决策：**结论指纹一致则静默重提交**，不一致则提示重新核对。

**理由**：L1 实现最简、水位管理无缝隙；"重派 + 指纹比对"把它的误伤缺点补掉，体验接近作用域基线（L3）。指纹必须基于来源身份、金额、日期与参与者等业务键，不得使用 `planId`/`suggestionId`/`candidateId` 等每次派生都变的临时 ID。

**备选**：作用域基线 L3（需变更日志带作用域字段，本期不做，保留升级形状）；读集 OCC（候选窗口实体多、成本高，否决）。

**事务边界**：校验与落库必须在同一事务内完成，否则存在 TOCTOU，会接受过期写入。

基线守卫复用现有托管连接和版本管理器，在写事务内锁定并比较工作区 `ledger_seq`：PostgreSQL 使用 `FOR UPDATE`，SQLite 由 `Database.write` 的 `BEGIN IMMEDIATE` 串行化写事务。守卫本身不推进版本、不保存接受结果；回滚到 savepoint 后必须读取真实版本，实际事实变化仍通过现有标记每事务只推进一次。拒绝携带精确的期望／当前 Long，HTTP 字符串编码由后续写集边界承担。调用顺序为重新鉴权、原键收据重放、基线守卫、完整写集校验、事实与收据同事务保存；守卫不代替鉴权或写集合法性校验。该内部原语尚未接入客户端写集服务，不改变旧导入的重算行为。

提交收据的 ledger_seq 只证明该次提交成功，不能直接替代本地完整事实水位。提交后的刷新显式携带该版本下限；版本查询即使仍等于旧缓存，也必须取得至少该收据版本的完整快照才能发布。返回快照低于收据、已查询版本或现存缓存时保留原缓存并停止此次刷新，不将提交结果改判失败或以新键重复提交；待提交记录的清理由后续 owner 在成功取得该下限快照后完成。本片同步守卫不保存或清理 outbox，也不改变结果未知时先按原键核实的规则。

**livelock**：需退避与重试上限，超限提示稍后再试。

### D6 幂等：数据层 + 提交层两层

**决定**：

- **数据层**：现金流水按来源绑定身份去重（沿用既有唯一索引语义）；交易关系按关系类型、成员来源键与关联金额的确定性指纹去重。相同指纹视为已应用并幂等成功。
- **提交层**：以用户、工作区与幂等键确定一次提交；相同键的重试返回第一次结果；结果未知时按原键核实；已成功内容不重复写入。

提交收据的 `ledger_seq` 为可选的规范非负有符号 64 位十进制字符串，沿用版本／快照的精确文本合同；新写集提交须填写本次事务的提交版本，旧收据保持缺省，不按读取时的最新版本补写。存储摘要、按 ID／原幂等键读取和 shared 收据模型保留同一个值；字段出现时拒绝显式 null、数值 JSON、负数、非规范文本和超 Long 范围，缺字段才按旧收据缺省处理；客户端使用字段级解码，不修改全局 JSON。损坏持久值按既有收据不可用错误停止，不静默丢弃或取当前版本。此切片先打通白名单及类型保真，不将任意调用方提供的版本视为已完成事务绑定；最终写集 service 负责填写真实提交版本。OpenAPI 沿现有 Kotlin additions 的 LedgerVersion 字段定义补入收据元数据，不修改已退役 Python 业务模型，也不引入通用 schema 覆盖框架。

**理由**：行身份让重放安全，收据让回复正确且可审计；二者职责不同，不可互替。手工录入没有来源单据，只能依赖提交层。

**约束**：指纹必须由共享代码生成，三端一致，否则跨设备去重漂移。客户端生成的值（如需要）必须在本地队列中生成一次并持久化复用，重试不重算。

来源绑定、待处理问题与已认证空页在实际插入／变化／清除时标记；重复来源出现、相同问题和已存在空页不推进。问题的候选集合未变时保留既有候选行，避免同值重发删除再创建内部身份；问题正文变化而候选集合相同也不重建候选。草稿绑定迁移复用已验证身份快照的计数，空迁移不写入、不推进。对应清除只在原问题存在时标记，仍由同一工作区锁和外层事务负责原子性。

来源出现仓储将真实插入／更新返回给流水写入器，写入器累计本次全部来源更新，并将绑定发生变化的流水加入受影响集合。当前服务端仍维护物化投影时，仅补来源绑定的重复导入也须维护来源排序依赖的派生结果；同值重新导入不触发该维护。此标记只传播实际写入结果，不改变来源身份、收据状态或工作区版本的既有含义。

### D7 规则落位：下沉 `business-domain` 共享 KMP

**决定**：查重、配对、投影、余额规则与写集 DTO 下沉共享模块，三端与服务端共用一份实现。

**理由**：D4 要求端侧派投影、D3 要求端侧跑匹配，若各自实现必然漂移；共享实现同时保证"在线离线一致"与"双后端一致"。规则版本变化触发端侧整体重派生。

来源覆盖证明复用原 `CashSourceCoverage` 序列化结构，数据形状放入 `business-contracts`，时间包含性与可比较性放入 `business-domain` 扩展函数。domain 依赖 contracts，contracts 不反向依赖规则；backend 通过 typealias 与 JVM 时间类型薄适配复用，不保留第二份模型或算法。来源定位键使用固定的字符串／空值／整数数组编码，位置保持整数文本；原始字符串先通过严格 UTF-8 检查，再编码与摘要，不依赖 JS 的 Any 数值类型判定或 JSON writer 对非法 Unicode 的处理。

字段变更的可编辑性、固定财务字段、人工保护、类型组合、完整性与现金部分一致性由共享 `CashRecordPolicyRules` 编排。现有 backend 的 JVM 值归一与 Python 数值等价比较通过两个值适配函数进入共享规则；适配不决定哪些字段可修改，也不绕过服务端校验。该切片不宣称客户端值归一或完整导入已接通。

来源查重的分组、证据优先级、歧义判定和多重集合匹配统一下沉到共享 `CashSourceResolver`；匹配索引作为等价键由调用方提供，backend 继续用原 JVM 金额／时间编码。字段准备、来源摘要和覆盖证明的原始值桥接在构造时注入，规则主体不依赖 JVM；这一步不改变索引等价关系、来源 ID 分配或任何数据库写入，也不代表端侧生产适配与 Batch／Rows 已接通。

已解析的 `ParsedCashRow`／`ParsedCashDocument`、文件最小视图与 `SourceBatchRows` 放入共享领域层；它们是导入计算输入，不新增线路 serializer，原服务端显式暂存编码继续复用同一模型。`CashSourceRows` 共享文件顺序、字段深复制、来源范围和页面证据组合，平台 CSV 文本／解码、银行记录／TSV byte 与逐行归一已有共享生产规则；值型平台 XLSX 已提供本地字节／归一入口，公式按本 change 的范围整份拒绝；旧 CCB XLS 按用户确认保留无状态服务端解码，端侧继续归一；PDF parse-only 的服务端入口、共享传输与归一文档还原已提供；共享单文件分派已组合全部读取器，批次 owner 与页面尚未接入。来源模型共享不等同完整文件调度或端侧导入已可用。

来源批次 `CashSourceBatch` 的内容归一桥接继续保留 backend 既有 Decimal／时间表示；批次决定、文件时间优先级、最大多重数与共享歧义组移到 domain。JVM 引用缓存改为请求内内容缓存：候选及去向列表以只读快照缓存内容 hash，避免同一大候选组逐行重复散列；求值缓存键同时包含“本行是否直接目标”，保持原直接结果与批内重复结果的区别。缓存不跨调用，不保存财务事实或用户决定。

来源行类型判断复用共享 `CashRecordTypeRules`，保留撤销、平台转账退回、退款、还款和渠道关键词的既有优先级；原 JVM 对任意原生数值的 Python 文本／真假转换通过两个值桥接提供，金额方向仍使用共享精确十进制表示。对方账号的掩码识别与重建证明仍由既有 backend 分类入口处理，尚不宣称完整行归一已迁移。

对方账号识别与重建校验下沉 `CounterpartyAccountRules`，`CounterpartyAccount` 只保留一份共享模型，证明仍是规则实例内的不可伪造运行时 token，不作为客户端提交即可信的证明。JVM 专属数字正则改为按同一 Unicode 14 码点表读取数字段；尾号左边界保留既有 JVM 对补充平面前置数字的特殊匹配，原 UTF-16 长度条件、属性组合、空值、掩码清理与来源原文绑定保持。十进制与非十进制数字表由共享生成器维护，公开访问返回副本，backend 生成表仅持有初始副本；原生值文本与严格来源摘要桥接继续复用 backend 既有入口。

条目的可变领域记录 CashEntry／CashEntryMember 复用为共享模型，原生仓储以别名保留同一对象和修改追踪，不新增持久状态。预览公共字段继承使用共享规则：先按操作顺序合并同一条目的编辑补丁，再由当前根流水或成员回退取非手工字段，只解码实际使用的手工字段，最后应用补丁并更新投影事实；新操作保留 new: 标识和原手工字段排序。原生仍按叠加前的当前存量集合读取一次条目，不改变数据库或授权边界。此迁移不等于完整端侧预览工厂和页面接线。

端侧预览存量值读取限定同一完整快照与已加载关系上下文的 transactionIds，不按正式／未删除再筛一次，保留草稿和已删成员元数据。来源绑定范围沿账户优先、单一文件回退和歧义标记；现金部分沿上下文的精确版本和原顺序归一，再附来源排序键。此入口只构造独立可变值树，无网络、落盘、来源重新解析或配对；本地快照／上下文应来自同一已确认版本，缓存 owner 负责该边界。该读取器作为下述本地初始预览工厂的输入；完整发现、业务计划与提交仍待接通。

本地初始预览工厂组合该存量读取、正式上下文事实、有效草稿、共享操作叠加及条目公共字段继承；条目仅按叠加前存量集合从同一快照读取。预览专用整数包装已有精确整数解析／比较，承载原 2^64 偏移与完整 128 位摘要，不窄化为 Long、浮点或字符串字典序。已知整数经专用值编码器作为 JSON 数字保留；原开放 Number 不据数值猜测为整数。此类型只用于计算中的预览标识，不改变持久标识或金额筛选范围。工厂的时钟显式注入，输入 JSON 深复制；关系发现生产配置、完整计划与提交／页面仍待接通。

本地关系建议组使用该真实预览状态与已计算提案，注入相同精确虚拟整数、摘要、存量边界及计算型退款文本。微信原消费的负数／来源／类型门和状态文字规则共享，平台只保留既有十进制解释；嵌入退款文字的识别仍使用原模式，不把流水列限制套到计算值。该入口不运行商户匹配或候选召回，也不据组构建成功宣称选择应用、完整发现或冻结计划已接通。

工厂的计算型入口直接接收本地操作规划所得的金额、时刻及显式整数类型，并深复制操作；JSON 入口仅解码并委托，不猜测普通字符串是否为计算值。两种边界不能通过先编码为普通 JSON、再还原来混同：关系建议指纹包含操作原值，计算时刻与普通时刻字符串的摘要语义不同。生产规划使用计算型入口，已序列化输入按其原类型处理；恢复计算计划需由其明确业务字段重新规划，不为任意 JSON 字符串加隐式类型标签。

### D8 解析边界：CSV/XLSX 端侧，PDF／旧 XLS 服务端 parse-only

**决定**：端侧解析 CSV/XLSX。PDF 通过服务端无状态 parse-only 返回归一化行；旧 XLS（当前建行借记卡 OLE／BIFF）通过同类无状态边界只解码成原始文档，字段归一、类型分类、查重和配对继续由端侧完成。两类解析需要联网，不建立导入会话、不读账本、不写业务数据；PDF 密码只用于当前请求且不落日志与持久化。不新增 XLS 密码能力。

共享文件分派复用原字节／来源提示优先级：PDF 标识或工行 PDF 来源优先；无来源时以 OLE／UTF-16 BOM 识别银行格式；显式银行来源必须与实际字节匹配；其余 PK 交本地 XLSX，其余内容交平台 CSV。文件扩展名仍按既有客户端接受集合校验，不用扩展名覆盖来源判断。单文件读取入口先校验元数据并有界读取一次原文件，本地格式不联网；远端分支复用已读取的同一份字节，传输文件名固定为格式名，避免原文件名携带密码。返回既有 `ParsedCashDocument`，不创建导入会话、计划、收据或新的持久化文档模型。原始输入的稳定引用与摘要仍由后续导入 owner 管理；本入口不代表页面或完整导入已经接通。已知文件错误、网络故障、权限拒绝、取消与内部异常保持各自类型／错误码，不转换为成功或部分解析结果。同步本地解码的长任务与取消仍须在页面集成时处理。

**理由**：PDF 抽取依赖 PDFBox，旧 XLS 是独立于 XLSX 的 OLE／BIFF 格式；用户确认两者保留服务端无状态解析，以减少端侧解析代码。XLS 二进制读取继续复用当前 POI，原始字段与错误保持，导入领域计算留在端侧。

**接口切片**：`POST /api/v1/cash-import/pdf/parse` 沿用有界 multipart 的 `metadata.files`／`file:<client_file_ref>` 编码，但每次仅一份 PDF，请求总量限制为一文件预算加元数据；密码仍在当前请求元数据中，不进入 URL。独立于旧导入会话及暂存配置注册，复用现有受限 PDF 子进程与共享行归一规则。返回 `rules_version` 和类型化归一文档（逐行 fields／来源说明用 JSON，金额为精确文本），不返回会话、计划或收据。只做认证／工作区权限校验，不读取现金账本；完成解析后重新核对会话范围再返回。入口不保留文件／密码；真实解析、密码分支、鉴权失效、请求边界及双库前后状态须验证。归一文档开放 JSON 复用快照的精确数字 serializer，作用域限定在对应 DTO；不改全站 JSON 配置。文件预算在调用解析器前拒绝，响应预算按与 HTTP 相同的默认字段与 UTF-8 编码计数。取消先于权限重查传播；重查失败遮蔽文档／文件错误时，以 suppressed 保留原异常诊断。客户端传输不清除全局 token，权限失败由所属登录流程处理，避免迟到 401 清除新凭据。

**XLS 接口切片**：新增 `POST /api/v1/cash-import/xls/parse`，沿用单文件有界 multipart／身份与工作区鉴权，来源仅接受当前受支持的 `ccb_debit`（允许现有连字符来源提示归一），不回退为 TSV／CSV／PDF 解析。返回 `rules_version` 和现有 contracts `CashStatementDocument`／`RawCashRow` 的原始文档；复用其完整字段、原始单元格字符串、null、位置、计数与覆盖证明，不另造同义行模型。客户端调用共享 `normalizeLocalCashStatement`，不把服务器解码结果当可信可直接写入的事实。接口拒绝不适用的密码元数据，原文件与密码不进入持久化或日志。

XLS 使用现有受限子进程的独立操作，和 PDF 共用并发额度、256 MiB heap、60 秒超时、受限环境及私有临时目录清理；不在 Ktor 请求进程直接解析不可信 OLE。文件仍最多 100 MiB，实际线路响应按完整默认字段 JSON 的 UTF-8 长度限制为 25 MiB。解析完成或失败后重查原用户／工作区写权限，取消与程序异常保留原传播／诊断，返回前擦除请求文件。测试先复现端点缺失，保留全部原银行成功／错误文档和端侧归一对照，双后端实际 SQL 观测证明只有鉴权查询、无账本读写；补齐超限、错误格式、权限中途变化、取消／未知错误及迟到 401 的客户端回归。服务端与共享传输已由单文件读取入口消费；批次 owner、稳定输入保存和页面尚未接入，不以接口或单文件入口存在宣称完整本地导入可用。

程序异常由 parse-only 最外层返回安全的 `internal_error`／500，不返回开发模式调用栈或原异常消息。原进程内 cause 保留；受限 worker 对可捕获的未知异常传回类型和有界调用帧／cause 诊断，不传异常消息或账单内容，父进程校验内部协议后记录安全诊断。新 XLS 操作的不明退出、启动失败、EOF 或内部回包损坏不能认定文件格式有错，按内部失败处理；明确的文件错误继续返回原 422，busy／timeout 返回 503。既有 PDF 文本抽取的旧进程退出分类不随本片重定义；parse-only 的实际未知故障仍不得泄露调用栈。必须以真实受限子进程的故障与异常退出回归证明该边界，不能仅用替换 service 的内存异常作为证据。旧 BankReader 内部已有的 Exception 到文件错误分类保持，本片仅验证到达 worker／parse-only 外边界的已覆盖故障，不将 AssertionError 工厂注入扩大为内部任意 RuntimeException 的分类证明。端侧 XLS 解析路线留待后续验证，本期不引入 JS／Rust 解析库。

### D9 Web 持久化：OPFS + SQLDelight-wasm

**决定**：Web 端以 OPFS 承载 SQLDelight 的 wasm 存储；其余端使用平台原生存储。

**理由**：localStorage 容量与事务能力不足；OPFS 提供可持久化的文件级存储。

**接入条件**：[SQLDelight web-worker-driver 已提供 wasmJs](https://github.com/sqldelight/sqldelight/releases/tag/2.1.0)，但自带 SQL.js Worker 不是 OPFS／加密存储。按[自定义 Worker 协议](https://sqldelight.github.io/sqldelight/2.1.0/js_sqlite/custom_worker/)适配前，先用合成数据实测 OPFS 文件、事务、重启和密文页／索引；未验证前不宣称已接入。[SQLite OPFS 文档](https://sqlite.org/wasm/doc/tip/persistence.md)中 opfs 与 sahpool 的隔离响应头和多连接限制不同，按实际 VFS 验证。可评估 [SQLite3 Multiple Ciphers 预编译 WASM](https://github.com/utelle/SQLite3MultipleCiphers/releases/tag/v2.6.1)及其非默认 VFS 包装；具体依赖需在接入前验证，不把“支持 SQLCipher 密码方案”当作已链接 Zetetic SQLCipher。

**已验证的兼容边界**：SQLDelight 2.4.1 的真实 JS／wasmJs WebWorkerDriver 已与 SQLite3 Multiple Ciphers 2.6.1（SQLite 3.54.0）加密 OPFS VFS 运行。合成库在完整 Chrome 进程重启后，两端均先读取既存行，再完成提交和回滚；实际主文件未出现所测明文值或 SQLite 明文文件头。只验证运行兼容，不代表应用接入或安全验收完成；公开合成密钥、主库有限标记检查不能覆盖密钥生命周期、活动 journal／WAL、多标签页、崩溃恢复和性能。独立探针 webpack 有工具版本冲突，使用原编译产物直接在浏览器加载；不能写作 webpack 通过。

实际浏览器数据库使用固定版本、校验和及完整分发声明随包提供的 SQLite3 Multiple Ciphers 基础 WASM，不在运行时从第三方 CDN 下载。Worker 按范围持有排他文件租约，先核已有文件再选择只读密钥或明确新库创建；已有文件缺钥不得新建。数据库仅通过 multipleciphers-opfs 打开，键通过 C API 传入而不拼入 SQL；初始化验证实际版本、密码算法、硬件加速关闭及 DELETE 日志模式，临时表与排序强制使用内存。上游 2.6.1 发布说明指出 ChaCha20 硬件路径的计数器溢出问题，按其建议在任何新写入前关闭并核对，不沿用探针缺省。Worker 保留 SQLDelight 的执行／事务协议和原错误诊断；关闭或删除先停止后续操作，数据库确实关闭后才删除范围目录及密钥。实际 Worker 已验证重启、活动 DELETE 日志、错钥不改文件、清理失败围栏及未提交页溢出后的中断恢复。内部排他租约的忙碌拒绝不代表应用多标签协调已完成；SQLDelight 工厂、页面、会话及完整缓存所有者另行组合。

**精度与存储切片**：Web 驱动的 Long 绑定／读取经过 Double，标识、修订、版本和金额必须经 TEXT／JSON 原词法保存。先实现基于 SQLDelight runtime 的内部快照存储：服务地址、用户、工作区为复合键，完整 DTO 序列化为单个 TEXT，由单条 UPSERT 原子发布事实和版本，读取核对范围。实测普通 serializer 在 HTTP 与缓存均会改写开放 JSON 数字（含超出 UInt64 的整数精度）；在 `LedgerSnapshot.kt` 文件作用域指定同一个 JsonElement serializer，递归保留合法数字词法，字符串／布尔／null 原样，拒绝非法裸值。此修复只覆盖快照事实 DTO，不改变其他 API 的全局 JSON 配置或字段形状。此存储本身不实现加密缓存端口，也不创建明文平台驱动；加密驱动、密钥销毁和本地事实索引接入后才可连接应用。合成 JDBC 测试只验证真实 SQL 持久化／失败保旧，不计作加密通过。

范围 SQL 缓存适配器只接收平台已打开的驱动及该范围的文件／密钥清理动作，不自行选择密码算法或创建明文库。固定单一登录范围，串行读写；清理开始先关闭返回围栏，等待既有 SQL 完成，再确实关闭驱动并清理存储。已开始的读写在返回前重查围栏，清理失败保持关闭且允许明确重试；关闭失败不删文件，删除失败不重复关闭已关闭的驱动。建表失败只关闭驱动，保留原文件及密钥和原异常，不以初始化失败作为丢弃旧缓存的许可。此适配器仍需平台工厂及应用生命周期组合。

Web 工厂以同一中间源集消费真实 WebWorkerDriver，先完成加密 Worker 的 open 确认再允许建表。控制消息与 SQL 请求标识分离；关闭先等待 Worker 释放数据库与范围租约，再终止驱动，删除由不打开账本的独立 Worker 执行。初始化取消须等待资源打开结果并关闭，不能丢弃仍在打开文件的 Promise；控制通道的载入错误与超时保留明确诊断，不静默回退。真实 JS／Wasm 浏览器测试直接组合工厂、完整快照存储和范围清理，不以协议模拟替代驱动接线；应用会话与页面仍另行组合。

固定 SDK 2.4.1 的实际产物在成功回包后只移除 message 监听，遗留 error 监听会在线程抛错后再次恢复已完成协程，真实驱动回归已复现。私有连接控制器在该版本的请求注册／发送边界成对管理这两个监听；完成或取消任一侧即释放整对。线程失败时只通知仍活动的请求，后续发送直接保留原失败，避免挂起或重恢复；不修改第三方源文件。关闭确认错误可明确重发，只有成功确认才终止；线程错误或超时已终止且缺少确认时持续拒绝，不能把再次 close 当成功删库。未交付的初始化资源可强制终止以释放句柄，但不因此宣布存储清理完成。该 SDK 适配必须随版本升级复跑真实故障与取消测试。

Web 的版本／整包同步与本地浏览须再组合真实加密工厂验证：页面只读缓存，版本相同不下载，版本变化发布完整事实，失败保旧；401／403 先封闭本实例，再删除实际文件及密钥。HTTP adapter 可由合成响应独立验证，但不能据此宣称真实后端、应用登录或产品页面已接通。

Apple 加密驱动使用 SQLDelight native-driver 2.4.1 与官方 SQLCipher 4.20.0 Swift 包，固定 exact 版本、Package.resolved 及上游二进制校验和；不引入 CocoaPods 或自编密码库。当前 Kotlin 2.4.20 的 Alpha SwiftPM 导入已在仓库外 macOS 合成探针验证，应用接入仍须验证两个 iOS 目标及 Xcode 最终链接，不为此升级 Kotlin。内部 C 声明只引用公开 sqlite3_key API；每个连接从私有 ByteArray 副本传入密钥，不拼 SQL 密钥文本，关闭全部实际连接后才擦除副本。连接核对 cipher_version、DELETE 日志与内存临时存储；禁用 SQLiter 的 SQL／错误日志，错误保留给调用方。

真实 SDK 探针已复现 SQLiter 1.3.3 在错误密钥打开时、连接尚未交给 SQLDelight 连接池便抛出，driver.close 不会关闭该句柄。私有 DatabaseManager 适配器必须追踪实际连接，在创建失败及关闭失败后仍保持所有权；正常关闭完成须所有连接均关闭且无关闭异常。SQLiter 在调用 C 关闭前先置 closed，任何关闭异常都必须持久保留为“不确定关闭”；尽力关闭其余连接，但后续 close 不清除此诊断、不擦私有密钥，也不允许范围适配器推进删除。不能把重复 close 无操作或 closed 标志当成底层关闭证明；此异常实例需停止使用并重新建立进程级所有权，不承诺原实例能重试恢复。适配器只补资源所有权，不复制上游驱动或密码实现。底层驱动不承担范围目录租约、Keychain、缓存工厂或应用会话；平台工厂按下述所有权组合，不能仅据驱动宣布原生离线功能完成。

Apple 范围文件所有权以服务地址、使用者和工作区的完整精确文本生成稳定 SHA-256 标识；长度前缀消除拼接歧义，UTF-8 严格编码拒绝孤立代理项，不按显示名称或客户端时钟分配身份。文件名不包含原始范围文本。范围工厂持有进程间非阻塞排他文件锁，锁文件与可删除事实目录分开：删除事实及密钥期间一直持锁，锁文件不随清理删除，避免新 inode 绕过旧锁。释放通过关闭独占描述符完成；关闭异常保留为不确定状态，不重复关闭可能已复用的描述符。此组件只提供范围标识和租约；默认目录的备份排除、实际数据库打开、缺钥拒绝及文件／Keychain 清理由下述 Apple 缓存工厂负责。

Android 范围租约复用同一严格 UTF-8／UTF-16 长度前缀范围摘要，Apple 既有摘要字节保持不变，摘要实现移入共享层。Android 工厂提供私有不备份根目录；租约只创建根及独立 locks，拒绝对应路径的符号链接和宽权限，非阻塞 FileChannel 排他锁覆盖整个数据库生命周期及清理。[FileLock 平台限制](https://developer.android.com/reference/java/nio/channels/FileLock)指出关闭同文件的其他通道可能释放进程已有锁；同进程须按规范根目录及范围标识阻止再次打开对应锁文件，不能只依赖 OverlappingFileLockException 后关闭新通道。facts/<摘要> 与持久锁文件分开，租约不创建或删除事实目录，不接触密钥。释放仅关闭自有流和通道，不 unlink 锁；关闭异常锁存且不重复关闭可能已被回收的资源，同范围的进程占用保持到进程退出；正常关闭才移除占用，旧实例重复释放不能解除新实例占用。真实系统回归验证互斥、删事实不解锁、路径拒绝和正常重复释放；确认异常可以在真实 close 后注入，不能冒称已复现内核 close 故障或跨进程崩溃。此组件不代替加密驱动、数据库文件资格、缓存工厂与应用接线。

Apple 缓存工厂把 Keychain、范围租约、真实 SQLCipher 驱动和 SQL 快照适配器组合，默认使用应用私有 Application Support 目录并排除备份。持锁后先检查事实目录和数据库，再读取密钥；已有数据库缺钥或目录残留侧文件但没有主库时拒绝，不以失败为重建许可。只有没有既存数据库的新库流程允许创建随机密钥；已有密钥可用于空库重建。初始化失败保留文件／密钥，确实关闭连接后才释放租约；若失败打开的资源关闭不确定，驱动用保留原始 cause 及关闭诊断的内部异常标明，工厂保留租约直到进程退出，不猜测释放。成功清理先关闭驱动，再删除事实目录、指定 Keychain 项，最后释放独占租约；任何步骤失败保持旧实例关闭且不提前让新实例取得范围。该工厂仍不代替应用会话、离线认证、主线程调度或本地事实索引接线。

Android 加密驱动固定官方 sqlcipher-android 4.20.0、SQLDelight android-driver 2.4.1 和 AndroidX SQLite 2.7.1，使用原始 32 字节私有密钥副本，不拼接 SQL 密钥文本。副本保留到全部连接确认关闭；SDK 配置直接引用该数组，不能打开后立即擦除。实际 API 36 独立探针验证引擎 4.20.0 community／libtomcrypt 1.18.2、精确 TEXT、真实回滚及主库／活动日志的有限明文标记检查；三次错钥保原文件且无匹配描述符。普通游标和标量查询均读回 24 MiB 文本，不把 CursorWindow 初始值当作最终容量，不以单次规模证明无限容量。当前单 TEXT 原子发布不因此改变，事实索引仍单独实施。

同一探针在 postKey 实际读取 schema 后抛普通异常，确认隐藏连接遗留一个匹配描述符；生产不得使用探针反射清理。回调必须暂存原始失败并抛私有通用 SQLiteException，使 SDK 执行已知的清理路径；公开边界再还原原异常。若原失败被清理异常取代，或 SDK 报告关闭失败，保持关闭不确定和文件租约，不冒称已关闭。故障所有者连同已捕获的实际 SDK 对象及私有密钥保留至进程退出，避免 GC 终结器重新关闭不确定资源。SDK 连接池可能吞掉关闭 RuntimeException 仅交给公开 LogTarget，驱动在自有打开／关闭边界保留原错误并静默输出，不能仅看 isOpen。普通操作只关注连接池资源错误，不能把普通查询约束错误当作关闭失败；密钥及清理围栏保持到确认资源关闭。适配固定版本并经真实 SDK 故障回归，禁止复制上游内部驱动或反射补关。初始化必须验证实际引擎、内存临时存储及 DELETE 日志；损坏回调拒绝自动删除或重建。调用方提供私有目录及串行缓存生命周期，不把该驱动当完整范围工厂或应用接线；依赖许可、密码提供方和最终 Android 包的原生对齐另行核对。

### D10 缓存加密与登出清理

Android 范围工厂在应用私有 noBackupFilesDir 下组合同一范围摘要、独立租约、Keystore 仓储和真实 SQLCipher 驱动，再交给现有串行 SQL 缓存适配器。先以 lstat 检查 facts 父目录、范围目录及现有主库，拒绝符号链接与孤立边文件；已有主库缺钥时不生成替代钥。打开失败只在真实驱动关闭确认后释放租约，不删除旧存储；关闭不确定时强引用租约，避免 Java 流终结器释放仍需保留的锁。清理先封闭实例并确认关库，再按不跟随符号链接的递归删除事实、擦除该范围密钥，最后释放租约；任一步失败保持围栏供明确重试。工厂只组合内部缓存，不接应用登录、原生索引或页面。

**决定**：缓存加密落盘，密钥取自平台安全存储（Keystore/Keychain）；登出、认证失效或工作区不可访问时清除缓存与密钥。

Android 密钥仓储与登录令牌隔离，以范围摘要对应独立 AndroidKeyStore AES-256-GCM 包装密钥，包装密钥不可导出，不增加额外认证提示。独立安全随机 32 字节数据库密钥只在调用期间解包，版本、12 字节随机 IV 与认证密文保存在私有 noBackupFilesDir；范围摘要加入认证附加数据，拒绝跨范围文件替换。固定长度记录先写临时文件并同步，再同目录原子重命名并同步目录；不使用可能仅记录同步失败而无法向调用方确认的便捷写接口。进程内串行与范围文件锁覆盖读取、首次创建及删除，锁文件不随记录删除。read 缺项不生成密钥；有文件但缺包装密钥、损坏、认证失败或系统拒绝均保留原状态并失败。create 只供明确新库调用，重复创建读回原钥；erase 只删除指定记录、临时密文及对应 Keystore 别名，允许明确重试。原始密钥须等锁与流的释放全部成功后才转交调用方；后置清理失败时擦除未交付副本并保留原异常。Android SDK 的实际 Keystore 与文件行为须通过非 UI 的系统单元测试，不能用 JVM 假密钥库代替；此仓储不代表 SQLCipher、范围工厂、缓存索引或应用已接通。[Android Keystore](https://developer.android.com/privacy-and-security/keystore)的非导出边界不等同于抵御进程内恶意代码，也不把模拟器测试当作硬件保护证明。

Apple 密钥仓储与登录令牌隔离，按完整登录范围的摘要寻址，保存独立随机 32 字节数据库密钥；Keychain 项使用 WhenUnlockedThisDeviceOnly 且不参与 iCloud 同步。read 缺失返回 null，只有明确新库流程调用 create；重复创建读取原项，不删除后重建或覆盖，长度损坏及系统错误直接失败。delete 只清理指定范围；文件存在但缺钥的拒绝及关闭后文件／密钥清理归平台工厂，不由仓储猜测。临时 ByteArray 由持有方擦除，CoreFoundation 对象在异常路径同样释放，不声称可证明 OS 内部所有副本物理擦除。

真实 Keychain 验证使用测试专用授权声明及已启动模拟器的独立入口，不给生产应用增加测试 access group。仓库外探针已确认：普通 standalone 模式返回 errSecNotAvailable，完整启动但仍 standalone 也失败；同时嵌入测试 entitlements 并关闭 standalone 后合成项写入／删除成功。[Kotlin 官方问题及维护者建议](https://youtrack.jetbrains.com/issue/KT-61470)提供测试二进制的授权声明接线方式。普通原生单测与需要系统服务的 Keychain 集成测试分别明确运行，不能把跳过后者计作安全验证通过。

**Web 自动解锁**：用户已确认不增加独立缓存密码。按服务地址、使用者和工作区生成独立随机数据库密钥；用不可导出的 WebCrypto AES-GCM 包装密钥加密后，连同包装 CryptoKey 持久化到 IndexedDB，不保存明文数据库密钥。范围编码使用明确数组边界，其摘要同时作为记录标识和认证附加数据，防止拼接歧义及跨范围密文替换。创建、读取和删除通过同源 Web Locks 串行；密钥记录事务完成后才对调用方返回。浏览器资源 ledger-key-vault.mjs 已实现该仓储，read 缺失返回 null；只有已确认是新库的所有者才能显式调用 create，不以已有加密库缺钥作为重建许可。损坏、存储拒绝及能力缺失直接失败，不静默换钥或回退明文。密钥仓储只负责密钥材料，数据库文件／侧文件删除、跨标签页打开句柄及登录撤权仍由后续缓存所有者组合，不以删一条 IndexedDB 记录宣称完整登出清理。

**风险**：Web 密钥不能等同于 OS 安全存储。[WebCrypto 安全边界](https://www.w3.org/TR/webcrypto/#security-considerations)不保证底层密钥落盘加密；不可导出密钥仍可被同源脚本用于解密。自动解锁不保证抵御完整浏览器配置文件复制或同源恶意脚本，不据此实现明文缓存。

### D11 余额：服务端继续派生维护，端侧不缓存

**决定**：`ledger_snapshots` 与校准语义保持不变，由服务端在提交时按改动流水增量维护；端侧不缓存余额、不提交余额数字。端侧如需展示余额，用共享规则从缓存事实派生。

**理由**：余额是流水的纯函数；让客户端提交余额数字是信任漏洞。此项记为"后续可砍"的简化候选，不在本次范围，因其牵连 `accounts` 规格与投资侧（投资读模型以 `ledger_snapshots.version` 作新鲜度版本号、投资账单期末余额核对依赖校准）。

### D12 投资：本轮不纳入

**决定**：仅**只读**缓存 `cash_investment_funding_relations` 作为现金导入匹配输入；用户已确认允许同步已关联资金记录的最小投资端字段，以保留银证转账双端展示，不缓存完整投资账本、不做任何投资计算。

已接受且生效的资金关系在快照内嵌一个可空的 `investment_event` 子对象，仅复制原事件的 account_id、currency、from_amount 与 to_amount；事件标识沿用外层 investment_event_id，不重复。未接受或失效关系不附带投资端事实。金额继续使用原始精确十进制文本与真实 null，服务端不估值、不聚合、不分配金额；客户端按既有 direction 取对应原资金金额。账户目录已包含所引用账户，私有配置与原投资正文不输出。

删除已关联现金流水时，必须先在同工作区的全部物化数据集中解除目标资金关系的派生外键，再删除关系及维护当前派生结果；与原关系引用清理一样位于同一业务事务，失败时事实、引用和版本全部回滚。该顺序修复不改变投资事件，也不额外推进版本。只读关联字段与资金关系在同一快照读取事务内返回。建立、接受、拒绝或失效关系以及引用账户变化均须同事务推进 ledger_seq；未关联的投资写入不推进现金账本版本。实施时审计资金事件的全部实际写入口：当前事件若仅新增且无原地修改路径，版本由关系进入或离开快照覆盖；未来若加入已关联事件的已同步字段编辑或删除，必须同时接入规范事实版本，不能因其物理表属于投资而跳过。

**理由**：现金导入的候选召回读取该表，缺数据会使"现金↔投资"匹配降级；只读缓存可在不纳入投资计算的前提下保持现金导入结论不变。

### D13 后端差异与事务边界

**决定**：所有校验、写入、版本推进、收据写入在同一事务内完成。PostgreSQL 以工作区行 `FOR UPDATE` 取得写序列化；SQLite 以 `BEGIN IMMEDIATE` 取得写锁。快照在只读事务内锁定版本。方言差异只存在于 persistence adapter，用户可见结果、精确金额与幂等结果必须等价。

### D14 同步与缓存层置于端口之后

**决定**：端侧的同步与缓存实现置于一个明确端口（接口）之后，本地事实缓存 schema 与具体同步机制解耦；领域层只依赖端口，不感知同步机制。

刷新编排 `LedgerSnapshotSync` 绑定单次登录的服务地址／用户／工作区范围，通过事实缓存端口读、原子替换和清理；未确认意图不在此端口内。网络失败保留原快照，版本未变不下载；版本变化只发布一个完整且范围一致的快照。每实例串行刷新，网络不占用存储发布锁；关闭不等待网络响应，先封闭后清理，防止网络迟到重建已清理范围；认证／访问失效同样封闭并清理。每实例成功清理只执行一次，旧实例关闭后的迟到失败按取消处理，不能清掉新登录同范围缓存；清理失败保留原失败并允许重试。新快照不得低于已查询版本或原缓存版本，版本回退作为协议错误停止。缓存 HTTP 请求不自行清除共享登录 token，401／403 由所属同步实例与会话生命周期处理；否则旧请求的 401 可能擦除新登录凭据。其他既有 HTTP 路径保持原认证处理，本片不改全局登录语义。会话切换必须关闭旧实例后接入新实例，不能把 HTTP 前置条件当作完整本地生命周期隔离。真实加密存储由后续端口实现完成，本片测试替身不作为落盘证据。

缓存请求显式携带 `workspace_id`，服务端以已鉴权的当前工作区校验；不相同则拒绝，不能把另一个工作区恰好相同的版本号当成原缓存未变化。版本响应仍只返回版本；快照响应另由客户端核对工作区。既有未携带参数的读取仍按当前选择执行，缓存传输入口始终携带参数；这不赋予按任意工作区读取的权限。

**理由**：D1 将 PowerSync 记为条件性备选。置于端口之后，将来若切换只需替换端口实现（从"版本 + 全量快照"换成增量同步），不波及领域计算、派生与 UI；同时防止把某一同步机制的假设（如服务端物化投影、增量游标）泄漏进领域层。

**备选**：领域层直接依赖具体同步实现（切换时波及面大，否决）。

## Risks / Trade-offs

本地工作簿解码为同步纯计算；合成 5 万行在 Chrome 的 JS／Wasm 读取约 6 秒，尚未计入归一、配对、缓存和呈现。应用接线须验证长任务期间的界面响应与取消，不能仅把同步函数调用改写为挂起函数即认定不阻塞。读取器保留整个预算内 XML 部件，100 MiB 解压预算不是堆内存上限；当前规模证据不覆盖上限输入、低端移动设备或完整导入性能。

- **端侧承担全部启发式计算，低端设备/Web 大账本性能压力** → 以本地索引优化；必要时按"按需拉取旧事实"降级；先在代表视口做真实浏览器冒烟。
- **Web 静态加密接入与密钥生命周期** → 已用合成数据验证 Multiple Ciphers WASM／OPFS 与真实 SQLDelight 驱动兼容；自动解锁密钥仓储已通过 Chromium 重启、并发及拒绝回归。数据库打开组合、活动侧文件、完整清理与故障恢复仍须验证，不采用明文降级。
- **快照体积随账龄增长** → 快照分页/流式；后续如成为瓶颈，按 D1 触发条件补增量。
- **L1 误伤整次导入** → 以重派 + 指纹比对齐静默重提交；加退避与重试上限防 livelock。
- **平台时区数据版本不同** → 浏览年月适配使用各平台当前时区库，固定缩写语义由共享层统一；代表性夏令时、历史秒偏移和公历边界跨端回放。iOS 仅编译不视为运行时验收，也不把有限样本扩称全部时区／年份绝对等价。浏览查询实际接线时评估 formatter 构造与调用成本。
- **端侧派生与服务端规则漂移** → 单一共享实现 + 规则版本；规则变更触发整体重派生。
- **删除物化为破坏性且牵连多接口** → 未上线可接受；迁移期 parity 项随本变更标废，需在文档与规格同步中明确。
- **删除后仍被外部消费的投影接口** → 需确认旧 React Web 与 `mobile/` 已不在兼容范围（proposal 已列非目标）。
- **余额能力保留带来的后续简化债** → 记为可砍项，避免遗忘。

## Migration Plan

1. **前置**：`kotlin-backend-shared-core` 完成 parity 并合入；确认 Python 运行时已废弃。
2. **共享层先行**：把查重/配对/投影/余额规则与写集 DTO 下沉 `business-domain`/`business-contracts`，先服务端复用并保持行为不变（此步不改变对外契约）。
3. **服务端**：新增版本、版本查询、全量快照与写集提交（校验 + 落库 + 收据）；随后删除投影物化与投影读取接口（同步更新 Kotlin 基线 SQL 与显式升级说明）。
4. **端侧**：落地本地库、索引、加密、快照替换，再接入端侧导入与派生，最后切换浏览到端侧派生。
5. **验证**：双后端契约矩阵（版本/快照/写集/幂等/降级）、三端编译与单测、Web 真实浏览器冒烟；原生端默认只做相称编译与单测。
6. **文档收尾**：同步 `docs/feature-map.md`、`DOMAIN_GLOSSARY.md`、现金导入流程文档，并标废被覆盖的 parity 项。

**Rollback**：本变更为未上线产品的破坏性重设计。回滚以版本回退迁移后的 parity 基线（恢复服务端投影物化与投影读取接口、恢复服务端导入写路径）为准；端侧缓存可整体丢弃并从快照重建，不产生服务端孤儿数据。回滚不涉及历史数据迁移。

## Open Questions


- **快照分页阈值与单页规模**：可由实现期依据真实账本规模标定，不改变合同。
- **自研快照性能基线**：本期完成后按现实规模（1 万 / 5 万条流水）测量刷新耗时、流量与资源，作为 D1 独立比较实验的固定基线，不据此取消已约定的后续实验。
- **PowerSync 本地静态加密支持**：仅在启动 D1 spike 时才需核实，不改变当前设计。

现金条目写入仅在 dirty flush、实际新建或删除成员时标记版本，重复 reconcile 和同值 patch 不增加版本；空条目清理由同次成员迁移／删除的标记覆盖。原子流水与组成项创建复用事务标记，任何后续异常连同版本回滚。保存点边界沿用条目仓储的 flush／reload 回调，不从投影版本推断事实变化。

普通导入与有界批量导入在真实父项／组成项写入前标记；重复正式流水沿既有快速路径不写入。草稿合并的实际删除、更新与修订推进共用标记；流水删除在已校验非空目标后、清理引用前标记，整次删除共用事务。人工创建在父项插入前标记，不依赖投影是否可用；分类批量更新只对规范条目变化标记，不把单纯物化投影修正算作事实变更。

组成项金额无变化沿既有后端存储语义判断：SQLite 比较 fixedCashDecimal 文本，保留原有尾零／负零表示更新；PG 比较精确数值。真正无变化才跳过 DML，保留 label、source_key 和 metadata，不改变共享精确值类型对原表示的保留。原来源 writer 黄金中的 touched 仍含旧 Python 全量触达语义，当前 Kotlin 基线已有问题／关系范围优化；本片保留原断言和失败记录，不用它冒充完整黄金通过，旧导入路径退役时核对其测试归属。

关系仓储的 add／replace／候选替换／状态或类型修订在真实 DML 前标记；保留现有显式命令即推进 row_revision 的合同，不把相同候选命令改成无修订。批量状态命令仅触及存在的工作区关系时标记。候选失效仅在实际待失效候选存在时标记。资金对应关系 store 先比原始记录字段，重复扫描无变化不写入；分类更新只对规范 entry／member 变化标记，单纯修正物化投影不推进事实版本。
