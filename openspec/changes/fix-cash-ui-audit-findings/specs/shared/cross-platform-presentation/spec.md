## ADDED Requirements

### Requirement: 关系待确认的主操作与摘要层级

当详情存在待确认关系时，核对动作 MUST 在首屏可见，并作为该状态的主操作。关联摘要 MUST 先表达关系或记录身份，不得在标题与行内重复同一关系类型，也不得把多条记录压成一条无法分辨层级的长串。同一“关系待确认”状态 MUST 在所有页面使用同一语义色。

#### Scenario: 存在待确认关系

- **WHEN** 使用者打开含有待确认关系的收支详情
- **THEN** 首屏 MUST 提供核对入口
- **AND** 关联摘要 MUST 先说明关系，再展示记录明细

#### Scenario: 关联动作与业务标签可辨认

- **WHEN** 使用者在详情查看转账退回等带业务标签的收支，或准备添加关联
- **THEN** 业务标签 MUST 有明确的用户可见位置，不以内部代码代替
- **AND** 添加关联的动作名称 MUST 与所在区块标题区分，清楚表达将新增关联

#### Scenario: 状态颜色一致

- **WHEN** 同一笔收支在列表与详情显示关系待确认
- **THEN** 两处 MUST 使用相同的 warning 语义色

### Requirement: 关联搜索结果区分可选与不可用状态

关联搜索结果 MUST 让使用者从外观区分可选与不可用的目标行。不可用行 MUST NOT 显示可点击的单选控件，并 MUST 以禁用状态和原因说明当前不可关联；存在可选结果时 MUST NOT 重复展示整块“暂不能合并”错误。错误说明 MUST 只在没有可选结果或使用者尝试无效选择时出现。

#### Scenario: 混合可选与不可用结果

- **WHEN** 关联搜索结果中同时存在可选和不可用的目标行
- **THEN** 可选行 MUST 保持可选择
- **AND** 不可用行 MUST 禁用并说明原因，不得显示可点击的单选控件，也不得重复展示整块错误

#### Scenario: 全部结果不可用

- **WHEN** 当前搜索条件下没有可选目标
- **THEN** 界面 MUST 集中说明不可用原因，并保留调整搜索或关闭的出口
