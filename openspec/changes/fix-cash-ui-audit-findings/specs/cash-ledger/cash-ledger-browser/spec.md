## ADDED Requirements

### Requirement: 账本表格状态、行打开与汇总可读性

收支账本 MUST 避免在同一单元格重复表达类型和已确认状态；确认状态 MUST 只在需要用户注意时显示，表头与单元格内容 MUST 表达一致。桌面列表 MUST 允许使用者从整行打开当前收支，并保留键盘与辅助技术可识别的操作语义；复选与单选项仍只改变选择状态。选择列 MUST 提供与列表行为一致的批量选择入口，不得让常驻复选框缺少全选或选择说明。多币种月份汇总 MUST 使用固定列对齐币种、收入和支出，金额 MUST 使用等宽数字。

#### Scenario: 从整行打开收支记录

- **WHEN** 使用者在桌面列表点击某笔收支的名称、日期或金额区域
- **THEN** MUST 打开该笔收支的当前详情
- **AND** 复选或单选项仍只改变选择状态，不触发行打开

#### Scenario: 已确认状态不重复显示

- **WHEN** 一笔收支已确认且没有待处理事项
- **THEN** 类型列 MUST 不重复显示“已确认”
- **AND** 类型列与状态列的显示规则 MUST 一致

#### Scenario: 关联搜索输入与账本筛选一致

- **WHEN** 使用者在关联弹窗输入日期或金额
- **THEN** 输入 MUST 使用与账本筛选相同的日期选择和精确金额校验
- **AND** 无效输入 MUST 在提交前阻止继续，不只依赖服务端通用错误

#### Scenario: 多币种月份汇总对齐

- **WHEN** 同一个月包含多种币种
- **THEN** 各币种行 MUST 按币种、收入、支出固定列对齐
- **AND** 金额 MUST 使用等宽数字

## ADDED Requirements

### Requirement: 筛选弹窗与移动端操作保持可见且不遮挡

详细筛选弹窗 MUST 在首屏提供固定的完成或应用操作，正文独立滚动，不得只依赖关闭图标结束筛选。移动端账本的悬浮新增操作 MUST NOT 遮挡流水的金额或状态信息；快捷筛选换行时“筛选”入口 MUST 保持稳定位置，多余类型 MUST 进入溢出菜单，不得形成零散两行。

#### Scenario: 完成详细筛选

- **WHEN** 使用者打开详细筛选并滚动到任意位置
- **THEN** 完成或应用操作 MUST 保持可见并可结束筛选

#### Scenario: 移动端浏览流水

- **WHEN** 使用者在窄屏查看流水列表并换行显示快捷筛选
- **THEN** 悬浮新增操作 MUST NOT 覆盖任何流水金额
- **AND** “筛选”入口 MUST 保持稳定位置，其余类型进入溢出菜单
