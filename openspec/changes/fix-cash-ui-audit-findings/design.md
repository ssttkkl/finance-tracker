## Context

本变更承接 2026-10-30 Hallmark 对关系治理交付界面的审查。Kimi K3.1 Pro 对最新 7 张截图（1440/390）执行视觉复核，并对照 Material 3 Dialog／Side sheet 规范；结论为 0 critical、8 major、6 minor，另有 2 项静态图无法判断。视觉复核确认无缺字方框，三类关系选择、无 subtype 和一级类型筛选外观成立；未能确认整行点击、列表状态色、账单原文直接展示和动态筛选生成逻辑。用户决定本轮保留已完成的 UI，把修复归入本变更。

## Goals / Non-Goals

**Goals:**

- 修复导入、账本、详情三类页面的层级、重复文案、操作可达性和状态语义问题。
- 保持现有信息架构、业务合同和共享响应式类，不新增页面或路由。
- 复用现有 Material 3 组件与 token。

**Non-Goals:**

- 不改变金额、关系、投影、持久化、权限、导入业务规则或 API 合同。
- 不重做导航、主题或全局视觉系统。
- 不在本阶段实现；实施前须完成 `grill-me → grilling` 并确认各项交互选择。

## Decisions

1. **导入步骤名称只出现一次。** 优先保留正文标题，步骤条使用短步骤名并区分已完成/当前/未开始；步骤条与底部操作对齐到同一内容列。账户分组标题统一为来源账户或渠道主标题，文件名作次级说明。
2. **账本表格拆分类型与状态。** 已确认状态不再重复显示；状态只在待确认、待复核或关系待确认等例外出现。桌面行增加整行打开动作，选择控件不触发行打开。选择列补齐全选或明确的批量选择入口。月份汇总改为固定三列并对金额使用等宽数字。
3. **详情把核对动作提到首屏。** 存在待确认关系时，底部主操作改为核对关联，编辑降为次操作；建议卡排在成员卡之前。关联摘要按记录分行，关系类型只在标题或单个 chip 出现一次。关联卡片的关系类型标签上移到卡片顶部。关系待确认在列表与详情统一使用 warning 语义色；补拍列表标签后确认实际颜色角色。
4. **筛选弹窗提供固定完成出口。** 弹窗正文独立滚动，底部固定“完成／应用”操作，首屏可见；不依赖关闭图标完成筛选。
5. **关联搜索结果区分可选与不可用。** 不可用目标行移除可选单选圈并显示禁用状态；存在可选结果时不重复展示整块“暂不能合并”错误，原因集中或逐行说明；仅在没有可选结果或选中无效项时显示对应错误。
6. **移动端安全区与筛选稳定性。** 悬浮新增按钮不得遮挡行金额，必要时为列表预留安全区或移动动作；快捷筛选换行时“筛选”入口固定在稳定位置，多余类型进入溢出菜单，不形成零散两行。
7. **验证方式。** 共享单测、Android/iOS 编译、Web 构建与真实浏览器 1440/390 冒烟；实施后重新执行 Hallmark 审查并记录人工替代范围。

## Risks / Trade-offs

- 首屏主操作调整会改变详情底部按钮层级，可能影响既有 E2E 断言，需要同步更新测试并重新演示。
- 整行可点与选择控件共存需要确保点击目标不冲突，并保留键盘与无障碍语义。
- 整行点击、列表状态色、账单原文直接展示和动态筛选生成逻辑无法仅凭静态截图确认，需在实施前补运行时检查或补拍。
- 首屏操作调整和移动端安全区会影响既有 E2E 布局断言，需要同步更新并重新演示。
