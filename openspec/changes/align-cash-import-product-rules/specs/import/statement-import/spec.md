## MODIFIED Requirements

### Requirement: 每个来源业务行都有明确处理结果

系统 MUST 为每个来源行返回正式新增、更新、草稿、完全重复、批内重复或跳过以及安全原因。缺必要信息的可辨认新流水保存草稿；无法可靠辨认的行或正式固定字段冲突跳过。仅渠道合同允许隔离的输入问题和既定业务冲突不阻塞其他行；内部程序错误 MUST 停止当前操作并保留诊断，不暴露技术细节。

#### Scenario: 缺账户与正常新增

- **WHEN** 1000 行中 5 行缺账户
- **THEN** 保存 995 条正式和 5 条草稿，草稿不统计

#### Scenario: 正式金额冲突

- **WHEN** 相同身份已有正式记录而新来源金额不同
- **THEN** 整条更新跳过，已有记录及关系不变，其他行继续

#### Scenario: 白名单提示行
- **WHEN** 来源文件包含该导入渠道明确允许忽略的非业务提示行
- **THEN** 系统 MUST 计入白名单跳过数量且不创建账本记录

#### Scenario: 未知业务行
- **WHEN** 来源文件包含不符合任何已声明业务行或白名单结构的记录
- **THEN** 系统 MUST 使整批导入失败，并不得写入该文件的部分账本记录

#### Scenario: 预览白名单跳过行

- **WHEN** 来源文件包含该导入渠道明确允许忽略的非业务提示行
- **THEN** 系统 MUST 计入导入预览的可核对摘要
- **AND** 该行 MUST 不要求账户映射且不得创建账本记录

#### Scenario: 业务行缺少来源账户身份

- **WHEN** 一个业务行既没有来源合同声明的账户身份，也不能由该文件唯一且确定的账单档案身份归组
- **THEN** 系统 MUST 使当前导入会话进入错误状态并指出无法识别来源账户
- **AND** MUST NOT 用对方账号、备注、商户名称或空字符串默认账户代替来源账户身份

#### Scenario: 转换器内部错误

- **WHEN** 来源行通过输入边界后，转换器出现断言、类型或算术程序错误
- **THEN** 停止当前操作，不将其转成 `row_unreadable`、跳过或草稿，也不换另一个解析器重跑
