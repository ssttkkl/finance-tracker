## Context

动机与范围见 proposal。沿用现有导入会话、三文件并发队列、账户命令恢复和统一诊断；不增加通用错误框架。现有捕获点有些位于整个转换／扫描循环外，使程序错误被当成用户文件问题后继续。UI 审查另确认原请求重试被错误正文隐藏、账户未决币种更新可重复提交等路径。

## Goals / Non-Goals

修复当前现金导入到编辑／恢复路径的真实缺陷。保留精确金额、权限、修订和原命令核实，既有独立成功不回滚为失败。备注明确确认后的长期保护有效；不清理既有人工标记、不顺带修改分类规则。不改页面信息架构、主题或原生设备验证范围。

## Decisions

### 异常与结果

在外部文本、ZIP／XML、密码、容量、SDK 网络边界识别预期故障。转换器或内部对象验证异常原样上抛，现有 cash_diagnostic_scope 提供定位，HTTP 边界 report_cash_failure 记录安全调用帧；未知错误返回 500。提交边界保留 CashCommitBoundary 的结果确定性及原幂等键，不从异常类型单独推断是否写入。

明确可由用户恢复的故障展示具体原因及处理入口；网络读取可重试，不可恢复程序错误显示“系统错误”，保留安全退出，写入未知仍核实原操作。客户端业务失败保留既有 DomainFailure，包装时保留 cause。任务边界记录原异常，使用安全错误状态停止受影响操作；上传 finally 只能释放槽位，不能重新启动因程序错误停止的队列。真实单文件输入失败仍单项隔离。分页内部合同错误不得作为普通网络重试继续。恢复指针保存失败显式报告，不静默吞掉。

### 账户与选择

ensureCurrencies 与手动更新共用未决目标保护；未知目标恢复键先核实，防止生成新键。当前会话本地未提交选择仍有效时，刷新保留这些选择，包括本次暂不选择；这不是持久空值策略。账户读取成功且对应当前选择请求后才回填，失败不采用旧缓存。

### UI 策略与跨端

使用现有 Material 3 按钮、AlertDialog、Snackbar 和不定进度，沿用 FinanceTheme/Git token。Hallmark 预检方向：保留文件→账户→预计结果的任务结构；只在相应对象显示错误或动作，去除计时伪进度和重复确认，正常状态保持安静。局部组件修正不构成重大 UI 重构，无需新 HTML 原型。

原请求重试入口与错误正文独立渲染。空密码在字段处说明，不发请求。退出选项放弹窗正文，只有一个确认和取消；继续编辑保留编辑内容。灰色可点击按钮保留活动控件可访问性，不用 disabled 文本色冒充可访问点击。首次新版演示在相称编译及代表浏览器检查后立即提供，最终审查随后完成。

短反馈按具体动作归属：文件选择器打不开、请求中尝试退出、已就绪后选择账户的临时读取失败使用一次 Snackbar；超出文件总容量补一次批次提示，保留超限文件的原因与移除入口。账户读取失败保留原选择，Snackbar 的重试动作读取同一账户；资格失效、初次加载、币种写入和未知结果仍用持续状态。文件移除的网络失败不能证明未执行，保留刷新要求，不统一替换成短提示。文件问题解决只清理文件引导；子表单的通知在该表单内显示，不叠加确认框。

组件沿用单一明确决定、明确动作名与正文滚动时保留操作的仓库规则。Material 官方组件核验已按 §4.1 对渲染页正文执行（无头 Chrome 读取 M3 官网，2026-11-03）：`Dialogs`（多步骤任务用 full-screen dialog；标题区只放关闭 X；未保存关闭先用基本对话框确认丢弃；确认动作写明结果，不用 Done/OK）、`Snackbar`（单个文字按钮动作；带动作的 Snackbar 保持到用户处理；连续多条一次一条）、`Buttons`（次要动作用 text button）、`Progress indicators`（时长不确定用不定进度）。采用：全屏导入容器、左侧关闭、1 dp 分隔线、底部操作栏、退出确认对话框、Snackbar 单个“重试”动作。偏差：M3 建议 full-screen dialog 只用于 compact 断点，medium/expanded 改用 basic dialog；本实现各断点沿用同一完整任务容器，按 §3.1“多步骤任务使用已有完整任务容器”并在桌面把表单内容收窄到 720 px、列表按信息架构铺开，演示时用户未提出异议，记为有意保留的偏差。Web、Android、iOS 共享状态和文案均受影响；Web 代表视口真实冒烟，Native 编译及单元测试。

渲染页审查（用户确认演示后补做，真实 Chrome 截图）暴露的共享组件问题按用户决定“全修含共享组件”处理：新增 `financeInteractiveBorder`，把活动 `OutlinedButton` 与未选中 `FilterChip` 的描边从 `outlineVariant`（对白底 1.27:1）统一到 `outline`（约 4.6:1），选中态由容器色表达；`CashLedgerRow` 增加 `fieldLabels`、`amountUnknown`、`attentionAction` 三个默认关闭的开关，仅导入核对启用字段名、未知金额中性色与“补齐信息”入口，账本列表其余行为不变；月份汇总在无已定价收支时不再显示“无收支”，避免与“金额未知”冲突；文件行改为文件名与“✕ 移除文件”同行，并保留“移除文件 <文件名>”无障碍名称。权威未提交拒绝只提供返回，不再给出重放或再查入口。桌面表格的状态徽标从“流水类型”列移到交易信息列，该列只保留收支类型与来源标签。用户可见的原因文案统一不带句末句号（与后端 `_REASONS` 既有写法一致），演示夹具同步。

账户映射按用户确认的语义调整：打开“合并不同渠道的同名账户”时不再显示第一级分组，所有来源账户按来源顺序平铺，每个条目用账户名作标题、渠道与会话账户作补充信息；关闭合并时保留按会话账户分组，但组标题降为弱化小节标签（`titleSmall` 半粗、次级色、更大上留白），与账户名（`bodyLarge`）形成层级，避免组标题、账户名与“对应账户”取值三者同级。

### 备注清空

保存前通过弹窗明确告知“保留为空”会阻止重导／重算自动填回，用户确认后继续使用现有长期人工保护。重复提交和未修改保存不额外建立保护或重复确认。普通编辑在维护规划边界去除同值公共补丁；导入中相对新来源的明确覆盖保持原意，仓储不按更新前的旧值擅自丢弃补丁。关闭弹窗仅回到表单。用户明确选择恢复账单原始备注，并在弹窗展示实际内容。服务端按公共对象展示基准返回 `original_note` 和 `original_note_token`；凭据绑定来源流水 ID、修订与备注值。只有明确恢复原文时请求携带 `restore_note_token`，预览和最终提交重验来源及请求备注，变化返回已有 `entry_changed`。普通编辑仍按公共修订核对，客户端不能猜测组内第一笔。恢复来源值作为明确备注修改保存；无来源备注时展示为空，不虚构历史值。

## Risks / Trade-offs

- 收窄捕获可能遗漏合法坏文件异常 → 用真实坏 ZIP/XML/PDF 与外部 I/O 故障回归，同时注入 AssertionError/TypeError/ZeroDivisionError 验证传播。
- 未知写入与诊断混淆 → 保留提交结果协议；明确在发出写入前后的故障注入，断言原键不丢失。
- 多请求乱序 → 维持 generation/revision 接纳规则，停止队列不改写独立已成功事实。
- 共用备注编辑影响账本 → 仅在明确清空且保存时询问，同值与失败重试验证幂等，分类行为不变。

## Migration Plan

无数据库结构迁移和旧标记清理。客户端与服务端合同变更同组发布；SQLite 与专用 PostgreSQL 测试库验证写入合同。回滚本次代码／规格即可，已确认用户值和原恢复键不可批量删除。
