## Context

旧编辑状态按单条流水构造全部字段并调用已关闭的 PUT；当前后端允许范围按创建方式和当前权限返回。公共属性保存在稳定收支对象，普通手动和双端转账通过当前维护计划保存，新建仍使用各自直接命令。

合同输入为 [现金流水](../../../docs/cash-ledger.md#5-操作流程及作用范围) 和 [维护接口](../../../docs/cash-import-redesign-contracts.md#35-后续维护与读取)。共享模型、宿主与集中声明所有权见 [维护变更](../compose-cash-ledger-maintenance/design.md#共享基础与并行归属)。

## Goals / Non-Goals

在原详情容器完成正确编辑，在“记一笔”内完成普通记录与转账。只构造服务端允许的字段和操作，不修改配对、金额、来源或持久化规则，不承担来源问题／草稿补处理界面。

## Decisions

### 用户任务与信息架构

| 场景 | 表单内容 | 保存方式 |
|---|---|---|
| 导入单条或合并记录 | 固定信息只读摘要；仅分类、备注、对方及对方账户信息输入 | 公共对象修订约束的 `edit_entry` |
| 普通手动记录 | 当前允许的金额、币种、账户、时间、类型和公共信息 | 当前单条维护计划，禁止外部配对 |
| 手动转账 | 双账户、同币种联动金额或换汇双金额及公共信息；无合法双端编辑能力时仅公共字段 | `edit_entry` 及服务端允许的 `member_patches` 共同提交 |
| 记一笔 | 同一入口切换“普通记账／转账”；普通记账内选收入／支出，各模式保留未保存输入 | 普通创建或 `/cashflow/transfer` 明确转账命令 |

编辑仍使用 Compact 全屏、Regular/Wide 右侧详情任务容器，在原容器替换布局；固定摘要→可编辑字段→底部取消／保存。组内来源不再有编辑入口。新建转账在同一记账任务中以“普通记账／转账”两选项切模式，不新增一级导航或独立转账产品页。

### 输入与命令边界

新建编辑器文件及独立状态，消费维护模块公共协议；不在旧账本巨型 ViewModel 继续堆叠另一组状态。字段未改与明确清空分别编码，禁止序列化整个旧 DTO 再删字段。创建方式和内部人工标记不允许由表单指定。

普通公共保存可在点击后内部预览再提交；若出现未向用户展示的影响，留在当前任务确认。保留当前 `entry`／父流水／关系和计划的真实修订，不在冲突时自动换成最新修订覆盖。已知并发冲突统一提示重试，不实现自动重放或表单合并；未知维护结果通过原命令核实；本地状态切换不能伪造保存成功。

转账新建使用后端现有明确双端命令和真实账户资料；同币种新建只输入一个金额并联动双端，不提供会被后端忽略的独立转入金额；不同币种显示双金额，不用 `Double` 推算汇率或把两币种面额强制相等。编辑使用服务端返回的双端成员 ID 和允许字段，不按数组顺序猜转出／转入，也不单独写一端。现金—投资单端及孤立转账遵守服务端保守权限，不能套用完整双现金转账表单。

直接新建没有维护计划相同的收据恢复保证：响应未知时不自动重发，保留输入并提示核对当前账本；不新增后台自动去重机制。已有记录维护后按实际稳定流水引用重新定位／刷新。新建转账成功只返回直接命令结果，没有稳定流水 ID 或维护收据；确定成功后刷新当前账本，不猜造 ID 或自动定位同额记录。取消和返回按未保存输入确认，不能把取消理解为回滚已发送命令。

### Hallmark 方向与自查

共同预检见 [维护变更](../compose-cash-ledger-maintenance/design.md#hallmark-方向与自查)。用户选择只列可编辑项、固定信息放摘要，以及记账内切换转账；沿用整体外观、Material 3、字体和 token，不重做品牌。

表单聚焦输入，摘要不伪装成禁用输入框；移除旧全字段编辑、来源成员编辑、重复保存说明和无关外部关联动作。沿用标准字段状态与底部主要操作，不固定按钮尺寸、不增加 Finance 控件包装。桌面单项表单不超过 720 dp，Compact 单列无横向滚动。

规划自查覆盖权限不伪造、金额精确、双端原子、清空、并发、返回和键盘；开发后仍需实际页面 Hallmark audit、Web 代表视口演示及用户确认。

## Risks / Trade-offs

- 以渠道文字推断可编辑范围 → 仅消费固定创建方式及服务端当前权限。
- 单端转账被当作普通可改金额记录 → 双端能力缺失时保守只展示公共字段。
- 预览对象与提交对象变化 → 保留原确认依赖，过期后核对，不自动改目标。
- 与维护模块抢改宿主 → 新文件实现编辑器，宿主改动由维护模块集成，App／Graph 最终由导入模块统一接线。

## Migration Plan

共享基础合入后，先以失败测试覆盖权限与补丁，再实现公共编辑、普通手动、转账双端；由宿主接入真实入口，删除无人调用的旧更新路径。新协议不能回退旧 PUT。Cross-platform Impact Check：Web、Android、iOS 及共享输入状态均受影响，必须验证相同字段、确认时点、错误和结果；没有 schema 迁移或未决业务方向。

并发处理按个人使用场景保持简单：后端发现修订变化、过期或安全可重试失败时返回明确错误，页面提示重试；不自动合并表单、不自动替换修订重放、不增加跨版本执行路径。只有结果无法确定的已发送命令保留最小原键核实，避免重复记账。实际配对及公共值冲突仍由用户作业务选择。

默认验证遵循当前 AGENTS.md：Web 仅冒烟受影响流程，Android、iOS 只做相称编译和单元测试；三类窗口仍是响应式实现合同，不强制设备或逐窗口截图 QA，不将未执行范围记为通过。
