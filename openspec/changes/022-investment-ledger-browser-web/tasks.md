# Tasks

## 1. 需求拆分

- [ ] 1.1 验证并实现：- **FR-001**：系统必须在 020 已交付的本机 API 与 Node 前端中提供投资账本视图，展示发生时间、账户、事件类型、标的、付出资产、换入资产、手续费、备注、导入渠道、关系摘要和证据入口。
- [ ] 1.2 验证并实现：- **FR-002**：系统必须支持投资事件的日期范围、账户、事件类型和标的筛选，以及稳定分页。
- [ ] 1.3 验证并实现：- **FR-003**：系统必须按当前页投资事件批量组装关系摘要，并提供当前工作区内单条事件的受控证据详情。
- [ ] 1.4 验证并实现：- **FR-004**：系统必须展示既有组合查询返回的账户、标的、数量、成本、当前单价、计价币种、计价币种市值、展示币种、折算市值和估值状态。
- [ ] 1.5 验证并实现：- **FR-005**：系统必须保留 `complete`、`stale`、`partial`、`unsupported` 状态及原因；不可用金额必须为空。
- [ ] 1.6 验证并实现：- **FR-006**：系统必须以一次有界批量组合查询读取估值，且行情局部失败不能隐藏其他持仓或投资事件。
- [ ] 1.7 验证并实现：- **FR-007**：系统必须在 PostgreSQL 与文件型 SQLite 上运行同一投资浏览响应契约矩阵，并覆盖工作区隔离、精确金额、时间边界、稳定分页、证据和估值状态。
