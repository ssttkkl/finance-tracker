## MODIFIED Requirements

### Requirement: 现金账单导入统一核对并一次确认

Compose MUST 在文件和账户准备后，以一个预计收支列表承载流水、差异和配对核对，一次确认整个计划。主列表按服务端拟确认合法图展示，每项显示已确认或待确认；组成流水、来源和关系仅在该项详情按需展开。待确认不阻塞其余内容保存，默认引导之后回主页处理，不增加独立关系步骤或逐条强制确认。核对表格 MUST 复用主页流水表格，默认筛选待确认，可切换全部；没有待确认项时自动显示全部。已知业务跳过、重复与文件问题 MUST 在确认前展示，不受待确认筛选隐藏。

#### Scenario: 完整与缺项内容一起核对

- **WHEN** 同批包含完整记录、缺账户记录、重复及一项跳过
- **THEN** 列表展示可保存的正式／草稿预计项，摘要和明细保留重复与跳过原因，允许按当前可提交计划一次确认

#### Scenario: 待确认不拆散已有组

- **WHEN** A 与 B 已确认合并，B 与 C 的新增关系待确认
- **THEN** 预览保留 A-B 与 C 两项，不提前合并 C，也不拆开 A-B

#### Scenario: 完整候选成员在当前详情核对

- **WHEN** 关联候选包含当前预计项之外的新行或已有流水
- **THEN** 当前详情按明确引用显示完整真实成员，单候选也不省略；不把预计合并摘要当成员，缺成员时不允许接受

#### Scenario: 退款已全额抵扣

- **WHEN** 合法拟确认组的最终净额为零
- **THEN** 列表保留该项供核对，不将退款另列为重复收入

### Requirement: 导入账户准备使用独立账户命令

账户准备 MUST 显示服务端来源分组、建议与本次选择，支持暂不选择及独立创建／修改入口；保存成功的真实账户才可选择。创建／修改立即生效，不随导入事务自动回滚。未完成且未有成功导入业务写入时退出，若存在账户改动 MUST 合并询问撤销并退出、保留并退出或继续导入；未知结果先核实。安全撤销仅使用普通账户命令及真实连续修订证据，不猜测刷新前旧值。

#### Scenario: 创建后选择

- **WHEN** 用户在账户表单保存新账户成功
- **THEN** 账户立即进入可选集合，取消后续导入不会自动删除它

#### Scenario: 新账户已被其他记录使用

- **WHEN** 用户选择撤销并退出但账户已被其他记录引用
- **THEN** 保留不能安全撤销的改动，显示具体业务原因，不删除被引用账户

#### Scenario: 已持久化失败结果但没有成功业务写入

- **WHEN** 收据为 `committed=true/status=failed` 且不存在成功业务写入，用户退出时仍有独立账户改动
- **THEN** 仍提供安全撤销／保留／继续的退出选择，不仅凭结果阶段或 `committed` 跳过询问；成功、部分完成、仅草稿和正常无新增结果不触发撤销

#### Scenario: 刷新后无法恢复旧值

- **WHEN** 恢复任务时只有账户命令标识，没有完整旧值和连续修订证据
- **THEN** 可核实命令结果，但不提供虚假的自动还原；退出可保留实际账户状态

### Requirement: 导入核对与实际结果具有可操作状态

统一核对 MUST 展示日期、金额、账户、说明和确认状态，未知值保持未知；草稿不计入金额汇总，正式待确认不按状态一概排除。完全重复、跳过及关系失败保留处理原因，文件问题单列。结果 MUST 使用实际收据的摘要，不重列全部流水，不沿用失败前的预计合并。加载、空、错误、提交中、部分完成、仅草稿、无新增、全局未保存和结果未知 MUST 可区分；技术细节不得进入用户原因。

#### Scenario: 关系保存失败

- **WHEN** 预览预计合并，但实际结果中该组关系保存失败
- **THEN** 显示统一导入错误和未合并原因，准确说明存在已保存流水，不断言全批成功或全批回滚

#### Scenario: 结果返回账本

- **WHEN** 用户从摘要或统一错误页返回账本
- **THEN** 刷新当前账本并保留原筛选，不增加结果页逐项处理入口

#### Scenario: 全部重复

- **WHEN** 实际收据表明本次没有新建且记录均为重复
- **THEN** 显示真实无新增结果并允许结束，不把零新增当作网络失败重新提交

### Requirement: 导入选择变化在当前任务重新预览

账户、字段或关联决定变化后 MUST 在同一任务重新生成预计列表，保留完整选择集合及当前修订；未刷新计划不能确认。失效选择 MUST 指出需要重新处理的项，不悄悄改选对侧。分页和筛选 MUST 不缩小最终确认范围。输入权限与公共值采用服务端合同；实际人工公共冲突时才要求选择共同值。同一共同来源操作 MUST 只提交一份行决定；“保留当前信息”仅在已有对应流水时显示并可选择，新流水只提供实际可执行的动作。

#### Scenario: 新流水不出现保留当前信息

- **WHEN** 用户打开尚无对应现有流水的导入预计项
- **THEN** 详情不显示“保留当前信息”，客户端也不接受该行决定；已有流水的来源差异仍可选择保留

#### Scenario: 已填写的资金信息互相矛盾

- **WHEN** 用户在导入字段表单填写不可用账户、矛盾的币种／收支方向或不等于总额的完整分摊
- **THEN** 保存时在当前表单提示修改，保留输入且不发起预览；绕过表单的无效补丁由后端拒绝。尚未填写的字段仍允许按草稿规则保存

#### Scenario: 独立编辑预计整笔公共属性

- **WHEN** 用户修改合并后收支的公共备注，同时保留或延后某来源差异
- **THEN** 通过当前计划明确授权的整笔引用预览和保存公共修改，来源决定及原文不变；无本次操作的既有成员也属于完整目标

#### Scenario: 整笔编辑目标变化

- **WHEN** 预计整笔成员或既有修订变化，或提交时该目标依赖未能完整保存
- **THEN** 拒绝该命令并回滚，不将修改套用到其他收支；用户重新核对后才可提交

#### Scenario: 修改一项账户

- **WHEN** 用户修改选择后尚未取得新计划
- **THEN** 确认不可执行，重预览成功后使用新计划及新修订，其他有效决定继续保留

#### Scenario: 候选失效

- **WHEN** 服务端返回某关系选择已失效
- **THEN** 只提示对应项重新处理，不换成另一对侧，也不回到独立配对步骤

## ADDED Requirements

### Requirement: Compose 导入接通实际结果和原命令恢复

实际页面 MUST 接通实际收据与原键提交核实。正常完成仅展示结果摘要和返回；提交新增异常统一显示“导入出错”、安全原因与返回，不提供逐项处理、失败明细或重试入口。发送确认前持久保存有界且隔离的最小命令标识；不得持久保存原文件、密码或财务正文。未知结果期间不得换键重导、清除恢复证据或启动账户撤销；已提交重放返回原结果；核实为 `retry_original` 时只以原计划、修订和键重放，`pending` 继续核实，`not_committed` 后才恢复编辑；返回仍保留未知请求的最小恢复证据。安全恢复不构成逐项失败重试入口。金额和修订 MUST 按真实协议传输，三端不因 SQLite 或 PostgreSQL 改变业务结果。

#### Scenario: 确认响应丢失

- **WHEN** 提交已发送但没有确定结果
- **THEN** 显示正在核实的状态，通过原键／原计划核实，已提交读取实际收据，权威未提交后才恢复可编辑状态

#### Scenario: 提交新增异常

- **WHEN** 提交发生预览后并发变化或执行异常
- **THEN** 展示统一导入错误、安全原因和返回；本次业务写入全部回滚，不提供逐项处理或失败子集重试入口；历史收据仍显示真实摘要

## REMOVED Requirements

### Requirement: 导入配对阶段在移动端使用关系卡片

**Reason**: 导入采用统一收支列表，关系在当前项详情处理。
**Migration**: 使用“现金账单导入统一核对并一次确认”和共享完整任务页合同。

### Requirement: 移动端关系卡片保持原有配对决定语义

**Reason**: 独立关系卡片步骤不属于当前导入任务。
**Migration**: 使用服务端完整候选与组决定，在当前收支详情核对。

### Requirement: 配对移动视图覆盖响应式状态与无障碍交互

**Reason**: 三端验证以统一任务及其详情为范围。
**Migration**: 使用共享完整任务页的三类窗口、键盘和系统返回验收。

### Requirement: Web 导入关系建议与 CLI 关系结果保持等价

**Reason**: 现金导入 CLI 已退出公共合同。
**Migration**: Web 与 Native 直接消费当前会话计划和实际收据，不恢复 CLI。

### Requirement: 导入错误只读显示准确诊断位置

导入错误及文件失败具有诊断信息时，共享页面 MUST 在既有安全原因下显示处理环节、文件和来源位置及错误编号。单条直接摘要，多条通过次要文字按钮展开只读明细；相关范围 MUST 明确为相关记录，不称为已确定坏行；无法定位只显示已知阶段。不新增逐项修复或重试入口，不改变返回及原命令核实合同，三端共享语义。诊断来源与安全规则以 `import/cash-import-session` 为唯一合同。

#### Scenario: 转换失败具有单条来源位置

- **WHEN** 文件解析结果携带转换阶段和一个来源位置
- **THEN** 文件卡直接显示文件和来源序号及错误编号，不显示异常堆栈或增加行级动作

#### Scenario: 提交失败涉及多个成员

- **WHEN** 提交异常只定位到关系组或批次
- **THEN** 错误页显示环节和相关数量，默认折叠成员定位，点击可展开或收起，返回保持唯一主要动作
