## MODIFIED Requirements

### Requirement: 现金账单导入统一核对并一次确认

Compose MUST 从账本打开全屏对话框，先完成文件选择与解析，再单独展示从文件识别出的来源账户映射，然后以一个预计收支列表承载只读流水、差异和关联核对，一次确认整个默认计划。账户未映射允许继续，相关可保存内容按实际计划成为草稿。核对首屏 MUST 在默认全部流水中优先排列预计草稿及其已知值、缺项原因，并明确区分仍可统计的正式待确认流水；未知账户、金额或时间不得伪填。主列表按服务端拟确认合法图展示；草稿和待确认关系 MUST 使用醒目的状态标签与对应底色，普通已确认记录 MUST 不显示状态标签。待确认关系统一标作“关系待确认”，不得称为“手动配对”；同一记录同时为草稿和关系待确认时可并列显示两个标签。关系类型、双方来源和完整真实成员仍可在流水行与详情中只读核对。流水备注 MUST 只显示账单中该流水的业务备注字段；关系摘要与核对原因 MUST 分别标明，不得拼入或替换备注。待确认不阻塞其余内容保存，之后回账本维护，不增加独立关系步骤或逐条强制确认。核对表格 MUST 复用主页流水表格，可切换草稿、关系待确认与全部；默认全部视图不得把配对隐藏在独立提示或入口后。已知业务跳过、重复与文件问题 MUST 在确认前展示，不受筛选隐藏。详情 MUST 只读，不提供字段编辑、来源采用、关系接受、延后或候选改选。

#### Scenario: 文件后指定账户

- **WHEN** 用户选择并解析文件，系统返回来源账户分组
- **THEN** 先显示逐文件处理结果，再进入来源账户映射；每组显示建议与本次选择，允许暂不选择后继续生成预计列表

#### Scenario: 草稿优先核对

- **WHEN** 预计列表同时包含缺账户草稿和有待确认关系的正式流水
- **THEN** 核对首屏优先展示草稿已知信息、缺账户原因及不参与统计的状态；正式流水单独标示待确认且保留其统计语义，两者均可打开只读详情

#### Scenario: 完整与缺项内容一起核对

- **WHEN** 同批包含完整记录、缺账户记录、重复及一项跳过
- **THEN** 列表展示可保存的正式／草稿预计项，摘要和明细保留重复与跳过原因，允许按当前可提交计划一次确认

#### Scenario: 待确认不拆散已有组

- **WHEN** A 与 B 已确认合并，B 与 C 的新增关系待确认
- **THEN** 预览保留 A-B 与 C 两项，不提前合并 C，也不拆开 A-B

#### Scenario: 完整候选成员在当前详情核对

- **WHEN** 关联候选包含当前预计项之外的新行或已有流水
- **THEN** 当前详情按明确引用只读显示完整真实成员，单候选也不省略；不把预计合并摘要当成员，缺成员时保留服务端待确认状态

#### Scenario: 流水行显示关系信息与待确认状态

- **WHEN** 预计列表同时包含草稿、证据充分的同笔支付关系和证据不足的退款候选
- **THEN** 默认全部视图先排列草稿；同笔支付的预计合并流水行显示关系类型和两条来源但不添加确认标签，退款候选所在行显示醒目的“关系待确认”标签、关系类型、候选双方与尚未合并
- **AND** 点击任一流水行可在只读详情查看完整真实成员、识别依据与预计统计效果；预计关系在最终确认前尚未生效，待确认关系的两笔流水保持独立统计

#### Scenario: 只标记草稿与待确认关系

- **WHEN** 核对列表同时包含草稿、普通已确认记录及一个 `action=defer` 的关系候选
- **THEN** 草稿以“草稿”标签和警示底色显示，关系候选以“关系待确认”标签和主色底色显示，普通已确认记录不显示状态标签
- **AND** 草稿同时存在待确认关系时，两种状态标签均显示；列表可通过“关系待确认”筛选查看候选

#### Scenario: 业务备注与关系说明分开展示

- **WHEN** 预计流水同时包含账单备注、关系摘要或核对原因
- **THEN** 备注原样显示账单中的业务字段；关系摘要以“关联”单独标明，核对原因以“需核对”单独标明，两者都不拼入或替换备注

#### Scenario: 默认决定一次提交

- **WHEN** 用户只完成账户准备并确认核对列表
- **THEN** 提交保留账户选择，`row_choices`、`entry_choices`、`relation_choices` 均为空，字段和关系使用服务端默认决定

#### Scenario: 退款已全额抵扣

- **WHEN** 合法拟确认组的最终净额为零
- **THEN** 列表保留该项供核对，不将退款另列为重复收入

### Requirement: 导入账户准备使用独立账户命令

账户准备 MUST 显示服务端来源分组、建议与本次选择，并允许暂不选择。不得显示分区级新建账户按钮或账户编辑按钮；每组目标账户下拉菜单 MUST 含“＋新建账户”选项。选择后立即打开独立新建账户表单，并预填来源账户名称、来源币种；账户类型按既有 Web 规则从名称推断，名称包含“花呗”或“信用卡”时为 `loan`，其余为 `cash`。创建成功后 MUST 返回原来源组并选中新账户；取消创建不得更改映射。保存成功的真实账户才可选择，创建立即生效且不随导入事务自动回滚。所选账户未支持该来源组的一个或多个币种时，MUST 在该组下拉框下方以小字列出缺少的币种，不得自动修改账户。未完成且未有成功导入业务写入时退出，若存在账户改动 MUST 合并询问撤销并退出、保留并退出或继续导入；未知结果先核实。安全撤销仅使用普通账户命令及真实连续修订证据，不猜测刷新前旧值。

#### Scenario: 创建后选择

- **WHEN** 用户从某来源账户的目标账户下拉菜单选择“＋新建账户”并成功保存
- **THEN** 表单预填该来源的名称和币种，按名称推断账户类型；保存后回到同一来源组并选中新账户，取消后续导入不会自动删除它

#### Scenario: 已有账户币种不足

- **WHEN** 已选账本账户未支持来源组中的一个或多个币种
- **THEN** 在该来源组的账户下拉框下方显示缺少的币种，不自动修改该账户

#### Scenario: 新账户已被其他记录使用

- **WHEN** 用户选择撤销并退出但账户已被其他记录引用
- **THEN** 保留不能安全撤销的改动，显示具体业务原因，不删除被引用账户

#### Scenario: 已持久化失败结果但没有成功业务写入

- **WHEN** 收据为 `committed=true/status=failed` 且不存在成功业务写入，用户退出时仍有独立账户改动
- **THEN** 仍提供安全撤销／保留／继续的退出选择，不仅凭结果阶段或 `committed` 跳过询问；成功、部分完成、仅草稿和正常无新增结果不触发撤销

#### Scenario: 刷新后无法恢复旧值

- **WHEN** 恢复任务时只有账户命令标识，没有完整旧值和连续修订证据
- **THEN** 可核实命令结果，但不提供虚假的自动还原；退出可保留实际账户状态

### Requirement: 导入核对与实际结果具有可操作状态

统一核对 MUST 展示日期、金额、账户、说明和确认状态，未知值保持未知；草稿不计入金额汇总，正式待确认不按状态一概排除。完全重复、跳过及关系失败保留处理原因，文件问题单列。结果 MUST 使用实际收据的摘要，不重列全部流水，不沿用失败前的预计合并。加载、空、错误、提交中、部分完成、仅草稿、无新增、全局未保存和结果未知 MUST 可区分；技术细节不得进入用户原因。

#### Scenario: 关系保存失败

- **WHEN** 预览预计合并，但实际结果中该组关系保存失败
- **THEN** 显示统一导入错误和未合并原因，准确说明存在已保存流水，不断言全批成功或全批回滚

#### Scenario: 结果返回账本

- **WHEN** 用户从摘要或统一错误页返回账本
- **THEN** 刷新当前账本并保留原筛选，不增加结果页逐项处理入口

#### Scenario: 全部重复

- **WHEN** 实际收据表明本次没有新建且记录均为重复
- **THEN** 显示真实无新增结果并允许结束，不把零新增当作网络失败重新提交

### Requirement: 导入账户准备变化在当前任务重新预览

账户准备变化后 MUST 在同一任务重新生成预计列表，保留账户选择及当前修订；未刷新计划不能确认。字段与关系使用服务端默认决定，不由 Compose 导入修改。分页和筛选 MUST 不缩小最终确认范围。

#### Scenario: 修改一项账户

- **WHEN** 用户修改选择后尚未取得新计划
- **THEN** 确认不可执行，重预览成功后使用新计划及新修订

#### Scenario: 只读核对默认计划

- **WHEN** 用户查看字段差异或关联候选后确认导入
- **THEN** 查看操作不改变计划或修订，提交不包含字段或关系选择，也不回到独立编辑或配对步骤

## ADDED Requirements

### Requirement: Compose 导入接通实际结果和原命令恢复

实际页面 MUST 接通实际收据与原键提交核实。正常完成仅展示结果摘要和返回；提交新增异常统一显示“导入出错”、安全原因与返回，不提供逐项处理、失败明细或重试入口。发送确认前持久保存有界且隔离的最小命令标识；不得持久保存原文件、密码或财务正文。未知结果期间不得换键重导、清除恢复证据或启动账户撤销；已提交重放返回原结果；核实为 `retry_original` 时只以原计划、修订和键重放，`pending` 继续核实，`not_committed` 后才恢复可继续核对状态；返回仍保留未知请求的最小恢复证据。安全恢复不构成逐项失败重试入口。金额和修订 MUST 按真实协议传输，三端不因 SQLite 或 PostgreSQL 改变业务结果。

#### Scenario: 确认响应丢失

- **WHEN** 提交已发送但没有确定结果
- **THEN** 显示正在核实的状态，通过原键／原计划核实，已提交读取实际收据，权威未提交后才恢复可继续核对状态

#### Scenario: 提交新增异常

- **WHEN** 提交发生预览后并发变化或执行异常
- **THEN** 展示统一导入错误、安全原因和返回；部分保存时说明事实，不提供逐项处理或重试入口

## REMOVED Requirements

### Requirement: 导入配对阶段在移动端使用关系卡片

**Reason**: 导入采用统一收支列表，关系在当前项只读详情核对。
**Migration**: 使用“现金账单导入统一核对并一次确认”和共享全屏对话框合同。

### Requirement: 移动端关系卡片保持原有配对决定语义

**Reason**: 独立关系卡片步骤及导入内关系决定不属于当前导入任务。
**Migration**: 使用服务端完整候选与默认组决定，在当前收支详情只读核对，后续在账本维护。

### Requirement: 配对移动视图覆盖响应式状态与无障碍交互

**Reason**: 三端验证以统一任务及其详情为范围。
**Migration**: 使用共享全屏对话框的三类窗口、键盘和系统返回验收。

### Requirement: Web 导入关系建议与 CLI 关系结果保持等价

**Reason**: 现金导入 CLI 已退出公共合同。
**Migration**: Web 与 Native 直接消费当前会话计划和实际收据，不恢复 CLI。

### Requirement: 导入错误只读显示准确诊断位置

导入错误及文件失败具有诊断信息时，共享页面 MUST 在既有安全原因下显示处理环节、文件和来源位置及错误编号。单条直接摘要，多条通过次要文字按钮展开只读明细；相关范围 MUST 明确为相关记录，不称为已确定坏行；无法定位只显示已知阶段。不新增逐项修复或重试入口，不改变返回及原命令核实合同，三端共享语义。诊断来源与安全规则以 `import/cash-import-session` 为唯一合同。

#### Scenario: 转换失败具有单条来源位置

- **WHEN** 文件解析结果携带转换阶段和一个来源位置
- **THEN** 文件卡直接显示文件和来源序号及错误编号，不显示异常堆栈或增加行级动作

#### Scenario: 提交失败涉及多个成员

- **WHEN** 提交异常只定位到关系组或批次
- **THEN** 错误页显示环节和相关数量，默认折叠成员定位，点击可展开或收起，返回保持唯一主要动作
