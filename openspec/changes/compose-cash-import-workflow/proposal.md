## Why

Compose 导入已接通解析会话、统一预览、收据和恢复，但准备区卡片堆叠、核对层级重复，详情混入整笔编辑、来源决定和关系处理，导致主任务失焦。需要完整重写展示层，复用账本表格与侧滑详情，让确认前的核对保持只读，待确认内容以后在账本维护。

## What Changes

- 将账单导入改为覆盖账本的 Material 3 全屏对话框，保留 `/cash-import` 兼容地址；流程为“选择并解析文件 → 指定来源账户映射 → 重点核对预计草稿及其他流水 → 一次确认 → 实际结果”；手机与桌面采用相同任务顺序。
- 文件和账户映射是连续的独立任务；账户分组从已解析文件产生，允许暂不选择。核对页复用账本流水表格，明确区分草稿与正式待确认流水；Regular/Wide 使用右侧模态详情，Compact 使用全屏详情。
- 详情只读呈现摘要、问题、来源差异、完整候选成员与原文，不提供备注、分类、来源采用、关系接受或候选改选；提交使用服务端默认决定，后续在账本维护。
- 保留多文件、密码重传、来源设置、独立账户创建及退出补偿、草稿／手动配对／全部筛选（全量读取合同未齐时明确已加载范围）、分页、处理明细、实际收据和未知提交原键核实；导入账户映射内不提供已有账户编辑操作。
- **BREAKING**：仅移除 Compose 导入内编辑交互及专属关系编辑器，不删除后端、DTO、Repository 或 ViewModel 的既有协议能力。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cash-ledger/cash-ledger-browser`：统一只读核对、实际结果及后续账本维护边界。
- `shared/cross-platform-presentation`：共享准备页、账本表格与侧滑详情、退出及三端一致合同。

## Impact

A 类共享 UI 变更，影响 `/cash-import` Screen、准备／核对／详情／结果组件、三语言文案、离线演示、功能地图和 Web／Native 验证。非目标包括账本主页、导入后的草稿／关系维护、后端业务语义、DTO、Repository、账户 ViewModel、命令状态机、恢复存储、路由地址及解析、数据库和依赖。

验收覆盖文件后才出现账户映射、未映射来源可继续、草稿优先核对且未知值不伪填、正式待确认与草稿分开表述、默认空字段／关系选择、只读差异与完整候选成员、部分文件失败继续、全部重复、仅草稿、净额零退款、未知提交原键核实及账户退出。390、768、1440 px 保持相同语义；Web 做真实浏览器主流程，Android、iOS 只做编译和单元测试。

复用 FinanceTheme、Noto Sans SC、IBM Plex Mono、Git token、4 dp 间距和现有侧板宿主；采用克制的 Workbench 工具方向，不新增视觉系统或装饰。无 schema 迁移或新增依赖。回退只恢复展示组件，不恢复已退役接口。
