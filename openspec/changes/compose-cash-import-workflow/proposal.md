## Why

Compose 导入页面仍使用旧扫描、预览、提交接口及分离的流水／配对步骤，尚未接入现有后端。需要把已实现的解析会话、统一预览、收据和恢复基础接到共享页面，让可保存内容先导入，待确认内容以后补处理。

## What Changes

- 在主内容区承载完整导入任务；手机端全屏，保留现有 Material 3、配色与字体。
- 文件与账户准备后进入一份预计收支列表，流水差异与配对在当前项内核对，一次确认整个计划。
- 接通逐文件失败与重传、草稿和待确认项、完整组选择、公共人工值冲突、实际结果摘要、未知结果核实及提交异常统一错误返回。
- 独立账户表单立即保存，成功后才可选择；接通退出一次询问、有限安全撤销及账户命令独立恢复。
- **BREAKING**：移除本模块的旧导入调用、四步状态、独立关系步骤和导入内账户草稿。复用现有新客户端及状态机，补齐公共对象等缺失字段。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cash-ledger/cash-ledger-browser`：统一导入核对、实际结果及后续入口，替换分步导入呈现。
- `shared/cross-platform-presentation`：共享完整任务页、文件与账户准备、退出及三端恢复合同。

## Impact

A 类前端变更，影响共享导入 Screen、生命周期 DTO／映射、任务与账户 ViewModel、恢复存储接线、App 注入、演示和三端 QA；允许为本次页面合同调整后端响应；扩充收据提交事实及明确的预计整笔公共编辑目标；来源决定独立保留，被编辑目标不能完整保存时整命令拒绝。保持 schema 和原性能预算。不接入无法由当前后端支持的关系重新发现，不新增关系页面、问题中心或独立账户产品页面。

验收覆盖部分文件失败继续、全部重复、仅草稿、净额零退款、关系组延后与失败、来源差异保护人工值、未知提交原键核实，以及有／无账户改动的退出。Web、Android、iOS 使用同一业务合同，真实入口与验证完成前不提升功能地图覆盖。

共享维护模型与宿主边界由 [账本与维护](../compose-cash-ledger-maintenance/design.md) 先行冻结；导入拥有自己的任务状态和路由，不改账本维护实现。当前后端与已交付客户端基础见 [导入主变更](../cash-import-lifecycle-redesign/proposal.md)；移交范围及并行顺序见本变更 design。

无 schema 迁移或新增依赖计划。回退不能重新启用已关闭接口；无法兼容时关闭导入入口并保留最小恢复标识，仍可核实已发送命令。实施沿用已确认 UI 方向，不部署或写入真实账本。
