## Why

Compose 导入已接通解析会话、统一预览、收据和恢复，但准备区卡片堆叠、核对层级重复，详情混入整笔编辑、来源决定和关系处理，导致主任务失焦。需要完整重写展示层，复用账本表格与侧滑详情，让确认前的核对保持只读，待确认内容以后在账本维护。

## What Changes

- 将账单导入改为覆盖账本的 Material 3 全屏对话框，保留 `/cash-import` 兼容地址；流程为“选择并解析文件 → 指定来源账户映射 → 默认核对待确认流水，可切换全部 → 一次确认 → 实际结果”；手机与桌面采用相同任务顺序。
- 文件和账户映射是连续的独立任务；账户分组从已解析文件产生，允许暂不选择；账户建议仅按身份匹配，不因币种不足隐藏。点击下一步时为所选目标账户补充本次来源所需币种。核对页复用账本分页流水列表：有待确认流水时默认仅显示待确认项，可切换全部；没有待确认项时自动显示全部。列表连续加载，保留主页右侧序号滚动条与详情行为。流水备注保留账单中的业务字段，关联说明和核对原因分开呈现；Regular/Wide 使用右侧模态详情，Compact 使用全屏详情。
- 详情只读呈现摘要、关联流水和账单原文：关联区在多笔实际关联流水或存在候选时默认展开，候选嵌入对应关系并标明候选；账单原文置后且默认折叠。来源差异和问题随摘要查看。导入详情不提供关系接受、拒绝或候选选择；提交使用服务端默认决定，后续在账本维护。
- 保留多文件、密码重传、来源设置、独立账户创建及退出补偿、待确认／全部筛选、Paging3 序号定位与右侧滚动条、处理明细、实际收据和未知提交原键核实；导入账户映射内不提供已有账户编辑操作。草稿和待确认事项以状态提示区分，普通已确认记录不显示状态标签。
- **BREAKING**：仅移除 Compose 导入内编辑交互及专属关系编辑器，不删除后端、DTO、Repository 或 ViewModel 的既有协议能力。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cash-ledger/cash-ledger-browser`：统一只读核对、实际结果及后续账本维护边界。
- `shared/cross-platform-presentation`：共享准备页、账本表格与侧滑详情、退出及三端一致合同。

## Impact

A 类共享 UI 变更，影响 `/cash-import` Screen、准备／核对／详情／结果组件、三语言文案、离线演示、功能地图和 Web／Native 验证。非目标包括账本主页、导入后的草稿／关系维护、导入财务算法、账户命令状态机、恢复存储、来源解析、数据库结构和依赖；为序号分页扩展只读计划读取 API，并由映射步骤调用现有账户修改命令补充币种。

验收覆盖文件后才出现账户映射、未映射来源可继续、币种不足账户仍被建议且下一步自动补齐、待确认默认筛选及空待确认时自动切换全部、按序号定位未加载分页、密码错误原因只显示一次、正式待确认与草稿分开表述、只读差异与完整候选成员、仅草稿和待确认关系记录显示有色标签及对应底色、普通已确认记录无状态标签、部分文件失败继续、全部重复、仅草稿、净额零退款、未知提交原键核实及账户退出。390、768、1440 px 保持相同语义；Web 做真实浏览器主流程，Android、iOS 只做编译和单元测试。

复用 FinanceTheme、Noto Sans SC、IBM Plex Mono、Git token、4 dp 间距和现有侧板宿主；采用克制的 Workbench 工具方向，不新增视觉系统或装饰。无 schema 迁移或新增依赖。回退只恢复展示组件，不恢复已退役接口。
