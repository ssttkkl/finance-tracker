## Purpose

为使用终端的人和自动化程序提供可安装的账本客户端。用户可以在线管理工作区与收支，也可以在断网后重新打开同一工作区的缓存，继续准备现金账单并在联网后明确确认。

## ADDED Requirements

### Requirement: 人与自动化程序使用同一套命令

CLI 安装后 MUST 提供 `ft`、分层帮助和版本查询。每个业务动作 MUST 支持无交互调用、稳定 ID、明确退出状态和机器可读输出。财务金额 MUST 保留十进制精度和币种。

#### Scenario: 自动化脚本查询和处理缺项

- **WHEN** 脚本指定 JSON 模式查询账本或在无终端环境中遗漏必需的选择
- **THEN** 标准输出 MUST 只包含结构化结果或错误，成功返回零，缺项返回非零并标明待补参数；进程不得等待交互输入

### Requirement: 按命令恢复原范围并判断连接

CLI MUST 按本次操作所需的请求判断后端可达性。加密缓存、恢复身份、清除及替换遵循 `shared/offline-ledger-cache` 和 `shared/ledger-snapshot-sync`；进程退出后 MUST 释放运行资源。正式写入 MUST 在线重新鉴权。

#### Scenario: 断网后新进程查看收支

- **WHEN** 原用户已同步工作区并退出进程，新进程读取账本时发生网络不可达或超时
- **THEN** CLI MUST 在匹配的服务地址、原登录令牌、使用者和工作区范围内显示缓存中的收支、来源和最后同步时间；无缓存时提示先联网同步

#### Scenario: 服务端明确拒绝或本机无法解密

- **WHEN** 服务端确认认证失效或访问权被撤销，或发现密钥损坏、身份不匹配
- **THEN** CLI MUST 拒绝相应缓存访问，确认失效或撤权时清理对应材料；协议错误及服务端错误不得被报告为离线成功

### Requirement: 身份、工作区与记账所需账户

CLI MUST 支持注册、登录、查询会话、退出，列出、查看、创建、选择、改名和删除工作区，管理成员与角色、创建邀请、预览及接受邀请。财务账户 MUST 可按 ID 选择、查看支持币种和余额，并在记账或导入准备时创建或按需补币种。权限、删除影响与确认条件沿用对应业务合同。

#### Scenario: 两个进程选择不同工作区

- **WHEN** 一条命令显式选择新工作区，另一条命令仍以原工作区为预期范围
- **THEN** 后一条命令 MUST 只在原范围执行或报告冲突；不得隐式切换工作区或尝试其他账户

#### Scenario: 只读成员与邀请

- **WHEN** 用户先预览邀请再登录接受，并以只读角色进入受邀工作区
- **THEN** CLI MUST 显示实际工作区与授予角色，可浏览账本，服务端拒绝越权修改

### Requirement: 收支查询、记账与维护对齐客户端

CLI MUST 覆盖现行收支列表、详情与记账、收支分类管理任务。对相同事实、版本、筛选和时区，CLI MUST 返回与图形客户端一致的稳定 ID、顺序、准确计数、分币种月度汇总、来源证据和待处理原因。

#### Scenario: 退款与转账参与同一查询

- **WHEN** 在同一工作区按日期、币种、金额、分类、账户、类型、确认状态、草稿状态、流水组成或关键词筛选并分页
- **THEN** CLI MUST 支持同条件的序号定位和汇总，遵守零元过滤、退款抵扣与内部转账口径，并拒绝跨版本或跨筛选复用游标

#### Scenario: 编辑收支并处理关联

- **WHEN** 有权限的使用者创建普通收支或跨币转账，编辑手工或导入记录，分摊草稿、转正式、核对来源差异或处理关联与身份候选
- **THEN** CLI MUST 提供与客户端相同的字段资格、候选搜索和取舍、影响核对及提交结果；完整转账一次保存两端，草稿普通保存仍为草稿

#### Scenario: 批量维护与分类目录

- **WHEN** 使用者对选中的收支批量分类、删除，或创建、移动、改名、排序、删除收支分类
- **THEN** CLI MUST 核对相应影响、权限和修订，按原业务事务提交，并报告实际结果

### Requirement: 现金账单整批核对与跨进程接续

CLI MUST 支持现有现金来源、多文件、对应账户、整批核对、待确认项与实际结果。CSV 和 XLSX MUST 本地读取，PDF 和旧 XLS 使用现行在线解析。每个批次 MUST 保存原范围、文件及有效选择，允许关闭进程后继续、增删替换文件或取消。

#### Scenario: 离线准备并修改选择

- **WHEN** 用户使用缓存账户离线准备本地可解析文件，之后在另一进程继续修改并核对
- **THEN** CLI MUST 恢复原批次并重新计算受影响的结果，提示需联网的步骤，连接恢复本身不得触发写入

#### Scenario: 单独生效的账户变更

- **WHEN** 用户在导入时新建账户或扩充币种，然后取消批次
- **THEN** CLI MUST 显示已生效的独立变更，按原流程保留或执行有修订保护的补偿，保留逐项结果

#### Scenario: 两个进程核对与提交同一批次

- **WHEN** 一进程更改已核对的选择，另一进程以旧核对版本确认
- **THEN** CLI MUST 拒绝提交陈旧结果；有效确认覆盖整批，保留来源证据，按真实收据返回新增、更新、草稿及未导入原因

### Requirement: 写入中断后恢复同一次操作

CLI MUST 在发送可恢复写入前固定原身份、工作区、操作身份和正文。结果未知时 MUST 按原合同核实，明确未提交后才可按原规则继续。后续进程 MUST 能恢复同一操作，独立发起的两笔相同收支仍是两笔业务。

#### Scenario: 后端已提交但客户端未收到响应

- **WHEN** 确认现金导入或保存收支后进程被终止，用户再次接续该操作
- **THEN** CLI MUST 查询原收据或按安全重放合同接续同一请求；已知成功时显示实际结果，无法确证时保留未决状态，不生成新键重复入账
