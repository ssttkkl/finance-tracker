## ADDED Requirements

### Requirement: 登录与注册认证表单保持跨端一致

Web、Android 与 iOS 的登录和注册表单 MUST 不显示「Finance Tracker」品牌标识、「工作区访问」标签或邮箱占位文字。认证页 MUST 按 Compose `WindowSizeClass` 响应布局：`COMPACT` MUST 使用铺满窗口的白色背景，表单内容顶部对齐且不得显示独立卡片层；`REGULAR` 与 `WIDE` MUST 使用灰色页面背景、居中的白色表单卡片。Native 启动器名称和认证后页面品牌不受影响。

登录页标题 MUST 为「登录」，注册页标题 MUST 为「创建账户」。注册页标题左侧 MUST 提供仅显示左箭头的返回登录按钮，图标下沿与标题文字 baseline 对齐；按钮无障碍名称 MUST 为「返回登录」，触控区域至少为 44 dp。注册页 MUST 不显示底部「已有账户？登录」入口；登录页继续显示「还没有账户？注册」模式入口。

布局结构 MUST 同时适用于深色主题；深色主题继续使用现有主题颜色角色，不另行改变页面层级。浅色主题按上述白色/灰白视觉呈现。

#### Scenario: COMPACT 使用者打开登录页

- **WHEN** 未认证使用者在 `COMPACT` 窗口打开登录页
- **THEN** 登录表单 MUST 从页面顶部内容区开始排布，白色背景铺满窗口
- **AND** 页面 MUST 不显示品牌、邮箱占位文字、工作区标签或独立卡片层

#### Scenario: REGULAR 或 WIDE 使用者打开登录页

- **WHEN** 未认证使用者在 `REGULAR` 或 `WIDE` 窗口打开登录页
- **THEN** 页面 MUST 保持灰色背景，白色登录表单卡片在可用视口中居中
- **AND** 页面 MUST 不显示品牌、邮箱占位文字或工作区标签

### Requirement: 注册表单展示实时、可区分的凭据校验项

注册表单 MUST 按邮箱、密码、确认密码的顺序呈现字段。字段校验文案 MUST 位于字段标题下方、输入框上方，并使用区别于字段标题的次级文字样式。校验反馈分为强提示和弱提示：强提示是使用者需要被明确告知的填写条件，即使字段为空也 MUST 展示灰色中性文案；弱提示是使用者通常无需预先解释的常识性规则，字段为空时 MUST 隐藏校验文案、图形符号及中性占位反馈，仅在字段非空后展示校验结果。满足规则时 MUST 展示绿色对勾与通过文案；非空但不满足规则时 MUST 展示红色叉号与失败文案。状态 MUST 同时通过图形符号、文字和颜色表达，不得只依赖颜色。输入值变化时 MUST 即时重算相关校验项。

- 邮箱格式和确认密码一致性 MUST 作为弱提示；密码至少 12 个字符 MUST 作为强提示。
- 邮箱 MUST 使用现有共享邮箱格式规则校验；为空时隐藏反馈，非空但格式无效时显示失败状态。
- 密码 MUST 使用现有至少 12 个字符规则校验；为空或不足 12 个字符时显示灰色中性强提示，达到要求后显示通过状态。
- 确认密码 MUST 与当前密码完全一致；确认密码为空时隐藏反馈，非空时按一致/不一致即时显示通过/失败状态；密码或确认密码任一变化时均须即时更新一致性状态。
- 登录模式 MUST 不显示注册校验项或确认密码字段。

#### Scenario: 注册字段为空

- **WHEN** 注册表单中的邮箱、密码或确认密码为空
- **THEN** 邮箱格式与确认密码一致性弱提示 MUST 不显示
- **AND** 密码字段 MUST 显示灰色「至少 12 个字符」强提示
- **AND** 任何字段均不得呈现红色失败状态

#### Scenario: 输入有效邮箱和符合规则的密码

- **WHEN** 使用者输入符合现有格式规则的邮箱且密码达到至少 12 个字符
- **THEN** 对应字段 MUST 即时显示绿色对勾及通过状态

#### Scenario: 输入格式错误的邮箱或过短密码

- **WHEN** 使用者输入非空但格式无效的邮箱，或输入少于 12 个字符的密码
- **THEN** 对应字段 MUST 即时显示红色叉号及失败状态

#### Scenario: 确认密码与密码不一致

- **WHEN** 确认密码非空且与当前密码不一致
- **THEN** 确认密码字段 MUST 即时显示红色叉号及失败状态
- **WHEN** 使用者继续输入直至两次密码完全一致
- **THEN** 确认密码字段 MUST 即时切换为绿色对勾及通过状态

#### Scenario: 注册密码编辑使确认状态变化

- **WHEN** 使用者修改密码且已有确认密码
- **THEN** 确认密码状态 MUST 按新的密码即时重新判断

### Requirement: 注册确认密码和表单级错误保持安全语义

注册提交 MUST 要求邮箱与密码通过现有验证且确认密码与密码一致；确认密码 MUST NOT 发送到认证服务。提交校验失败及认证服务错误 MUST 继续显示在表单级通用错误位置，不得伪装成实时字段规则结果。密码和确认密码 MUST 保持隐藏输入语义。

#### Scenario: 注册确认密码不一致时提交

- **WHEN** 使用者提交两次密码不一致或缺少必需注册字段的表单
- **THEN** 客户端 MUST 阻止认证请求
- **AND** 表单 MUST 在通用错误位置提供提交校验反馈

#### Scenario: 注册信息校验通过

- **WHEN** 使用者提交有效邮箱、符合规则的密码和完全一致的确认密码
- **THEN** 客户端 MUST 仅将邮箱和密码发送至现有注册认证接口

#### Scenario: 登录或注册服务端返回错误

- **WHEN** 现有认证服务返回登录或注册错误
- **THEN** 错误 MUST 显示在表单级通用错误位置
- **AND** 字段级实时校验状态 MUST 继续仅反映本地字段规则

### Requirement: 认证状态设计稿展示完整页面

Pen 设计稿 MUST 按 `COMPACT`、`REGULAR`、`WIDE` 三类窗口尺寸，为每个认证页面状态提供包含完整页面结构的独立画板；不得仅以局部状态卡片或控件片段代替完整页面状态。

- 登录 MUST 覆盖默认、登录中、登录服务端错误三种完整页面状态。
- 注册 MUST 覆盖默认、字段校验全部通过、字段校验失败、注册中、注册服务端错误五种完整页面状态。
- 24 张状态/页面画板 MUST 保持对应类别的布局、品牌移除、全屏/卡片背景和字段顺序；空值中性、校验通过和失败必须使用完整注册页面展示。
- 深色主题复用相同层级和类别布局，使用当前 token 表达，不要求为每种状态重复绘制深色画板。

#### Scenario: 查看完整认证状态画板

- **WHEN** 设计评审查看任一认证状态和窗口尺寸类别
- **THEN** Pen MUST 展示该状态对应的完整登录或注册页面
- **AND** 注册页面状态 MUST 包含邮箱、密码和确认密码字段
- **AND** 校验反馈 MUST 按强提示/弱提示的空值展示规则呈现

#### Scenario: 深色主题使用认证页面

- **WHEN** 使用者在系统深色主题下打开任一认证状态
- **THEN** 页面 MUST 保持相同的信息层级、状态和窗口尺寸布局
- **AND** MUST 使用现有深色主题颜色角色，不得强制显示浅色主题色

### Requirement: 注册页以返回按钮承载返回登录导航

注册页 MUST 在标题左侧提供仅显示左箭头的返回按钮，并返回登录页；按钮 MUST 提供无障碍名称「返回登录」。注册页 MUST NOT 显示底部「已有账户？登录」入口，以避免重复的登录导航。

#### Scenario: 从注册页返回登录

- **WHEN** 使用者在任一窗口尺寸的注册页触发标题左侧返回按钮
- **THEN** 页面 MUST 返回登录表单
- **AND** 返回按钮 MUST 具有「返回登录」无障碍名称，但界面上不得显示文字标签
- **AND** 注册页 MUST 不显示底部「已有账户？登录」入口
