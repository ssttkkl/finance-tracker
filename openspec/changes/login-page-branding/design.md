## Context

认证页面由 Compose `commonMain` 共享，覆盖 Compose Web、Android 和 iOS。当前页面共用品牌标题和辅助标签；密码长度文案被用作登录/注册共用的提示。行为要求见 `specs/shared/cross-platform-presentation/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让登录和注册页使用独立于系统启动器名称的「Finance Tracker」品牌文案。
- 移除认证卡片顶部的「工作区访问」标签。
- 只在注册模式显示密码长度提示。
- 保持既有页面布局、认证与密码校验行为。

**Non-Goals:**

- 不更改「登录到你的账本」主标题、错误提示、字段标签或登录后工作区页面。
- 不更改应用启动器名称、认证 API、令牌存储或密码最小长度规则。
- 不扩展旧 React Web/Expo 参考实现。

## 信息架构与删除冗余信息

认证页顺序为品牌名、登录/注册主标题、邮箱、密码、注册模式下的密码辅助提示、错误反馈、主要操作和模式切换。删除「工作区访问」标签；删除登录模式中的密码最小长度提示；注册模式在密码框下方继续显示该提示。设计稿为 `design/login.pen`，覆盖 320、375、390、414、768、1440 px 登录画布及注册状态示例。

## Decisions

- 新增认证页面专用资源 `auth_brand`，不复用或改写 `app_name`，避免影响系统启动器名称和其他页面。
- 在共享认证表单中按注册模式控制密码辅助文案的可见性；登录模式不显示该文案，注册模式保留现有本地化文案。
- 使用 Compose Web E2E 断言品牌、标签和两种模式的提示，再运行生产 Wasm 预览浏览器检查；同一共享页面为 Android/iOS 提供一致实现。
- 功能地图继续以 F-01 记录页面级覆盖，仅补充本次共享文案合同及证据入口，不改变覆盖统计。

## Risks / Trade-offs

- `[资源范围扩大]` 直接修改 `app_name` 可能改变原生应用名称；通过新增认证专用资源规避。
- `[注册提示误删]` 登录与注册共用同一字段；使用模式条件和模式切换回归测试，确保注册提示及最小长度校验保留。
- `[页面纵向节奏变化]` 移除标签后表单卡片变矮；按 Pen 六档宽度和实际 390/1440 px 页面复核布局。

## Migration Plan

无需数据或接口迁移。改动随 Compose Web/Android/iOS 共享资源发布；回滚时恢复认证页面文案及提示条件，不影响持久化数据或认证协议。
