## Context

比较基线为 `d07d8a43`。`:client-operations` 已提供 CLI 的会话、写入和导入操作。Compose 的本地收支读取已调用共同查询，其他入口仍通过自己的会话发布、HTTP 仓储、账户准备和现金导入生命周期编排。旧归档作为历史记录保留。

## Goals / Non-Goals

让两个正式入口对共同业务动作调用同一有类型的公共 Kotlin 实现，维持现有范围、权限、输入、效果和结果。Compose 构建图形状态与 Worker 生命周期，CLI 构建参数及终端结果。保持服务端事务和 HTTP 接口。投资、内置 AI、添加缺少的单端页面或命令不在本变更范围。

## Decisions

操作矩阵按可到达的页面和命令登记公共实现。依据实际职责提取现有稳定实现。应用入口绑定会话和原工作区后，把平台凭据、HTTP、带条件的持久化、处理队列和刷新回调交给操作层。公共层保留业务输入、复核、防止重复写入和恢复；平台层保留平台状态、Worker 执行和任务生命周期。提交前固定请求身份和内容，已保存收据后再刷新或整理，平台任务取消不得使收据失效。

优先切分无本地持久化的认证或维护请求，再收敛带持久化的普通记账、账户准备和导入。导入以 Compose 既有逐文件捕获、冻结、收据、归档、快照刷新顺序为兼容准绳。宿主仍以原会话绑定恢复旧状态，保留历史会话识别与待处理操作。两端接通后删除只供旧生产入口消费的编排。以独立审查确认宿主适配未重新实现业务，单元同夹具验证仅作补充。

## Risks / Trade-offs

- 宿主切换会话或暂停时，旧任务不得使用后续令牌。已有本地访问资格、离线浏览和显式重新连接沿用原平台行为。
- 浏览器 Worker 承担计算和持久化成本。变更须保证本地主线继续后台计算；关闭页面、迟到响应和线程故障分别验证。
- 保留旧恢复记录格式、原操作 ID 和已验证的权威收据。重试或版本冲突不能重新冻结不同意思的请求。
- 跨平台验证包括运行 Chrome 中的 Compose 正式页面、npm 安装包、Android 与 iOS 编译和单测。涉及同一财务写入与存储保证时，按相同用户合同验证 SQLite 和 PostgreSQL。

普通记账与转账先共用冻结命令执行。恢复先读原收据，只有精确的查无收据可原样重放。服务端可持久化一份拒绝收据，其中 `committed` 描述收据状态，账本效果以失败状态和 `commit_outcome` 为准。Compose 宿主在每次实际发送前核对原令牌、原发布和离线状态；页面保留提示及退出交互。跨进程恢复须把原请求检查点接到已有的加密账本范围，恢复操作由用户触发现有入口，后台核实不重发业务写入。

## Migration Plan

先逐步接通双方调用链并核对原业务结果。灰度风险以独立提交和双库证据控制。回滚可切回应对相同公开 HTTP 的上一客户端版本，条件是维持原恢复记录可读；任何必需的本机格式迁移先回写兼容方案。
