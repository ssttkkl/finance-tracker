## MODIFIED Requirements

### Requirement: 客户端业务操作可通过有类型的 Kotlin 接口调用

系统 MUST 为一期范围内的会话与工作区、财务账户、收支与分类、现金导入提供宿主可直接调用的 Kotlin 操作。操作 MUST 接受业务参数并返回有类型的结果或可识别错误；调用方无需构造命令行、启动 Node 进程或解析终端文本。Compose 的正式页面与 CLI 执行同一业务动作时，MUST 直接进入同一个有类型的 Kotlin 操作实现。共享操作 MUST 承担共用的权限、范围、写入、收据和恢复规则。宿主提供平台时序、传输、会话发布、文件、持久化及呈现能力。

#### Scenario: 同一工作区查看月度支出

- **WHEN** Compose 收支页面和 CLI 使用相同的工作区、时区、筛选条件与快照版本查询月度汇总
- **THEN** 两者 MUST 得到相同的精确分币种金额与数据版本；终端格式仅在 CLI 输出时生成

#### Scenario: 同一批次核对与接续提交

- **WHEN** Compose 导入页面和 CLI 提供相同的文件、账户选择与核对版本，并在网络中断后恢复原操作
- **THEN** 操作 MUST 保留同样的来源、待处理原因、核对结果及原提交身份；相同的服务端结果在两种调用方式下表达为相同的成功、冲突或待核实状态

#### Scenario: 写入未收到响应

- **WHEN** 使用者在任一入口提交同一次记账、转账、维护或导入，并在结果返回前断网或退出
- **THEN** 原入口接续 MUST 使用共用的操作身份和恢复规则，保留原工作区及写入内容，核实实际收据；未知结果继续待核实，已成功的写入只产生一次账本效果

#### Scenario: 同一账户准备动作

- **WHEN** 使用者通过任一入口在导入中选择、创建账户或补齐币种，随后撤回准备阶段产生的变更
- **THEN** 两者 MUST 使用相同的资格、原修订检查及逐项补偿规则；保留其他操作产生的事实
