## Why

后端 Python 与 Compose 已分别实现部分金额、分类和现金分摊规则。本变更将完整后端迁移到 Kotlin，并按实际双端需求，让前后端消费同一套无 UI 依赖的协议和业务规则，保持现有用户合同。

## What Changes

- 新增独立 KMP `business-contracts` 和 `business-domain`，提供 JVM 及现有客户端平台目标；优先共享协议、输入校验、金额/分摊、分类和账单行模型。其他纯算法按真实客户端需求接入，不以代码能跨平台编译代替实际复用。
- 新增 Kotlin/Ktor 后端，全部 JSON 使用 `kotlinx.serialization`，分阶段覆盖完整当前 HTTP、同步、行情、暂存、投影与维护能力；不恢复已退役 CLI 或 HTTP 写入口。
- 后端持久化迁移到 jOOQ 类型化 DSL，由当前迁移后的匿名 schema 生成表与字段类型；生成类型、方言及金额绑定仅在后端使用。用户确认 PostgreSQL 版本可升级，以 PostgreSQL 18 和现有 SQLite 验证，不再以 PostgreSQL 16 限制选型。
- 逐切片接入 Compose，替换可安全移除的重复实现。客户端校验始终不替代服务端对最新工作区、权限、账户、修订、来源、幂等及完整组的权威校验。
- 保持当前 API 字段、空值、缺省、分页、错误与 SSE 合同，保持 `NUMERIC(38,18)`、精确运算、UTC、SQLite/PostgreSQL 原子事务及审计语义。
- **BREAKING（用户明确授权）**：注册/登录的 `email`、`password` 只接受 JSON 字符串，不再把数字、数组、对象、布尔或 `null` 隐式转为字符串；其余字段不因此变更。
- 账单保持客户端上传、服务端解析和返回预览的流程；先共享行模型和协议，归一算法保留在后端，存在明确客户端调用场景后再规划共享。后端按格式分离字节解码与业务归一，保留 CSV/TSV/XLS/XLSX/PDF 全部能力。
- 同步迁移 Python 单元、合同和集成测试中的验证规则与断言，建立源用例到 Kotlin 测试的对应关系；参数化边界、错误和无写入断言不得遗漏，黄金差分不替代 Kotlin 原生测试。
- 用户明确授权同步修复 Python/Kotlin 分类移动时后代深度依赖可变根节点的问题，以正确树结构及五层限制验收；补原失败回归，不自动修复真实数据库中既有错误深度。
- 用户明确授权同步修复旧现金新增在响应编码失败后仍提交流水和余额的问题：提交前验证完整成功响应可编码，失败时整笔回滚；SQLite 和真实 PostgreSQL 均补原失败回归，不自动修复真实数据库。

## Capabilities

### New Capabilities

- `shared/business-core`：前后端共同消费确定性业务规则，平台解码与服务端权威校验保持明确边界。
- `shared/kotlin-backend-parity`：Kotlin 运行时在现有 API、财务、安全、数据及后台任务合同下逐项提供等价能力。

### Modified Capabilities

- `authentication/user-workspace-access`：注册/登录凭据仅接受字符串；这是用户明确确认的输入合同收紧，其他认证行为保持。
