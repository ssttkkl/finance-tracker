## Purpose

定义服务端与 Android、iOS、JS、Wasm 客户端共用业务规则的输入、结果及信任边界，保证相同业务输入可得到相同的确定性结论，同时保留服务端的授权、事实重读与财务写入责任。

## ADDED Requirements

### Requirement: 公共业务规则跨平台一致

系统 MUST 为前端和后端提供无 UI、SQL、凭据或网络依赖的公共业务规则。相同输入在所有支持平台 MUST 得到相同结果；金额 MUST 保持精确十进制、原币种和明确舍入语义，持久化合法范围保持 `NUMERIC(38,18)`。既有表单输入语法不得因下沉实现被隐式扩宽或收紧。

公共层 MUST 按实际双端需求接入；协议、输入校验、金额/分摊、分类和账单行模型优先。公共规则仅在客户端和后端正式调用路径均使用、对应重复实现已移除或明确保留兼容适配、跨平台与真实协议消费验证通过后，才能计为双端复用完成。测试或演示专用调用不得代替实际消费者。投影、关系规划和投资重放等无当前客户端消费者的算法允许保留在后端纯业务层，不缩减完整后端迁移范围。

#### Scenario: 精确分摊
- **WHEN** 前后端校验包含 18 位小数及大额数值的同一组分摊
- **THEN** 守恒、金额方向、币种和缺项结论 MUST 一致，且不得通过二进制浮点计算

#### Scenario: 分类移动
- **WHEN** 前后端获得同一分类树并评估一个新上级
- **THEN** 自身、后代和移动后超过五层的上级 MUST 在客户端不可选并在服务端被拒绝

### Requirement: 共享规则保留服务端权威边界

服务端 MUST 在当前请求的授权工作区内重新读取账户、来源、完整关系组、修订、幂等收据和其他依赖事实后执行适用公共规则。客户端的校验结果、来源完整性声明或预计结果 MUST NOT 代替服务端事实或授权。

#### Scenario: 客户端通过后事实变化
- **WHEN** 客户端校验成功后账户失效或修订变化
- **THEN** 服务端 MUST 按现有错误合同拒绝，且不得猜测、自动重放或发布部分财务写入

### Requirement: 解码与业务归一分离

账单 MUST 保持客户端上传、服务端解析和返回预览的现有流程；公共层先共享行模型和协议，不新增客户端本地解析或预览流程。后端的格式解码与业务归一 MUST 分离，并保留原字段、物理位置和来源声明。归一算法只有存在明确客户端调用场景并另行规划后才接入公共层。服务端 MUST 权威核对来源完整性、去重和事务。

#### Scenario: PDF 格式适配
- **WHEN** 某平台没有经验证的 PDF 字节解码能力
- **THEN** 系统 MUST 使用明确支持的服务端格式适配入口或披露不支持，不得宣称共享业务规则等于该平台可解码 PDF
