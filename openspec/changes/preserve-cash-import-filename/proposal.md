# 导入文件名按上传原样展示

## 缺陷

现金导入在服务端 `_display_filename` 中改写上传文件名：删除文件名中的密码及 `密码/password/pwd` 标记、清理空括号、把 11 位以上连续数字替换为 `尾号XXXX`，并在识别失败时改写扩展名。前端文件列表显示服务端返回的 `display_name`，因此上传完成后的名称与用户选择的文件名不一致：上传中显示本地原名，解析返回后发生跳变。

## 预期

文件条目展示与用户上传的文件名逐字一致。服务端只在协议边界取 basename 并截断到 255 字符，不再删除或脱敏密码、账号等片段。该决定有意撤销旧设计“从临时展示文件名中去除密码”的约束：文件名属于上传者本人，只返回给已认证的上传者，会话仍按 TTL 过期，诊断日志仍不记录文件名。

## 范围

- 修改 `src/ft/application/cash_import_context.py` 的文件名处理，移除密码、账号、扩展名与括号改写。
- 保持微信缺少昵称时的来源账户会话标签仍按账户标签规则脱敏。
- 更新受影响回归测试：文件名含密码或完整账号、basename、255 截断、来源账户标签脱敏。
- 新增 `import/statement-import` 行为场景。
- 通过 `MODIFIED Requirements` 把 `statement-import` 的「导入失败不泄露敏感来源数据」与 `cash-import-session` 的「临时导入会话保存来源但不写入业务账本」「文件级扫描状态可分别重试且有效文件可继续」中的密码禁令限定为「用户填写的密码字段值」，消除与文件名原样展示的冲突。

## 非目标

- 不修改支付宝或微信来源账户的名称规范化与资金分组规则。
- 不修改日志与诊断日志规则；诊断日志仍不记录文件名。
- 不修改上传协议、API 字段结构、数据库或持久化。
- 不为在途会话做迁移；其已生成的显示名随会话 TTL 过期，新上传立即使用原名。
- 不新增文件名内嵌密码的隐藏、提示或自动读取机制。

## 能力与影响

修改 `import/statement-import` 的可见文件名展示语义。公开字段 `display_name` 的名称与结构不变，值改为原样文件名。本次为 B 类变更：不新增领域能力、不改金额或持久化、不改路由、公共契约形状或依赖。

## 验收

- 文件名含密码、完整账号或 `尾号` 字样时，文件条目 `display_name` 与上传名一致。
- 只保留 basename 与 255 字符截断；空文件名回退为“账单”。
- 微信缺少昵称时的来源账户会话标签仍按账户标签规则脱敏。
- 受影响测试与 OpenSpec strict 校验通过。

## 回滚

恢复 `_display_filename` 的原改写逻辑与对应测试即可；不涉及数据迁移或部署回滚。
