# 收支账本管理与账单导入

## 为什么做

当前收支账本只能浏览收支投影和收支详情。使用者遇到漏记、金额错误、分类错误或需要补齐历史账单时，必须离开 Web 页面使用 CLI 或其他工具，无法在原有核对路径中直接校准实际流水。

本变更把收支账本扩展为可维护页面：手工和导入产生的实际现金流水都可以直接增删改，账单通过统一导入会话进入账本，关联记录可以在当前状态下创建、编辑、解除或稍后确认；收支投影仍然只作为派生结果，不作为写入对象。

## 产品目标

- 在收支账本页面完成手工流水录入；金额决定收入或支出汇总方向，流水类型独立表达单条记录自身的业务性质，零金额也必须保留该类型。
- 收支流水列表使用分页器切换页面，不使用自动追加或滚动到底部继续加载。
- 在同一条实际现金流水上直接校准导入错误，不创建修正版流水或版本列表。
- 支持所有当前已有的现金账单导入渠道：支付宝、微信、工行信用卡、工行借记卡、建行借记卡和工银亚洲。
- 通过导入渠道和业务行标识保证重复导入幂等；用户校准字段在再次导入时不被来源值覆盖。
- 支持关联记录新增、查看、编辑、取消、驳回和待确认处理；使用者手动添加时选择关联类型并直接确认，待确认只保留给系统扫描或独立审查流程，不改变收支投影。
- 使用数据库中已有的账户支持币种配置；手工流水、关联新增和账单导入只能使用账户当前支持的币种，不设置账户主币种或默认币种。本期不提供币种管理入口。
- 任何实际流水或关系变化都通过 Application Service 重新维护收支投影和相关汇总。

## 范围

### P0：实际流水维护

- 页面提供「新建流水」和「导入账单」两个主入口。
- 支持现金流水创建，字段包括发生时间、账户、币种、金额、交易对方、分类、流水类型、按类型适用的业务细分和备注。
- 账户字段先于币种字段确定；币种下拉框只展示数据库中该账户当前的支持币种。账户支持币种由迁移或数据库初始化提供，不在流水页面维护。
- 编辑界面不提供收入 / 支出选择控件：负金额计入支出，正金额计入收入，零金额不改变两者汇总；任何金额都由使用者选择或确认流水类型，零金额不得用「中性」替代该类型。
- 流水类型和业务细分复用现有 `record_type` / `record_subtype` 合法组合并使用用户可理解的中文名称；“个人转账”等多记录语义不得作为单条流水类型出现。
- 个人转账通过一条负金额转出流水和一条正金额转入流水建立已确认关联后形成；「添加关联」只从已有流水中搜索和选择对侧流水，若需新建对侧流水，先通过页面的「新建流水」入口创建，再回到关联流程选择。
- 手工和导入产生的单条现金流水都可以直接编辑当前有效值。
- `source_type`、`record_id` 和 `source_payload` 只作为来源信息展示，不能由用户编辑；来源信息更新只能来自再次导入。
- 删除按实际删除语义处理：确认页先说明关联影响，提交后自动处理相关关系、物理删除当前流水并重建剩余记录；不要求使用者预先逐条取消关联，也不级联删除其他流水。
- 修改关系敏感字段时先判断现有关系是否仍合法；仍合法则直接保存并重建，失效时必须在使用者确认后原子保存并取消关联，不能静默解除。

### P0：账单导入与校准

- 导入会话覆盖：选择文件 → 识别渠道与参数 → 解析预览 → 重复 / 冲突处理 → 确认提交 → 导入结果摘要。
- 预览不写入账本；预览行至少显示发生时间、交易对方、金额、币种、目标账户、导入渠道、分类、重复状态和错误状态。
- 重复身份使用工作区、导入渠道和业务行标识；不使用备注、UI 行号或最终展示字段。
- 每条实际现金流水可以保存 `manual_overrides`，只记录用户校准过的字段及最近来源值，不建立来源实体或完整来源标准值表。
- 再次导入同一业务行时，未被校准的字段采用最新来源值；已被校准的字段保留当前值，同时更新其来源值对照。
- 已删除的实际流水不再占用当前幂等记录；再次导入同一业务行时，按新记录重新发布。
- 导入完成后展示新增、已存在、需要处理、冲突和失败摘要；系统自动扫描结果不在本期详情中展示，字段保留规则由后台处理，不在界面展示。
- 导入行按目标账户检查币种；不支持的币种在预览中集中列出并提示“请更新账户配置后重新导入”，系统不得静默扩展账户配置。

### P0：关系维护

- 支持同笔支付关系、转账配对关系、退款冲销关系和现金—投资资金调拨关系的当前状态管理。
- 使用者新增关联时必须选择面向业务的关联类型；关系类型不从金额符号唯一猜测，也不混入流水类型选项。
- 收支详情的「关联记录」区域支持添加、查看、编辑和取消关联；区域只提供一个「添加关联」入口，进入后直接搜索已有流水。
- 使用者从实际流水手动添加关联时固定创建 `accepted` 关系，不选择保存方式；系统扫描或独立审查流程仍可产生不改变收支投影的 `pending_review` 关系。
- 选择已有流水时通过服务端搜索、默认前后三天时间范围和分页结果定位对侧流水，不预读取全部流水，也不使用承载全量数据的下拉框。
- `pending_review` 关系可以直接编辑、驳回或撤回；取消已确认关系时复用当前 `rejected` 决定阻止自动扫描重新建立同一组流水，使用者仍可主动重新添加。
- 关系操作不创建用户可见的版本列表；关系底层状态和投影约束继续遵循现有关系主规格。
- 修改或删除关系只改变关系，不级联删除关系两端的实际流水。
- 关系重建只读取实际流水的当前字段并重建派生结果，不得把主记录、来源记录或其他成员的备注、交易对方等字段反写到实际流水。

## 非目标

- 本变更不新增统一操作日志、各类型审计表、流水版本表或关系版本表；审计操作日志作为后续横切能力单独设计。
- 本变更不在收支账本页面直接导入投资事件、持仓或投资账户账单；投资账本保持独立，现金—投资资金调拨关系可以在关系审查列表中查看。
- 不把收支投影当成可编辑事实，前端不得直接写入投影表或自行计算投影金额。
- 不覆盖用户上传的原始文件，不持久化上传文件路径或文件级导入批次实体。
- 不为通用 CSV 任意列映射预建独立规则；现有解析器不支持的格式必须显示不支持原因。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `020-cash-ledger-browser-web`：为既有收支账本增加实际流水维护、现金账单导入校准和当前关系管理，并让零金额流水按自身流水类型在账本中可见。
- `004-mapping-import-open-currency`：开放币种从“任意三位字母”收敛为系统币种目录，并由账户支持币种约束导入写入。
- `005-multi-currency-accounts`：账户正式保存多币种支持集合，替代通过 `metadata_json` 承载的 `base_currencies` 配置语义；本期只读取数据库配置，不提供币种管理 UI。

## 已确认的产品决策

1. 导入流水允许直接编辑和删除；编辑的是实际现金流水，来源字段只读。
2. 不建立 `cash_source_records`、`source_values`、流水版本或关系版本实体；`cash_transactions` 保存当前值、来源字段和 `manual_overrides`。
3. 删除以实际删除的产品语义呈现，不提供撤销和版本入口；再次导入已删除业务行时允许重新发布。
4. 所有当前现金账单渠道首期一起支持：支付宝、微信、工行信用卡、工行借记卡、建行借记卡、工银亚洲。
5. 关系只面向当前状态维护；待审关系不影响投影，取消关联不删除实际流水，并保留当前拒绝决定阻止自动重新匹配。
6. 当前不实现操作审计日志；未来使用统一日志方案，不按业务类型拆表。
7. UI 采用方案 C 的卡片流并复用既有信息抽屉；抽屉原位切换查看态与编辑态，并直接承载关联记录的添加、查看、编辑、取消和删除影响确认。
8. “个人转账”不是单条流水类型；单条流水保留转账入账 / 出账等自身业务类型，关联后才形成个人转账展示。
9. 账户支持币种使用 `accounts.currencies` JSON 数组；数组保存账户当前支持的、去重且大写的系统币种代码，不新增账户币种表，不设置主币种或默认币种。本期由数据库或迁移脚本填入，不提供运行时管理入口。
10. 「添加关联」只搜索和选择已有流水；人工添加固定为已确认，已有流水使用服务端检索、默认前后三天时间范围和分页结果，不加载全量候选；新建对侧流水通过独立的「新建流水」入口完成。

## 验收标准

- 使用者无需 CLI 即可新增、编辑和删除手工或导入现金流水，并在列表、余额、月份汇总和收支详情中看到一致结果。
- 导入流水被用户校准后，再次导入不会覆盖校准字段；界面不展示最近来源值、校准标记或恢复来源操作。
- 同一工作区同一导入渠道和业务行标识不会重复生成当前活跃流水；已删除行再次导入时可以重新发布。
- 删除包含关系的实际流水时，页面先说明影响，确认后自动处理相关关系并删除当前流水；对侧实际流水不会被级联删除。
- 取消关联后，自动扫描不会重新建立同一组流水的关系；使用者主动添加时可以重新确认。
- 编辑普通字段或重建关系不会覆盖实际流水当前值；投影展示字段稳定取自主记录。
- 新建、编辑和导入均遵守数据库中的账户支持币种集合；本期不设计运行时添加、移除或修改账户支持币种的用户流程。
- 账户支持币种迁移完成后，旧 `metadata_json.base_currencies` 不再作为账户币种配置来源；迁移不会删除仍可能承载其他遗留信息的 `metadata_json` 列。
- 关系可以保存为待审；待审、驳回和解除状态不改变收支投影，已确认关系的影响可在收支详情中解释。
- 手工添加关联只有一个入口，直接搜索已有流水；该流程不展示保存方式，提交结果固定为已确认。新建对侧流水通过独立的「新建流水」入口完成。
- 关联流水检索按交易对方、账户、金额和时间范围等摘要字段在服务端执行，每次只返回有限结果并通过分页器切换；进入查看态或编辑态不会预取全部流水。
- 收支流水列表通过分页器切换页面；关联流水搜索默认限制在当前流水发生日期前后 3 天，并允许使用者调整日期范围。
- 任一写入失败不产生半完成的内部资金移动、关系或投影；SQLite 与 PostgreSQL 使用同一 Application Service 得到等价结果。
- Web 端在 320、375、414 和 768 px 宽度无横向滚动，键盘可以完成新建、编辑、导入和关联提交。

## 影响与回滚

- 影响 Web 写入 API、现金流水 Application Service、导入幂等与校准合并、关系当前状态管理、收支投影刷新和前端管理状态；本期不增加账户币种管理 API。
- 账户表使用 `currencies` JSON 列；迁移或数据库初始化将现有账户已知币种和投资账户的 `metadata_json.base_currencies` 归并到该列，停止继续写入该遗留键。
- 可能需要在现有现金流水表增加 `source_fingerprint`、`manual_overrides`、并发版本或等价字段；不得新增 `cash_source_records` 或版本历史表。
- 实际删除必须在 Application Service 事务内处理关系和投影引用，并提供 SQLite 与真实 PostgreSQL 证据。
- 回滚以应用版本回退为主；本变更未授权时不得提交、推送、部署或操作真实账本数据。
