# 提案：投资账本浏览 Web

## Why

系统已经能够导入、保存和估值投资事件，但当前 Web 只提供收支账本，使用者无法在浏览器中分别查看“现在持有什么”和“发生过什么”，也无法筛选投资事件、核对来源与关系证据。

原 `022-investment-ledger-browser-web` 是未实现的 Spec Kit 草案。它不属于当前主规格，本 change 将其整理为可实施、可验证的 OpenSpec 规划；原始草案保存在 `legacy/022-investment-ledger-browser-web/`。

## What Changes

- 新增独立的“当前持仓”和“投资事件”只读页面，并通过侧边分级导航切换。
- 当前持仓页复用既有估值合同，按“总浮盈亏 → 近 24 小时盈亏 → 当前总市值”展示总览，并以持仓表格展示标的、当前单价、数量、当前市值、仓位、浮盈亏、浮盈亏率、近 24 小时盈亏和近 24 小时盈亏率；手机端降级为持仓卡片。投资事件页支持筛选、稳定分页、关系摘要和受控证据详情。
- 当前持仓每 10 秒自动刷新，并提供手动刷新入口；刷新过程只在刷新按钮上显示圆形进度，不增加更新时间卡片。刷新失败与成功使用单一结果状态，不把 `complete`、`partial` 等行情覆盖状态直接呈现给使用者。
- 增加浏览器本地保存的展示偏好：账户筛选、标的排序、同标的合并/分开展示、可自由输入的换算币种和时间范围。
- 面向不了解内部模型的使用者简化投资页及共享账本详情的呈现，不把关系、投影、来源渠道、规则编号等实现语义带到用户主流程。
- 持仓总览和卡片只保留指标名称、结果与必要动作，不用辅助句解释分母、资产范围或刷新机制；这些精确定义保留在规格和无障碍名称中。
- 所选时间范围的盈亏同时包含持仓价格变化形成的浮盈亏和期间买卖形成的已实现盈亏；总览只展示一个合计结果，不单独增加“已实现盈亏”指标。
- 保留行情局部失败、工作区隔离、精确十进制、明确时间、双后端等价和可访问性边界。
- 在实现前完成 A 类 UI 原型、产品与工程复核，并以失败测试驱动 API、查询和界面实现。

### Scope

- 投资事件与持仓的只读 Application Service、Web API 和两个独立 Web 页面。
- 日期、账户、事件类型和标的筛选，版本化稳定分页，批量关系摘要和证据详情。
- 响应式、键盘操作、生产预览、视觉审查和双后端契约验证。
- 用户可见术语审查、原型同步、文案回归和交付流程证据。

### Non-goals

- 不新增或修改投资事件、持仓、行情或交易关系。
- 不改变投资导入、账本写入、关系扫描和成本基础规则；新增指标只在读取时计算。
- 不单独展示已卖出部分的收益或损失，也不拆分周期盈亏；周期总额仍必须包含期间完全卖出标的形成的已实现盈亏。
- 不把单个行情数据源的内部覆盖状态直接暴露为持仓卡片状态；持仓读取接口整体成功或失败，具体无法计算的指标使用空值并保留可审计原因。
- 不改变收支数据、投资数据、关系扫描或投影维护行为；本次只调整用户可见呈现。

## Capabilities

### New Capabilities

- `investment-ledger-browser`: 投资事件浏览、证据核对、持仓估值展示和只读 Web 交互。

### Modified Capabilities

- 无。该能力消费 `investment-event-model`、`ledger-records`、`portfolio-valuation` 与 `time-semantics` 的既有合同。

## Impact

- 预计影响投资查询 Application Service、持仓表现查询、行情历史/24 小时基准读取、Web API、Web 页面、测试与 OpenSpec artifact。
- 浏览器本地存储新增展示偏好，不写入账本、账户或投资事件数据。
- 涉及工作区隐私、精确金额、时间、稳定分页、行情局部失败、PostgreSQL/SQLite 等价和用户可见 UI，按 A 类变更执行。
- 完成实现、验证和归档前，`openspec/specs/` 不得出现 `investment-ledger-browser` 主规格。
