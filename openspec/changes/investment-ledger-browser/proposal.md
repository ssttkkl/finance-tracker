# 提案：投资账本浏览 Web

## Why

系统已经能够导入、保存和估值投资事件，但当前 Web 只提供收支账本，使用者无法在浏览器中分别查看“现在持有什么”和“发生过什么”，也无法筛选投资事件、核对来源与关系证据。

原 `022-investment-ledger-browser-web` 是未实现的 Spec Kit 草案。它不属于当前主规格，本 change 将其整理为可实施、可验证的 OpenSpec 规划；原始草案保存在 `legacy/022-investment-ledger-browser-web/`。

## What Changes

- 新增独立的“当前持仓”和“投资事件”只读页面，并通过侧边分级导航切换。
- 两个账本页面共用一个 SPA 外壳和同一棵侧边导航树；路由只切换主内容区，导航不随页面重复实现。
- 移动端默认折叠侧边导航，只保留品牌和“菜单”入口；展开后复用同一棵分级导航，选择路由后自动收起，桌面端保持常驻侧栏。
- 当前持仓页复用既有估值合同，按“总浮盈亏 → 近 24 小时盈亏 → 当前总市值”展示总览，并以持仓表格展示标的、当前单价、数量、当前市值、仓位、浮盈亏、浮盈亏率、近 24 小时盈亏和近 24 小时盈亏率；手机端降级为持仓卡片。投资事件页支持筛选、稳定分页、关系摘要和受控证据详情。
- 当前持仓改用 SSE 接收服务端推送的估值快照，浏览器不再定时轮询完整估值；服务端常驻行情刷新器按手动刷新优先、活跃展示口径次之的顺序批量更新持仓标的。刷新过程只在刷新按钮上显示圆形进度，不增加更新时间卡片。刷新失败与成功使用单一结果状态，不把 `complete`、`partial` 等行情覆盖状态直接呈现给使用者。
- 增加浏览器本地保存的展示偏好：账户筛选、标的排序、同标的合并/分开展示、可自由输入的换算币种和时间范围。
- 面向不了解内部模型的使用者简化投资页及共享账本详情的呈现，不把关系、投影、来源渠道、规则编号等实现语义带到用户主流程。
- 投资事件页使用真实长度数据校验桌面表格：页面只保留一个“投资事件”标题，筛选开合文字不得折行；金额和数量在 API 中保持精确十进制，列表按最多 8 位小数四舍五入并去除无意义尾零，币种和标的统一大写，不把数据库定长小数原样展示给使用者。
- 投资事件表不再固定显示“付出 / 换入”两行：交易按“流出 / 流入”展示两侧资产，流出数字带 `-`、流入数字带 `+`；收入、费用、出入金等只展示实际变化的一侧，快照使用“余额 / 持有”；空值和结构占位零不占一行。流入/流出的字体、字号和颜色与收支账单金额保持一致。
- 投资详情改为一张连续信息面板：标题直接显示事件类型，时间和账户只出现一次；资产变化是主体，现金账户和备注按需补充。相同时间、金额、操作、数量或备注不得因来自不同记录或字段而重复展示，只有不同的业务事实才新增一行。
- 移动端投资事件以整张卡片作为详情入口，不单独显示眼睛图标；桌面端继续保留眼睛图标作为表格行的详情入口。
- 投资页面沿用 PR #42 收支账单页的 Cobalt 视觉基准、控件状态与线性 SVG 图标语言；筛选、展开、查看详情和关闭等相同行为保持同一图标含义，不使用 Unicode 字符模拟图标，同时保留投资账本自己的分级导航和信息结构。
- 持仓总览和卡片只保留指标名称、结果与必要动作，不用辅助句解释分母、资产范围或刷新机制；这些精确定义保留在规格和无障碍名称中。
- 所选时间范围的盈亏同时包含持仓价格变化形成的浮盈亏和期间买卖形成的已实现盈亏；总览只展示一个合计结果，不单独增加“已实现盈亏”指标。
- 保留行情局部失败、工作区隔离、精确十进制、明确时间、双后端等价和可访问性边界。
- 在实现前完成 A 类 UI 原型、产品与工程复核，并以失败测试驱动 API、查询和界面实现。
- 为投资浏览查询和前端首屏补充固定负载性能门禁：覆盖 20,000 条事件历史、事件详情、持仓查询、浏览器基线对比、首屏核心指标、资源体积和请求数，并在 SQLite/真实 PostgreSQL 条件下记录可复现证据。
- 当前持仓保留两阶段读取：打开页面后先读取不访问行情源的持仓清单，并在 1 秒内显示标的、账户和数量；浏览器随后连接 SSE，接收服务端刷新器产生的估值快照。单次外部数据源调用仍有独立超时和退避，但不再以整个完整估值请求的 2 秒截止时间决定页面结果。刷新期间始终保留最近一次有效行情、估值和总览，直到同一展示条件下的新有效字段可替换它们。
- 行情刷新器并行读取当前行情、周期起点行情与汇率，并在每次可用快照推进时通过 SSE 发送；行情不全时继续返回未知值，绝不以 `0` 代替。浏览器断线后由 `EventSource` 重连，服务器以最新快照恢复，且页面刷新或后台切换不会重新引入定时轮询。
- 当所选周期内存在投资快照时，周期表现从该账户和标的最后一条快照开始计算，不尝试把快照倒放成更早的持仓；总览和受影响持仓明确标注具体的记录时间及“可能无法反映真实盈亏”，避免把部分可观测结果误解为完整周期收益。
- 投资事件的标的筛选改为大小写不敏感的包含匹配：输入标的代码中的任意连续片段即可匹配付出或换入资产；`%`、`_` 和反斜杠按普通字符解释，不提供通配符或全文搜索语法。

### Scope

- 投资事件与持仓的只读 Application Service、Web API 和两个独立 Web 页面。
- 日期、账户、事件类型和标的片段筛选，版本化稳定分页，批量关系摘要和证据详情。
- 响应式、键盘操作、生产预览、视觉审查和双后端契约验证。
- 用户可见术语审查、原型同步、文案回归和交付流程证据。
- 与收支账单页的视觉一致性检查，基准固定为 PR #42 当前提交 `24e8f317435a481d83bb280c6e9905ef961c8f95`；生产实现前重新确认该 PR 的最新提交并复用已落地的共享组件。
- 性能回归报告与基线文件；只优化本 change 引入的超预算项，不将基线已有字体负担误归因于投资页。
- 当前持仓的快速清单请求、SSE 快照、常驻行情刷新器、行情局部不可用、断线重连，以及带既有数值的手动刷新回归。
- 周期内投资快照的不可倒放边界、快照后的持仓表现、API 返回基准时间和总览/持仓提示。

### Non-goals

- 不新增或修改投资事件、持仓、行情或交易关系。
- 不改变投资导入、账本写入、关系扫描和成本基础规则；新增指标只在读取时计算。
- 不单独展示已卖出部分的收益或损失，也不拆分周期盈亏；周期总额仍必须包含期间完全卖出标的形成的已实现盈亏。
- 不把单个行情数据源的内部覆盖状态直接暴露为持仓卡片状态；持仓读取接口整体成功或失败，具体无法计算的指标使用空值并保留可审计原因。
- 不改变收支数据、投资数据、关系扫描或投影维护行为；本次只调整用户可见呈现。
- 不伪造、猜测或将 `0` 用作未知行情；冷启动时若可信行情源尚未返回，页面只显示已知持仓并保持 SSE 连接，而非捏造价格或估值。

## Capabilities

### New Capabilities

- `investment-ledger-browser`: 投资事件浏览、证据核对、持仓估值展示和只读 Web 交互。

### Modified Capabilities

- 无。该能力消费 `investment-event-model`、`ledger-records`、`portfolio-valuation` 与 `time-semantics` 的既有合同。

## Impact

- 预计影响投资查询 Application Service、持仓表现查询、行情历史/24 小时基准读取、Web API、Web 页面、测试与 OpenSpec artifact。
- 浏览器本地存储新增展示偏好，不写入账本、账户或投资事件数据。
- 涉及工作区隐私、精确金额、时间、稳定分页、行情局部失败、PostgreSQL/SQLite 等价和用户可见 UI，按 A 类变更执行。
- 完成实现、验证和归档前，`openspec/specs/` 不得出现 `investment-ledger-browser` 主规格。
