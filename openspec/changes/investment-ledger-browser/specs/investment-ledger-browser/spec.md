## Purpose

定义使用者在只读 Web 中浏览投资事件、核对来源与关系证据，并查看当前持仓及估值状态时的完整行为。

## ADDED Requirements

### Requirement: 投资事件列表支持稳定筛选和分页
系统 MUST 为当前工作区返回投资事件的发生时间、账户、记录类型、记录子类型、标的、付出资产、换入资产、手续费、来源说明和导入渠道。列表必须支持浏览器本地日期范围、投资账户、记录类型和标的筛选，并使用绑定排序键、筛选条件和数据版本的稳定分页游标。

#### Scenario: 按账户和标的连续翻页
- **WHEN** 使用者选择一个投资账户和标的，并在数据版本不变时连续翻页
- **THEN** 列表 MUST 按稳定顺序返回全部匹配事件，不重复或遗漏同一排序范围内的事件

#### Scenario: 数据变化后使用旧游标
- **WHEN** 新投资事件使列表数据版本变化后，使用者继续提交旧游标
- **THEN** API MUST 返回可识别的游标失效错误，且不得把两个版本的数据混入同一分页序列

### Requirement: 当前页批量提供关系摘要和受控证据
系统 MUST 按当前页投资事件批量读取关系摘要，避免逐行查询。证据详情必须限定当前工作区，展示正式字段、来源行快照中的可核对业务信息和已确认关系影响；不得暴露内部代理键、凭据、完整认证材料或其他工作区数据。

#### Scenario: 查看现金—投资资金调拨证据
- **WHEN** 使用者打开一个具有已确认资金调拨关系的投资事件详情
- **THEN** 详情 MUST 展示投资端与现金端账户、精确金额、币种、方向和关系影响，并隐藏不属于业务证据的内部字段

#### Scenario: 跨工作区读取证据
- **WHEN** 请求使用当前工作区之外的投资事件标识读取详情
- **THEN** API MUST 拒绝访问，且不得泄露目标事件是否存在

### Requirement: 当前持仓与投资事件使用独立页面和统一 SPA 分级导航
Web MUST 在同一个 SPA 外壳中提供独立的“当前持仓”和“投资事件”只读页面，并由共享外壳统一渲染侧边导航和页面框架；路由只替换主内容区，不得由页面组件各自复制导航。侧边导航必须以“收支账本 / 投资账本”为一级项目、以“当前持仓 / 投资事件”为投资账本下的二级项目，并在收支账本和投资账本路由下保持一致。桌面端导航常驻；移动端 MUST 默认折叠为品牌和“菜单”入口，展开后显示同一棵分级导航，选择路由后自动收起，不得新增另一套导航语义。页面顶部不得重复放置同级页面切换。当前持仓页必须复用既有组合查询，桌面端以持仓表格展示账户、标的、当前单价、数量、当前市值、仓位、浮盈亏、浮盈亏率、近 24 小时盈亏和近 24 小时盈亏率；仓位分母 MUST 包含所有投资标的市值和现金市值。表格列顺序 MUST 固定为“标的 / 账户、当前单价、数量、当前市值、仓位、浮盈亏、浮盈亏率、近 24 小时盈亏、近 24 小时盈亏率”。各列字号 MUST 保持一致，浮盈亏相关列通过字重和颜色建立视觉层次；在 820 px 及以下 MUST 将每行降级为持仓卡片。不可用金额必须为空，不得显示为假 `0`。当前持仓在用户界面只能有整体的读取成功或读取失败状态，不得显示 `complete`、`stale`、`partial`、`unsupported` 或其中文技术映射。

#### Scenario: 从侧边导航切换页面
- **WHEN** 使用者在侧边导航展开投资账本并选择当前持仓或投资事件
- **THEN** Web MUST 打开对应独立页面，标记当前二级项目，且页面主体不得拼接另一个页面的内容

#### Scenario: 两个账本共用导航外壳
- **WHEN** 使用者分别打开收支账本、当前持仓和投资事件路由
- **THEN** 三个路由 MUST 渲染同一套一级和二级侧边导航，只有主内容区随路由切换；打开详情抽屉时侧边导航和主内容背景 MUST 不可交互

#### Scenario: 移动端折叠菜单
- **WHEN** 使用者在 320、375、414 或 768 px 宽度打开任一账本路由
- **THEN** 导航 MUST 默认收起并显示“菜单”入口；点击后显示完整分级导航，选择任一项目后菜单 MUST 自动收起，且页面不得出现横向滚动

#### Scenario: 持仓查询成功
- **WHEN** 当前持仓查询和当前价格读取成功
- **THEN** 当前持仓页 MUST 以成功状态展示持仓表格（窄屏为持仓卡片），并显示表现指标，而不显示行情覆盖等级

#### Scenario: 持仓查询失败
- **WHEN** 当前持仓查询或当前价格读取失败
- **THEN** 当前持仓页 MUST 以单一失败状态展示持仓区域并提供重试动作；投资事件页 MUST 仍可独立打开

#### Scenario: 桌面端查看持仓表格
- **WHEN** 使用者在宽屏设备打开当前持仓页
- **THEN** 页面 MUST 按固定列顺序展示持仓表格，并将浮盈亏、浮盈亏率、近 24 小时盈亏和近 24 小时盈亏率作为四个独立列

#### Scenario: 手机端查看持仓
- **WHEN** 使用者在 820 px 或更窄的设备打开当前持仓页
- **THEN** 页面 MUST 将每个持仓行转换为可读卡片，保留表格中的全部字段，不得产生页面级横向滚动

### Requirement: 当前持仓按固定频率刷新并支持手动刷新
当前持仓 Web 查询 MUST 在页面可见时每 10 秒自动刷新一次，并提供一个小型手动刷新按钮。刷新期间 MUST 只在该按钮的圆形图标上显示旋转反馈，页面不得为刷新机制增加更新时间指标卡或解释文字；减少动态效果时 MUST 使用静态忙碌状态。页面不可见时 MUST 暂停定时请求，在重新可见时立即发起一次刷新；刷新请求 MUST 可取消旧请求，避免过期响应覆盖较新的持仓结果。

#### Scenario: 定时刷新持仓
- **WHEN** 投资账本页面保持可见且距离上次持仓查询达到 10 秒
- **THEN** 页面 MUST 发起一次新的持仓查询，并更新当前持仓、总览和表现指标

#### Scenario: 手动刷新持仓
- **WHEN** 使用者点击手动刷新按钮
- **THEN** 页面 MUST 立即发起持仓查询，刷新图标在请求期间显示旋转反馈，按钮保持可访问，并在成功或失败后恢复可操作

#### Scenario: 页面不可见时恢复
- **WHEN** 页面从不可见变为可见
- **THEN** 页面 MUST 停止积累隐藏期间的轮询，并立即只发起一次新的持仓查询

### Requirement: 当前持仓支持浏览器本地展示偏好
Web MUST 支持按投资账户筛选、按标的排序、同一标的在不同账户间合并或分开展示、使用原币种或统一换算币种，以及切换时间范围。换算币种 MUST 使用可自由输入的币种代码控件，而不是限制为固定下拉选项；留空表示原币种，合法输入保存为浏览器偏好，非法或不支持的输入不得覆盖上次有效偏好。偏好 MUST 仅保存在当前浏览器，不得写入账本或投资事件；默认值 MUST 为全部账户、按市值倒序、分开展示、原币种和近 24 小时。合并同一标的时，数量 MUST 相加，成本 MUST 按总成本除以总数量重新计算；成本币种不一致时 MUST 保持分开展示并阻止错误合并。

#### Scenario: 还原浏览器偏好
- **WHEN** 使用者修改账户、排序、合并、币种或周期选项后重新打开投资账本
- **THEN** 页面 MUST 从当前浏览器还原上次偏好，且不得改变服务端账本数据

#### Scenario: 输入换算币种
- **WHEN** 使用者在币种输入框输入受支持的币种代码
- **THEN** 页面 MUST 使用该币种重新读取并显示金额，并在当前浏览器保存该输入

#### Scenario: 输入不可用币种
- **WHEN** 使用者输入无效或不受支持的币种代码
- **THEN** 页面 MUST 保留上次有效结果并在输入框附近显示简短错误，不得清空持仓或写入无效偏好

#### Scenario: 合并同一标的
- **WHEN** 使用者开启合并，且不同账户的同一标的成本币种一致
- **THEN** 页面 MUST 显示一个合并持仓，数量为各账户数量之和，平均成本为总成本除以总数量，并基于合并后的数量和成本重新计算表现

#### Scenario: 成本币种不一致
- **WHEN** 使用者开启合并，但同一标的的成本币种不一致
- **THEN** 页面 MUST 不合并这些持仓，也不得通过隐式汇率换算制造一个合并结果

### Requirement: 当前持仓突出显示浮盈亏与周期表现
持仓行（窄屏为持仓卡片）MUST 在最显眼位置展示当前浮盈亏额、当前浮盈亏率和所选时间范围的浮盈亏率，并在明细中把“当前市值 / 仓位”作为同一行显示；默认时间范围为近 24 小时。当前浮盈亏额 MUST 使用均摊成本法计算为当前市值减总成本，当前浮盈亏率 MUST 使用浮盈亏额除以总成本绝对值，以支持负成本而不反转正负方向；总成本为 0 时比率为空。仓位 MUST 使用该标的当前市值除以全部投资标的与现金的当前市值。周期表现 MUST 使用精确十进制计算：总额使用期末资产总额减期初资产总额并扣除外部资金流，单标的结果使用期初/期末市值扣除期间买入支出并加回期间卖出净收入，再计入分红等投资收入和相关费用；周期结果必须同时包含浮盈亏与已实现盈亏，但不得单独展示已实现盈亏指标。

#### Scenario: 负成本持仓
- **WHEN** 一个持仓的总成本为负数且当前市值可用
- **THEN** 页面 MUST 计算当前浮盈亏额为当前市值减总成本，并使用总成本绝对值作为浮盈亏率分母，不得因负成本把正浮盈亏显示为负率

#### Scenario: 期间买卖不被误判为收益
- **WHEN** 选定周期内发生买入或卖出，但没有外部出入金
- **THEN** 总周期盈亏 MUST 基于期末资产总额减期初资产总额；单标的周期盈亏 MUST 使用期末市值减期初市值、扣除期间买入支出并加回期间卖出净收入，买卖本金不得直接计为收益，且期间卖出形成的已实现盈亏必须保留在周期合计中

#### Scenario: 外部出入金不被计为收益
- **WHEN** 选定周期内发生投资账户外部入金或出金
- **THEN** 周期盈亏 MUST 从期末资产值减期初资产值中扣除外部入金影响、加回外部出金影响；外部出入金本身不得计为投资收益

#### Scenario: 期间完全卖出的标的计入总周期盈亏
- **WHEN** 某标的在所选周期内被全部卖出，当前持仓中已经没有该标的
- **THEN** 总周期盈亏 MUST 包含该标的的已实现盈亏；当前持仓表可以不新增该标的行，且不得把已实现盈亏单独作为用户指标展示

#### Scenario: 周期盈亏率使用带时间权重的投入基数
- **WHEN** 所选周期内发生买入、卖出或外部出入金
- **THEN** 周期盈亏率 MUST 使用期初资产与期间资金流的时间加权投入基数；资金流发生时间越晚，对分母的影响越小；投入基数为 0 时比率为空

#### Scenario: 切换表现周期
- **WHEN** 使用者选择本周至今、本月至今、近 30 天、近 90 天、年初至今或近 365 天
- **THEN** 页面 MUST 使用对应本地时间边界或滚动时长重新计算持仓和总览的周期盈亏率，并明确显示当前周期

#### Scenario: 展示当前市值和仓位
- **WHEN** 页面已获得标的市值、其他持仓市值和现金市值
- **THEN** 持仓卡片 MUST 在“当前市值 / 仓位”一行显示该标的市值与仓位百分比，仓位分母包含现金

### Requirement: 当前持仓提供标的总览和资产口径
当前持仓区域 MUST 同时展示所有投资标的的总当前浮盈亏额、总当前浮盈亏率、总当前市值，以及所选时间范围的浮盈亏额和浮盈亏率。总当前浮盈亏额只统计证券、加密资产等投资标的；总当前浮盈亏率的分母 MUST 为所有投资标的市值与现金市值之和。统一换算币种可用时，金额 MUST 在该币种内汇总；使用原币种且存在多个币种时，页面 MUST 按币种分别展示汇总，不得直接相加不同币种金额。总览 MUST 只显示指标名称和数值，不得添加“含现金”“投资标的 + 现金”或同类解释句；精确口径由本规格定义。系统 MUST NOT 单独展示已卖出部分的收益或损失，但所选周期的总盈亏 MUST 包含期间完全卖出标的的已实现盈亏。

#### Scenario: 总当前浮盈亏
- **WHEN** 页面成功读取投资标的和现金持仓
- **THEN** 总当前浮盈亏额 MUST 只累加投资标的浮盈亏，且总当前浮盈亏率的分母 MUST 包含投资标的市值和现金市值

#### Scenario: 总周期盈亏
- **WHEN** 使用者选择任一表现周期
- **THEN** 总周期盈亏额 MUST 使用当前资产总额减周期起点资产总额再扣除外部入金影响、加回外部出金影响，且买卖不得被当作外部资金流排除

#### Scenario: 展示周期浮盈亏
- **WHEN** 页面获得所选时间范围的浮盈亏结果
- **THEN** 总览 MUST 显示该时间范围内浮盈亏与已实现盈亏的合计金额和比率，不得增加已卖出部分的独立盈亏指标

#### Scenario: 原始币种总览
- **WHEN** 使用者选择原始计价币种且持仓包含多个计价币种
- **THEN** 页面 MUST 为每个币种分别展示总览金额和比率，避免产生无币种意义的跨币种合计

### Requirement: 行情失败不阻塞投资事件浏览
系统 MUST 在共享有界预算内查询当前持仓和表现数据。持仓查询或当前价格读取失败时，持仓区域 MUST 返回整体失败结果并保留可操作的错误原因；不得向使用者呈现逐标的覆盖等级。投资事件查询 MUST 与持仓查询隔离，持仓失败不得阻塞投资事件浏览。

#### Scenario: 持仓行情查询超时
- **WHEN** 当前价格或表现数据源在总预算内未返回
- **THEN** 持仓区域 MUST 显示整体失败状态并允许重试，投资事件列表 MUST 保持可用，且页面不得出现 `partial` 或同义状态标签

### Requirement: 投资页面使用面向普通用户的简洁文案
Web MUST 假设使用者不了解内部数据模型、查询实现或状态枚举。可见文案 MUST 使用短业务词和直接动作，隐藏关系、投影、来源字段、渠道、规则编号、覆盖状态及其他实现语义；指标已有清晰名称和值时不得追加解释句。内部精确术语和计算定义 MUST 保留在 API、代码、规格、日志或无障碍名称中，不得以牺牲财务语义为代价删除。

#### Scenario: 普通用户查看当前持仓
- **WHEN** 使用者打开当前持仓页并读取正常结果
- **THEN** 页面 MUST 使用“平均成本”“时间范围”“当前市值 / 仓位”等直接标签，且不得显示“均摊成本”“表现周期”“更新时间”“行情覆盖”或解释分母的辅助句

#### Scenario: 普通用户遇到错误
- **WHEN** 持仓、事件或详情读取失败
- **THEN** 页面 MUST 使用一条简短结果和一个可执行动作，不得解释内部失败链路或状态枚举

### Requirement: 金额和时间保持无歧义
API MUST 以十进制字符串返回投资金额、数量、成本、单价和市值，并为发生时间返回带明确 offset 的值。Web 必须按浏览器本地时区展示时间和解释日期筛选，不得用二进制浮点重新计算账务数值。

#### Scenario: 展示高精度投资事件
- **WHEN** 投资事件包含超过常见货币两位小数的合法数量和成本
- **THEN** API 与页面 MUST 保留原十进制精度，且筛选和排序不得改变该值

### Requirement: 投资账本 Web 支持键盘和响应式布局
筛选、列表、分页、区域切换和证据详情 MUST 可通过键盘操作，具有正确语义和可见焦点。证据抽屉或模态层打开时背景不可交互，关闭后焦点必须回到原入口；在 320、375、414 和 768 px 宽度不得出现页面级横向滚动或关键信息溢出。

#### Scenario: 键盘核对事件证据
- **WHEN** 使用者通过键盘打开并关闭一条投资事件的证据详情
- **THEN** 焦点、背景交互和关闭行为 MUST 符合模态语义，且完整业务信息仍可访问

### Requirement: 双后端返回等价的投资浏览合同
PostgreSQL 与 SQLite MUST 对相同工作区、投资事件、关系、持仓、行情和汇率输入返回等价的列表、分页、证据和估值状态。工作区隔离、精确十进制和错误结果不得因数据库后端不同而改变。

#### Scenario: 比较双后端投资浏览响应
- **WHEN** 两个后端使用相同去标识化夹具执行列表、详情和持仓查询
- **THEN** 除内部代理键外，响应内容、顺序、精度、状态和错误合同 MUST 等价
