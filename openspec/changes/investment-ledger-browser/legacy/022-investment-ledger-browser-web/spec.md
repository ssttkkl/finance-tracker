# Feature Specification: 投资账本浏览 Web

**Feature Branch**: `022-investment-ledger-browser-web`

**Created**: 2026-07-29

**Status**: Draft

**Context**: 本 feature 在 `020-cash-ledger-browser-web` 完成后扩展同一只读 Web/API 运行形态。它交付投资
事件、持仓和持仓估值浏览，不重建或替换 020 的本机运行、账户浏览、游标、证据脱敏与错误边界。

## 用户场景与测试

### 用户故事 1 - 浏览投资事件并查看证据（优先级：P1）

用户在 020 已交付的账本浏览器中选择投资账本视图，按日期、投资账户、事件类型和标的筛选投资事件，
稳定翻页并查看来源与关系证据。

**独立测试**：准备买卖、换入换出、分红、费用、出入金、校准和预测市场活动，验证筛选、分页和证据详情。

**验收场景**：

1. **假如** 工作区包含不同类型投资事件，**当** 用户筛选并翻页，**那么** 页面保留付出资产、换入资产、数量和手续费，不简化为买入/卖出模型。
2. **假如** 用户打开投资事件证据详情，**当** 该事件属于当前工作区，**那么** 页面显示来源与关系摘要，且不会读取其他工作区记录。

### 用户故事 2 - 查看当前持仓与估值状态（优先级：P1）

用户查看当前持仓，并区分投资事件“发生过什么”与持仓“现在持有什么”；行情受限时仍可阅读投资事件和其余持仓。

**独立测试**：为同一持仓集合准备完整、过期、局部失败和不支持的行情结果，验证金额与状态。

**验收场景**：

1. **假如** 行情报价完整，**当** 用户查看持仓，**那么** 每项持仓显示 `complete` 状态和当前市值。
2. **假如** 单个数据源超时或标的不支持，**当** 用户查看持仓，**那么** 其他持仓和投资事件仍可浏览，受影响金额留空并显示 `partial`、`stale` 或 `unsupported` 原因。

### 边界与失败场景

- 投资事件与持仓是不同对象，页面不得用持仓替代事件流水。
- 估值只能复用既有组合查询和估值能力；不得逐行请求行情、重新实现 ticker 去重、超时、并发、批量取价或币种折算。
- 金额、数量、成本、单价和市值均为十进制字符串；无行情时不得显示 `0` 或成本冒充当前市值。
- PostgreSQL 与文件型 SQLite 的投资事件、证据、持仓、估值状态和工作区隔离必须等价。

## 需求

### 功能需求

- **FR-001**：系统必须在 020 已交付的本机 API 与 Node 前端中提供投资账本视图，展示发生时间、账户、事件类型、标的、付出资产、换入资产、手续费、备注、导入渠道、关系摘要和证据入口。
- **FR-002**：系统必须支持投资事件的日期范围、账户、事件类型和标的筛选，以及稳定分页。
- **FR-003**：系统必须按当前页投资事件批量组装关系摘要，并提供当前工作区内单条事件的受控证据详情。
- **FR-004**：系统必须展示既有组合查询返回的账户、标的、数量、成本、当前单价、计价币种、计价币种市值、展示币种、折算市值和估值状态。
- **FR-005**：系统必须保留 `complete`、`stale`、`partial`、`unsupported` 状态及原因；不可用金额必须为空。
- **FR-006**：系统必须以一次有界批量组合查询读取估值，且行情局部失败不能隐藏其他持仓或投资事件。
- **FR-007**：系统必须在 PostgreSQL 与文件型 SQLite 上运行同一投资浏览响应契约矩阵，并覆盖工作区隔离、精确金额、时间边界、稳定分页、证据和估值状态。

## 成功标准

- **SC-001**：在至少含 100 条投资事件的工作区中，用户可在 2 分钟内完成筛选、连续翻页和证据详情查看。
- **SC-002**：同一去标识化数据在 PostgreSQL 与文件型 SQLite 上的投资浏览契约测试 100% 一致。
- **SC-003**：一个数据源失败或一个标的不支持时，受影响持仓以外的持仓和 100% 的投资事件仍可浏览。
- **SC-004**：所有投资金额、数量、成本、单价和市值均以十进制字符串输出，浮点数输出为 0 处。

## 非目标

- 重建 020 的本机运行时、Node 前端基础、现金账本浏览、账户目录、游标、来源脱敏或通用错误合同。
- 投资事件写入、关系审查、认证、云端同步、财富归因或报告。

## 假设

- 020 已完成并提供稳定的本机 API、Node 前端和双后端契约基线。
- 当前 `PortfolioQueryService.get_portfolio()` 与估值 port 可复用；本 feature 不改变其财务语义。
