# 设计：投资账本浏览 Web

## 上下文

现有 Web 已提供收支账本，投资领域已有统一事件、关系、持仓与估值能力；本 change 为投资账本浏览页面、周期表现查询和展示偏好的实现记录。旧 Spec Kit 草案只包含占位验收，且曾被错误写入主规格；本 change 仍是归档前的规划与审计事实源，原始草案继续保存在 `legacy/022-investment-ledger-browser-web/`。

## 目标与非目标

目标是通过只读 API 和 Web 页面连接投资事件、关系证据与当前持仓，同时保持精确金额、工作区隔离、时间和双后端合同。非目标是创建或修改投资事件、改变估值、重新扫描关系、增加数据库字段或把行情失败扩散到事件浏览。

## 设计决策

### 1. 使用独立 capability，不提前创建主规格

delta capability 为 `investment-ledger-browser`。完成实现、审查、验证和归档后才创建 `openspec/specs/investment-ledger-browser/spec.md`；当前主规格不声明该能力已经存在。

### 2. 投资事件和当前持仓使用两个独立页面

投资事件页回答“发生过什么”，读取规范投资事件、关系摘要和来源证据；当前持仓页回答“现在持有什么”，复用 `portfolio-valuation` 的数量、成本、行情、折算和覆盖状态。任何页面都不得通过持仓变化反推或伪造事件。

两个页面必须挂在同一个 SPA 外壳下：`App` 统一渲染侧边导航和页面框架，路由只替换主内容区；收支账本路由和投资账本两个路由看到的是同一棵导航树，不允许由页面组件各自复制导航。左侧导航使用两级结构：一级为“收支账本”和“投资账本”，二级在投资账本下展开“当前持仓”和“投资事件”。桌面端侧边导航常驻；移动端默认折叠为品牌与“菜单”按钮，展开时显示同一棵分级导航，选择路由后自动收起，不新增另一套导航语义。默认进入当前持仓页；页面顶部不重复放置同级页面切换。当前持仓页顺序为：页面标题 → 显示设置 → 总浮盈亏 → 近 24 小时盈亏 → 当前总市值 → 持仓表格；投资事件页顺序为：唯一页面标题 → 事件筛选 → 事件数量与列表 → 详情抽屉，不再用同名二级标题重复“投资事件”。桌面端持仓表格按“标的 / 账户、当前单价、数量、当前市值、仓位、浮盈亏、浮盈亏率、近 24 小时盈亏、近 24 小时盈亏率”排列。所有表格数值使用相同字号，浮盈亏四列通过字重和颜色建立层次；820 px 及以下将每行降级为持仓卡片，保留全部字段。详情抽屉渲染在共享外壳的背景内容之外；打开时背景（含侧边导航和移动端菜单按钮）不可交互，关闭后焦点回到原入口。

面向不了解账本内部模型的使用者，页面只显示结果和下一步动作，不显示 `record_type`、`record_subtype`、`source_type`、`quote_status`、关系规则编号或“状态覆盖”等实现语义；代码和 API 仍保留原字段。事件类型映射为“买入 / 卖出 / 转入资金 / 收入 / 支出”等短标签，详情入口统一为“查看详情”。

投资事件的资产单元格按经济效果渲染，不按 DTO 形状机械输出两行。`trade` 同时显示“流出”和“流入”；其他事件只显示真正改变数量的一侧，忽略空资产和仅为结构完整性保存的零值占位。`snapshot(cash)` 显示“余额”，`snapshot(position)` 显示“持有”，即使校准值为零也必须保留。用户界面不得出现“付出 / 换入”或 from/to 字段名；这些精确术语只留在领域模型、API 和规格内部。手续费为零时显示 `—`，避免把没有费用的事件表现成一项需要阅读的数据。

详情抽屉采用单一连续事实表，不使用三张同权卡片。抽屉标题直接显示事件类型，例如“买入”；其下用一行显示“发生时间 · 投资账户”。资产变化是唯一的主信息区：交易显示“流出 / 流入”，单侧事件只显示实际一侧，非零手续费紧随资产变化。分隔线下只补充尚未出现的现金账户和备注；不再显示“资金流向”或“更多信息”分区。

去重按用户看到的业务事实执行，不按 DTO、来源记录或关系边机械分组。相同时间只显示一次；“流入 10 AAPL.US”已经表达数量时不再增加“数量 10”；标题已经表达“买入”时不再增加“操作 买入”；备注只保留一次；现金端金额与主资产流出金额相同且币种一致时，只补充现金账户，不重复金额。若关联记录带来确实不同的金额、币种、时间或账户，则只显示这些不同事实，并保持可核对性。

#### 2.1 原型对齐修复（2026-08-12）

用户反馈生产投资事件页的表格比已确认的 `prototype/events.html` 松散，且详情抽屉中的资产数值发生逐字换行。此修复以原型为唯一视觉基线：桌面表格恢复深色表头、固定列宽、紧凑行距和单行截断；资产单元格保留“流出 / 流入”的两行结构，但数值在自己的可用列内对齐。详情抽屉的资产变化和补充事实必须各占完整一行，行内采用固定标签列与弹性数值列；不得让共享抽屉的通用双列 `dl` 规则把多条资产变化并排排布。

范围只限 `web/src/investment.css` 的展示规则及其前端回归检查；不改原型、组件结构、API、筛选、事件详情事实、金额/时间格式或账务数据。验收条件是：宽屏表格的七列与原型同宽度层次、流出/流入数值不任意断行；打开详情时流出、流入、手续费、现金账户和备注均独占一整行，长值只在数值列内换行；320、375、414、768 px 继续无页面级横向溢出，关闭与焦点行为不变。风险是共享 `.evidence dl` 规则会再次影响投资详情，因此以显式、更窄范围的覆盖规则和样式契约测试固定边界。

第二轮截图验证发现上述覆盖的选择器与共享 `.evidence dl` 规则等权，而共享规则在最终样式表中更靠后，备注所在的补充事实 `dl` 仍会退回双列网格，数值列在宽屏详情中被压缩到约 38 px，因而发生非语义断词。修复必须改为更高特异性的 `.evidence .investment-detail-*` 单列覆盖。事件表同时改用无间距的独立边框模型，使每个单元格在同一行的分隔线连续呈现；“已加载 N 条”所在的标题区保留明确下边距。验收补充为：表格横向分隔线不在列边界中断，计数与表格之间保留一个标准间距，长英文备注按自然词边界换行且不会逐字断裂。

持仓区域只保留整体的读取成功或读取失败状态，不在卡片上展示 `complete`、`stale`、`partial`、`unsupported` 或中文技术映射。成功结果展示当前数据；失败结果展示短错误提示和重试动作。内部查询仍可保留诊断原因，但不进入用户主流程。

### 3. 查询编排保持只读、有界且可刷新

投资事件页的 Application Service 先按工作区、筛选和稳定排序读取一页投资事件，再按该页事件 ID 批量读取关系摘要。当前持仓页的查询同时读取当前组合、当前价格、周期起点资产值、期间投资事件和外部出入金，统一返回表现所需的精确十进制字段。两页请求独立；一页失败不回滚或隐藏另一页。

分页游标绑定筛选摘要、排序键和事件数据版本。版本变化时旧游标明确失效，不跨版本拼接结果。

标的筛选使用经过 `strip()` 和小写规范化的字面量片段，同时检查付出与换入资产代码。关系型查询将片段中的反斜杠、`%` 与 `_` 转义后，以带显式转义字符的包含条件传给两个后端；因此 SQLite 与 PostgreSQL 都把它们视作普通标的代码字符。选择数据库层包含匹配而不是前端过滤，确保分页总是从完整匹配集生成，游标继续绑定规范化后的片段。此项不引入全文索引、打分、前缀偏好或新的 API 字段；回滚时恢复精确相等条件即可。

持仓页只在进入页面、展示币种或时间范围改变时读取一次基础清单，并建立一条按展示币种、时间范围和时区区分的 SSE 连接；浏览器不得再以定时器请求完整估值。`EventSource` 断线时使用浏览器标准重连，页面隐藏或卸载时关闭连接，重新可见时重新建立连接并请求一次优先刷新。手动刷新通过单独的只读刷新触发接口把当前展示口径放入最高优先级队列，按钮在收到下一份该口径的快照或确认失败前保持忙碌。

服务端的 `PortfolioRefreshCoordinator` 在应用 lifespan 内启动并在关闭前停止。它在进程内维护按展示口径划分的最新估值快照、单调版本与订阅条件：手动刷新优先于活跃 SSE 订阅，活跃订阅优先于过期缓存。每次计算只读组合、当前行情、周期起点行情和汇率；外部源调用仍使用各自有限超时，失败标的按退避重试，但不再由一个完整组合请求的 2 秒共享截止时间取消其它标的。刷新得到的快照与同一口径的最后成功值逐字段合并：新未知值不能清空已有行情、估值、周期表现或总览；从未得到可信值的字段继续为空。每次快照版本推进后，协调器将完整、精确十进制的快照作为 `portfolio` SSE 事件发送，心跳只维持连接而不改动页面数据。

证券当前报价采用确定的降级链。先保留现有 yfinance 批量下载的低请求数路径；仅对其中返回空值或异常的证券，以有界并发按标的依次查询 Yahoo Finance chart、Cboe delayed quote、Nasdaq quote，最后在本机配置 `FT_FINNHUB_API_KEY` 时查询 Finnhub。每个源有独立的短超时，当前报价成功后停止该标的后续尝试；首选源成功时绝不被备用源覆盖。每个 `ProviderTick` 携带实际源名、计价币种与源响应可提供的观测时间，估值层继续按既有新鲜度规则决定可用性。备用源不参与周期起点历史行情，不写入缓存、账本或数据库；全部源均失败时维持局部未知和刷新退避。

本机 Web 运行时是单进程本地服务，因此该协调器使用进程内同步原语和易失缓存；它不写入账本、投资事件、行情历史或数据库，也不假设多实例共享。若未来部署为多实例，必须另行变更为共享缓存和发布通道，不能静默让每个进程重复抓取行情。

持仓展示偏好是浏览器本地状态，不进入 API 写入或账本事实。偏好包括账户过滤、排序键、合并方式、换算币种和时间范围；默认值为全部账户、市值倒序、分开展示、原币种和近 24 小时。换算币种使用可输入控件：空值表示原币种，合法币种代码触发换算，无效值保留上次有效结果且不写入偏好。

### 3.1 性能门禁与容量边界

后端性能夹具固定为 20,000 条投资事件、1,000 条资金关系、4 个投资账户和 128 个持仓，校验实际插入数量后再测量。事件列表和事件详情各取 12 次热样本，p95 预算分别为 750ms 和 500ms；持仓查询在完整 20,000 条事件历史上取 12 次热样本，p95 预算为 3s。门禁覆盖 SQLite，并在 `FT_TEST_POSTGRES_URL` 指向专用 `_test` 数据库时复用同一夹具执行真实 PostgreSQL 矩阵；PostgreSQL 不可用时必须记录跳过原因和准确补跑条件。

浏览器性能以 `origin/refactor/web` 的同一收支路由为基线，并对当前投资持仓路由做绝对预算检查：FCP < 1.8s、DOM 完成 < 2.5s、JS < 500KB、CSS < 100KB、请求数 < 50。相对比较沿用 benchmark 规则，计时增加超过 50% 或 500ms 视为回归，bundle 增加超过 25% 视为回归，请求数增加超过 30% 视为回归；10% 以上的 bundle 增长仅作为 warning。LCP 若浏览器没有 buffered entry 必须标为未采集，不以估算替代。

路由拆分后的实测投资页冷加载 FCP 44ms、DOM 完成 26.8ms、9 个请求、JS 总计 79,735B（主包 69,991B，投资 chunk 9,744B）、CSS 总计 9,164B（全局 6,157B，投资 chunk 3,007B），均通过绝对预算；收支页为 7 个请求、FCP 52ms、DOM 完成 24.6ms，JS/CSS 仅比基线增加 1.6%/4.6%。投资页面的代码和样式在进入投资路由时懒加载，不增加收支页首屏负担。两条路由的总传输量仍约 2.40MB，主要由基线已有的两份 Noto Sans SC 字体构成，基线同样超过 benchmark 示例的 2MB 提示。为保持 PR #42 的视觉基准，本 change 不在投资页范围内替换全局字体；字体子集化或系统字体回退作为后续独立性能变更，不混入本次 UI 语义和信息架构变更。

#### 3.2 当前持仓 SSE 分阶段契约（2026-08-12）

用户实测确认原完整请求在 2.01 秒稳定结束，本地 `phase=holdings` 只需约 0.11 秒，但 18 个持仓只有 6 个成功、12 个因 `query_deadline_exceeded` 变为部分结果。根因是把本地只读组合查询、外部行情和期间表现放在同一 2 秒响应临界路径上；SSE 本身不能加快行情源，因此必须先把刷新任务脱离请求线程并保留最后成功快照。

`phase=holdings` 只调用组合仓库，不访问当前行情、历史行情、汇率或期间流水表现；它返回与完整 DTO 相同的账户和持仓基础字段（标的、账户、数量、成本、现金识别），金额与表现字段仍为空。它必须在固定负载及注入阻塞行情源的测试中于 1 秒内完成。新增 `/investment-portfolio/stream`：以 `text/event-stream` 返回 `portfolio` 事件，每项携带单调版本和完整估值 DTO；无缓存时保持连接并触发刷新，有缓存时先发送该口径最新快照。新增刷新触发接口只入队而不在 HTTP 请求中等待 yfinance。保留既有完整 JSON 查询作为兼容读取，但生产 Web 不再用它轮询。

Web 在同一页面生存期内发起 `holdings` 快速读取并建立 SSE：快速结果到达后立即渲染持仓行与数量，`portfolio` 事件原位补齐行情列、估值列与总览。展示币种或时间范围改变时必须关闭旧 SSE 连接、先清除不兼容的旧完整结果并建立新口径连接；同一口径的手动刷新始终以最后一次有效结果为显示底座。服务端和前端均只允许新的有效字段替换已有字段，因此刷新期间不发生行情、估值或总览闪空。SSE 事件不显示源状态、失败原因或更新时间卡片；页面继续只提供整体可用或重试状态。

门禁以单调时钟验证基础清单在 1 秒内不受阻塞行情源影响；服务端测试必须证明 SSE 订阅先获得缓存快照、刷新器的新快照会推送到既有订阅、慢行情不阻塞 HTTP 或断开连接、手动刷新优先于常规刷新，并且失败更新不能清空最后成功值。Web 回归必须断言没有 `setInterval` 轮询、基础行先于 SSE 估值可见、断线后重连、刷新保持旧金额直到新有效值出现，以及更改币种/周期不会复用不兼容的旧金额。生产预览继续记录基础行的 1 秒门禁；估值展示改为“收到首个可信 SSE 快照”而非硬编码 2 秒承诺。

#### 3.3 当前估值快照优先，周期行情后续补齐（2026-08-12）

反馈复现表明，完整阶段虽然可在 2 秒内返回当前单价和市值，但所有近 24 小时盈亏为空。直接根因是服务先串行等待当前行情批次，再开始逐个读取周期起点行情；两类行情争用请求级截止时间，周期计算在发起历史查询前即返回未知。迁移至无请求级总截止时间的 SSE 刷新器后，实际浏览器复测又发现：同一 upstream 客户端同时发起历史与当前批量读取时，当前行情的首份可见快照仍会被历史任务拖慢。

完整 JSON 兼容读取仍可并行预取周期起点行情；SSE 刷新路径则先完成有界的当前行情批次、当前估值与汇率转换，并立即发送不含周期盈亏的首份快照，再开始有界并发的周期起点行情预取。这样首屏当前单价、市值与浮盈亏不会与历史报价争用 upstream 容量；随后快照按既有资产流量公式补齐每个标的和总览的周期盈亏。任一必要报价、汇率或时间序列不可用时，相关结果仍为未知，且绝不伪造 `0`。有界守护 worker 不得阻塞 SSE 连接、应用关闭或后续刷新周期。

#### 3.4 报价时间与交易时段（2026-08-12）

行情元数据与金额分开建模。`ProviderTick` 保留数据源返回的 `observed_at`，并增加 `quote_session`：`pre_market`、`regular`、`post_market`、`overnight` 或 `unknown`。`QuoteResult`、`PortfolioPositionDTO`、SSE/JSON 序列化和前端 `PortfolioPosition` 分别透传为 `quote_observed_at` 与 `quote_session`。只有数据源明确给出的时间和时段才能进入合同；本地请求/刷新时钟只用于超时和新鲜度判断，不能伪造报价时间。

当前持仓不增加全局更新时间卡片或新表格列。当前单价单元格在价格下方显示一行小字：前端用浏览器当前时间减去数据源 `quote_observed_at`，显示“报价于 x 小时 y 分 z 秒前”，并追加“盘前 / 盘中 / 盘后 / 夜盘 / 时段未知”。只显示实际非零的时间单位，时间差不足 1 分钟时显示秒，时间缺失或无效显示“报价时间未知”。当前 SSE 刷新器持续按活跃订阅刷新，因此没有额外的全局“收市后一次”定时器；若后续启用独立的收市后补价阶段，刷新器必须按标的市场与其常规交易收盘边界各执行一次，不能把美股、港股、A 股、台股、日股、韩股等套用同一时刻。补价若来自盘后或夜盘，必须原样标注其时段。

yfinance 批量读取若能从盘中序列取得带时区索引，使用该索引作为报价时间并按市场时段推导标签；若批量响应没有可验证时间，则报价时间为空，不回退到 `clock()`。Yahoo chart、Cboe、Nasdaq、Finnhub 等备用源继续使用其响应中的时间，并在可确认时映射交易时段。刷新合并与 SSE 断线重连将报价时间和时段视为价格的同一有效字段，失败时成对保留。

### 4. 证据详情实施最小披露

详情只返回正式业务字段和可核对的业务事实。工作区在 Application Service 与 persistence adapter 两层校验；内部代理键、凭据、认证头和不相关原始隐私不进入 Web 响应或日志。前端把事件与关联记录中的事实合并为一张连续详情，并按业务含义去重；用户看到事件类型、时间、账户、资产变化、必要的现金账户和备注，不看到内部关系、来源行快照、导入渠道名称、“资金流向”或“更多信息”等数据分组标题。

### 5. 金额和时间复用既有合同

金额、数量、成本、单价、市值和表现指标沿 API 边界使用十进制字符串。当前浮盈亏使用均摊成本法：`current_value - total_cost`；浮盈亏率使用 `profit / abs(total_cost)`，负成本仍保持正负方向直观，成本为 0 时比率为空。合并持仓使用数量之和与总成本除数量得到均摊成本，不改变任何账本事实。

精确传输与紧凑展示是两个边界。API、筛选、排序和前端状态保留原始十进制字符串；投资事件列表和详情只在渲染时使用字符串算法格式化，最多展示 8 位小数、按第 9 位四舍五入、删除小数末尾的 `0` 并增加千分位。该过程不得经过 JavaScript `Number`，不得改写响应、参与账务计算或反向保存。币种与标的代码在显示时转为大写；极小非零值四舍五入为 0 时显示 `≈0`，避免把非零事实伪装成零。

当前持仓页的单价、数量、市值、浮盈亏及总览金额属于更高频的表格读数，生产展示层最多保留 2 位小数并按第 3 位四舍五入，同时继续使用字符串算法和千分位；这只影响渲染文本，不改变 API、前端状态、排序或任何盈亏计算。整数不强制补零，避免数量和大额整数出现无意义的 `.00`。

周期表现使用统一的资产流量口径。总周期盈亏为 `期末资产总额 - 期初资产总额 - 外部入金 + 外部出金`；买入和卖出仍包含在两个资产总额中，不作为外部资金流扣除，因此总额同时包含未卖出部分的浮盈亏和期间卖出/清仓形成的已实现盈亏。单标的周期表现为 `期末市值 - 期初市值 - 期间买入支出 + 期间卖出净收入 + 投资收入 - 相关费用`；同一标的完全卖出后不进入当前持仓表，但仍进入总周期盈亏。期间比率使用带时间权重的投入基数，避免把期间资金移动误计为收益；不单独返回或展示已实现盈亏指标。周期边界按浏览器本地时区转换为 UTC，滚动周期使用精确时长。

#### 5.1 周期内投资快照是不可倒放的记录基准（2026-08-12）

`snapshot` 是某一时刻确认的余额或持有数量，并不是带有现金部分、成交价和完整历史的交易。若所选周期内某账户/标的存在快照，服务必须选取该键在期间内最后一条快照，以它的发生时间和确认数量作为该键的记录基准；不得通过“当前数量减期间变动”推导该快照前的数量。期初报价请求改为读取基准时间的报价；该标的的买入、卖出、投资收入和费用只累计基准之后的事件。快照为零也有效，允许表示从零持仓开始的后续表现。

完整组合仍可返回由可观测资产组成的期间金额，但跨资产的基准时间不再一致，外部资金流也可能早于某个记录基准。因此只要期间内使用了任何记录基准，总周期盈亏率必须返回未知，不能给出看似精确的百分比。API 在组合和每个受影响持仓上返回账户、标的和记录发生时间；Web 在周期总览下以小字列出实际时间并提示“可能无法反映真实盈亏”，受影响持仓行同样标出自己的基准时间。这个提示只解释记录完整性，不更改原始快照、持仓、买卖或外部出入金的事实。

后端时间携带明确 offset，浏览器按本地时区展示，并把本地日期筛选转换为 UTC 区间；页面不使用 JavaScript 浮点重算账务结果。

### 7. 用户界面文案与内部语义隔离

用户界面采用“短标签 + 结果 + 动作”的表达：表格标题、状态、按钮和错误提示优先使用日常词汇；只有用户主动打开详情时才展示必要的核对字段。空状态和错误状态各保留一条能指导行动的短句，不在页面上解释数据模型、重建过程或规则实现。

同一审查范围包含投资账本和共享的收支详情抽屉。收支页中的“关系投影”、投资页中的“关系影响 / 来源行快照 / 导入渠道 / 已配对”等词都不得出现在渲染后的用户界面；内部命名只允许留在代码、API、测试和 OpenSpec 设计记录中。

### 8. 持仓合并与总览口径

持仓查询先产生按账户、标的和成本币种区分的原子持仓，再由 Web 读模型按展示偏好分组。分开展示保留账户维度；合并展示按标的合并，数量相加、总成本相加、均摊成本为总成本除总数量，当前市值和当前浮盈亏重新计算。成本币种不一致的分组不可合并，避免隐式汇率造成虚假成本。内部仍称“均摊成本”，用户界面使用“平均成本”。

总当前浮盈亏额只汇总投资标的；总当前浮盈亏率的分母仍是投资标的市值和现金市值之和。原币种模式下跨币种不做加法，按币种分别返回总览；统一换算模式先用明确汇率折算，再生成单一总览。仓位是独立的 USD 归一化读模型字段：后端为每个持仓及现金计算 usd_market_value，前端以该字段汇总 USD 分母并计算仓位，不受页面当前展示币种影响；汇率缺失时保持未知。总览只保留“总浮盈亏”“当前总市值”“近 24 小时浮盈亏”等指标名称及对应数值，不显示“含现金”“投资标的 + 现金”或更新时间卡片。

### 9. 周期表现数据流

表现查询需要两个边界快照和期间流水：期末使用当前实时价格，期初使用目标边界最近可验证价格和当时的持仓数量；期间投资买卖按发生时间进入单标的投入基数，`funding` 事件进入总资产资金流，账户间成对转移在总额中自然抵消，不作为收益。行情源不能提供边界价格时，表现查询失败并说明需重试，不伪造 0 或把当前价格冒充历史价格。

优先复用既有估值观察和财富日结果的工作区隔离、精度与来源语义；新增的实时边界查询只读，不新建账本记录，不修改历史观察。24 小时周期使用 `now - 24h`，本周至今、本月至今和年初至今使用本地自然边界，30 天、90 天和 365 天使用滚动时长。

### 10. SSE、刷新器和失败恢复

SSE 只更新当前持仓及表现，不重复请求投资事件分页。浏览器使用 `visibilitychange` 控制连接生命周期：可见时建立 SSE，不可见和卸载时关闭，恢复可见时重连并请求一次优先刷新；不得使用 `setInterval` 或定时 HTTP 拉取。手动刷新只向刷新器发出优先请求，按钮在等待下一份快照时旋转，不显示更新时间或下一次刷新说明，`prefers-reduced-motion` 下改为静态忙碌状态。首次没有缓存且刷新器失败时显示失败态；已有成功数据之后的失败保留最近快照并在总览附近显示短错误和重试动作。`EventSource` 负责网络断线重连，服务端用事件版本只发送更新后的快照。

### 11. 周期浮盈亏边界

总览按“总浮盈亏 → 近 24 小时盈亏 → 当前总市值”排列。持仓表格只展示结果，不增加解释句；周期表现继续使用期初与期末资产值并扣除外部出入金影响，合计仍包含已卖出和仍持有部分的盈亏，但不拆分展示二者，也不为独立已实现盈亏预留用户界面字段。

## 风险与缓解

- [逐行关系查询] → 只按当前页批量读取关系摘要，并以查询计数回归约束。
- [行情失败阻塞页面] → 事件与持仓分离；持仓以整体成功/失败呈现，已有成功快照在轮询失败时保留，下一周期继续重试。
- [周期边界价格缺失] → 只使用可验证的历史估值或行情边界，缺失时让表现查询失败并提供重试，不用当前价格或 `0` 代替。
- [首选证券行情源空响应] → 只对缺失标的触发有界、确定顺序的备用源链；首选成功不被覆盖，备用源均失败时如实保留未知，不把源请求时间伪造成价格观测时间。
- [负成本导致收益率符号反转] → 浮盈亏率分母使用成本绝对值，成本为 0 时返回空比率。
- [跨币种错误汇总] → 原始币种按币种分组；只有统一展示币种和可用汇率时才形成单一总览。
- [高频轮询重叠请求] → 页面可见性暂停、AbortController 和请求序号共同防止旧响应覆盖新响应。
- [周期指标被误拆分] → 规格明确返回包含浮盈亏与已实现盈亏的周期合计，不增加已卖出部分的独立指标或占位字段；用总资产快照校验总额，用单标的资金流调整校验行级归因。
- [标的筛选被通配符放大] → 在两个关系型后端显式转义 `%`、`_` 与反斜杠，并以 API 契约测试锁定字面量包含匹配。
- [用户文案重新暴露内部模型] → 建立用户可见字符串负向回归与新用户任务审查，指标定义留在规格和无障碍语义中。
- [证据泄露] → 工作区双层校验、字段白名单、脱敏日志和跨工作区安全测试。
- [分页漂移] → 游标绑定版本与筛选，变更后失败关闭。
- [前端精度丢失] → 十进制值保持字符串，只做展示格式化。
- [定长小数压垮事件表] → 使用包含 18 位小数、长账户名和长备注的真实形状夹具审查桌面列表；列表格式化不得改变 API 精度，数值不得按字符任意断行。
- [机械展示两侧资产] → 测试交易双侧、收入/费用/出入金单侧、现金/持仓快照和零手续费；界面按经济效果选择一侧或两侧，不显示结构占位。
- [数据库行为分歧] → 同一 Application Service 在 SQLite 与真实 PostgreSQL 运行契约矩阵。
