# 设计：投资账本浏览 Web

## 上下文

现有 Web 已提供收支账本，投资领域已有统一事件、关系、持仓与估值能力，但没有投资账本页面。旧 Spec Kit 草案只包含占位验收，且曾被错误写入主规格；当前实现任务仍为 0%。本 change 是未来实现的唯一规划事实源，原始草案继续保存在 `legacy/022-investment-ledger-browser-web/`。

## 目标与非目标

目标是通过只读 API 和 Web 页面连接投资事件、关系证据与当前持仓，同时保持精确金额、工作区隔离、时间和双后端合同。非目标是创建或修改投资事件、改变估值、重新扫描关系、增加数据库字段或把行情失败扩散到事件浏览。

## 设计决策

### 1. 使用独立 capability，不提前创建主规格

delta capability 为 `investment-ledger-browser`。完成实现、审查、验证和归档后才创建 `openspec/specs/investment-ledger-browser/spec.md`；当前主规格不声明该能力已经存在。

### 2. 投资事件和当前持仓使用两个读模型区域

事件区域回答“发生过什么”，读取规范投资事件、关系摘要和来源证据；持仓区域回答“现在持有什么”，复用 `portfolio-valuation` 的数量、成本、行情、折算和覆盖状态。页面不得通过持仓变化反推或伪造事件。

### 3. 查询编排保持只读和有界

Application Service 先按工作区、筛选和稳定排序读取一页投资事件，再按该页事件 ID 批量读取关系摘要。持仓及行情通过一次共享有界预算查询；行情局部失败返回受限状态，不回滚或隐藏事件页。

分页游标绑定筛选摘要、排序键和事件数据版本。版本变化时旧游标明确失效，不跨版本拼接结果。

### 4. 证据详情实施最小披露

详情只返回正式业务字段、可核对来源信息和关系影响。工作区在 Application Service 与 persistence adapter 两层校验；内部代理键、凭据、认证头和不相关原始隐私不进入 Web 响应或日志。

### 5. 金额和时间复用既有合同

金额、数量、成本、单价和市值沿 API 边界使用十进制字符串。后端时间携带明确 offset，浏览器按本地时区展示，并把本地日期筛选转换为 UTC 区间；页面不使用 JavaScript 浮点重算账务结果。

### 6. A 类 UI 在实现前完成原型门禁

进入任务拆分与实现前，必须使用 Hallmark 在 `prototype/index.html` 创建可直接打开的原型，覆盖事件、持仓、筛选、加载、空、错误、行情受限和证据详情状态，并检查 320、375、414 和 768 px。当前尚未创建原型，对应任务保持未完成；原型评审通过前不得开始生产 UI。

## 风险与缓解

- [逐行关系查询] → 只按当前页批量读取关系摘要，并以查询计数回归约束。
- [行情失败阻塞页面] → 事件与估值分离，持仓逐项返回覆盖状态。
- [证据泄露] → 工作区双层校验、字段白名单、脱敏日志和跨工作区安全测试。
- [分页漂移] → 游标绑定版本与筛选，变更后失败关闭。
- [前端精度丢失] → 十进制值保持字符串，只做展示格式化。
- [数据库行为分歧] → 同一 Application Service 在 SQLite 与真实 PostgreSQL 运行契约矩阵。

## 发布与回滚

页面和路由在 API、双后端、生产预览、响应式与可访问性验证完成后一起交付。若发布后出现问题，可回滚 Web 路由和只读查询入口；本 change 不迁移或修改账本数据，因此不需要数据回滚。归档前必须同步 delta，并记录实际 `HEAD`、比较基线、命令和 finding。
