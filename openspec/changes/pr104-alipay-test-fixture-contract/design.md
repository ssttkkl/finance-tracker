# 测试夹具调整

## 背景

支付宝和微信来源行都必须包含有效平台交易单号。部分测试的目标是覆盖一般银行来源的弱身份、文件变化和候选保存，却沿用支付宝夹具并清空编号；另一些来源文档测试未给支付宝行设置编号。

## 方案

- 保留现有测试所验证的业务路径。需要无编号来源行的通用场景改用工行借记卡来源；涉及支付宝的场景继续使用支付宝来源。
- 来源文档测试夹具在编号未设置时，按文件标记和行序生成稳定且互不冲突的合成支付宝交易号。显式提供的值保持原样，以便无效值测试仍能触及校验。
- 不修改生产解析、匹配或暂存逻辑，也不改写性能测试。

## 风险与回滚

若合成编号相同，测试可能误覆盖重复流水路径；编号包含文件标记和行序以避免该冲突。回滚只需恢复本次测试夹具改动，不需要数据或部署操作。
