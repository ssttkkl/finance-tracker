## REMOVED Requirements

### Requirement: 财富变化满足可解释恒等式

**Reason**：用户决定退役当前财富归因后端；它没有对应的 Compose 页面，现有计算口径也不符合预期，后续将重新设计。

**Migration**：移除财富变化分解服务和计算实现，不提供旧能力的替代接口。未来方案需另行定义规格。

### Requirement: 不完整覆盖必须明确呈现

**Reason**：覆盖状态和缺失证据只服务于已退役的财富归因报告，没有独立客户端使用场景。

**Migration**：移除财富归因覆盖计算和查询。现金账本及投资组合估值继续按各自合同提供数据。

### Requirement: 趋势分桶使用规范时间边界

**Reason**：日、周、月财富趋势是已退役财富归因报告的一部分。

**Migration**：移除财富趋势计算与查询；不改变投资表现页面的周期盈亏合同。

### Requirement: 每个归因组成项可追溯

**Reason**：组成项与证据下钻服务于当前不再支持的归因报告。

**Migration**：删除财富归因组件、证据清单及相关查询数据；正式现金流水、投资事件与其来源信息保持不变。

### Requirement: 财富读模型可安全重建

**Reason**：财富读模型只用于已退役的财富归因能力。

**Migration**：移除财富读模型重建和发布流程，并通过后续数据库迁移删除其派生表及内容。账本、账户、投资事实和收支投影不受影响。

### Requirement: 双后端归因结果等价

**Reason**：不再提供财富归因服务后，两个数据库后端之间的归因结果合同不再适用。

**Migration**：移除财富归因专属的双后端运行时矩阵；其他持久化能力继续遵循 SQLite 与 PostgreSQL 等价要求。
