## Why

用户可以在当前工作区通过对话组合共享客户端操作来查账和记账。在同一段对话里，用户可以核对金额、打开已有流水详情，并决定是否写入账本。

## What Changes

- Web、Android、iOS 按已确认原型提供统一入口。宽屏侧栏展示原有功能导航和对话，窄屏通过抽屉访问。消息内展示查询结果、草稿、确认和写入结果，单笔流水详情复用现有弹窗。
- 首批只读工具为 `list_accounts`、`list_categories`、`list_transactions`、`summarize_transactions`、`get_transaction`。详情默认包含流水构成。首批写工具为 `create_transaction`，调用后展示可编辑的确认卡，等待用户决定。
- 所有已登录用户默认可在有访问权限的工作区使用助手。推理请求和工具续跑复用现有登录鉴权与工作区权限检查。服务端统一配置模型、系统指令和工具目录。首版沿用普通会话接口，不引入 AI 专用历史签名、调用凭据或服务端对话轮次校验。
- 对话仅保存在当前设备，按登录用户与工作区隔离。服务端统一配置模型和凭据。客户端在设备上保存消息、回复及重新展示所需的卡片和结果。服务端代理推理，仅处理本轮所需上下文；消息正文和工具结果不写入服务端数据库、日志或追踪系统。汇总、列表和详情调用分别返回筛选条件与合计、当前页、单笔流水及其构成。供应商留存策略按最终服务和配置核实。已确认的收支沿用正式账本的持久化流程。
- 用户在同一对话发送新消息时，若工具仍等待确认，先将该调用结为取消，再将新消息原文追加为用户输入，一起交给 agent 继续处理。输入但尚未发送、切换对话或离开页面均不表示取消。
- 点击确认时按卡片最终字段调用共享客户端写操作。已接受的确认沿用原操作身份查询收据。确认与新消息并发时只能有一个动作结束等待状态，已结束的卡片不能再次批准。
- 首批范围聚焦收支工具。跨设备对话同步、从其他页面带上下文唤起、投资工具与导入工具留待后续设计。首版暂缓按用户用量限额，包括每日 token 预算、请求频率和并发配额。

## Capabilities

### New Capabilities

- `shared/ledger-assistant` 规定对话入口、本地历史、工具结果、待确认操作和继续输入的行为。

### Modified Capabilities

- 复用 `shared/client-operations` 的工作区、权限、财务写入与恢复合同。

## Impact

涉及共享 Compose 导航、对话与本地状态、共享客户端操作适配及服务端模型接入。按 A 类设计和验证。A2UI 渲染器候选为 uny/a2ui-compose 0.3.0，已通过独立三端编译与 Web 编辑确认验证。Agent SDK 的中断与恢复仍待验证。交付验收需覆盖取消并追加输入、同设备重启、确认和发消息并发，以及已写入但响应丢失的恢复。回滚入口时须保留已授权写入的收据与恢复路径。
