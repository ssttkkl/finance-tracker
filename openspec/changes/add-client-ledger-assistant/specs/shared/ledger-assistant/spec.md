## ADDED Requirements

### Requirement: 助手提供当前工作区内的工具对话

客户端 MUST 在既有主导航的业务导航下提供新对话和本机对话历史，按用户及工作区隔离；服务端 MUST 使用现有鉴权代理推理并统一配置模型，仅处理本轮需要的上下文。客户端 MUST 通过共享操作查询账户、分类、流水列表、分币种汇总及含构成的流水详情。服务端 MUST 避免持久化聊天正文和工具结果。

#### Scenario: 使用原有导航切换对话

- **WHEN** 用户展开桌面侧栏或打开移动端抽屉
- **THEN** 客户端保留原有业务导航项，在分隔线下方显示不可点击的「账本助手」标题、新对话及本机历史，沿用现有导航样式、账号和工作区入口
- **AND** 选择新对话或历史时直接打开助手中的对应页面，移动端关闭抽屉；侧栏收起时可沿用原有展开动作访问分组

#### Scenario: 管理历史对话

- **WHEN** 用户从侧栏操作按钮、右键、长按或页头当前对话菜单发起操作
- **THEN** 操作只作用于目标对话。置顶和普通组各按最近活动排序，手动名称跨重载及新消息保留，早期历史继续使用首条消息名称
- **AND** 删除须明确确认本机移除且保留已记录流水，未授权草稿可一并删除，已授权在途、恢复或结果未知的对话禁止删除
- **AND** 删除当前对话回到空白对话，删除其他对话保留当前对话
- **AND** 宽窄屏页头右侧操作区依次为新建和当前对话菜单，页头新建和侧栏新对话使用同一动作，空白时不生成历史，当前无历史对象时隐藏页头菜单，输入框上方常驻核对提示

#### Scenario: 阅读多行消息和工具记录

- **WHEN** 用户输入带换行的消息并提交
- **THEN** 客户端保留原文换行，用户消息显示为右对齐且可换行的气泡，助手正文按所采用的跨平台组件渲染 Markdown/GFM，与业务卡共用同一内容列，超宽表格在本身区域横滚
- **AND** 客户端以真实顺序在对应位置显示次级工具摘要，点击在模态底部面板查看调用名、业务参数与结果或状态，排除凭据与内部提示
- **AND** 打开或关闭面板不读取账本、不请求推理、不授权写入，关闭后恢复对话滚动位置及入口焦点
- **AND** 已保存的工具结果在重载时保留，尚无结果的在途只读记录显示「已中断」

#### Scenario: 流式回复与中断恢复

- **WHEN** 用户提交消息
- **THEN** 本机保存原文后立即显示用户气泡及等待进度，收到可见文本时增量展示并收起进度；完整工具调用经校验才可执行
- **AND** 已显示正文后中断时保留部分正文，在正文下显示「回复中断」「重试」，重载保留状态且不自动请求
- **AND** 手动重试复用原用户消息，重新生成的正文替换未完成部分，不新增气泡

#### Scenario: 打开已有 Markdown 对话

- **WHEN** 用户打开先前保存且含 Markdown 的助手回复
- **THEN** 客户端直接根据原文呈现支持的 Markdown、链接和可访问的 HTTPS 图片，无需再次推理

#### Scenario: 从查询结果打开流水

- **WHEN** 用户点击查询结果中的一笔流水
- **THEN** 客户端打开已有流水详情，关闭后回到当前对话。

#### Scenario: 换设备或工作区

- **WHEN** 用户在另一设备或工作区打开助手
- **THEN** 助手只展示该设备、用户和工作区下的历史。

### Requirement: 写工具等待用户授权

新增收支工具 MUST 在对话内展示可编辑的确认卡，仅在用户明确确认后按最终字段提交。等待时发送新消息 MUST 取消该次调用，再携带用户原文继续推理。客户端 MUST 保留同一写操作身份和实际收据。

#### Scenario: 等待时发送纠正

- **WHEN** 用户在等待确认 38 元草稿时发送“改成 36 元”
- **THEN** 原卡标为取消，客户端将取消结果和用户原文一起交给 agent，新的写请求仍须确认。

#### Scenario: 直接取消待确认草稿

- **WHEN** 用户在待确认卡片上点击「取消」
- **THEN** 客户端保留原卡并显示「已取消」，账本不写入
- **AND** 用户在同一对话发出下一条消息时，客户端把该工具的取消结果和新消息一起交给助手

#### Scenario: 修改后确认并丢失响应

- **WHEN** 用户在卡片输入 36 元，确认后客户端在收到响应前退出
- **THEN** 客户端在重启后核实原提交，账本至多新增一笔，只有已确认的账本结果才能显示为已记录。

#### Scenario: 取消草稿后发送消息但回复丢失

- **WHEN** 同一对话的原卡已取消，新输入已保存，推理请求中断且设备未保存回复
- **THEN** 原消息气泡下方 MUST 右对齐呈现错误色「未送达」及加粗且可操作的「重试」，恢复网络或重新打开应用时 MUST 保留此状态
- **AND** 用户点击「重试」后 MUST 沿用原消息重新请求推理，保留卡片取消状态，不重复提交账本写入。重试进行中及送达后隐藏状态行，重试不新增用户消息
