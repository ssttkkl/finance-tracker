历史列表在每条对话上提供同一个 M3 菜单。桌面悬停或键盘聚焦显示操作按钮，右键可直接打开。移动长按可打开，选中行常显操作按钮。菜单仅作用于触发行。置顶与普通分组分别按最近对话活动排序，支持多条置顶。重命名仅改变列表名称，原消息与对话页标题保持原样。删除需确认从本设备移除对话，已记入流水保留。已授权写入在途、恢复或结果未知时应用层与持久层共同阻止删除，按版本删除避免迟到更新复活。
对话定位沿用 AppRoute。空白页使用 `/w/{workspace}/assistant`，已保存对话使用 `/w/{workspace}/assistant/{conversationId}`。首次消息保存后进入具体地址，历史切换和新建进入已有导航栈。刷新、浏览器前进后退及登录恢复按当前账号／工作区的本地历史解析。加载完成前保留目标地址。浏览器在仍有权限的工作区之间恢复地址时，沿用工作区切换及加载状态，切换完成后才读取本机目标工作区。确认缺失或删除后替换为新对话地址。页面背景使用配对的 FinanceTheme 前景角色。

宽窄屏页头左侧保留导航与标题，右侧操作区依次为新建对话和当前历史的同一个菜单。窄屏保留抽屉，空白对话隐藏菜单，新建不写入空历史。对话已有保存的消息时，输入框上方固定显示「AI 可能会出错，请核对重要账目信息。」。空白新对话及仅有未发送输入时隐藏提示且不留空位，首条消息保存后即显示。分享、锁定、项目和归档不在此变更范围。

## 流式发送与中断

输入框首行采用紧凑胶囊形，发送与输入同一行，多行自然增高至六行。原文写入本机后，客户端立即显示气泡并清空输入，气泡下用细线性进度指示等待。第一个可见正文或待处理卡片到达后收起进度。后端通过 SSE 透传可见文本，按顺序组装并校验完整工具调用后才交给 Koog，不转发推理过程。客户端仍由 Koog 管理回合和原工具身份，流式执行器只将完整校验结果返回给框架。
首段回复前失败在用户气泡下显示「未送达」「重试」。已有可见正文后流中断，保留已显示部分，「回复中断」「重试」在对应助手回复下呈现。手动重试复用原用户消息，新正文原位替换未完成部分。重载保留未完成状态，不发起推理；已有工具结果、待授权及已授权收据保留既有语义。
## 数据流

客户端按账号、服务地址与工作区加载本设备历史。客户端 agent 通过现有鉴权访问后端推理代理，后端持有模型凭据、工具目录和系统指令。服务端不持久化聊天正文、草稿或工具结果，沿用工作区权限；模型不可用时返回可识别的服务异常。模型调用目标与凭据通过服务端配置注入。上线前核对所选供应商留存策略。

只读工具适配共享操作层的账户目录、分类目录、分页流水、按月分币种汇总及详情。列表返回客户端可解析的行引用，详情同时返回当前行和组成记录。工具参数保留金额精度、时区和筛选条件。仅把本次工具调用所需的结果回传。打开详情是宿主动作。

## 写入与本机恢复

工具请求创建稳定的本机调用身份，保存草稿并展示卡片。用户编辑字段只更新本机草稿。确认与取消竞争同一等待状态，只有成功结束等待的一方生效。确认前复核当前会话、权限和草稿版本，使用最终字段执行共享写操作。在首个外部副作用前，确保工具调用和原写操作身份之间可恢复。后端仍负责最终鉴权和落账。用真实收据恢复 agent；响应丢失时接续原操作。 新增收支沿用原记账命令的永久收据。成功收据保留实际收支记录 ID，供对话内打开详情；历史收据缺少该字段时只显示已记录。

等待期间在同一对话发送消息时，将取消结果和原文输入作为一个本地状态变更持久化，按工具结果、用户输入的顺序一次交回 agent。退出或切换对话保留等待状态。确认后发送的新消息保留在当前会话，待结果核实后处理。写操作逐个等待授权。已取消、已确认及恢复中的卡片不得再次发起同笔写入。

## SDK 与技术验证

A2UI 候选锁定 uny/a2ui-compose 0.3.0 的协议格式。首批注册查询结果、可编辑草稿及结果组件，只有宿主可把用户动作绑定到待确认写请求。独立工程通过 Android、iOS 两个目标与 wasmJs 编译；浏览器验证输入 38 改 36 后确认回调为 36。临时工程曾手工解压校验过的空资源包，正式构建仍须验证标准资源解析路径。

拟用 Koog 1.3.0 客户端工具循环。agents-core 与 agents-features-snapshot 均发布 Android、iOS 与 wasmJs 变体。上游 RunFromCheckpointTest 覆盖从已完成图节点之后恢复。不得依赖正在工具内挂起的协程跨进程存活。首个实现步骤用确定性模型响应和真实 SDK 验证持久化工具请求后重建 agent，并分别回传修改后的收据、取消结果及新输入。用独立进程或重新装载的网页验证，记录模型请求次数与写入次数。失败则回到此设计比较 SDK，不自建推理循环。

Koog 1.3.0 在独立 JVM 进程中可以从已完成的模型节点恢复原工具调用。退出后取消并追加用户原文，正常续跑只发送一次请求。已提交但响应丢失时，临时 SQLite 账本可按原调用身份读回收据，只有一笔 36 元记录。

发送或续跑中断且设备未保存回复时，「未送达」与「重试」在原消息气泡下方右对齐。两者使用 M3 error 小字，重试加粗并可键盘或触控操作。重试进行中和送达后隐藏。重启或重连保留此状态，只有用户点「重试」才再次请求推理。重试复用原消息，保留原卡的取消决定；同次重试在途时防止重复点击。已经提交的记账按原操作身份核实收据。

## 内置技能运行时与附件

用户已确认 `c260f656` 的[运行时设计](skill-runtime-design-draft.md)，其中的产品范围、授权与中断恢复适用于本变更。按 A 类验证跨端运行时、只读账本边界、版本协商和附件事务。先用发布制品在 Web、Android 和 iOS 验证异步账本读取、相同 CSV 字节、受限执行及中断后的恢复。制品差异和参数以实测定案，再接入产品。

推理请求继续接受旧消息数组。具备本机运行时的客户端才发送包含 `messages` 与 `capabilities: ["assistant-skills-v1"]` 的对象。服务端拒绝未知能力和自定义工具定义，两种响应模式按同一协商目录校验。新工具字段为 `read_skill(skill_id, resource?)`、`run_script(code, input?)` 和 `send_file(file_ref)`，其中 `input` 为可选 JSON 对象。

应用适配固定原生 `quickjs-kt 1.0.19` 和 Web `quickjs-emscripten-core` 标准同步 Wasm `0.32.0`。每次调用创建独立上下文，Web Worker 仅在运行时加载。共享桥按调用次序派发，最多 1024 次，返回时仍有未等待的宿主调用则整次失败。跨桥前检查字节大小，宿主入口再次检查；Web 保留一个在途请求。两端运行与等待共用 10 秒截止，JS 堆上限 32 MiB。

只读宿主使用既有本机账本的分页、汇总和详情证据。脚本桥以十进制字符串承载账本版本、账户 ID 和记录版本，避免 JS 对超出安全整数范围的值舍入。分页向本机查询传入固定版本，正式输出提交前再次检查同一作用域和版本。 同一条用户消息重新执行时，规范路径和文件字节相同会得到同一文件版本，允许收据丢失后复用已经发出的附件。工具参数按 JSON 对象键规范化比较。CSV 沿用本机分隔文本解析，按 UTF-8、CRLF 和显式引号导出。

附件 UI 建议保留三个信息层级。聊天内容列仅增加对应工具行和文件卡，卡显示文件名、格式、大小及预览入口。预览对话框处理单一文件，CSV 限制表格预览行列，文本原样展示，导出由可见按钮触发。空白对话、导航、输入区不增入口，不展示文件内部引用。Hallmark 预检保留单列阅读节奏，去掉技能介绍、重复文案和第二层卡片。已用 Chrome 阅读 Material 3 Cards、Dialogs、Buttons 的 Overview／Specs，采用默认 OutlinedCard、单任务对话框和默认按钮尺寸。项目现有 FinanceTheme 供应色彩与排版。验收用宽窄屏检查文件名、工具与卡片顺序、无网络预览、系统保存／浏览器下载和退出后定位。
