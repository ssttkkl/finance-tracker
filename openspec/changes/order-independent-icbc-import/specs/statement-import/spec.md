## MODIFIED Requirements

### Requirement: 导入账户由来源行和映射规则解析
账单导入 MUST 根据来源行中的支付方式、账号、卡号、账户产品档案或明确映射规则解析目标账户。对于工行借记卡 PDF，来源账户身份 MUST 使用来源表格的本方账号字段；对于工行信用卡 PDF，来源账户身份 MUST 使用交易卡号或账单明确声明的本方卡号字段。来源 PDF 明确提供前缀/尾号掩码时，该掩码可作为稳定来源身份。交易渠道只能作为该流水的业务字段，不能作为来源账户身份。完整或稳定掩码来源标识只能作为受控内部身份，映射证据 MUST 脱敏展示；缺少稳定来源标识时 MUST 失败关闭，不得退回尾号或交易渠道，也不提供历史工行身份兼容回退。通用导入命令 MUST NOT 依赖调用方提供一个覆盖整份多账户账单的 `--account` 参数，且导入与转换流程必须使用相同的账户解析语义。

#### Scenario: 多支付方式账单
- **WHEN** 一份支付平台账单包含映射到不同账户的业务行
- **THEN** 一次导入 MUST 将各行分别写入对应账户，不得把整份账单强制写入同一账户

#### Scenario: 工行信用卡同卡多渠道流水
- **WHEN** 工行信用卡 PDF 的多条流水具有相同交易卡号但交易渠道分别为快捷支付、网上银行或手机银行
- **THEN** 系统 MUST 将这些流水归入同一个来源账户映射组，并保留每条流水各自的交易渠道

#### Scenario: 工行借记卡同账户多渠道流水
- **WHEN** 工行借记卡 PDF 的多条流水具有相同本方账号但交易渠道分别为快捷支付、网上银行或手机银行
- **THEN** 系统 MUST 将这些流水归入同一个来源账户映射组，并保留每条流水各自的交易渠道

#### Scenario: 工行信用卡多卡文件
- **WHEN** 一个工行信用卡来源文件包含不同交易卡号的业务行
- **THEN** 系统 MUST 按交易卡号分别生成来源账户身份并要求分别映射，不得按交易渠道合并或拆分

#### Scenario: 工行借记卡多账户文件
- **WHEN** 一个工行借记卡来源文件包含不同本方账号的业务行
- **THEN** 系统 MUST 按本方账号分别生成来源账户身份并要求分别映射，不得按交易渠道合并或拆分

#### Scenario: 账户无法唯一解析
- **WHEN** 一个业务行无法从受控来源字段和映射规则唯一解析到账户
- **THEN** 系统 MUST 失败并说明缺少的映射证据，不得根据自由文本猜测账户
