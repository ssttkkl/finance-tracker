## 测量与覆盖

以 `compose/client-operations/perf/budgets.json` 定义操作 ID、公开签名、场景、正确性、采样和预算；从 Kotlin 编译接口核对公共方法、嵌套类型、重载与顶层入口。DTO、宿主 SPI 和内部协作符号在清单明确归属。使用可复用夹具与断言，漏登、漏跑或错误结果阻断。业务测试照常保留。

固定 GitHub 托管 Ubuntu 26.04 x64、Node 26.13.1 和 JDK 21。以 Kotlin/JS 生产产物运行，用温机五次预热和 30 次独立采样的 p95 判断短操作。写入使用等价初态。轻操作从调用到结果就绪，纳入该入口实际需要的磁盘、网络和序列化。冷 CLI 单独用新进程、实际 npm 安装包测量。最大场景每阶段记录单次墙钟和独立客户端 RSS。构建在测量前结束。所有样本与夹具摘要、版本和镜像随运行上传。预算以用户确认值为准，超标不得自动改预算。

## 操作性能门禁与请求性能门禁

操作按公开业务入口、场景和负载判定。所有操作分别登记墙钟与客户端峰值 RSS 预算，普通场景也须实测内存。温机采样固定预热与输入，在隔离进程测量操作区间的峰值，冷 CLI 从进程创建量到输出就绪。进程生命周期和采样方法随报告保存。操作可以纯本地执行，也可以关联多次请求。默认导入确认以完整收据和结果整理完成为结束，19 文件预算为 60 秒及 512 MiB。`--no-wait` 另测持久受理结果。

请求按 HTTP 方法、路由模板和负载分别登记。第一期覆盖现金导入实际使用的远端文件解析、账本快照、需要的账户操作、写集上传与受理、状态、取消、收据、分页和恢复。用独立取消或恢复场景验证正常成功路径上未触发的请求。每次轮询、重试、分页单独记录，可按操作及请求序号关联。报告不保存正文、凭据及真实业务标识。

服务端从开始接收请求量到完整响应写完，客户端另记从发起至读完的耗时。按下表逐次执行服务端墙钟上限，同时保留各次最大值。实际传输正文按字节累计，压缩请求另计解压后的大小；原有写集 64 MiB 容量合同仍适用，无正文状态查询为 0 B。

在独占且已预热的后端进程串行回放相同负载，记录请求前内存、区间峰值与增量。Linux 以独占 cgroup v2 的内存计费高水位覆盖服务进程及解析子进程，包含内核与页缓存计费，每个请求通过同一文件描述符重置并读回，按内核页记账。客户端、代理、PostgreSQL 和隔离回放的后台执行进程各在测量组外。内存预算按路由和负载单列，报告注明测量单位、进程范围和夹具。异步执行与查询重叠的场景另记服务整体峰值，并实际验证并发时的单请求耗时。独立回放不能替代真实整批路径。先按产品操作和固定负载确定预算，再用五台独立托管执行机验证同一提交。原始分布用于定位超限和验证改进；调整预算需独立的产品或负载依据并经用户确认。采集缺失、无法识别的范围内请求、业务断言失败或任何一层超限，固定检查均失败。

## 固定资源预算

## 快照与原键收据分页

用户确认 19 文件的原快照和按键原收据继续提供旧表示，并允许 CLI 协商分页。旧合同的解压正文实测为 60,381,687 B 和 3,210,974 B。服务在成功核验会话时用 `X-FT-Read-Pages: 1` 宣告能力。新版 CLI 按同一次已核验会话选择明确的 GET 路径 `/api/v1/ledger/snapshot/pages` 和 `/api/v1/cash-import/write-set/receipt/pages`。已有快照、按键收据、流水页和关联页保留。会话没有宣告能力时沿旧读取；选择分页后的权限、业务 404 和跨页失败不切换表示。当前生产候选的门禁要求确实使用分页。

分页使用按原顺序排列的事实集合或收据集合、集合偏移及下一位置。每个集合声明同版本的总元素数，客户端验证实际消费数量、终点及集合顺序。快照页含当前工作区、账本版本、规则版本和分类目录修订；同一读取事务核版本及事实，后续页必须匹配首次固定的版本。原收据页携原工作区、收据 ID 和提交版本，以 Bearer 与原键核读取所有权，每页复核会话及授权。收据概要及写集身份列表沿原字段语义，不能用流水及关联结果页推算。分页正文按实际 UTF-8 编码及完整包络裁切，包含多字节字符与转义。超过目标页长的单个元素按原 JSON UTF-8 字节继续分页，片段包含元素偏移、字节偏移、总字节数和 Base64 内容；客户端仅在该元素完整且严格解码后接纳。分页先校验完整 UTF-8 正文，再独立协商 gzip 或 identity。服务在发出前核实实际编码长度，客户端核编码长度并边读边约束解压正文。当前 identity 实装对照表明，新页累计传输由约 3.96 MB 增至 60.42 MB；同一合成账本复验 gzip 的单页与整次实际传输、墙钟和 RSS。快照和按键原收据每页分别上限 32 MiB 和 2 MiB，实际传输和解压分别校验。

服务端复用原快照查询映射及排序，以数据库有界窗口读取；按键收据复用现有永久收据及读取权限，PostgreSQL 只把本页字段和项目交给服务 JVM。 对照真实 19 文件收据，页元数据查询曾反复分析 PostgreSQL 内同一个压缩 JSON 字段。读取一次有界持久收据后，按原顺序抽取其顶层字段分别校验账本版本、空值、正文集合和页计数。保留精确 JSON 原始值、旧数据校验、原读事务和授权，重复字段按原 PostgreSQL JSON 提取次序处理。诊断单列数据库缓冲块命中与请求 cgroup 测量。客户端逐页验证版本、身份、位置和终点，解码为既有类型并丢弃已消费的正文，发布一个完整对象。CLI 保存账本时按类型集合分批编码到原 AES-GCM 信封，完整 JSON 文本无需同时驻留。旧版继续读取同样的加密状态，保存遵循会话、作用域和缓存代次围栏。失败时丢弃本次未完成对象；失权仍清理原工作区的离线材料。分页 body、原收据和所有成员保持同数据逐字段可对照。

隔离回放和真实安装包按每页保留压缩前后字节、服务端和客户端耗时及适用内存峰值。跨页失败回归覆盖断线、重复、缺失、错误位置、工作区及版本切换、原收据身份变化，验证缓存原子发布与原唯一收据。现有 19 文件、普通夹具、各次和整次预算保持同一标准。读取协议变更独立审查，无 UI 影响。

## 现金导入正文体积分布

在相同合成 19 文件上，于暂存内存中归集冻结写集、账本快照和原收据的实际未压缩字节。报告保留集合或字段字节、占比、重复数、实际消费入口及单页和累计传输。源数据、对象内容、令牌和业务标识不写入证据。结合状态、单页、确认至完整结果、按键恢复及离线初始同步验证字段依赖。候选表示需在相同写集、原收据、逐成员及离线结果下比较体积和进程峰值。任何超出兼容读取分页的语义取舍另需用户确认。

## 已归档结果读取

结果和原收据归属于原工作区，读取时沿用已校验会话及工作区边界。已归档或已持久保存原收据的读取不依赖当前账本快照。读取一页时保留完整归档验证、服务器项目先于本地项目的顺序、逐成员身份及原分页边界。验证以同一合成归档对照 CLI JSON、读取字节数、分配和进程峰值。恢复已冻结提交时，先验证原用户、当前工作区与所存批次，按原键查状态和完整收据及分页。恢复入口仅在批次仍可编辑，或原键明确报告基线失效而需要重算时读取账本快照。提交原冻结正文仍由服务原子校验基线与规则，保留原收据持久保存、缺页时的离线结果和权限判定。只读请求遇工作区拒绝时复核当前会话，撤权清理原工作区离线材料，单纯切换活动工作区则保留。同一 3,000 行已提交控制批次实装恢复曾额外下载 13,578,476 B 的完整快照，以该缓存副本及同一原收据复验消除读放大。

## 已核对项目读取

同一账本版本与规则下，已完成核对的批次可用原文件捕获、选择与身份重新读取展示计划。分页、单条及处理状态均沿同一展示规则与稳定 ID，无需读取或构造写集。版本变化、历史上下文缺失或批次已冻结时，沿原核对入口处理。正式核对和确认仍计算并核实完整写集。只读路径保留时间区域校验和会话围栏。

本地核对只复制需要改写的行及操作外层，并在构造写集前释放内部预览图。对外快照继续复制调用方提供的数据。

## 本地账本缓存读取

安装包从同一 SQLite 事务读取完整账本缓存并认证成功后，可以在作用域和行包装密钥均未变时复用同一个解码结果。复用使用弱引用，不增加账本留存。缓存保存仍比较会话、工作区与原代次，且更新后清除观察；检查点释放原数据库锁前同样清除。若包装密钥、事务或工作区变化，读取并认证最新整行。分页与原加密格式保持原读取和跨进程兼容合同。

## 本地加密状态写入

CLI 加密状态沿原 AES-GCM nonce、认证标签、密文顺序与关联数据合同读写。解密先完成认证再交付结果。由 SQLite 返回的密文字节以视图读取，认证后的连续明文直接交给现有解码，不再构造整块复制。写入仍一次构造完整加密信封并使用原事务和原键检查点。确认首次冻结时，在原 SQLite 写事务内核同一批次和核对正文版本，可复用已认证的解码值；仍在检查点前持久保存完整原状态。同一连接重新取得写锁后，若有其他连接写入，重新读取并验证完整状态。否则只对同一槽、同一状态版本的一次紧邻读取复用刚保存的值。旧缓存、提交响应丢失和重新打开仍读取已持久状态。

大冻结正文是原加密状态中的字符串。宿主用原生 JSON 读取和封装该字符串，业务元数据仍沿原类型解码。元数据中的数字沿原数词精度保留。保存的状态仍使用同一 JSON 字段、授权范围和加密事务，供旧包按原键恢复。旧格式或无法安全提取的状态沿原读取入口。

大段状态文本按 Unicode 字符边界分块编码并加密，直接写入一个连续的原格式信封。SQLite 在原事务中保存加密值。小型状态沿现有加密入口。

首次冻结时先按 JSON 转义与 UTF-8 字节规则计算所需信封大小，再将原请求字符串的转义正文和 Kotlin 元数据逐段写入同一加密信封。旧版本仍能读到相同的字段和完整正文，无需拼出整份待加密的 JSON 文本。

## 安装包归档结果的输出

安装包的确认、恢复和归档读取继续输出相同 JSON 字段、原收据、精确标识字符串以及同一结果页。确认与恢复沿原合同核验全部结果。完整归档可在保存原批次的同一 SQLite 事务生成独立的加密读取记录，保留旧版可读的原批次与原结果。读取记录只从已验证的原收据、结果项与本地省略项派生。旧格式、临时结果与旧包改写批次后沿原完整读取。

读取记录包含结果计数、原文本摘要、原收据的等价机器表示及按序分块的结果项。各加密槽绑定原服务、用户、工作区、批次及本次归档标识。索引记录父档包装键戳及父档密文摘要，读取时在同一事务核对。父档包装键戳改变时走旧格式；同键摘要不符、所需块缺失、损坏或认证失败时拒绝。索引与块随批次删除及登录、权限变化清除，原批次的原键和恢复检查点继续使用原路径。

本地结果继续遵守同一工作区、会话和断网规则，输出请求页及原有完整收据。机器输出使用现有字段顺序、标识精度和换行，先认证此次输出涉及的全部块，再向 stdout 增量写出。文本输出使用同一摘要及参数校验。以同一份完整 19 文件归档比较整份输出、各页边界、旧包读取新缓存、旧缓存回退、篡改拒绝和被中断事务，并测量额外保存对确认预算的影响。

## 确认控制读取

恢复在原确认事务内核对已认证冻结批次的包装密钥，可复用刚读的对象。保存原收据后的紧邻读取同样受会话、SQLite 外部写入版本及完整性检查点约束。缓存降级或外部事务改写后读取原持久记录，保留原键和原收据。

安装包在冻结提交的同一 SQLite 事务保存原操作键控制记录，沿原工作区、用户和批次的加密槽。状态与取消依据持久原键查询服务，不读冻结正文。有效控制记录随原操作更新，转入归档或删除时在同一事务移除。控制记录以父批次包装密钥绑定该次存储写入，旧版本改写原批次后走原完整读取。缺少控制记录的历史批次同样走原完整读取；损坏控制记录拒绝。原键恢复发起和收据核实保持原行为。 安装包验证并保存完整原收据和结果页时，在同一次 SQLite 事务内记下提交状态所需的原键及收据 ID。归档状态使用独立加密槽，沿用工作区、用户、批次和原行包装密钥绑定；旧版识别的待完成槽仍按原生命周期移除。归档状态只读取该事实，会话及离线回退规则相同。旧缓存或行戳改变时沿既有完整读取。取消命中已归档结果仍使用原收据输出。

现金写集上传沿用完整冻结正文、原键、身份编码和原请求时限。Node 按 UTF-8 边界逐段交给传输，使用完整原正文的准确 Content-Length。接收端仍按全部原字节验容量和摘要，原子受理、取消与按键恢复合同保持。验证实际受理与控制过程的客户端峰值。

## 取消后的执行围栏

异步执行在原事务各阶段及源行处理间检查同一代次仍在运行。工作进程等待流水表后重新获得执行能力时，先核是否已经记录取消。命令依旧在同一事务完成写入、收据和终态，或在取消后整体回滚。开始执行仍使用原租约规则，执行中的状态检查不改变提交时的原代次规则。

## 写集受理的解析与摘要

受理沿原 UTF-8、重复字段、数词、深度和容量校验。解析器在单次请求内限量复用短字段名。排序写入摘要时遍历原解析树，按原字节规则验证与计算，不为字段排序另外保留一整份树。数据库仍持久保留完整写集、稳定摘要和原键。 独占 Linux 的实际受理剖析显示，持久受理阶段的 JFR 加权分配样本中约 8.08 亿 B 经过逐字段严格 UTF-8 编码，另有约 3.26 亿 B 经过字符串转义。复用固定容量 UTF-8 缓冲和编码器，保持旧排序、原数词、代理字符校验、编码字节上限和同键摘要。JFR 权重单列用于定位；实际判定仍使用无 profiler 的 cgroup 窗口。

## 整批核对结论的摘要

整批核对使用现有领域归一化、排序及 ASCII 摘要格式。摘要按集合消费类型化的结果，每次以现有序列器输出一条规范写入元素，同时保持对象键的码点顺序、数组顺序、金额数词、UTF-16 转义及原摘要。保留结论所需的全部写入和核对事实。验证原版摘要、确认及恢复的冻结内容，并用同一 19 文件的实际峰值评估改动。

冻结预览计划时，在递归访问每个容器的同一步完成数词转换、键排序及最终 JSON 编码。生成独立快照，保留字符校验、历史数字表示、显示字段和恢复输入。共享读取器仍持有自身快照，调用方随后改写原容器时读结果保持稳定。

一次核对从同一领域计算构建冻结计划和写集。写集、结论、选择绑定和显示校验读取这份冻结计划。冻结容器在构建结束后拒绝改写，防止公开计划与写集中共享的嵌套 JSON 失配。原类型化计划用于提取编辑上下文，提取完成后退出其作用域，再编码完整写集及结论。选择绑定从已冻结的输入生成。继续生成原公开读快照，保留确认与恢复的完整上下文；重算仍沿现有各阶段入口。

本地整批核对在操作构造结束时同时持有已认证的解析行、整个资金扫描、全批来源索引、行决定及操作值。资金规则读取原文来识别组，后续扫描和解析中只保留资金字段及入账类型校验字段，不把原文、备注等复制到资金结果。完整来源原文仍由来源发生和操作写值持有。操作构造新建的可写外层映射和行决定由本地计划独占，按原顺序交给预览准备和叠加，避免两个阶段各复制一整批外层容器。公开准备和快照入口维持原隔离，叠加中保留可变金融组成项的复制。所有候选、弱匹配、分录编辑、冻结和恢复沿原规则。验证全字段及关系候选守恒、初始快照隔离、规模增长及独占 Linux 原 19 文件峰值。

本地预览叠加保存关联投影、分录公用字段和独立的可变组成项。关系匹配在本次本地核对内部通过只读引用读取操作原文，失败回滚或未修改的成员仍从独立账本快照读取。修改历史和其他只供写集使用的字段由操作持有。公开快照仍提供完整且独立的值；实际核对、关联候选与审阅明细逐项对照。

默认 Linux 堆在冻结正文序列化后达到约 2.31 GB RSS，随后在完整规范核对结果就绪前退出。规范结论逐字段构造和输出，保留旧 ASCII 键序和完整参与事实闭包。在参与事实后的字段先编码到定长内存块，发布该参与事实后将字节依次送入同一 SHA-256。前面的字段直接输出，所有字段编码后释放其规范 JSON 树。正文在结论前经过原容量校验。冻结格式、旧摘要、加密状态与恢复输入沿原合同。用旧规范字节、依赖闭包、不同规模内存增长及原 19 文件验证该路径。

原 19 文件的同刻诊断显示，开始归一化写集后 8.68 秒，V8 堆由 1,387,882,160 B 升至 2,044,865,032 B。整份规范写集仍同冻结树、原始写集驻留。摘要序列化可以按当前消费的写入集合生成规范值和规范顺序，生成器只持有输入引用；完成一个集合后释放其规范化项，再计算后续集合。完整写集、原参考身份、字段顺序和旧摘要保持。原入口继续可得到完整规范写集用于既有对照。

## 核对重算

重算依次重新绑定关系选择及分录编辑。某阶段产生同样的选择和历史时复用已有计划及写集，仍以完整结论检查已确认事实。真实选择改变时执行对应阶段并保留失效和不可恢复判定。同一次重算使用固定的计算时点，返回前再次核实会话活动状态。

## CI 与校准

普通共享场景的环回代理与本地计时共用 Node 事件循环。每个客户端连接完成一项 HTTP 响应后关闭，避免长时间纯本地计算结束后借用已空闲超时的连接。请求和退出证据，以及首个业务错误和清理异常，分别保留给失败报告。

本机内存探针在实际 CLI 阶段入口采样 V8、External、ArrayBuffers、匿名和文件 RSS，并累计 SQLite 密文与加解密输入。加密传入的文本按其编码计算字节数，累计字节不表示原生驻留。可另外在阶段入口显式 GC 观察保留对象，仅用于诊断。

main PR 事件无路径过滤。普通场景的共享入口和安装包冷命令分别在独立 runner 运行，与最大场景并行。最终 `client-operations-performance` 严格要求所有分组成功。校准提交通过提交正文的独立标记扩为五个副本，每个场景使用五台独立托管 runner，保存原始证据。拆分后保留每项 5 次预热和 30 次采样，工作流时限与操作预算分别执行。核对、汇总和冷启动用同 runner 同夹具比较 base/head，超过 20% 且短操作增加至少 100 ms、重型增加至少 2 秒时独立复测，复现即失败。首次目标 `5e847a7e` 缺共享模块及安装包，报告标识不可比。base 构建失败时也先执行并保存 head 绝对预算的结果，报告并阻断无法判断的相对检查。

19 文件含 5 PDF、2 XLS、6 CSV、6 XLSX，以及跨文件重复、缺来源 ID 和多币种。一次在线确认、实际收据、成员身份和断网新进程读回均须验证。最大场景与普通场景各自使用临时状态或测试数据库。运行环境、密码和全部数据由测试构造。普通和最大场景的测试代理独立管理客户端连接，移除上游逐跳连接设置。最大场景另记录中断文件。新 head 与旧 head 使用不同的并发组，保留各自诊断证据。

托管最大场景保留 runner CPU 型号、进程 CPU／墙钟、核对阶段、可用系统压力和 GC 样本。标记启动 GC 观察器的核对，和前两轮未采集 GC 的计时可区分。代理首包、正文传输、断开及上游结束使用统一时间，与 PostgreSQL 事务观察对齐。首次确认失败始终阻断。诊断用原工作区、使用者和键只读查询同一测试库，单独记录观察到的收据和事务结论。诊断期间不得发送第二次写入，原预算和应用请求超时保持。

## 核对的临时加密工作区

用户确认在整批结果和故障恢复等价时优先选择每批独立加密文件。两轮同机对照中 D 的核对用时均低于两个 SQLite 方案，RSS 未见 SQLite 可复现的实质优势，清理后独立文件零占用。正式候选使用 D 保存临时核对块，已发布状态、离线缓存和原冻结写集由现有 SQLite 保存。核对墙钟和 RSS 继续执行固定预算。

对旧加密缓存的分块读取试验，在原 GCM 完整认证后，从次级加密文件分割元数据、原文件 Base64 和已经归一化的行，保留精确 JSON 数词并增量核对来源长度与 SHA-256。此试验仍由 SQLite 返回整个密文 BLOB，关联等阶段会重新解码行块。原 19 文件核对和高转义输入的实测未证明这一路径满足固定预算，正式候选沿用旧缓存读取。

已认证且由本进程冻结的计划，生成空白来源页证据时只读取被跳过的行、目标交易和候选集合。公开的写集组合入口保留接收外部计划的整树验证。固定门禁记录独立文件峰值，校验最终无残留块和目录，并报告 SQLite 可复用空间。

本地确认写集的分录构造若没有显式分录编辑，生成的每个分录由已算好的同一图成员集合直接组成。构造后复用该分组验证最终根、成员和受影响的已有分录，同时执行最终写集引用及修订检查。正式服务独立从事务事实构图，显式分录编辑保留完整复算。以原分组、分录成员、原收据及相同 19 文件验证。

采用用户确认的磁盘空间与内存取舍。比较已提交的内存基线 A、现有本地 SQLite 加密分块 B、每批独立 SQLite 文件 C 和每批独立加密文件 D，按对照结果选择正式存储介质。共享核对代码决定块、顺序、精确 JSON 和业务依赖。三个磁盘原型共用应用层 AES-GCM、块负载、索引和最终发布接口。全批关联、歧义和冲突保留完整候选及所需索引。规范摘要按原稳定顺序处理完整结果，冻结写集继续从同一个独立账本版本和完整核对生成。服务端暂存需联网及上传来源数据，无法支持既有离线核对，并增加工作区权限、重试与过期清理成本，作为设计对照。

临时块按原点、当前会话工作区、批次和代次隔离。共库对照分别量短事务和主库写锁等待；独立 SQLite 对照保留同一认证层和短事务。独立文件使用按块索引和完整发布边界。最终核对仍通过原批次比较及主库事务发布。成功、异常、取消及进程中断后应清理对应代次，保护仍被使用的代次和有效冻结记录。磁盘不足、坏块、跨代次读或中断不得发布半份预览或触发 POST。

对照同时记录库、WAL、回滚日志、临时文件、索引和孤块的高水位，区分逻辑删除与物理文件留存。65 MB 微测分顺序和跨块随机读取，另测同批竞争及其他普通 `ft` 读写延迟。原 19 文件在独占 Linux、默认 Node、实装包与相同 PostgreSQL 初态下交错复验，记录样本量和波动。每个可行候选验证旧缓存、离线读取、强杀、空间不足、篡改及原键合同。以 30 秒／512 MiB、实测数字、完整逐成员、原收据和维护成本共同判断；未完成整批的候选只记录已测边界。
