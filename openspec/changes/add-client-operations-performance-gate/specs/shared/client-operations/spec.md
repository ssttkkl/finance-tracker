## ADDED Requirements

### Requirement: 所有 main PR 验证共享操作性能预算

仓库 MUST 以同一清单按公开入口、场景和预算逐项验证共享客户端操作，并覆盖实际安装的 CLI。以 main 为目标的每次 PR 更新 MUST 运行普通负载及最大负载，包括纯文档变更。

#### Scenario: 公共接口或场景缺失

- **WHEN** 共用操作对外入口变更或预期场景执行不完整、结果错误、泄漏写入或超预算
- **THEN** `client-operations-performance` MUST 失败，普通和最大作业均成功才可通过

#### Scenario: 19 文件一次确认

- **WHEN** 安装的 CLI 核对、确认、整理结果并重新进程读取同一个合成批次
- **THEN** 各阶段 MUST 独立满足墙钟及内存预算，校验一次原子写入、完整原收据、逐关联成员和断网恢复

#### Scenario: 独立判定操作与请求预算

- **WHEN** CI 执行已登记的共享业务操作
- **THEN** 每项操作 MUST 校验结果就绪耗时和客户端峰值 RSS，包括纯本地操作
- **AND** 对现金导入链路，仓库 MUST 按实际发生的每个请求校验后端耗时和正文大小，使用隔离采样对相应路由与负载执行后端内存门禁

#### Scenario: 整批达标且一次请求超限

- **WHEN** 最终入账正确且整批符合预算，其中一次轮询、分页或重试超出请求硬上限
- **THEN** 固定检查 MUST 失败并指出所属操作、路由和超限指标

#### Scenario: 异步受理或请求采集不完整

- **WHEN** 受理后后台仍在写入，客户端查询、取消或按原键恢复
- **THEN** MUST 独立验证这些短请求，默认确认持续计时至完整结果，显式提前退出以持久受理或已有终态为准
- **AND** 任一预期场景、请求样本或必需资源指标缺失时 MUST 阻断

#### Scenario: 热点相对退化

- **WHEN** 同机同夹具热点相对耗时增加超过 20% 且达到场景的绝对增量
- **THEN** MUST 独立复测，复现时失败。无兼容 base 时记录原因并完整执行 head 的绝对预算
