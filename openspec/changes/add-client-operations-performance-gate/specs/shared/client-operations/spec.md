## ADDED Requirements

### Requirement: CLI 核对可使用按批的临时加密工作区

安装的 `ft` MUST 逐块认证和处理大型核对中间值，并保持全批来源候选、关联与冲突判断、旧缓存恢复、离线核对明细和原有输出。临时工作区 MUST 使用本地认证加密存储，隔离工作区、批次和计算代次。

#### Scenario: 核对完成、异常或进程中断

- **WHEN** 核对完成，或遇到坏块、存储空间不足、会话变化、异常或进程中断
- **THEN** 临时块 MUST 在结束或恢复后清理，只有完整且通过原批次比较校验的核对才可发布
- **AND** 核对不得产生提交，既有冻结写集、原键及唯一原收据 MUST 可按原合同恢复

#### Scenario: 固定负载的完整核对

- **WHEN** 门禁运行原 19 文件的实装流程
- **THEN** MUST 计入整个客户端的墙钟、峰值 RSS 和 SQLite 含临时文件、日志的磁盘高水位，分别核实临时块逻辑清理和可复用文件空间
- **AND** 继续验证原输出、金额、币种、逐成员、一次原子写入及断网读回，维持固定预算

### Requirement: 所有 main PR 验证共享操作性能预算

仓库 MUST 以同一清单按公开入口、场景和预算逐项验证共享客户端操作，并覆盖实际安装的 CLI。以 main 为目标的每次 PR 更新 MUST 运行普通负载及最大负载，包括纯文档变更。

#### Scenario: 先固定预算再验证实现

- **WHEN** 为固定负载增加操作或请求性能门禁
- **THEN** 仓库 MUST 在测量前登记数值预算；同一提交上的运行用于判定是否达标，超过预定上限或缺失样本均阻断
- **AND** 调整预算须有用户确认的用途或负载依据，不能依据当前实现的峰值自动放宽

#### Scenario: 公共接口或场景缺失

- **WHEN** 共用操作对外入口变更或预期场景执行不完整、结果错误、泄漏写入或超预算
- **THEN** `client-operations-performance` MUST 失败，普通和最大作业均成功才可通过

#### Scenario: 19 文件一次确认

- **WHEN** 安装的 CLI 核对、确认、整理结果并重新进程读取同一个合成批次
- **THEN** 各阶段 MUST 独立满足墙钟及内存预算，校验一次原子写入、完整原收据、逐关联成员和断网恢复

#### Scenario: 独立判定操作与请求预算

- **WHEN** CI 执行已登记的共享业务操作
- **THEN** 每项操作 MUST 校验结果就绪耗时和客户端峰值 RSS，包括纯本地操作
- **AND** 对现金导入链路，仓库 MUST 按实际发生的每个请求校验后端耗时和正文大小，使用隔离采样对相应路由与负载执行后端内存门禁

#### Scenario: 整批达标且一次请求超限

- **WHEN** 最终入账正确且整批符合预算，其中一次轮询、分页或重试超出请求硬上限
- **THEN** 固定检查 MUST 失败并指出所属操作、路由和超限指标

#### Scenario: 异步受理或请求采集不完整

- **WHEN** 受理后后台仍在写入，客户端查询、取消或按原键恢复
- **THEN** MUST 独立验证这些短请求，默认确认持续计时至完整结果，显式提前退出以持久受理或已有终态为准
- **AND** 任一预期场景、请求样本或必需资源指标缺失时 MUST 阻断

#### Scenario: 热点相对退化

- **WHEN** 同机同夹具热点相对耗时增加超过 20% 且达到场景的绝对增量
- **THEN** MUST 独立复测，复现时失败。无兼容 base 时记录原因并完整执行 head 的绝对预算


### Requirement: 账本快照与原键收据支持兼容分页

服务 MUST 为账本快照和按原键读取现金导入原收据提供显式可选的分页表示。既有读取入口、响应结构和权限保持可用。新版 `ft` MUST 逐页验证并重组原本的完整业务结果。服务端和门禁 MUST 分别约束每个分页实际传输和解压正文大小，快照每页最多 32 MiB，原收据每页最多 2 MiB。

#### Scenario: 旧客户端继续使用原表示

- **WHEN** 客户端未选择分页
- **THEN** 服务 MUST 沿原入口、响应结构、用户与工作区的读取资格返回同一版本快照或同一原键的原收据

#### Scenario: 新客户端取得同一账本与原收据

- **WHEN** 新版 `ft` 显式使用分页读取
- **THEN** 每页 MUST 绑定用户当前有权访问的原工作区和账本版本或原收据身份
- **AND** 客户端 MUST 按稳定顺序完整取得各事实、结果身份及逐成员，验证字段、顺序和金额精度与原表示一致
- **AND** 性能门禁 MUST 计入每次请求、完整重组与原操作的耗时和 RSS，维持原预算与测试夹具

#### Scenario: 将连续事实段合并为一次读取

- **WHEN** 客户端明确请求合并快照或按原键原收据的分页
- **THEN** 服务 MUST 在同一个经核验的读取上下文内返回按原顺序连续的段，所有段共用账本版本或原收据身份，且每次仍检查工作区和读权限
- **AND** 新版客户端 MUST 验证响应内及跨响应的连续位置、集合、行数和分片。只支持原分页的服务和旧分页客户端继续使用原表示
- **AND** 门禁 MUST 核对实际返回段及其覆盖，逐请求判定原传输、解压、完整延迟与内存预算。固定页数不作为完整性证据

#### Scenario: 分页中断、内容错误或访问变化

- **WHEN** 页缺失、重复、连接中断、账本版本变化、收据身份变化或当前会话失去读取资格
- **THEN** 客户端 MUST 丢弃未完成的重组，不发布部分快照、结果归档或替代收据
- **AND** 已有有效缓存按原会话、工作区和权限规则处理；撤权仍触发清理
- **AND** 恢复有原提交时继续依据原键，分页读取不能产生新写入或新收据
