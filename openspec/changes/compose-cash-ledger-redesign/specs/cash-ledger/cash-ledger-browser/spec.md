## ADDED Requirements

### Requirement: Compose 收支账本按窗口提供一致的流水浏览结构

Compose Web、Android 和 iOS 的收支账本 MUST 保持相同的页面区域顺序、筛选语义、月份汇总、分页、批量操作和状态反馈。筛选区 MUST 先显示复用现有交易对方筛选的搜索输入，以及固定的「全部」「支出」「收入」「转账」四个快捷项；快捷项 MUST 只更新现有经济类型筛选，「全部」MUST 清除经济类型及转账细分筛选而保留其他筛选条件。详细筛选 MUST 默认收起，由「筛选」入口打开；分类 MUST 保留在详细筛选内。`COMPACT` MUST 以 Bottom Sheet 展示详细筛选；`REGULAR` 和 `WIDE` MUST 以模态弹窗展示，账本保持可见但不可操作；面板 MUST 支持 Escape 或系统返回关闭，并沿用平台默认焦点行为。搜索和筛选 MUST 继续使用既有字段、查询与结果语义，不得新增搜索或筛选能力。

`COMPACT` MUST 使用可扫读的单列流水卡片；`REGULAR` 和 `WIDE` MUST 使用紧凑表格。每条可见收支 MUST 保留发生时间、交易对方、账户、收支分类、经济类型、金额、适用的来源和打开详情的入口；关系两端信息及长文本可在详情中查看。每个月份 MUST 形成独立的视觉容器，月份与收入/支出汇总 MUST 位于该月流水之前并与其保持在同一容器中；`REGULAR` 和 `WIDE` 的月份容器 MUST 包含表格列标题及对应流水。相邻月份容器之间 MUST 由页面底层表面形成清楚间隔。筛选、分页、选择、批量分类、批量删除和导入的业务结果 MUST 保持不变；列表和表格 MUST 提供正常、加载、空、错误和禁用状态，窄屏不得出现页面级横向滚动。

账本筛选区 MUST 使用独立的 Material 3 前景容器，并固定在屏幕上方；滚动操作 MUST 只滚动流水列表，不得带走筛选区。每个月份的流水 MUST 使用与筛选区分开的独立前景容器；页面底色 MUST 继续作为更低一层背景，并在筛选区和各月份容器之间形成清楚间隔。账本、筛选和详情的表面层级 MUST 通过全局 `FinanceTheme` 的 `surfaceContainer*` 角色表达，不在组件调用点写入独立颜色值；流水详情摘要 MUST 保持在详情面板表面上，主要信息和关联流水 MUST 使用 Material 3 默认卡片表面角色；收入/支出金额颜色保持既有语义。

#### Scenario: 在 Compact 窗口浏览收支账本

- **WHEN** 使用者在 `COMPACT` 窗口打开收支账本
- **THEN** 页面 MUST 以单列流水卡片展示列表，并按月份连续分组
- **AND** 每张卡片 MUST 让金额、交易对方和发生时间易于扫读，且可查看账户、分类、经济类型和适用的来源
- **AND** 筛选区 MUST 固定在屏幕上方；每个月份的汇总与流水 MUST 位于各自独立的容器中
- **AND** 页面 MUST 保留筛选、记一笔、导入账单、分页和当前可执行的批量操作
- **AND** 页面 MUST 不出现横向滚动

#### Scenario: 在 Regular 或 Wide 窗口浏览收支账本

- **WHEN** 使用者在 `REGULAR` 或 `WIDE` 窗口打开收支账本
- **THEN** 页面 MUST 以紧凑表格连续展示日期、流水信息、账户、分类、类型和金额
- **AND** 月份及其收入、支出汇总 MUST 与对应记录分组保持在一起
- **AND** 每个月份 MUST 使用独立容器，并在容器内展示该月列标题和流水
- **AND** 长交易信息 MUST 受限以保持账户、分类和金额可读，完整文本 MUST 可在详情中查看
- **AND** 表格 MUST 保留行选择、详情、分类及适用的来源信息

#### Scenario: 继续使用既有筛选和批量操作

- **WHEN** 使用者在任一窗口等级更改筛选、翻页、选择流水、修改分类、删除已选流水或打开导入
- **THEN** 系统 MUST 保留当前筛选字段、分页游标、选择清理、危险确认、权限和错误恢复语义
- **AND** 页面 MUST 在对应加载、追加加载、空结果、错误及只读状态显示可操作的既有反馈

#### Scenario: 滚动流水列表时筛选区保持固定

- **WHEN** 使用者在任一窗口尺寸向下滚动收支流水
- **THEN** 搜索、快捷类型和详细筛选入口 MUST 保持固定在屏幕上方
- **AND** 流水列表 MUST 在筛选区下方独立滚动，月份容器 MUST 依序显示且彼此分隔

#### Scenario: 使用搜索和快捷筛选定位流水

- **WHEN** 使用者在搜索输入中填写交易对方，或选择「全部」「支出」「收入」「转账」快捷项
- **THEN** 搜索 MUST 复用现有交易对方筛选；快捷项 MUST 复用现有经济类型值并立即更新账本结果
- **AND** 快捷项 MUST 保留其他筛选条件；「全部」MUST 清除经济类型与转账细分筛选
- **AND** 分类及其他详细筛选 MUST 继续通过详细筛选入口访问

#### Scenario: 按窗口尺寸打开详细筛选

- **WHEN** 使用者在 `COMPACT`、`REGULAR` 或 `WIDE` 窗口选择「筛选」
- **THEN** `COMPACT` MUST 打开 Bottom Sheet，`REGULAR` 和 `WIDE` MUST 打开模态弹窗
- **AND** 详细选项 MUST 保留当前日期、账户、分类、币种、金额范围、转账细分和组成筛选值
- **AND** 详细选项 MUST 以常驻标题分为「时间」「金额」「分类」「账户」「其他条件」五组；日期范围归入「时间」，币种和金额范围归入「金额」，分类和账户分别独立成组，资金转移类型与合并状态归入「其他条件」
- **AND** `COMPACT` MUST 按组纵向排列筛选项；`REGULAR` 和 `WIDE` MUST 在组内并排排列日期范围、金额范围，以及其他条件中的可配对选项
- **AND** 分组 MUST 仅改变信息层级和排布，不折叠选项，也不得改变筛选字段、结果语义、关闭保留值或重置语义
- **AND** 模态打开期间账本 MUST 保持可见但不可操作；关闭 MUST 保留已选条件，重置 MUST 清除全部筛选
- **AND** 搜索输入和快捷筛选 MUST 在详细筛选关闭后仍反映当前条件

### Requirement: 收支账本以统一操作菜单和按尺寸选择交互管理流水

Compose Web、Android 和 iOS 的收支账本 MUST 在所有窗口尺寸提供相同的记一笔、导入账单和批量操作入口。无选中流水时，操作菜单 MUST 提供「记一笔」和「导入账单」；有选中流水时，MUST 改为提供「设置分类」「删除」和「取消选择」，并展示已选数量。系统 MUST 移除「全选当前已加载」入口。设置分类 MUST 在模态对话框中完成分类选择和明确应用；取消 MUST 不修改流水，应用 MUST 继续使用现有批量分类结果、权限和错误语义。删除 MUST 保留既有危险确认语义。

在 `COMPACT` 中，账本 MUST 默认隐藏行复选框；未进入选择模式时，普通点击流水 MUST 打开详情，长按流水 MUST 立即选中该笔并进入选择模式。选择模式中，行复选框 MUST 显示，点击流水或复选框 MUST 切换该笔选择状态；取消选择最后一笔后 MUST 自动退出选择模式。`REGULAR` 和 `WIDE` MUST 持续显示行复选框，普通流水操作 MUST 仍可打开详情。列表搜索、筛选、汇总、分页及已有批量业务结果 MUST 保持不变。

#### Scenario: Compact 使用长按选择流水

- **WHEN** 使用者在 `COMPACT` 窗口长按一条尚未选中的流水
- **THEN** 系统 MUST 立即选中该笔并进入选择模式，显示已选数量、该行复选框和选择模式操作菜单
- **AND** 选择模式操作菜单 MUST 自动展开，FAB MUST 显示多选图标，已选数量 MUST 作为提示胶囊显示在 FAB 左侧
- **AND** 选择模式中点流水或复选框 MUST 切换该行选择状态
- **AND** 取消选择最后一笔后 MUST 退出选择模式并隐藏行复选框
- **AND** 在选择模式外普通点击流水 MUST 打开详情

#### Scenario: Regular 或 Wide 通过复选框选择流水

- **WHEN** 使用者在 `REGULAR` 或 `WIDE` 窗口选择或取消选择流水
- **THEN** 行复选框 MUST 始终可用，页面 MUST 显示已选数量
- **AND** 选中第一条流水时操作菜单 MUST 自动展开，FAB MUST 显示多选图标，已选数量 MUST 显示在 FAB 左侧
- **AND** 选择期间的操作菜单 MUST 提供批量分类、删除和取消选择
- **AND** 页面 MUST 不显示「全选当前已加载」复选框

#### Scenario: 在操作菜单打开记一笔或导入账单

- **WHEN** 没有选中流水且使用者展开操作菜单
- **THEN** 菜单 MUST 提供「记一笔」和「导入账单」动作
- **AND** 选择「记一笔」MUST 打开既有新增面板，选择「导入账单」MUST 打开既有导入流程

#### Scenario: 在模态分类对话框内确认或取消批量分类

- **WHEN** 使用者在选择模式中选择「设置分类」
- **THEN** 系统 MUST 打开包含现有分类选择器及「取消」「应用」操作的模态对话框
- **AND** 「取消」MUST 关闭对话框且不修改已选流水
- **AND** 「应用」MUST 将选中分类应用于全部已选流水，并保留既有忙碌、权限和错误反馈

#### Scenario: 通过操作菜单批量删除流水

- **WHEN** 使用者在选择模式中选择「删除」
- **THEN** 系统 MUST 进入既有危险确认流程
- **AND** 取消确认 MUST 保留流水和当前选择，确认后 MUST 使用既有批量删除结果

### Requirement: 新增、详情和编辑共用响应式模态信息面板

使用者从收支账本新建流水、打开收支详情或编辑现有流水时 MUST 使用同一响应式模态信息面板。`COMPACT` MUST 全屏呈现；`REGULAR` 和 `WIDE` MUST 从右侧呈现面板，账本保持可见但不可操作。面板 MUST 隔离背景交互并支持 Escape 或系统返回关闭。Compose 面板 MUST 沿用 Compose 与平台默认焦点行为，不得额外请求初始焦点或在关闭时显式恢复触发入口焦点；此规则只约束共享 Compose 面板，不改变旧 React Web 的抽屉行为，也不移除其他功能（例如导入导航）已有的焦点逻辑。详情 MUST 以金额、币种、交易对方、经济类型和发生时间构成卡片外的摘要区；账户、流水类型、适用的业务细分、分类、备注和来源 MUST 在一张 Material 3 ElevatedCard 内以标签与值分列组织，凭证成员、组成及退款时间线 MUST 归入相应的信息区域。存在关联事实时，详情 MUST 使用另一张并列的 Material 3 ElevatedCard，以默认 `surfaceContainerLow` 前景角色呈现默认收起的「关联流水」区域；展开内容 MUST 留在该卡片内，并在同一详情面板中分组展示当前流水与关联流水，保留每笔流水的可核对信息和现有关联管理操作。两张卡片 MUST 并列，不得互相嵌套；详情面板内不得再叠加 Dialog 或 Bottom Sheet。单源收支 MUST 不显示空的凭证或关联区域。编辑 MUST 在当前面板内切换，取消后回到原详情或收支账本，保存后展示更新结果。现有新增、编辑、删除、凭证、关联操作、权限、字段校验、错误、忙碌状态和危险确认语义 MUST 保持不变。

#### Scenario: 从列表打开详情或新增流水

- **WHEN** 使用者在 `COMPACT`、`REGULAR` 或 `WIDE` 窗口打开某条流水详情或选择「记一笔」
- **THEN** `COMPACT` MUST 显示全屏面板，`REGULAR` 和 `WIDE` MUST 显示右侧模态面板
- **AND** `REGULAR` 和 `WIDE` 中的账本 MUST 保持可见但不可操作
- **AND** 打开期间账本保持可见但不可操作

#### Scenario: 从收支详情编辑并返回

- **WHEN** 使用者在详情中选择编辑、修改字段后取消或保存
- **THEN** 编辑表单 MUST 在同一面板内呈现并保留已有字段、校验和权限限制
- **AND** 取消 MUST 返回原收支详情，保存 MUST 返回更新后的详情并刷新账本结果
- **AND** 需要确认关联影响或删除影响时 MUST 保留既有的明确确认流程

#### Scenario: 键盘关闭 Compose 流水面板

- **WHEN** 使用者通过浏览器键盘打开共享 Compose 流水面板并按 Escape
- **THEN** 面板 MUST 关闭，背景账本 MUST 恢复可交互
- **AND** 面板 MUST 不请求专属初始焦点或在关闭后显式恢复焦点到触发入口
- **AND** 其他功能已有的键盘与焦点行为 MUST 保持不变

#### Scenario: 查看单源或有关联流水的收支详情

- **WHEN** 使用者打开单源收支或包含凭证、关联流水的收支
- **THEN** 详情 MUST 首先展示完成核对所需的主要收支信息
- **AND** 金额、交易对方和时间摘要 MUST 位于卡片外；主要流水信息 MUST 使用 Material 3 ElevatedCard，且不得与关联流水卡片嵌套
- **AND** 详情摘要 MUST 位于中性面板 Surface 上，主要信息卡与关联流水 ElevatedCard MUST 使用 `surfaceContainerLow` 前景角色
- **AND** 主要属性 MUST 按标签与值分列展示；来源、凭证成员、组成、退款时间线及关联流水 MUST 在次级区域分组展示，且不得暴露实现层术语
- **AND** 单源收支 MUST 不显示空的凭证或关联区域

#### Scenario: 在详情内展开已关联流水
- **WHEN** 使用者打开包含已接受关系或相关凭证流水的详情并展开「关联流水」区域
- **THEN** 区域 MUST 默认收起，并通过「查看关联流水」及关联数量让其可发现
- **AND** 折叠入口及展开内容 MUST 位于独立的 Material 3 ElevatedCard 内
- **AND** 展开后 MUST 在当前详情面板内分组显示当前流水与每条关联流水的交易对方、金额、发生时间、账户，以及适用的流水类型、分类和备注
- **AND** 展开区域 MUST 保留现有编辑关联流水、修改关系类型、取消关联及危险色解散关系操作
- **AND** 展开 MUST 不打开第二个 Dialog、Bottom Sheet 或路由

### Requirement: 收支账本主要操作保留文字并用图标和危险色区分

编辑、添加关联、创建关联、保存和删除等主要操作 MUST 显示表达对应动作的图标，并保留本地化文字标签及无障碍名称。批量删除、删除流水和解散关联 MUST 使用 FinanceTheme 的危险色（`error`）角色显示操作；现有删除确认按钮 MUST 使用相同危险色角色。取消和非破坏性确认 MUST 保持普通操作颜色。图标和颜色不得改变既有操作结果、权限或确认流程。

#### Scenario: 快速识别账本与详情中的主要操作

- **WHEN** 使用者浏览账本操作菜单、流水详情或新增/编辑表单
- **THEN** 编辑、关联、保存和删除等主要动作 MUST 同时显示图标与文字
- **AND** 批量删除、删除流水、解散关联及现有删除确认 MUST 使用危险色角色
- **AND** 图标 MUST 不替代可见文字或无障碍名称，Web、Android 和 iOS MUST 保持相同标签、操作结果和危险语义
