## Context

现有 `account_aliases` 已按工作区绑定到具体账户，并具备别名类型和值索引；当前仅 `card_tail` 用于支付镜像。转账关系的候选先由金额、币种、日期、方向和记录类型形成，随后评估时间和文本规则。见 `proposal.md` 和 delta 规格。

## Goals / Non-Goals

**Goals:**

- 让用户显式登记的完整账号或卡号尾号安全收敛转账候选。
- 让已确认关系只保存不可由原始事实重建的人工决定和正式规则标识。
- 保持 SQLite 与 PostgreSQL 在相同事实和别名输入下的关系结果等价。

**Non-Goals:**

- 不从账户名称、导入映射或既有账单自动推断、回填或登记账号。
- 不将转账的 `counterparty_account` 用于支付镜像、退款关系或非转出方向。
- 不让账号命中绕过金额、币种、时间、记录类型或人工审核门槛。

## Decisions

### 使用既有账户别名表

新增 `account_identifier` 别名类型表示完整账号；既有 `card_tail` 表示四位尾号。两者均由用户通过既有别名入口绑定账户，无需迁移。相比在账户表增加账号列，此方案保留一个工作区内可多值、可撤销且已索引的受控注册表。

### 分层比较并只筛选候选

对未掩码的完整数字账号先精确匹配 `account_identifier`；不能精确匹配时，再使用唯一 `card_tail`。账号命中只将候选限定到对应账户，随后仍走原有规则。候选账户已登记标识却与来源账号不匹配时排除；未登记账户不据此排除，避免把不完整的本人账户注册表误作全量权威。

### 账号命中只参与本次候选筛选

`FactView` 读取 `counterparty_account` 但其文本字段不包含账号。完整账号与尾号的命中结果只在本次候选筛选中使用，原账号只保留在现金正式列与来源行快照；关系持久化、CLI、日志和错误路径均不保存或回显匹配过程。

### 平台支付方式验证支付镜像账户

支付镜像保持「平台账单 × 银行账单 + 同一 `account_id`」的硬前提。平台侧原始 `payment_method` 是该账户身份的受控输入：先将其中未掩码的完整数字标识与唯一 `account_identifier` 精确比较；仅有尾号时，同时查询显式 `card_tail` 和由已登记完整 `account_identifier` 推导出的尾号。只有尾号最终唯一映射到当前同一账户时才增加身份证据。

此处不复用转账的候选筛选：支付镜像本来禁止跨账户，账号别名只用于验证既有同账户候选。不把完整账号、由完整账号推得的尾号或命中过程写入关系、JSON、CLI 或日志。

### 待配对候选作为受控操作状态

关系结果可由正式事实、账户别名和 `rule_id` 重算；因此 `transaction_relations` 不保存 JSON 证据、置信度或“稍后处理”标记。唯一例外是待配对关系的 `candidate_fact_ids`：它是按规则排序、去重且上限为 20 的账本记录 ID 列表，供人工在当次审查中选择对侧；不包含金额、时间差、分数、文本、账号或命中信号。

待配对关系仍以空的对侧端点表示。创建时写入候选 ID；人工确认必须选择其中一项，并在绑定后清空该列；驳回、替换或 supersede 也必须清空该列。零候选的高信号锚点允许保存空列表，但不得接受任意对侧。退款额度仍只在单次匹配中计算。相比独立候选表，单列避免额外生命周期和联接，同时候选上限很小且只服务一条待审核关系。

## Risks / Trade-offs

- [用户未登记本人账户标识] → 关系保持既有行为，不产生错误排除；文档给出显式登记命令。
- [四位尾号碰撞] → 仅在尾号绑定唯一账户时使用，冲突时不收敛也不提高置信度。
- [账号格式变化] → 比较仅处理明确的数字账号和格式分隔符；不确定格式不匹配，保守回退。
- [账号泄露] → 回归测试断言关系、CLI 输出和异常均不包含别名或来源账号。
- [完整账号尾号碰撞] → 将 `card_tail` 与完整账号派生尾号合并后要求唯一；多个账户共享尾号时不提高支付镜像置信度。
- [候选随账本变化失效] → 人工确认前重新校验候选 ID、工作区、活跃状态和关系类型；不允许绕过已保存候选选择任意流水。

## Migration Plan

1. 使用迁移入口增加 `candidate_fact_ids`，历史关系初始化为空列表；新关系检查会为新建待配对关系写入候选。
2. 用户可选择为本人账户添加 `account_identifier` 或 `card_tail` 别名；未添加时行为不变。
3. 回滚时恢复迁移前数据库备份；账户别名和原始事实不需要回填或改写。
