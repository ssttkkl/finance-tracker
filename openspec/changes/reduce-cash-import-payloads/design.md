## Context

当前客户端在本地生成完整写集，冻结原命令和结果归档材料，通过一次 POST 确认。服务端以精确 JSON 求命令摘要，在工作区锁内先查回执，再校验账本基线，最终在一个事务中保存事实、逐项结果和回执。回执里按命令顺序返回的 ID 和修订供客户端归档及恢复使用。

## Goals / Non-Goals

首次导入减少反复编码的来源覆盖信息；整批和混合重导减少完全重复流水的正文；大型 JSON 的传输字节与解压后的字节分别验收。业务结果、离线预览、确认与恢复入口沿用当前合同。本次范围限现金账单。投资导入、增量同步、解析结果复用和界面改版排除在外。

## Decisions

### 传输层独立协商

继续使用现有写集 POST。新客户端在冻结前用同源已鉴权的 OPTIONS 探测该路由支持的命令版本与请求编码，每个服务地址与登录会话缓存成功结果。旧服务无能力声明时新命令用普通 JSON；鉴权失败沿原流程处理。命令格式由 JSON 顶层版本判定，缺省为旧版；gzip 由 Content-Encoding 标识，代理和应用只由实际接收该编码的一层解压。压缩参数不参与命令摘要。

初始阈值取 16 KiB，仅在支持 gzip 且压缩后更小时发送压缩请求。回执（含按键恢复）、PDF/XLS 解析 JSON 和全量快照按 Accept-Encoding 协商 gzip，维护 Vary、私有缓存策略及正确的长度，已有代理编码时避免二次压缩。Web 使用浏览器协商响应编码并在 Worker 压缩请求；Android、iOS 在后台使用各端可用的 gzip 能力。无法编码时可用相同冻结正文的 identity 传输。小型版本查询、首次查回执的 404 和二进制文件上传沿用当前路径。

服务端同时限制输入流、产出 UTF-8 字节和逻辑展开预算。写集继续遵守 64 MiB 上限，解析响应继续遵守 25 MiB 上限。按块消费 gzip，越界即中止；未知编码返回 415、损坏流返回 400、大小超限返回 413，均在业务写入前。测试覆盖缺失 Content-Length、伪造声明、截断流、小字典被大量引用；记录字节计数、状态与耗时，不记录账单正文。

### 首次导入共享覆盖证据

首次请求的来源绑定占 1,179,617 B，流水占 571,865 B，账目占 228,564 B。紧凑版写集将绑定的 coverage 值放入批内 coverage_table，绑定保留原位置和身份，以从零开始的 coverage_ref 引用。按首次出现顺序确定索引，只合并完全相同的 JSON 值（对象键顺序无关，数组顺序和精确数字词形保留）。文件范围、来源键、策略、身份强度与绑定目标继续各自校验。解码器拒绝越界、歧义及非法结构，再交现有绑定校验与写入服务。服务端可共享只读值；逻辑展开预算按每次引用计费。仅压缩可以节省传输，却仍要求解析每个重复对象。

### 重导采用可还原的只读证明

客户端先生成现有完整逻辑命令。仅当已有流水及组成项、账目和成员在基线中可以逐字段还原为相同命令，且本次没有新增绑定、来源更新、人工编辑、关系或问题操作依赖该项时，才编码为重复项。其余逐项发送完整内容。允许一个批次混合两种表示；既有账户映射、依赖及其他操作继续按原合同提交。

每个证明携带流水和账目的原命令位置、工作区内已有 ID、期望修订，以及从**本次输入拟提交的完整逻辑片段**计算的 SHA-256。客户端与服务端共享版本化重建与摘要规则，覆盖父流水、全部有序组成项、来源原文、账目成员、人工覆盖和来源身份所需证据；保留 null、空值、精确十进制和数字词形。若字段不能从持久事实无损重建，则该项只能使用完整表示。禁止从旧快照单独生成摘要来代替本次输入。

在原工作区锁与事务中验证规则、基线、归属、修订，批量读取所引用事实，按相同规则重建并比对证明。原位置必须唯一且完整；拒绝重复占位和跨范围引用。把验证后的片段按原位置交给既有写入和回执统计逻辑，以保留 unchanged 结果、顺序、ID 和账本版本。对证据不符返回确定未提交并要求重新核对；只有既有基线冲突流程可以自动重算。仅发送一组重复 ID 无法发现备注、来源状态或组成项变化。

### 冻结、重放和回滚

恢复记录区分冻结的传输 JSON 与本地归档所需的完整逻辑材料。新版记录显式存命令格式及基线，旧记录缺省按原解码器读取。归档器使用冻结时的完整命令顺序匹配现有回执；本地保存成本单独计量。首次发送前原子持久化恢复材料。继续使用现有作用域和按键查询；404 后重放同一冻结 JSON，gzip 可重新生成。同键摘要取解压后的原命令规范 JSON，新版版本字段纳入摘要，旧版算法及既有回执摘要不变。回执命中先于基线与重复项重建，避免用最新账本解释已提交命令。

先发布服务端双读和响应协商，再逐端开启发送；代理验收须检查请求编码透传、身份、CORS（适用时）和响应是否已编码。回滚先关闭新命令生成和压缩发送，保留新版解码、回执和本地恢复能力直到所有待恢复提交可接续。不能证明冻结记录已清空时持续保留兼容读取；无需业务表迁移。

## Risks / Trade-offs

- 单纯删除回执映射会影响本地结果归档；本次保留回执字段，优先协商压缩。
- 重建会增加锁内工作量。优先复用已有事实读取并批量索引；测量全重复与混合批的查询次数、峰值内存和事务时长，避免逐行往返。两种后端分别验证同一服务的事务与回执等价。
- Web 保持主线程同步计算 P95 小于 50 ms。分别测冷、热缓存，报告压缩耗时、Worker 复制和端到端耗时，核对整个网络路径实际编码。若紧凑表示加 gzip 比单用 gzip 更大，应在冻结前选更小的已协商表示。

## 验收

同一月账单在独立的相同初始库分别跑旧版与新版。首次与全重导的解压 JSON 均须小于表中基线；协商压缩后两次上传各自至少比旧版未压缩减少 80%。对回执和全量快照核对解压等价及协商后的实传字节。分别报告两层大小、逻辑展开量、来源绑定占比和全重复项命中率；同版本回放另外核对原键返回原始回执。数字门槛是本样本的实施验收目标。

对齐 377 条首次流水、382 个批内重复、全重导零新增及版本不变。按稳定身份比较来源证据、金额币种、成员关系、回执逐项顺序和结果，允许独立数据库产生不同代理 ID。另测混合批、来源备注改变、人工覆盖、部分组件变化、同键异体、并发版本变化、跨工作区引用、响应丢失、升级恢复与上下限。Web 用真实浏览器记录传输，原生端编译并覆盖编码与恢复测试。
