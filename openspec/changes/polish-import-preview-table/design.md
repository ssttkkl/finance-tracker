## Context

本修复基于已合入 `origin/refactor/web` 的共享 `TransactionTable`。问题集中在共享组件的列数计算、导入状态 CSS 和两个场景的金额映射，不涉及 API 或持久化。

## Decisions

1. `TransactionTable` 的月份分组列数以实际固定列为准：基础列包含金额，因此分组行必须覆盖发生时间、账户、交易信息、流水类型、金额，以及可选的分类、状态、操作和选择列。
2. 导入状态仍由业务状态映射决定，但视觉改为带浅色背景、明确边框、最小宽度和半粗字重的状态标签；收入绿色、已存在使用主题蓝色、异常状态使用危险色，文字仍是唯一必要语义。
3. 在 `format.ts` 提供精确的零金额判断，先于收入 / 支出方向判断使用。仅匹配带可选符号、整数或小数且小数部分全为零的十进制文本，避免二进制浮点和误判。
4. 顶部四个摘要块改为按钮并作为表格筛选入口，使用 `aria-pressed` 表达当前筛选；筛选在前端基于预览行状态完成，并重新计算当前可见行的月份分组和月汇总。

## Non-Goals

- 不修改来源金额字符串、月汇总算法、导入摘要数量、后端状态判定或确认逻辑。
- 除摘要筛选外不新增交互，不新增字段、颜色 token 或页面结构。
- 不把筛选状态带入预览 / 确认请求；切换步骤或重新载入预览时恢复“全部”。

## Risks and Rollback

- 零金额方向改为 `unknown` 后不再展示方向颜色和箭头，但流水类型文字仍保留；回滚只需恢复金额映射和共享组件的列数 / 状态样式。
- 状态背景使用现有 Cobalt token，深色主题沿用 token 覆盖，不引入固定颜色。
