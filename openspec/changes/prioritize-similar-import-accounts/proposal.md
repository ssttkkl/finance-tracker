## Why

现金导入的“对应账户”下拉框目前是一张平铺列表。银行账户名称常带产品词和卡号尾号（如“建设银行储蓄卡(1234)”“建设银行(1234)”“建设银行”），用户需要在大量账户中逐条寻找同一家银行或同一张卡。把名称相似或已确认建议的账户优先集中展示，可以减少选择成本，同时不改动账户事实或映射语义。

## What Changes

- 客户端按来源账户显示名与已加载账户名称计算“建议账户”：规则匹配（银行主体相同/包含、卡号尾号兼容）与 Jaro-Winkler 模糊评分（≥ 0.75，较短主体至少 3 个字符）各自独立判定，满足一个即可。
- 双方都有 4 位以上卡号尾号且不同时 MUST 排除；已确认映射或别名建议的账户无条件排在建议组首位。
- 下拉框在存在建议账户时按“暂不选择 / 建议 / 其他账户 / ＋新建账户”分区，分区之间加分隔线，只有建议组以灰色小字“建议”开头；没有建议账户时保持现有平铺列表。
- 建议排序：完全同名 → 同银行同尾号 → 银行级账户 → 包含关系 → 模糊分降序；建议组不设数量上限。
- 只使用已经加载的账户列表与来源建议，不新增账户读取请求，不持久化排序或建议。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cash-ledger/cash-ledger-browser`：新增“导入目标账户优先展示名称相似账户”的下拉框行为与分区呈现。

## Impact

- 共享 Compose：`CashImportPreparation` 的下拉框选项构建、`ChoicePicker` 的可选分区标题、共享匹配函数与单测；Web 与 Native 同源。
- 文案：4 份 locale 新增“建议”分组标题。
- 后端与数据库：本变更本身无接口、字段或迁移变更；只消费同一 PR 的 `reduce-cash-import-account-round-trips` 新增的 `suggestion.account` 快照与 `accounts?view=cash`。
- 无新增依赖；Jaro-Winkler 在共享 Kotlin 内实现。
- 回滚：移除建议分区与匹配函数，恢复平铺列表；无数据回滚。
