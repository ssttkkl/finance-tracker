## Context

见 `proposal.md`。账户选择下拉框由共享 Compose 的 `CashImportPreparation` 构建，选项来自已加载的 `ImportAccountUiState.accounts`（`id/name/type/active/currencies`）与来源组 `ImportSourceAccount`（`displayName`、`suggestion`）。现有 `ChoicePicker` 只接受平铺的 `(value, label)` 列表；账户名称是用户自由输入，没有结构化的银行主体或卡号字段。

## Goals / Non-Goals

**Goals:**

- 在不新增请求、不持久化排序的前提下，把名称相似与已确认建议账户排到最前。
- 规则可解释、可单测；模糊匹配只作为补充，不淹没明显不同的账户。
- 复用现有 `ChoicePicker`，不复制下拉框实现。

**Non-Goals:**

- 不改变账户名称、账户事实、映射建议或选择语义。
- 不引入拼音、简称、英文行名或机器学习相似度。
- 不改变“合并同名账户”分组；建议只影响每个条目内部的目标账户下拉框。

## Decisions

### 1. 在共享 Compose 内计算，不新增接口

账户列表已经在进入导入页时加载；来源建议也已随会话返回。建议排序是纯展示派生，放在共享 Kotlin 的 `presentation` 层，Web 与 Native 共用，避免为一次下拉再发请求。

替代方案：服务端返回每个来源的候选账户列表。需要新增读模型与缓存失效规则，收益只是把一次纯本地的字符串匹配移走，不采纳。

### 2. 规则与模糊独立判定

先归一化：`trim`、小写拉丁字母、全角括号/数字转 ASCII、去空白；从原名称末尾或括号内取最后一段 4 位以上数字的后 4 位作为尾号（忽略名称中部的年份等数字；兼容 `6225****1234` 与带空格完整卡号）；去掉括号内容；按最长优先反复移除产品词；再移除残余标点与空格得到“银行主体”。

- 规则命中：主体相同；或一方包含另一方且较短主体长度 ≥ 2。
- 模糊命中：对主体再剥离 `中国/银行/分行` 等通用行名词后计算 Jaro-Winkler；分数 ≥ 0.75、较短原主体长度 ≥ 3，且两侧剥离后主体非空。
- 尾号硬过滤：双方尾号都存在且集合不同，直接排除。

Jaro-Winkler 在共享代码内实现（匹配窗口、转置计数、前缀加权 0.1、最多 4 个前缀），不引入依赖。对短中文主体，0.75 能容忍一个字差异，同时不会把“建设银行”和“招商银行”配到一起（两者共享“银行”但分数约 0.5）。

替代方案：只用编辑距离。对“建设银行”与“建设很行”可以，但对长名称和字符换位不如 Jaro-Winkler 稳定；只用包含关系会漏掉错字。

### 3. 排序与置顶

建议集合排序键：
1. 归一化完整名称完全一致；
2. 规则命中且尾号一致；
3. 规则命中且一方无尾号（银行级）；
4. 规则命中且主体包含；
5. 模糊命中，按分数降序。

已确认映射/别名建议的账户无条件插到第 0 位；若它同时命中规则，不重复。相同排序键按账户 ID 稳定排序。

### 4. 复用 `ChoicePicker` 的可选分区

给 `ChoicePicker` 增加可选的 `sectionOf: (String) -> ChoiceSection?`：
- 返回 `key` 与可选 `label`；相邻选项 `key` 变化时插入 `HorizontalDivider`；
- `label` 非空时在分区开头渲染灰色小字，使用 `labelMedium` + `onSurfaceVariant`，加 `heading()` 语义；
- 分区标题不是 `DropdownMenuItem`，不进入选项的焦点/选择序列，避免读屏把它读成可选项。

调用方只在存在建议账户时传入分区函数：
- `""` → `none`
- 建议 ID → `suggested` + “建议”
- 其余 → `other`
- `CashImportCreateAccountOption` → `create`

没有建议时传 `null`，`ChoicePicker` 行为完全不变。

### 5. 建议来源与合并条目

每个来源条目使用 `ImportSourceAccount.displayName` 计算；合并同名条目使用首个成员的 `displayName`。已确认建议取该条目成员的 `suggestion.accountId`，若成员建议不一致则不置顶（保持用户已有多选状态）。

### 6. 文案与无障碍

4 份 locale 新增 `cash_import_suggested_group` = “建议”。分组标题加 `heading()`；选项的 `contentDescription` 仍由可见名称提供，不额外朗读“建议”。下拉框的键盘导航、Escape、滚动行为沿用 `ChoicePicker`。

## Risks / Trade-offs

- **误报**：模糊阈值过低会把不同银行排进建议组。→ 尾号硬过滤 + 较短主体至少 3 字 + 0.75 阈值；单测覆盖“建设银行/招商银行”“建设银行/建设很行”边界。
- **漏报**：简称（建行/建设银行）、拼音、英文行名不匹配。→ 明确非目标；包含关系与模糊只覆盖常见变体。
- **菜单变长**：建议组不设上限。→ 建议组只收窄候选，不复制全部账户；用户明确要求不限制。若后续反馈过长，再加“最多 N 个”的独立规则。
- **计算开销**：每次重组对每个来源条目与账户列表做 O(S×A) 字符串比较。→ 账户与来源数量都在导入上限内（文件 ≤ 20）；用 `remember(matchName, accounts, suggestedAccountId, targetAccountId)` 缓存每个条目的结果，避免滚动时重复计算。
- **已确认建议不在账户列表**：账户可能停用或类型变化。→ 现有过滤已包含当前选中账户；建议账户若非当前选中且不合格，不强行加入选项，避免展示不可选账户。

## Migration Plan

- 纯客户端展示变更，无接口、存储或迁移。
- 回滚：移除分区函数与建议计算，恢复平铺列表；已加载账户与映射不受影响。
