## Why

收支账本虽然已有一个历史 `category` 字段和自由文本编辑入口，但该字段仍混用旧收入、支出与转账语义，无法表达由使用者维护的多级收支分类，也无法支持一致的筛选、批量归类和后续 AI 分类识别。需要把流水类型与收支分类彻底拆开，并在 Web 中形成“维护分类目录—单笔或批量归类—按分类树筛选”的完整闭环。

## What Changes

- 新增工作区级分类管理页和最多 5 层的分类目录；支持创建、编辑名称与描述、移动、同级排序和受控删除，父分类与叶子分类均可分配给收支详情。
- 收支账本新增分类列、树状分类筛选、无分类筛选、详情分类查看与修改，以及明确勾选已加载条目后的批量修改分类操作。
- 一笔收支详情的全部现金流水共享同一收支分类；投影从展示基准流水读取分类，建立关系时静默采用展示基准流水分类并同步全部现金成员。
- 删除已使用的叶子分类前提示影响数量；确认后相关流水改为无分类。有子分类的节点不得删除。
- **BREAKING**：执行一次保留财务数据的 schema 与数据重建，删除旧 `category` 列及其全部旧值；新增 `cash_transactions.category_id`、分类目录物化 `category_path` 和投影派生分类字段。所有既有流水升级后均为无分类。
- **BREAKING**：移除旧分类 API、筛选参数和响应兼容逻辑；导入、关系、报表和查询中的收入、支出、转账等业务判断只使用 `record_type` / `record_subtype`。
- 分类描述作为未来 AI 分类识别的受控上下文；本 change 不调用 AI、不保存模型结果或置信度，也不允许 AI 覆盖用户分类。
- 分类管理和账本分类交互按当前任务最小展示；正常状态不使用常驻帮助文案，不向使用者暴露投影、分类 ID 路径、后端或未来 AI 等实现信息。

### Scope

- 分类目录领域规则、Application Service、双后端持久化、一次性数据重建和 Web API。
- 收支投影分类派生、关系建立时的分类同步、父分类后代筛选、单笔与批量分类。
- 分类管理页、收支账本分类交互、响应式、键盘操作、生产预览和 UI 审计。
- UI 信息架构、文案预算、1440 px / 390 px 截图审查和实现术语静态检查。
- 新增性能门禁：分类目录、分类筛选、删除影响、单笔 / 批量分类及其 Web API 使用固定去标识化夹具，在 SQLite 与真实 PostgreSQL 上分别验证查询次数、P95 响应时间和场景 RSS 增量。

### Non-goals

- 不实现 AI 分类识别、自动分类、分类建议、置信度或模型调用。
- 不提供批量删除、批量关联或其他批量字段编辑。
- 不提供“选择全部筛选结果”；首期只处理使用者明确勾选的已加载收支详情。
- 不保留旧 `category` 值、旧 schema、旧 API 或旧应用版本兼容路径。
- 不增加分类颜色、图标、预算、报表规则或跨工作区共享分类目录。
- 不把性能门禁变成生产环境持续采样或线上压测；本 change 只增加可重复的发布前基准与查询复杂度保护。

## Capabilities

### New Capabilities

- `cash-category-management`: 工作区分类目录、收支详情分类一致性、单笔与批量分类、受控删除和分类写入并发合同。

### Modified Capabilities

- `cash-ledger-browser`: 列表、详情和筛选改用树状收支分类，并新增明确选择与批量分类交互。
- `ledger-records`: 现金流水以可空 `category_id` 引用工作区分类目录，旧 `category` 业务值不再属于账本记录合同。
- `cash-record-classification`: 导入边界只生成 `record_type` / `record_subtype`，不得把来源分类或旧方向值写入用户收支分类。
- `transaction-relations`: 关系进入已确认状态时，以展示基准流水分类原子同步关系投影中的全部现金流水。

## Impact

- 影响关系型模型与迁移、现金流水仓储、导入与查询、收支投影、交易关系 Application Service、Web API、React 页面、测试和 OpenSpec artifact。
- 不新增第三方依赖；分类目录和全部写入均保持工作区隔离，SQLite 与 PostgreSQL 使用同一 Application Service 和等价合同。
- 性能基准使用固定规模夹具：1,000 个分类节点、10,000 条流水、最多 5 层分类树、100 个批量投影和 10,000 条删除影响引用；阈值以查询复杂度为硬门禁，并为本地 CI 机器设置稳定的 P95 与 RSS 上限。
- 数据升级保留账户、现金流水、来源、关系、校准和其他财务字段，但有意丢弃旧 `category` 值并重建全部收支投影。
- 新旧应用与 schema 不兼容；发布必须配套升级并在升级前备份，回滚只能恢复升级前备份或前向修复。
