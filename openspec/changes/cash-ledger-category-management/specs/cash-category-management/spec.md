## Purpose

定义使用者在工作区内维护多级收支分类、为整笔收支详情设置或清除分类，以及安全删除和批量修改分类时的完整行为，使分类独立于流水类型并可作为未来 AI 分类识别的受控目录。

## ADDED Requirements

### Requirement: 工作区提供可维护的多级分类目录
系统 MUST 为每个工作区提供独立的分类目录。使用者必须能够创建顶级分类或子分类，并编辑名称、分类描述、父分类和同级顺序；父分类和叶子分类都必须可以直接分配给收支详情。分类名称最多 40 个字符，分类描述最多 500 个字符，分类树最多 5 层。

#### Scenario: 创建可分配的父分类
- **WHEN** 使用者创建顶级分类“餐饮”并在其下创建“工作餐”
- **THEN** “餐饮”和“工作餐” MUST 都能被选择为一笔收支详情的分类

#### Scenario: 拒绝超过层级上限
- **WHEN** 使用者尝试在第 5 层分类下继续创建或移动子分类
- **THEN** 系统 MUST 拒绝操作，且分类树和既有流水分类不得发生部分变化

#### Scenario: 跨工作区引用父分类
- **WHEN** 请求尝试把当前工作区分类移动到其他工作区的父分类下
- **THEN** 系统 MUST 拒绝操作，且不得泄露目标分类是否存在

### Requirement: 分类身份、路径和树约束保持稳定
每个收支分类 MUST 具有不随名称和位置变化的稳定分类 ID，以及由稳定分类 ID 组成的分类路径。同一父分类下的规范化名称必须唯一；移动不得形成环。重命名或移动分类必须保留全部流水的分类 ID，并立即更新分类目录、分类选择器、筛选器和收支账本中的可读路径。

#### Scenario: 移动已使用分类
- **WHEN** 使用者把已有流水使用的“工作餐”从“餐饮”移动到“工作”下
- **THEN** 相关流水 MUST 保持同一分类 ID，并在后续读取中显示“工作 / 工作餐”

#### Scenario: 创建同级重名分类
- **WHEN** 同一父分类下已经存在规范化名称相同的分类
- **THEN** 系统 MUST 拒绝再次创建或重命名为该名称，但其他分支可以使用相同叶子名称

#### Scenario: 移动形成分类环
- **WHEN** 使用者尝试把一个分类移动到自身或其后代分类下
- **THEN** 系统 MUST 拒绝操作，且不得改变任何分类路径

### Requirement: 分类删除先处理子分类和使用影响
有子分类的分类 MUST 禁止删除。删除没有子分类但已被流水使用的分类时，系统必须先返回当前工作区内直接使用数量；只有使用者基于当前分类版本确认后，系统才能把全部直接引用改为无分类并删除该分类。影响数量或分类版本在确认前变化时必须拒绝旧确认。

#### Scenario: 删除有子分类的分类
- **WHEN** 使用者尝试删除仍有直接或间接子分类的“餐饮”
- **THEN** 系统 MUST 拒绝删除，并要求先删除或移动全部子分类

#### Scenario: 删除已使用的叶子分类
- **WHEN** 一个叶子分类被 12 笔收支详情使用，且使用者确认当前影响数量
- **THEN** 系统 MUST 原子地把相关现金流水改为无分类、发布匹配的新投影并删除该分类

#### Scenario: 删除确认已经过期
- **WHEN** 使用者确认删除前又有流水采用该分类或分类版本发生变化
- **THEN** 系统 MUST 不执行删除，并返回新的影响信息供使用者重新确认

### Requirement: 一笔收支详情共享一个收支分类
系统 MUST 允许一笔收支详情设置任意可用分类或无分类。分类写入必须以当前投影为边界，把相同 `category_id` 原子写入该投影的全部活动现金流水；投影必须从展示基准流水派生 `category_id` 和分类路径。分类不得改变金额、流水类型、关系或财务汇总。

#### Scenario: 修改关系投影分类
- **WHEN** 使用者把包含多条现金流水的收支详情改为“餐饮 / 工作餐”
- **THEN** 该投影的全部活动现金流水 MUST 引用同一分类，投影与详情必须显示同一路径

#### Scenario: 清除分类
- **WHEN** 使用者把一笔已有分类的收支详情改为无分类
- **THEN** 该投影的全部活动现金流水 MUST 使用空 `category_id`，且分类目录不得创建“无分类”节点

### Requirement: 批量分类只处理明确选择且保持原子
系统 MUST 只对使用者明确提交的有限投影 ID 集合执行批量分类，不得把筛选条件隐式解释为选择全部结果。批量请求必须绑定当前投影版本；任一投影失效、隐藏、跨工作区、不存在或不再属于该版本时，整批操作必须失败且不得写入部分结果。

#### Scenario: 批量设置分类
- **WHEN** 使用者明确选择 8 笔已加载收支详情并提交同一分类和当前投影版本
- **THEN** 系统 MUST 在一个事务中更新这 8 笔收支详情的全部活动现金流水，并发布一致的新投影版本

#### Scenario: 批量请求包含过期投影
- **WHEN** 任一选中投影在提交前因账本或关系变化而失效
- **THEN** 系统 MUST 拒绝整批请求，保持所有选中流水原分类不变，并要求重新读取列表

### Requirement: 分类目录和分类写入保持双后端等价
PostgreSQL 与 SQLite MUST 对相同工作区、分类目录、现金流水、关系、投影版本和分类命令返回等价的树顺序、分类路径、影响数量、写入结果和错误合同。分类 ID、路径和错误不得因数据库代理键或排序规则差异而改变。

#### Scenario: 比较双后端分类合同
- **WHEN** 两个后端使用相同去标识化夹具执行分类创建、移动、删除、单笔分类和批量分类
- **THEN** 除数据库内部代理键外，分类目录、流水引用、投影结果、顺序和错误合同 MUST 等价

### Requirement: 分类管理界面保持任务聚焦
分类管理页 MUST 只在正常状态展示完成分类查找、创建、编辑、移动、排序和删除所需的控件与用户数据。页面不得展示投影、分类 ID 路径、数据库规则、未来 AI 用途或其他实现说明；不得为每个字段放置常驻帮助文字。使用数量只在删除确认需要表达实际影响时显示，有子分类时删除操作必须不可执行并通过按需状态说明原因。

#### Scenario: 正常浏览和编辑分类
- **WHEN** 使用者打开已有分类的分类管理页并选择一个分类
- **THEN** 页面 MUST 展示分类树、名称、上级分类、描述、顺序和保存操作，且正常状态不得出现教学区或字段说明段落

#### Scenario: 从分类列表末尾新建一级分类
- **WHEN** 使用者点击分类列表最后一行的“新建一级分类”
- **THEN** 页面 MUST 打开新增分类编辑区并将上级分类设为无；分类管理页页头不得显示另一个一级分类新增入口，且新建成功后该项 MUST 继续位于分类列表最后

#### Scenario: 删除已使用分类
- **WHEN** 使用者启动删除一个已被使用且没有子分类的分类
- **THEN** 页面 MUST 在二次确认中显示受影响数量和改为无分类的结果，且不得在未启动删除时常驻显示该影响说明

#### Scenario: 输入不合法
- **WHEN** 使用者提交空名称、同级重名或超过层级限制的分类修改
- **THEN** 页面 MUST 在相关控件附近显示可执行的错误信息，并在修正后移除错误信息
