## Context

本次仅实现和验收后端；Compose 接入、页面及客户端 QA 留给后续任务。字段权限与稳定收支对象按功能范围交付，万行导入预览性能优化独立处理，不作为本次功能交付的阻断项；原性能预算不调整，未达标结果不计为通过。未实现的 UI delta 不同步，整个变更不提前归档。

行为输入为 [主设计](../../../docs/cash-import-redesign.md) 与 [跨层契约](../../../docs/cash-import-redesign-contracts.md)。来源流水及资金分配保存在 `cash_transactions`、`cash_transaction_components`，当前关系保存在 `transaction_relations`，公共属性由稳定收支对象持有，投影按受影响闭包维护。导入采用限时解析会话、不可变计划和一次确认，不保留原文件；公开编辑使用当前维护计划及统一约束。

## Goals / Non-Goals

本变更实现 proposal 所列九项能力；以服务端计划和共享 Compose 流程承载统一合同。历史数据保持其身份、金额、账户和来源，当前角色明确校验；不建设历史版本链，不自动全库重配，不将真实账单写入 Git。外部账单可在专用临时测试库读入，日志仅输出计数和安全失败分类。

## Decisions

### 1. 固定创建方式与稳定收支对象

`cash_transactions.record_origin` 由真实创建入口确定且不可修改：`import`、`manual`、`manual_transfer`、`legacy`。历史缺少可靠创建证明时使用 `legacy`，沿用导入权限，不能猜成手工而扩大权限；现有明确 `manual.transfer.v1` 的双端记录可回填 `manual_transfer`。新手工入口不由来源文本决定创建方式。普通手工流水禁止现金配对及现金—投资关联；手工转账仅允许自身双端关系，不参与后续扫描。

导入正式流水的用户编辑白名单为 `category_id/note/counterparty/counterparty_account/counterparty_account_attrs`，类型及财务字段固定；来源原文只能通过来源更新路径写入。草稿可补齐合法业务字段。手工流水可修改合法业务字段，财务变更须重新校验完整字段、账户及币种、组成项守恒，并按前后资金记录更新余额；系统身份不开放。

`cash_entries` 是稳定收支对象，保存公共属性、逐字段人工标记及修订；`cash_entry_members` 保存当前成员。单条和合并使用相同编辑合同，来源父记录不接收公共属性的批量回写。现有 `cash_projections` 仅保存可重算的列表／统计结果并关联稳定对象；全量数据集替换不删除稳定对象。公共字段未被人工修改时采用展示基准的当前来源值；人工清空与未设置必须区分。

局部维护仍按旧投影成员与新确认关系迭代到闭包稳定。成员不变的组保留稳定对象及派生行，只更新变化列；关系成员按差量更新。显式全量重建允许替换计算数据集，但必须保留稳定对象和人工字段；不得以可丢弃投影行承载唯一人工事实。整笔公共属性编辑不改金额、不重新配对，不扩散至闭包外。

合并逐字段归并已有人工值，包括清空；唯一人工值优先，没有人工值时采用展示基准。不同人工值冲突时整个必要依赖关系组保持待确认，详情返回冲突及允许的公共值选择，不阻塞其他流水。确认选择与整组关系同一保存点。解除关联的请求若涉及人工公共值，必须明确 `inherit_common_fields`；选择继承则写入拆出各收支对象，不继承则保留其各自值。未确认关系不共享对象或公共值。普通手工与导入之间不增加去重、合并或提醒机制。

稳定对象使用不依赖数据集的随机 `entry_id`。合并优先保留展示基准所在对象；被合并对象的当前独立字段及人工标记保存在每条当前成员的 `standalone_values`，仅保留一份当前恢复值，不建立版本链。拆分时包含原基准的结果优先保留对象 ID，其余结果创建对象；不继承时从各自成员恢复值取公共值，继承时把原公共人工值应用到拆出的对象。重导只刷新未人工修改的恢复值。迁移既有已确认组时保留原展示公共值，各成员不同人工值进入恢复值，不解散关系或丢弃人工内容。

公共写入使用稳定对象 `entry_id/revision`，在工作区锁内重验成员集合与对象修订，幂等收据与属性、资金记录、余额及派生更新同事务。既有维护计划冻结所涉对象及成员摘要，确认前重验；公共编辑不依赖来源父记录修订推进。批量分类同样写对象而不回写成员。合并冲突延后完整必要关系提交组；明确公共值及拆分继承选择进入不可变计划，并在同一关系保存点应用。

删除工作区时，在删除分类与来源父记录前显式删除该工作区的收支成员和收支对象，避免公共分类的限制外键阻塞整体清理；其他工作区的对象、分类和结果不受影响。

导入同一已合并对象的多条来源若携带相同或互补公共补丁，按对象归并为唯一公共写入，相关来源操作在同一必要保存单元内重验和保存；显式同字段冲突拒绝不一致输入，不按遍历顺序覆盖。已通过锁内重验后写入失败的操作仍保留弱来源对应的重试证明。普通公共编辑只改变对象修订，不使未变化的来源父修订或候选过期。

计划单项详情通过 `entry.fields/editable_fields` 表达预计公共属性，来源成员字段与用户公共值分开；从任意成员进入均返回同一整笔决定。完整手工转账使用 `edit_entry.member_patches` 原子修改双端及内部关系；缺少合法内部双端时保守关闭单端财务权限，不能以拆分后的单独对象绕过。失效关系选择的私有恢复上下文保留经过公共字段与类型校验的 `common_fields`，不保留可执行关系或来源正文。

迁移新增稳定对象和成员，保留已存在的流水及关系身份；从当前投影和人工保护回填当前值，不篡改来源原文。缺证创建方式保持 `legacy`；降级遇到新增人工公共值、可编辑手工财务数据或无法无损映回的结构时拒绝，须恢复升级前备份。SQLite 和 PostgreSQL 使用相同服务、精确 Decimal 与事务边界，无新增依赖。真实账本和部署不在本次授权内。

### 2. 来源对应与草稿问题

增加当前 `cash_source_bindings` 与必要候选问题，可靠编号按来源账户作用域绑定，无编号只用经验证的完整范围与多重集合规则。未知来源账户使用非空文件局部作用域，补全后保留别名。既有活动记录优先，删除记录不参与命中；来源变化只更新白名单，不复活旧人工决定。歧义只保存当前问题，不复制正式账务。

实施勘查补充：现有六种来源没有输出可信覆盖范围；首末交易、文件名、解析计数均不能充当完整性证据。新解析结果明确携带来源账户、范围／筛选／边界及证据，缺少时为 unknown。旧 `record_id` 混用平台交易号、商户订单号和内容散列，不直接回填可靠编号；只采用来源明确认证的渠道编号。内容散列仅用于内容比较，原始出现次数必须在进入现有跨行去重前保留。来源所属账户与资金渠道／内部映射分开，不能用银行卡尾号或商户账号替代完整本方身份。

来源对应先实现独立规划器和事务内存储，再在解析会话接入。规划器按文件分别消耗旧候选；同一稳定候选集合整体评估，只有无变化的多重集合、互为唯一且证据可比的更新或结果等价时自动对应。未知范围仅实际碰撞项延后，不把首次无候选的新记录一律变草稿；同文件定位绑定覆盖重复上传和草稿合并后的幂等。来源技能的旧“导入不写关系／映射失败阻断”段落由本变更明确取代，本步仅复用来源字段及校准方法，不改既有分类语义。

来源当前绑定额外保存可空的 `stable_evidence_key` 并建立工作区索引，确保已认证的固定逐行证据经过持久化后仍能命中或排除，不依赖可丢弃的内存属性。该键只由适配器明确认证的证据生成，不采用旧内容散列。渠道编号、认证行证据及已知目标别名共同确定批内冲突范围，不能只检查优先证据而让另一条覆盖同一对象。旧正式记录若缺少可证明的来源账户，仅同固定特征的实际碰撞延后处理，不伪造账户、不自动复制正式记录。候选集合本身改变时也推进当前问题修订，确认版本覆盖正文及候选，不保存历史链。

多文件共同规划先归并同文件定位、可靠编号、认证证据及已知目标的确定对应，联合发现冲突后再规划写入，不按文件先后覆盖。同一文件重复上传仍逐来源行返回结果，但每个真实出现只规划一次。无编号且范围可比的重叠集合，只有各文件集合完全相等，或全部内容一致且仅次数不同，才合并为共同集合；每种内容保留的次数不小于任一文件的次数及已证明不同的可靠身份数。内容比较只证明集合结果等价，不充当跨文件身份。不同快照不能贪心相减；范围不足或非等价变化只延后实际碰撞的弱证据行，可靠独立身份及其他正常集合继续。

共同集合交给同一更新策略，每个当前目标只消耗一次。共同集合中的明确对应可保存别名；不能确定单笔归属的批内重复只引用等价结果集合，不新增流水或任意绑定某条旧流水。解析桥接保留会话 `row_ref` 与内在文件定位两层引用，计划通过共同结果引用归并 `operation_ref`，最终逐行结果不丢失。此步仅完成后端规划及输入组合，发布计划、保存点与 HTTP／Compose 切换仍分别由 4.8–4.12 验收。

共同操作保留各行提供的联合身份和已知目标，不能只选首行重新识别而丢失证据。已识别但冲突的身份仍参与碰撞检查，不能因跳过它而把同范围相撞的无编号行当成独立新增。等价结果及大候选集合使用计划内共享集合引用，逐行不展开整个集合；集合只描述共同处理范围，不声明集合中每一对行都是同一身份。相同内容的大量出现必须保持线性结果体积，纳入解析内容及完整计划的独立字节预算验收。

### 3. 一次解析、不可变计划与收据

新增解析行会话存储接口，复用受控临时存储能力但不调用旧保存原文件行为。服务端解析上传流后立即关闭并清理，逐文件及逐行分离错误。计划只包含服务端验证的操作、预计列表、候选选择和修订；客户端仅传选择及补丁。解析和计算可在工作区锁外，发布、文件修改、取消及最终消费在同一工作区同步边界重验；不只依赖对象存储 CAS。

计划发布层与业务计算分开验证：发布层只接收服务端构建器，不接受客户端操作图，将完整替换的选择、完整计划及递增修订放进同一个解析会话 CAS 对象；计算失败或超预算不损坏原计划，TTL 不续期。计划标识包含可定位的随机会话部分及独立随机实例部分，所有读取仍重验实际成员、用户／工作区归属和当前计划，不用全局计划索引或数据库表保存临时内容。普通列表只返回预计投影字段，操作图、解析正文及详情按需读取；列表与处理明细游标绑定计划、类型及筛选，默认 50、最多 200 项，提交不消费分页子集。重预览、文件变化、取消和过期都使旧计划不可执行；消费收据在临时对象之前读取。该层先内部接入，业务投影、配对与联合写入仍须完成后才切换 HTTP／Compose。

提交先查持久收据，再取最新计划。一个外层事务持有工作区写锁；每条流水或配对提交组用保存点，回滚后重载 ORM 与余额／标识缓存；最后持久收据、实际结果与投影一起提交。后续同键返回原结果，不重跑失败项。临时失败重试内容须在提交前准备，提交后凭收据访问，原 TTL 到期清理；无内容要求重传。核实未知结果在同锁内确定，禁止把收据 404 当未提交。

批量预览性能保持既有万行／5 s／256 MiB 预算。切换时发现当前流程万行预览超限，先依据独占剖析消除单次调用内部重复复制、重复计算不可变来源身份及逐项扫描全部旧关系；候选读取可先按同一工作区和来源检查是否有实际旧目标，空集合不继续按键分批查询。超过单片预算的大批量绑定查找，在本工作区没有任何绑定时跳过空分片；单笔查询仍使用完整身份索引。来源证据未增加及联合身份未改变时复用本次已准备对象；完成逐行规则、传递身份归并、页面冲突及多文件次数检查后，若活动旧记录集合为空，规范单元直接得到新建决定，不重跑已完成的单文件匹配；后续重复／待处理展开保留，有旧记录及公开单文件匹配仍用原算法。已序列化的操作不重复转换，快照只恢复计算所需的财务类型，来源原文只读复用。详情验证只读取叶子值，仍单独复制会被修改的成员和组成项容器。对外返回与暂存之间仍保持对象隔离，解析内容、完整计划的安全检查及 CAS 不缩减。计划发布不需要回传完整会话：将元数据的编码／解码校验归于同一验证器，在写入前完成相同结构、页面证明、嵌套深度和字节预算检查；不要求返回会话的发布只写经过验证的编码，后续读取仍走完整解码校验，避免为被丢弃的返回值再物化一份完整计划。编码按有界容器块生成同一份 JSON 字节，避免完整 Unicode 字符串与多份正文同时驻留；优化后重新运行两种后端的原始固定场景，不以剖析耗时代替验收。

旧收据切换（4.11.4.3）先清理已退出公开合同的旧现金导入及原文件会话实现，将仍使用的会话异常移到独立错误模块，不保留可恢复原文件的兼容工厂。原文件暂存／会话模块及旧现金导入方法明确退出；旧性能场景迁至当前服务，千行重复／更新和万行预览的原预算不降低。现金手工新建、当前删除和独立投资导入继续保留；停用旧写入并作废旧临时上下文后，再以迁移将 `cash_import_commits` 合入统一收据，最后移除旧表、模型及工作区清理引用。开发仅操作专用测试库；既有外部原文件对象的清理需在发布时按精确命名空间另行授权，不能把代码删除当作远端对象已经清除。

迁移保留原收据 ID、工作区、用户、原幂等键和创建时间，操作种类为 `legacy_import`。原 `new_rows/updated_rows/mapping_saved/skipped_rows` 仅按确实存在的整数值进入 `summary`，保留原名，不换算成新流程的正式／草稿计数；原 `by_account` 的历史账户名及处理计数保留为安全的 `legacy_by_account`，不猜测当前账户 ID，也不改称新增数或要求合计等于 `new_rows`；该映射只接受文本名称和非负整数，并服从统一摘要大小上限。没有稳定逐项 ID，因此结果分页为空，不伪造行、关系或新计划，不生成失败重试正文。旧消息、文件名／摘要、原始技术字段不进入新永久结果。缺失状态不推断完成类型；`committed` 只来自已有持久提交事实。

旧 `session_digest` 不是新上下文消费证明，同一旧摘要可对应多个合法旧键，因此不填新 `session_digest/edit_context_digest/plan_id`。请求摘要按旧收据身份生成带命名空间的不可逆标识，仅用于保留键的冲突边界，不参与来源识别。迁移先全量有界预检原结构、真实非负计数及目标 ID／工作区用户键碰撞，再按批复制并删除旧表；坏摘要或冲突整次拒绝，不能重命名键、丢弃原结果或部分迁入。迁移不改流水、关系、来源绑定或余额。

旧幂等键只要求非空及长度，新写入仍沿用严格字符约束。读操作使用单独的有界键查找校验，重放及新写入继续使用原严格键校验，不扩大重放规则。读取补 `GET /cash-mutations/receipts/by-key?key=...`，在原用户及工作区内按原字符串精确查找，支持旧键中的斜杠／Unicode，不修剪或重写；保留已提供的路径式查询。两种查询的键及查询串均从应用访问日志脱敏，反向代理另按部署配置处理。通过 ID、键或结果分页都只返回白名单摘要；旧收据不能用于派生新导入会话；原用户请求派生时返回已有的 `retry_context_unavailable`（410），归属不符仍返回 404。

旧收据迁入后已主动去掉不属于永久结果的技术正文，降级无法还原，存在 `legacy_import` 收据时必须在任何 DDL 前拒绝有损降级；不存在旧收据时可恢复空的原表，保留新收据。发布优先前滚修复；若确需恢复迁移前完整数据库，必须使用另行授权的备份恢复，不能删除收据以绕过门禁。验证覆盖两个真实后端、多个旧键共享摘要、特殊旧键、空／有数据升级降级、ID／键碰撞、坏摘要、回滚及工作区删除；中间第 40 版的旧表保留测试仍按该版本合同执行。

未知结果核实使用非阻塞工作区锁；只有明确的存储锁忙才返回 `pending`，连接故障、查询取消及其他存储异常仍传播为尚无法核实，不能伪装未提交。普通写命令的等待合同不变：核实创建独立 UoW，PostgreSQL 使用 `FOR UPDATE NOWAIT`；SQLite 只在该连接取得写锁时暂设零等待，随后恢复原 `busy_timeout`，不污染连接池。适配层优先按原生错误码识别 PostgreSQL `55P03` 和 SQLite `BUSY/LOCKED`（含扩展码），有原生码时不依赖可变错误文本；仅无原生码的兼容驱动保留原文本回退。PostgreSQL 代码依据 [官方 SQLSTATE 表](https://www.postgresql.org/docs/16/errcodes-appendix.html)，实际独立连接持锁覆盖两后端的 `pending → retry_original/committed`；PG 测试显式关闭 `lock_timeout`，不能依赖测试环境超时掩盖无限等待。

收据基础先新增 `cash_mutation_receipts/cash_mutation_results`，旧导入表暂时只供未切换的旧服务使用；最终切换时迁入旧结果并移除旧表，不保留两个正式入口。新收据按工作区、用户、幂等键唯一，并分别对非空会话／编辑上下文摘要设消费唯一约束；请求摘要覆盖操作种类、计划及提交携带的会话修订。结果表按收据、种类及项引用唯一，保存计数、安全原因及稳定引用，不保存来源正文或完整差异；目标引用可在对象以后删除后保留，只有收据归属使用复合外键。普通账户命令同用该设施。`RelationalUnitOfWork` 在 PostgreSQL 进入时即锁工作区行，SQLite 沿用先开始写事务；所有变更先取得同一边界，再查询消费状态或改写数据，不能等投影发布时才补锁。

联合提交在锁内用相同解析内容、完整选择及原计划重新只读计算；逐流水按内在出现匹配，不依赖可能变化的数组位置或 `operation_ref`。核对当前值、完整组成项、流水及问题修订、账户资金资格和来源对应，变化只使相关决定跳过；不以全批上下文令牌拒绝其余行。关系建议身份还包括局部旧闭包结构、资金占用、问题和发现证据，自动确认及用户选择都必须仍对应原建议，不采用重算产生的新对侧。已有草稿问题和来源别名随该条流水同保存点生效。

每条流水保存点只修改该流水、必要旧关系及当前问题；成功前后值收集到事务内结果，不提前改余额缓存。导入正式类型固定；手工转账内部双端修改先验证完整最终图，失败整体回滚。关系按最终选择重新组织保守提交组，同组全量验证、写入及失败回滚；回滚后清除 ORM 加载状态，内存身份映射只在保存点成功后更新。所有局部决定结束后按成功前后值统一应用余额，再发布旧、新受影响闭包的当前投影，最后同事务写收据。连接失效、全局投影发布或收据持久化失败属于外层失败，不能返回局部成功；可恢复的单条约束或业务错误只保留安全原因。

认证空页按渠道、解析命名空间及导出标识组织保存点；失败时按来源固定索引、明确目标和候选记录的证据依赖阻止相关来源决定，不因同渠道而跳过其他无关文件。重算使用锁内当前证据，但不能继续执行依赖未成功保存的新空页的决定。没有原始内容的长期结果只保留稳定引用及原因；限时解析资料在原 TTL 内可供已提交收据派生失败子集，重新提交必须使用新计划、新键。

独立预审补充：关系组依赖每条必要流水的实际成功，失败／跳过后不允许用旧同 ID 流水补位；批内重复同样依赖共同操作和全部必要别名保存成功。`begin_nested()` 之前不得留下待刷业务修改，实际 `flush()` 必须在保存点内。失败关系不作为非法草稿保存，回滚后另存当前安全问题；必要问题也无法可靠保存时整体回滚。收据摘要只保留计数和发布版本，稳定目标引用进入分页逐项结果，不建立随最大批次增长的摘要数组。失败重试只复制失败逻辑操作的必要解析行和证明，不复用保留成功正文的原会话；由持久收据限定访问及范围，原 TTL 不延长。

并发期间其他会话已保存完全相同内容时，只在可靠对应及完整值等价的情况下返回重复；必要的新来源别名仍在行保存点保存，不改当前流水、人工保护或关系。关系重复要求完整端点方向、角色、精确分摊、锚点、证据、候选及当前完整决定组等价；金额或决定变化仅使该组待处理，不覆盖当前确认。写入计数按唯一操作，重复／跳过计数按原始出现。文件失败参与部分完成判定，正常白名单跳过不当作失败。提交后原会话一律尽力清空，已消费收据同时阻断正文访问；清理失败不改变已提交事实，原 TTL 清扫物理残留。有可重试项时，收据仅保留独立失败上下文引用及原到期时间。

#### 3.1 失败子集的隐私、次数证明与派生

解析暂存增加仅由服务端设置的上下文种类及有界内部资料，区分普通导入、派生重试和收据专用失败上下文；旧对象缺字段按普通导入读取。公开文件／计划入口只接受普通导入或派生重试，不能凭失败上下文 ID 读取或改写其正文。失败上下文在业务事务提交前另存，只有同一工作区及操作者的持久收据授权派生；外层回滚产生的孤儿不可访问，只按原 TTL 清理。它只含可重试失败逻辑操作、该操作全部必要失败别名、失败行选择及所需账户选择，不复制成功行正文、完整原计划或旧关系选择。创建与派生继承原创建／到期时间，读取、编辑、反复派生均不延长 TTL。

失败文件元素显式标记为来源子集，保留原摘要、解析命名空间、物理行和认证位置用于确定对应；子集不是另一份完整导出。所有来源组合、完整性提升和空页保存都检查该标记：不授予子集完整范围，不把省略的成功行推断为空页，不因页摘要齐全再次认证子集。已保存的独立认证证据仍可用于冲突核对和当前旧记录，但不能证明当前子集的出现次数。普通文件不同物理位置可在弱对应阶段排除同笔；该互斥证明不能推翻相同可靠编号的共同对应。

仅降为未知完整性不足以保证数量：原完整账单有两笔等价出现、旧库已有一笔，新增一笔失败后，子集只剩一行，普通多重集合会错误判重。提交因此为失败的共同操作保存最小来源决定和局部证明：只对**已经通过锁内来源及操作重验、之后实际保存失败**的决定保留原新增／对应次数；`record_changed` 或来源证据未成功保存的旧决定不能借新令牌获得信用。保存原失败输入的签名和等价集合内当前来源候选集合摘要，覆盖成员增删、来源作用域、固定索引、当前字段／保护、绑定及覆盖／认证证据；成功正文仅参与计算摘要，不写入上下文。摘要在本次其他成功写入及当前投影完成后、工作区锁内生成；按相关固定索引共享，不按每行复制完整候选或输入集合。

派生预览及提交都重验当前局部集合和输入签名；没有加入相关的新输入且证明仍成立时，可继续原来已证明但未保存的次数决定，同时按当前账户／字段规则重新计算。可靠编号、认证行或原物理位置已经绑定时优先使用当前强对应，不继续消费旧新增次数。证明变化时重新判断：可确定者自动处理，其余只存身份待补草稿／当前问题，不能把单行子集误判为旧集合重复或无条件新增。原共同操作的必要别名仍一起执行，选中任一失败出现即携带该共同操作所需的其余失败别名，不要求用户重复选择。多次派生必须在工作区锁内重验，首次写入后的绑定及候选变化使旧信用不能重复新增。

重试中移除必要来源文件，或修改文件的来源作用域使原出现签名改变时，仅跳过该共同操作的剩余行并提示重新导入相关账单，其余独立操作继续处理；不得部分保存后把未保存的必要别名视为已处理。消费过滤要求共同操作的全部必要别名都有持久成功结果。内部证明逐层校验版本、字段类型、完整来源决定、候选引用、次数描述及文档证据；损坏时在返回正文或计算计划前统一失败关闭，不修改会话或依赖底层异常碰巧拒绝。

派生命令按收据、选择范围和新幂等键保存最小命令收据，仅返回同一新会话引用；重复请求不延长 TTL、不再创建会话。只允许选择收据内可重试且有可靠解析内容的失败项，省略选择表示全部，空列表或成功项／未知引用拒绝。子上下文重新生成计划和关系建议，不采用原关系决定。失败上下文准备不可用时继续可安全提交的流水，收据明确需要重选文件；不得以保留完整原正文降级。派生时已过期、清理或不可用则返回安全可操作错误，按原合同重选文件。

成功重试还要关闭祖先和其他派生上下文的正文访问，不能只清当前子会话。根失败上下文保留有界派生登记表（最多 256 个上下文引用，不含正文）；新子会话及后续失败上下文必须在公开／业务提交前登记，失败则不授予访问或安全降级。子会话记录根收据与根上下文引用，保留原失败出现引用；读取时在工作区锁内验证根收据授权、登记关系，并按已登记子会话的持久消费收据及成功逐项结果，扣除已处理的逻辑操作。该成功事实复用现有收据及索引，不建立业务历史表，也不依赖清理是否成功。孤儿没有消费收据，不能被当成成功；成功别名按共同操作整体扣除。

原收据结果不改写。子会话提交成功后尽力裁剪根及已登记派生对象的对应解析行、行选择和全部旧计划，保留必要哈希证明及剩余失败项；查询、再次派生、重预览、详情和提交都先执行同一消费过滤。已处理项不能再次派生正文，既有子会话的旧计划失效；全部已处理时返回安全的已处理状态及有权访问的消费收据引用。裁剪存储失败时失败关闭正文读取，物理残留由原 TTL 清理，不以另一子会话绕过。登记及清理按有界批次，不把子会话 ID 或成功原文复制到永久收据摘要数组。

成本分析定位到同一请求反复解码根上下文及重复校验。工作区锁内已授权并完整校验的根对象可在本次派生登记中复用，实际替换仍由原存储读取、修订 CAS 及 TTL 校验保护；不跨请求缓存授权、正文或消费状态。JSON 预算遍历可内联字典键检查，仍逐键拒绝非字符串、非法 Unicode，保留深度、字节预算及编码后精确上限；不能以跳过校验或扩大预算换取性能。

大量失败单元共享候选时，失败证明及冻结计划各保存一份按内容签名的候选集合，单元／操作只带引用；校验先验证共享集合，再逐引用确认存在及类型。指纹包含集合内容签名，实际保存问题时通过统一解析器取得同一冻结集合；不在每项序列化、指纹或数据库查询中重复展开。证明失效优先复用当前普通来源规划器已有的候选组，不按固定索引猜测共用候选，也不另做逐单元全候选扫描；作用域、可靠编号和物理位置等资格仍由现有来源对应规则核对。共享资料不合并流水操作、字段补丁、账户选择或成功消费身份。

解析边界分两步迁入：先逐行读取原始表格、明确位置及文件声明，保留相同内容的每次出现，再调用共享来源分类，单条错误转为安全行结果。平台表格的范围完整性只依据格式声明的起止、筛选与笔数核对，不使用首末流水；声明缺失或笔数不符为 unknown。微信昵称和说明中出现的“微信号”不能冒充本人账号。新文档对象只有解析后的行与必要元数据，不持有文件字节、路径、密码或工作簿；CSV／Excel 读取资源在解析完成时关闭。后续会话和计划只消费该对象，不再调用旧的内容去重或每次预览重读原文件路径。

声明字段必须收集所有精确出现并一致：账户矛盾不产生确定身份，范围／筛选／笔数矛盾或存在结构错误行时不授予完整覆盖证据，仍保留声明、观测计数及其他有效行。平台 XLSX 仅支持 XML 部件，拒绝宏及嵌入二进制、非空目录项、DTD 和实体声明；对所有 XML 做预算及实际行列坐标预检，不依赖扩展名对应的工作表目录。忽略不可信的 worksheet dimension，按实际行读取，补齐 XLSX 隐式尾部空单元格；物理行（包括空行）最多 200,000、业务行最多 100,000、列最多 128、解压总量最多 100 MB、解析文本最多 25 MB。超限为该文件的安全错误，不影响其他文件。

平台逐条归一复用转换器的原生方向、资金归属及分类，不复制一套财务规则；新边界使用完整来源文字填备注，不保留旧生成的说明。可辨认但金额／时间／方向无法确定的行保留空值及当前原因，只有无法处理的适配器异常或结构坏行成为跳过项。任一无法索引的行使可用覆盖证据降为 unknown；正常白名单跳过保留逐行结果。该层不查询账户、不提前合并真实出现，也不执行退款配对。

`ParsedCashRow.source_explanation` 保存同次原生单行归一取得的标量白名单：平台交易号、商家订单号、状态、来源类型及方向，银行结构化摘要、原始商户及单行退款／撤销／抵扣类型等。资金方式和本方来源线索可包含其中，但金额、生成备注、用户分类及原始行不成为第二套字段。跨行 `offset_group/offset_role/offset_strength` 等决定和候选置信不进入该对象，内容散列或 `_fact_id` 不提升为来源身份。后续关系计划直接消费该解释，不再读取原文件或用用户备注补猜；既有关系仍以关系上的持久角色校验。

来源解释只允许明确的字符串及布尔键，未知键、结构化对象或错误类型不成为可采信证据；提取时忽略它们，避免仅关系提示异常影响正常财务字段。暂存拒绝不符合该白名单的 DTO，旧对象缺少该字段时按空对象兼容。正常化和暂存继续使用原有文件／会话字节预算，不新增原文件或密码存储。流水持久化和已有来源解释回填在统一计划／写入口切换时接入，不在本读取小步声称旧跨行元数据已经全部移除。

银行表格先迁入建行 XLS 和工银亚洲 UTF-16 CSV，再迁入工行 PDF；文件签名、银行名称／标题及表头在一次读取内确定来源，不使用文件名猜来源或探测后重新读取，相同列名不能把其他银行重标为支持渠道。每条原始出现独立归一，旧内容散列、序号及未认证的凭证号都不提升为可靠编号。正常行复用既有来源分类和资金提示，坏金额／日期／币种保留未知及原因，结构错误和意外适配异常仅跳该行；原始摘要／备注直接展示，不沿用拼接说明。表格解析资源始终关闭，行列、输入及解析文本预算与平台边界一致；XLS 扇区不完整或解析器发出结构诊断时拒绝该文件，诊断不输出。

银行来源声明只在一致且可校验时作为证据：建行使用完整本方卡号、全部交易标题、起止日期、完整 XLS 容器及连续行序；工银亚洲区分银行账号和下挂账户字段，按既有优先级选身份但不混合矛盾声明，并使用明确币种和日期范围。两种表格的遮蔽账号及纯尾号仅作展示，不能建立跨文件身份。任何结构坏行、缺失／矛盾声明、序号不完整或越界时间均降为 unknown，不用首末流水推断范围。CSV 连续序号不能证明尾部完整；工银亚洲仅在格式额外声明总笔数且与观测一致时认证完整范围，否则保留 unknown，不伪造总笔数。日期只有天精度的来源保留该覆盖精度；零金额开户行是有明确原因的白名单跳过。

工行 PDF 采用同次打开、逐页提取的原生表格：信用卡 12 列、借记卡 13 列，银行标识及规范化表头同时识别，不能只凭文件名或来源提示重标其他银行。每页处理后释放对象，限制页数、字符、表格、行列和解析文本；原文件与密码只在本次调用内存在。密码需求和密码错误由文件结果区分，用户重新上传该文件后解析，暂存不保存密码。信用卡本方卡号来自每行 `交易卡号`，不能把整份多卡账单统一归给一张卡；借记卡本方身份只来自文件级卡号，表格 `账号` 仍只是来源字段。行级可空身份加入解析 DTO，旧暂存未包含时按空读取；未认证的掩码与尾号不充当完整身份。

样本的密码在文件名中，临时展示文件名同样必须去除显式密码片段及本次已提供密码，失败／待重传时也适用；否则虽然没有密码字段，仍会从文件名间接保留秘密。解析不从文件名自动猜测生产用户的密码；测试执行器按用户授权读取文件名，内存传入后使用合成展示名。

金额读取固定的交易金额列，不向余额列搜索替代值；日期、币种或方向无法可靠识别时保留空值与安全原因。正常行复用提取后的原生单行分类及对手方规则，解析阶段不配对，不做内容去重；备注取原始摘要等来源字段，不沿用生成描述。完整覆盖证据还要求原生完整文件、明确查询范围、页码总数及连续页序、各页声明笔数和观测一致、没有未知筛选或坏行；缺少任一项保留 unknown。真实五份 PDF（包含文件名提供密码的样本）校准只保存汇总，密码和原始内容不进 Git。

真实样本额外确认：两份信用卡 PDF 分别为同一次 114 页导出的 1–100 页和 101–114 页，不能把每份各自认证为完整，也不能相加重叠账单的次数。后续单独步骤保存本方文件头、查询范围、下单声明和连续页段的最小认证证据，在同一会话汇齐后自动核对完整覆盖；同次导出的原始页行定位用于识别重复页面，互斥页段保留真实出现，跨次重叠导出仍按多重集合对应。不让用户额外选择、不保留或重新拼接原文件；缺段或矛盾证据保持 unknown。该扩展完成前，单文件读取如实保留未知完整性。

连续页面的解析契约在 `SourceCoverage` 增加可空 `document_key`、`page_total` 和页码到内容摘要的 `page_fingerprints`；`RawCashRow/ParsedCashRow/SourceOccurrence` 增加可空 `document_position`（声明页、表格、行）。只在完整文件头本方、规范范围、有效下单时间、总页数及筛选一致，各页笔数核对且页序连续、原生文件完整、归一后无坏行或范围外日期时授予该证据。`document_key` 是这些声明的命名空间摘要，不是交易编号；不保存姓名、原始文件头、密码或 PDF ID。旧解析对象缺少新增字段时按空兼容。

来源存储向领域返回现有文件局部绑定的作用域与位置集合；同一认证导出内不同页行位置可排除同笔，即使后上传部分尚不能证明整个时间范围完整。其他导出空间或没有认证定位的旧流水不据此排除，仍按原范围与次数策略处理；不增加数据库列或跨次导出的行号身份。

输入组合只汇总同一声明空间的解析证据，页码覆盖 `1..page_total` 且重叠页摘要一致才认证完整；不修改原暂存、也不拼接文件。相同声明空间按一个观测集合统计出现次数，原始页行定位排除重复上传页，互斥页段的相同内容仍是两次出现；不同下单声明仍走原多重集合规则。定位以既有 `file_local/file_occurrence` 别名类型持久化，不改变行级资金身份或把页码当全局编号。重叠页内容矛盾时仅相应页的行结果冲突并保留安全原因，整组不授完整覆盖，其余页／文件继续；缺页保持未知但不妨碍文件内已知出现。页摘要数最多 2,000，不能使每条结果复制整个证据集合。

文件输入通过 `SourceBatchInput` 独立携带所有文件的声明，包括没有业务行的页面，不能只从行集合反推证据。来源规划与提交前重验还须从仓库按认证导出作用域批量取得既有页证据（`document_coverages_for_rows`），既有当前候选中的证据同样参与冲突检测；避免时间或位置变化后漏查。每条绑定只持久化该行所在页的摘要；另保存按页作用域的同一行别名，单条保存时利用已有索引拒绝矛盾页，草稿合并也校验。原始文件、页文本与完整页摘要集合不复制到每条绑定。

本读取步骤只认证同会话汇齐的完整范围；跨会话仍可按同导出的认证位置识别重复和互斥出现，但不会仅因后来上传另一页就回写所有旧流水的完整标志。计划层的跨会话完整性及空页证据保存接入列入 4.8，届时从当前来源证据统一计算，不把单条旧覆盖标志当作全部证据。未完成前不宣称跨会话汇齐后与另一导出已自动等价。

4.8.1 使用当前来源绑定保存有业务行页面的证据，另增 `cash_source_empty_pages` 保存认证空页的最小范围及单页摘要，不造空流水或悬空来源绑定。唯一键为工作区、渠道、解析命名空间、认证导出标识及页码；不存原文件、页文本、账号或处理历史。空页必须由认证文件及全部物理业务行位置证明，含跳过行的页面不能被认作空页；不具备位置证据时不保存。预览不写该表，联合提交在文件证据保存点中记录，重复记录幂等，矛盾证据不覆盖。

计划与提交重验统一按当前文件声明（包括零行文件）及本次有界候选旧记录的认证导出声明查询已保存空页和当前活动绑定，不扫描全账本。旧导出 A 的业务页与空页已汇齐时，另一导出 B 也可自动对应其候选；不能只加载 B 的范围。渠道、解析命名空间和导出标识贯穿当前记录、文件证据和领域冲突键，不将缺命名空间的页摘要扁平混用。

将历史完整标志视为派生输入而非证明；只有同命名空间、导出声明、边界、筛选、时间精度和全部页摘要一致，且页码汇齐，才在本次内存规划中提升新行和当前记录的覆盖完整性，不回写旧来源行。来源绑定仍按活动流水读取，删除流水的旧页绑定不能变成重导阻断证据；空页本身无流水和金额，不作为交易删除标记。更换解析命名空间或声明矛盾均不混合认证，其他来源及合法流水继续处理。提交必须在写锁内重验全部依赖证据；空页保存点冲突或失败时，依赖该证据的来源对应决定不得继续应用，相关组跳过并给出原因，无关流水继续。该依赖处理随 4.9 联合提交接入，不把低层证据存储验收当作完整提交验收。

币种必须取明确交易币种；样本中的 5 笔欧元识别为 `EUR`，不沿用旧未知币种默认 `CNY` 的行为。借记卡共享分类使用新读取器已校验的精确金额，避免第二次两位小数解析拒绝合法整数／一位小数或截断高精度值；既有旧入口默认行为保持，最终由新写入口统一切换。

解析暂存使用独立的单一 JSON 会话对象，包含不可变的所有者／创建与到期时间、单调修订、解析文件集合、最后输入及当前计划；不调用旧原文件存储接口。内存适配器及私有 R2 适配器实现同一条件替换合同：R2 使用读取所得 ETag 的 `If-Match`，首次创建用 `If-None-Match: *`；不能丢失竞争者的修订，也不能退回无条件覆盖。解析文件集合保持 25 MiB 上限，含输入及规范化计划的完整 JSON 上限为 64 MiB；文件最多 20 份、TTL 最多 1,800 秒且修改不续期。预算按未压缩 UTF-8 JSON 计算，不通过压缩规避资源边界。文件加入超预算时由服务保存该文件安全失败结果，不能截断出现或丢弃其他成功文件；计划超预算保持原修订及原计划。取消同样条件写入空正文的终结状态，避免并发发布把取消对象复活。过期不可访问并清理，客户端不取得对象下载地址；部署前接入无人访问对象的有界过期清扫及运行检查，读取时清理不能替代此任务。R2 条件请求能力依据 [官方 S3 API 合同](https://developers.cloudflare.com/r2/api/s3/api/#implemented-object-level-operations) 核实；对象 CAS 只保护临时对象，应用层仍须执行前述工作区同步与收据校验。

联合提交成本验证 Flow-Back：固定一千行的初版新链路在两后端超出已有 5 秒预览／15 秒提交预算，不放宽门槛。会话编解码原先对一次发布多次递归复制、完整重编码和往返；使用白名单数据类的浅层 JSON 适配；解析集合先独立计量，再由有界容器分块生成完整内容，按实际 UTF-8 字节检查两个上限。读取仍验证完整结构、深度、JSON 类型、所有者和两个预算，但不为验证再次编码整个计划；需要回传会话的路径在发布前只做一次解码验证并返回该独立对象；不回传的计划发布采用前述共同写读校验器与有界编码，不额外物化会话。CAS、固定 TTL、损坏对象失败关闭及返回值隔离合同保持。

成本定位同时覆盖来源绑定：按完整来源身份索引和独立证据索引分别查找，再合并结果，避免复合 `IN` 与空证据条件的 `OR` 导致工作区扫描。提交在同一工作区锁内只准备一次当前来源结果，供计划重验与实际绑定共同使用；不跨请求缓存，也不略过保存点内的当前归属检查。

新父记录主键不复用，因此首次绑定前没有旧别名、组成项、问题或候选依赖。联合命令只在该保存点首次绑定时省略旧目标别名查询；同条流水其余别名、所有已有目标及来源键的活动归属仍逐次校验。该优化不引入跨保存点可变缓存。实际待确认数量从最终当前投影去重计算，结果分页按读取时的当前归属提供有界定位引用。

进一步成本 Flow-Back：逐行往返使 PostgreSQL 首次提交仍有波动。至少 20 个相互独立、已重验的全新正式操作，可按至多 100 条批量试写；仅处理无当前问题、无旧来源键及无认证页依赖的普通解析行。流水、组成项和全部来源别名仍在一个保存点内，成功后才发布实际身份映射与余额变化。任何可恢复批量错误均回滚整批，再用原逐流水保存点逐一执行；连接／外层故障仍整体失败，不以批量失败跳过整批。旧目标、草稿、认证页、现有别名和小批量继续原路径，不引入跨保存点缓存。两个后端使用同一应用分支及结果合同，适配层按确定顺序返回新身份；不以返回顺序猜测归属。

真实 19 份账单共 15,198 个原始出现的只读试跑表明：解析会话约 16.8 MB，初版计划约 106.4 MB，其中新增流水的伪字段差异在操作及详情重复约 54 MB，成员字段又重复一份最终值。新增流水只展示字段，不生成“原值为空”的更新差异；操作保存一份最终值，详情保存对该值的内部引用，在按需读取时恢复既有公开 DTO。已有对侧无本次操作时，在计划内保留一份冻结值；引用只能指向当前计划内服务端值，不接受客户端引用、不回读实时库拼出旧预览。实际共享后再验证预算、不可变性、重预览和完整真实样本，不以调大上限代替去重。

文件应用服务先在工作区锁内验证实际成员及写权限、当前修订和消费收据，然后释放锁解析新上传；发布前重新取得同一锁并再次验证。会员行在 PostgreSQL 发布阶段加锁，避免权限已被撤销后仍发布；用户隔离的消费收据先于临时内容读取，因此清理后的已提交会话仍可恢复结果，也不能再取消或追加文件。来源可在同一次表头读取中自动识别，不做探测后重读。

`client_file_ref` 表示稳定的客户端上传槽位；`file_ref` 表示本次解析结果命名空间。重传保留前者并生成新的后者，移除旧行选择和计划，其他文件不重新解析；其余选择必须由后续计划重验。解析器异常、密码需求、坏 DTO 和文件／会话预算溢出转为该文件的安全结果。超限文件保留实际观测大小及失败原因，不将大小截成上限；成功文件的内容上限仍为 100 MB。原文件及密码不进入暂存。

过期清扫使用运行期后台任务，启动执行一页并在失败时拒绝启用新会话存储，运行中按有界页继续扫描；无下一页时最多等待 60 秒。R2 对象元数据只存固定到期时间；清扫通过私有 `parsed/<digest>/session` 前缀的列表及 HEAD 判断，不下载解析正文，不扫描其他对象。缺少元数据的旧对象以最后修改时间加最大 TTL 作为保守兜底。清扫失败只记录稳定安全码和健康状态并重试，不记录对象键、来源内容或供应商异常；生产配置要求列表／HEAD／读／写／删权限和有界网络超时。多实例重复删除已过期对象是幂等的，到期时间不能续期，因此不会删除后来续期的有效会话。

#### 3.2 无文件维护与同身份草稿保存

先将导入内已验证的流水、组成项、当前问题写入边界提取为共享写入器，导入保留薄转发以继续覆盖实际保存点故障；写入器只接受应用服务准备的操作，不能把公开补丁直接当成可信计划。维护服务直接从库中按工作区及活动身份读取父流水和组成项，先重验成员、写权限、父修订和组成项归属，再使用统一字段策略、最终账户资格及相同保存边界，不创建伪导入文件或解析会话。

普通草稿保存始终保持 `draft`，合法但尚不完整的字段可保存并重算已掌握的字段／资金问题，完整草稿也不更新余额。来源歧义、待采用来源字段、关系问题及其候选由各自维护动作处理，普通草稿保存必须保留其实例、修订和正文；不能向共享写入器传空来源解释而清掉既有元数据。明确备注／分类包括同值和清空设置人工覆盖，来源身份及状态不在普通补丁内。组成项完整替换验证 ID 属于当前父记录，新项才分配身份；清理删除项涉及的草稿端点／候选，保留父锚点，不扩张潜在候选闭包。活动确认关系不可因草稿保存被静默解除。

来源行补丁须在字段合并后执行共享无 IO 派生，导入中的人工补充与无文件维护使用相同过程。明确提交 `note`（包括同值和清空）优先；没有明确备注且已有人工保护时保留当前备注，否则按最终来源行重取完整原文，无对应内容则清空。自动取值不建立人工保护。工行 PDF 仅规范列名中的空白，保留来源字段原值；规范后有歧义的列不充当可靠解释。一般 JSON 中的缺字段、非文本值不能抛出原生解析器异常或生成有效退款证明。

当前解释复用各来源既有纯规则重算并按所属键替换，不调用会重新解析金额／时间、跳过整行或产生业务身份的整行转换器。交易号、状态、摘要、渠道及退款提示可以变化；已绑定的本方账户身份、文件账户键、可信卡尾号及来源标签由既有可信解释保留，不能从人工来源行改写。说明变化不改来源绑定、文件／页证据、固定财务值或流水类型，不解除当前关系。只改备注／分类不重算解释；只改类型保留单行来源事实，清除非白名单的旧跨行缓存，类型相关角色仍由最终类型和当前来源事实在关系规划时生成，不持久化第二份角色。发布后的最终操作冻结派生值，写入器不重新解释公开补丁。

草稿补金额或改变方向时，同时按最终金额重算依赖金额的来源解释，但不因此重取备注。首次归一即保留已知原始线索及来源明确提供的可信本方身份，不能因金额未知丢失这些信息，后续也不能用人工行内卡号补造身份。解释单独变化同样属于更新并推进父修订；来源字段选择稍后处理时仍保留当前解释，不把尚未采用的解释立即写入。

父 `row_revision` 覆盖本身业务字段、人工保护和组成项，不是整个详情的单一版本；问题按实例／修订、关系及候选按所属关系修订分别校验。后续维护计划同时冻结这些依赖及相关局部 token，问题的新增／清除／重建不能靠父修订不变绕过。删除组成项改变关系端点或候选时，即使没有候选或候选已失效，也推进所属关系修订，不保留仍可提交的旧确认；不要求每条命令恰好递增一次。候选最终失效状态不因组成项被删除而恢复。

维护补丁在计算幂等摘要前验证 JSON 结构、UTF-8、深度及字节预算，沿用 64 MiB 未压缩输入上限；非法输入返回稳定原因且不产生写入。摘要仍根据原始请求计算，不依赖可能已经改变的当前记录，确保相同请求可以读取原收据。库内流水／账户引用先检查十进制长度，再转换为受支持的正整数；不限制外部来源编号。格式合法但当前不可用的账户仍按草稿问题处理，不能因超长引用触发底层整数转换异常。组成项 `ordinal` 由共享字段规则限制为 `0..2**31-1` 的整数，匹配两后端既有 `Integer` 列；不要求连续，不新增或放宽数据库字段。

详情返回 `transaction_id/state/row_revision/confirmation_status`、允许维护字段、组成项、当前问题及其实例／修订、关联摘要和当前投影定位。草稿保存的字段／关联变更、局部投影和最小永久收据在同一事务提交，任一发布失败整体回滚。响应明确分离 `{receipt,current_record_status,current_record}`：收据是本次原结果；详情是当前态，可为 `available/deleted/unavailable`。重放先查收据，不因旧父修订重跑写入；提交后详情读取失败仍返回已保存收据及 `unavailable`，不泄漏底层异常或误报结果未知。永久收据不保存流水正文。

随后为正式编辑、转正式及当前问题／关系处理建立专用 `mutation` 编辑上下文：允许无文件，具有与导入相同的受控存储、原 TTL、所有者、字节上限和 CAS；普通导入及失败项入口不得授予该种上下文访问。客户端仅提交意图、稳定目标、预期修订、补丁和决定；当前计划保存最终操作及预计列表。没有原文件也能从当前详情重新预览，成功后消费编辑上下文；HTTP 与 Compose 仍随 4.11–4.13 切换。

4.10.3.2 先实现计划发布边界，业务构建器通过只读会话接入，正式编辑／转正式及问题／关系行为随后逐项落地。`mutation` 上下文只允许空文件集合，不能夹带解析来源或重试证明；原导入／私有重试入口继续失败关闭。首次请求先校验有界 JSON、判别意图、目标和父修订，再构建／检查完整结果，成功后才创建上下文并条件发布；发布失败不写账本，必要的空上下文按原 TTL 清理。重预览带 `edit_context_id/previous_plan_id/expected_plan_revision`，稳定目标不能换成另一笔流水，允许使用重新读取的父修订；失败不改变已发布计划。

公开 `plan_revision` 从 1 开始，只在成功发布新计划时递增；存储对象的内部修订另外用于条件写，不向用户解释。计划 ID 使用独立维护命名空间并定位原上下文；分页、过滤游标、字段白名单及冻结详情复用既有只读合同。读取先检查当前成员及所有者，再检查编辑上下文的永久消费收据，之后才访问暂存；原临时正文已经清理时，仍能识别已提交，不能重新授权写入。过期、取消及旧计划不可提交，重预览不续期。发布层完成不代表真实业务构建器、联合提交或公共 HTTP 已切换。

重预览响应丢失时，可按已知 `edit_context_id` 读取当前计划，不要求用户重填或猜测新的计划 ID；该读取仍先检查永久消费收据。预览数据库事务只读并在退出时回滚，不把构建器的意外写入提交到业务账本。

公开摘要使用接口合同列出的数量键及非负、非布尔整数；不能把构建器的内部错误或源正文放入 `summary`。首次发布及重预览都在创建／替换上下文前检查，失败保留原计划；读取同样不透传未知摘要键。

实际维护规划从共享当前流水读取及操作准备开始，不创建解析行或伪文件。正式编辑使用统一固定字段策略，不重新检查已用账户的启用状态；草稿转正式检查最终账户、组成项及完整性，来源歧义或未处理的来源更新须先解决。校验失败不发布可提交的转正式计划，普通草稿保存仍可延后处理。导入和维护共用“已准备操作→当前完整关系图→类型影响→新建议→预计列表”边界；正式编辑的发现种子为空，只有转正式组成项可触发新配对。暂未实现的问题／关系维护意图不得落入默认正式编辑分支。

整笔公共属性在稳定收支对象上保存，来源成员不回写。计划冻结对象身份、修订、当前成员与恢复值摘要，以及父记录、关系和问题令牌；提交前重新校验，公共编辑不依赖父修订推进。导入正式类型固定，不采用编辑触发自动拆组。

当前来源描述从可信绑定取得作用域，不把内部业务标识当平台交易号。多个账户作用域保持歧义隔离；普通微信文件使用已确认的默认范围并保存绑定；只有文件局部绑定时使用文件范围，完全没有可信绑定的旧流水按单记录隔离，微信也不例外。可靠来源键仍可跨时间窗口寻找对侧。无变化的维护预览仍展示目标当前结果及详情，不伪造更新；全额退款继续显示。当前图中已有确认、忽略及未确认决定保持，由后续明确的关系维护意图处理。

新配对读取来源原文时复用首次归一和来源行维护的备注映射，包含 PDF 列名中的换行；不读取用户人工备注，不用其他来源字段替代本应读取的原文。

普通正式编辑预览在一万笔账本背景下单独验收，沿用现行普通编辑 P95 100 ms 的相称门槛，3 次预热、20 次测量；该数字只覆盖规划命令，不冒充随后联合提交或网络往返的总耗时。草稿保存及千行导入／重试继续运行既有成本矩阵，不放宽预算。转正式的新发现、关系组清理及完整维护写入随联合命令补相称验证。

维护联合命令与导入分别保留自己的授权及上下文入口，只共用事务内流水写入、完整关系组保存、当前事项及余额处理。维护命令在工作区写锁内先查永久幂等收据和 `edit_context_digest` 消费状态，再读取当前计划、校验公开计划修订并重建当前业务结果。重建只用于核对，实际执行冻结计划；父流水、问题实例／修订、账户资金资格、当前稳定对象及成员、当前图令牌、对象公共值或关系建议内容变化时，在任何写入前拒绝并保留编辑上下文。关系建议核对覆盖动作、候选、端点、角色、精确分摊、锚点和证据，不能采用用户尚未看过的新建议；普通编辑不依赖账户展示名或工作区全局版本。

同一次维护的流水、手工转账双端及公共属性操作使用同一保存点；任何可恢复错误回滚整个单元，不留下部分公共属性或单端资金变化。成功后再发布余额差额及受影响集合。关系按完整提交组隔离；关系失败保留合法流水。最终余额、局部派生发布、问题或永久收据失败回滚外层事务。

维护收据使用独立 `operation_kind=mutation`，请求摘要覆盖计划 ID 和提交携带的计划修订；同键不同计划冲突，同一编辑上下文换键也不能再次消费。收据与当前流水、关系和局部投影在同一事务保存，永久结果仅含数量、安全原因及稳定引用。提交后的临时清理失败不改变成功结果；原键重放先读永久收据，不依赖仍存在的临时正文或目标流水。结果分页按读取时最新投影定位，历史收据不改写。维护结果核实使用相同工作区非等待锁语义：锁忙返回 `pending`，有收据返回 `committed`，当前计划有效返回 `retry_original`，已取消、过期或被替换且无收据返回 `not_committed`，其他存储错误继续传播。

联合命令复核发现，原导入链路仅将没有具体建议的发现失败保存为当前事项，未纳入永久关系结果。与维护一起补齐：预览先按相同原因、父成员集合和适用建议去重，避免组合支付多个组成项反复失败而虚增同一问题；共享执行边界为无具体建议的失败生成稳定、有界且不含原文的关系结果，计入关系失败和部分完成，保留合法流水及当前安全事项。已经交给具体提交组处理的失败不重复计数。流水保存点的可恢复失败也会持久保存本次失败结果并消费编辑上下文，重新尝试须从当前详情建立新计划；提交前的陈旧依赖拒绝不消费。

普通正式备注维护的完整成本另在一万笔背景下测量首次预览加确认提交，包含权限、局部依赖重验、写入、投影、收据及临时清理；采用相同 3 次预热／20 次测量和既有 P95 100 ms 门槛，单列提交耗时，不把预览孤立数字当作完整保存。每次使用新计划和幂等键，不依赖跨请求业务缓存或重复收据捷径；复杂转正式及关系组场景仍按实际规模另验。

### 当前来源问题与复合维护意图

维护输入使用 `issue_resolutions[]`，不再使用只能处理一个问题的平铺字段。问题决定与显式字段补丁、拟关联决定共用一次预览和确认：`edit_record` 处理正式流水，`resolve_issue` 处理所选事项但保留草稿状态，`finalize_draft` 可在同次计划中消除已选来源阻断、补齐并转正式。数组只接受当前流水的问题实例及预期修订，拒绝重复、跨流水、过期或不适用动作；关系维护意图不接受该数组。首个实现小步只处理 `apply_source/keep_existing`，身份独立及合并在后续小步完成，未实现动作不能提前开放。

每份待采用来源先使用统一字段约束独立验证，再合并来源值，最后应用本次显式补丁。不能以补丁掩盖正式固定字段冲突；多份采用来源的同字段不同值必须由补丁明确统一，不能按顺序择值。来源合并遵守已有备注／分类保护，只有本次显式补丁建立新的人工保护；来源备注按最终原文派生，来源解释按最终正文及金额重算，保留当前可信本方身份，不能恢复整包旧 `_source_explanation`。导入正式类型冲突整条拒绝，手工字段更新不自动解除关系。

每份来源中的组成项必须在合并前验证字段白名单、当前流水归属、引用唯一及 ordinal 完整／唯一，显式补丁不能把非法组成项遮掉。该准入只校验可保存结构，不提前要求草稿财务完整、账户启用或可转正式；读取及实际采用共用同一准入。

待采用正文的缺失和明确清空须可区分。新问题在 `pending_fields` 中保存仅由服务端生成的严格布尔 `_source_payload_present`；旧非空正文仍可采用，旧 `None` 不代表清空。无足够可采用内容、非法字段或固定冲突时，不展示且不接受采用来源；保留现有仍可用。读取及规划使用同一可采用校验，查看者不获得处理动作。

冻结计划保存所选问题的实例、修订、决定及当前正文／来源解释／origin 摘要，不在收据保存原文。未选问题按实例保留，不按同原因覆盖另一份正文；成功写入时仅清除所选实例。单纯事项处理可保持父字段及修订不变、流水 outcome 为 `duplicate`；提交按实际成功处理数返回 `completed`，刷新当前事项、待处理计数和局部投影，不能误报 `no_changes`。流水单元或外层发布失败时，问题正文、实例及原修订完整回滚；确认前正文或修订变化使旧计划失效，即使父修订未变。

后续身份小步区分两件事：输入出现自身的外部身份是否可靠，以及它是否对应已有未知流水。已验证 `SourceOccurrence` 自带的来源范围、可靠编号或稳定证据可以在最初保存草稿时进入现有来源绑定表；身份问题和候选仍表示后一个问题，不能因强绑定命中而自动消失或转正式。`uncertain` 只要求目标为草稿，不再否定已经验证的输入身份。范围未知时仍只有文件局部身份，不生成全局编号；所有必要别名、稳定键和页证据继续在同一流水保存点内检查活动归属，多个键指向不同活动目标或共同输入矛盾时不得抢占、择一或留下部分绑定。

复用来源绑定本身作为可信身份事实，不另存 `origin.identity_proof`，也不为查询问题 JSON 新增索引。不同文件中的同一可靠键即使时间改变也应找到原草稿，保留旧身份问题及候选；同批确定互为别名的出现也共用一条草稿和保存点，不因与旧流水对应未定而拆成两次写入。重导旧文件别名时，仍补存本次自身证明的可靠键，重复快速路径不得跳过。自定义微信范围不回退默认。旧无可信绑定的数据不从可改来源行、备注或关系解释恢复身份。后来输入只保存该出现自身明确证明的绑定，旧未知文件别名不顺带变为账户范围；来源数量／完整性信用必须取与已知范围相符的账户绑定证据，不能挪用旧未知别名的 coverage。来源绑定规则变化和相关读取应一起验收。

确认独立只结束明确选择的当前身份问题，保留原流水及全部绑定，不重建可靠键，也不隐式转正式；无绑定／仅文件局部绑定的旧草稿同样可以确认独立，但该决定不生成可信范围。明确补充及转正式可共用同次确认。预览冻结问题正文／修订和当前完整来源绑定集合的规范数量与摘要，覆盖实例 ID、创建时间、父 ID、完整键、修订、强度、稳定证据、解析版本及 `coverage`；提交锁内重读，即使父修订没变，绑定新增、删除、转移、同内容重建或证据改变仍使旧计划失效。只从绑定检查内部一致性及完整键／稳定证据的活动归属，不从可改来源行推导证明；同一目标的多个问题复用一次检查。预览 `create_independent` 按流水计数，永久收据沿用 `resolved_issues` 按事项计数，不新增重复摘要。身份问题、明确转正式的余额及局部投影共用流水单元／发布事务，收据不保存绑定证明正文。合并仍需核对双方修订、固定财务值和人工冲突，转移现有绑定、问题、候选及草稿锚点，返回保留目标；不隐式转正式目标草稿。上述独立／合并分别由 4.10.4.2／4.10.4.3 实现验收，不以来源采用／保留实现代替。

完整维护成本首轮 PostgreSQL 超预算。聚合剖析显示当前图和投影各自重建递归查询表达式，虽未全库重配，重复的表达式构造及数据库往返仍占用普通编辑预算。先复用仅含绑定参数的递归查询结构；每次仍传入当前工作区及本批种子、实际查询数据库，不缓存闭包、授权、问题、候选或业务事实。双向索引遍历、循环终止及每批 500 项上限保持，跨工作区及连续不同种子须有回归证据。

固定字段集合的局部关系图查询同样复用带参数表达式，保留原来的三个有索引端点分支及外层工作区／关系 ID 查询；完整关系和候选读取不改为全库扫描。闭包和关系图都必须在下一次执行反映当前关系变更，不能把结构复用扩展为结果缓存。

递归结构复用后仍未满足 PostgreSQL 整体预算，继续消除单次事务内的重复读取：命令已经完成当前权限和永久消费检查后，直接加载并校验临时上下文，公开读取及独立提交预检入口仍各自完整授权；维护构建器复用本次已加载的目标对象；投影维护复用调用方在同一事务已锁定的活动状态。待处理读取没有已加载关系时，将问题版本和两个草稿端点合成一条有界查询，不加载正式／忽略关系的完整图字段。所有优化仅限同一调用／事务，预览与确认之间仍重新读取当前事实，外层锁、保存点、权限、永久消费及当前图令牌保持。

来源决定接入后，完整普通编辑成本再次超出原 PostgreSQL 门槛；诊断确认同次预览／确认仍重复读取目标、来源范围及未变化的正式组成项。继续只在本次事务内复用已经授权并加载的目标，以及带完整已查询 ID 集合的来源范围快照；必须区分已查无绑定与尚未查询，闭包中其他成员照常读取。预览和确认之间不复用对象或查询结果。正式流水的当前与最终组成项完全相同时，写入器保留原组成项和 ID 映射，省去重复读取及无效赋值；新增、草稿、转正式或组成项不同仍走原完整写入。冻结指纹、当前依赖、保存点及余额／投影发布保持，不能为成本跳过确认时重验。

确认独立及之后转正式的预计列表、配对发现和后续当前态读取必须使用同一持久可信来源范围；同次和分两次处理结果一致。只有文件局部身份的旧草稿保持隔离，不能在清除问题后回退微信默认范围；来源正文和关系解释不能补可靠键。确认时重新核对当前绑定集合，预览和实际提交使用相同范围。

身份草稿合并分为只读规划和同单元执行。规划先校验源草稿与同工作区活动目标、双方修订及来源兼容，再比较双方已知的固定财务事实；后续来源采用或显式补丁不能掩盖原有金额、币种、时间或已知资金分配冲突。未知值不覆盖已知，金额不相加，正式目标保留原组成项，目标草稿不隐式转正式。来源绑定的转移兼容校验提取为可只读调用的边界，预览不调用写方法再回滚；旧身份兼容只用于限制，不生成新的可靠键。

身份草稿合并先验证来源财务事实，再将明确公共属性写入目标稳定收支对象；来源成员不接受分类或备注的批量回写。人工冲突包括清空，由显式决定统一；未采用来源内容保留为当前问题。组成项映射必须有唯一资金证明，无法确定时保留父锚点，不能绕过已知财务冲突。

同次采用多份来源先逐份验证财务字段及组成项，再合并有效资金信息。公共值冲突通过稳定对象决定处理，来源自动值不升级成人工标记。冻结来源证明、目标对象修订及成员摘要，确认时重验。

合并上下文冻结双方绑定，以及相关问题正文、修订、候选、正反向关系引用、完整决定组及当前分类成员；数量与规范摘要用于比较，不向收据复制正文。目标原问题及源未解决问题保留实例和正文；父内 `issue_key` 碰撞只作有界、确定的重命名，不按相同原因覆盖。候选转移同时覆盖其他流水反向引用源的情况；去掉自身候选，重复候选只在当前事实一致时合并。父 ID 与组成项 ID 成对处理，源组成项在引用处理前保留。

目标本身为草稿且同次明确调整组成项时，映射以最终目标组成项为准；目标原有草稿关系和候选也不能继续引用被移除的组成项，须一并退回父锚点并保持待处理。既有确认组在类型维护后可以保留部分合法活动边和已经停用的边；身份合并保存完整当前决定及活动状态，不把本次决定草稿组的状态一致约束套用于旧确认组。

关系按完整决定组规划，保留已确认目标关系和人工决定，不自动寻找或确认新配对。映射形成自身关系、唯一键碰撞或失效联合组时，只有能证明完整等价且保持全部决定的处理才可执行；否则整个合并单元返回安全冲突并保留源草稿，供使用者之后在原流水详情处理。不能只停用一条边留下半组，或用保存顺序选取获胜关系。

执行在同一保存点完成目标及其分类成员更新、绑定、当前问题、双向候选及关系锚点处理，最后使源草稿退出活动态；外层统一发布源和目标涉及的旧、新闭包及永久收据。源草稿本来不贡献余额，正式目标不重复记账；目标草稿仍不入统计。结果行和 `retained_transaction_id` 指向保留目标，原操作引用继续用于定位输入及幂等恢复。原源草稿或临时上下文已不可读时，同键仍返回原收据。

联合执行将候选当前含义纳入只读规划：映射为同一目标、同一组成项且证据和失效含义一致的候选才可去重，优先保留目标已有实例；不同当前证据不能靠写入顺序择一。指向源的候选改指保留目标时明确失效，不能把旧草稿修订当作目标的新证明；问题候选没有独立失效枚举时，使用目标更新前修订，确保它与本次保存后的修订不同。当前候选变更推进其所属问题／关系修订。自身候选以问题新归属或关系新锚点判断，不能误删仍表示对侧的候选。问题的业务正文、原始来源行及实例保持；其中确指源组成项的技术引用按已证明对应改指目标，不能对应时省略该引用而保留全部财务字段，避免悬挂旧归属。

同一保存点先执行计划已证明安全的候选删除，再更新目标和清理其组成项，最后完整迁移其余引用，避免默认组成项清理在等价项合并前制造唯一键冲突。只读键占用同时包含已有目标问题及本次预计新建的问题，源问题的确定重命名必须在写入前完成；不能让实际保存顺序重新决定保留哪个实例。

合并成功的流水结果为 `merged_draft`，按退出的源草稿计一笔；当前问题仍由 `resolved_issues` 按实际结束实例计数。结果的输入 `item_ref` 保留源引用，`transaction_id` 和 `retained_transaction_id` 指向目标。合并保存点失败则保留源引用及当前内容，不能把失败目标误报为已经保留；投影或收据发布失败仍回滚外层全部操作。源草稿沿用普通逻辑删除退出活动态，不物理删掉仍需外键约束的父记录；不建立取代链、历史流水或历史正文副本。

导入行的 `keep_existing` 只跳过该份输入的更新，不等于维护接口按问题 ID 结束事项。共同写入器对已明确保留、且本次没有新的待采用字段的旧来源问题，必须保留实例、正文、origin、候选及修订，不能重新保存空内容。多个同原因事项都保留；来源绑定及其预览摘要与正文保留分别维护，不能因保留旧问题而漏掉新出现的合法绑定。新待采用内容仍按原规则保存。

#### 3.3 逐文件 HTTP 上传与安全会话视图

4.11.2 使用标准流式 multipart 解析器，新增其直接运行依赖 `python-multipart>=0.0.32`，为已直接使用的 Starlette 分段大小接口声明 `starlette>=0.44.0` 下限；不自行实现文件格式解析。请求只有一个不超过 64 KiB 的 `metadata` JSON 文本字段和最多 20 个 `file:<client_file_ref>` 文件字段，两者一一对应。元数据拒绝未知字段、重复键、非整数修订及非有限数字；新增／替换通过同一文件命令，替换必须只带一个文件及目标 `file_ref`，槽位引用保持。实际请求流限制总字节量，分段头限制 16 KiB；文件在当次有界总请求内暂存，随后按 100 MiB 限制逐个读取，不能描述为网络接收阶段逐文件硬截断。超大或不可读单文件成为文件结果，不阻止其余文件。临时上传文件只活到请求退出，成功、协议错误、解析异常和断开都关闭；密码不落暂存。同步解析在线程池执行，应用服务在读上传内容前及发布前重验权限。

不依赖解析器的 `finalize()` 证明完整性：必须收到 multipart 结束回调，截断请求整体拒绝；无条件关闭解析器创建的全部临时文件，包括还没有进入表单的未结束部分。OpenAPI 的小型嵌套请求结构内联，文档中的本地引用必须可解析，不保留嵌套 schema 指向文档根的悬空引用。

文件显示名称对整个可见名称去除密码标记及完整账号，只把已知安全扩展名单独保留，不能通过最后一个点把密码或账号藏在扩展名中绕过脱敏。格式或文字无法读取等已知文件原因提供重新导出的业务指引，不显示表头、编码或解析异常等内部细节。

会话接口成本另以一千条已解析合成行、一万笔背景流水和一万条无关映射验证真实 HTTP 发布及读取；来源原生解析不计入该探针，另由来源测试和真实样本验证。沿用原 5 s 导入准备、100 ms 读取 P95 和导入内存预算，读取按 3 次预热／20 次样本；不得为成本跳过权限、当前映射资格或完整公开视图。反复读取不重新解析文件，不写流水或映射。

上传交给应用服务的是当次文件读取器而不是一次复制全部文件的字节数组；服务每次至多读取一份上限加一个字节，再将该份字节交给已有来源解析器，保留一次解析语义。会话公开视图显式选择字段，不直接序列化内部暂存 dataclass；不返回原始文件、密码、摘要、来源键、行正文或上下文内部证明。账户元素区分只读 `suggestion` 与 `selection`，建议不冒充用户选择。失败文件的已识别行数未知时保持 `null`；移除或重传使用会话 CAS，删除文件的修订来自 `If-Match`。

会话读取优先检查持久消费收据；已经提交且解析暂存已清理／过期时，仍返回 `committed`、`receipt_id` 及持久 `last_plan_id`，文件／账户数组为空，`session_revision/expires_at/last_preview_input` 为 `null`，不伪造临时元数据。普通过期返回 `410`，不存在、其他操作者或工作区访问统一 `404`；结构错误为 `422`，修订／关闭冲突为 `409`。接口只返回预定义业务文案，错误不含来源值、密码、路径、SQL 或解析器异常正文。

#### 3.4 计划、确认和收据 HTTP 边界

4.11.3 将既有应用服务接入新 HTTP 合同；计划输入只含预期修订、上次计划及完整的三类选择集合，不接受服务端操作图。JSON 实际流上限沿用 64 MiB，解码及模型校验在线程池执行；重复键、非有限数字（含指数溢出）、未知结构字段及非整数修订整体拒绝。行内 `patch` 保持普通 JSON 对象，由共享字段规则产生逐行问题，不能把可定位字段错误提升为整批协议失败。失败项重试入口返回新会话公开视图，不暴露私有失败正文上下文；客户端据 `last_preview_input` 明确发送完整选择。

预算遍历的递归入口优先分派字典和数组，因为其标量叶值已在父容器内检查；减少重复类型判断，不跳过任何成员。字节扣减、即时负预算、64 层深度、非法 Unicode、有限浮点及实际编码长度检查保持原合同，不新增缓存。

计划列表、明细和收据结果均使用既有服务端分页，默认 50、最大 200；游标不能跨计划、种类或筛选使用。查询参数拒绝重复、未知键及非整数页大小。永久结果的行 ID 及 `next_after` 在 HTTP 中使用十进制字符串，避免客户端整数精度损失；临时计划继续使用不透明游标。提交适用于完整计划，读取多少页不改变授权范围。

公开响应使用明确的 DTO 白名单；摘要不附加全量结果，详情不附带内部执行计划、候选证明或私有来源绑定。收据查询共用当前操作者和工作区边界，先查永久结果再读取临时计划；`resolve` 依据计划前缀选择既有导入或维护服务，核实本身不执行提交。已提交时返回同一收据，不能因暂存清理而失去恢复入口。按键查询的路径由应用安装的 Uvicorn 访问日志过滤器脱敏；部署反向代理仍须使用相同脱敏或禁记该路径，不把应用过滤等同代理已配置。

会话与计划使用同一文件公开状态转换及问题生成：`ready/partial/password_required/failed`，不能在切换核对时改成内部解析状态，无法识别的行数保持 `null`，不伪装成零行。永久收据只给有界摘要，逐项结果从分页读取；草稿保存定位到实际流水，不新增另一组历史创建／更新字段。

新会话、计划、收据及维护路径的认证／角色前置拒绝同样返回 `field_errors=[]/retryable=false`，不能与路由内错误使用两种结构；未改动的其他业务接口保留其原认证错误合同。

千行真实 HTTP 分页读取在两后端超出原 100 ms P95，剖析表明已完整解码验证的新会话又对整份计划做一次深复制。解析暂存每次读取都从独立 JSON 字节解码出当前请求独占对象；导入计划读取直接在该对象上选择公开页及详情，不再额外复制完整操作图。仍每次重验权限、永久消费、TTL、当前计划及全部暂存结构／字节预算，公开字段继续产生独立结果；不新增缓存、不复用跨请求授权或跳过损坏检查。已有返回值污染和构建器输入隔离合同须保持。

去除整图复制后 PostgreSQL 仍略超预算，继续在同一 JSON 预算遍历中内联普通字符串、空值、布尔及整数叶节点，减少逐标量递归调用；ASCII 长度等于 UTF-8 字节长度，非 ASCII 仍严格编码校验。容器和标量都保持原 64 层边界、原预算扣减、非有限数字拒绝及最终实际编码上限。不能以已解码为由跳过 Unicode、深度、类型或字节检查；内存／R2 均验证第 64／65 层及非法代理字符时原修订保持。

提交应用边界初始为结果未知，不能仅凭本次尚未调用数据库提交就否定上次同键成功。只有在工作区锁内成功检查原键重放及会话消费、确认都没有永久结果后，才将之后提交调用前的非业务异常经外层回滚报告为 `503 commit_failed/not_committed`；此前查询失败、重放读取后的退出异常，以及一旦进入数据库提交而未获得正常结果，均保守返回 `503 commit_state_unknown/unknown`，随后核实。业务冲突、权限和输入错误仍保留其安全 4xx，不把异常正文或 SQL 传给用户。提交成功后的清理失败不改变永久成功事实；重试会话派生的存储故障同样不能假定派生未成功，客户端保留原键恢复。

#### 3.5 无文件维护 HTTP 切换

4.11.4.1 将当前详情、草稿保存及维护计划接入跨层契约 3.5 的路径。当前流水详情替换旧固定字段 DTO；只返回维护字段、组成项、可编辑字段、当前问题和关系摘要，不返回内部证明。普通草稿保存使用 64 MiB 实际 JSON 上限、幂等键及父修订，即使字段完整也保持草稿；原收据与读取时当前详情分开。草稿保存和维护提交复用 3.4 的确定未提交／结果未知边界，重放查询失败不能误报未提交，已提交后的详情读取失败仍返回成功收据。

维护预览按 `intent` 区分正式编辑、转正式、事项处理和当前关系维护；前者可携带有界问题决定，关系维护不接收来源问题决定。引用及修订严格校验，补丁内容继续交由统一字段规则解释；用户输入错误返回安全字段提示，不透传来源值、SQL 或异常正文。首次预览不依赖文件，重预览携带编辑上下文、旧计划和计划修订；读取、分页、当前计划恢复及最终确认与导入共用不透明引用和公开白名单，权限及消费先验仍在应用服务重验。

同工作区其他编辑者读取或提交他人的临时计划仍返回不可见，不能因提交错误包装改成可重试保存失败。CORS 位于认证中间件之外，让允许来源的浏览器能够读取 401／403 的安全正文；允许来源、方法和请求头名单保持原约束，未允许的来源不能读取。

公开当前详情不成为列表或统计的新事实源。当前投影详情与流水重新定位随后在 4.11.4.2 接入，旧详情和直接写入口同步关闭；手工新建和既定删除能力保持。4.11.4.3 先停用旧写入并清理旧服务，迁移保留真实结果后移除旧表，不能将旧文件摘要伪装为新上下文消费证明或编造逐行结果。最后更新 Agent 技能，Compose 在 4.12 消费同一组公开接口；未接入前不将后端合同计为产品流程完成。

Agent 使用相同解析会话、完整替换预览和持久结果接口，用户明确导入请求授权本批合法内容的一次确认。缺账户、缺分摊、单份文件或关系未确定均可延后，不增加逐条问答门禁；来源变化及保护规则由服务端决定。恢复保留当前有效选择，账户列表不提供修订则从 by-id 读取，不能猜测。未知提交先在同步边界核实，部分成功不重跑原请求；账户独立生效，未完成退出按原值和修订补偿。结果按逐行实际状态报告，关系失败不能推断所有流水已保存。技能与 API 参考不使用旧令牌、摘要确认、密码请求头或账户草稿，也不声称 Compose 已消费新接口。

#### 3.6 当前结果读取及旧入口关闭

4.11.4.2.1 的 `GET /cash-projections/{projection_id}` 在列表相同的读取快照和活动来源边界内，返回 `projection_version/projection/members/issues`：`projection` 沿用列表字段，成员只含稳定流水引用、父修订、生命周期和确认状态；问题只含安全原因、实例、修订及所属流水。金额来自当前投影，不从成员重新求和，不返回旧关系历史、私有证明或来源正文。只读取当前已发布的数据集和可维护范围；标识仍属于当前结果时返回最新成员及发布版本，不把稳定根标识当作冻结分组。已退出当前数据集或不可见的引用返回安全 `404 projection_not_found`，客户端重载列表，不保存旧投影到新投影的历史映射。

`GET /cash-records/{transaction_id}/projection` 从稳定流水定位当前结果，返回引用、待处理计数和同快照发布版本；草稿没有组成项也能定位。删除或跨工作区目标返回不可见，活动流水缺少当前归属或数据集未就绪时返回安全不可用，不用旧缓存伪造当前结果。前端保存后按稳定成员重新定位，不能沿用确认前的旧分组。

4.11.4.2.2 关闭旧 `/cash-import/detect/scan/preview/commit`、单条固定字段 `PUT`、直接 `/cash-relations` 决定、旧 `/relations` 独立待确认读取／发现／确认／拒绝和旧 `/cash-facts` 删除；不再通过运行时工厂分发保存原文件的旧会话服务，也不保留其配置构造器；运行时对剩余现金命令显式授权分发，不以任意方法名回退至旧类。旧入口从公开路由及 OpenAPI 移除，关联核对改由流水内维护计划承载。保留手工新建及既定删除、整笔分类、账户别名、余额校准、明确转账和独立投资能力；手工新建拒绝解释、人工保护等服务器私有字段。投资资金关联使用独立表，不能随现金关系入口一起删除；其候选和锁内确认必须排除草稿，补齐同表草稿引入后的准入边界，金额及投资语义不改。原投资关联服务仅在后续投影维护时可能取得同步锁，不能据此声称匹配前已经锁定；扫描、确认及拒绝在读取当前决定前取得同一工作区同步边界，避免与删除及维护交错。两项预审 P2 按先失败测试完成，不将关闭旧入口当作删除投资产品功能的授权。

手工新建在应用边界显式列出可接收字段：账户名称、金额、币种、时间、对方名称／账号／属性、备注、分类、类型及支付组成项；组成项只接收账户、金额、币种和标签。兼容原有 `category` 输入但不据此猜测分类 ID。来源身份、来源正文、来源键、关系解释、人工保护、对象 ID、状态及审计字段均由服务端管理，未知字段整次拒绝，不静默剥离后保存。明确填写的备注及 `category_id`（含清空）由服务端建立人工保护，不接受客户端自报保护值。HTTP 正文有界，拒绝重复键和非有限数字；协议解码与业务调用分开处理，非法编码、过深嵌套和结构错误统一返回安全 `422`，不泄漏解码器异常。本步不重设既有手工新建的金额或账户业务。

投资关联确认按明确组成项 ID 读取，再按其父流水 ID 校验工作区、活动及正式状态，两次读取均在同一工作区锁及事务内。避免把工作区正式状态过滤与端点连接交给优化器时，在批量导入后统计信息尚未刷新期间退化为重复扫描；不依赖先运行 `ANALYZE`、关闭优化器能力或放宽关系操作预算。扫描及确认的实际万笔背景成本继续单独验证。

### 4. 关系最终图与当前投影

业务构建器先按来源共同操作组织行结果，再合并资金选择、来源补丁与明确的人工补丁；预览阶段不改流水、来源绑定或问题。已有正式流水没有重新选择账户时保留原财务组成，不因账户停用或来源支付方式文案变化阻止普通字段更新；明确选择了不同财务组成则整条跳过。来源合并保护人工备注和分类，之后的明确人工补丁可覆盖保护，同值和清空仍记录人工决定。已知来源更新选择稍后处理时，在原流水保存当前待处理字段，不另造草稿；已有身份问题不会因再次上传同文件且字段完整就自动转正式。共同操作的多个来源行保留独立结果和别名工作，重复不冒充流水更新，矛盾的人工选择不能按遍历顺序覆盖。

关系存储先切换到同一张 `transaction_relations`：移除旧状态、端点代理、排序副本、活动槽、JSON 候选及取代链列；保留主键与投影引用，新增目标合同中的父端点、可空组成项、持久角色、决定组、证据、决定来源及单调修订。父端点独立复合外键与组成项三元外键共同约束工作区和父子归属；锚点必须是当前端点，确认要求双端、双组成项和角色完整。活动父端点不得相同。父草稿／删除状态和具体角色矩阵在共享服务锁内校验，不能以数据库只检查非空代替。

无向同笔支付仅在业务唯一键中按组成项 ID（缺项时按父 ID）排序，持久主／对侧顺序保留原展示基准；不能为了去重改变既有投影的主次方向。有向关系保留业务方向。数据库用活动条件及空组成项的规范表达式索引确保双边唯一，未确定对侧按父锚点及可空锚点组成项唯一，不另存排序副本。候选拆为 `cash_relation_candidates`，保存明确父记录及可空组成项、预期流水修订和当前证据；`validity` 为 `valid/incomplete/stale`，只描述当前候选可用性，不能把组依赖关系当成独立合法。候选变更同时推进关系修订，反向索引用于局部刷新。

迁移按原组成项回填父端点和既有决定角色，保留当前正式财务值、关系主键与投影引用，不重新发现候选或改配对。旧 `accepted/pending_review/rejected` 分别映射 `confirmed/draft/ignored`；`superseded` 为非活动，不能冒充用户忽略。旧无效候选不构造悬空外键，只记录当前缺失数量供刷新；不保留历史取代链。旧服务在最终接口切换前只使用适配 DTO 映射新状态和候选行，不保留第二套列或双写。降级只允许可由旧结构完整表达且未推进修订／使用新组或证据的状态，其他情况明确拒绝，不静默丢失草稿。

旧端点声明为非现金、父子引用缺失或锚点不属于两端时，迁移拒绝并整体回滚，不能依据碰巧相同的整数 ID 改归现金关系；未知旧候选元数据仅降为当前缺失提示，不影响已知关系财务值。新关系只接受明确的现金父端点，现金—投资关系继续使用专用结构。旧投影场景夹具按已有组成项补齐父引用和角色，新合同测试直接覆盖新模型及仓库，不以代理别名维持测试。

未确定对侧时，其组成项和持久角色均为空；候选不能指向自己的父锚点。`decision_source` 描述当前决定，以当前决定者优先于发现者；人工确认／忽略后不能继续标为规则决定。降级逐侧核对可重建角色，不能因一侧未绑定而跳过其值检查。局部端点和候选查询按有界 ID 分片，避免大文件选择触及数据库参数上限。

父端点闭包的递归直接按主／对侧索引展开，不先枚举工作区全部确认边；两个方向使用固定两行方向表及分别按父端点定位的连接，避免一个 `OR` 连接被 SQLite 优化为按工作区遍历全部确认边，也避免按图深度逐次数据库往返。组成项查询保留对应索引供明确的组成项定位使用。SQLite 用实际查询计划复核，PostgreSQL 同跑公共闭包及旧维护合同；批量性能夹具也使用明确父端点、持久角色与当前状态，不能让 ORM 忽略旧键后测到另一份数据。

直接关系读取同样分别沿主端、对侧、锚点和候选反向索引取关系 ID，再按主键读取同一批结果；不用带状态公共条件的多端点 `OR` 扫描。每个分支均独立限制工作区，且 ID 输入有界分片；这是查询边界，不增加另一份关系状态。

新计划保护已确认关系，只有新增正式流水搜索直接候选；普通更新不重配。导入正式类型固定，普通手工不参与现金或投资配对；手工转账内部变化必须保持最终图合法。必须联合生效的退款钻石共享提交组；草稿组保留必要联合标识，用户以后从流水详情共同确认。

已有关系维护从当前流水及其原确认闭包中读取相关关系，按服务端保存的 `decision_group_id` 展开全部当前成员；候选只按这些关系中已有引用有界读取，不触发发现或沿其他草稿递归扩张。原组中已停用的边仍用于核对成员及修订，但默认保持不写任何边，不复活旧成员，也不以统一的延后状态覆盖混合旧决定。服务端输出与导入相同的 `suggestion_id/action/candidate_id`，使用者只选择完整组。未选择的当前组保持原样，不计为新确认或新延后。已有组更新使用原关系 ID、锚点及决定组和 CAS，不能落入导入新增关系的写法。

当前组及候选快照包含全部实例、父／组成项引用、原预期修订、证据及有效性。候选父修订或证明变化须使旧选择失效，延后／保持不得刷新旧证明。只有活动正式端点、组成项归属、角色证据、旧确认占用及完整最终图共同成立时才提供确认；无组成项草稿仍可延后、忽略或解除。多边候选只能生成完整的合法组合，不能把逐边候选独立提交；不能证明完整组合时继续待处理。确认、延后、忽略及解除均按共享端点、旧确认组和显式联合组形成保存点，任一成员失败回滚该单元，独立单元继续；投影和收据发布失败回滚外层。解除更新活动成员，保留此前停用成员，重建解除前后全部相关流水。

已有草稿改选对侧时，预计列表和最终发布范围同时保留旧暂定成员及新成员；旧对侧即使父字段未改变，也展示解除待处理后的当前单例。详情关系影响按原确认边与最终活动状态比较，不只读取类型解除集合，明确解除不能仍标记保留。未确认角色的原消费提示从最终端点的当前来源解释重算；投资退款及个人转账退回只对选定双端复用平台硬键纯规则，重验当前关联键、状态和可信来源作用域，不搜索第三方。旧布尔结论或固定来源编号不能替代可变商户关联键的当前证明；已确认且结构不变的关系仍保留持久角色。

旧维护选择失效时仅撤回该次选择，保持当前组实际决定；不能沿用新建议的默认延后逻辑，将既有确认组重新标为待确认。失效引用仍在响应中明确返回，供使用者刷新核对。

当前关系联合执行使用专用更新器。外层取得工作区写锁后、任何写入前重建并核对完整计划；同次流水写入造成的组成项移除、候选失效和关系修订变化只能按已成功的操作吸收，候选实例、原预期修订和证据不能改变或重新授信。每个当前组同时冻结字段保存后的预期边和选择前原成员，供保存点重验及失败依赖判断。完整组参与图校验，实际只更新发生变化的活动成员；未选组、未变成员及以前停用成员不写。

类型、财务结构或来源关联解释的本次补丁同样参与建议标识，失效选择只要求重新核对，不阻塞合法字段重预览；普通备注补丁不制造配对失效。草稿删除组成项可能把同一关系的多个候选改成同一父引用时，若本次已明确忽略／解除完整组，将该组及其同提交组先在流水保存点内清理候选，再保存组成项，并在整个单元成功后才发布结果；任一步失败共同回滚，不能丢失不同证据。未授权清理的延后动作不能靠删除候选强行保存。关系失败依赖同时覆盖当前候选所引用、并在本次实际修改的流水。

失效选择的原输入及原成员范围仅作为临时计划内的私有验证信息保留，不进入永久收据或公开详情。提交重建及再次重预览只能继续识别同一份已失效选择，不能借旧引用替换动作或注入新候选；按其原影响范围保持默认延后／当前决定，使包含失效选择的新计划仍可保存其余合法操作，不要求前端额外清理隐藏的输入。

临时计划同时保留建议的选择代际。建议因字段或来源解释变化而失效后，即使撤回补丁、原建议再次出现，也使用新一代建议 ID；旧输入持续失效，不能自动恢复执行权。代际在后续重预览及确认重建中保持，使用者可直接从新计划明确选择新 ID。候选证明及其修订不随代际更新，私有代际信息不进入永久收据或公开详情。

最终图服务仅为明确的完整组清理提供窄入口：延后、忽略及解除可以保留组内旧停用成员，豁免联合草稿的活动状态一致检查；完整成员、修订令牌、父子归属、工作区及最终图仍全部校验，旧停用边的全部图字段保持原值。确认继续使用原完整活动草稿组校验和当前角色证据。若清理同时选择服务端候选，仍须按当前计划的完整候选组合重验，不能从清理入口构造任意端点。流水单元失败阻断其旧、新全部端点相关的关系组；关系单元失败只回滚该组，成功流水保持，外层投影或收据失败仍整体回滚。

流水删除沿用表合同的逻辑删除，保留父字段、支付组成项和删除审计，退出当前来源绑定、问题、关系和投影；不能沿用旧实现最后物理删除父记录的行为。删除后的来源再次出现时按新流水静默导入，不用被删对象阻断或复活旧身份，也不提供历史版本产品。

删除范围为明确选择的父流水；旧确认闭包只界定重建范围，不能把整个闭包当作关系删除集。清理直接父端点／锚点引用的活动和停用关系，并完整清理其决定组的未确认成员；同组无关且仍合法的确认边保留。仅反向候选引用被删流水时，只移除该候选、推进所属关系或问题修订，保留其他证明及问题正文，不自动采用剩余候选。来源绑定及被删流水自身当前问题同时退出，避免唯一键阻断静默重导。

删除预览按父引用读取当前关系，包含无组成项草稿，保留当前数据集／版本与可维护范围校验。执行先捕获旧闭包和其他受影响端点，依序清理派生关系引用及当前引用，再标记目标删除、撤销目标正式余额影响并发布局部投影；外层事务失败全部回滚。其余流水不因目标删除而丢失合法关联，不扩张到其他候选的潜在闭包。

预计列表在同一只读快照中使用计划内虚拟父流水、组成项及关系 ID，不提前分配数据库主键；虚拟 ID 不进入公开成员引用，提交后统一换成实际 ID。重预览沿相同来源出现复用服务端已分配的无编号 `record_id`，建议／候选引用按完整成员及结构生成，不能仅按数组位置复用选择。已有流水按当前确认闭包加载，新增正式或草稿转正式才查询直接候选；普通字段更新不启动发现。候选查询以新种子的业务时间窗口、资金账户及来源可靠键限定，不走旧全账本规划或自动替换确认关系的路径。

先虚拟应用合法逐流水及收支对象操作；导入类型固定，手工转账内部双端整体校验，失败撤回整个操作。新关系按旧确认组、共享端点及联合决定组织保守提交组，每组用同一最终图验证后才进入预计合并结果。没有确认的边不占用、不合并，相关正式流水各自统计；组内错误仅生成该组的安全结果，流水和其他合法组继续。列表只显示本次操作和关系涉及的完整结果，历史候选池不成为另一份列表；旧组解除后的其他成员也不能漏掉。

实际发现输入携带当前来源账户作用域：新行取解析来源，已有行按当前来源绑定有界读取；微信旧记录只沿既定默认来源兼容。相同平台的编号证据在同一来源范围内解释，近期开窗与远期可靠键查询遵守同一边界。镜像配对的稳定排序只决定输出顺序，不能用随机 `record_id`、同分最近项或等数量排序配对制造唯一证据；真实多候选保留待确认，额外证据能唯一决定时仍可拟确认。已有确认不按本规则重新发现或改配。

镜像自动确认在双方的完整候选池上分别取证，只有双方均唯一且互相指向时才成立；不能先占用一条弱建议，再把剩余候选当成唯一证据。待确认建议显式携带锚点，最多 20 个展示候选不包含当前默认对侧时也能展开其他合法选项。当前内部调用用 `require_unique_mirrors=true` 接入新构建器，旧写入口暂沿原适配；4.11 关闭旧入口时收敛这一过渡开关，不建立两套长期业务规则。

导入正式流水的类型及子类型不可更新，普通手工流水不存在对外关系。手工转账只允许在同一操作内修改其双端并校验内部关系，不能把内部更新扩展为重新配对。普通公共属性编辑不改变关系；来源记录或候选所依赖修订变化时，候选标记为当前失效。

现金—投资资金关联按固定创建方式准入，只允许导入或历史缺证的正式现金端。非法字段变化拒绝原子操作，不自动解除已有关系；明确解除仍使用既有授权维护入口，不修改投资事件。

角色矩阵具体列于跨层合同 4.6：保留既有支付宝投资支出退款、微信个人转账退回、提现配对、同账户跨币种转账和入出端子类型不同的转账场景。新建议使用来源证据推导角色，已确认角色的兼容检查不依赖可修改文本；两者使用不同入口，不能把旧关系的角色当作新候选证据。角色校验与最终财务图校验均须通过。

最终图共享边界消费完整相关父流水、全部组成项、最终确认边及现金—投资占用；先重验归属、持久角色、组成项金额及占用，再按真实组成项和镜像等价类归并退款分配，最后交给父级投影构建检查结构。父端点相同、金额相同不能证明分配是镜像重复：两个不同组成项各退款 20 元必须合计 40 元，只有经确认镜像证明为同一部分的证据才去重。所有额度加总使用明确的高精度 `Decimal` 上下文，不用 SQL 浮点聚合或候选发现的剩余额度代替最终图检查。资金关联位于非根流水时也须检查互斥。

既有同币种 `0 → 0` 普通退款继续有效：两端父流水总额均为零，支出端保留消费角色、入账端保留退款角色；不因此允许非零父流水仅凭两个零组成项建立退款、单边零退款、零转账或跨币种零退款。该兼容来自现有投影合同，不重新按来源文本判定。折叠后的逻辑边直接携带其分配金额，不能按原物理端点反查而丢失非基准侧金额；明确的零分配也不能回退为整笔父退款。联合草稿确认前按标识读取当前完整成员及修订，校验成员集合和端点仍可用；不能只对调用方传入的残缺边做连通分组。草稿边不占正式额度，合法最终图仍按保守提交组整体验证。

内部最终图输入以 `None` 区分未提供分配与明确的精确零值，先用组成项求出缺省值再校验；非零资金的退款／镜像不能以明确零值建立合并边。旧数据库的零哨兵只由适配层按旧合同转译，新计划保存前已经得到实际分配金额，不能把零值同时解释为缺省和用户决定。

统一应用边界从明确的既有父流水及本次所需决定组加载快照：组按标识读取全部当前成员（包括已解除项），将这些端点加入本次种子后只沿已确认关系展开；不沿其他草稿或候选递归扩张。读取完整相关父记录／组成项、关系角色及修订、资金占用，排除无关来源正文；组成员不能由客户端子集代替。当前令牌由这些局部修订和成员组成，应用前重新读取比较，成员加入、解除、端点类型或占用变化均要求刷新；上下文外修改不应使其失效。该边界在调用方工作区事务内运行，不独立提交，也不创建全局关系组。

组成项没有独立修订且旧写入口不能保证推进父修订，因此令牌还必须覆盖相关父流水（含草稿）的完整组成项财务结构及序号，不能只比较父修订或依靠最终图拒绝变化后的非法分摊。新增／重绑草稿同样检查父端点属于本工作区已加载范围、组成项归属及父记录仍活动；未改的其他草稿邻居不因此扩张范围。联合决定要求所有成员得到一致的当前状态及活动决定，不能用原样草稿或混合忽略成员凑齐 ID 而只确认其中一条。

确认已有草稿、创建或重绑关系时重新按服务端来源证据发现角色；既有确认关系仍只按持久角色重验。组内决定必须覆盖完整当前成员，缺成员或修订变化安全拒绝；更新及新增边共同形成完整最终图，返回旧、新受影响成员及预计结果供计划／提交／维护复用。这里只验证和准备，不先写流水、关系或投影，保存点及同事务发布由联合提交负责。

局部闭包取旧、新已确认图从受影响流水出发的并集，解除后的旧成员仍须重建，草稿／忽略关系不作为合并边。配对提交组按本次全部修改的端点、其旧已确认组以及显式联合草稿标识做保守连通分组；先形成完整分组，再校验每组最终图，不能边提交边决定独立性。组计算只消费应用层已加载的相关图，不自行扫描账本。

局部闭包从旧组与新操作端点展开，只遍历确认边，必要草稿反向引用只刷新待确认标识。每条活动流水恰一个当前投影，草稿单例且无统计资格。派生确认状态及待确认优先展示与统计资格分开；全额退款及全额平台退回在导入预览和主页均展示净额 `0`，已确认且没有待处理事项时也不隐藏。拒绝每次变更生成整个工作区数据集或全库重新扫描。

全额退款可见性按用户最新确认覆盖旧隐藏规则。纯领域构建将这一类结果设为 `visible=true`、`hidden_reason=null`，保留根流水日期、成员、关系及净额算法；普通零金额／余额调整的既有隐藏规则保持。升级迁移只改活动及暂存数据集中已有 `hidden_reason=full_refund` 派生行的显示标志，统一规则版本、ORM 及数据库默认值，并对受影响工作区的当前发布版本递增，使旧列表游标失效；不修改原流水、关系、来源、金额或统计资格，不把未就绪状态改为就绪。降级从正式、支出、存在退款且净额为零识别全部全额退款，包含升级后新生成的结果，恢复旧隐藏语义并再次推进受影响的发布版本，不能倒退版本。迁移属于一次升级维护，普通导入和编辑仍只更新受影响闭包。

草稿在共享投影输入中保留其 `state`、已知财务值及父流水创建时间；未知金额／币种／发生时间继续为空，经济类型不猜测。草稿生成单例、`statistics_eligible=false`，不能作为确认边端点；正式投影的统计资格不因未确认关联而关闭。`attention_count` 只按有问题的不同成员计数，确认状态由草稿或非零计数派生，不独立持久化审批开关。

当前投影增加 `sort_at` 供索引和游标排序：已知发生时间使用发生时间，未知时间的草稿使用父流水创建时间，不能回填 `occurred_at` 冒充账单日期。局部替换和全量修复都沿用同一父创建时间。读取与统计接入前不开放新的草稿写入口；派生表升级保留正式财务值、主键及成员／关系引用，旧发布状态标记待重建，部署时在启用新读入口前显式重建一次当前派生结果，不改原始流水。

已有管理员操作 `POST /operations/projections/rebuild` 承担这一次受控修复，使用目标应用服务及工作区边界；修复成功后才能启用新读取，失败时继续保持不可用，不能把旧形状重新标为就绪。该动作属于后续发布授权，开发验证只针对专用测试库执行；不恢复已移除 CLI，也不把全量修复放进普通导入流程。

待处理信息按本次父流水 ID 有界加载：读取当前问题的 ID／父记录／修订，以及相邻活动草稿关系的明确端点，不读取来源正文或沿候选扩张。每个成员最多贡献一次计数；忽略或已解除关系不贡献。关系上下文令牌同时覆盖当前问题修订，不能因问题变化未推进父流水修订而漏掉失效计划。问题实例 ID 不得因删除重建而复用：SQLite 使用 `AUTOINCREMENT` 并在表重建时保留序列高水位，PostgreSQL 使用原有序列；同父流水、同问题键重新出现也使旧上下文失效，不依赖时钟精度。发布当前结果时统一读取这些信息，单独保存问题或关系的低层仓库不自行在联合组的中间态发布投影。

列表按 `sort_at` 和稳定投影 ID 排序；游标绑定工作区、发布版本和筛选，使用排序位置而非未知账单日期。默认 `state=all`，支持 `posted/draft` 及派生的 `confirmation_status`；未知日期不会被伪造为发生日期，也不会越过用户明确的日期／金额等筛选。列表、当前成员／关系、筛选选项、待确认计数及月汇总在同一个数据库读取快照中生成；月汇总额外要求统计资格，不从包含草稿的页面行求和。待确认仅覆盖业务隐藏，工作区、删除状态和显式筛选始终保留。

全量修复的发布检查包含父流水状态／修订／创建时间、完整组成项、活动确认及草稿决定和当前问题修订；只改变草稿状态或待处理事项也必须使旧输入失效。普通变更仍只维护相关闭包；无组成项的草稿也可作为父流水种子，不因旧的组成项 ID 转换而丢失。

投影存储的工作区、数据集及投影行使用复合外键保持一致，每个工作区至多一个活动数据集。数据集只用于显式全量修复的暂存切换；全量写入和发布前先取得工作区写锁，再强制刷新当前指针及目标，核对它是本工作区的暂存集，不能覆盖活动集；发布还须异于当前指针。不能依赖跨事务保留的 ORM 缓存状态，SQLite 也须在校验前建立实际写事务。清理始终附带工作区条件。成功发布在同一事务切换并刷新活动指针后删除旧派生副本，不保留退休结果。迁移只清理派生副本，不删除或改变来源流水；当前指针、活动集合或已有归属矛盾时拒绝并回滚，不能任意选取一个结果。预检先于任何清理，包含不存在的父行及没有对应指针的活动集；SQLite 迁移关闭外键期间显式按子表到父表清理，完成后校验外键。降级先移除引用约束再移除被引用唯一键，不恢复派生历史。`last_build_id` 只作诊断，不变成保留旧实体的强引用。

确认关系读入必须保留组成项分配证明：涉及确认边的父流水加载完整组成项，经过共享最终图验证后再取得父级关系及分配键；无确认边的独立草稿或正式项仍直接构建。局部维护同时由旧当前成员分组及新确认图求闭包，直到相关成员不再增加；不能在关系解除后只从新图出发而遗漏旧组的另一端。查询按相关 ID 与当前数据集索引，不沿草稿或候选扩大。每轮仅展开新到达成员，已读取的旧分组不重复展开；旧、新分组交替连接的长链也不得反复绑定全部已访问成员。过渡期的旧确认入口同样通过组成项最终图校验，不重新构造丢失分配身份的父关系；旧影响检查须将读入阶段的失败映射为安全业务错误。

共享最终图接入还覆盖已有写入口产生的端点类型：明确的手动信用卡还款命令生成 `repayment/credit_repayment`，明确换币命令生成 `fx_out/fx_in`，普通同币转账保留 `transfer_out/transfer_in`；不能把新建的还款关系绑在不兼容类型上。该解释来自命令业务上下文，不从金额或自由文本猜测。既有源流水不在读取时自动重分类；授权真实迁移前先检查当前确认关系，异常须明确处理，不能为重建成功而放宽角色或额度。

整笔分类的明确人工操作继续作用于其全部成员，逐个合并人工覆盖标记，包含同值选择及清空，保留备注等其他覆盖；自动归并同步跳过成员已有的人工分类。删除分类同时把对应保护值改为受保护的空值，不能在重导入时复活已删除分类。仅实际改变的父修订使候选失效，所有命令先取得工作区锁。

分类保护合并在关系型适配层使用两种数据库各自的 JSON 更新表达式，保留其他覆盖及来源值；按实际变化条件更新并返回父 ID，避免大分类删除逐行加载或逐批读写覆盖对象。分类删除仍按工作区及分类索引定位。已受保护且展示分类也相同的重复专用分类命令不改父修订或投影版本；首次同值确认仍建立保护。只在有候选依赖时读取更新集合并使相应候选失效，不放宽既有分类性能规模及耗时门禁。

流水、支付组成项及当前关系的代理键只在本库标识对象实例，新合同启用后物理删除也不可复用，防止旧修订上下文误命中新对象。SQLite 使用 `AUTOINCREMENT`，表重建保留可用的序列高水位，空表也不能丢失已用编号；PostgreSQL 沿用既有序列。迁移保留当前值、引用及来源关系的表达式唯一索引，降级至前一版本保留这个兼容的安全属性；继续降到重建源表的更早迁移前须另行验证。旧非单调表已经丢失的历史最高编号无法推回，启用新写入口前须使升级前的临时确认上下文失效或排空，不宣称修复既往全部编号复用。该规则不要求跨库代理键相同，也不新增历史版本查询。

草稿状态和未知财务值必须贯穿内部行映射、删除及余额增量：草稿不产生余额增量，不将未知金额当零或将未知日期格式化为有效账单时间；转正式后才按完整组成项应用一次既定余额规则。增量的正负换算、累加及序列化都使用足够的 Decimal 精度，并随外层事务回滚。既有普通及批量删除、编辑和过渡导入均受此约束。统计盘点包含旧管理报表入口，不能只改主页月汇总；收入、支出和资金流汇总必须排除草稿及已删除项，正式收支读取当前投影，不另算一套关系归并。业务隐藏但待确认的可见项，其分类、详情和删除操作采用同一可见条件，不能出现能看到却无法维护的项。

余额入口复用无存储依赖的组成项增量函数，统一排除草稿及删除项；没有余额影响时不改余额内容或更新时间。金额符号换算、旧写路径的组成项合计、现金转账及余额累加使用精度 80 或无舍入的符号操作，仍以 `NUMERIC(38,18)` 校验持久值，不重定义既有转账余额口径。旧管理报表由运行时和 Web 组合入口共同注入当前投影读取器，收支与资金流在同一数据库快照中读取；月份沿用该接口的 UTC 范围和基准流水月份，资金流排序仍为全时段。未就绪派生状态返回安全的暂不可用结果，不能退回原始流水另算收支。原始流水查询同时排除草稿与删除项；完整草稿维护及父锚点关系清理仍在 4.10 接入。

双后端精度盘点同时覆盖 `ExactDecimal` 的结果读取：PostgreSQL 去除补齐尾零时必须保留全部合法位数，不能使用默认精度的 `normalize()`；存储值保持不变，无需 schema 迁移。混合正式／草稿批次只从有余额影响的正式行选择更新时间；内部草稿 DTO 的父账户保留实际空值，不从部分已知组成项补猜。

过渡关系入口的镜像默认分摊使用无舍入绝对值，退款累计在应用层以精度 80 累加当前分摊，不使用 SQLite 浮点 `SUM`；导入预览的组成项完整性合计遵守同样精度。它们仍将在 4.11 随统一写入口切换收敛，过渡期也不能把合法金额判缺失或放过最小单位的超额分配。

### 5. 账户普通命令与前端补偿

计划的账户映射先通过纯组合桥接消费已解析行，不重读文件、不创建账户。来源身份与资金账户映射身份分开：银行完整本方账号用于资金来源组；微信按默认或用户区分的本人来源隔离支付方式映射；来源身份未知时只在文件局部归组。组引用不透明，列表标签不含完整账号；账户选择使用稳定 ID 和预期修订，账户当前不可用或缺少所需币种只影响引用该组的行，保留草稿所需已知金额、币种及组成项；单独修订变化按当前资金资格重验。

4.11 接口接入前补齐账户映射的成功使用证明。沿用 `statement_account_mappings`，新映射的 `identity_kind=funding_group_v1`、键为现有不透明资金来源组引用；不新增表。微信默认／自定义来源、支付宝本人来源及文件局部来源分别隔离。预览在合并同账户组成项前保留来源组到所选账户的证明；只有实际保存成功或已验证等价重复、且最终资金仍使用该整组选择的操作才参与映射发布。单笔账户／组成项覆盖不改整组默认，人工备注或分类不影响证明；失败、跳过及保留已有决定不授予新映射。草稿实际保留所选账户时也可保存映射。映射、余额、投影及收据同事务；同值保存和收据重放不推进映射修订。

会话读取只给出非最终账户建议，不写库，也不悄悄改已冻结的选择。建议须通过当前工作区、账户存在、启用、允许类型和该来源组已知币种校验；成功使用证明也须通过最终该笔所需币种，不因草稿允许保留不完整资金而覆盖已有可用默认。旧映射只允许精确银行身份、默认微信来源的支付方式；不将未区分本人的旧支付宝映射、银行卡尾号或文件局部来源提升成其他来源的默认。完整银行账号的唯一显式账户别名可作建议，冲突保持未选择；不得按账户名称猜测。

识别不了资金来源时先提供文件局部的待选账户组；用户明确选择可用账户后解除该待补原因，不让“原来识别失败”的标记永久阻止完整流水保存。信用卡本方只剩掩码时，不同掩码在文件内仍分开映射，不能把同文件多张卡并成一个未知账户，也不将掩码提升为跨文件来源身份。

支付宝资金部分复用原生支付方式拆分规则，分期归基础账户、非资金附加项排除，仅明确零金额行可回退余额；金额未知不能当零。显式分摊金额与资金标签分开，重复资金来源或最终映射到同一内部账户时合并；仅剩一个实际资金账户且没有矛盾金额时可取父金额，多账户缺分摊保持空值，不用余数猜测。组成项金额沿父记录方向，采用精确十进制及充分精度求和；已知分摊不守恒保留原因，不将其变成正式流水。来源原文与备注均不修改。该桥接只负责准备计划输入，既有正式流水更新仍由统一固定字段约束决定，不能因账户当前停用等新建校验阻止无关可更新字段。

对照原有现金组成项合同，转正式的共享校验同样必须拒绝正负相抵的伪分摊，不能仅因汇总等于父金额就接受；草稿仍能保存未完成信息。建行合并列 `交易地点/附言` 属于原始描述，备注读取完整原文，不从其中拼接或生成另一段说明；这两项在统一计划接入前补回共享边界，不改既定财务或备注合同。

账户增加单调修订、稳定 ID 和幂等收据，所有写入口统一推进。Compose 内普通表单立即保存；前端在内存记录连续修订及可恢复旧值，未完成退出统一询问。删除新账户按 CAS 停用、CAS 删除执行；已被引用或修订链中断不得强制撤销。刷新丢失旧值不猜测恢复，未知导入结果先核实，不先撤销账户。

导入选择携带的账户修订用于识别需要重验，不作为与普通账户修改相同的 CAS 拒绝条件。预览及提交始终按稳定账户 ID 重验当前工作区、存在、启用、允许类型及该条流水所需币种；名称、纯修订或无关币种变化不改变选择的含义。计划指纹保存该流水真正依赖的账户语义，不仅保存易受展示修改影响的修订号；失效的账户及所需币种只跳过相关流水。正式流水普通可变字段编辑继续允许既有停用账户，新增／草稿转正式仍须当前有效账户；账户 PATCH／DELETE 的严格修订约束不变。

是否记住默认是成功后的派生决定，不作为正式可变字段更新的前置条件，也不单独进入操作指纹。冻结的完整选择输入、最终财务字段及新建／草稿账户依赖仍重验。正式流水预览后原账户停用或移除所需币种时，合法备注等修改继续保存，但不记住失效默认；明确换账户仍按固定字段冲突拒绝。

账户依赖从人工补丁合并后的父流水和全部组成项提取并按稳定 ID 去重排序，冻结 `account_id/exists/active/type/currency_support`；币种支持映射只包含该笔实际所需的已知币种，未知值不填猜测键，并由完整性校验阻止转正式。名称、修订号及完整支持币种列表不参与提交指纹；单个分摊账户失效使整条流水跳过，不部分写入分摊，也不自动改成另一份草稿计划。

提交重验发现账户资格变化、且目标流水身份及修订未变化时，逐项结果使用已有安全原因 `account_changed`；目标流水本身或其他依赖变化仍使用对应原原因，不能把无关变化都归为账户问题。

账户 ORM 使用版本列，使旧普通写入口及导入过渡期的币种增补也推进同一修订；新命令另外核对客户端预期修订、持有工作区／账户锁并先查用户范围收据。成功的空补丁也推进一次修订，不以值恰好相同绕过命令链。创建、更新、删除收据允许保存白名单内的普通账户结果字段，用于删除后及后续编辑后的稳定重放；不保存来源正文或前端补偿旧值。

稳定 ID 不可在删除后复用。SQLite 迁移重申 `AUTOINCREMENT` 并保留现存序列高水位，ORM 建表也使用同一约束；PostgreSQL 保留现有序列。账户迁移只增加修订并保留旧字段、引用及余额；已有修订推进时拒绝丢失并发令牌的降级。删除前检查当前引用和非零旧快照；草稿组成项、来源映射或别名等引用也不能被退出补偿级联删除。币种配置修改不删除已存在的分币种余额，新增币种只补缺少的零余额。

删除能力查询与实际删除共用旧快照归属规则：`security/crypto` 均读取 `accounts.security`，不能因账户类型名与存储桶不同就误判无余额。该保护不改变投资功能或金额语义。

账户 HTTP 接口先独立切换：`POST /accounts` 强制幂等键，GET／PATCH／DELETE 使用 `by-id` 路径；移除旧按名称写路径及服务工厂。写正文使用严格模型及 64 KB 流上限，修订号拒绝数值强制转换，重复 JSON 键拒绝。错误仅返回业务原因及有权访问的收据引用；写入存储故障保守返回结果未知，客户端只能用原目标、正文及幂等键恢复，不假定回滚或先执行退出补偿。同步命令在线程池运行，避免等待工作区锁阻塞事件循环。Compose 接口消费和退出补偿仍属于后续跨端步骤，不能因 HTTP 切换就关闭 UI 验收。

账户 UI 编排澄清：上述原正文重试限于本次内存仍保留请求的情形。每条账户命令（包括补偿）发出前先在当前后端／使用者／工作区范围独立保存随机操作键，不与主导入指针共用删除寿命；达到 64 条可见未确定键时拒绝新增命令，不能静默淘汰。跨标签页并发可能短暂超过该准入上限；恢复按最多 64 条一批列出，核实清除后继续列出剩余键，超限不视作数据损坏，也不使任何合法键失去查询入口。刷新后仅按键查询，404 和读取失败都不能推定未提交，不能重造正文或旧值；确定的 `account_*` 收据证明本次成功，随后重新读取当前账户及资格，不用旧收据结果直接填映射。未确定的创建不当作已有账户，相关补偿链暂停，但其余流水可以继续处理并保存草稿，不新增后端 resolve 接口。当前任务内存保留已生效操作的前后值和连续修订，只据此逆序补偿；刷新前的旧值丢失则账户继续生效。实际结果 `committed=true/status=failed` 表示没有成功业务写入，仍按既定合同询问是否撤销独立账户改动，不能只根据 RESULT 阶段或 committed 布尔值决定不再询问。

### 5.1 共享客户端切换顺序

先在现有 FinanceApiClient 数据边界接入当前解析会话及文件命令，再接计划、收据、核实、失败重试和独立账户，随后由共享领域模型及 ViewModel 统一消费；不让 presentation 依赖原始 JSON 或构造服务端操作图。协议层使用字符串对象 ID、可空展示与精确金额字符串；旧收据键按服务端 Unicode 字符数校验长度，严格拒绝未配对代理字符，不替换或修剪原字符。协议层明确必填 null 和完整替换数组，不沿用旧扫描 DTO 伪装成新合同。multipart 元数据与文件部分一一对应，密码仅当次正文；单文件重传携带原 file_ref 及当前修订，其余文件不重读。

客户端上传补充：先前尝试在 multipart 前同时读取全部文件，被独立复核拒绝。当前数据边界改为逐文件有界读取，每次只将一份文件上传到同一解析会话；首个可读取文件创建会话，之后逐份携带最新修订追加。单份本地超限、类型不支持或读取失败保存独立安全结果，其余继续；这些本地结果不伪造为服务端 file_ref。返回本次最新会话、本地失败及请求中断信息，HTTP／权限／网络失败先停止后续请求并保留已知会话，不能当作本地文件失败继续。每次成功响应都可发布进度，取消仍传播取消信号；恢复后根据当前会话核实未确定的追加结果，不盲目重传。

新增有界文件读取能力，不能回退到旧 `read()` 后才检查大小。Native 通过 FileKit 已有 RawSource，最多读取上限加一个探测字节并始终关闭；Web 仅在浏览器不可变 File 的可信大小不超限时读取，不接受未知大小的无界回退；适配器必须处理读取成功、错误及中止，取消时终止读取并清理处理器，不能让本地 I/O 失败无限等待。为直接使用有界缓冲读取，显式声明已由 FileKit／Ktor 解析使用的 `kotlinx-io 0.9.1`，不改变解析版本或新增存储。原字节只在单次上传内存中存在，不落盘、不为整批缓存；新增测试证明读取与发送交替、坏文件不拦好文件、上限探测及资源关闭。

计划选择使用独立的显式 null 序列化合同：`previous_plan_id` 与三种完整选择数组始终发送，账户／候选清空及字段 patch 的 null 不被全局配置省略。列表与结果分别沿用不透明 `cursor`／字符串 `after`；请求由客户端固定本源路径构造，不把响应中的分页值当 URL 访问。收据兼容旧结果缺失的状态、统计和重试信息，不猜测当前值。账户列表的数字 ID 直接读取 JSON 词法值为字符串，不能经过浮点数；修订和资格从 by-id 读取。网络数据边界只发送调用方指定的一次命令，不自动重试或更换键；只保留白名单收据 ID 与已知 `commit_state`，具体恢复状态机留给共享层。

恢复选择的两项 P2 回流：文件变化仍清空可执行计划，但解析上下文私有保存一份最小关系重验证明（旧建议／候选 ID、成员引用、source generation 与每组 choice_generation、失效选择及同一 occurrence 的未入库 record_id 分配），连续变化沿用；新预览只按当前文件及候选重建，不提供旧计划读取／执行能力。证明与会话共用所有者、固定 TTL、CAS 和原预算，不保留执行边、操作图或历史链；成功重预览后移除私有副本，后续从最新计划提取；两处 generation 必须一致，任何非零代数不能在提取时降为默认值，以免旧指纹恢复后旧选择重新命中。完整输入保留旧失效选择用于阻止自动复活；仅本次在当前组通过全部校验且成功应用的显式决定免于旧选择触达兜底，其余受影响组仍延后，不按成员集合扩大豁免。

共享状态切换先补当前领域模型与专用 Repository，将传输 JSON 转为既有结构化字段类型；presentation 不读取 JSON 或依赖旧导入 DTO。会话恢复需区分未曾选择、明确清空和已有决定，保存三类完整选择，不用建议覆盖显式清空。传输错误映射保留安全收据 ID／提交状态，取消继续传播。再以失败状态流测试实现准备、统一核对、结果三种任务状态及提交恢复，最后在同一页面切换中移除旧四步消费者；未接页面的基础实现不算第二个产品流程。

共享状态先以纯转换验证：每个任务有独立 epoch，每个异步请求有递增令牌，全部响应及结束回调必须核对令牌；会话另检查当前标识和修订，收据核对冻结计划或明确待获取的收据。结果阶段清除计划及全部预计数据，仅保留当次文件处理信息，拒绝迟到预览响应。完整选择只由服务端恢复输入或当前详情动作修改，保留显式清空及失效关系选择；新的计划、筛选和会话不能接收旧异步页／详情。确认前冻结 plan_id、修订和随机命令键，冻结后不允许修改选择或再发新提交；未知结果只经四态核实推进，pending 保持未知、retry_original 仅允许原请求、not_committed 才能重新准备，committed 必须取得确定收据。该核心状态不自行重试或持久化财务内容，实际 ViewModel、最小恢复存储和账户退出编排随后接入。

为保持可验证的小步，当前数据接口可以先以未接入页面的能力落地，旧客户端入口只在共享状态／页面切换后整组删除；过渡代码不新增产品入口、不开放第二套后端写入，也不成为可单独部署的兼容承诺。恢复仅保留必要标识，最终状态流不持久保存密码、原文件或财务正文。账户普通命令、提交未知核实、草稿后续维护和最终浏览器／Native／用户演示各有独立验收，不能用 DTO 编译代替 UI 完成。

执行编排先绑定后端地址、认证使用者及工作区，再读取该范围的一份恢复标识；三个范围任一变化不能沿用旧任务。恢复标识区分准备会话、已冻结提交及确定收据，严格限定字段和长度；不缓存完整选择、密码、文件内容、账户原值或财务正文。逐文件上传的进度回调改为可挂起，保存最新会话后才能发送下一份文件，保存失败停止后续传输。确认前保存原计划、修订及命令键成功后才发出请求；保存失败不得发送，仍可重试同一冻结请求。恢复冻结提交时先核实，不能把收据暂未找到解释为未提交；权威未提交后刷新会话才能再编辑。响应和持久化后均检查任务令牌，取消或换任务后的旧响应不得改写新任务状态。

读取当前上下文之前就锁定编辑，读取及保存恢复标识均成功后才解锁；读取失败不能重新启用旧计划。核实接口已按当前所有者确认同一会话消费结果时，允许接收另一客户端以同会话新计划完成的确定收据，不把它误判成永久未知；仍核对当前请求、同一会话及导入操作，其他会话或普通任意收据响应不放开。若实际提交计划不同，丢弃旧预计列表和文件信息，结果仅取真实收据及当前引用。

页面接入前补齐实际结果分页和任务结束动作：逐项结果按收据及种类分页，结果事实可累积，当前投影引用只能来自同一最新版本；任一页版本推进就移除其他已缓存页的旧引用，不把旧归属用于当前导航。取消只用于没有冻结提交的未完成任务，命令前锁定，服务端取消确定并清除本机标识后再重置；未知提交只核实，不能借取消或重新开始丢弃请求。确定完成或已取消之后才清理恢复引用并开始新任务；账户退出询问与补偿仍在独立前端编排完成后调用这些动作。明确回滚或核实为可重试原请求时，允许取消当前会话，但须专用取消状态转换保留冻结命令及原 Submission 标识；取消响应丢失或提交抢先成功仍核实收据。只有服务端确定取消／会话已不存在并完成本机清除，才产生绑定旧任务的取消完成信号供账户补偿使用。原计划被替换后的 `not_committed` 不能代表整个会话已关闭，退出仍须取消当前会话。

取消接口先检查永久收据再检查临时会话，因而该命令明确返回 `410 session_expired`、`404 session_not_found` 或 `409 session_closed` 时，可以结束本机无冻结提交的任务；其他状态或读取收据 404 不能作为这个依据。取消响应丢失、存储清除失败均保持锁定，刷新取得当前状态后才能继续；不能因已经发过取消请求就丢弃恢复标识。

### 6. 客户端规划归属

页面方向与实施以 [导入任务](../compose-cash-import-workflow/design.md)、[账本与补处理](../compose-cash-ledger-maintenance/design.md)、[记账与编辑](../compose-cash-entry-editor/design.md) 为准。共享客户端基础及账户恢复机制保留本节合同，页面不在本变更重复实施或验收。后端、客户端基础完成不代表 Compose Web、Android 或 iOS 新流程可用。

## Risks / Trade-offs

- 既有 schema 非空约束与草稿冲突 → 通过 Alembic 条件约束替换，迁移前后比对正式记录及关系；用 SQLite 与真实 PostgreSQL 同一服务合同验证。
- SQLite 有引用数据时重建父子表 → 迁移连接在实际写事务之前关闭外键执行，使用显式写事务保护 DDL 和数据复制，完成后在事务内运行 `foreign_key_check`，提交／回滚后恢复外键。已在执行真实 SQLite 写事务的外部连接拒绝迁移，不能提前提交调用方写入。PostgreSQL 保留原有事务 DDL 行为。
- 旧迁移链缺失流水到账户的工作区复合外键 → 新迁移检查并补回 ORM 已声明的约束；不修正或丢弃脏数据，无法满足时迁移失败并回滚。
- 来源无编号的完整性假设错误 → 各来源明确完整范围和精度，交叉名称／筛选范围反例先有失败测试；不能静默把可变哈希当身份。
- 旧 API／Agent 绕过新约束 → 切换矩阵列出所有调用方，最终移除或统一委托，不能同时开放两套确认规则；不恢复已经移除的 CLI。
- 外部临时对象不参与业务事务 → 业务收据为成功事实源；失败重试内容可缺失但不能影响已提交流水，旧计划必须锁内重验。
- 回滚后内存状态残留 → 保存点测试注入中间错误并证明下一项读当前状态，外层事务失败不能显示局部成功。
- 实际 QA／依赖环境不足 → 如实记录未完成项及补跑条件；不得跳过双后端、真实浏览器或重大 UI 用户演示门禁。

### 开发中已确认：微信默认单一来源

用户已明确接受工作区内默认一个稳定微信来源、多账号才在文件设置区分。普通导入不要求微信号，也不把昵称当身份；保留其他渠道的本方账户隔离和原始元数据。默认来源与自定义名称分别编码，来源名称按 NFC 及两端空白规范化，最多 64 字符／256 UTF-8 字节，不接受控制字符。来源选择只改变当前文件的规划输入，不改解析正文或已保存流水，复用会话 CAS、权限及消费收据边界；修改后清理本文件行选择并使旧计划失效，重传默认保留选择，TTL 不续期。

新来源键在既有 `account` 作用域存储，范围仍受工作区隔离；不新增来源管理产品或把内部账户当微信账号。同号跨文件自动识别重复和更新，固定金额／方向／时间冲突整条跳过；不同显式来源的同号互不对应，消费与退款各自的渠道编号不合并为一个身份。旧微信记录只有原始交易号与既有 `wechat_<交易号>` 身份一致才按默认来源保守读取，查询兼容旧原文的首尾空白，成功写入时增加当前绑定；已绑定自定义来源者不迁入默认来源。旧隐含来源身份与显式绑定共用兼容校验，草稿合并不能绕过；文件解析失败、密码重传及预算回退仍保存已选来源设置。覆盖不同昵称、同号异侧、消费／退款、旧来源回填及多文件冲突反例后验收。

## Migration Plan

1. 先提交并推送计划，代码前加入失败测试。现有数据迁移只在专用测试库验证，部署或真实账本迁移另需授权。
2. 新增字段／表并兼容读既有正式数据；来源绑定按可证明的当前身份回填，人工值保护按保守策略处理，不凭空分类为来源值。迁移不自动重新配对。
3. 新服务与测试逐层完成后同步切换 FastAPI、Agent 技能及共享 Compose；不恢复已移除 CLI，旧写入口不再独立绕过合同，更新功能地图。
4. 最终验证包括全部回归、双后端、迁移往返／数据不变性、接口权限、并发幂等、性能及三尺寸真实 QA；重大 UI 演示后待用户确认才标完成。
5. 应用回滚前检查新状态存在性。包含草稿、来源绑定或新关系状态的数据库不得直接交给不认识它们的旧应用；可逆 schema 回滚必须验证不丢业务数据，否则保留数据库并前向修复。停止写入、备份和部署均属于后续发布授权范围。

## 导入摘要与提交新增异常

为接通用户确认的 Compose 结果合同，新导入收据在现有 JSON result_summary 中保存 commit_outcome：has_new_failures、has_business_writes 和 reason_codes。status／summary 保留当前兼容语义，不再要求前端通过 partial／failed 猜测异常阶段。新增行／关联组执行失败与来源证明保存失败按执行阶段收集；原计划已知 skip、文件失败及发现失败不加入。批量写回退后逐项最终成功不算新增异常。has_business_writes 沿用现有 written 口径，排除重复。原因固定白名单、去重有界，不存异常原文。该对象与业务／收据同事务发布，读取与重放不重算；旧收据保持字段缺省。无需 schema 迁移。Compose 结果页仅摘要，新增异常只有统一错误、安全原因与返回；后端失败子集接口保留但不新增页面入口。

## Compose 保存与额外影响

普通草稿保存增加 `save_draft` 维护计划意图，使用现有计划上下文、消费收据和 resolve，不把仅查询直接 PATCH 收据当作可终结恢复。保留直接 PATCH 兼容。客户端本机只保存原计划定位，不保存财务补丁；权威未提交后释放原命令并重读当前对象，允许重新编辑。

维护构建器在完整业务构建完成后生成顶层 `additional_effects`，从规范化输入、实际操作、原／最终关系、类型影响及失效决定比较，不能从 UI 首屏或 summary 反推。每项只含安全类型及授权对象引用／字段，不公开内部操作正文或来源 payload。明确请求与必需转账联动不重复确认；额外关系或资金关联解除、非请求有效值、新失效决定与新增待处理必须确认。计划重建会重新计算，提交 fresh 校验同样保护影响事实。未带该字段的旧计划，客户端保守要求确认。

当前问题读取须提供 `pending_source_payload_present`：明确原文替换（含 null 清空）为 true，确认无原文更新为 false，无法判断为 null；复用问题保存时的来源正文存在性，不从 null 正文自行推断清空。只补只读合同，不改变采用／保留权限、来源补丁或提交算法。Compose 用该事实呈现原文替换及清空。
