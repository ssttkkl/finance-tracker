## Context

行为输入为 [主设计](../../../docs/cash-import-redesign.md) 与 [跨层契约](../../../docs/cash-import-redesign-contracts.md)。既有现金数据在 `cash_transactions`、`cash_transaction_components`，关系为 `transaction_relations`，投影已有局部维护服务；现有 `CashLedgerCommandService` 同时承担旧导入和编辑，临时存储保存文件。现有完整回归必须作为切换证据，不能绕过旧路径留下规则分叉。

## Goals / Non-Goals

本变更实现 proposal 所列八项能力；以服务端计划和共享 Compose 流程承载统一合同。历史数据保持其身份、金额、账户和来源，当前角色明确校验；不建设历史版本链，不自动全库重配，不将真实账单写入 Git。外部账单可在专用临时测试库读入，日志仅输出计数和安全失败分类。

## Decisions

### 1. 状态与统一修改规则先于入口切换

在现金父表增加 `state`、`row_revision`、人工覆盖标记；允许草稿业务字段为空，正式记录用条件约束及共享业务校验要求完整。组成项继承父状态，并用工作区、父记录和组成项复合引用保证归属。新增纯领域更新策略，所有写入口调用；固定字段实际改变拒绝，导入同身份冲突整条跳过。拒绝为草稿另设一套业务表，避免补全时复制身份。

来源行允许整体更新；`note` 从原生注释／描述／备注获取，无则空；人工备注和分类单独记录覆盖标记，不把导入器加工描述当来源事实。金额仍使用现有精确 Decimal 类型；SQLite 文本、PostgreSQL NUMERIC(38,18) 由适配器解释，共享范围校验避免静默舍入。

### 2. 来源对应与草稿问题

增加当前 `cash_source_bindings` 与必要候选问题，可靠编号按来源账户作用域绑定，无编号只用经验证的完整范围与多重集合规则。未知来源账户使用非空文件局部作用域，补全后保留别名。既有活动记录优先，删除记录不参与命中；来源变化只更新白名单，不复活旧人工决定。歧义只保存当前问题，不复制正式账务。

实施勘查补充：现有六种来源没有输出可信覆盖范围；首末交易、文件名、解析计数均不能充当完整性证据。新解析结果明确携带来源账户、范围／筛选／边界及证据，缺少时为 unknown。旧 `record_id` 混用平台交易号、商户订单号和内容散列，不直接回填可靠编号；只采用来源明确认证的渠道编号。内容散列仅用于内容比较，原始出现次数必须在进入现有跨行去重前保留。来源所属账户与资金渠道／内部映射分开，不能用银行卡尾号或商户账号替代完整本方身份。

来源对应先实现独立规划器和事务内存储，再在解析会话接入。规划器按文件分别消耗旧候选；同一稳定候选集合整体评估，只有无变化的多重集合、互为唯一且证据可比的更新或结果等价时自动对应。未知范围仅实际碰撞项延后，不把首次无候选的新记录一律变草稿；同文件定位绑定覆盖重复上传和草稿合并后的幂等。来源技能的旧“导入不写关系／映射失败阻断”段落由本变更明确取代，本步仅复用来源字段及校准方法，不改既有分类语义。

来源当前绑定额外保存可空的 `stable_evidence_key` 并建立工作区索引，确保已认证的固定逐行证据经过持久化后仍能命中或排除，不依赖可丢弃的内存属性。该键只由适配器明确认证的证据生成，不采用旧内容散列。渠道编号、认证行证据及已知目标别名共同确定批内冲突范围，不能只检查优先证据而让另一条覆盖同一对象。旧正式记录若缺少可证明的来源账户，仅同固定特征的实际碰撞延后处理，不伪造账户、不自动复制正式记录。候选集合本身改变时也推进当前问题修订，确认版本覆盖正文及候选，不保存历史链。

### 3. 一次解析、不可变计划与收据

新增解析行会话存储接口，复用受控临时存储能力但不调用旧保存原文件行为。服务端解析上传流后立即关闭并清理，逐文件及逐行分离错误。计划只包含服务端验证的操作、预计列表、候选选择和修订；客户端仅传选择及补丁。解析和计算可在工作区锁外，发布、文件修改、取消及最终消费在同一工作区同步边界重验；不只依赖对象存储 CAS。

提交先查持久收据，再取最新计划。一个外层事务持有工作区写锁；每条流水或配对提交组用保存点，回滚后重载 ORM 与余额／标识缓存；最后持久收据、实际结果与投影一起提交。后续同键返回原结果，不重跑失败项。临时失败重试内容须在提交前准备，提交后凭收据访问，原 TTL 到期清理；无内容要求重传。核实未知结果在同锁内确定，禁止把收据 404 当未提交。

解析边界分两步迁入：先逐行读取原始表格、明确位置及文件声明，保留相同内容的每次出现，再调用共享来源分类，单条错误转为安全行结果。平台表格的范围完整性只依据格式声明的起止、筛选与笔数核对，不使用首末流水；声明缺失或笔数不符为 unknown。微信昵称和说明中出现的“微信号”不能冒充本人账号。新文档对象只有解析后的行与必要元数据，不持有文件字节、路径、密码或工作簿；CSV／Excel 读取资源在解析完成时关闭。后续会话和计划只消费该对象，不再调用旧的内容去重或每次预览重读原文件路径。

声明字段必须收集所有精确出现并一致：账户矛盾不产生确定身份，范围／筛选／笔数矛盾或存在结构错误行时不授予完整覆盖证据，仍保留声明、观测计数及其他有效行。平台 XLSX 仅支持 XML 部件，拒绝宏及嵌入二进制、非空目录项、DTD 和实体声明；对所有 XML 做预算及实际行列坐标预检，不依赖扩展名对应的工作表目录。忽略不可信的 worksheet dimension，按实际行读取，补齐 XLSX 隐式尾部空单元格；物理行（包括空行）最多 200,000、业务行最多 100,000、列最多 128、解压总量最多 100 MB、解析文本最多 25 MB。超限为该文件的安全错误，不影响其他文件。

平台逐条归一复用转换器的原生方向、资金归属及分类，不复制一套财务规则；新边界使用完整来源文字填备注，不保留旧生成的说明。可辨认但金额／时间／方向无法确定的行保留空值及当前原因，只有无法处理的适配器异常或结构坏行成为跳过项。任一无法索引的行使可用覆盖证据降为 unknown；正常白名单跳过保留逐行结果。该层不查询账户、不提前合并真实出现，也不执行退款配对。

解析暂存使用独立的单一 JSON 会话对象，包含不可变的所有者／创建与到期时间、单调修订、解析文件集合、最后输入及当前计划；不调用旧原文件存储接口。内存适配器及私有 R2 适配器实现同一条件替换合同：R2 使用读取所得 ETag 的 `If-Match`，首次创建用 `If-None-Match: *`；不能丢失竞争者的修订，也不能退回无条件覆盖。单会话 JSON 最多 25 MB、文件最多 20 份、TTL 最多 1,800 秒且修改不续期；文件加入超预算时由服务保存该文件安全失败结果，不能截断出现或丢弃其他成功文件。取消同样条件写入空正文的终结状态，避免并发发布把取消对象复活。过期不可访问并清理，客户端不取得对象下载地址；部署前接入无人访问对象的有界过期清扫及运行检查，读取时清理不能替代此任务。R2 条件请求能力依据 [官方 S3 API 合同](https://developers.cloudflare.com/r2/api/s3/api/#implemented-object-level-operations) 核实；对象 CAS 只保护临时对象，应用层仍须执行前述工作区同步与收据校验。

### 4. 关系最终图与当前投影

新计划保护已确认关系，只有新增正式流水搜索直接候选；普通更新不重配。类型变化按持久角色及共享类型矩阵保留合法关系，解除非法关系；现金—投资资金关联只处理现金端兼容性。必须联合生效的退款钻石共享提交组；草稿组保留必要联合标识，用户以后从流水详情共同确认。

局部闭包从旧组与新操作端点展开，只遍历确认边，必要草稿反向引用只刷新待确认标识。每条活动流水恰一个当前投影，草稿单例且无统计资格。派生确认状态及待确认优先展示与统计资格分开；全额退款当前待处理项仍可找到。拒绝每次变更生成整个工作区数据集或全库重新扫描。

### 5. 账户普通命令与前端补偿

账户增加单调修订、稳定 ID 和幂等收据，所有写入口统一推进。Compose 内普通表单立即保存；前端在内存记录连续修订及可恢复旧值，未完成退出统一询问。删除新账户按 CAS 停用、CAS 删除执行；已被引用或修订链中断不得强制撤销。刷新丢失旧值不猜测恢复，未知导入结果先核实，不先撤销账户。

### 6. Hallmark 方向及 Cross-platform Impact Check

本轮显式调用 `$hallmark`，按仓库 `docs/ui-design-rules.md` 和既有 FinanceTheme、Material 3、token JSON 预检；继承现有视觉系统，不另建 palette 或网页原型。用户任务：准备文件及账户后看一个流水列表、确认导入、主页继续处理。`COMPACT` 单列全屏，`REGULAR/WIDE` 沿既有全高任务容器，信息顺序为文件账户准备、预计列表、固定最终操作。列表按需展开差异与组成流水；状态文字有语义标签，不只靠颜色。

删除冗余：旧四步导航、独立关系清单、强制补齐映射、正常状态大段教学、逐条无编号身份问答及重复退出弹窗。相关文件为 `CashImportScreen.kt`、`CashImportUiState.kt`、`CashImportViewModel.kt`、`ImportWorkflow.kt`、`CashImportApi.kt`、`CashImportDtos.kt`、`CashLedgerScreen.kt`、`CashLedgerDetails.kt`、共享映射与演示；优先原位替换旧状态机，不删除无关页面。文案和可编辑性由共享层承载，Web、Android、iOS 均受影响，不能以共用代码代替客户端运行证据。

预检自评（设计方向，尚无最终 UI）：Philosophy 5、Hierarchy 4、Execution 3、Specificity 5、Restraint 5、Variety 3。后续以实际 Compose 三尺寸审查和 Hallmark audit 为准；本分数不是 QA 通过。账户表单最大 720 px、窄屏无横向滚动，错误／空／提交中／部分完成／未知结果及键盘返回均须实际验收。

## Risks / Trade-offs

- 既有 schema 非空约束与草稿冲突 → 通过 Alembic 条件约束替换，迁移前后比对正式记录及关系；用 SQLite 与真实 PostgreSQL 同一服务合同验证。
- SQLite 有引用数据时重建父子表 → 迁移连接在实际写事务之前关闭外键执行，使用显式写事务保护 DDL 和数据复制，完成后在事务内运行 `foreign_key_check`，提交／回滚后恢复外键。已在执行真实 SQLite 写事务的外部连接拒绝迁移，不能提前提交调用方写入。PostgreSQL 保留原有事务 DDL 行为。
- 旧迁移链缺失流水到账户的工作区复合外键 → 新迁移检查并补回 ORM 已声明的约束；不修正或丢弃脏数据，无法满足时迁移失败并回滚。
- 来源无编号的完整性假设错误 → 各来源明确完整范围和精度，交叉名称／筛选范围反例先有失败测试；不能静默把可变哈希当身份。
- 旧 API／CLI 绕过新约束 → 切换矩阵列出所有调用方，最终移除或统一委托，不能同时开放两套确认规则。
- 外部临时对象不参与业务事务 → 业务收据为成功事实源；失败重试内容可缺失但不能影响已提交流水，旧计划必须锁内重验。
- 回滚后内存状态残留 → 保存点测试注入中间错误并证明下一项读当前状态，外层事务失败不能显示局部成功。
- 实际 QA／依赖环境不足 → 如实记录未完成项及补跑条件；不得跳过双后端、真实浏览器或重大 UI 用户演示门禁。

## Migration Plan

1. 先提交并推送计划，代码前加入失败测试。现有数据迁移只在专用测试库验证，部署或真实账本迁移另需授权。
2. 新增字段／表并兼容读既有正式数据；来源绑定按可证明的当前身份回填，人工值保护按保守策略处理，不凭空分类为来源值。迁移不自动重新配对。
3. 新服务与测试逐层完成后同步切换 FastAPI、CLI／技能及共享 Compose；旧写入口不再独立绕过合同，更新功能地图。
4. 最终验证包括全部回归、双后端、迁移往返／数据不变性、接口权限、并发幂等、性能及三尺寸真实 QA；重大 UI 演示后待用户确认才标完成。
5. 应用回滚前检查新状态存在性。包含草稿、来源绑定或新关系状态的数据库不得直接交给不认识它们的旧应用；可逆 schema 回滚必须验证不丢业务数据，否则保留数据库并前向修复。停止写入、备份和部署均属于后续发布授权范围。

### Active changes 取代与同步顺序

旧变更仍有各自的未完成验收，不随本变更自动关闭。以下条款在本变更完成后由本 delta 取代，不能之后再次按旧合同同步覆盖；本变更归档前须逐项完成 delta 清理或合并记录。旧变更若先同步，则必须在同一最终同步中应用本变更；若后同步，必须先移除或改写下列已取代条款，仅保留适用差异。此约束同时写入相关旧 proposal，避免只在新变更中留下单向说明。

| 旧变更 | 本变更取代 | 可保留部分 |
|---|---|---|
| `safe-cross-source-refund-replacement` | 新候选自动替换已确认关系及取代链行为 | 确定性结构化证据、最终图合法性和精确退款校验 |
| `exclude-unallocated-components-from-import-relations` | 分摊未完成全批阻断、CLI 跳过、删除旧逐行 requirement 的 delta 操作 | 未完整组成项不能成为已确认关系端点 |
| `route-batch-scan-through-import-session` | 密码重试从暂存原文件读取及全部文件就绪前置 | 统一多文件入口、来源结构探测、逐文件识别 |
| `compose-cash-import-side-sheet` | 四步状态机、未完成退出不得保留独立账户 | 共享响应式任务容器、焦点及返回语义 |
| `compose-cash-ledger-redesign` | 与旧导入流程、字段可编辑性冲突的部分 | 当前账本布局、详情和用户演示未完成项 |

关系组隔离采用主设计第 9.1 节的保守分组：按受影响既有组和共享端点归并，不求解最小依赖子集。
