## Why

2026-10-23 范围调整：用户明确要求本次只完成后端，UI 另开独立任务。此次交付验收覆盖解析、持久化、领域规则、应用服务、HTTP、Agent 入口及后端测试；不包含 Compose 页面、交互、演示、浏览器或 Native 客户端 QA。下文原客户端合同仍是后续实现输入，不代表本次已交付，也不允许提前同步未实现的 UI delta 或归档整个变更。已提交的共享客户端基础保留，本轮尚未提交的 UI 代码已撤回。

现有导入以必须完成的文件、账户、流水、关系步骤组织流程；缺失信息或单项错误会阻断整批，也缺少可在账本中继续处理的草稿。用户已确认重设计及跨层契约，要求把外部账单转为内部流水，以统一列表核对和一次提交完成，并允许替换不合理的旧流程和结构。

## What Changes

- **BREAKING**：以一次解析的临时会话、不可变计划和持久收据替换旧导入合同；解析后不保留原文件，成功项、草稿、跳过原因及关联结果逐项返回。
- 同表保存 `draft/posted` 流水；草稿及未确认关联可在主页详情继续维护，草稿排除所有统计，未确认关联不合并正式流水。
- 全额退款及全额平台退回在导入预览和主页均展示净额 0；无问题时显示已确认，问题解决后不隐藏。升级同步现有派生显示标志并使旧游标失效，原始流水、关系及净额不变。
- 旧导入收据保留原归属、键及真实摘要后迁入统一结果，不伪造新上下文或逐项记录；移除旧表及原文件会话实现。
- **BREAKING**：导入与手动更新共用字段约束；正式金额、币种、时间、资金账户和组成项固定，允许类型及来源行等已确认字段更新，保护人工分类和备注。
- 自动对应来源、区分完全重复与来源变化；无编号采用来源作用域及出现次数，不增加逐条选择负担；删除后再次出现静默重导。
- 微信默认使用工作区内一个稳定来源，普通导入不要求微信号；多账号时才在文件设置区分，不以昵称或内部资金账户代替来源身份。
- 流水按保存点隔离；有最终图依赖的关系按提交组隔离；只维护受影响旧、新关系闭包，关系失败不回滚合法流水。
- **BREAKING**：Compose Web、Android、iOS 共用一个预计投影列表和一次确认；账户创建／修改独立立即生效，未完成任务退出时可安全撤销账户改动。

## Capabilities

### New Capabilities

无；现有能力足以承载目标，不另建关系产品或导入问题中心。

### Modified Capabilities

- `import/cash-import-session`：不保留原文件、部分文件继续、按当前资金资格重验账户、计划修订及消费、持久收据、恢复与限时失败重试。
- `import/statement-import`：来源对应、来源原文备注、草稿、统一字段约束及逐行隔离。
- `cash-ledger/transaction-relations`：草稿关联、联合最终图、已确认决定保护、类型更新清理及局部闭包。
- `cash-ledger/cash-record-classification`：草稿可缺类型、对方账号及属性直接覆盖、普通类型更新无需历史迁移。
- `cash-ledger/cash-category-management`：明确分类保护整笔成员及清空值，自动同步尊重人工决定，待处理项维护范围与列表一致。
- `cash-ledger/cash-ledger-browser`：统一导入列表、确认状态、主页后续处理、独立账户及跨端一致性。
- `shared/ledger-records`：同表草稿、正式字段约束、来源绑定、当前投影和删除重导。
- `accounts/multi-currency-accounts`：普通账户命令稳定引用、并发修订及幂等，用于导入内独立账户操作和安全补偿。
- `shared/cross-platform-presentation`：三端共享统一预览任务、部分错误继续、独立账户及退出合同，替换旧四步和账户草稿。

## Impact

A 类完整变更。影响 Python 领域规则、ORM／Alembic、应用服务、FastAPI、Agent 写入口，以及 Compose 共享数据、状态、页面和演示；不恢复已移除 CLI。功能地图、词表和调用技能随实际能力同步，不提前声称覆盖完成。multipart 上传新增 `python-multipart`，并显式声明已使用的 Starlette API 下限，理由及资源边界见 design。客户端为逐文件有界读取显式声明既有传递依赖 `kotlinx-io 0.9.1`，解析版本保持不变。

验收以 [主设计](../../../docs/cash-import-redesign.md) 和 [跨层契约](../../../docs/cash-import-redesign-contracts.md) 为输入，delta 是本实施变更的行为合同。非目标：重设计其他产品导航、全库重新配对、历史追溯或版本链、自动修正正式固定字段、保留原始文件、修改真实账本。允许只读使用 `~/.ft/bills`，测试数据库及中间结果均在仓库外，提交夹具必须去标识化。

切换采用保留现有数据的 schema 迁移和写入口同步切换，不能用删库重建代替；停止旧版本写入后迁移，回滚先回滚应用与可逆 schema，已生成草稿或新状态时禁止无损保证之外的强制降级。具体风险与恢复条件写入 design 和验证证据。

需求澄清：已显式通过项目 `grill-me → grilling` 核对历次决定；用户本轮明确要求先提交推送计划再开发，并允许发现缺口时补计划。当前没有未决业务分支。提交推送授权限本仓库当前 `average-snail` 分支，不包含 PR、合并、部署或真实数据迁移。
