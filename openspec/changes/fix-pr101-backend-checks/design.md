## Decisions

分类批量读取当前对象及成员，校验完整归属后统一写入；公共值只写稳定对象，单成员对象的拆分恢复值同步，多成员保留原独立值。分类删除必须同时清除旧引用、当前公共值与成员恢复值，按已有语义保留来源原文；用集合 SQL 与有界批次处理 JSON 更新，当前投影同步发布。使用 `(workspace_id, category_id)` 索引，新增可逆迁移；不改旧迁移。

性能夹具补齐当前对象，不绕过创建方式准入。备注验证公共值与对象修订，另断言来源未变；过时的导入金额编辑场景改为合法公共编辑，删除仍覆盖两种模式。优化只在同次操作内复用已验证结果和完整查询覆盖，不保留跨事务缓存，不移除校验。普通 JSON 字段复制对精确标量与普通字典／列表提供快路径，以同一 memo 保留循环及跨字段别名，遇到未知类型、子类或元组即放弃整个快路径并将原值整体委托标准深复制，避免改变自定义复制协议对 memo 的作用；保留原对象引用到复制结束，避免编号复用。JSON 预算检查在既有父深度校验后直接按原成本扣除精确空容器，子类继续递归，不减少预算或合法性校验。计划序列化先处理同一组精确标量类型；组件虚拟编号仅在缺少或为 `None` 时计算一次，保留非空现值及调用内复制边界。组成项始终新建字典；仅当键均为精确字符串且全部值为精确不可变标量类型时复用标量，含嵌套值或类型子类时仍整体深复制，保留未知字段间共享引用和输入隔离；金额、账户、币种、序号校验全部不变。

常规后端全量测试按测试文件确定分片，在独立 runner 内顺序执行，每个 PostgreSQL runner 显式使用独立专用 `_test` 数据库；分片不得遗漏或重叠，收集失败和空分片失败关闭。原检查名汇总全部分片结果，取消、跳过和失败均不能变绿。性能任务继续独立运行。不引入 pytest 并发依赖或迁移缓存，避免同库重置竞争及迁移测试失真。

候选读取按现有关系角色合同使用保守的类型伙伴集合过滤：消费／退款／投资支出、转账双向、提现双向、换汇双向、还款和转账退回。仅排除不可能成为合法现金关系端点的类型，已有关系完整闭包仍由图服务加载并重验；不按文字或来源猜测，不缩短时间窗或减少有效候选。用角色合同矩阵检查预筛选是合法关系的超集，防未来新增角色时遗漏。

完整常规回归还发现旧关系入口在解析明确组成项前，用组成项编号检查父流水创建方式。PostgreSQL 序列不重用导致两套编号分离后，合法关系被拒，编号碰撞也可能误读其他父流水。创建方式检查必须在明确解析组成项后，仅使用真实父流水编号，保留原准入规则并覆盖相反创建方式的编号碰撞。映射测试须自行初始化专用测试库，不能依赖前一模块遗留的 Alembic 状态。

PostgreSQL 游标集成测试的账户查询曾在已持工作区锁的 UOW 内再次进入同一 UOW，第二连接等待第一连接的锁而无法返回。测试辅助查询改为使用当前事务，保留运行时锁顺序及事务隔离，不增加重入／重试路径。关系复核测试读取返回的组成项编号时，显式提供父编号与组成项编号，遵守当前命名空间合同。

## 剩余热路径的实现边界

远端 `013f068` 的 20 个常规及 Compose 检查通过，性能仍有 6 项超时。继续在原预算和工作量内减少同次调用的重复工作：普通容器内精确标量直接复制；独占普通容器的序列化不重复赋值，子类保留完整协议。资金分组摘要仅对精确字符串参数作调用内复用；支付宝解析缓存按文件限制 128 个参数组合，先检查原始账户、文件摘要、解析器版本、金额、支付方式和商品说明的精确类型，其他类型走原逻辑。

无既有记录、单文件同来源和账户、唯一可靠编号及位置、无文档分页证据时，可逐行完成原完整字段校验后直接得到新增结果；标准非分页文件证据可直接保留；未知证据类型、未知字段转换协议及其他输入保留通用来源算法。通用算法只在实际比较时计算规范内容摘要。负向消费的自动关系候选可排除明确属于现有 `source_group=other` 的非空来源，未知／空白来源保留文本回退；银行、平台、硬编号和既有闭包不裁剪。通用商户退款由显式退款种子发起，全负消费种子不会触发该分支；以强制完整候选的最终计划差分约束此条件。

小批当前收支对象读取可在正常 autoflush 下联合读取成员与对象；连接始终包含工作区。ORM 成员指向与联合行不一致、缺对象、禁用 autoflush 或超过 400 个编号时保留原二阶段读取，不能改变会话身份、待写变更和损坏数据的错误。单次记录准备复用无写入间隔的对象及成员快照。分类 JSON 仅在数据库原值精确为 `{}` 或 `[]` 时直构等价结果，其他形状保留原合并。

没有 accepted 关系且全部为精确 `CashProjectionFact` 时，正式单笔可直接构造与原通用算法逐字段相同的投影；草稿、输入校验、最终排序和完整性保持。关系图空边优化必须先完成全部组成项和资金引用校验，仅精确事实、组成项、Decimal 与标识字符串走快路径；子类继续原遍历协议。所有写后重验和错误翻译保留。不调整 UI、财务规则、来源准入、性能预算、runner 或依赖。
