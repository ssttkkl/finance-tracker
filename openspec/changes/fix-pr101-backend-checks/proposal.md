## Why

PR #101 的性能任务有 17 项失败，常规 SQLite／PostgreSQL 全量测试分别超过 20／30 分钟。旧性能夹具未跟随稳定收支对象更新，同时分类批量处理与导入预览存在真实成本回归。

## What Changes

- 按用户确认范围修复全部失败及超时根因，保留原业务合同、性能预算和全部测试覆盖。
- 分类读取与批量写入使用当前收支对象和集合操作，补齐索引及双后端迁移。
- 旧性能场景改用合法来源与公共属性；保留来源不可变、修订、原子性和关系准入。
- 优化完整导入计划及当前关系维护热路径；常规 CI 按文件分片并用原检查名称汇总。

非目标：UI、放宽金额或来源规则、降低性能门槛、新增依赖、修改用户未提交工作、未经授权的提交／推送／合并。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cash-ledger/cash-category-management`：细化当前收支对象的既有集合操作与双后端性能验收。

## Impact

影响分类应用服务、关系／导入计划及持久化热路径、分类索引、性能夹具和 PR 工作流。索引升级不改财务数据；降级仅删除新增索引。既有 active change 的公共属性与创建方式合同保持不变。验收是全部常规回归与性能矩阵通过、原检查完整覆盖、编译及 OpenSpec 检查通过；GitHub 运行结果须在获准推送后另行确认。
