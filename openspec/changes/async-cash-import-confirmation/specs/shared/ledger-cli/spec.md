## ADDED Requirements

### Requirement: 现金导入确认可选择等待最终收据或仅等待受理

CLI MUST 默认等待现金导入的最终入账收据。用户显式选择 `--no-wait` 时，CLI MUST 可在持久受理后成功退出，输出可用于恢复的标识和实际状态。两种模式共用同一操作键及状态协议。

#### Scenario: 脚本按默认方式等待入账

- **WHEN** 用户执行 `ft import confirm BATCH --review REV --json`，后台已受理但尚未完成
- **THEN** CLI 通过短请求查询进度，取得最终入账收据后才报告成功，标准输出提供一个最终 JSON 结果
- **AND** 取消、确定拒写及断网后无法核实均不得报告为成功入账

#### Scenario: 提前退出后接续已受理的批次

- **WHEN** 用户添加 `--no-wait` 并收到持久受理凭证
- **THEN** CLI 的输出区分已受理和已入账，并提供批次与操作标识；再次打开 CLI 可核实同一操作，已经入账时返回原收据
- **AND** 客户端等待期间退出不触发后台取消，也不授权接续进程新建一次导入
