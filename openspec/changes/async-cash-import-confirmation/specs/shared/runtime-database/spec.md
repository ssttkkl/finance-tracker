## MODIFIED Requirements

### Requirement: Kotlin 管理 schema 初始化和版本门禁

系统 MUST 由 Kotlin 后端负责数据库 schema 初始化与版本校验。应用启动不得隐式升级已存在的数据库。启动时若数据库没有应用表，后端 MUST 在单一事务中创建 `20261127_55` 基线 schema 并写入该版本；非空数据库 MUST 校验完整表集合和版本等于 `20261127_55`，不匹配时 MUST 失败关闭，且不得自动升级、降级、重建或改写现有表。

#### Scenario: 空数据库首次启动
- **WHEN** Kotlin 后端连接到一个没有应用表的 PostgreSQL 或 SQLite 数据库
- **THEN** 它 MUST 创建当前基线 schema、写入 `20261127_55`，并开始提供现有 HTTP 合同

#### Scenario: 已处于当前版本
- **WHEN** 数据库已包含完整应用表且版本为 `20261127_55`
- **THEN** 后端 MUST 只校验并启动，不得执行建表或迁移写入

#### Scenario: 旧版本或未知版本
- **WHEN** 数据库版本不是 `20261127_55`、版本行缺失或表集合不完整
- **THEN** 后端 MUST 失败关闭并返回脱敏的存储错误，不得尝试从旧 revision 升级或修改现有数据

#### Scenario: 建库中途失败
- **WHEN** 基线建库在提交前发生任何错误
- **THEN** 数据库 MUST 不保留部分应用表或部分版本记录，后续启动仍按空库处理

#### Scenario: 显式升级已验证的 PostgreSQL 54 数据库

- **WHEN** 运维者对已备份的完整 `20261104_54` PostgreSQL 库显式执行现金导入确认升级命令
- **THEN** 系统 MUST 在一事务中创建受理表并推进版本到 `20261127_55`，保持已有账本事实、收据与版本序列
- **AND** 遇到未知版本或残缺结构 MUST 失败，MUST NOT 改写已有数据
