## ADDED Requirements

### Requirement: 收支账本导入使用独立三步处理页面

收支账本 MUST 将导入入口导航到独立的导入处理页面，而不是在右侧浮窗中完成导入。页面 MUST 按“选择文件”“导入预览”“关系配对”三个步骤组织内容，并在页面上明确当前步骤、可返回的上一步和最终确认导入入口。

#### Scenario: 从收支账本进入导入处理页面

- **WHEN** 使用者点击收支账本中的“导入账单”
- **THEN** 浏览器 MUST 进入独立导入处理页面
- **AND** 收支账本背景和旧导入抽屉 MUST 不再承载该流程

#### Scenario: 步骤间返回

- **WHEN** 使用者在预览或关系配对步骤点击返回上一步
- **THEN** 页面 MUST 保留当前文件和已完成的预览结果
- **AND** 返回或重新选择文件时必须清除受影响的后续步骤状态

### Requirement: 导入处理页面支持标准字段核对和关键状态

导入处理页面 MUST 为预览提供标准化字段表格、四项数量摘要、加载、空结果、识别失败、解析失败、暂不支持、确认中和确认成功状态。页面 MUST 不展示来源账单原始列；桌面和窄屏都 MUST 能访问完整标准字段，窄屏可以通过表格横向滚动而不得造成页面级横向溢出。

#### Scenario: 键盘完成导入确认

- **WHEN** 使用者仅使用键盘选择文件、查看预览、跳过待手动配对并确认导入
- **THEN** 焦点顺序 MUST 按步骤内容自然前进，当前步骤和错误状态具有可访问名称
- **AND** 确认按钮在请求期间 MUST 显示加载状态并阻止重复提交，成功后 MUST 显示导入结果摘要

#### Scenario: 小屏核对预览

- **WHEN** 使用者在 320、375、414 或 768 px 宽度打开导入处理页面
- **THEN** 页面 MUST 无页面级横向滚动，步骤导航、摘要卡片、表格和底部操作均不得溢出视口
- **AND** 标准字段表格可以在其自身容器内横向滚动，主要按钮 MUST 保持至少 44 px 命中区域

### Requirement: 导入入口和结果保持双后端等价

同一工作区和同一导入输入在 SQLite 与真实 PostgreSQL 中 MUST 返回等价的自动识别、标准化预览、数量摘要、配对建议、确认结果、精确金额、幂等结果和错误边界；页面不得根据数据库后端选择不同流程。

#### Scenario: 比较 SQLite 与 PostgreSQL 导入会话

- **WHEN** 两个显式选择的后端处理相同去标识化现金账单
- **THEN** 自动识别渠道、预览行标准字段、四项摘要、关系建议和确认后的账本结果 MUST 等价
