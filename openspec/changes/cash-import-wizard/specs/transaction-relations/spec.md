## ADDED Requirements

### Requirement: 导入会话展示关系配对建议

导入会话 MUST 在确认导入前，基于标准化现金流水、现有工作区流水和既有关系规则展示关系配对建议。系统 MUST 区分自动配对与待手动配对；预览和建议计算不得写入交易关系或收支投影。

#### Scenario: 展示自动配对

- **WHEN** 导入预览中的新流水与现有或同批流水满足唯一且精确的自动关系规则
- **THEN** 第三步 MUST 展示自动配对的关系类型、两侧标准化流水摘要和匹配原因
- **AND** 使用者确认导入后系统才可以在同一确认事务中保存该已确认关系

#### Scenario: 展示待手动配对

- **WHEN** 一个候选关系存在多个对侧候选、证据不足或只能形成待审核关系
- **THEN** 第三步 MUST 展示待手动配对及可选择的合法对侧流水
- **AND** 页面 MUST 允许使用者暂不处理该关系并继续确认导入

### Requirement: 手动配对决定与现金流水确认保持同一事务

使用者在导入会话中主动选择的手动配对 MUST 在确认导入时限定当前工作区、当前预览输入和合法关系类型，并与新现金流水写入、幂等合并和收支投影刷新处于同一 Application Service 事务。暂不处理的候选 MUST 以待审核关系保留或由确认后的关系扫描生成，不得被伪装成已确认关系。

#### Scenario: 确认手动配对

- **WHEN** 使用者为待手动配对选择合法对侧流水并点击确认导入
- **THEN** 系统 MUST 先完成现金流水的幂等写入，再在同一事务中创建已确认关系并刷新受影响收支投影
- **AND** 任一环节失败 MUST 回滚本次确认产生的现金流水和关系变化

#### Scenario: 跳过手动配对

- **WHEN** 使用者不选择待手动配对的对侧流水并点击确认导入
- **THEN** 系统 MUST 写入合法现金流水并保留该候选为待审核关系或等价的可审查状态
- **AND** 不得自动确认该关系，也不得因跳过配对而阻塞合法流水落库

### Requirement: 关系建议保持既有精确和幂等规则

导入会话中的自动配对 MUST 复用既有关系种类、标准记录类型、结构化证据、精确十进制金额比较、工作区边界和关系图互斥规则。相同预览输入、现有账本和规则版本重复进入预览或确认时，建议和已确认关系 MUST 保持确定且不产生重复活动关系。

#### Scenario: 金额存在最小差异

- **WHEN** 两条候选流水的精确金额不相等
- **THEN** 导入会话 MUST 不把它们自动配对
- **AND** 只能按既有规则展示为无建议或待手动配对

#### Scenario: 重复确认同一预览

- **WHEN** 使用者重复提交同一份已确认账单
- **THEN** 系统 MUST 保持原有关系和待审核集合，不得创建重复关系
