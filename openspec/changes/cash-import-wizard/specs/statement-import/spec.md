## MODIFIED Requirements

### Requirement: 受支持账单直接进入统一导入流程

系统 MUST 允许受支持的 CSV、XLS、XLSX 和 PDF 账单作为原始输入，经解析、验证和账户路由后进入一个不立即写入的导入会话。导入会话 MUST 依次提供文件识别、标准化预览、关系配对和确认导入；只有使用者明确确认后，系统才可以把有效业务行写入当前工作区的运行时数据库。原始文件只能作为输入证据，不得成为运行时账本、迁移载体或数据库不可用时的回退。

#### Scenario: 导入受支持文件

- **WHEN** 使用者为受支持导入渠道提交格式有效的账单文件
- **THEN** 系统 MUST 先创建仅存在于当前操作中的导入会话并返回自动识别的导入渠道和标准化预览
- **AND** 在使用者确认前 MUST NOT 创建或更新账本记录、余额、交易关系或收支投影
- **AND** 使用者确认后 MUST 把有效业务行转换为当前工作区的账本记录，并返回可核对的导入计数

#### Scenario: 预览后离开导入页面

- **WHEN** 使用者在确认导入前关闭或离开导入处理页面
- **THEN** 系统 MUST 丢弃本次未确认的导入会话状态
- **AND** MUST NOT 在数据库中留下账本记录、关系或余额变化

### Requirement: 账单渠道自动识别且必须唯一

收支账单导入 MUST 在文件选择后根据已声明的现金账单解析器、文件结构和来源合同自动识别唯一导入渠道。用户界面 MUST NOT 要求使用者先手动选择渠道；无法识别、识别为多个渠道或结构不受支持时 MUST 失败关闭并给出可操作的重试提示，不得猜测渠道。

#### Scenario: 文件识别为唯一渠道

- **WHEN** 使用者选择一份能被唯一现金解析器识别的账单文件
- **THEN** 页面 MUST 显示已识别的渠道名称和文件名，并允许进入导入预览
- **AND** 识别结果 MUST 使用正式 `source_type` 语义，不得使用浏览器文件扩展名代替导入渠道

#### Scenario: 渠道无法唯一识别

- **WHEN** 文件结构无法匹配任何受支持渠道，或同时匹配多个渠道
- **THEN** 系统 MUST 返回明确的识别失败状态
- **AND** 页面 MUST 保留重新选择文件的入口，不得进入预览或写入任何数据

### Requirement: 每个来源业务行都有明确处理结果

支持范围内的每个来源业务行 MUST 在导入预览中满足以下结果之一：待新增、已存在、暂不支持、需要关系处理，或使整批导入明确失败。系统 MUST 展示总记录数、待新增、已存在和暂不支持数量；不得静默跳行、吞掉解析异常或以成功状态掩盖未处理行。

#### Scenario: 预览白名单跳过行

- **WHEN** 来源文件包含该导入渠道明确允许忽略的非业务提示行
- **THEN** 系统 MUST 计入导入预览的可核对摘要
- **AND** 该行 MUST 不创建账本记录

#### Scenario: 预览未知业务行

- **WHEN** 来源文件包含不符合任何已声明业务行或白名单结构的记录
- **THEN** 系统 MUST 使当前导入会话进入错误状态
- **AND** 使用者未确认前 MUST 不写入该文件的部分账本记录

### Requirement: 导入预览只展示标准化字段

导入预览 MUST 展示每条导入预览行的标准化字段，包括发生时间、金额、币种、账户、交易对方、对方账号（存在时）、流水类型、业务细分、分类、备注、导入渠道和处理状态。预览 MUST NOT 向普通使用者展示来源账单原始列、完整来源行快照、内部业务行标识、关系匹配标记或数据库代理键。

#### Scenario: 查看标准化预览表格

- **WHEN** 使用者进入导入预览步骤
- **THEN** 页面 MUST 使用可滚动的表格展示所有预览行的标准化字段
- **AND** 页面 MUST 同时展示总记录数、待新增、已存在和暂不支持数量
- **AND** 表格不得出现来源账单原始列名或原始列值

#### Scenario: 预览存在暂不支持行

- **WHEN** 某预览行因目标账户不支持其币种或其他已声明边界而无法导入
- **THEN** 该行 MUST 标记为“暂不支持”并说明可操作原因
- **AND** 确认导入 MUST 不写入该行，其他合法行仍按既有整批失败或白名单合同处理

### Requirement: 业务行标识提供跨文件幂等

导入幂等 MUST 以当前工作区、导入渠道和业务行标识共同判断，不得以文件摘要或数据库内部代理键作为账本真实性。重复导入同一文件、重叠时间范围文件或完整重导时，预览 MUST 标示已存在行，确认后只允许新增尚未存在的业务行；确认接口 MUST 校验提交文件与预览会话使用的是同一份输入。

#### Scenario: 重复导入相同文件

- **WHEN** 使用者在导入预览中再次提交已经成功处理的同一份账单
- **THEN** 预览 MUST 将对应业务行标记为“已存在”且待新增数量为 `0`
- **AND** 确认导入 MUST 不创建重复账本记录，并报告新增行数为 `0`

#### Scenario: 确认时文件内容已改变

- **WHEN** 确认请求携带的文件摘要与预览会话摘要不一致
- **THEN** 系统 MUST 拒绝确认并要求重新选择文件、重新识别和重新预览
- **AND** MUST 不写入部分账本记录

### Requirement: 来源时间在导入边界解释

导入器 MUST 按来源合同解释业务时间：自带 offset 的时间使用该 offset，无 offset 的时间使用该导入渠道明确规定的来源时区。解释后的时间必须进入统一后端时间边界，且不得由浏览器时区或服务器本地时区重新解释；预览与最终写入 MUST 使用相同时间值。

#### Scenario: 无 offset 的中国账单时间

- **WHEN** 中国账单来源提供无 offset 的本地时间
- **THEN** 导入预览和确认写入 MUST 按该来源声明的中国时区解释后再提交
- **AND** 不得按运行服务器时区或浏览器时区解释

### Requirement: 导入失败不泄露敏感来源数据

解密、解析、映射、精度、币种、时间或持久化错误 MUST 使导入会话失败关闭，错误信息不得记录账单密码、完整账号、Token、来源文件路径或整行来源数据。标准化预览可以展示来源合同允许展示的掩码对方账号，但不得恢复隐藏内容。

#### Scenario: 加密 PDF 密码错误

- **WHEN** 使用者提供的 PDF 密码无法解密账单
- **THEN** 页面 MUST 返回明确失败且不创建账本记录
- **AND** 日志、API 错误和页面文案不得包含密码或账单正文
