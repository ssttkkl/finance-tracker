## Context

现有现金导入会话、`CashImportService`、Web API 客户端和 Native 导入页都以一份原始文件为边界。会话临时存储的 manifest、扫描结果、预览和幂等结果也都是单文件字段；现金导入应用服务在一个事务内完成解析、账户映射、关系应用和投影刷新。现有单文件 HTTP API 与 CLI 已被使用，不能改变其输入输出语义。

本变更需要把“文件集合”提升为导入会话边界，同时保留每个文件的来源渠道、业务行标识和错误状态。临时文件仍属于受控短期输入，不新增持久化导入批次表。金额、币种、工作区隔离、幂等和关系事务继续遵循 `openspec/project-context.md` 以及对应主规格。

## Goals / Non-Goals

**Goals:**

- 以一个不透明会话令牌承载最多 20 个、每个不超过 100 MB 的文件，并在会话中按顺序保存每份文件的摘要、名称、渠道和扫描状态。
- 让所有文件在一个统一扫描、映射、预览、关系规划和确认流程中处理；混合渠道的流水仍保留各自行来源。
- 让客户端在选择阶段只维护低存在感的文件名清单，并按文件内容 SHA-1 去重；密码仅随当前受限请求传递。
- 让最终确认继续使用同一 Application Service 事务、幂等键和回滚边界，且保留单文件调用方兼容性。
- 让 Web、Android 和 iOS 共享相同的状态顺序、错误边界、语义 ID 与用户可观察结果。

**Non-Goals:**

- 不创建持久化导入批次实体，不把原始账单正文、密码或客户端 SHA-1 作为账本事实。
- 不实现账单正文查看器、按渠道拆分的独立确认流程或新的账单解析器。
- 不改变已有单文件原始 HTTP/CLI 合同，也不改变单条流水的允许跳过语义。
- 不引入新的运行时依赖；客户端 SHA-1 使用现有运行时可用的实现。

## Decisions

### 1. 一个会话令牌 + 按文件的临时对象

新增批量请求沿用 `/cash-import/scan`、`/preview` 和 `/commit` 的会话入口，在请求体中携带文件数组；服务端为每个文件保存独立的 `source-{index}` 对象，并在 manifest 保存有序文件元数据、批次摘要、渠道和状态。旧的单文件请求继续使用 `source` 对象和原有字段。

选择按文件对象而不是把文件拼接成一个对象，是为了保留文件边界、支持只重试对应密码文件、清理单个对象并避免解析器通过拼接内容误判来源。选择复用现有 JSON 会话入口，是为了避免引入 multipart 依赖并让旧客户端继续工作；20 个 100 MB 文件的内存和请求大小限制由现有部署限制、客户端逐文件校验和服务端可操作错误共同约束，后续可单独演进为流式上传。

备选方案是创建数据库导入批次表，或直接把所有内容拼成一个临时压缩包。前者会把短期输入引入持久化生命周期并扩大迁移面，后者丢失文件级密码和错误边界，因此不采用。

### 2. 扫描是全有或全无的会话状态机

首次批量扫描逐文件解析并返回 `ready`、`password_required` 或 `error`。任何文件不是 `ready` 时，服务端不返回可进入映射的聚合结果；密码重试使用令牌和按文件索引的密码映射重新解析对应文件，密码不写 manifest、对象、响应或日志。文件失败时 UI 保留删除/重新选择入口，删除或重新添加会清空旧令牌、映射、预览和关系决定并重新扫描集合。

旧单文件扫描保留现有异常型密码错误和状态码；批量流程优先用文件级状态返回可恢复错误，以便一次展示多个问题而不把成功文件误认为可导入。

### 3. 聚合解析与渠道身份

现金导入层增加批量内部命令，把所有已就绪文件解析为带 `source_type` 的行集合，再一次调用来源账户扫描、映射应用、标准化预览和关系规划。`SourceAccountGroup` 的身份继续由渠道、身份类型和来源账户键组成，因此同一渠道的同一来源账户可跨文件合并，不同渠道即使原始业务行标识相同也不会互相覆盖。

Statement import service 增加仅供批量会话使用的 mixed-source 路径；旧调用仍要求单渠道。业务行幂等查询以 `(source_type, record_id)` 为键，批量预览 item 与关系决定使用来源限定的稳定引用，避免不同渠道重用原始业务行标识时发生错误匹配。所有文件的关系候选在一次规划调用中生成，不按文件分别规划再拼接。

备选方案是为每个文件分别调用现有导入服务后再合并结果。该方案无法可靠发现跨文件关系，也会使重复判断和事务回滚边界分裂，因此不采用。

### 4. 摘要职责分离

客户端在选择阶段计算本地 SHA-1，只用于同一选择会话内按内容去重；同名但内容不同的文件保留。服务端继续用现有 SHA-256 校验原始对象，并按有序文件摘要集合计算批次摘要，预览/确认必须校验文件顺序和摘要集合没有变化。响应中返回批次摘要以及每份文件的服务端摘要，便于幂等和审计，不把客户端 SHA-1 当作业务幂等键。

### 5. API 兼容与敏感信息边界

共享契约新增可选 `files`、`channels`、`batch_digest` 和文件状态字段，同时保留单文件的 `file`、`digest`、`channel` 字段。批量客户端方法使用数组输入，单文件方法保留原签名。密码映射仅通过受限请求头传递，服务端读取后立即用于解析；禁止放入 URL、持久化状态、普通响应、日志和业务记录。

### 6. 跨端选择与呈现

Web 使用 `multiple` 文件选择器，Native 使用 Expo DocumentPicker 的多选能力；Android 对部分 DownloadsProvider 的非标准 CSV MIME 使用系统通配选择器，仍由服务端解析器做格式校验，iOS 保留格式类型过滤。两端都在本地读取文件内容计算 SHA-1，限制数量/大小，追加新文件并允许删除。选择区不显示正文或预览，只显示文件名和轻量的删除操作；点击「下一步」之前不发扫描请求。后续密码、错误、映射、预览、关系和确认都读取聚合响应，并共享 presentation 层文案和语义 ID。

原型放在 `prototype/index.html`，沿用现有导入页的紧凑、工具型视觉语言，仅验证选择清单、逐文件状态和聚合步骤，不引入新设计系统。原型覆盖空状态、已选文件、焦点/禁用、扫描中、密码/错误和聚合映射入口，并按 320、375、414、768、1440、390 px 检查无横向滚动。最终实现后使用可用的 Hallmark `audit`；若运行时没有该动作，记录等价人工审查，不声称工具已执行。

### 7. 事务、清理和回滚

批量预览只读临时对象和数据库现状。批量确认复用现有 UOW：先验证会话、文件集合、映射摘要、预览摘要和关系计划，再在同一事务中处理全部文件的账户映射、业务行幂等、关系决定和投影；任何一份文件、任一关系或投影步骤失败都让事务回滚。幂等记录以工作区、用户、会话和幂等键为范围，重试返回第一次结果或同一错误。

只有事务成功后才清理整组临时对象；失败保留可安全重试的会话（不保留密码），过期、已确认和异常清理删除所有 `source-*`、扫描、预览和结果对象。SQLite 与 PostgreSQL 使用同一应用服务和契约矩阵验证，差异只能留在 persistence adapter。

## Risks / Trade-offs

- **请求体和内存压力** → 客户端逐文件限制 100 MB/20 个，服务端在创建对象前验证数量和大小，批量接口对超限返回可操作错误；记录后续流式上传演进点。
- **不同渠道复用相同业务行标识** → 所有批量查询、预览引用和关系决策使用 `source_type + record_id`，并增加混合渠道回归测试。
- **部分密码/解析失败造成误导** → 会话级 `ready` 由每个文件共同决定，任何非 `ready` 禁止映射和确认；客户端显示文件级错误并支持删除/重试。
- **密码或原始文件泄露** → 密码只在受限请求内存中存在；对象私有、日志脱敏、TTL 清理和成功后整组清理均纳入测试。
- **旧单文件调用方回归** → 保留旧方法、旧路由分支、旧响应字段和单渠道约束，先运行现有单文件契约测试再切换批量路径。
- **Native 选择器能力差异** → 统一平台状态合同，平台适配层声明不支持多选时提供追加选择的等价行为；不允许静默替换或直接进入扫描。
- **跨端 UI 漂移** → 共享文案、语义 ID、状态名和聚合字段，并在 Web 与 Native 测试中覆盖相同操作序列。
- **PostgreSQL/SQLite 行为差异** → 使用同一 Application Service 运行契约矩阵；没有专用 `_test` PostgreSQL 时在 tasks 中明确记录未完成，不将其计入通过项。

## Migration Plan

1. 先加入规格、原型、共享契约和失败测试，再实现临时存储/应用服务批量路径；旧单文件路径保持可用。
2. 在 SQLite 上完成批量扫描、混合渠道、重复判断、跨文件关系、失败回滚和幂等回归；构建 Web/Native 并完成真实浏览器 QA。
3. 若本机具备专用 `_test` PostgreSQL，配置 `FT_TEST_POSTGRES_URL` 运行同一契约矩阵；否则在交付记录未完成项和补跑条件。
4. 批量路径出现问题时，客户端可暂时隐藏多选入口，服务端仍保留旧单文件合同；回滚代码只需撤回批量路由/契约调用，不需要数据迁移或清理持久化表。
5. 最终确认成功后归档 change 前，把 delta 同步至主规格；未授权提交/推送不在本次变更范围内。
