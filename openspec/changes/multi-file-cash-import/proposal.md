## Why

当前账单导入一次只能处理一份文件。使用者需要为同一批账单重复进入导入流程，无法在账户映射、流水核对和关系配对时看到完整的流水集合，也无法识别不同文件之间的重复流水或转账关系。

这项变更把多份账单纳入同一个短期导入会话，同时保持导入前不写业务数据、最终确认原子提交和既有单文件调用方兼容。

## What Changes

- Web、iOS 和 Android 的选择文件步骤支持一次会话添加多个文件，并允许继续添加或删除文件。
- 选择步骤只显示低存在感的文件名列表；用户点击「下一步」后才统一扫描，允许混合账单渠道。
- 客户端使用本地 SHA-1 按文件内容去重；不同内容的文件全部保留，最多 20 个文件，沿用单文件 100 MB 限制。
- 对需要密码的文件按文件显示独立密码输入框；所有保留文件扫描成功后，才进入账户映射。
- 服务端导入会话保存多份来源、每份文件的摘要和扫描结果；账户映射、流水预览、重复判断和关系识别基于所有文件的全部流水。
- 跨文件关系候选在同一份服务端预览配对计划中生成，最终确认一次性提交。
- 任一最终提交错误都使整批事务回滚；保留现有单文件 HTTP 接口和 CLI 行为。

非目标：不提供账单正文查看器，不创建持久化导入批次实体，不改变既有可按规则跳过的流水语义，不让不同选择会话共享临时文件或密码。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cash-import-session`：临时导入会话从单份来源扩展为最多 20 份来源，要求按文件保存摘要、文件名和扫描结果，并保持工作区隔离、密码隐私、预览计划和最终确认幂等。
- `statement-import`：允许混合渠道文件在同一导入流程中统一解析、映射、预览、幂等判断和关系识别，并要求所有来源集合参与最终输入校验。
- `cross-platform-presentation`：Web 与 Native 的文件选择、文件列表、逐文件密码、错误重试和聚合导入状态保持相同业务语义。

## Impact

- 后端：导入临时存储、`CashImportSessionService`、现金导入应用服务、关系规划和 Web 路由请求/响应合同。
- 共享包：导入会话状态、文件来源类型、导入 API 客户端、语义测试 ID 和跨端文案。
- Web：`CashImportPage` 的选择阶段、密码阶段和统一扫描状态；需要真实浏览器覆盖桌面与移动宽度。
- Native：Expo 文档选择器、导入页和相同的多文件状态机；需要 Android/iOS 的对应文件选择和错误状态验证。
- 测试：Python 导入会话和应用服务契约、SQLite 与 PostgreSQL 导入矩阵、共享 TypeScript 测试、Web Vitest/Playwright，以及 Native 状态和平台适配测试。
- 依赖：不新增运行时依赖；SHA-1 使用 Web Crypto API 和 Native 现有运行时能力。
