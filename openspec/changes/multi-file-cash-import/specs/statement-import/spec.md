## MODIFIED Requirements

### Requirement: 受支持账单直接进入统一导入流程

系统 MUST 允许一组受支持的 CSV、XLS、XLSX 和 PDF 账单作为原始输入，经逐文件解析、来源账户扫描和账户映射确认后进入一个不立即写入的多文件导入会话。现金导入会话 MUST 依次提供选择文件、统一扫描、账户映射、标准化预览、关系配对和确认导入；不同文件可以属于不同导入渠道，但每个文件自身 MUST 被唯一识别。只有使用者明确确认最终导入后，系统才可以把全部有效业务行和已确认账单账户映射写入当前工作区的运行时数据库。原始文件只能作为输入证据，不得成为运行时账本、迁移载体或数据库不可用时的回退。

#### Scenario: 导入混合渠道文件

- **WHEN** 使用者一次提交来自多个现金导入渠道的一组格式有效账单，并完成账户映射、流水核对和关系确认
- **THEN** 系统 MUST 在一个最终事务中转换并写入全部文件中的有效业务行
- **AND** 返回按文件、渠道和整体批次可核对的导入计数

#### Scenario: 扫描或预览不写账本

- **WHEN** 使用者只完成文件扫描、账户映射确认或流水预览
- **THEN** 系统 MUST 返回合并后的可核对结果，但不得写入账户、账户币种、账单账户映射、现金流水、交易关系或收支投影

#### Scenario: 任一文件未就绪

- **WHEN** 一组文件中仍有文件需要密码、无法识别渠道或解析失败
- **THEN** 系统 MUST 阻止账户映射、预览和最终确认
- **AND** MUST 不得提交该组中任何文件的部分业务结果

### Requirement: 业务行标识提供跨文件幂等

导入幂等 MUST 以当前工作区、每条业务行的导入渠道和业务行标识共同判断，不得以文件摘要、账单账户映射或数据库内部代理键作为账本真实性。重复导入相同文件、重叠时间范围文件或同一批次内重叠文件时，预览 MUST 标示已存在行，确认后只允许新增尚未存在的业务行；确认接口 MUST 校验提交的全部文件、渠道、来源账户分组和账户映射与预览使用的是同一组输入。

#### Scenario: 多文件中存在重叠流水

- **WHEN** 同一批次的两份文件包含相同导入渠道和业务行标识的流水
- **THEN** 预览 MUST 将其按同一业务事实标示为已存在或批次内重复
- **AND** 最终确认 MUST 至多写入一条该业务事实，不得重复记账

#### Scenario: 不同渠道使用相同业务行标识

- **WHEN** 两份不同渠道文件恰好使用相同的业务行标识
- **THEN** 系统 MUST 按导入渠道分别判断幂等，不得把它们误判为同一业务事实

#### Scenario: 确认时文件集合已改变

- **WHEN** 确认请求中的文件摘要、文件顺序、渠道或来源账户分组集合与账户映射确认或预览时不一致
- **THEN** 系统 MUST 拒绝确认并要求重新扫描、重新确认映射和重新预览
- **AND** MUST 不写入部分账单账户映射或账本记录

### Requirement: 账单渠道自动识别且必须唯一

收支账单导入 MUST 对选择集合中的每个文件根据已声明的现金账单解析器、文件结构和来源合同自动识别唯一导入渠道。用户界面 MUST NOT 要求使用者手动选择渠道；不同文件识别出不同渠道是合法的批次状态。任一文件无法识别、识别为多个渠道或结构不受支持时 MUST 失败关闭并返回对应文件的可操作错误，不得猜测渠道或让批次部分进入后续步骤。

#### Scenario: 每个文件识别为唯一渠道

- **WHEN** 使用者提交一组能分别被唯一现金解析器识别的账单文件
- **THEN** 系统 MUST 为每个文件返回正式 `source_type`、文件摘要和行数
- **AND** MUST 合并所有文件的来源账户分组后进入账户映射

#### Scenario: 一组文件包含多个渠道

- **WHEN** 一组文件分别识别为支付宝和微信
- **THEN** 系统 MUST 接受该批次并在预览每条流水中保留各自的导入渠道
- **AND** 关系规划 MUST 同时读取两种渠道的全部待导入流水

#### Scenario: 一个文件无法唯一识别

- **WHEN** 集合中的任一文件结构无法匹配任何受支持渠道，或同时匹配多个渠道
- **THEN** 系统 MUST 返回该文件的明确识别失败状态
- **AND** 页面 MUST 保留删除或重新选择该文件的入口，不得进入账户映射、预览或写入任何数据

### Requirement: 导入关系决定与现金写入保持同一确认事务

现金账单确认导入 MUST 在完成全部文件的业务行幂等写入后，在同一个 Application Service 事务中校验并应用跨文件关系决定，再刷新受影响的收支投影。CLI 与 Web MUST 使用相同的关系规划和应用合同；任一文件流水、关系、账户映射或投影步骤失败时，整次多文件确认 MUST 回滚本次确认产生的全部变化。

#### Scenario: 跨文件确认关系

- **WHEN** 关系预览识别出来自不同文件的两条流水属于同一关系，且使用者确认导入
- **THEN** 系统 MUST 在同一事务中写入全部有效流水并应用该跨文件关系
- **AND** 关系结果 MUST 与所有文件作为一个关系输入集合时的规划结果一致

#### Scenario: 任一文件写入失败

- **WHEN** 其中一份文件的流水、账户映射、关系或投影写入失败
- **THEN** 系统 MUST 回滚本批次所有文件产生的账户、币种、映射、流水、关系和投影变化
- **AND** 不得返回导入成功或留下半完成的关系图

#### Scenario: 重复确认

- **WHEN** 使用者以相同幂等键重复确认相同多文件账单和关系决定
- **THEN** 系统 MUST 返回同一确认结果而不得重复写入流水或关系
- **AND** 既有关系和收支投影 MUST 保持不变

### Requirement: 导入预览只展示标准化字段

导入预览 MUST 在账户映射确认后展示全部文件每条导入预览行的标准化字段，包括发生时间、金额、币种、已选择账户、交易对方、对方账号（存在时）、流水类型、业务细分、分类、备注、导入渠道和处理状态。预览 MUST NOT 向普通使用者展示来源账单原始列、完整来源行快照、内部业务行标识、来源账户规范键、关系匹配标记或数据库代理键。

#### Scenario: 查看混合渠道标准化预览

- **WHEN** 使用者确认完整账户映射并进入流水核对步骤
- **THEN** 页面 MUST 使用可滚动表格展示全部文件合并后的标准化字段
- **AND** 每条流水 MUST 展示其所属导入渠道，整体摘要 MUST 统计所有文件的记录数、待新增、已存在和暂不支持数量

## ADDED Requirements

### Requirement: 多文件关系规划使用统一输入集合

服务端 MUST 在生成导入预览配对计划时，把当前会话内所有已扫描文件的全部有效流水与当前工作区可配对流水放入同一次关系规划。关系规划不得按文件分批运行后再拼接，且预览计划 MUST 能在最终确认时引用每个文件的稳定来源身份。

#### Scenario: 两份文件之间存在转账关系

- **WHEN** 第一份文件包含转出流水，第二份文件包含同一笔转入流水，且两条流水满足既有关系规则
- **THEN** 预览 MUST 生成跨文件关系候选
- **AND** 使用者确认后 MUST 在同一导入事务中应用该关系

#### Scenario: 文件顺序变化

- **WHEN** 使用者删除并重新添加文件，导致文件顺序变化但文件内容集合不变
- **THEN** 系统 MUST 重新生成批次摘要和预览计划
- **AND** 不得复用旧批次的账户映射、关系决定或确认摘要
