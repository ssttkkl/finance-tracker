## Context

本变更承接远端 `refactor/web` 最新基线 `381b48660fb33ccb794f7e3392c0cdf4cbb0ce3b`。当前 `CashImportPage` 直接遍历 `preview.columns` 渲染标准表格，表格最小宽度为 1250 px；收支账本的 `CashTable` 已经实现浏览器本地时间格式化、交易信息双行、月分组和方向金额语义。项目已有 Cobalt token、`Noto Sans SC` + `IBM Plex Mono` 字体和页面级 `overflow-x: clip` 约束。

用户要的是导入预览在核对阶段的可读性，而不是改变导入合同。导入预览仍需保留处理状态和摘要；分类在导入确认前尚未完成，不应成为一列，也不能用内部值代替中文文案。

## Goals / Non-Goals

**Goals:**

- 让核对流水的主扫描顺序与收支账本一致：时间 → 账户 → 交易信息 → 流水类型 → 状态 → 金额。
- 复用现有时间、颜色、字体和交互 token，避免出现第二套账本视觉。
- 让桌面完整展示、移动端自然折叠，并覆盖正常、加载、空、错误、禁用、焦点、确认中和成功状态。
- 使原型可以脱离生产路由直接打开，并能在规定宽度检查布局。

**Non-Goals:**

- 不修改解析器、预览 API、导入会话、关系配对、分类目录或数据库。
- 不在导入预览阶段新增编辑、选择、分类或详情交互。
- 不把“无法识别”行转换成猜测账户或猜测分类；该行状态仍由既有后端决定。
- 不更换项目全局主题、字体、侧栏导航或收支账本实际页面。

## Decisions

### 1. 使用 Index-First 的预览列表结构，生产页面保持现有四步壳

原型和生产实现只重做第三步内容区域，不调整导入步骤、顶部操作位置或确认动作。列表本身成为核对的主界面：上方是简短步骤标题、数量摘要，下面是按月分隔的记录序列。选择 `Index-First` 是因为该结构适合浏览大量同构记录，并且与已有 `Workbench / Ledger Grid` Hallmark stamp 区分开；视觉仍保留 Cobalt 和应用侧栏，保证同一产品的一致性。

备选方案是继续在现有宽表上隐藏几列。它不能解决来源列驱动布局、时间格式和交易信息层级问题，也会让移动端继续依赖横向滚动，因此不采用。

### 2. 固定六个业务信息面，状态并入列表而非恢复原始列

桌面列顺序固定为：`发生时间`、`账户`、`交易信息`、`流水类型`、`状态`、`金额`。交易信息用第一行粗体交易对方、第二行低层级备注；状态使用中文短标签并保留文字，不以颜色单独传达。分类、独立币种、对方账号和渠道等内容在本阶段从首屏删除；完整来源仍由已有详情/证据路径负责。

备选方案是保留“分类”列并显示“未分类”。这会把尚未完成的后续整理状态伪装成当前核对信息，也重复收支账本中分类的后置管理，因此不采用。

### 3. 时间和月份沿用浏览器展示边界

预览行时间使用与收支账本相同的 `formatOccurredAt` 语义；月份 key 使用明确后端时间构造 `Date` 后交给浏览器本地 `Intl.DateTimeFormat`。分组标题展示“YYYY年M月”，右侧按该月预览行和币种计算收入 / 支出汇总。该汇总只是当前预览视图的可读摘要，不写入数据库，也不改变后端摘要。

备选方案是使用来源账单时区或固定中国时区分组。它会和收支账本的浏览器本地展示不一致，也违反时间语义主规格，因此不采用。

### 4. 桌面固定列比例，小屏改成记录卡片

桌面表格 `table-layout: fixed`，列比例优先保证交易信息与金额，表格宽度 `100%` 且不再设置 1250 px 的最小宽度；内容区使用现有应用布局可用宽度。交易对方和备注允许受控换行 / 截断，金额使用 `tabular-nums`。在 820 px 以下隐藏桌面表头，行改成两列 CSS grid：左侧时间、账户、交易信息、流水类型与状态，右侧方向金额；月分组整行展开。页面根级继续使用 `overflow-x: clip`，不使用横向滚动容器。

备选方案是所有尺寸保持宽表并提供滚动。它满足不了“保持横向在一屏视野内”和移动端无横向滚动的项目硬约束，因此不采用。

### 5. 纯展示原型先于生产实现

`prototype/index.html` 使用同一套项目 token 的独立 HTML，包含正常示例、加载、空、错误、确认中、完成、禁用和焦点示例；状态按钮只作用于原型预览，不会成为生产功能。原型顶部保留 Hallmark 设计 / 自检标记，`prototype/tokens.css` 集中定义其使用的颜色、字体、间距、规则和动效 token。

### 6. 共享表格组件承载两种场景，适配器只提供业务字段

新增 `TransactionTable` 作为统一的展示组件：它负责表头、月分组、双行交易信息、方向金额、状态单元、加载骨架、键盘可访问行和桌面 / 小屏布局。`CashTable` 只负责把 `CashProjection` 映射为共享行模型，并提供账本专属的分类、选择、详情和操作菜单；`CashImportPage` 把 `ImportPreviewItem` 映射为相同行模型，开启状态列和月份汇总，不提供分类、选择或操作菜单。这样两个场景共享 DOM 层级和 CSS 断点，同时不会把导入阶段尚未成立的字段塞进账本数据模型，也不需要修改 API。

共享行模型保留可选的 `source` 引用，仅用于账本适配器把用户操作回传到既有回调；导入适配器不暴露来源字段。金额月汇总在前端使用整数缩放的 `BigInt` 字符串加法，避免把展示摘要转换成二进制浮点计算。

## Risks / Trade-offs

- [预览 API 返回列顺序变化导致旧遍历逻辑重新显示内部字段] → 生产渲染改为按固定业务字段组装，状态和类型使用显式中文映射，测试断言禁止出现 `category`、`expense`、`income` 等不应见文本。
- [浏览器本地时区跨月后月分组与后端月份不同] → 只影响展示，不改变提交值；复用收支账本的本地 `Intl` 语义，并增加跨时区单元测试 / 浏览器检查。
- [长对方或备注在固定列中遮挡金额] → 交易信息列占比最大、文本受控截断，完整内容保持在既有详情路径；桌面截图检查金额和状态可读。
- [小屏状态标签或金额导致卡片溢出] → 移动行使用 `minmax(0, 1fr)`、金额列固定可收缩宽度、所有可操作文字 `nowrap`，在 320 / 375 / 390 / 414 / 768 px 实测。
- [重构仅改样式却漏掉状态边界] → 先补预览页面的失败回归，再实现视图，覆盖加载、空、错误、确认中和成功。

## Migration Plan

1. 用户确认原型后，先更新 Web 预览组件测试，使当前宽表在目标行为上失败。
2. 仅修改 `CashImportPage`、相关 Web 样式 / 组件和测试；不运行数据迁移，不改变 API 请求结构。
3. 通过 Vitest、TypeScript、生产构建和生产预览真实浏览器 QA 后发布。
4. 若需回滚，恢复预览组件和对应样式；既有导入会话、数据库记录和服务端契约无需回迁。
