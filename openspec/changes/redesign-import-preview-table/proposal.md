## Why

当前导入账单的“核对流水”仍使用来源字段驱动的宽表：发生时间直接展示 ISO 字符串，导入预览把 `expense` / `income` 等内部值和暂未生效的分类带到界面上，交易对方和备注也没有沿用收支账本的双行信息层级。使用者在确认导入前最需要的是快速核对“什么时候、哪个账户、和谁、是什么方向、多少钱”，而不是阅读解析字段，因此需要在远端 `refactor/web` 最新基线上统一这段浏览体验。

## What Changes

- 将导入处理页第三步“核对流水”改为与收支账本一致的列表优先视图。
- 发生时间按浏览器本地时区格式化为可读的中文日期和时间；月份按同一展示时区分组。
- 将交易信息固定为双行：第一行交易对方，第二行备注；长文本保持可读并在桌面端受控截断。
- 移除导入预览中的分类列、独立币种列、对方账号列等当前核对阶段不必要的信息；不展示尚未分类状态，也不泄露内部分类或记录枚举值。
- 将金额与币种合并为一个金额单元，按支出 / 收入使用已有红色 / 绿色语义，并保留正负号作为非颜色方向提示。
- 按月份插入分组行，并展示该月份预览数据的收入 / 支出汇总；保留“全部、待新增、已存在、无法识别”摘要和行状态。
- 桌面端固定列比例，保证完整表格在内容区一屏横向可见；320、375、390、414、768 px 转为单列记录卡片，不产生页面级横向滚动。
- 保留导入数据、状态、确认动作和后端合同；本变更不改变解析、分类写入、关系配对、金额计算或持久化行为。

## Capabilities

### New Capabilities

无。本次是在既有账单导入能力中调整导入预览的可见行为。

### Modified Capabilities

- `statement-import`：新增导入预览的本地化时间、月份分组、收支方向金额和核对字段展示合同。

## Impact

- Web：修改 `CashImportPage` 的预览渲染，并新增可复用的导入预览表格视图或其等价组件样式；生产入口、步骤和确认接口保持不变。
- 测试：更新预览页面的 Vitest 断言，增加时间、中文流水类型、无分类列、月分组、金额方向及响应式结构覆盖；按仓库门禁补跑生产预览真实浏览器 QA。
- OpenSpec：新增本变更的 UI 原型、设计取舍、实施任务和 `statement-import` delta；不涉及迁移、依赖或双后端持久化矩阵。
- 回滚：恢复 `CashImportPage` 预览结构和对应样式即可回到当前接口驱动宽表，导入数据无迁移影响。
