# 工作区管理页面重设计

## Why

“工作区管理”已经是侧边导航中的一级页面，但当前实现仍沿用早期成员管理表单：内容区过窄、页面内重复提供返回账本、固定 ID 和名称编辑没有形成清晰的信息层级。需要把页面重心改为管理当前工作区，而不是解释页面用途。

## Scope

- 将工作区名称和固定 ID 放在页面顶部的身份区。
- 管理员可以直接编辑工作区名称；固定 ID 只读并支持复制。
- 成员列表作为主内容区，展示邮箱、正式角色名称和管理员操作。
- 邀请链接作为同级操作区，创建时选择“可编辑”或“仅可查看”。
- 所有成员可查看页面；非管理员只能查看，不能修改名称、成员或邀请。
- 桌面端内容填满右侧工作区，移动端改为单列布局。
- 删除页面内“返回账本”和教学说明。

## Non-goals

- 不改变工作区 ID 生成或持久化规则。
- 不新增工作区删除、转移所有权或批量成员操作。
- 不改变成员角色、邀请有效期或后端权限合同。
- 不改变侧边导航和账本页面的路由结构。

## Acceptance

- `/workspace-management` 是与收支账本、投资账本同级的一级页面。
- 页面不显示页面内返回账本链接，也不显示常驻教学说明。
- 1440 px 下内容区域横向使用右侧可用空间，成员和邀请不会被压缩成窄表单。
- 390 px 下内容单列排列，无横向滚动；名称、ID、成员和邀请操作仍可完成。
- 管理员可保存名称、复制固定 ID、调整成员角色、移除成员和创建邀请链接。
- 非管理员看到相同的信息结构，但编辑、成员操作和创建邀请均不可用。
- 保存失败、成员为空、邀请创建成功和加载状态均有明确反馈。
