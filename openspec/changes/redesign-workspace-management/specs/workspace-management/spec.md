## ADDED Requirements

### Requirement: 工作区管理作为一级页面提供管理任务

系统 MUST 在统一侧边导航中提供与收支账本、投资账本同级的“工作区管理”入口。页面标题 MUST 为“工作区管理”，不得使用当前工作区名称替代页面标题，也不得提供重复的页面内账本返回入口。

#### Scenario: 成员从侧边导航打开工作区管理

- **WHEN** 已登录成员点击“工作区管理”
- **THEN** 系统 MUST 在统一右侧内容区打开工作区管理页面，并且侧边导航只标记该一级入口为当前项

#### Scenario: 页面不重复提供账本导航

- **WHEN** 工作区管理页面加载完成
- **THEN** 页面 MUST 不显示“返回账本”链接或常驻功能介绍、操作影响说明

### Requirement: 工作区身份信息区分固定 ID 与可编辑名称

工作区管理页面 MUST 将页面标题与工作区名称分开呈现。管理员 MUST 能编辑工作区名称；固定工作区 ID MUST 只读展示并支持复制，名称修改不得改变固定 ID。

#### Scenario: 管理员修改工作区名称

- **WHEN** 管理员修改名称并点击“保存”
- **THEN** 系统 MUST 保存新名称、保留原固定 ID，并在页面上反馈保存结果

#### Scenario: 成员复制固定工作区 ID

- **WHEN** 成员点击固定 ID 旁的“复制”
- **THEN** 系统 MUST 将当前工作区固定 ID复制到剪贴板或提供可复制的选中值，并反馈复制结果

### Requirement: 成员与邀请按管理任务纵向组织

工作区管理页面 MUST 在同一宽内容区按“工作区信息、成员、邀请成员、删除工作区”的顺序纵向展示管理任务。每个板块 MUST 有可见标题和明确分隔；管理员 MUST 能调整其他成员角色、移除成员并创建指定角色的邀请链接；非管理员 MUST 只能查看成员和当前工作区信息，不能执行这些写操作。

#### Scenario: 管理员管理成员和创建邀请

- **WHEN** 管理员在页面调整成员角色、移除成员或选择“可编辑/仅可查看”后点击“创建链接”
- **THEN** 系统 MUST 调用既有成员/邀请行为并在页面显示对应结果，邀请角色以创建时选择为准

#### Scenario: 非管理员访问工作区管理页面

- **WHEN** `editor` 或 `viewer` 打开工作区管理页面
- **THEN** 页面 MUST 保留工作区、成员和邀请的信息结构，但名称、角色、移除和创建邀请控件 MUST 不可写入

### Requirement: 管理员可安全删除当前工作区

工作区管理页面 MUST 仅向当前工作区管理员提供删除入口。系统 MUST 要求管理员输入当前工作区名称后再次确认，确认不匹配、权限不足或删除失败时 MUST 保持工作区及其数据不变。

#### Scenario: 管理员确认并删除工作区

- **WHEN** 管理员在工作区管理页输入当前工作区名称并确认“删除工作区”
- **THEN** 系统 MUST 在一个事务中永久删除当前工作区、其成员、邀请和全部工作区账本数据，并返回该用户删除后的工作区会话状态

#### Scenario: 删除确认名称不匹配

- **WHEN** 管理员输入的名称与当前工作区名称不完全匹配
- **THEN** 系统 MUST 拒绝删除，不得删除任何工作区数据，并显示确认名称错误

#### Scenario: 非管理员不能删除工作区

- **WHEN** `editor` 或 `viewer` 请求删除当前工作区
- **THEN** 系统 MUST 拒绝请求，不得删除任何工作区数据，且页面 MUST 不提供可执行的删除入口

#### Scenario: 删除后仍有其他工作区

- **WHEN** 管理员成功删除当前工作区且该用户仍属于其他工作区
- **THEN** 系统 MUST 将该用户会话切换到一个仍可访问的工作区，并离开已删除工作区的管理页

#### Scenario: 删除后没有其他工作区

- **WHEN** 管理员成功删除当前工作区且该用户不再属于任何工作区
- **THEN** 系统 MUST 将活动工作区设为空，并引导用户进入创建工作区页面

### Requirement: 工作区删除在双后端保持等价并满足规模性能预算

系统 MUST 在 SQLite 与 PostgreSQL 上使用等价的工作区删除语义：以集合操作清理指向已删除工作区的活动会话，并由数据库级级联清理工作区数据；不得按成员或账本记录逐行加载后删除。固定规模性能夹具（每个工作区 1,000 个活动会话、1,000 条现金流水和 50 个账户）下，删除请求 p95 MUST 不超过 1,000 ms；会话清理 MUST 使用单条集合更新。

#### Scenario: 大工作区删除使用索引化集合清理

- **WHEN** 管理员删除包含固定规模夹具数据的工作区
- **THEN** 系统 MUST 以一条按 `active_workspace_id` 过滤的集合更新清理会话指针，删除请求 p95 MUST 不超过 1,000 ms，且工作区级联数据仍完整删除

#### Scenario: SQLite 与 PostgreSQL 删除结果等价

- **WHEN** 相同的固定规模夹具分别在 SQLite 和 PostgreSQL 上执行管理员删除
- **THEN** 两个后端 MUST 返回相同的活动工作区切换结果，并删除工作区、成员、邀请与账本数据；PostgreSQL 验证必须使用专用 `_test` 数据库

### Requirement: 工作区管理页面适配桌面与移动视口

页面 MUST 在桌面端填满统一账本壳的右侧滚动区，并在移动端改为单列布局；在 320、375、390、414、768 和 1440 px 宽度下 MUST 不产生横向滚动或文本溢出。

#### Scenario: 桌面端按顺序使用可用内容宽度

- **WHEN** 使用 1440 px 宽度打开工作区管理页面
- **THEN** 工作区信息、成员、邀请成员和删除工作区 MUST 从上到下排列；每个板块使用可见标题和分隔线，右侧内容区可独立滚动

#### Scenario: 移动端使用单列布局

- **WHEN** 使用 390 px 宽度打开工作区管理页面
- **THEN** 工作区身份、成员和邀请区域 MUST 按单列排列，页面 MUST 无横向滚动且所有主要操作可触达
