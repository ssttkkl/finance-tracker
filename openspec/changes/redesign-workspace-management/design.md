# 工作区管理页面设计

## Information architecture

页面按使用者任务分为三段，使用同一宽工作区承载，不使用卡片套卡片：

1. **工作区身份**：页面标题“工作区管理”、可编辑名称、固定 ID 和复制操作；工作区名称不是页面标题。
2. **成员**：成员邮箱、正式角色名称和管理员可执行的操作。
3. **邀请**：选择“可编辑”或“仅可查看”，创建邀请链接并显示结果。
4. **删除工作区**：管理员可见的低优先级危险操作，与主要管理任务分隔；删除入口不在首屏身份字段中重复出现。

侧边导航已经提供页面入口，因此页面主体不提供返回账本链接。名称和 ID 同一行展示，成员占据桌面端主要宽度，邀请作为右侧同级区域；小屏幕时两者顺序改为上下排列。

## Visible copy budget

正常状态只保留以下必要文字：`工作区管理`、`工作区名称`、`固定 ID`、`成员`、`邀请成员`、`删除工作区`、邮箱、`管理员`、`可编辑`、`仅可查看`、`保存`、`复制`、`移除`、`创建链接`。不显示功能介绍、操作影响、权限机制或实现说明。

状态文字只在对应状态出现：读取中、保存成功/失败、复制成功、没有其他成员、邀请链接已生成、删除失败。删除确认弹层只说明“将永久删除当前工作区及其全部账本数据、成员和邀请”，并要求输入当前工作区名称；每段帮助文字不超过 16 个汉字；本页面正常状态不安排常驻帮助文字。

## Interaction

- 名称输入框仅管理员可编辑；名称为空或未变化时保存按钮禁用。
- 固定 ID 使用等宽字体展示，复制按钮复制当前值，成功后短暂显示“已复制”。
- 保存、复制、移除和创建链接按钮使用对应的通用线性图标，并保留文字标签；图标只辅助识别，不承担唯一语义。
- 当前用户只显示角色，不允许自己修改或移除自己。
- 其他成员的角色选择和移除按钮仅管理员可见；最后一个管理员的保护由后端负责，失败时显示接口错误。
- 邀请角色在创建时选择；链接生成后显示只读输入框，方便复制。接受邀请页面不提供角色修改。
- 非管理员保留相同布局，名称输入、成员选择、移除和创建链接均为禁用或只读状态。
- 删除工作区入口和确认操作仅管理员可见；确认输入必须与当前名称完全匹配。删除成功后返回账本；若没有其他工作区则进入创建工作区页面。取消、输入不匹配和接口失败均留在当前页。
- 删除事务先以单条集合更新清理所有 `active_workspace_id` 指向当前工作区的会话，再删除工作区并使用数据库外键级联清理成员、邀请和账本数据；删除后只查询当前用户的第一个剩余成员关系决定会话去向。

## Responsive strategy

- 桌面（≥ 1024 px）：应用壳的右侧滚动区内，身份区横向铺开；成员列表与邀请区使用 `minmax(0, 1fr)` 网格，成员区优先获得空间。
- 移动（< 1024 px）：页面主体单列；身份区的名称和 ID 分行；成员每行允许操作换到下一行；邀请控件纵向排列。
- 在 320、375、390、414、768 px 检查无横向滚动、邮箱不撑破布局、按钮保持可触达。

## Persistence and performance

- `user_sessions.active_workspace_id` 不建立外键，以保留跨工作区登录会话；为删除时的集合更新增加 `ix_user_sessions_active_workspace`，避免按工作区清理会话时扫描整张会话表。
- 删除接口保持一个写事务和数据库级级联，不在应用层逐行加载成员或账本数据。性能夹具固定为每个工作区 1,000 个活动会话、1,000 条现金流水和 50 个账户，分别在 SQLite 与 PostgreSQL 上采样 1 次预热加 5 次，删除请求 p95 预算为 1,000 ms；同时断言会话清理为单条集合 `UPDATE`。
- 新增 Alembic 迁移只创建索引；回滚仅删除该索引。SQLite 与 PostgreSQL 均从当前 head 执行迁移并运行同一删除契约与性能门禁。

## Hallmark pre-check

- 目标：`/workspace-management` 页面。
- 方向：沿用 Cobalt 工作台 token，减少装饰性容器，使用边界线和留白表达分组。
- 已删除：页面内返回链接、功能介绍、操作影响说明、邀请机制说明和窄表单外壳。
- 原型：`prototype/index.html`。
- 原型状态：正常管理员、只读成员、空成员、保存错误、加载中、邀请生成后和删除确认。
- 最终 UI 需要在 1440 px 与 390 px 截图，并运行 Hallmark `audit`；critical/major finding 修复后重新审计。

## Final audit

最终页面沿用现有 `Workbench / Ledger Grid` 结构和 Cobalt token。对 `web/src/AccessApp.tsx`、`web/src/App.tsx`、`web/src/styles.css`、`/tmp/workspace-management-delete-desktop.png` 和 `/tmp/workspace-management-delete-mobile.png` 执行 Hallmark `audit` 只读审查，新增检查管理员危险操作与确认弹层：未发现 AI 模板结构、设计系统漂移、实现术语、重复教学文案、确认缺少具体影响或确认弹层在移动端溢出；结果为 0 critical、0 major、0 minor。
