## Why

Compose 共享界面同时使用标准 Material 3 对话框和自行绘制的弹层，但它们的容器层级、响应式尺寸、任务边界和确认语义并不一致。审查发现日期选择会在确认前提交，流水删除确认也把多个结果并列成独立操作；进一步对照 Material 3 Dialog 指南，发现导入流程在宽窗口仍使用全屏容器，且未确认就会丢弃未完成的导入。继续审查业务行为后，还发现编辑流水离开时会直接丢弃修改、部分提交错误没有保持在模态任务中、只读投资详情在紧凑窗口使用全屏容器，以及模态内菜单的 Escape 可能越过菜单关闭底层对话框。再次审查紧凑窗口截图时，发现只读流水详情和删除/关联移除确认也复用了全屏任务容器；这些短任务应使用基础对话框，避免空白全屏和把确认误呈现为独立流程。

## What Changes

- 审查 Compose 共享实现中的 `Dialog`、`AlertDialog`、`DatePickerDialog` 及承担同等模态职责的容器，按 Material 3 对话框类型、任务边界、关闭/确认语义和响应式容器规则复核视觉设计与业务行为。
- 仅允许在 `COMPACT` 全屏对话框上打开 M3 基础对话框，用于账户编辑、未提交内容丢弃确认和提交失败后的重要错误；`REGULAR`/`WIDE` 的基础对话框不再嵌套另一基础对话框，而在当前容器内切换状态。
- 避免在较宽窗口的基础对话框中再打开日期/时间基础对话框；选择器在当前对话框内容内展开并保留确认/取消语义。
- 标准 Material 3 对话框继承 `FinanceTheme` 的形状和表面角色；自定义基础对话框使用 Material 3 容器与不超过 560 dp 的宽度、单一遮罩，按短内容收缩，并在正文滚动时固定标题和操作区。
- 多步骤导入在 Compact 使用全屏对话框，在 Regular/Wide 使用基础对话框；退出含未提交内容的导入前，先用基础对话框确认是否丢弃。
- 只读的投资事件与持仓详情在所有窗口尺寸使用基础对话框；Compact 不再把详情铺成全屏任务。
- 只读流水详情在所有窗口尺寸使用基础对话框；Compact 居中限宽，Regular/Wide 保留右侧定位；长正文独立滚动，标题与可见关闭入口固定。
- 只有需要编辑草稿或逐步查找并创建关联的流水任务在 Compact 使用全屏任务面；删除、取消关联、解散关联等短确认在当前详情基础对话框内切换状态，不再占据全屏，也不在基础对话框上再叠一层基础对话框。
- 只读详情在固定标题和滚动正文之外，提供始终可见的关闭入口；编辑和关联创建按各自任务使用 Compact 全屏或 Regular/Wide 基础对话框，确认状态使用当前任务内的取消/保留操作，避免重复关闭。
- 保留宽屏账单详情右侧面板，但遵守 M3 大屏自定义定位时的边缘留白。
- 将账单详情的“编辑”和“更多操作”固定在模态容器底部，避免详情正文滚动后主要入口消失。
- 编辑流水时，若草稿已改变，取消、Back 或关闭前先确认丢弃；Compact 在全屏编辑上显示基础确认对话框，Regular/Wide 在当前基础对话框内切换确认状态；取消保留草稿，确认只丢弃未保存内容。
- “取消关联”与“解散关联”执行前先明确说明会移除关系、保留流水，并由用户确认；取消时不调用关系移除操作。
- 提交中的确认按钮保持可用并显示进行中状态；现有 ViewModel 请求保护负责阻止重复提交。全屏任务提交失败时在其上显示基础错误对话框；宽屏基础任务在当前容器内进入错误知悉状态。若使用者已关闭正在保存的面板，则以单操作基础对话框呈现错误并保留原有数据结果。
- 若用户在危险操作请求完成前关闭确认框，操作失败时以单操作基础对话框给出错误确认。
- 导入请求处理中用户尝试关闭时，在当前全屏任务内显示等待提示并保留可操作的继续入口，不在全屏任务上叠加信息对话框。
- Full-screen dialog 可以承载一个 M3 基础对话框；Compact 流水编辑和导入中的丢弃确认、账户编辑及提交错误使用此模式。基础对话框上不再打开第二个基础对话框；Regular/Wide 任务在当前容器内切换状态。
- 当菜单或选择弹出层打开在对话框之上时，Escape 先关闭最上层菜单并保留对话框任务；再次 Escape 才按任务规则关闭对话框。
- 日期选择只在确认后写入，取消不改变表单；清除日期移到日期字段；流水删除先选择影响范围，再用单个危险确认操作提交。
- 保留紧凑窗口筛选底部弹窗、较宽窗口筛选对话框，以及账单编辑的紧凑全屏和较宽窗口右侧面板合同；筛选及投资详情基础对话框遵守 560 dp 宽度上限。
- 更新账本功能地图与三尺寸 Web 截图/交互记录，明确只读流水详情与短确认使用基础对话框，Compact 编辑和关联创建保留全屏任务。
- 在 `tasks.md` 记录对话框行为审查、Hallmark 审计、功能地图、跨端影响和 Web 浏览器 QA。

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `shared/design-system`: 增加 Compose 对话框的 Material 3 设计与行为合同。

## Impact

- 影响 `compose/shared/src/commonMain` 中共享 FinanceTheme、账单、导入、投资、工作区和确认弹层实现；Compose Web、Android 与 iOS 共用这些改动。
- 更新 `docs/feature-map.md` 的相关实现证据和 `compose/qa/web` 现有浏览器用例。
- 不改变账单、关系或投资领域规则；仅调整日期确认时点、导入放弃确认、响应式容器及删除确认的交互表达，最终保存/删除结果仍走现有业务操作。
- 按用户此前指定，仅运行 Compose Web 验证；Android 和 iOS 不做运行验证。
