## Context

参见 [proposal.md](proposal.md) 与 [delta 规格](specs/shared/design-system/spec.md)。对话框分布在账本、导入、投资、分类和工作区页面；部分使用 Material 3 标准组件，部分用 `Dialog` 自行绘制。当前 `FinanceTheme` 的 `extraLarge` 只有 5 dp，标准 M3 对话框也因此被压成小圆角；账本筛选和投资详情自定义基础对话框超过 M3 560 dp 最大宽度；导入多步骤流程在所有窗口尺寸都使用全屏容器，并且退出时不确认就清空未提交进度；日期选择通过状态监听即时写回，取消路径不能撤销。业务行为复核还发现流水编辑可在未确认时丢弃草稿、保存失败在部分路径中没有对话框级反馈，以及宽窗口投资详情仍暴露全屏对话框的关闭按钮。对截图的第二轮 Material 3 复核进一步发现，Compact 只读流水详情和删除/取消关联/解散关联等短确认使用全屏任务面，导致短确认呈现成独立页面并留下大量空白；这些状态应在限宽基础对话框中完成。

## Goals / Non-Goals

**Goals:**

- 按用户触发、单一任务、明确标题与结果、确认/取消语义和适配任务复杂度的 Dialog 类型审查共享 Compose 弹层；检查视觉规范与业务行为，尤其是未提交表单/导入的退出、提交失败和进行中操作。
- 让标准 M3 对话框从 `FinanceTheme` 获得合理形状；让自定义容器使用 M3 Surface 角色、层级与响应式布局。
- 只读流水详情和短确认在所有窗口使用基础对话框；Compact 编辑与关系创建等包含暂存输入的任务使用全屏对话框，`REGULAR`/`WIDE` 使用限宽 560 dp 的基础对话框。
- 修正日期选择的暂存/提交语义、流水删除多结果选择方式和重复关闭入口。
- 修正导入放弃确认、请求中关闭语义，并保留筛选的实时应用行为。
- 保持 Compose Web、Android、iOS 的交互语义一致；按用户指定只在 Web 运行验证。

**Non-Goals:**

- 不调整账户、账单、分类、投资和工作区业务规则，不改变保存/删除 API、影响范围或财务结果。
- 不重构普通菜单、FAB 菜单、导航抽屉或独立 `ModalBottomSheet`（紧凑账本筛选除外：仅恢复 M3 默认形状）。
- 不添加自定义焦点捕获、焦点回跳或焦点边框逻辑；保留 Compose Dialog 默认的模态与键盘行为。
- 不进行 Android 或 iOS 运行验证。

## Decisions

### 对话框模式与信息架构

- 标准 `AlertDialog`、`DatePickerDialog` 用于短确认与聚焦输入；保持其 M3 标题、正文、动作区和默认容器行为。
- 多步骤账单导入在 `COMPACT` 使用全屏模态任务，在 `REGULAR`/`WIDE` 使用基础模态对话框；内容过长时仅正文滚动，标题与操作区固定。全屏任务的主要确认动作位于标题栏；较宽窗口的基础对话框操作留在底部。
- `REGULAR`/`WIDE` 的导入基础对话框不重复显示标题栏关闭按钮；由操作区中的“取消”或“返回”提供明确的界面内退出路径，Escape 和遮罩关闭执行相同的状态转换。短内容按内容收缩，超出可用高度时仅正文滚动，标题与操作区固定。
- 全屏导入流程未提交且包含文件、扫描结果或阶段草稿时，点关闭、Back 或 Escape 会在 Compact 全屏任务上打开 M3 基础丢弃确认对话框，提供“继续导入”和“放弃导入”；取消保留原任务及其草稿，确认后退出且不提交账单。空白的初始选择页可直接关闭。`REGULAR`/`WIDE` 在当前基础对话框内切换同一确认状态，不在基础对话框上再嵌套基础对话框。
- 新账户编辑在 Compact 使用覆盖于导入全屏任务上的 M3 基础对话框；Regular/Wide 在原基础对话框内切换内容。取消保留导入映射草稿，应用时同步更新共享账户草稿。
- 收支流水只读详情在所有尺寸使用基础对话框：Compact 居中限宽，Regular/Wide 保留右侧定位；Wide 遵守至少 56 dp 的大屏边缘留白，标题、关闭入口与底部操作固定，详情和关联正文独立滚动。编辑与关系创建继续复用同一业务状态，但 Compact 在这些包含暂存输入的任务使用全屏容器，Regular/Wide 使用当前右侧基础对话框。
- 删除、取消关联与解散关联是短确认，在当前流水基础对话框内切换任务状态，不扩成 Compact 全屏页面，也不在基础对话框上叠第二个基础对话框。正文说明后果并收集删除范围；固定操作区只放一个危险确认和一个取消。取消、Back、Escape 或允许的遮罩关闭返回同一条流水详情，不执行写入；确认调用既有操作，忙碌锁拒绝重复请求。
- 只读详情在所有尺寸提供可见关闭入口；编辑和关系创建状态只使用对应任务的取消/返回动作，不重复显示关闭与取消。脏草稿丢弃确认在 Compact 全屏编辑上打开 M3 基础确认对话框，在 Regular/Wide 当前基础对话框内切换状态；取消返回编辑并保留草稿，确认只丢弃未保存修改。
- 流水详情的正文可以独立滚动；“编辑”和“更多操作”固定在模态底部并靠逻辑末端排列，最多显示两个直接动作。更多动作仍使用现有菜单承载关联、危险解除关联和删除入口。
- Compact 流水编辑和关系创建的主要提交动作放在全屏对话框标题栏；标题栏关闭作为取消入口，编辑存在未保存修改时先显示丢弃确认。正文独立滚动，不在底部重复放置相同的取消/提交操作；Regular/Wide 保留当前基础对话框底部动作区。删除和关系移除确认在所有窗口尺寸均使用固定操作区，不占用全屏任务标题栏。
- 日期/时间字段从任何模态任务打开时，都在当前容器内以内联选择状态展开，不再叠加第二个对话框。日期选择继续暂存到用户明确确认，取消与 Escape 不写回；Compact 编辑区可纵向滚动以容纳选择器。
- 详细筛选保留既有合同：Compact 使用 Material 3 `ModalBottomSheet`，Regular/Wide 使用一个定宽上限的基础对话框；五组筛选仍在同一个筛选任务内。
- 投资事件证据与持仓详情是由用户点击触发的单项只读详情，不需要全屏多步骤任务；所有尺寸使用最大宽度 560 dp 的基础对话框，标题和唯一“关闭”知悉操作固定，正文可滚动。Escape、点击外部或固定的“关闭”操作均可结束详情。

### Material 3 容器与主题

- `FinanceTheme` 的 `extraLarge` 采用 Material 3 Dialog 容器的 28 dp 圆角值；其余形状与既有 token 映射不改，限制主题影响范围。
- 标准控件不覆盖 M3 默认形状和表面色。自定义基础 Dialog 直接用 `Dialog` 与内部 `Surface`，颜色使用 `surfaceContainerHigh`，形状使用 `MaterialTheme.shapes.extraLarge`，层级使用 M3 对话框默认 tonal elevation，最大宽度为 560 dp。
- 紧凑全屏对话框使用 `surface` 与无圆角边缘；较宽窗口对话框使用 `surfaceContainerHigh`。由 `Dialog` 提供遮罩，移除重复的手绘 Web scrim。
- 自定义内容超过可视高度时仅正文滚动；标题和最终动作固定可见。Compact 全屏任务把确认操作放在标题栏，Basic Dialog 把确认/取消操作固定在底部。常规基础对话框按内容收缩，不用剩余可用高度撑出空白；达到高度上限时才滚动正文。Wide 自定义定位的基础对话框距屏幕边缘至少 56 dp。
- Compact 全屏任务的内容尊重安全绘制区域；自定义 Dialog Surface 将任务标题暴露为无障碍窗格标题。流水关联创建的 Regular/Wide 内容区可以滚动，但取消与创建操作固定在详情对话框底部。
- 流水面板在同一对话框内切换详情、编辑和确认任务时，按当前任务标题重建模态语义子树，避免 Web 上仍暴露上一状态的控件；每个状态都保留自己的窗格标题和可操作控件。
- `COMPACT` 全屏任务使用 `Dialog` 提供遮罩与系统模态行为；`REGULAR`/`WIDE` 以 560 dp 基础对话框呈现。宽窗口基础对话框不再打开另一个基础账户编辑对话框，而是在同一容器内切换编辑内容。

### 交互与提交语义

- `DatePickerInput` 暂存所选日期；“完成”才提交，取消、Back/Escape、点外部关闭均保留打开前日期。清除操作移到日期字段，不在 DatePickerDialog 动作区增加第三个按钮。
- 时间选择已由显式确认提交，保持现状。
- 流水删除若有多个影响范围，在确认正文内用单选项收集范围，底部只提供一个危险确认和一个取消；仍调用现有删除操作及现有范围值。
- 工作区删除的确认按钮使用 `error` 角色；其他现有危险操作继续使用 `error` 角色。取消/关闭不得执行数据变更。
- “取消关联”与“解散关联”在调用现有关联移除接口前先进入单一确认状态；正文明确说明关联会移除、流水记录保留。所有窗口均在当前详情基础对话框中切换确认内容，避免用全屏呈现短任务或嵌套基础对话框。
- Compact 编辑流水以页头关闭作为取消入口、以页头“保存”作为确认入口，移除重复的底部取消/保存按钮；Regular/Wide 保留底部保存/取消操作。只读详情作为基础对话框呈现，并保留明确关闭入口。删除与关联移除确认在所有窗口使用当前详情对话框的固定底部操作区；关闭或取消返回详情，确认后调用既有操作。
- Compact 的流水丢弃确认以 M3 基础对话框覆盖在全屏面板上；保存或关联操作失败时，错误以基础错误知悉对话框覆盖在仍打开的编辑面板上，确认后回到原任务并保留草稿。Regular/Wide 在原基础对话框内展示错误与重试/取消入口。用户已关闭流水面板后才返回的失败，在账本上显示单独的知悉对话框。
- 导入任务中的账户编辑、错误反馈和丢弃确认在 Compact 使用覆盖于全屏任务上的 M3 基础对话框；Regular/Wide 在当前基础对话框内切换状态。处理中关闭提示只在已有任务容器中知会，不创建额外的信息弹窗。
- 编辑流水、创建关联、保存关联影响确认、删除与取消关联的提交动作必须受当前写入权限约束；忙碌状态仅展示进行中，不通过禁用提交按钮代替 ViewModel 重复请求保护。工作区和分类删除失败标题准确指向所属对象。
- 基础对话框操作区至多显示一个确认和一个取消动作；只有一个确认或知悉结果的任务可以只显示一个确认动作。确认在前置条件不满足时禁用，取消不禁用。用户已确认并启动的异步操作继续执行；若在进行中关闭弹窗，失败状态仍在原页面可见。Compact 全屏任务可以在其上打开一个基础对话框；`REGULAR`/`WIDE` 的基础对话框通过切换自身内容呈现次级确认或错误状态。
- Web Escape 处理遵循弹层栈：嵌套的选项菜单或字段选择器先关闭，底层对话框保留；随后一次 Escape 才进入当前对话框的退出语义。当前对话框如果有未提交更改，则走其既定丢弃确认。
- Compact 账本筛选使用 `ModalBottomSheet` 时，Web 不启用其默认 Back/Escape 解散；Web 弹层栈为锚定选项菜单设置高于筛选面板的优先级，因此第一次 Escape 关闭菜单，下一次才关闭面板。Native 保留 Material 3 默认 Back/Escape 行为。
- `DialogProperties` 按任务风险设置点外部关闭；全屏导入有未提交内容时，标题栏关闭、Back、Escape 均在 Compact 全屏任务上显示基础丢弃确认。无未提交内容时可直接离开。全屏流水编辑存在脏草稿时，页头关闭、Back 与 Escape 也显示基础丢弃确认；较宽窗口在同一基础对话框内切换确认内容。基础对话框不嵌套第二个基础对话框。
- 记录、导入和关系操作的确认按钮在请求期间保留可用状态并展示进行中标签；调用方保留现有忙碌状态保护以拒绝重复请求。取消始终可用。若已开始的请求失败，Compact 全屏任务上方显示基础错误确认，较宽窗口在当前基础对话框中进入错误知悉状态；用户关闭流水编辑后才返回的保存错误在账本页显示基础确认。
- 工作区、分类、流水和批量删除的确认按钮在请求中保留可用并显示进行中状态；现有业务忙碌锁阻止重复写入。若用户在操作已开始后关闭确认框，请求继续；失败原因显示在所属页面或基础错误对话框。
- 详细筛选的字段属于实时查询控件，选择立即应用；关闭筛选面板只结束面板任务，不撤销已生效的筛选。日期选择器仍是暂存值，只有确认才写入字段。
- 移除二级页面标题区自定义 `FocusRequester` 与焦点边框，使用 Material 控件默认无障碍焦点行为。

### 用户任务与将移除的信息

- 选择日期：用户在日期字段打开日历，选择后明确完成或取消；将清除按钮移出弹窗，避免三个并列结果。
- 删除流水：用户先在对话框正文决定删除范围，再确认删除；删除操作区不再并排放置两个删除动作。
- 导入账单：用户在 Compact 全屏、Regular/Wide 限宽基础对话框内完成选择、映射、预览和提交；Compact 的账户编辑、错误与丢弃确认用 M3 基础对话框覆盖于全屏任务，Regular/Wide 在当前基础对话框内切换；移除宽窗口全屏容器和重复关闭入口。
- 编辑流水：Compact 页头保留关闭/保存，表单正文滚动；Regular/Wide 底部保留保存/取消。修改后的草稿不再被静默丢弃，确认放弃后才返回详情或账本。
- 自定义容器移除重复遮罩、手写小圆角、无层级的表面和装饰性焦点边框。
- 删除与关联移除确认移除随内容滚动的动作行；将紧凑全屏任务的确认操作放入页头，并固定较宽基础对话框的底部操作区。

### Hallmark 设计方向与自查

- 方向：沿用 Finance Tracker 现有字体、颜色、业务标签与 Compose 组件；按 M3 对话框角色把信息压缩到一项明确任务，先呈现标题与必要内容，再呈现确认/取消；通过主题角色建立容器层级，不增加装饰性卡片或说明文案。
- 自查：不把对话框统一改成同一尺寸；短确认和只读详情使用 M3 基础对话框，多步骤导入与暂存编辑只在 Compact 使用全屏任务面；详情保留可读的滚动正文；基础对话框不超过 560 dp、确认和取消操作不超过两个且取消不禁用；危险动作使用唯一确认操作，取消保持低强调；小屏不横向滚动，暗色与亮色共用主题角色。
- Hallmark 六项预评：理念 5，层级 4，执行 4，具体性 4，克制 5，变化 4。最终 UI 仍须按 `hallmark audit` 检查实际 Compose 页面和截图。

## Risks / Trade-offs

- [紧凑的日期字段需要额外清除按钮] → 将清除移到字段图标区，保留原有能力；在三种窗口及浅/深色主题检查布局。
- [宽窗口的 560 dp 导入弹窗比当前全屏视图窄] → 在宽窗口采用纵向内容与固定动作区；三尺寸检查映射长文本、滚动和账户编辑。
- [退出确认增加一次交互] → 仅当导入含未提交内容时询问；空白初始页保持直接关闭，取消时保留全部进度。
- [投资详情增加按窗口尺寸的容器分支] → 仅共享容器变化，事件事实、估值内容和加载/重试状态保持原样；用现有 Web 页面用例复核。
- [全球 `extraLarge` 角色改变会影响依赖该角色的 M3 组件] → 只更新该一个 M3 形状角色，其他 token 映射不变；三尺寸浏览器截图覆盖对话框和页面中的形状回归。

## Migration Plan

1. 先更新共享设计系统 delta 和页面实现；不涉及 API、数据库、迁移或财务数据。
2. 更新相关 Playwright 断言并按 Compact、Regular、Wide 及亮/暗主题运行 Web QA，保存截图、测试步骤与控制台/网络结果。
3. 运行 OpenSpec 校验、Compose Web 生产构建/浏览器测试、`git diff --check` 和影响范围复核；未通过时可通过回滚本 change 的代码与主题改动恢复既有展示。
