## Context

参见 [proposal.md](proposal.md) 与 [delta 规格](specs/shared/design-system/spec.md)。对话框分布在账本、导入、投资、分类和工作区页面；部分使用 Material 3 标准组件，部分用 `Dialog` 自行绘制。当前 `FinanceTheme` 的 `extraLarge` 只有 5 dp，标准 M3 对话框也因此被压成小圆角；账本筛选和投资详情自定义基础对话框超过 M3 560 dp 最大宽度；导入多步骤流程在所有窗口尺寸都使用全屏容器，并且退出时不确认就清空未提交进度；日期选择通过状态监听即时写回，取消路径不能撤销。业务行为复核还发现流水编辑可在未确认时丢弃草稿、保存失败在部分路径中没有对话框级反馈，以及宽窗口投资详情仍暴露全屏对话框的关闭按钮。账单详情有独立于短确认的一套产品布局合同：Compact 使用全屏任务，Regular/Wide 使用右侧全高模态面板；编辑在同一详情容器内替换布局。删除、关系移除、放弃和错误则分别使用 M3 确认/知悉弹窗。

## Goals / Non-Goals

**Goals:**

- 按用户触发、单一任务、明确标题与结果、确认/取消语义和适配任务复杂度的 Dialog 类型审查共享 Compose 弹层；检查视觉规范与业务行为，尤其是未提交表单/导入的退出、提交失败和进行中操作。
- 让标准 M3 对话框从 `FinanceTheme` 获得合理形状；让自定义容器使用 M3 Surface 角色、层级与响应式布局。
- 账单详情与编辑共用一个模态容器：Compact 全屏，Regular/Wide 为右侧全高面板；编辑替换同一容器内的布局。新增关联为独立模态任务，使用 Compact 全屏、Regular/Wide 右侧全高面板。
- 只读投资详情和其他短确认遵循基础对话框尺寸合同；账单详情内的删除/关系移除、放弃编辑及错误反馈仍使用 Material 3 确认/知悉弹窗。
- 修正日期选择的暂存/提交语义、流水删除多结果选择方式和重复关闭入口。
- 修正导入放弃确认、请求中关闭语义，并保留筛选的实时应用行为。
- 保持 Compose Web、Android、iOS 的交互语义一致；按用户指定只在 Web 运行验证。

**Non-Goals:**

- 不调整账户、账单、分类、投资和工作区业务规则，不改变保存/删除 API、影响范围或财务结果。
- 不重构普通菜单、FAB 菜单、导航抽屉或独立 `ModalBottomSheet`（紧凑账本筛选除外：仅恢复 M3 默认形状）。
- 不添加自定义焦点捕获、焦点回跳或焦点边框逻辑；保留 Compose Dialog 默认的模态与键盘行为。
- 不进行 Android 或 iOS 运行验证。

## Decisions

### 对话框模式与信息架构

- 标准 `AlertDialog`、`DatePickerDialog` 用于短确认与聚焦输入；保持其 M3 标题、正文、动作区和默认容器行为。
- 多步骤账单导入在 `COMPACT` 使用全屏模态任务，在 `REGULAR`/`WIDE` 使用基础模态对话框；内容过长时仅正文滚动，标题与底部操作区固定。所有尺寸的操作按钮都在底部，取消靠左、主要确认最靠右。
- 账户映射阶段在所有尺寸下纵向排列来源信息、账户选择和新账户摘要；`REGULAR`/`WIDE` 的对话框限宽 560 dp，不并排压缩选择框，确保选中值可完整展示账户名称、类型和币种。
- `REGULAR`/`WIDE` 的导入基础对话框不重复显示标题栏关闭按钮；由操作区中的“取消”或“返回”提供明确的界面内退出路径，Escape 和遮罩关闭执行相同的状态转换。短内容按内容收缩，超出可用高度时仅正文滚动，标题与操作区固定。
- 全屏导入流程未提交且包含文件、扫描结果或阶段草稿时，点关闭、Back 或 Escape 会在 Compact 全屏任务上打开 M3 基础丢弃确认对话框，提供“继续导入”和“放弃导入”；取消保留原任务及其草稿，确认后退出且不提交账单。空白的初始选择页可直接关闭。`REGULAR`/`WIDE` 在当前基础对话框内切换同一确认状态，不在基础对话框上再嵌套基础对话框。
- 新账户编辑在 Compact 使用覆盖于导入全屏任务上的 M3 基础对话框；Regular/Wide 在原基础对话框内切换内容。取消保留导入映射草稿，应用时同步更新共享账户草稿。
- 收支流水详情与编辑共用一个模态任务容器。Compact 的详情与编辑均使用全屏任务；Regular/Wide 均使用只在逻辑起始侧留白、逻辑末端贴齐屏幕的右侧全高面板。进入编辑时，在原容器内切换标题和正文布局，不创建新对话框；返回详情保留已提交记录内容，放弃确认时保留未保存草稿。
- 新增关联是独立于详情/编辑的 M3 模态任务，使用 Compact 全屏与 Regular/Wide 右侧全高面板；屏幕中只展示当前活动任务，取消/返回时恢复此前详情，不在现有详情弹窗之上再叠一层任务弹窗。
- 删除、取消关联与解散关联使用标准 M3 确认弹窗；正文说明影响并收集删除范围，操作区只放一个危险确认和一个取消。确认弹窗作为当前唯一模态显示；取消返回原详情，确认调用既有操作，忙碌锁拒绝重复请求。
- 只读详情和编辑均提供清楚的离开入口；编辑和关系创建状态的保存/取消操作按各自任务布局固定显示。脏草稿的放弃确认使用 M3 基础确认弹窗；取消恢复同一编辑内容并保留草稿，确认只丢弃未保存修改。
- 流水详情的正文可以独立滚动；“编辑”和“更多操作”固定在模态底部并靠逻辑末端排列，最多显示两个直接动作。更多动作仍使用现有菜单承载关联、危险解除关联和删除入口。
- 所有模态任务的操作均固定在容器底部；次要/取消操作靠左，主要提交操作最靠右。Compact 全屏任务也使用固定底部操作区，页头只放标题和左上关闭入口。
- 所有非 `AlertDialog` 模态的关闭按钮放在内容左上角，包括 Compact/Regular/Wide 的导入任务、账单详情/编辑/关联、账本筛选、DatePickerDialog 与投资详情；AlertDialog 保留 M3 自带结构，不额外添加关闭图标。操作区中的取消按钮按任务需要保留，即使它与左上关闭入口执行同一退出语义。
- `AlertDialog` 的确认和取消操作只显示文本，不添加图标；危险确认仍用 `error` 颜色并放在最右侧。
- 日期/时间字段从任何模态任务打开时，都在当前容器内以内联选择状态展开，不再叠加第二个对话框。日期选择继续暂存到用户明确确认，取消与 Escape 不写回；Compact 编辑区可纵向滚动以容纳选择器。
- 详细筛选保留既有合同：Compact 使用 Material 3 `ModalBottomSheet`，Regular/Wide 使用一个定宽上限的基础对话框；五组筛选仍在同一个筛选任务内。
- 投资事件证据与持仓详情是由用户点击触发的单项只读详情，不需要全屏多步骤任务；所有尺寸使用最大宽度 560 dp 的基础对话框，标题和唯一“关闭”知悉操作固定，正文可滚动。Escape、点击外部或固定的“关闭”操作均可结束详情。

### Material 3 容器与主题

- `FinanceTheme` 的 `extraLarge` 采用 Material 3 Dialog 容器的 28 dp 圆角值；其余形状与既有 token 映射不改，限制主题影响范围。
- 标准控件不覆盖 M3 默认形状和表面色。自定义基础 Dialog 直接用 `Dialog` 与内部 `Surface`，颜色使用 `surfaceContainerHigh`，形状使用 `MaterialTheme.shapes.extraLarge`，层级使用 M3 对话框默认 tonal elevation，最大宽度为 560 dp。
- 紧凑全屏对话框使用 `surface` 与无圆角边缘；较宽窗口对话框使用 `surfaceContainerHigh`。由 `Dialog` 提供遮罩，移除重复的手绘 Web scrim。
- 自定义内容超过可视高度时仅正文滚动；标题和最终动作固定可见。Compact 全屏任务与 Basic Dialog 都把操作固定在底部。常规基础对话框按内容收缩，不用剩余可用高度撑出空白；达到高度上限时才滚动正文。Wide 自定义定位的基础对话框距屏幕边缘至少 56 dp。
- Compact 全屏任务的内容尊重安全绘制区域；Regular/Wide 账单面板按 Material 3 Modal Side Sheet 呈现，贴合视口上下边缘和逻辑末端边缘，只在逻辑起始侧保留 16 dp/56 dp 留白，并限宽 560 dp。面板使用 `surfaceContainerLow`、`MaterialTheme.shapes.large`、零 elevation 及 Dialog 提供的单一 scrim；点击 scrim或沿逻辑末端方向拖动，均按当前任务退出规则关闭面板。自定义 Dialog Surface 将任务标题暴露为无障碍窗格标题。流水关联创建是独立模态任务，Regular/Wide 内容区可以滚动，底部固定取消与创建操作。
- Compose Multiplatform 当前没有通用 Material 3 SideSheet API；共享 Compose 使用现有 `Dialog` 模态宿主，按官方 Side Sheet token 与模态行为绘制 Surface，不新增依赖或平台分支。产品最大宽度 560 dp 保留为页面约束。
- 流水面板在同一对话框内切换详情、编辑和确认任务时，按当前任务标题重建模态语义子树，避免 Web 上仍暴露上一状态的控件；每个状态都保留自己的窗格标题和可操作控件。
- `COMPACT` 全屏任务使用 `Dialog` 提供遮罩与系统模态行为；`REGULAR`/`WIDE` 以 560 dp 基础对话框呈现。宽窗口基础对话框不再打开另一个基础账户编辑对话框，而是在同一容器内切换编辑内容。

### 交互与提交语义

- `DatePickerInput` 暂存所选日期；“完成”才提交，取消、Back/Escape、点外部关闭均保留打开前日期。清除操作移到日期字段，不在 DatePickerDialog 动作区增加第三个按钮。
- 时间选择已由显式确认提交，保持现状。
- 流水删除若有多个影响范围，在确认正文内用单选项收集范围，底部只提供一个危险确认和一个取消；仍调用现有删除操作及现有范围值。
- 工作区删除的确认按钮使用 `error` 角色；其他现有危险操作继续使用 `error` 角色。取消/关闭不得执行数据变更。
- “取消关联”与“解散关联”在调用现有关联移除接口前先进入 M3 确认弹窗；正文明确说明关联会移除、流水记录保留。取消返回原详情，确认后才调用既有关系移除操作。
- Compact 详情与编辑共用全屏面板；详情页脚把“更多操作”放左、“编辑”放最右，编辑的“取消/保存”固定在底部且“保存”最右。Regular/Wide 共用贴合逻辑末端边缘的右侧全高面板；详情操作和编辑保存/取消固定在面板底部。所有状态的左上关闭入口固定可见。状态切换只替换原面板内部内容。
- 删除/关系移除、编辑草稿丢弃和提交错误分别由 Material 3 AlertDialog 呈现；显示确认或错误时暂时隐藏详情/编辑面板，使其成为当前唯一模态，取消/知悉后再恢复原面板和业务草稿。用户已关闭流水面板后才返回的失败仍在账本页显示单操作知悉弹窗。
- 导入任务中的账户编辑、错误反馈和丢弃确认在 Compact 使用覆盖于全屏任务上的 M3 基础对话框；Regular/Wide 在当前基础对话框内切换状态。处理中关闭提示只在已有任务容器中知会，不创建额外的信息弹窗。
- 编辑流水、创建关联、保存关联影响确认、删除与取消关联的提交动作必须受当前写入权限约束；忙碌状态仅展示进行中，不通过禁用提交按钮代替 ViewModel 重复请求保护。工作区和分类删除失败标题准确指向所属对象。
- 基础对话框操作区至多显示一个确认和一个取消动作；只有一个确认或知悉结果的任务可以只显示一个确认动作。确认在前置条件不满足时禁用，取消不禁用。用户已确认并启动的异步操作继续执行；若在进行中关闭弹窗，失败状态仍在原页面可见。账本流水详情/编辑面板与独立 M3 确认弹窗不同时渲染，确认关闭后恢复原任务状态；导入 Compact 全屏任务仍可承载一个基础对话框。
- Web Escape 处理遵循弹层栈：嵌套的选项菜单或字段选择器先关闭，底层对话框保留；随后一次 Escape 才进入当前对话框的退出语义。当前对话框如果有未提交更改，则走其既定丢弃确认。
- Compact 账本筛选使用 `ModalBottomSheet` 时，Web 不启用其默认 Back/Escape 解散；Web 弹层栈为锚定选项菜单设置高于筛选面板的优先级，因此第一次 Escape 关闭菜单，下一次才关闭面板。Native 保留 Material 3 默认 Back/Escape 行为。
- `DialogProperties` 按任务风险设置点外部关闭；全屏导入有未提交内容时，标题栏关闭、Back、Escape 均在 Compact 全屏任务上显示基础丢弃确认。账单流水 Compact 全屏详情/编辑与 Regular/Wide 右侧全高面板使用相同状态路由；脏草稿的关闭、Back 或 Escape 会先暂时隐藏编辑面板，再显示独立 M3 丢弃确认弹窗，取消后恢复编辑容器。删除、关系移除、关系影响确认、错误知悉也仅显示 M3 AlertDialog；其所属的详情、编辑或关联面板暂时不渲染，避免同一时刻出现多个活动模态。
- 记录、导入和关系操作的确认按钮在请求期间保留可用状态并展示进行中标签；调用方保留现有忙碌状态保护以拒绝重复请求。取消始终可用。流水保存失败使用独立 M3 错误知悉弹窗；确认后恢复原编辑容器和草稿，用户已关闭流水面板后才返回的保存错误在账本页显示知悉弹窗。
- 工作区、分类、流水和批量删除的确认按钮在请求中保留可用并显示进行中状态；现有业务忙碌锁阻止重复写入。若用户在操作已开始后关闭确认框，请求继续；失败原因显示在所属页面或基础错误对话框。
- 详细筛选的字段属于实时查询控件，选择立即应用；关闭筛选面板只结束面板任务，不撤销已生效的筛选。日期选择器仍是暂存值，只有确认才写入字段。
- 移除二级页面标题区自定义 `FocusRequester` 与焦点边框，使用 Material 控件默认无障碍焦点行为。

### 用户任务与将移除的信息

- 选择日期：用户在日期字段打开日历，选择后明确完成或取消；将清除按钮移出弹窗，避免三个并列结果。
- 删除流水：用户先在对话框正文决定删除范围，再确认删除；删除操作区不再并排放置两个删除动作。
- 导入账单：用户在 Compact 全屏、Regular/Wide 限宽基础对话框内完成选择、映射、预览和提交；Compact 的账户编辑、错误与丢弃确认用 M3 基础对话框覆盖于全屏任务，Regular/Wide 在当前基础对话框内切换；移除宽窗口全屏容器和重复关闭入口。
- 编辑流水：详情和编辑共用 Compact 全屏或 Regular/Wide 右侧全高容器；进入编辑时替换当前布局，表单正文滚动。所有尺寸左上提供关闭入口，底部保留取消/保存且保存最右。修改后的草稿不再被静默丢弃，确认放弃后才返回详情或账本。
- 自定义容器移除重复遮罩、手写小圆角、无层级的表面和装饰性焦点边框。
- 删除与关联移除确认移除随内容滚动的动作行；所有任务的操作固定在底部，取消靠左、主要确认最靠右；AlertDialog 的操作按钮只保留文本。

### Hallmark 设计方向与自查

- 方向：沿用 Finance Tracker 现有字体、颜色、业务标签与 Compose 组件；将详情视为持续的用户任务容器，Compact 全屏、Regular/Wide 右侧全高，编辑时只替换容器内部布局；独立关联任务和短确认各自保持明确任务边界；通过主题角色建立层级，不增加装饰性卡片或说明文案。
- 自查：不把所有对话框统一改成同一尺寸；账单详情与编辑按已确认的任务合同固定容器尺寸，投资只读详情与筛选等基础对话框仍遵循 560 dp 上限；关联创建独立于详情，确认/错误弹窗不与详情模态同时显示；确认和取消操作不超过两个且取消不禁用；危险动作使用唯一确认操作；小屏不横向滚动，暗色与亮色共用主题角色。
- Hallmark 六项预评：理念 5，层级 4，执行 4，具体性 4，克制 5，变化 4。最终 UI 仍须按 `hallmark audit` 检查实际 Compose 页面和截图。

## Risks / Trade-offs

- [紧凑的日期字段需要额外清除按钮] → 将清除移到字段图标区，保留原有能力；在三种窗口及浅/深色主题检查布局。
- [宽窗口的 560 dp 导入弹窗比当前全屏视图窄] → 在宽窗口采用纵向内容与固定动作区；三尺寸检查映射长文本、滚动和账户编辑。
- [退出确认增加一次交互] → 仅当导入含未提交内容时询问；空白初始页保持直接关闭，取消时保留全部进度。
