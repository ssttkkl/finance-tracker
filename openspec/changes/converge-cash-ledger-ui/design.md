## Context

现金账本的列表、空态、加载态和详情由 `CashLedgerScreen.kt`、`CashDetailRelations.kt` 与共享 `FinanceComponents.kt` 组成。本轮只收敛同一规则的多种写法，不改变业务语义。

## Decisions

1. **列模型以数据行为准**：行操作由整行点击承担，不单设列。表头、数据行和骨架使用同一组权重（5/12/15/24/12/11/13，按剩余宽度等比分配），删除骨架末尾的 8% 占位。
2. **空态按原因拆分**：无任何过滤且结果为空 → “还没有流水” + 新建流水／导入账单；存在过滤条件 → 保留“没有匹配的收支记录。” + 清除筛选。两条路径共用 `ledger.empty` 语义 ID，动作复用 FAB 菜单的既有回调。
3. **移动端状态标签位置**：与桌面“交易信息”列一致，放在交易对方／备注／核对原因之后、时间与账户信息之前。
4. **金额统一去尾零**：明细行与月度汇总都使用 `displayDecimalAbs` / `displayDecimalSign` 的输出；不再让行金额直接使用接口原文。
5. **账单原文保持内容**：字段名与值按来源原样展示，仅把固定 72 dp 标签列改为按内容取宽，值占剩余宽度，消除 `account_na/me` 断词；不改变字段集合、顺序或本地化策略。
6. **规格例外**：原始账单是审计次级区，允许展示技术字段；主详情与列表仍不得暴露代理键、投影或审计表结构。
7. **状态标签归属交易信息列**：具体待处理原因与状态标签放交易信息列、核对原因之后，流水类型列只放类型、子类型与业务标签；桌面与移动端一致，并与导入核对使用同一归属规则。该决定来自跨 change 回溯：主规格仍写“流水类型列下方”，而代码、导入规格和 UI 规范都已改为交易信息列。

## Risks

- 768 视口下 7 列比例变化需要复核金额与交易信息可读性。
- 空态拆分改变了“无流水”的文案与动作，需要同步现有 e2e 断言。
- 去尾零会改变金额视觉宽度，需确认右对齐与汇总不抖动。

## Known limitation

空态判定只依据 `CashFilters.hasActiveFilters`（忽略默认的“隐藏0元流水”开关），因为 page 合同没有返回“未筛选是否有记录”的信号。账本仅含零元流水且默认隐藏时，页面会显示“还没有流水”，与“筛选无结果”不完全一致；补该信号属于接口变更，超出本次“不涉及接口”的范围，记录待后续评估。
