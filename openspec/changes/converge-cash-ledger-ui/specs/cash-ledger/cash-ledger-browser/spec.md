## MODIFIED Requirements

### Requirement: 收支账本表格列与交易信息层级

Compose 收支账本在 `REGULAR` 与 `WIDE` MUST 使用一致的桌面表格列顺序：选择框、发生时间、账户、交易信息、分类、流水类型、金额。上述列宽 MUST 依次按 5、12、15、24、12、11、13 的相对权重分配剩余宽度；行操作由整行点击承担，MUST NOT 单设行操作列。表头、数据行与加载骨架 MUST 使用相同的列顺序与列宽；加载完成 MUST NOT 发生列位置或列宽跳动，骨架 MUST NOT 保留额外空列。行金额、详情金额与月度汇总 MUST 使用同一显示精度口径，同一视图内不得一处保留固定小数位、一处去尾零。交易信息列 MUST 先显示交易对方，再在其下显示备注；任一字段缺失时 MUST 保留其行位置并以短横线表示。`COMPACT` MUST 继续使用流水卡片，并让备注紧接交易对方显示。

#### Scenario: Regular 与 Wide 使用一致的表格列

- **GIVEN** 收支账本在 `REGULAR` 或 `WIDE` 窗口展示流水
- **WHEN** 列表含有可选择流水
- **THEN** 表格 MUST 依次呈现选择、发生时间、账户、交易信息、分类、流水类型和金额
- **AND** MUST NOT 出现单独的行操作列，整行点击承担打开详情
- **AND** 交易信息列 MUST 在同一列内先显示交易对方，再显示备注
- **AND** 交易对方或备注缺失时 MUST 保留两行结构

#### Scenario: 加载骨架与数据行列对齐

- **GIVEN** 收支账本在 `REGULAR` 或 `WIDE` 首次加载或完整刷新
- **WHEN** 骨架占位切换为实际数据行
- **THEN** 列顺序与列宽 MUST 保持稳定，MUST NOT 出现额外空列或列位置跳动
- **AND** 表头、数据行与骨架 MUST 使用同一列顺序与列宽

#### Scenario: Compact 卡片显示交易对方和备注

- **GIVEN** 收支账本在 `COMPACT` 窗口展示流水卡片
- **WHEN** 流水包含交易对方和备注
- **THEN** 卡片 MUST 将交易对方和备注相邻展示，交易对方先于备注
- **AND** 缺失值 MUST 使用短横线占位

#### Scenario: 行、详情与月度汇总使用同一金额精度

- **WHEN** 同一笔收支分别显示在账本行、详情和月度汇总中
- **THEN** 三处金额 MUST 使用相同的小数位与去尾零口径
- **AND** MUST NOT 一处固定两位小数、另一处省略尾零

### Requirement: 证据详情只展示可核对业务信息

收支详情 MUST 优先展示金额、交易对方、发生时间、账户、收支分类路径和备注；来源、原始账单和关联记录等核对信息必须进入详情的次级区域。收支分类必须作为整笔收支详情的共享字段查看和修改，不得把成员流水展示为互相冲突的分类。原始账单次级区域 MUST 按来源返回内容展示字段名与值，允许出现技术字段名与枚举原文；该区域之外的主详情与列表 MUST NOT 暴露投影、数据库代理键、分类 ID 路径、底层审计表结构或不存在的角色。原始账单区域 MUST 与主详情分层，默认位于详情末尾。

#### Scenario: 查看单源投影

- **WHEN** 使用者打开没有采用关系的单源投影
- **THEN** 详情 MUST 展示该记录自身字段和收支分类或无分类状态，导入渠道进入次级核对信息，且不得显示空的关联记录区域

#### Scenario: 查看关系投影

- **WHEN** 使用者打开采用同笔支付或退款关系的投影
- **THEN** 详情 MUST 显示整笔收支详情共享的分类，并在次级核对信息中逐条显示关联记录，不得用实现术语解释组成方式

#### Scenario: 查看原始账单

- **WHEN** 使用者展开某条流水的账单原文
- **THEN** 字段名与值 MUST 按来源返回内容原样展示，允许技术字段名与枚举值
- **AND** 主详情与列表 MUST 继续使用用户可读的账户、分类与类型，不得把代理键混入主要字段

### Requirement: 新工作区可直接浏览空账本

系统 MUST 在创建或首次切换到合法工作区后提供可读取的空收支账本。工作区没有现金流水时，列表、筛选选项和月份汇总 MUST 返回合法空结果，不得把缺少活动数据集当作用户可见系统错误。账本空状态 MUST 区分“没有任何流水”与“当前筛选没有结果”：前者提供“记一笔”“导入账单”入口，后者提供“清除筛选”。

#### Scenario: 创建工作区后首次打开收支页

- **WHEN** 使用者注册后创建一个没有任何现金流水的新工作区并打开收支页
- **THEN** API MUST 返回成功的空列表合同，页面 MUST 显示空状态和“记一笔”“导入账单”等核心入口

#### Scenario: 切换到没有流水的工作区

- **WHEN** 使用者从已有工作区切换到一个尚未产生现金流水的工作区
- **THEN** 收支页 MUST 在当前工作区边界内返回空结果，不得展示上一个工作区的记录或 `projection.unavailable`

#### Scenario: 初始化失败

- **WHEN** 空账本初始化因数据库或投影构建错误失败
- **THEN** 系统 MUST 保留工作区创建事务的一致性，并返回可重试的存储/初始化错误；不得伪造成功的账本数据

#### Scenario: 筛选没有结果

- **WHEN** 账本有流水，但当前搜索或筛选条件没有匹配项
- **THEN** 页面 MUST 显示“没有匹配的收支记录”并提供清除筛选，不得提示账本还没有流水

### Requirement: 账本表格状态、行打开与汇总可读性

收支账本的“流水类型”列 MUST 首行显示主流水及适用的子类型，并可在该列辅助显示不同于类型名称的业务标签。草稿、待处理配对、账单更新问题和来源身份疑似重复等具体待处理原因与状态标签 MUST 显示在交易信息列、位于核对原因之后，不得占用流水类型列；不得单独显示“待确认”或“已合并”标签。草稿显示“草稿待补充”，待处理配对显示“配对建议”，正式流水的账单更新问题显示“账单更新待核对”，来源身份疑似重复时显示“疑似重复待核对”。待处理行 MUST 使用警告色底色，原因标签 MUST 有底色；表头与单元格内容 MUST 表达一致。桌面列表 MUST 允许使用者从整行打开当前收支，不显示行尾小眼睛或空操作列，并保留键盘与辅助技术可识别的操作语义；复选与单选项仍只改变选择状态，现有选择方式 MUST 保持不变，不新增选择入口或全选。账本 MUST 复用导入核对与关联搜索的瀑布流组件及其时间分组吸顶、右侧滚动条、分组容器、行与列标题；账本启用可选的月度收支合计。REGULAR／WIDE 的多币种月份汇总 MUST 与月份标题分居左右。COMPACT MUST 第一行单独显示左对齐的月份，随后每种币种各占一行，币种、收入和支出按顺序横向排列，汇总行整体右对齐。所有尺寸的金额 MUST 使用等宽数字。

#### Scenario: 从整行打开收支记录

- **WHEN** 使用者在桌面列表点击某笔收支的名称、日期或金额区域
- **THEN** MUST 打开该笔收支的当前详情
- **AND** 复选或单选项仍只改变选择状态，不触发行打开
- **AND** 行尾 MUST 不显示小眼睛或空操作列

#### Scenario: 已确认状态不重复显示

- **WHEN** 一笔收支已确认且没有待处理事项
- **THEN** 流水类型列 MUST 不重复显示“已确认”
- **AND** 流水类型列 MUST 显示主流水及适用的子类型，不显示“已合并”标签

#### Scenario: 少量流水时细微拖动滚动条

- **WHEN** 当前列表有约二十笔收支，使用者在右侧滚动条上连续拖动一小段距离
- **THEN** 已加载列表 MUST 随拖动距离连续移动，滚动条不得只在跨过整笔流水序号时跳动
- **AND** 跨页定位仍 MUST 按稳定流水序号加载目标，松手后精确落位

#### Scenario: 账本待处理原因

- **WHEN** 收支是草稿、存在待处理配对建议或正式流水有待核对的账单更新
- **THEN** 交易信息列 MUST 依次显示“草稿待补充”“配对建议”或“账单更新待核对”的有底色标签
- **AND** 流水类型列 MUST 只显示类型与适用子类型，不得承载待处理原因
- **AND** 整行 MUST 使用警告色底色，不得仅显示笼统的“待确认”

#### Scenario: 来源身份疑似重复

- **WHEN** 正式流水因来源身份疑似重复而需要人工核对
- **THEN** 交易信息列 MUST 显示“疑似重复待核对”的有底色标签
- **AND** 与类型名称不同的业务标签 MUST 保留在流水类型列，不得与待处理原因混同

#### Scenario: 状态标签在桌面与移动端同属交易信息

- **WHEN** 使用者在 `REGULAR`／`WIDE` 或 `COMPACT` 查看同一笔待处理收支
- **THEN** 状态标签 MUST 都位于交易信息区域，位于核对原因之后
- **AND** MUST NOT 因断点改变状态标签的归属或语义

#### Scenario: 关联搜索输入与账本筛选一致

- **WHEN** 使用者在关联弹窗输入日期或金额
- **THEN** 输入 MUST 使用与账本筛选相同的日期选择和精确金额校验
- **AND** 无效输入 MUST 在提交前阻止继续，不只依赖服务端通用错误

#### Scenario: 多币种月份汇总对齐

- **WHEN** 同一个月包含多种币种
- **THEN** REGULAR／WIDE 的月份标题 MUST 位于左侧，多币种汇总 MUST 作为整体靠右排列
- **AND** COMPACT 的月份 MUST 单独位于第一行并左对齐，下一行起每种币种 MUST 各占一行，以“币种、收入、支出”横向排列且整行右对齐
- **AND** 账本与导入核对 MUST 使用相同的月份汇总布局
- **AND** 金额 MUST 使用等宽数字
