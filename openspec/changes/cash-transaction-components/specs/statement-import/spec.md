## MODIFIED Requirements

### Requirement: 导入账户由来源行和映射规则解析
账单导入 MUST 根据来源行中的支付方式、账号、卡号、账户产品档案或明确映射规则解析每个支付组成项的目标账户。对于可验证的支付宝 `&` 支付方式，真实账户组成项 MUST 分别进入导入预览；红包、立减、优惠、抵扣和券等不产生账户的成分 MUST 只保留在来源行快照。缺少组成项金额或账户无法唯一解析时 MUST 阻塞确认，不得把总额猜测归入单一账户。

#### Scenario: 支付宝组合支付要求补齐金额
- **WHEN** 支付宝行包含两个真实账户但来源只提供合计金额
- **THEN** 预览 MUST 标记为待补齐并要求使用者输入各组成项金额，未守恒前 MUST NOT 写入父流水

#### Scenario: 组合支付确认后只写一条父流水
- **WHEN** 使用者补齐并确认组成项账户和金额
- **THEN** 系统 MUST 在同一事务中写入一条父流水和全部组成项，并保留完整 `source_payload`

### Requirement: 业务行标识提供跨文件幂等
导入幂等 MUST 以当前工作区、导入渠道和父流水业务行标识共同判断；重复确认同一组合支付时不得创建第二个父流水或第二组活动组成项。组成项顺序和派生身份 MUST 由父业务行稳定确定。

#### Scenario: 重复导入组合支付
- **WHEN** 使用者再次确认包含相同支付宝业务行的文件
- **THEN** 系统 MUST 不创建重复父流水或组成项，并报告新增行数为 `0`
