## Context

本变更承接 2026-10-30 Hallmark 对关系治理交付界面的审查。Kimi K3.1 Pro 对最新 7 张截图（1440/390）执行视觉复核，并对照 Material 3 Dialog／Side sheet 规范；结论为 0 critical、8 major、6 minor，另有 2 项静态图无法判断。视觉复核确认无缺字方框，三类关系选择、无 subtype 和一级类型筛选外观成立；未能确认整行点击、列表状态色、账单原文直接展示和动态筛选生成逻辑。用户决定本轮保留已完成的 UI，把修复归入本变更。

## Goals / Non-Goals

**Goals:**

- 修复导入、账本、详情三类页面的层级、重复文案、操作可达性和状态语义问题。
- 保持现有信息架构、业务合同和共享响应式类，不新增页面或路由。
- 复用现有 Material 3 组件与 token。

**Non-Goals:**

- 不改变金额、关系写入、投影、持久化、权限或导入业务规则；关联搜索的结果资格和游标语义按本变更调整。
- 不重做导航、主题或全局视觉系统。
- 不新增选择入口、批量模式或全选；保留现有按窗口尺寸选择方式。
- 建议／预览的选定现金部分与约束错误定位需要扩展公开协议，留为后续工作；本轮不推断缺失数据，保留主动新增关联已有的现金部分摘要。
- 保留手机 FAB 和既有选择方式；本轮只调整现有页面，不重建页面结构。

## Decisions

1. **导入步骤名称只出现一次。** 优先保留正文标题，步骤条使用短步骤名并区分已完成／当前／未开始；步骤条与底部操作对齐到同一内容列。本次来源账户的不同 `sourceType` 至少有两种时才显示渠道分组及跨渠道同名合并开关；单渠道直接列出账户，行名保留昵称或脱敏账号与资金方式，避免同名账户无法区分。
2. **账本表格拆分类型与状态。** 已确认状态不再重复显示；状态只在待确认、待复核或关系待确认等例外出现。桌面行增加整行打开动作，选择控件不触发行打开。现有选择方式保持不变，不增加选择功能。月份标题留左侧，汇总整体靠右，金额使用等宽数字。
3. **详情保留原有操作层级。** 底部主操作仍为编辑；建议卡内提供核对入口。已有关联卡保持在建议卡之前。关联摘要按记录分行，关系类型只在标题或单个 chip 出现一次。关联流水和账单原文共用成员卡片的标题行、右侧标签／金额及字段上方分隔线；关联卡保留自己的业务字段与移除操作，原文卡保留来源字段。关系待确认在列表与详情统一使用 warning 语义色；补拍列表标签后确认实际颜色角色。
4. **详细筛选点击应用后生效。** 用户已确认条件编辑时不更新账本结果，固定底部按钮使用“应用”，点击后统一提交当前条件。正文独立滚动，首屏可见应用出口。关闭图标、Escape 或系统返回放弃待应用修改；重新打开从已应用条件初始化。重置只修改本地条件，仍须应用；无效金额禁用应用。账本页搜索与快捷筛选的既有行为不在本次变更范围内。
5. **关联搜索只返回可选结果。** 服务端按已有查询、工作区与角色条件确定候选，再分批计算现金部分资格，跳过不可选目标；收集 `limit + 1` 个可选目标后生成页面和游标。`next_cursor` 指向本页最后一个可选目标；没有更多可选目标时为 `null`。客户端与演示仓库只展示可选结果；写入时仍重新验证修订与财务不变量。
6. **移动端列表与筛选。** 保留悬浮新增按钮及列表原有末尾留白，不增加 Compact 列表视口底部占用区；所有尺寸保留既有快捷筛选换行，类型直接可见，“筛选”入口位于右侧。
7. **唯一瀑布流组件。** 账本、导入核对与关联搜索共用时间分组、分组 Surface、行与列标题、右侧滚动条及月份吸顶逻辑。组件接收可选的月度收支合计；账本和导入核对启用，关联搜索关闭。不同使用点保留各自的分页、筛选、选择和整行操作。桌面账本和导入核对删除行尾眼睛及空列，整行仍可打开；关联搜索整行用于选择。滚动条与吸顶表面处于同一视口，轨道高于吸顶表面；关联弹窗表格横向溢出时，由共享组件根据可见宽度与水平滚动位置把轨道留在视口右侧。
   滚动条拖动位置保留小数序号，已加载目标按行内像素偏移连续移动；未加载目标仍通过整数序号分页定位，松手后用加载后的实际行高校正。鼠标滚轮或列表手势滚动时，以首个可见行及其像素偏移同步滑块。目标月份按整数序号读取缓存区间。
8. **类型列与原因标签。** 账本和导入核对用同一列结构：首行取预计收支主流水的 `record_type`，仅当 `record_subtype` 适用时附加其可读名称；与类型名称不同的业务标签在账本类型列辅助显示；需关注的原因以有底色标签显示。服务端列表响应补齐主流水类型／子类型，主页待处理原因须由服务端提供可判定依据，不能从笼统的 `confirmation_status` 猜测。草稿标“草稿待补充”，待处理配对标“配对建议”；不显示“待确认”或“已合并”独立标签。需关注的行统一使用警告色底色，标签保留独立的有底色视觉形式。正式流水因重新导入的账单字段变化而待处理时显示“账单更新待核对”，来源身份疑似重复时显示“疑似重复待核对”。导入计划公开项和分页项均透出类型／子类型；演示列表按日期倒序；关联搜索的类型列只显示类型及适用子类型，REGULAR 横向表格的垂直轨道固定在可见视口右侧。
   旧导入计划若缺少 `monthly_source` 或项目的类型字段，读取、翻页及确认均按现有 `plan_changed` 拒绝，避免把旧数据静默显示为空值；结果核实返回 `not_committed`，重新预览可沿用旧计划的选择并生成完整的新计划。此校验只作用于导入计划，不更改现金修改计划共用的合同版本。
   账本类型与原因字段按最多 500 条投影分批，以一次 `UNION ALL` 查询读取主流水类型、所有成员的当前问题和待确认关系，避免逐行查询和多次往返；证据页合并投影与账户读取，保持原有查询数量预算。
9. **验证方式。** 共享单测、Android/iOS 编译、Web 构建与真实浏览器 1440/390 冒烟；实施后重新执行 Hallmark 审查并记录人工替代范围。

## Risks / Trade-offs

- 搜索资格过滤移入后端会改变响应集合与分页游标，必须覆盖不可选项跨页和全部不可选的结果。
- 新展示字段与月度汇总使旧导入计划不可直接展示；读取与提交均返回 `plan_changed`，用户可在当前会话重新预览，已提交收据不受影响。
- 整行可点与选择控件共存需要确保点击目标不冲突，并保留键盘与无障碍语义。
- 整行点击、列表状态色、账单原文直接展示和动态筛选生成逻辑无法仅凭静态截图确认，需在实施前补运行时检查或补拍。
- 首屏操作调整和快捷筛选换行会影响既有 E2E 布局断言，需要同步更新并重新演示。

## 实施合同与预检

按 A 类执行：本轮关联搜索改变公开响应集合与分页语义，三处共享列表组件跨页面复用。当前 feature worktree 隔离于主分支。影响仅在共享呈现的三个业务模块，不属于重大 UI 重构；现有导航、页面外框、任务主线与 Material 组件保留，直接修复 Compose，不创建 HTML 原型。

信息层级：账本仍为搜索／快捷筛选／列表／详情；Compact 直接展示全部当前可用快捷类型，空间不足时换行，详细筛选入口位于右侧。详情为摘要／关联流水／待确认建议／账单原文，固定底栏仍以“编辑”为主。导入维持文件／账户／核对，准备阶段步骤、正文与底栏在 720 dp 内容列对齐，核对表格继续铺开。

删除冗余信息：普通已确认标签、步骤长标题、建议摘要重复关系类型、搜索结果中的不可选记录、桌面行尾重复打开图标。保留来源成员原始类型、主动新增的现金部分摘要、所有财务未知值与实际原因。

Hallmark 预检与方向：沿用 FinanceTheme、Git token 与 M3 Expressive，账本保持高密度列表、详情保留固定操作、导入保持单任务窄内容列；通过层级和必要信息修复，不新增主题、装饰、教学文案或控件包装。自查重点为滚动正文与固定出口、warning 角色配对、金额可读性、选择与打开的点击隔离。

Cross-platform Impact Check：Web、Android、iOS 均消费 commonMain 页面，交互、文案、错误、确认和响应式合同同时生效。Compact 共享手机合同，Regular／Wide 保持现有导航及筛选／详情／操作关系；不新增平台差异。Web 在 1440／390 真实浏览器演示与冒烟，Native 相称编译和单测，不默认设备 QA。

先行验证覆盖筛选编辑／应用／取消／重置、桌面金额区打开与复选隔离；服务端合同覆盖不可选目标在可选目标之前、两页之间与全部不可选的情况；导入夹具覆盖单／多渠道账户分组。纯几何修复以浏览器复现及截图验证。第一版完成编译和 Web 可演示检查后立即启动最新演示，最终审查与完整回归在用户确认后继续。

回滚为还原本 change 的共享 UI、字符串、测试及 artifact，不涉及数据迁移；协议定位缺口保持后续任务。无新增依赖，沿用 CMP 1.12.1 / Material3 1.12.0-alpha03；FAB 菜单现有实验 API 保留，日期使用现有 commonMain API，编译确认跨端可用性。

组件沿用现有 Material 3 控件与主题 token：选择使用独立选中语义，日期沿用日历确认，输入使用错误状态，FAB 保持悬浮，金额使用等宽数字。

## 最终设计复核依据

2026-10-31 使用真实 Chromium 加载并阅读 Material 3 官方正文：[Dialogs overview](https://m3.material.io/components/dialogs/overview)／[specs](https://m3.material.io/components/dialogs/specs)、[Side sheets overview](https://m3.material.io/components/side-sheets/overview)／[specs](https://m3.material.io/components/side-sheets/specs)、[Chips overview](https://m3.material.io/components/chips/overview)／[specs](https://m3.material.io/components/chips/specs) 及 [Start building with Material 3 Expressive](https://m3.material.io/blog/building-with-m3-expressive)。采用单任务弹窗、动态高度、正文滚动与固定操作区、侧板分离留白和内容间距、筛选芯片的选中／焦点反馈及内容自适应；沿用仓库明确批准的容器宽度、关闭位置和操作顺序。Expressive 用于强调当前操作与待处理状态，不增加装饰性页面结构。组件 API 以当前依赖及 Web／Android／iOS 编译为依据。

## 演示场景数据

用户已明确要求主页至少 20 条、覆盖本次场景；通过 `grill-me → grilling` 核对已确认边界，无新增未决产品选择。使用进程内固定合成记录与明确关系成员、候选和现金部分，服务于现有 UI 演示，不新增页面或恢复协议。基础仓库测试保留最小夹具；应用演示 Graph 初始化时加载丰富场景，关联搜索只返回可选目标。月份汇总与筛选选项依据实际可见演示结果生成，未知值保持 null，转账与草稿不作为外部收支累加。核对走现有维护预览／确认入口，所有合成写入和幂等结果仅留当前进程；刷新重新初始化。内置账单提供多来源账户组、不同币种与待确认项。
