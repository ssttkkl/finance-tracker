## MODIFIED Requirements

### Requirement: 从详情自由搜索导入流水新增关联

用户 MUST 能从当前收支详情打开模态弹窗，搜索同一工作区内已保存的导入流水，并选择同笔支付、退款或转账建立关联；不选择关系子类型。搜索 MUST 不受自动匹配的时间窗口和现存候选范围限制；结果 MUST 对应可核对的实际流水，而不是无法明确成员的收支汇总。手动记录、手动转账、其他工作区记录和独立投资事件 MUST 不参与此能力。草稿、已删除、自身或已关联成员等不合法目标 MUST 由界面限制，并由服务端拒绝绕过输入。搜索服务端 MUST 在分页前按所选关系种类及现金部分资格排除不可选择的目标；每页仅包含可选择流水，游标 MUST 指向本页最后一个可选目标。没有更多可选目标时 `next_cursor` MUST 为 `null`。返回结果不保证提交时仍可用；提交 MUST 按当前修订与完整关系图重新验证。

#### Scenario: 搜索自动候选之外的流水

- **WHEN** 用户搜索一条从未被自动推荐、发生时间超出自动匹配窗口的已保存导入流水
- **THEN** 系统 MUST 允许按交易对方、备注或账单标识搜索，并按账户、时间和金额缩小结果；选择后展示实际基础信息和合法关系类型
- **AND** 添加关联弹窗 MUST 在搜索区域之前提供“同笔支付”“退款冲销”“个人转账”的 Material 3 单选分段按钮，选择状态 MUST 决定后续关联类型，转账的币种形态由两端币种决定，不提供子类型选择
- **AND** 当前详情为导入流水时，即使没有候选，MUST 仍能进入搜索；手动记录不显示此入口

#### Scenario: 不可选目标横跨分页边界

- **WHEN** 当前查询中不可选流水排在可选流水之前或位于两页之间
- **THEN** 不可选流水 MUST 不进入页面项目或占用页面名额
- **AND** 下一页游标 MUST 从本页最后一个可选目标之后继续，不能出现重复或漏掉可选目标

#### Scenario: 查询范围内全部目标不可选

- **WHEN** 当前查询匹配的流水都没有合法现金部分选项
- **THEN** 服务端 MUST 返回空项目与 `null` 游标

#### Scenario: 合法目标在搜索后失效

- **WHEN** 用户从搜索结果选择目标后，该目标修订或关系图发生变化
- **THEN** 预览或提交 MUST 拒绝失效决定并提示刷新，不得依据旧搜索结果直接写入

#### Scenario: 关联财务校验失败

- **WHEN** 所选关系的金额、币种、方向、合法角色、退款完整金额及额度、关系占用或完整组约束不成立
- **THEN** 系统 MUST 给出具体原因并阻止确认，不通过重分类、改写金额、拆分提交或业务跳过来建立关联

#### Scenario: 预览和提交关联

- **WHEN** 用户选择合法目标及关系类型
- **THEN** 系统 MUST 先展示实际涉及的完整成员及最终收支效果，再由用户确认；取消不保存关系
- **AND** 新增关联 MUST 复用修订校验、工作区权限、幂等核实和原始流水保留合同；SQLite 和 PostgreSQL MUST 在同一 Application Service 下保持等价结果，使用精确十进制金额

#### Scenario: 主动选择曾拒绝的关联

- **WHEN** 用户主动搜索此前拒绝的流水组合
- **THEN** 系统 MUST 能重新校验并让用户明确确认，不因旧拒绝而隐藏合法目标；自动推荐仍遵守原拒绝决定
