# 设计说明

## Context

动机与范围见 [proposal.md](proposal.md)，用户可观察合同见 [收支账本浏览 delta](specs/cash-ledger/cash-ledger-browser/spec.md)。收支账本、详情和表单都由共享 Compose 页面承载；同一实现用于 Compose Web、Android 和 iOS。旧 React Web 只用于核对现有用户任务与信息层级。

当前页面把筛选、每月摘要卡、流水卡、选择操作卡分段纵向堆叠；`REGULAR` 仍沿用卡片行，宽屏表格也把主要字段压在单行中。详情与编辑分别持有模态窗口，编辑时会叠在详情上方；详情中的凭证和关联流水与主要字段混在长滚动列中。

界面必须继续使用 FinanceTheme、Git 中的设计 token 与 Material 3 控件。token 保留 Noto Sans SC、IBM Plex Mono、4 dp 间距节奏、语义收入/支出色和现有焦点色；不创建颜色、字体或组件包装层。全局 FinanceTheme 将现有浅/深色表面 token 映射到 Material 3 `surfaceContainer*` 角色，让默认卡片与弹窗从主题读取表面颜色；该映射也作用于其他 Compose 页面，但不改变其页面结构或业务行为。运行时和业务状态继续由现有账本 ViewModel 提供，不改变 API、金额、关系或持久化行为。

## 用户任务与信息架构

**主要任务：** 快速浏览并定位一笔收支。

**次要任务：** 记一笔，查看并核对一笔收支，按需编辑、删除或管理其关联流水。

**页面结构：**

1. 唯一账本标题；各窗口统一在右下方浮动操作菜单中提供「记一笔」「导入账单」。
2. 固定筛选卡：搜索输入复用现有交易对方筛选；始终显示「全部」「支出」「收入」「转账」四个快捷项和详细筛选入口。筛选卡停留在屏幕上方，只有其下方的流水列表滚动。
3. 详细筛选入口；按「时间」「金额」「分类」「账户」「其他条件」分组展示既有日期范围、币种与金额范围、分类、账户、资金转移类型和合并状态。
4. 按月分成独立的前景容器；月份及收入/支出汇总放在各自容器顶部，流水跟随汇总显示。月份汇总离开原位置后固定在筛选卡下方；`REGULAR` / `WIDE` 的列标题与月份汇总一同固定。跨月时保留当前固定头，直至下月头部到达列表顶部，再一起切换，避免新月份提前固定并与列表中的原头部重复。`REGULAR` / `WIDE` 将列表右侧预留从 40 dp 缩到 16 dp。各尺寸的窄轨道和滑块贴齐列表内容右边缘，40 dp 交互热区仍叠加在列表上，不额外挤占列表宽度；`COMPACT` 在滚动时显示滚动条，停止 2 秒后渐隐，`REGULAR` / `WIDE` 常驻显示。
5. `COMPACT` 以单列流水卡片呈现日期、交易对方和金额优先级；`REGULAR` / `WIDE` 以紧凑表格呈现日期、流水信息、账户、分类、类型和金额。桌面行内容左右各缩进 16 dp，与月份汇总和列标题对齐，分隔线仍铺满月份容器。账单中的金额数字启用等宽数字并在表格列右对齐，便于跨行比较；金额颜色和语义保持不变。
6. `COMPACT` 默认不显示行复选框，长按一行即选中并进入选择模式；此时行复选框出现，点行切换选择，取消最后一行后退出。`REGULAR` / `WIDE` 始终保留行复选框。所有尺寸均不提供「全选当前已加载」。
7. 浮动操作菜单在无选择时提供「记一笔」「导入账单」，有选择时自动展开并改为提供「设置分类」「删除」「取消选择」；选择状态用多选图标表示，已选数量显示在 FAB 左侧的提示胶囊。批量分类在模态对话框内选择分类并确认应用；删除沿用既有危险确认。
8. 新增或查看流水时打开同一信息面板。金额、交易对方和时间摘要保持在卡片外；主要流水信息放入 Material 3 ElevatedCard，以标签/值分列展示；有关系时使用另一张并列 ElevatedCard 呈现默认收起的「关联流水」入口，展开后仍在该卡内分组查看当前与关联流水。详情面板使用中性高层 Surface，两张卡使用 ElevatedCard 默认的 `surfaceContainerLow` 角色；收入/支出金额保留现有语义配色。来源、凭证和退款时间线按需归入对应信息区域；编辑在同一面板中切换。卡片不互相嵌套。
9. 筛选卡和每个月份流水容器是彼此独立的前景表面，固定筛选卡与滚动列表分属不同布局区域；中性页面底色从视觉上隔开筛选与月份容器。详细筛选弹层仍使用 Material 3 默认容器色，不叠加主题色调提升。

## 将删除的冗余信息

- 不再将月度汇总与同月记录分开；月份汇总留在各自流水容器的顶部。
- 删除与列表分开的批量操作卡；操作只在有选择时出现，并紧贴列表。
- 删除宽屏记录行中重复的独立操作文字列；详情、分类和删除动作按列表工具栏或行内操作入口组织。
- 删除叠加在详情对话框上的第二个编辑对话框；新增、详情和编辑共用一个模态面板。
- 单源收支不显示空的凭证或关联区域；有关联时通过默认收起的详情内联区域查看，不叠加弹窗；不增加常驻帮助文案、教学区或实现说明。
- 搜索与快捷类型筛选保持在固定的顶部筛选卡；详细筛选收起后不占用首屏高度，分类不会重复显示在快捷项和详细筛选中。
- 移除 Compact 默认可见的复选框和「全选当前已加载」入口；移除页头分立的新增/导入按钮与选择后常驻的整排批量操作控件，由一个浮动操作菜单按状态承载这些动作。

## Hallmark 方向与自查

- **预检：** `.hallmark/preflight.json` 的 2026-10-12 记录确认了 Compose Multiplatform、Noto Sans SC、IBM Plex Mono、Finance 语义 token、4 点间距和克制动效；其中原型描述已过时。本次更新预检记录以当前 `commonMain` 产品页面为准。实际 token 见 `openspec/specs/shared/design-system/tokens/core.tokens.json` 与 `light.tokens.json`。
- **受众：** 使用 Finance Tracker 记录和核对收支的人。
- **任务：** 浏览、筛选并定位流水，必要时新增或打开详情。
- **语气：** 精确、克制、偏工具性。
- **结构选择：** 使用 Workbench 的“围绕一项高频工作组织界面”原则，适配真实账本而非营销式产品演示；不设 Hero、装饰统计或新增页面导航。
- **视觉选择：** 参考支付宝账单列表的中性底面、固定筛选入口和按月分开的白色账单容器，只借鉴信息分组与滚动关系，不复刻品牌内容、状态栏或图标。月度金额汇总与流水处于同一容器，内部分隔线保持行扫描节奏；金额使用等宽数字并在表格列右对齐，继续使用现有语义色。详情摘要不加卡片；主要流水信息与关联流水分别使用并列的 Material 3 Card，关联折叠内容留在同一张卡内，不嵌套卡片。浅色主题用白色表面承载筛选卡和月度容器，中性灰承载页面与详情面板；深色主题沿用现有背景、surface 和 muted surface token 构成对应层级。所有表面值集中映射到全局 `FinanceTheme.surfaceContainer*`，调用点使用 Material 3 默认角色，不指定每张卡的独立颜色，也不依赖 tonal elevation 生成偏蓝叠色。金额颜色维持现有语义映射。全尺寸使用 Material 3 FAB 菜单；进入选择模式时自动展开，显示多选图标，并在 FAB 左侧显示已选数量提示。
- **操作图标与危险色：** 编辑、关联/新增关系、保存和删除等主要操作在文字标签旁显示易辨识的 Material 图标，保留可见文案和无障碍名称；不为取消、重试、翻页等次要按钮统一添加图标。批量删除、流水删除、解散关联，以及删除确认按钮使用 FinanceTheme 的 `error` 语义色；取消和非破坏性确认保持普通颜色。沿用现有图标资源，必要时新增本地向量资源，不引入依赖。
- **筛选方向：** 借鉴参考图的「搜索输入 + 类型快捷项 + 详细筛选入口」信息顺序，不复刻其品牌样式；沿用 FinanceTheme 与现有控件。详细筛选在 `COMPACT` 使用 Bottom Sheet，在 `REGULAR` / `WIDE` 使用模态弹窗；搜索只绑定已有交易对方条件，分类留在详细筛选中。面板按五个常驻标题组织既有选项：时间（开始/结束日期）、金额（币种、最低/最高金额）、分类、账户、其他条件（资金转移类型、合并状态）；不增加折叠交互。Compact 纵向排布各组；Regular/Wide 在组内并排放置日期与金额范围，以及其他条件中的可配对项，分类和账户仍保持独立组。
- **自评：** Philosophy 5、Hierarchy 5、Execution 4、Specificity 5、Restraint 5、Variety 4。风险是 `REGULAR` 的表格列宽和密集信息容易相互挤压，实施时通过组合流水信息列、约束长文本并保留金额/账户列的可读宽度处理。
- **更新自查：** 搜索和快捷类型选择只搬动既有筛选入口，不增加查询字段、退款类型或业务语义；详细筛选默认关闭，各窗口共用相同值、标签和结果。固定筛选卡占用的竖向空间会减少首屏可见流水数，布局让列表使用其余高度，Web 在三种窗口尺寸复核。
- **本轮视觉自查：** 顶部筛选卡、每月独立账单容器和月汇总形成连续的阅读顺序；只滚动流水列表，Compact 仍以行信息快速浏览，桌面表格保持列标题和每月记录关系。进入多选后 FAB 自动展开，多选图标与左侧数量提示在菜单状态变化时保持稳定。月度数据继续按现有 Paging 流加载；月份跨页时必须保持容器连续，不为视觉分组加载完整月份。图标始终与本地化文字并列，不替代按钮名称；危险色只强调会删除流水或移除关联的操作和既有删除确认，不扩展业务动作或确认流程。详情摘要保持在面板底色上，流水信息卡与关联流水折叠卡并列并使用默认前景容器色；展开内容留在关联卡内。全局表面角色只取自已有 token，金额配色保持现状。本轮共享 Compose UI 影响 Web、Android、iOS；根据用户此前确认仅通过 Web 三尺寸验证，Native 运行时风险在任务记录中说明。
- **本轮筛选分组自查：** 分组标题对应使用者寻找筛选项的任务而非内部字段结构；金额范围与币种同组，账户与分类独立，少见的资金转移类型与合并状态置于「其他条件」。五组常驻展示，不再增加折叠层级；所有筛选值、触发时机、结果、关闭和重置语义保持原样。Compact 单列避免窄屏挤压；Regular/Wide 仅在各自组内横向组合成对字段。

## Goals / Non-Goals

**Goals:**

- 让浏览和定位流水成为首屏视觉重心。
- 用同一套区域、操作和状态合同覆盖三类窗口及 Compose 三个平台。
- 在一个模态信息面板内完成新增、详情、编辑和现有详情操作。
- 保留全部现有筛选、分页、批量操作、权限、字段验证、危险确认和财务语义。
- 让使用者通过交易对方搜索和常用类型快捷项快速定位流水，详细筛选按需打开。
- 通过 Compact 长按进入选择，并用跨尺寸一致的浮动操作菜单承载新增、导入及批量动作。
- 提高编辑、关联、保存和删除等主要操作的可识别性，并让破坏性操作清楚显示危险语义。

**Non-Goals:**

- 重写旧 React Web 或将其页面代码移植到 Compose。
- 改动业务层、ViewModel 合同、API、数据库、分类规则、关系规则或金额计算。
- 新增搜索维度、筛选维度、退款类型、批量能力、流水类型或其他财务功能。
- 改动全局导航、账单导入和其他 Compose 页面的信息架构或业务行为；全局 Material 3 表面容器颜色遵循本次 FinanceTheme 角色映射。

## Decisions

### 1. 沿用共享 Compose 入口和现有账本状态

在 `CashLedgerScreen.kt` 与 `CashLedgerDetails.kt` 内重组呈现，不拆平台实现，不引入新路由、依赖或 ViewModel。保留 `selectedRow` 与 `recordDraft` 的状态来源：无 draft 时显示详情；有 draft 且没有选中行时显示新增；两者都有时显示详情编辑。这样保存后沿用现有刷新路径，取消编辑可回到原详情。

**替代方案：** 按平台拆 Native/Web 页面，或者为新增、详情和编辑新增路由。前者会复制同一账本产品合同，后者会增加导航与状态迁移；两者都超出本次范围。

### 2. 按 WindowSizeClass 分配列表密度

`COMPACT` 使用单列卡片，以金额、交易对方、发生时间构成主扫描线；账户、分类、类型、来源和备注以紧凑次级信息呈现。`REGULAR` / `WIDE` 使用连续表格，`REGULAR` 将次要描述组合进流水信息列以保住账户、分类和金额，`WIDE` 提供完整列。月度金额汇总落在分组表头，不再使用孤立卡片。

搜索输入复用现有 `counterparty` 条件，并在每次输入时沿用原有筛选更新路径。快捷项始终显示「全部」「支出」「收入」「转账」四项；切换类型时复用现有经济类型值并清除不适用的转账细分，「全部」只清除经济类型和转账细分，保留日期、账户、分类等其他筛选。

详细筛选默认关闭。「筛选」在 `COMPACT` 打开可滚动的 Bottom Sheet，在 `REGULAR` / `WIDE` 打开居中模态弹窗，最大宽度遵循 720 px 单项表单约束；弹窗高度随筛选内容展开并在超出视口时滚动，不保留大块空白；背景账本保持可见但不可操作。日期、账户、分类（含无分类）、币种、金额范围、转账细分和组成筛选继续使用现有字段与回调；交易对方和经济类型移到顶部，不重复放在详细选项中。重置清除搜索、快捷类型及详细筛选的全部现有条件。关闭支持 Escape 或系统返回，焦点沿用 Compose 与平台默认行为，不增加专属请求或恢复逻辑。

### 3. 用浮动操作菜单承载主要与批量动作

在所有窗口尺寸使用 Material 3 Expressive `FloatingActionButtonMenu`，无选择时显示加号 FAB，展开态提供清晰的文字动作。无选中项时菜单提供「记一笔」「导入账单」；首次选中流水进入选择模式时菜单自动展开并改为「设置分类」「删除」「取消选择」。选择模式的 FAB 始终使用多选图标，旁边常驻显示「已选择 X 个」提示胶囊；菜单关闭后仍保留选择图标和数量。最后一笔取消选择或「取消选择」动作使模式退出并关闭菜单。菜单固定在右下方并叠加在列表上；列表末尾保留滚动余量，让最后一笔能够滚到 FAB 上方完整查看，不缩短列表视口或在列表外留固定空区。操作入口始终受现有权限和忙碌状态约束。`importButtonFocusRequester` 继续连接导入导航已有的返回路径，不新增账本面板焦点逻辑。

Compact 使用 Compose 点击/长按组合：未选择时普通点击打开详情，长按立即选中当前行；选择模式中点行或复选框切换该行，最后一项取消后自动退出。选择模式中才显示 Compact 行复选框。Regular/Wide 保留行复选框，普通行主体仍打开详情。所有尺寸展示已选数量，不提供全选当前已加载。

「设置分类」打开 Material 3 模态对话框，在对话框内完成现有分类选择，并通过「取消」「应用」明确控制批量写入；取消不修改流水。应用沿用原有分类服务、加载状态和错误反馈。删除继续调用当前危险确认流程。

搜索字段使用清晰的线框放大镜语义图标，并保持现有交易对方筛选字段与提示，不增加新的搜索行为或依赖。

**替代方案：** 三类窗口使用同一套卡片。该方式在 Regular/Wide 浪费横向空间，不利于连续比较日期、账户和金额。

### 4. 用一个模态容器承载详情和编辑

列表内新增和详情入口打开一个模态面板：`COMPACT` 全屏，`REGULAR` / `WIDE` 在右侧呈现。桌面遮罩后仍可见账本，但不能操作背景；窄屏全屏内容位于系统安全区内。面板焦点沿用 Compose 与平台的默认行为，不增加专属初始焦点请求或关闭后的焦点恢复逻辑；导入导航等其他功能已有的焦点行为保留。详情进入编辑时只切换面板内容；取消返回详情，保存显示更新后的详情。新建保存或取消则回到列表。

所有平台共用 Material 3 Dialog 容器及面板内容、尺寸合同。Compose Web 在容器内绘制遮罩并拦截背景点击；Compose 根预览处理器在 Web 上让出 Escape，模态捕获处理器关闭当前模式；已挂载的选择菜单和可见危险确认继续由内层操作处理。账户菜单的捕获监听在账单面板、详细筛选或分类弹窗已挂载时让位。Android/iOS 保留根级硬件键盘 Escape 和系统 Dialog 返回处理。只有危险确认和关联影响确认保留必要的二次确认浮层。

**替代方案：** 继续叠放详情和编辑 Dialog；这会重复模态层并让键盘返回顺序不清楚。非模态双栏则不符合已确认的背景隔离合同。

### 5. 详情按核对顺序组织

顶部在卡片外以清楚的摘要区呈现金额、币种、交易对方、经济类型和发生时间；主要流水属性放入一张 Material 3 `Card`，按固定标签列与值列展示账户、流水类型、业务细分、分类和备注，避免每个值都贴右边缘。来源、凭证成员和退款时间线归入对应信息区域，不展示内部术语。

有已接受关系、相关凭证成员或其他相关事实时，显示独立的「关联流水」Material 3 `Card`，默认收起。触发项显示「查看关联流水」和可核对的条数；展开后仍在该卡片和当前详情面板内展示「当前流水」及逐条「其他关联流水」，每项按交易对方与金额、时间与账户、类型与分类的顺序组织。关联项继续提供原有编辑流水、修改关系类型和危险色解散关联操作；相关凭证成员、组成和退款时间线按现有语义归入相应区域。两张信息卡彼此并列，不嵌套卡片；不新增路由、网络请求、关系动作或另一层 Dialog/Bottom Sheet；无关联事实时不显示空关系卡。底部的新增关联、解散关联和删除入口保持不变。

视觉方向参考支付宝账单详情的金额摘要和明确的关联记录入口，以及微信支付详情的字段标签/值分列和分段层级；不复制其品牌、营销信息或支付状态，不引入其未提供的业务字段。

**替代方案：** 在详情 Dialog 内再打开 ModalBottomSheet 或第二个 Dialog 展示关系。嵌套模态会遮挡正在核对的流水并增加返回层级，已由用户明确排除；采用详情内联折叠区。

**替代方案：** 所有证据字段无差别地铺在一个长文本列中。此做法使主要字段难以扫描，并重复呈现同一流水信息。

### 6. 状态 ID 与业务回调保持稳定

保留现有 `SemanticIds` 与 ViewModel 回调；为 FAB 菜单动作、已选数量、分类对话框和批量操作增加稳定、具业务含义的语义 ID。按钮、输入框和选择器直接使用 Material 3，在调用点设置回调、标签、禁用、错误与无障碍语义；颜色与字体来自 FinanceTheme。旧 React Web 仅参考其信息组织，不共享其 DOM/CSS 合同。FAB 展开/折叠及各动作按稳定语义 ID 做 Playwright 定位；Compact 长按/点按、桌面勾选、分类取消/应用和删除取消都加入端到端覆盖。该轮 UI 通过共享 `commonMain` 交付，另在 Android 与 iOS 演示模式检查原生长按、返回、弹窗和安全区。

### 7. 让合成账本记录可进入详情

Compose 演示数据的流水 ID 带有 `projection-` 前缀；`fetchEvidence` 接口接收投影 ID，演示仓库之前把带前缀的 ID 当作记录 ID 查询，因而详情加载失败。只在 `DemoFinanceRepository.fetchEvidence` 去掉该前缀，并用合成流水的详情回归覆盖；生产仓库与服务合同不变。

### 8. 阻止浏览器 QA 使用陈旧 Compose Web 包

本地 Playwright 配置之前在非 CI 环境复用占用预览端口的服务，因此会绕过本次测试启动的构建步骤；机器上存在多个长期运行的预览服务时，测试可能连到旧页面。另一次产物时间核对发现 Kotlin 源码/Gradle 中间产物已更新，但实际分发目录仍保留先前包，说明只依赖 Gradle 默认增量任务状态不足以作为页面新鲜度证据。

预览启动器以 SHA-256 指纹记录 `shared/src`、`webApp/src`、Gradle wrapper/脚本/版本目录、影响构建的 API/demo 环境值和可选的 Gradle init script；再与分发目录及处理后资源的实际内容指纹比较。缺少记录、源码/配置变化、环境值变化或服务产物被替换时，强制执行 `:webApp:wasmJsBrowserDistribution --rerun-tasks`。构建前后重算输入指纹，发现构建期间输入变化就失败退出；构建包和输入均通过核对后再原子更新 stamp。在线 API 预览与离线演示共用实现，但各自的构建环境值会使不同模式互不误用。

Playwright 运行器预留一个操作系统分配的空闲端口，并把同一个端口明确传入配置与预览服务；`reuseExistingServer` 固定为 `false`。如显式指定的端口已被旧进程占用，服务启动应失败退出，不允许静默接入旧服务。QA 工具不终止测试前已经运行的预览实例，也不改变 Compose 页面或财务行为。

### 9. 主要操作图标与危险操作颜色

编辑、添加关联、创建关联、保存、删除等主要动作使用能表达动作的 Material 图标，并继续显示本地化文字标签；图标与文字共同组成按钮内容，因此不会改变现有可见名称和辅助技术语义。取消、重试、翻页等次要动作保持纯文字，避免给每个控件增加视觉噪声。已有加号 FAB 菜单项继续保留图标和文字。

批量删除、删除流水、解散关联的动作标签/图标，以及现有删除确认按钮使用 FinanceTheme `error` 语义色；取消按钮、保存确认等非破坏性操作沿用默认角色。解散关联只改变颜色和图标，不增加确认流程，也不改变现有关系服务行为。确认对话框仍提供现有删除影响说明和取消路径。

Web、Android 和 iOS 使用共享 Compose 资源与主题角色，旧 React Web 不变。浅色和深色主题均检查错误色可读性；`COMPACT`、`REGULAR`、`WIDE` 检查图文按钮的间距、换行与可触达状态。

### 10. 全局 Material 3 表面层级

所有表面层级值都从现有 `FinanceTokens` 获取，不增加 JSON token 或新的颜色常量。`FinanceTheme` 显式填写 Material 3 `surfaceContainerLowest`、`surfaceContainerLow`、`surfaceContainer`、`surfaceContainerHigh` 和 `surfaceContainerHighest`：浅色依次映射到 `surface`、`surface`、`background`、`surfaceMuted`、`surfaceMuted`；深色映射到 `background`、`surface`、`surface`、`surfaceMuted`、`surfaceMuted`。该映射沿用现有中性色阶，避免 M3 默认淡紫色及 `surfaceTint` 叠色。

筛选卡与每个月份流水容器各自使用 Material 3 前景角色，落在由 `surfaceContainer` 表达的页面背景上；月容器之间保留间隔，不在外层再套一个覆盖全部月份的白色 Surface。筛选卡位于加权 `LazyColumn` 之外，保持固定；流水与追加加载状态在该列表内独立滚动。每条懒加载流水根据相邻月份边界绘制月容器的顶部、内部和底部形状；只在确定月份结束或分页到尾时闭合卡片，让跨页同月记录连续。Compact 的行作为月容器内部普通流水行，不再保留逐行卡片。`REGULAR` / `WIDE` 在每个月份容器中展示列标题和流水。详情摘要留在 `surfaceContainerHigh` 的模态面板底色上；主要信息卡和关联流水卡使用 Material 3 ElevatedCard 默认的 `surfaceContainerLow`，不在每张卡上覆盖颜色。普通 Material 3 Card 使用 `surfaceContainerHighest`，在当前色阶中与高层面板同色，无法形成前景层，因此详情选用 ElevatedCard；页面其他默认卡片和弹窗仍读取各自的全局角色。功能地图、审查和 Web 回归需检查这些表面层级。金额仍由现有收入/支出语义色绘制。

### 11. 固定筛选区并保持分页中的月度容器连续

把筛选卡放在账本主列顶部，把可滚动流水列表放在其下方并使用剩余高度。这样 Compact 的筛选快捷项一直可见；列表滚动不会带走筛选，也无需复制筛选状态。筛选卡和月份容器读取现有 M3 表面角色，依靠页面中性背景及 token 间距形成分隔。页面外层不再为 FAB 缩短列表视口；FAB 叠加在列表上，列表内的末尾滚动空间保证最后一笔可以完整滚到按钮上方。

现有 `PagingData` 按时间倒序返回流水，页大小为 20，一组月份记录可能跨越多页。为保持逐行懒加载，每条流水仍作为 LazyColumn 项目；根据当前行、相邻已加载行和 `endOfPaginationReached` 判断月份起止，按边界绘制卡片形状。未加载下一页且尚未到尾时保持卡片开放，避免同月记录跨页时出现重复的下边缘、间隔或月份标题。月份标题只在该月首条流水上出现，`REGULAR` / `WIDE` 的列标题与该月标题共同位于该月卡片顶部。列表滚动到月份头部离开其原位置后，在固定筛选卡下方显示该月的固定摘要；桌面列标题作为同一固定区域的一部分，后续月份进入列表顶部时替换前一组。该固定区域不得改变分页序号映射或预取整月数据。

**替代方案：** 将整月流水收集为一个普通 LazyColumn 项目。它会在大型月份中一次组合大量行并削弱现有分页懒加载，因此不采用。

### 12. 完整刷新立即清除旧结果，并仅让列表响应下拉刷新

筛选值变化、`listRevision` 变化、导入返回或流水写操作后调用既有完整刷新时，ViewModel 会立即清空当前 `page` 并启动新列表代次。Compose Paging 在首屏刷新时可能继续持有上一代 `PagingData`，因此界面不能只依赖 `itemCount` 或 Paging 的占位项判断当前结果；当前代首屏完成前必须隐藏旧的流水及月份汇总，首次加载和完整刷新都显示骨架。`COMPACT` 使用现有流水卡片骨架，`REGULAR` / `WIDE` 使用表格行骨架。当前代首屏成功后再展示流水和汇总；失败时使用既有刷新错误与重试入口，不回退旧结果。下一页追加时当前代 `page` 已存在，保留已有行和汇总，只呈现既有追加加载/错误状态。

在共享账本的流水 `LazyColumn` 外围使用当前 Material 3 依赖提供的下拉刷新容器；筛选卡留在容器之外，避免筛选区域下拉触发刷新。手势只在列表到达顶部时触发 `viewModel.reload()`；不在顶部则由列表继续滚动。所有 Compose 平台与窗口等级均启用下拉刷新，多选状态下禁用手势，避免意外清除所选项。刷新释放后按完整刷新状态合同隐藏旧内容并展示当前尺寸的骨架。

回归用例使用延迟首屏响应证明筛选或列表代次变化后旧行和月份汇总不会在网络等待期间闪现；分别验证加载成功、失败后重试及追加页等待/失败。Compose Web 以触屏输入在 Compact、Regular、Wide 验证列表顶部手势和固定筛选区边界；Android 与 iOS 运行时验证相同的列表手势、多选禁用及骨架/错误状态。

### 13. 窄滚动条贴齐列表边缘且不挤占内容

所有窗口的滚动条可见轨道和滑块均与列表右边缘对齐。`REGULAR` / `WIDE` 沿用 16 dp 列表右侧预留，`COMPACT` 不设置布局预留；所有尺寸保留 40 dp 交互热区并让其覆盖列表，不以热区宽度改变列表测量尺寸。`COMPACT` 延续滚动期间显示、停止 2 秒后渐隐的行为；`REGULAR` / `WIDE` 保持常驻。月份拖动提示继续位于滚动条内侧，不覆盖可见轨道。

浏览器回归检查可见轨道与滑块的右边缘和列表边界对齐、Compact 的列表宽度在滚动条显示前后不变、Compact 的滚动后显示和空闲渐隐，以及三个尺寸仍可拖动和点击定位。

## 风险 / 取舍

- **Regular 视口较窄，表格可能压缩核心列** → 将对方、类型和来源放入流水信息列；行文本限制宽度，账户、分类和金额保持可读；在 768 px 真实浏览器复核。
- **详细筛选字段多，模态内容可能超出可用高度** → Compact Bottom Sheet 与 Regular/Wide 模态弹窗均使内容可滚动并保留底部重置/关闭操作；按 390、768、1440 px 复核，不出现页面级横向滚动。
- **单一面板切换可能丢失详情操作状态** → 保留 `selectedRow` 与现有 `recordDraft` 状态，取消编辑返回详情；针对新增、详情、编辑、错误、危险确认和关系操作回归。
- **Compose Web 与 Native 的 Dialog 遮罩和返回行为不同** → 保持相同的背景隔离和关闭顺序；Web 根预览处理器让出 Escape，模态捕获处理器优先并让选择菜单/危险确认先处理，账户菜单仅在无模态时响应；浏览器验证连续 Escape 和面板切换，在 Native 演示模式复核硬件键盘、系统返回与安全区。
- **长列表和详情都可滚动，手势边界可能冲突** → 只让列表正文和面板正文各自滚动，固定页头、面板操作区和导航外壳不随内容移动。
- **底部 FAB 菜单可能遮住最后几条流水** → 让最后一笔可滚动到 FAB 上方完整查看，同时避免用列表视口外的固定空区给按钮让位；在 Compact、Regular、Wide 检查菜单覆盖、末行可达和无横向溢出。
- **月份固定头部可能与筛选卡、下一月边界重叠** → 固定区域限定在列表视口内，位于筛选卡下方；切换筛选与跨月分页时按可见月份更新摘要，桌面列标题随该摘要成组更新。
- **长按与滚动手势竞争** → 使用 Compose 点击/长按手势组合，仅长按触发选择，短点仍打开详情；在 Android、iOS 和 Compose Web 实际验证两种路径，选择模式内取消最后一项后同步退出。
- **本地浏览器测试连到旧包或旧服务** → 构建输入与实际服务产物双指纹比对，疑似过期时强制 Gradle 重跑；端口隔离且禁止复用既有服务，构建期间输入变化或显式端口冲突时失败关闭。
- **批量分类在对话框外应用容易误操作** → 将分类选择与应用按钮收进同一个模态对话框；先验证取消无写入，再验证应用和现有错误反馈。
- **Paging 在完整刷新期间继续提供上一代缓存行** → 以 ViewModel 当前页/列表代次作为显示门控；首屏完成前只显示骨架，错误时显示重试而不回退旧结果；追加分页保持已加载行。
- **下拉刷新可能与列表滚动或多选误触冲突** → 手势范围仅包住列表，在顶部才触发，多选时禁用；分别在 Web 触屏输入和 Native 运行时检查。
- **滚动条热区可能在窄窗口挤压列表，窄轨道也可能看起来离卡片边缘过远** → 仅让 4 dp 轨道与滑块绘制在 40 dp 热区右边缘；热区覆盖列表、不参与布局测量；Compact 视图前后比对列表宽度，并验证 2 秒空闲渐隐。
- **演示数据的详情查找使用不同 ID 前缀** → 在 `DemoFinanceRepository` 适配合成投影 ID，并验证详情调用链；不改生产数据路径。
- **颜色/文字在深色主题中可读性变化** → 只消费 FinanceTheme 语义角色，并在适用的浅色、深色模式检查。
- **全局 surface container 角色影响其他 Material 3 默认卡片和弹窗** → 除账本/详情的三尺寸浅深色 QA 外，在 Compose Web 检查使用默认 M3 容器色的其他主要页面；Native 运行时按用户范围不复验，并记录共享 `commonMain` 的残余风险。
