## MODIFIED Requirements

### Requirement: 受支持账单直接进入统一导入流程

系统 MUST 接收 CSV、XLS、XLSX 和 PDF，多渠道文件分别识别并在同一会话解析一次。完成文件及账户准备后 MUST 用一个预计流水列表核对和一次确认，缺账户及待确认关联可以延后。单文件或单行可预期错误只影响该项，预览不写流水映射关系；独立账户命令立即生效。最终事务发布实际成功项及收据，原文件解析后清理。

#### Scenario: 混合渠道部分可用

- **WHEN** 微信文件可用而另一文件需密码
- **THEN** 服务端保留微信记录并显示另一文件的具体问题；Compose 文件步骤要求先输入密码重试成功或删除该文件，再继续

#### Scenario: 统一核对

- **WHEN** 已得到正常及草稿预览
- **THEN** 同一列表核对并一次提交，不要求逐项补齐或进入独立关系步骤

#### Scenario: 预览后离开

- **WHEN** 未最终确认但期间独立创建账户
- **THEN** 不写流水映射关系，账户已生效，正常退出由前端询问是否安全撤销

#### Scenario: 导入混合渠道文件

- **WHEN** 使用者一次提交来自多个现金导入渠道的一组格式有效账单，并完成账户映射、流水核对和关系确认
- **THEN** 系统 MUST 在一个最终事务中转换并写入全部文件中的有效业务行
- **AND** 返回按文件、渠道和整体批次可核对的导入计数

#### Scenario: 导入受支持文件

- **WHEN** 使用者为当前工作区提交格式有效的受支持账单并完成账户映射、流水核对和关系确认
- **THEN** 系统 MUST 从临时来源读取有效业务行，在一个最终事务中转换并写入当前工作区账本记录，并返回可核对的导入计数

#### Scenario: 预览不写账本

- **WHEN** 使用者只完成文件扫描、会话内账户选择或流水预览，且没有另行提交账户普通命令
- **THEN** 系统 MUST 返回可核对的扫描或预览结果，但不得写入账户、账户币种、账单账户映射、现金流水、交易关系或收支投影；单独提交的账户普通命令按其独立结果生效

#### Scenario: 任一文件未就绪

- **WHEN** 一组文件中有文件需要密码、无法识别渠道或解析失败，同时另有文件已就绪或部分可用
- **THEN** 系统 MUST 返回每个文件的状态并保留有效文件；Compose 文件步骤 MUST 先要求处理失败或需密码文件，再进入账户映射、预览和一次最终确认，具体提示见「文件选择步骤允许在上传中追加」
- **AND** 未就绪文件不得被伪造成可导入业务行；全部文件均无业务行时只显示文件结果

#### Scenario: 导入受支持现金文件

- **WHEN** 使用者为受支持现金导入渠道提交格式有效的账单文件
- **THEN** 系统 MUST 先返回自动识别的导入渠道和来源账户分组
- **AND** 使用者确认完整账户映射后，系统 MUST 返回标准化预览和关系建议
- **AND** 在最终确认导入前 MUST NOT 创建新账户、更新账户支持币种、创建或更新账单账户映射、账本记录、余额、交易关系或收支投影
- **AND** 最终确认后 MUST 把有效业务行转换为当前工作区的账本记录，并返回可核对的导入计数

#### Scenario: 预览后离开导入页面

- **WHEN** 使用者在最终确认导入前关闭或离开导入处理页面
- **THEN** 系统 MUST 丢弃本次未确认的文件、账户映射和关系决定
- **AND** MUST NOT 在数据库中留下新账户、账户支持币种、账单账户映射、账本记录、关系、余额或投影变化

#### Scenario: 自动识别完整微信工作簿

- **WHEN** 上传包含微信账单表头及有效流水、且满足既有文件、解压、行列和解析预算的 XLSX，未指定来源
- **THEN** 系统 MUST 自动识别微信并完整读取工作表，不能因内部预读块大小把有效工作簿判为不可读
- **AND** 明确指定微信来源时使用相同校验及行字段，不改写来源原文、金额精度、币种或发生时间

#### Scenario: 读取工行 PDF 的表格与文字

- **WHEN** 上传受支持的工行信用卡或借记卡 PDF，正确提供所需密码，文件的文字与表格具有一致的页面或内容流旋转
- **THEN** 系统 MUST 在同一几何方向读取真实表头和业务行，不因坐标系不一致拒绝有效账单或转置行列
- **AND** 表头、预算、来源身份、完整性及坏行校验仍按既有规则执行，不能放宽校验以接受错误抽取

#### Scenario: 损坏或超预算工作簿仍被拒绝

- **WHEN** 工作簿的 ZIP／XML 损坏、包含不允许的实体声明，或实际解压、行列及解析内容超过既有预算
- **THEN** 系统 MUST 拒绝该文件并返回现有安全错误，不向外部解析实体，不因修复正常工作簿而接受被截断内容或取消安全预算

### Requirement: 自动识别先执行快速格式探测
现金账单自动识别 MUST 要求每个内置候选解析器提供快速格式探测。探测 MUST 只读取受控的文件签名、表头或 PDF 首页标识，MUST NOT 生成正式流水、执行完整文件解析、加载账户映射或写入存储。

自动识别 MUST 先完成所有候选解析器的格式探测；只有恰好一个解析器匹配时，才对该解析器执行一次完整解析。零个或多个解析器匹配时 MUST 返回 `import_channel_unrecognized`，且 MUST NOT 通过依次执行多个完整解析来选择渠道。

#### Scenario: 唯一解析器匹配后只完整解析一次
- **WHEN** 使用者选择一份格式明确符合单个现金账单解析器的文件
- **THEN** 系统 MUST 先完成候选解析器的快速格式探测
- **AND** 系统 MUST 只调用匹配解析器一次完整解析，并继续返回既有导入渠道和来源账户分组
- **AND** 其他候选解析器 MUST NOT 被调用完整解析

#### Scenario: 未加密工行信用卡 PDF 扫描
- **WHEN** 使用者选择一份未加密且首页格式明确的工行信用卡 PDF
- **THEN** 工行信用卡解析器的格式探测 MUST 返回匹配，工行借记卡解析器的格式探测 MUST 不匹配
- **AND** 系统 MUST 只执行一次工行信用卡完整解析，识别为 `icbc_credit` 并允许页面进入账户映射

#### Scenario: 未加密工行借记卡 PDF 扫描
- **WHEN** 使用者选择一份未加密且首页格式明确的工行借记卡 PDF
- **THEN** 工行借记卡解析器的格式探测 MUST 返回匹配，工行信用卡解析器的格式探测 MUST 不匹配
- **AND** 系统 MUST 只执行一次工行借记卡完整解析，识别为 `icbc_debit` 并允许页面进入账户映射

#### Scenario: 零个或多个解析器匹配
- **WHEN** 没有解析器匹配，或多个解析器同时匹配同一份文件
- **THEN** 系统 MUST 返回 `import_channel_unrecognized`
- **AND** 系统 MUST NOT 执行任何候选解析器的完整解析

#### Scenario: 探测或解析遇到密码保护
- **WHEN** 账单 PDF 需要密码，或提供的密码无法解锁文件
- **THEN** 系统 MUST 返回对应的密码错误结果
- **AND** 系统 MUST NOT 为同一份文件继续执行其他候选解析器的完整解析
- **AND** 页面 MUST 清除扫描中的忙碌状态并保留重新选择或重试入口

#### Scenario: 唯一匹配后的正式解析失败
- **WHEN** 格式探测唯一匹配，但该解析器的完整解析失败
- **THEN** 系统 MUST 返回既有的可操作解析失败或来源账户识别错误
- **AND** 系统 MUST NOT 把失败转换为另一个候选解析器的完整解析尝试

#### Scenario: 工作簿表头探测不读取全部业务行

- **WHEN** 自动识别有效的微信或支付宝工作簿
- **THEN** 探测 MUST 只取得有界表头并完成候选判定，唯一匹配后才执行一次完整文档校验和解析
- **AND** 完整解析发现的损坏或超预算 MUST 作为该文件的解析失败，不触发其他渠道完整解析

#### Scenario: 多页 PDF 仅探测首页

- **WHEN** 工行 PDF 的首页已包含明确渠道标识，且文件还有后续页面
- **THEN** 格式探测 MUST 只处理有界首页内容，不能因探测阶段没有遍历后页而拒绝多页文件
- **AND** 后续完整解析仍校验全部页面及既有预算
