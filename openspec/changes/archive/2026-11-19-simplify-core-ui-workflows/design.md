## Context

三个客户端共用 Compose 页面、ViewModel 和账本本地读取。工作区管理和投资流水沿用现有页面结构。首次记账的账户创建沿用现有工作区账户命令。分类定位和已提交导入收据在 SQLite、PostgreSQL 上共用服务层。

## Goals / Non-Goals

保持原填写内容、权限边界和已保存结果。缩短首笔记账、批次导入后续和分类排序路径。投资持仓与认证找回流程在本次范围之外。

## Decisions

- 首次工作区名称使用当前登录邮箱的本地部分和界面语言模板。首次创建页面维护可空的已编辑值，空字符串表示主动清空。连接状态、响应式窗口或界面语言变化不覆盖已编辑值。已有成员工作区的选择与新建表单按既有默认值处理。异常过长的候选使用本地化“我的工作区”。

- 账户创建复用已有账户表单与幂等保存，通过同一个会话刷新账本账户并回填原表单。普通记账在账户和币种字段附近提供入口。
- 工作区管理在原成员行打开确认对话框。已创建的链接和角色共同保存在当前管理任务，建立中的请求保持互斥。邀请接受先确认登录邮箱，使用既有退出和登录机制保留邀请路线。
- 收据由实际保存后实际变动且属于待确认条目的来源流水标识派生范围。按当前条目成员重新定位，合并或拆分后仍可找到原流水。旧收据缺少范围时提供“查看待确认”。本批范围是当前账本筛选的一部分，和待确认状态一起应用于分页、条数和汇总。
- 确定保存后继续使用现有自动刷新，移除用户手动整理入口，并保留恢复材料直至账本更新。未确定的原确认保留原命令恢复语义。
- 分类操作复用现有同级排序端点和修订保护，以独立目标操作值扩展，按一个原子操作落库。旧服务明确拒绝新操作值，既有相邻操作保持兼容。
- 关系核对复用现有备选区域，隐藏无法提交的联合改选。筛选型空状态沿用现金账本已有的清除动作。

## UI 方向

Hallmark 预检沿用 FinanceTheme、现有 Material 3 控件及各屏已有的任务结构。主要动作靠近操作对象，原应用导航和页面结构保留。删除“继续整理结果”和不能完成的联合改选，避免重复进度文案。危险动作对话框只确认一个成员相关决定，普通角色调整沿用原操作。快捷筛选继续响应式换行，按含义分开表示状态与类型。无需改造页面信息架构。Compose 与 Git token 是当前事实源。

Material 3 的 Dialogs 对重要决定使用明确的取消和确认，Chips 区分选择状态，Text Fields 在字段附近表明可修正错误。分类目标在对话框内用 Radio Buttons 单选，避免在弹窗中再打开一层选择。沿用仓库已使用的 AlertDialog、FilterChip、OutlinedTextField 和按钮，无新增依赖或实验 API。

## Risks / Trade-offs

缺少本批稳定标识不能按日期、账户名或界面展示值推断。仅恢复有原收据的批次，读取不到本机提交证明时不在后台发送确认。排序目标须由服务端校验同一目录和父级，冲突按现有修订合同处理。权限确认期间如失去权限，禁止提交。恢复过程不能以重新写入整个账本代替旧收据的安全接续。

入口可独立撤回，已落库账户、目录顺序和账本保持有效。导入收据扩展保留原有字段和旧收据查询兼容性，无数据库结构迁移。旧客户端回滚后不能读取已被新客户端写入新字段的本机导入存档，应保留新版读取并完成开放批次后再回滚 Web 客户端。
