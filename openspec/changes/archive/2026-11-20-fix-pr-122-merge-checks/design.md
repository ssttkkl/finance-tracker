## 合并边界

PR #122 与 PR #123 同时修改了导入生命周期、账本页面、收据校验和浏览器测试。冲突处置以两侧合同同时成立为准：

- `CashWriteSetApi` 调用主规格中的共享回执校验，再执行 PR #122 新增的待确认条目与计数一致性检查。
- `CashLedgerScreen` 采用 `main` 的后台刷新错误与保留列表状态，PR #122 的导入待确认筛选及记账账户联动保持不变。
- `ImportTaskViewModelTest` 保留 PR #122 的后台恢复用例，同时采用 `main` 的收据指针恢复用例名与流程。
- 账本主规格同时保留后台索引和保存重试两项需求。

## 测试对齐

启动诊断在 `main` 已把不支持 Wasm 的兼容性分支从错误级降为普通记录，Sentry 事件仍保留；PR #122 分支上的旧断言不再成立，因此测试改为零 Console 错误。

管理目录在 390 宽度下需要先等待全屏弹层开场动画完成，再读取选中标记；随后用轮询而非单次截图比较，避免动画帧造成假失败。产品选择、高亮与无障碍语义未变。

## 风险

合并范围大，主要风险是自动合并处的语义组合。已用共享 Wasm 测试、后端全量命令、Android/iOS 编译及完整浏览器套件覆盖；回滚可恢复合并前分支并单独重做冲突处置。
