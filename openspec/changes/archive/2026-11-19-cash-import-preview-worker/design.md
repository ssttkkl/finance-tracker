## Context

现有预览由 `LedgerSessionCacheOwner` 固定文件、账本快照及核对上下文后调用共享领域计算。Compose Wasm 的默认调度器运行在页面事件循环。仓库已有同源 SQLite Worker，Web 生产构建发布同源静态文件。

## Goals / Non-Goals

在 Web 后台执行预览、关联扫描、写集生成和核对上下文冻结。原生与 JS 构建沿现有计算路径。文件解析、提交后的冲突恢复、持久化格式及 HTTP 合同不属于本次变更。

## Decisions

- 独立 Kotlin/Wasm executable 链接 `business-domain`。Gradle 将链接产物和模块 Worker 入口一起打包为 Web 资源。页面启动时预热一个 Worker，正常计算完成后可复用，失败或取消时终止。这样已打开的页面断网后仍可使用已加载的计算模块。Worker 版本目录按入口和链接产物内容生成指纹，浏览器可用已缓存的同版资源重建 Worker。稳定客户端入口沿用站点默认缓存策略。
- 页面传标准化文档、已有快照 DTO、选择和上次核对编码。返回预览 JSON、原写集 DTO、已冻结核对及保留类型的核对上下文。桥接使用 Kotlin JSON 文本，避免 JS 浮点化账务字段。任务仍由会话 owner 固定输入并校验发布资格。
- Worker 启动或执行故障复用已有错误呈现及“重新核对”入口，直接重试同一未发布预览及选择。因会话或账本变化导致的重新核对仍走原有刷新逻辑。交互、控件、布局和文案沿用现有实现，信息结构无需删改。领域拒绝保留原错误码和诊断。恢复提交、存储和网络仍由原客户端负责。
- 端侧离线核对仍须可用。验证静态 Worker 资源加载和离线阶段请求，区分 API 断开与静态文件不可达。

## Risks / Trade-offs

跨线程传输、批次读取和结果消费仍可能制造页面长任务。使用合成大账单检查浏览器线程归属、结果一致性和页面帧回调。生产打包须一起发布配套资源。回滚恢复原计算调用。
