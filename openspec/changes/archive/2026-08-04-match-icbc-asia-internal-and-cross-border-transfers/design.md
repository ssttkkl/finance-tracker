## Context

见 `proposal.md`。现有 Phase C 以同币种、等额、不同正式账户构建普通转账候选；个人购汇则只处理同来源 `fx_out` / `fx_in`。工银亚洲币种子账号归并后，业务行中的原始对方账号仍可证明其属于同一规范账号，但目前没有专门路径使用该证据。

## Goals / Non-Goals

**Goals:**

- 用有界候选索引识别两种已验证的工银亚洲资金移动。
- 保持 SQLite 与 PostgreSQL 的关系、待配对和投影语义等价。
- 仅以别名、正式记录类型、来源语义、精确金额及时间判断，不写入账号或过程证据。

**Non-Goals:**

- 不变更账户路由、来源行、关系表或账户别名数据；仅纠正工行借记卡“跨境汇款”的导入分类。
- 不将任何跨币种相反方向流水泛化为换汇，也不调用市场汇率猜测跨境汇款。
- 不重写已存在关系；本次仅为后续关系检查提供新候选。

## Decisions

### 以独立的工银亚洲桥接匹配器处理例外形态

在 Phase C 中新增专门规则，而非放宽通用 `transfer_candidates()`。工银亚洲内部调拨需要允许同一正式账户；工行跨境汇款已规范为 `transfer_out`，但仍需来源语义和账户标识限定桥接到工银亚洲入账的范围。这两种豁免若进入通用规则会扩大所有来源的误配面。

候选仍按日期桶建立索引，之后执行严格的来源、方向、账户归属、币种、金额和时间过滤。没有全库双重扫描。

### 以双向最近且唯一决定自动确认

工行跨境汇款的宽窗口为 36 小时，但若同一金额在窗口内重复出现，仅凭先遍历的种子会选错。匹配器将候选按时间距离排序，只有出账和入账彼此唯一最近时才自动确认；10 秒内的唯一候选优先。其余候选保留为以出账为锚点的待配对关系。

工银亚洲内部调拨使用 5 分钟窗口，同样要求双向唯一；异币种写 `currency_exchange`，同币种保持空 subtype 且金额必须精确相等。

### 工行规范账号前缀只在桥接器启用

账户标识通用匹配保持现有精确和尾号语义。只有工行 `transfer_out` 已通过“跨境汇款”来源闸门并进入新桥接器时，才把 `icbc_debit` 的完整目标账号按工银亚洲末位币种位归属。这样不会扩大工行普通转账的账号前缀匹配范围。

## Risks / Trade-offs

- [工银亚洲账单对方账号缺失或掩码] → 不进入自动确认；不会根据账户名称猜测。
- [同金额跨境汇款密集发生] → 使用双向最近唯一性；仍不唯一时生成一条待配对关系。
- [来源分类含义不准确] → 仅接受已分类为 `transfer_out` 且原始来源语义明确为跨境汇款的工行出账；真正购汇保持 `fx_out` 并由拒绝路径覆盖。
- [已确认关系占用端点] → 复用现有 Phase C 的端点占用检查，避免重复关系。

## Migration Plan

无需 schema 或数据迁移。发布后通过显式关系检查发现新关系；回滚仅移除规则并将其系统生成关系标记为 `superseded`，不删除任何账本记录。
