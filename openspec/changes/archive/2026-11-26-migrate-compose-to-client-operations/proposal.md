## Why

Compose 和账本 CLI 已共用部分账本规则，但账户变更、现金写入和导入恢复仍有独立的生产编排。两个入口需要直接执行同一有类型的客户端操作，以便权限、修订、幂等及恢复规则只维护一处。

## What Changes

- 迁移一期中 Compose 与 `ft` 都有入口的操作。按页面、Graph、仓储适配器、命令和公共 Kotlin 操作追踪生产路径。
- 由宿主提供会话触发、传输、凭据、加密存储、文件、Worker 与呈现。共同操作统一业务校验、写入及恢复，保持工作区绑定和现有平台行为。
- 用真实页面和已安装的 npm 包验证生产调用链及业务结果。在操作矩阵登记仅有单端入口的项目及理由。

投资、内置 AI 和新增产品入口不在本次范围。服务端账本仍是财务事实来源。

## Capabilities

### Modified Capabilities

- `shared/client-operations` 为 Compose 和 CLI 的共同业务动作提供同一生产操作入口。

## Impact

A 类变更。涉及 Compose Web、Android、iOS、CLI 和共享客户端层，覆盖会话、账户、收支与导入的权限和恢复。保持既有服务端事务、持久数据与公开 HTTP 合同。以 `d07d8a43` 为实施基线，随 PR #126 交付。
