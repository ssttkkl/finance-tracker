## Context

`bill-export` 是交互式文件导出 Skill，不是账单解析器。微信支付和支付宝都有敏感认证及异步文件生成，但业务入口和文件获取路径不同；设备控制技术可以跨渠道复用。

## Design

采用三层结构：

1. **统一入口**：识别渠道、选择后端，维护通用状态、安全边界、多渠道隔离和交付口径。
2. **渠道流程**：完整描述应用内业务入口、控件顺序、参数映射、认证节点、消息或申请记录、下载保存和恢复规则。
3. **控制后端**：只描述如何通过特定技术观察和操作设备，包括点击、滚动、按键、重连、认证交接和通用系统保存，不包含渠道业务路径。

当前渠道为 `wechat.md` 和 `alipay.md`；当前后端为 `computer-use-iphone-mirroring.md`。未来 Android + ADB 增加独立控制后端，未来其他支付平台增加独立渠道流程。

## Decisions and Alternatives

1. **按渠道路由而非独立 Skill。** 统一状态与安全边界，同时保留渠道差异。
2. **业务点击路径属于渠道流程。** 页面入口和按钮顺序表达支付平台业务，不属于 Computer Use 技术能力。
3. **控制后端跨渠道复用。** 同一 iPhone 镜像控制规则不应在微信和支付宝文件中重复。
4. **不预建 Android 文件。** 当前没有经过验证的 Android + ADB 实现，只定义扩展边界。

## Risks and Rollback

- 渠道页面变化可能使流程过时：只更新对应渠道文件。
- Computer Use API 或镜像行为变化：只更新控制后端文件。
- 多渠道状态串线：主 Skill 要求分别记录参数、申请记录和文件证据。
- 回滚可恢复原 `alipay-bill` 目录和文档；不涉及数据库或运行时数据。
