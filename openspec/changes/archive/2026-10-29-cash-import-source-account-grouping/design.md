## Context

现有账单导入会话、来源绑定及 Compose 准备页已经运行。此次收敛三条边界：微信交易身份由固定内部范围和非空交易单号决定；昵称和支付宝账号只用于当前会话分组；资金账户组仍独立呈现，用户可选择是否让不同渠道的同名来源组共享账本目标选择。行为要求见本 change 的四份 delta spec。

## Goals / Non-Goals

**Goals:**

- 让服务端跨文件微信识别不依赖昵称或用户填写的来源名称，同时避免从未绑定记录猜测身份。
- 在单次会话中按渠道与账号形成可辨认分组，并让每个来源资金组保留独立引用。
- 允许用户控制跨渠道同名来源资金组是否共享目标账户选择；选择结果仍提交给每个原始来源组。
- 让密码重传按钮的文字、方向图标和可测试语义清楚一致。

**Non-Goals:**

- 不新增微信跨导入账户映射，也不把昵称作为账号永久标识。
- 不为未上线的用户可配置微信来源名称增加旧字段兼容读取或数据迁移。
- 不合并来源账号组、账本账户、流水或资金数据；本 change 的开关只协调本次选择。
- 不改造导入的其他状态、关系处理或金额计算规则。

## Decisions

### 固定微信来源身份，去掉未使用的兼容通道

上传、重传、文件更新和会话 API 不再传递 `source_scope_label`；后端继续使用内部固定 `source_scope_key`。微信解析要求非空交易单号，可靠绑定按工作区、微信渠道和交易号跨账号匹配。存储读取只接受当前可靠绑定，不再从旧 `record_id` 格式、来源行、时间、金额或文件位置恢复未绑定微信记录。

替代方案是把昵称或手工来源名加到匹配范围。这会让昵称变化导致同一交易重复写入，也与交易号跨账号唯一的产品事实冲突。读取旧未绑定记录也被排除：产品尚未上线，没有需要保留的可配置范围数据；猜测匹配会引入不可审计的财务合并。

### 会话组引用和显示标签彼此分离

解析阶段为微信昵称组和支付宝来源账号组生成当前会话引用及显示标签，不将临时组引用或脱敏标签写进来源绑定或账户映射。相同微信昵称的文件可汇入同组；没有昵称时按文件区分。支付宝按现有可信来源账号身份归组并只返回脱敏标签；身份不足时按文件区分。组内仍按资金方式保留各自的 `source_account_ref`；支付宝等渠道已有的可信长期来源映射规则不变。

替代方案是直接以昵称、账号文本或资金方式作为长期组 ID；这些值可变、敏感或不足以区分账号，因此仅用短期会话引用传输。

### 合并开关只作用于目标选择簇

Compose UI 状态的 `mergeSameNameAcrossChannels` 默认 `true`，不增加后端会话字段。开启时，只有显示名称相同、渠道不同且每个渠道只有一个同名候选的来源资金组才组成选择簇；相同选择写回簇内每个原始来源引用。发现已有选择不一致时，不推断用户意图并清空该簇选择。关闭时每个来源组独立选择。页面按来源账号分别显示分组，开关不把它们视觉合并。

替代方案是由后端直接合并分组或自动沿用其中一个账户选择；这会丢失来源账号上下文，或静默扩大财务决定范围。将选择保留到所有原始来源引用则能保持服务端账户映射合同。

### 使用 Material 3 文字层级和按钮图标

账号分组标题使用 `titleMedium`，资金方式名称使用 `titleSmall`，辅助行信息用 `bodySmall`，合并开关说明用 `bodyLarge`；沿用 Compose 现有 Material 3 组件和 token。密码重传使用向右箭头图标加“提交”文字，图标位于文字左侧，并在原文件级重试语义入口下设置稳定测试标识。

不另建文字 token 或自定义按钮包装；Material 3 Typography 和标准 `TextButton` 已覆盖当前层级与交互。

## Risks / Trade-offs

- **跨渠道同名来源组可能对应不同真实账户** → 开关显式展示且默认开启符合产品选择；用户可关闭。来源账号组仍分别可见，选择冲突时清空。
- **昵称或支付宝账号识别变化会改变本次分组** → 只改变本次选择步骤，不改变持久身份、既有流水或后续导入；无法识别时按文件隔离。
- **微信非空交易号成为严格解析条件** → 解析器在生成任何文件位置身份前拒绝缺号行；测试覆盖缺号输入。

## Migration Plan

无需 schema migration。产品尚未上线，删除的请求字段、来源设置命令和未绑定旧记录读取路径不保留兼容。部署或发布需成套使用匹配的后端协议与 Compose 客户端；若回滚则一并回退该 API 和客户端版本，不执行数据回填。

## Open Questions

无。来源分组、同名冲突、缺少昵称和旧记录读取边界均已确认。
