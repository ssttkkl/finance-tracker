# 修正支付宝交易单号测试夹具

## 缺陷

支付宝导入已要求每条业务行提供有效交易订单号。部分通用导入测试仍以缺少交易号的支付宝夹具测试弱身份、重复行和导入会话行为，因此 PR #104 的普通后端分片会在解析或暂存阶段失败。

## 预期

测试数据遵守各来源的流水号合同。测试确实需要无流水号来源行时，使用允许该场景的银行账单夹具；测试使用支付宝账单时提供有效且不冲突的交易订单号。生产校验保持不变。

## 范围

- 更新普通后端测试中的无交易号通用夹具和支付宝来源文档夹具。
- 保留这些测试原本覆盖的来源识别、会话恢复、重复处理和候选保存行为。
- 适配最新 `main` 的功能地图目录调整，将已有支付宝流水号规则保留在导入模块地图中。
- 不修改生产导入逻辑、支付宝身份规则或性能测试。

## 能力与影响

本次没有新增或修改产品能力；支付宝交易订单号合同已写入现有导入主规格。改动调整非性能测试数据并迁移已有规则的文档位置，不影响 API、运行时行为或数据库。

## 验收

- PR #104 的全部非性能后端检查通过。
- 涉及 SQLite 与 PostgreSQL 合同夹具的受影响测试通过。
- 性能检查不纳入本次验收。

回滚时恢复本次测试夹具即可，不涉及数据迁移或运行时回滚。
