## Context

见 `proposal.md`。当前现金流水只有 `record_type`，而现有转账关系匹配器通过导入渠道、来源文本和账户类型实现工银亚洲内部调拨与工行跨境汇款例外。`counterparty_account` 也仍含各来源原始展示形式，令别名匹配需要理解来源特例。

## Goals / Non-Goals

**Goals:**

- 将来源专用语义和工银亚洲账号归一收敛到导入边界。
- 用一个受约束的 `record_subtype` 表达配对所需的资金移动语义。
- 使关系扫描只读取结构化事实字段和显式账户别名，保持候选有界、幂等和双后端等价。
- 保留现有关系表结构和待配对候选载体，不新增仅作审计用途的列。

**Non-Goals:**

- 不凭汇率或金额容差猜测跨币种关系，不把跨境汇款导入成换汇。
- 不修改来源行快照，不从名称或备注猜测账号，不增加关系审计字段或独立候选表。
- 不为旧数据库读路径保留兼容分支；目标库由迁移或重建得到完整新模型。

## Decisions

### 以 `record_type + record_subtype` 表达导入语义

`record_type` 保持方向和一级业务类别，`record_subtype` 只补充关系匹配必须区分的资金移动语义。选择一列而非 `transfer_kind`，因为子类型同样需要表达换汇、还款和提现，避免把分类拆成两个会失真的维度。`not_applicable` 为显式值，禁止空字符串作为语义缺失占位。

### 规范化发生在导入器，原文只留在来源快照

导入器仅移除完整账号的格式字符，不把工银亚洲币种子账号改写为主账号。对于工银亚洲账单中的掩码对方账号，只有掩码前缀、掩码长度、尾号和当前账单账户严格吻合时，才还原完整对方账号；原始掩码只保留在来源行快照。工银亚洲主账户路由尾号维持 `4240`，而 `4240` 至 `4247` 作为同一账户的显式别名参与关系匹配。

### 关系扫描按子类型分池

普通转账维持短时间窗口、不同账户、同币种与严格等额。只有对方账号通过完整账号或唯一尾号别名定位目标账户，转出才进入 7 天候选池；同币种严格等额，跨币种不比较金额。关系层先收集全部合法边，再按时间差、转出 ID、入账 ID 稳定排序，以双方未占用为条件全局一对一分配。目标等于转出账户的跨币种关系为 `currency_exchange`；不同账户且转出为 `cross_border_remittance` 的跨币种关系为 `cross_currency_remittance`。别名冲突、缺失或不符合类型/金额/币种约束时不生成宽窗口候选。

### 数据迁移和回滚

新增 `record_subtype` 的迁移以保守映射回填既有 `record_type`：换汇、还款和提现具有确定映射；既有 `transfer_in/out` 仅回填 `ordinary_transfer`。旧正式字段无法可靠重建为工银亚洲规范账号时保留原值，不伪造来源快照。发布后需要重新导入才能获得来源专用子类型和完整规范值。回滚通过恢复上一版本并将新增系统关系标为 `superseded`；不删除现金事实或来源快照。

## Risks / Trade-offs

- [账户别名未登记或冲突] → 不会自动确认，只保留既有非账号约束候选或待配对关系。
- [跨币种汇款慢到账] → 只有对方账号唯一定位目标账户时，才在 7 天内按全局最近的一对一规则自动确认；无唯一目标或别名冲突时不放宽普通转账。
- [旧数据缺少来源细节] → 只做确定性子类型回填；用户需重建或重新导入以得到完整归一。
- [SQLite 与 PostgreSQL 约束语法差异] → 在 Alembic 和 ORM 中使用等价检查约束，并运行同一应用服务的真实 PostgreSQL 契约。

## Migration Plan

1. 添加模型、Alembic 迁移、仓库读写与显式合法组合检查。
2. 先回填确定性历史子类型，再把列设为非空和目标约束。
3. 发布后可选择重建账本并重新导入，使来源专用子类型和规范账号完整生效。
4. 回滚时保留列和事实，停止新规则并将其产生的系统关系标记为 `superseded`；不得回写来源快照。
