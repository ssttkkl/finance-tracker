## Why

收支导入处理页面在预览与确认时重复运行配对器。即使使用者没有改变账单或账户映射，第二次规划也可能因当前工作区的关系上下文变化而产生不同建议，并把本应可恢复的业务状态呈现为“配对建议已经变化，请重新预览账单”的技术性失败。

## What Changes

- 导入预览在导入会话中保存一份服务端拥有的**预览配对计划**，包含稳定流水引用、建议、候选范围和关系上下文摘要。
- 确认导入在同一事务内仅校验该计划所依赖的关系上下文；校验通过时直接把缓存计划映射到已落库流水并应用，不再重新运行配对规则。
- 关系上下文不再适用时，系统不得写入账单、账户映射、关系或投影；API 返回结构化的“重新确认配对”结果，页面刷新配对建议并回到配对步骤。
- 确认请求必须验证每个使用者决定确实引用缓存建议及其合法对侧，不能仅凭建议键接受不属于该建议的对侧流水。
- 移除 Web 正常流程中以 `import_relation_preview_stale`、`import_relation_candidate_invalid` 引导使用者重新预览账单的出口，替换为可恢复的重新确认配对合同。
- 导入成功后，步骤导航回到“选择文件”必须丢弃已完成导入会话；下一次导入从新会话开始，不能将完成令牌送回预览接口。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `statement-import`：导入会话确认使用预览配对计划并在关系上下文变化时保持零写入。
- `transaction-relations`：缓存计划的端点、候选和使用者决定必须在应用前保持可验证且可审计。
- `cash-ledger-browser`：导入处理页面收到重新确认配对结果时，自动回到配对步骤而非展示不可操作的错误。

## Impact

- 受影响的后端包括导入会话、现金导入编排、关系计划应用和 HTTP 错误合同；不新增账本表或迁移。
- 受影响的前端包括现金导入 API 类型、四步导入页面的错误恢复状态和完成后重新开始导入的会话重置。
- CLI 仍在一次命令执行中规划并导入，不获得导入会话缓存，也不改变其参数或输出合同。
- 回滚只需恢复导入会话缓存及重新确认分支；缓存不作为账本事实持久化，已导入账本和关系无需数据回迁。
