## Purpose

定义投资事件的来源无关经济事实类型、资产方向、费用、本位资产、成本和持仓重放合同，使不同券商与连接器输入能够按同一精确、确定且可审计的模型保存和重建。

## ADDED Requirements

### Requirement: 投资事件使用来源无关的记录类型
投资事件 MUST 使用规范 `record_type` 和 `record_subtype` 表达 `funding(external|subaccount)`、`trade(security|fx|repo)`、`income`、`expense`、`reversal`、`subscription`、`adjustment` 与 `snapshot` 等经济事实。来源原生动作必须单独保留为溯源证据，不得成为正式记录类型。

#### Scenario: 外部资金进入投资账户
- **WHEN** 来源业务表示现金从收支账户进入投资账户
- **THEN** 投资事件 MUST 分类为 `funding(external)`，方向由现金部分位于换入资产一侧表达

#### Scenario: 投资账户内部调拨
- **WHEN** 资金只在同一投资机构或其子账户之间移动
- **THEN** 投资事件 MUST 分类为 `funding(subaccount)`，不得作为现金—投资资金调拨候选

### Requirement: 交易方向由付出资产和换入资产表达
`trade` MUST 通过付出资产与换入资产以及各自精确数量表达交易方向，不得再依赖 BUY、SELL 或来源动作推断方向。资产数量必须为有限十进制值，且一笔交易不得同时缺少两侧资产。

#### Scenario: 买入证券
- **WHEN** 一笔交易付出现金并换入证券
- **THEN** 投资事件 MUST 把现金保存为付出资产、证券保存为换入资产，并保持来源精确数量

#### Scenario: 卖出证券
- **WHEN** 一笔交易付出证券并换入现金
- **THEN** 投资事件 MUST 把证券保存为付出资产、现金保存为换入资产，不得通过负数量模拟卖出

### Requirement: 交易费用不改变来源净现金
可直接识别且能从来源净额安全拆分的交易总费用 MUST 保存为非负 `commission` 和明确 `commission_asset`。买入时现金部分加费用、卖出时现金部分减费用必须等于来源净现金绝对值；无法安全拆分时必须保留净现金并使用零费用，不得发明金额。

#### Scenario: 买入费用可安全拆分
- **WHEN** 来源买入净现金为 `-1011.53`，且明确列出总费用 `11.53`
- **THEN** 事件 MUST 保存现金部分 `1000.00`、费用 `11.53` 及费用币种，最终现金流出仍为 `1011.53`

#### Scenario: 费用字段矛盾
- **WHEN** 来源费用为负数、缺失或大于等于可拆分的买入净额
- **THEN** 系统 MUST 保留来源净现金、设置 `commission=0`，且不得拼造费用

### Requirement: 本位资产不维护成本基础
投资账户配置的本位资产 MUST 只维护数量，不维护成本基础。本位资产之间兑换只改变各自数量；非本位资产必须继续累计或释放精确成本，并记录成本币种。

#### Scenario: 存入本位现金
- **WHEN** USD 是账户本位资产且发生 USD 资金供给
- **THEN** 持仓重放 MUST 更新 USD 数量，但不生成 USD 成本基础

#### Scenario: 买入非本位资产
- **WHEN** 账户使用本位现金换入非本位证券
- **THEN** 持仓重放 MUST 为该证券累计精确成本和成本币种

### Requirement: 投资事件重放保持确定和完整
在相同有序投资事件输入下，持仓数量、成本和现金余额 MUST 可确定性重建。非法币种组合、非有限数值、成本币种冲突或缺少必需资产方向必须在提交前失败，且 PostgreSQL 与 SQLite 的结果必须等价。

#### Scenario: 重放同一事件序列
- **WHEN** 在两个正式后端按相同顺序重放同一组投资事件
- **THEN** 每个账户和标的的数量、成本、现金余额及错误结果 MUST 等价
