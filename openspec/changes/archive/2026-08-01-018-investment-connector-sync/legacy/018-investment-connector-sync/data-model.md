# Data Model: 投资连接器同步

**Feature**: `018-investment-connector-sync` | **Date**: 2026-07-26

## 新增实体

### SyncCursor

增量同步游标——记录每个 `(workspace, account, source_type)` 组合的同步断点。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | SurrogatePK | PK, auto | BIGINT(PG) / INTEGER(SQLite) |
| `workspace_id` | String(64) | FK → workspaces, NOT NULL | 所属工作空间 |
| `account_id` | BigInteger / Integer | FK → accounts.id, NOT NULL | 关联账户 |
| `source_type` | String(64) | NOT NULL | connector 标识（`binance_api`, `kraken_api`, `polymarket_api` 等） |
| `cursor_value` | String(256) | NOT NULL | 游标值（毫秒时间戳或 offset 的字符串表示） |
| `updated_at` | UTCDateTime | NOT NULL | 最后更新时间 |

**唯一约束**: `UNIQUE(workspace_id, account_id, source_type)`

**索引**: 唯一约束自带索引，无需额外索引。

**生命周期**:
- 首次同步成功后 INSERT
- 后续同步成功后 UPSERT（`ON CONFLICT ... DO UPDATE`）
- 用户可通过 `--full` 参数忽略游标（不删除，仅跳过读取）
- 账户删除时级联删除（FK ON DELETE CASCADE）

### ConnectorPort（领域接口，非持久化）

```python
@runtime_checkable
class ConnectorPort(Protocol):
    """领域层 connector 接口。"""

    @property
    def source_type(self) -> str:
        """返回此 connector 的 source_type 标识。"""
        ...

    def fetch_trades(
        self,
        *,
        since: str | None = None,
    ) -> ConnectorResult:
        """从外部数据源拉取交易列表。

        Parameters
        ----------
        since:
            增量游标值（上次同步的断点）。None 表示全量。

        Returns
        -------
        ConnectorResult:
            包含交易事件列表和下次游标的结果对象。
        """
        ...
```

### ConnectorResult（值对象，非持久化）

```python
@dataclass(frozen=True)
class ConnectorResult:
    events: list[dict]       # 标准化交易与 ledger 投资事件 dict 列表
    next_cursor: str | None  # 下次同步的游标值；None 表示已拉取完毕
    raw_count: int           # API 返回的原始记录总数（trade + ledger；含由 trade 覆盖的 ledger trade 分录）
```

### ConnectorError（异常类型）

```python
class ConnectorError(Exception):
    """Connector 可恢复错误（网络/限流重试耗尽后）。"""

class ConnectorAuthError(ConnectorError):
    """凭据无效（401/403）。"""

class ConnectorDataError(ConnectorError):
    """数据异常（缺少必要字段、格式错误）。"""
```

## 复用实体（无修改）

### InvestmentEvent（已有表 `investment_events`）

新增的 `source_type` 值：
- `binance_api` — Binance 交易所 API 同步
- `kraken_api` — Kraken 交易所 API 同步
- `okx_api` — OKX 交易所 API 同步
- `polymarket_api` — Polymarket Activity API 同步

命名规则：`<provider>_api`（与文件导入的 `<provider>_csv`/`<provider>_pdf` 区分）。

`record_id` 语义：
- 交易所 trade：ccxt trade `id` 字符串化
- 交易所 ledger 主事件：ledger entry `id` 字符串化
- 交易所 ledger fee：`<ledger_id>:fee`
- Polymarket `TRADE`：Activity API 返回的 `id` 字段（或 `transactionHash` 作为 fallback）
- Polymarket `REDEEM` / `YIELD`：`transactionHash`；当前 API 数据中每条此类活动对应唯一哈希，缺失时 fail-closed
- Polymarket pUSD 现金校准：`checkin:<block_number>`；同一确认 block 重跑幂等，后续 block 的 checkin 使用替换语义更新 USD 现金

`source_payload` 语义：
- 交易所：完整 ccxt trade 或 ledger dict 的 JSON
- Polymarket：完整 activity dict 的 JSON
- Polymarket pUSD checkin：`token`、`wallet`、`balance_base_units`、`block_number` 与 `block_timestamp`；以该 block 的 `balanceOf` 为唯一现金校准来源

### Account（已有表 `accounts`）

connector 同步对账户类型的验证要求：
- 交易所 sync → `account.type == "crypto"`
- Polymarket sync → `account.type in {"security", "crypto"}`

### Snapshot（已有表 `investment_snapshots`）

同步的事件通过 `apply_investment_event` 投影到快照，与文件导入完全相同。

Polymarket 活动映射：
- `TRADE`：既有双向 `swap`。
- `REDEEM`：`swap(from=pm:<slug>:<outcome>, to=usd)`。
- `YIELD`：USD `dividend`；不创建或修改结果仓位。

交易所 ledger 活动映射：
- `deposit` / `withdrawal` / `staking`、`reward`、`credit`、`rollover` 按其 currency/amount 映射为对应 action。
- `transfer` / `derivativescrossexchangetransfer` 映射为 `transfer` 审计事件，保存方向、金额和 reference ID；投影不改变同一账户快照。
- 有非零 fee 的非 trade ledger entry 另生成 `fee` 事件；不可解析 fee 绝不改写为零。

## 状态转换

### Sync 命令执行流程

```
[Start]
  │
  ▼
[Load Credentials] ──(missing/invalid)──► [Error: 报告缺失字段 + 示例]
  │
  ▼
[Validate Account] ──(not found/type mismatch)──► [Error: 账户不存在或类型不匹配]
  │
  ▼
[Read SyncCursor] ──(--full 或无游标)──► since=None
  │                  (有游标)──────────► since=cursor_value
  ▼
[Connector.fetch_trades(since=...)]
  │ ──(ConnectorAuthError)──► [Error: 凭据无效]
  │ ──(ConnectorError after retries)──► [Error: 网络/限流失败]
  │
  ▼
[Split into processing chunks (≤500)]
  │
  ▼ (all chunks, one UnitOfWork transaction)
[UnitOfWork Transaction]
  ├── Idempotency check (existing_fact_targets)
  ├── Map events → investment_events
  ├── apply_investment_event → snapshot
  ├── validate_investment_snapshot
  │     ──(invalid)──► [Rollback all chunks, Error]
  ├── UPSERT SyncCursor
  └── Commit once
  │
  ▼
[Report: N new, M skipped, K batches]
```

## PostgreSQL / SQLite 差异

| 维度 | PostgreSQL | SQLite | 等价性 |
|------|-----------|--------|--------|
| `sync_cursors.id` | `BIGINT GENERATED BY DEFAULT` | `INTEGER PRIMARY KEY` | `SurrogatePK` 类型 |
| `sync_cursors.updated_at` | `TIMESTAMP WITH TIME ZONE` | `TEXT` (ISO format) | `UTCDateTime` 类型 |
| UPSERT | `INSERT ... ON CONFLICT ... DO UPDATE` | 同语法 | SQLAlchemy `insert().on_conflict_do_update()` |
| 事务隔离 | SERIALIZABLE | WAL + BEGIN IMMEDIATE | 允许差异 |
| 并发 sync | 行锁保护 | 文件锁串行 | 允许差异 |
