## MODIFIED Requirements

### Requirement: 收支账本展示关系处理后的投影

系统 MUST 让每条活动现金流水恰好归属一个当前投影；没有已确认关系的正式流水独立显示，同笔支付只展示一次，退款抵扣原消费，部分退款和部分平台退回只抵扣剩余金额。列表、分析及金额汇总 MUST 使用当前投影；内部转账显示但不计入外部收入、支出和月度汇总。全额退款及全额平台退回 MUST 在导入预览展示净额 0；收支账本保留该投影和详情证据，但是否出现在列表由“隐藏0元流水”筛选决定，关闭该筛选时必须可见，且不另算退款收入；余额校准的既有业务隐藏规则保留。主页默认展示正式及草稿，并在每项显示已确认或待确认；确认状态由草稿、当前问题及未确认关系派生，不能独立编辑。草稿排除全部统计；未确认关系不合并，正式端点分别统计。其他业务隐藏项有活动待处理事项时优先展示，不越过权限、工作区、逻辑删除及显式筛选边界。列表及其成员、关系、选项、待确认计数和金额汇总 MUST 使用同一读取快照；每项返回该快照的发布版本。分页 MUST 使用稳定排序位置及投影标识，未知日期不伪造为发生日期，发布版本变化要求重载。API MUST 只为当前已登录成员的选定工作区返回投影。

#### Scenario: 浏览同笔支付

- **WHEN** 两条正式现金流水通过已确认 `payment_mirror` 表示同一笔消费
- **THEN** 收支账本 MUST 只显示一个消费结果，并在详情中保留相关记录

#### Scenario: 浏览银证转账

- **WHEN** 当前结果对应已确认现金—投资资金调拨关系
- **THEN** 列表和详情 MUST 显示银证转账及现金与投资账户两端金额，不计入外部收支

#### Scenario: 浏览已确认平台退回

- **WHEN** 平台退回与原始出账通过已确认 `refund_offset` 形成全额冲销
- **THEN** 预览 MUST 展示净额 0 的一项；收支账本保留净额 0 的投影和两条关联流水及来源证据，是否显示该行由“隐藏0元流水”筛选决定，且不把退回另算收入

#### Scenario: 待确认回主页

- **WHEN** 导入保存草稿和未确认关系后返回主页
- **THEN** 用户可以找到并打开相关项补充，无独立关系管理产品

#### Scenario: 全额退款按筛选展示

- **WHEN** 消费被已确认退款全额抵扣
- **THEN** 预览 MUST 展示净额 0；收支账本 MUST 保留该净额 0 项，筛选开启时默认隐藏、筛选关闭时显示；没有当前问题时为已确认，有问题时为待确认，解决后状态随当前问题更新；用户明确的金额、日期和状态筛选仍生效

#### Scenario: 旧显示结果升级

- **WHEN** 升级前当前全额退款结果被标为隐藏
- **THEN** 系统 MUST 更新相关派生显示标志及发布版本，旧游标失效，原始流水、关系、净额和统计资格保持原值，其他业务隐藏规则不变

#### Scenario: 未知日期草稿翻页

- **WHEN** 草稿没有发生日期且与其他草稿创建时间相同
- **THEN** 发生日期仍为空，按创建时间及投影标识稳定翻页，不遗漏或重复；用户明确的日期筛选仍排除未知日期

#### Scenario: 翻页期间账本变化

- **WHEN** 客户端使用旧发布版本的游标翻页
- **THEN** 返回 `409 read_snapshot_changed`，不能混合新旧流水及成员

### Requirement: Compose 账本消费当前状态和同一读取快照

Compose MUST 使用当前列表协议的正式／草稿状态、确认状态、可空时间金额、统计资格及待确认计数，按当前筛选范围显示服务端数量；只有数量大于零时提供“待确认 N”。用户切换该快捷项 MUST 保留其他筛选。列表沿用已有紧凑表格／移动列表，显示已确认／待确认；未知不替换为零或虚构日期。金额汇总使用服务端结果，不对混合列表自行求和。

#### Scenario: 过滤待确认

- **WHEN** 当前其他筛选下有待确认项
- **THEN** 提供带数量快捷筛选，点击后只切换确认状态；没有待确认项时隐藏入口

#### Scenario: 草稿和零金额退款

- **WHEN** 默认列表包含缺日期金额草稿和已确认全额退款，且“隐藏0元流水”处于开启状态
- **THEN** 草稿显示已知信息并标待确认；全额退款投影和详情证据保留，但该零金额流水默认从列表隐藏，统计沿用服务端口径

#### Scenario: 翻页期间版本变化

- **WHEN** 后端返回 `read_snapshot_changed`
- **THEN** 重新加载当前筛选的列表，不拼接不同版本；批量选择不得静默作用于变化后的另一组记录

#### Scenario: 草稿与未知日期保持连续滚动位置

- **WHEN** 当前筛选同时包含正式流水、草稿和缺少发生时间的流水
- **THEN** 索引总数及连续月份区间 MUST 覆盖全部匹配流水，缺少时间的区间沿用 `unknown`
- **AND** 月金额 MUST 只统计具统计资格的流水，待确认数与当前页大小无关
- **AND** 索引版本变化 MUST 清空旧批量选择并重新读取，不自动重放写入

## ADDED Requirements

### Requirement: 收支账本可隐藏零元结果并按空间排列快捷筛选

收支账本 MUST 提供“隐藏0元流水”筛选，默认开启。用户打开新账本或重置筛选时该项 MUST 恢复开启；用户在本次打开期间的选择可以改变结果，但不得记忆到下次打开。筛选依据每行最终展示金额与十进制 0 精确相等；净额为 0 的正式流水（包括全额退款及全额平台退回）和金额已知为 0 的草稿 MUST 被隐藏，金额未知的草稿 MUST 保留。启用时零元项目不得进入列表、总数、月份汇总或待确认数量；停用时按既有规则返回。分页游标 MUST 绑定该筛选值。快捷筛选 MUST 按可用空间自动换行，顺序为“待确认”、分割线、“全部”、支出、收入、转账；“待确认”、分割线和“全部” MUST 作为一个不可拆分组合。“筛选”操作 MUST 固定在快捷筛选区域右侧，并相对该区域整体垂直居中。空间足够时所有快捷项自然排列在一行；任何尺寸均不得横向滚动。

#### Scenario: 新开账本与重置筛选

- **WHEN** 用户首次打开收支账本或执行重置筛选
- **THEN** “隐藏0元流水” MUST 处于开启状态，且该默认值不得持久化到下次打开

#### Scenario: 隐藏已知零金额并保留未知草稿

- **WHEN** 当前结果包含最终净额为 0 的正式全额退款、金额为 0 的草稿和金额未知的草稿，且“隐藏0元流水”已开启
- **THEN** 前两项 MUST 从列表与相关计数、汇总中排除，金额未知的草稿 MUST 仍可查看

#### Scenario: 查看全额退款

- **WHEN** 用户关闭“隐藏0元流水”
- **THEN** 全额退款 MUST 作为净额为 0 的一项显示，详情仍保留关联流水与来源证据

#### Scenario: 待确认数量随筛选变化

- **WHEN** 待确认结果中包含已知零金额项目，且“隐藏0元流水”开启
- **THEN** 列表总数和待确认数量 MUST 均按排除零金额项目后的结果计算

#### Scenario: 游标跟随筛选值

- **WHEN** 用户改变“隐藏0元流水”后继续读取列表
- **THEN** 新查询 MUST 使用新的筛选条件和匹配的游标，不得混入先前筛选结果

#### Scenario: 快捷筛选按空间换行

- **WHEN** 用户在收支账本查看快捷筛选，且可用宽度不足以容纳全部选项
- **THEN** “待确认”、分割线和“全部” MUST 留在同一组合；支出、收入、转账 MUST 在左侧可用空间内自动换行；“筛选” MUST 固定在区域最右侧并相对所有换行整体垂直居中；页面 MUST 不出现横向滚动

#### Scenario: 快捷筛选空间充足

- **WHEN** 可用宽度足以容纳全部快捷项和“筛选”
- **THEN** 快捷项与“筛选” MUST 自然排列在一行
