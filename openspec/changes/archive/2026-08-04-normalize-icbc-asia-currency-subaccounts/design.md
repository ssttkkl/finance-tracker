## Context

现有实现与先前规格将完整币种子账号的末位直接删除，既缩短了账号，又产生错误的映射尾号。完整账号仍是来源事实的一部分，不能为路由而改写。

## Goals / Non-Goals

**Goals:**

- 让相同规范账号的币种子账号归并到一个账本账户。
- 保持完整账单账号和业务行键不变。
- 限定工银亚洲转账候选的账号家族判断，避免放宽其他来源。

**Non-Goals:**

- 不新增数据库列、关系审计字段或自动别名。
- 不修改已有来源行快照或业务行键。
- 不将映射尾号替换为完整账号。

## Decisions

### 末位替换为 `0`，不截断账号

对可用完整子账号构造 `account[:-1] + "0"`。路由与 `payment_method` 取其末四位；完整账号继续传入业务行标识计算。相较于删除末位，这保留固定尾号长度，也把 `...74240` 与 `...74241` 收敛到 `...74240`。

### 以规范账号前缀约束工银亚洲关系候选

精确账号命中继续优先。未精确命中时，以规范账号去除最后一位得到固定前缀；来源对方账号必须比该前缀长，且至少达到规范账号长度。这样可接受同币种子账号与扩展账号，同时拒绝只有前缀的截断号码。该策略仅用于 `icbc_asia_current_account` 的转出流水。

### 本地映射配置单独备份后更正

`~/.ft/mapping.yaml` 中错误的 `7424` 来源键需要改为 `4240`。先创建带时间戳的副本；现有正式事实已经路由到同一账户，无需重写。

## Risks / Trade-offs

- [异常短账号] → 只有不少于 4 位的完整数字账号参与规范化；缺失账号继续走通用映射。
- [规范前缀碰撞] → 仅当一个账户唯一登记该前缀时筛选候选，多账户时维持原有不确定状态。
- [配置切换] → 先保留映射备份；代码和配置不一致时导入将失败关闭，不会写入错误账户。

## Migration Plan

1. 在测试中锁定 `...0`、`...1` 和扩展后缀行为。
2. 修改解析器和关系匹配，并同步主规格、术语和文档。
3. 备份并修正 `~/.ft/mapping.yaml` 的工银亚洲来源键。
4. 用 SQLite 和本地 PostgreSQL 运行导入与关系契约；对 `~/.ft/bills` 的工银亚洲账单做幂等复跑。
5. 回滚时恢复映射备份；本次没有 schema 或事实迁移。
