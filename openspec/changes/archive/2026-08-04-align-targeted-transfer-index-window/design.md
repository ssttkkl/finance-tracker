## Context

见 `proposal.md`。标准化转账匹配使用按发生日期分桶的 `FactCandidateIndex` 避免全库双重扫描，但当前长窗口规则的业务限制为 7 天，索引调用仍只读取前后 2 个自然日。

## Goals / Non-Goals

**Goals:**

- 让索引候选集合覆盖所有时间差不超过 7 天的合法转入。
- 保留最终精确秒数判断、严格 Decimal 比较和全局一对一分配。

**Non-Goals:**

- 不改变转账分类、账户别名解析、金额规则或关系状态。
- 不重扫真实数据库或改写既有关系。

## Decisions

### 用业务窗口导出日期分桶范围

候选索引调用使用不少于 7 天的日期填充范围。日期分桶缺少时分秒，边界日会被额外读入；随后既有精确秒数判断排除超过 7 天的候选。选择此方式是为了保持索引复杂度为有限日期桶遍历，而不是退化为全量事实扫描。

不采用固定常量 `2`，以免业务窗口和索引窗口再次分离；候选范围由同一 7 天业务常量导出。

## Risks / Trade-offs

- [边界日候选略多] → 最终精确时间判断会排除超窗记录，且仅多读取有限日期桶。
- [全局一对一分配顺序变化] → 新加入的合法边按现有时间差和稳定 ID 排序参与分配；这是此前被遗漏的预期行为。

## Migration Plan

无需数据库迁移。发布后仅对后续或明确触发的关系扫描生效；回滚恢复原候选范围，不删除流水或关系。
