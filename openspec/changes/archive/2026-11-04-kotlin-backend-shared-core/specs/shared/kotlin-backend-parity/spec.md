## Purpose

定义 Kotlin 后端与当前后端在 HTTP、后台任务、数据库和安全方面的兼容验收边界，使运行时更换不改变既有客户端的任务流程、财务结果、身份权限和故障恢复方式，也不把局部移植当作全量完成。

## ADDED Requirements

### Requirement: 后端运行时保持全部现有合同

Kotlin 后端 MUST 覆盖全量迁移盘点中的现有能力，保持 HTTP 路径、方法、状态、请求类型、字段、省略与 `null`、默认值、分页、SSE、错误及停用入口合同；已授权差异为 `authentication/user-workspace-access` 定义的注册/登录字符串凭据要求，同步修复分类移动后代深度以保持既定树结构和五层限制、旧现金新增及投资命令写入的响应编码失败整笔回滚，以及手工转账双端编辑保留公共编辑动作及字段差异；同步凭据配置错误统一使用固定安全错误，不回显服务器文件路径或解析诊断。未完成项 MUST 明确标记，且不得以代理旧后端或局部实现宣称全量迁移完成。

#### Scenario: 原客户端请求
- **WHEN** 原客户端对已移植能力发送相同合法、非法或重复请求
- **THEN** Kotlin 后端 MUST 返回等价的响应及数据库结果；已停用路径保持停用

#### Scenario: 交易所连接器的已知限制
- **WHEN** 迁移 Kraken 成交分页、OKX 资金类型与历史窗口或 Binance 默认现货同步
- **THEN** 本次 MUST 保持原请求、结果及失败行为并用实际 SDK 验证，明确记录分页截断、类型拒绝及不支持的调用限制；修复留待迁移完成后的独立变更，等价迁移通过不得描述为完整同步可用

#### Scenario: 同步凭据配置错误不泄露路径
- **WHEN** 同步接口读取凭据时遇到缺失文件、无效配置或缺少必要字段
- **THEN** Python 与 Kotlin MUST 返回 `400 sync_configuration_invalid` 和固定安全提示，不在响应的代码、消息或详情中包含服务器文件路径、配置内容及解析诊断

#### Scenario: 手工转账备注与双端财务补丁同时提交
- **WHEN** 使用者修改手工转账的公共备注，并提交双端金额及现金部分补丁，无论财务值是否改变
- **THEN** Python 与 Kotlin 后端 MUST 保留备注的公共编辑、修改动作及字段差异；预览与保存结果 MUST 报告实际公共修改，财务补丁不得将其覆盖为没有变化；全部字段未修改时保留原无变化结果

### Requirement: 保留存储与安全不变量

Kotlin 后端 MUST 保持现有认证会话和密码可用、工作区隔离、角色、来源证据、修订冲突、TTL/CAS、永久幂等收据、审计和完整组合同。数据库 MUST 显式选择 PostgreSQL 或 SQLite，并满足现有运行时数据库主规格；不得自动升级真实数据库、静默回退或双写。

#### Scenario: 提交响应丢失
- **WHEN** 一次提交已经成功但客户端未收到响应
- **THEN** 原幂等键核实 MUST 返回原成功收据，且不得重复财务写入

#### Scenario: 中途失败
- **WHEN** 任一写入或投影发布前发生拒绝或内部错误
- **THEN** 该命令的所有业务写入 MUST 原子回滚，不能产生失败子集或自动拆分重试

#### Scenario: 类型化持久化适配
- **WHEN** Kotlin 后端通过 jOOQ 在 SQLite 或 PostgreSQL 18 执行业务查询和写入
- **THEN** 表和字段 MUST 来自当前迁移 schema 的可校验生成结果，且仅由后端持久化层消费；金额不得经浮点转换，原事务、保存点、空值及 UTC 微秒合同 MUST 保持

#### Scenario: 重新生成数据库类型
- **WHEN** 开发者重新生成后端数据库类型
- **THEN** 生成器 MUST 仅使用显式指定的匿名 `_test` 数据库，普通构建和功能测试不得自动创建、启动或升级数据库

#### Scenario: 旧现金新增响应无法编码
- **WHEN** 旧现金新增的成功响应包含不能编码为 UTF-8 的日期原文
- **THEN** Python 与 Kotlin 后端 MUST 在提交前拒绝，并回滚该操作的全部财务写入；不得返回失败却保留新流水或余额

#### Scenario: 投资命令成功响应无法编码
- **WHEN** 投资命令即将成功写入，但完整成功响应无法通过 JSON 序列化和 UTF-8 编码
- **THEN** Python 与 Kotlin 后端 MUST 在提交前拒绝，并原子回滚投资事件和持仓快照；不得返回失败却保留余额变更；正常可编码的 Unicode 日期仍按既有合同成功

#### Scenario: 旧会话访问
- **WHEN** 使用原后端产生的有效登录令牌访问 Kotlin 后端
- **THEN** 认证会话读取 MUST 依据兼容的摘要和有效期返回用户、当前活动工作区值及工作区列表，允许无工作区且不得自动修正活动工作区；业务接口另行校验当前成员和活动工作区，不信任请求指定的身份或角色

#### Scenario: 有效用户没有工作区
- **WHEN** 有效会话尚未加入任何工作区或原成员资格已经移除
- **THEN** 会话读取 MUST 保持当前成功响应，而需要活动成员资格的业务读取 MUST 按既有合同拒绝

### Requirement: 原测试规则随实现迁移

系统 MUST 将 Python 测试中的正常、边界、非法输入、错误返回、重复执行及失败无写入等验证规则迁为可独立运行的 Kotlin 测试，并维护源测试、参数化场景、断言、目标测试和验证结果的可审查对应关系。共享规则进入公共模块测试，服务端行为进入后端测试；存储行为 MUST 在 SQLite 和真实 PostgreSQL 验证。测试存在、执行旧 Python 回归或黄金样本通过均不得单独视为原测试已迁移。所有未迁移、发生源变化或缺少断言的用例 MUST 显式保留未完成。

#### Scenario: 切片测试存在漏项
- **WHEN** 已迁移接口通过而其原测试仍有未对应的边界、参数或无写入断言
- **THEN** 该切片 MUST 保持未完成，不得只依据 HTTP 成功率或测试数量宣称验证规则完整

#### Scenario: 基础设施测试继续保留
- **WHEN** 测试确属仍保留的历史 schema 或仓库基础设施而不应机械翻译为 Kotlin
- **THEN** 系统 MUST 逐项记录理由、持续执行方式及适用的 Kotlin 兼容验证，并接受独立复核；不得从测试盘点静默删除

#### Scenario: 旧内部账单转换链退役
- **WHEN** 原测试依赖当前 Web 已不再调用的完整账单转换服务、旧退款删除、固定来源标签或配置文件账户映射
- **THEN** 本次 MUST 按当前 Web 合同逐项迁移仍有效的业务断言，明确登记旧链退役与 Native 替代验证；无法同义替代的整定义 MUST 保留原参考、原因和持续执行方式，不得假称等价迁移，不恢复已退役 CLI 或创建旧入口

### Requirement: PDF 解码故障与服务进程隔离

Kotlin 后端 MUST 通过 PDFBox 在每次新建的独立 JVM 中解码 PDF，限制服务级同时解析数量、单次堆内存、总执行时间和输入输出规模；密码不得进入参数、环境、日志或持久文件。失败或超限 MUST 丢弃全部结果并释放进程及准入名额。文件／网络沙箱本轮暂缓，不得将进程隔离声明为操作系统权限隔离。CSV 读取合同不因此改变。

#### Scenario: 某租户提交难以解析的 PDF
- **WHEN** PDF 工作进程超时、耗尽堆内存、异常退出或返回不完整结果
- **THEN** 宿主 MUST 终止该次解析并返回可识别错误，不返回部分账单，不遗留占用名额，也不终止服务进程

#### Scenario: 多租户同时请求解析
- **WHEN** 服务已经达到 PDF 并发上限
- **THEN** 新请求 MUST 在启动进程之前明确失败，不创建无界进程或无界等待队列；先前请求结束后名额可供后续请求使用

#### Scenario: 加密 PDF 和后续请求
- **WHEN** 使用者提交加密 PDF，随后另一个请求开始解析
- **THEN** 缺密码、错误密码和成功保持可区分；后续请求 MUST 使用全新工作进程，不复用前次密码或解析对象
