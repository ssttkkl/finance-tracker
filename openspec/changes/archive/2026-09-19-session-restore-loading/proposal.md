## Why

网页刷新时，应用在**会话恢复**完成前会把未完成的状态当作未登录，短暂展示登录表单，容易让使用者误以为登录已失效。Native 虽然已有加载态，但网络或服务端暂时不可用时只尝试一次，认证行为没有跨端保持一致。

## What Changes

- Web 在检测到本机保存的**登录令牌**后，先展示中性的「加载中...」**恢复加载态**，不渲染登录表单。
- Web 与 Native 在恢复认证会话时最多发起 3 次请求；网络或服务端暂时失败时自动重试。
- 服务端确认令牌无效时立即进入登录页；没有本机令牌时直接进入登录页。
- 连续 3 次恢复请求仍因网络或服务端暂时失败时进入登录页。
- 保持既有令牌持久化、登录接口、工作区选择和登出语义不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workspace-entry`：调整 Web 会话恢复期间、无令牌、无效令牌和暂时性恢复失败时的入口状态。
- `cross-platform-presentation`：统一 Web 与 Native 的认证恢复加载、重试和失败后登录语义。

## Impact

- 影响 Web `AccessApp` 的启动路由和会话恢复调用，以及 Native `SessionProvider` 的启动恢复流程。
- 影响共享 presentation 文案与认证恢复测试；不新增 API、数据库字段、依赖或持久化格式。
- 令牌仍由现有 Web 本地存储和 Native 安全存储提供；无需数据迁移。回滚时恢复单次会话请求与原有启动路由即可，不影响服务端会话。
