## Purpose

让部署维护者通过同一次请求的编号关联浏览器和服务端证据，并按构建版本及浏览器运行能力区分服务端响应失败与 Web 本地运行故障。诊断仅使用排查所需的安全字段。

## ADDED Requirements

### Requirement: HTTP 请求能与安全服务端日志关联

应用接收的 HTTP 请求 MUST 获得服务端生成的唯一请求 ID。响应 MUST 携带该 ID，允许的跨源调用 MUST 能读取该响应头。应用 MUST 记录完成请求的状态与耗时，日志只能包含安全的诊断字段。

#### Scenario: 允许来源的登录请求

- **WHEN** 允许的 Web 来源发出登录请求
- **THEN** 响应返回 `X-Request-ID`，浏览器可读取，业务状态码与响应结构沿用认证合同
- **AND** 用该 ID 可以搜到对应请求的日志

### Requirement: 未预期的后端异常留下脱敏调用帧

未处理的非致命服务端异常在响应尚未提交时 MUST 返回固定的 `500` 错误，并以请求 ID 记录异常类型与有界的调用帧。该类意外异常的日志和响应 MUST 排除原始异常消息、原始 URI、请求或响应私密内容。已知异常继续使用原有合同。

#### Scenario: 异常包含敏感文本

- **WHEN** 应用代码抛出包含敏感内容的未知异常
- **THEN** 服务端日志保留请求 ID、异常类型和安全调用帧，HTTP 响应只有固定错误和请求 ID

### Requirement: Web 记录可定位构建和认证阶段的本地诊断

Web MUST 在加载 Wasm 之前记录构建版本和浏览器运行能力，并记录未捕获错误及未处理拒绝的固定事件。可读的认证响应 MUST 记录操作、状态和有效请求 ID。这些记录 MUST 有界，且仅使用安全字段。写入诊断失败 MUST 不影响应用流程。

#### Scenario: 登录已响应但浏览器缺少隔离能力

- **WHEN** 登录接口返回成功而浏览器上下文没有跨源隔离
- **THEN** 本地诊断同时包含构建版本、隔离状态和认证响应结果，可据此查找服务端日志

#### Scenario: 本地存储不可用

- **WHEN** 浏览器不允许写本地诊断记录
- **THEN** 诊断仍可通过 Console 查看，应用照常尝试启动
