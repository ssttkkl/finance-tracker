## 范围与分级

按 A 类处理。变更触及公共响应头、异常映射、日志依赖、生产构建和隐私边界。拉取后以 `origin/main` 的 `e2a16c7f` 为基线，在独立 worktree 实施。既有导入错误编号继续服务导入诊断，请求 ID 服务单次 HTTP 调用。既有服务端导入异常事件同时记录原错误编号和请求 ID。

## 后端

由 Ktor 在业务和 CORS 之前生成 UUID 并写入响应。允许的跨源响应暴露 `X-Request-ID`。访问日志使用已匹配的路由模板、HTTP 方法、响应状态、耗时和版本，未匹配时使用固定占位。意外异常以请求 ID 联系有界的 JVM 调用帧，排除异常原文、原始 URI、参数、请求体和凭据。既有异常处理优先，框架的客户端请求错误保留原状态语义。取消和 JVM 致命错误继续传播，已提交响应不能重写。应用诊断走标准输出，依赖的告警日志走标准错误，避免干扰解析子进程的二进制输出。

## Web

构建把有效的 Git SHA 写进启动脚本。启动在 Wasm 探测前捕获全局错误和未处理拒绝，记录安全上下文、隔离及 OPFS 等能力。认证请求响应记录仅包含固定操作、状态和格式已校验的请求 ID。既有领域诊断继续写入原格式。新增诊断使用单独的有界本地记录和 Console；记录保留当前文档的启动及最近事件，刷新后重新开始。多标签页共用本地存储键，Console 以当前标签页为准。存储禁用时仍可排查。允许列由固定事件、能力标志和协议字段构成。

## 边界与回滚

影响 Web 启动代码及 Web HTTP 客户端，原生端仅获得后端的附加响应头。共享领域、公开页面及操作、数据库和事务无变更。以真实浏览器在本地生产分发包上验证。本次不依赖第三方遥测服务，回滚可直接恢复前一应用构建。
