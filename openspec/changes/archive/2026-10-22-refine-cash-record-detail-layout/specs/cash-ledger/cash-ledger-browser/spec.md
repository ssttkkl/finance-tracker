## MODIFIED Requirements

### Requirement: Compose 收支账本按窗口提供一致的流水浏览结构

Compose Web、Android 和 iOS 的收支账本 MUST 保持相同的页面区域顺序、筛选语义、月份汇总、分页、批量操作和状态反馈。筛选区 MUST 先显示复用现有交易对方筛选的搜索输入，以及固定的「全部」「支出」「收入」「转账」四个快捷项；快捷项 MUST 只更新现有经济类型筛选，「全部」MUST 清除经济类型及转账细分筛选而保留其他筛选条件。详细筛选 MUST 默认收起，由「筛选」入口打开；分类 MUST 保留在详细筛选内。`COMPACT` MUST 以 Bottom Sheet 展示详细筛选；`REGULAR` 和 `WIDE` MUST 以模态弹窗展示，账本保持可见但不可操作；面板 MUST 支持 Escape 或系统返回关闭，并沿用平台默认焦点行为。搜索和筛选 MUST 继续使用既有字段、查询与结果语义，不得新增搜索或筛选能力。

`COMPACT` MUST 使用可扫读的单列流水卡片；`REGULAR` 和 `WIDE` MUST 使用紧凑表格。每条可见收支 MUST 保留发生时间、交易对方、账户、收支分类、经济类型、金额、适用的来源和打开详情的入口；关系两端信息及长文本可在详情中查看。每个月份 MUST 形成独立的视觉容器，月份与收入/支出汇总 MUST 位于该月流水之前并与其保持在同一容器中；`REGULAR` 和 `WIDE` 的月份容器 MUST 包含表格列标题及对应流水。相邻月份容器之间 MUST 由页面底层表面形成清楚间隔。筛选、分页、选择、批量分类、批量删除和导入的业务结果 MUST 保持不变；列表和表格 MUST 提供正常、加载、空、错误和禁用状态，窄屏不得出现页面级横向滚动。

账本筛选区 MUST 使用独立的 Material 3 前景容器，并固定在屏幕上方；滚动操作 MUST 只滚动流水列表，不得带走筛选区。每个月份的流水 MUST 使用与筛选区分开的独立前景容器；页面底色 MUST 继续作为更低一层背景，并在筛选区和各月份容器之间形成清楚间隔。账本、筛选和详情的表面层级 MUST 通过全局 `FinanceTheme` 的 `surfaceContainer*` 角色表达，不在组件调用点写入独立颜色值；流水详情摘要和主要信息 MUST 直接排列于详情面板表面上，主要信息 MUST 不使用卡片外框、阴影或替代背景块，关联流水 MUST 继续使用 Material 3 默认卡片表面角色；收入/支出金额颜色保持既有语义。

账本列表视口 MUST 延伸到右下角浮动操作菜单后方；`COMPACT`、`REGULAR` 和 `WIDE` 的 FAB MUST 叠加在列表上，不得通过缩短列表视口在其下方留出固定空区。列表 MUST 保留足够的滚动末尾空间，使最后一笔能够滚动到 FAB 上方并完整查看。

月份汇总离开其原有列表位置后 MUST 固定在筛选区下方的列表视口顶部；在 `REGULAR` 和 `WIDE` 中，该月表格列标题 MUST 与月份汇总一同固定。新月份进入顶部时，新的月份汇总及适用的列标题 MUST 自然顶替前一个月份；`COMPACT` 只固定月份汇总。固定区域 MUST 位于筛选卡下方，不得覆盖筛选控件。

`REGULAR` 和 `WIDE` 表格行的全部内容（包括选择框和行内操作）MUST 使用 16 dp 的水平内缩，与月份汇总及列标题对齐；行分隔线 MUST 保持铺满月份容器。该行内缩 MUST NOT 改变 `COMPACT` 布局。

`REGULAR` 和 `WIDE` 的列表右侧预留宽度 MUST 为 16 dp，避免为窄滚动条保留过多空白；月份汇总和列标题 MUST 与缩窄后的列表内容边界对齐。所有尺寸的可见滚动条轨道和滑块 MUST 保持纤细并贴齐列表右边缘，交互热区 MUST 保留 40 dp 以支持触控定位，且 MUST 覆盖列表、不改变列表宽度。`COMPACT` MUST 在滚动时显示滚动条，并在停止滚动 2 秒后渐隐；`REGULAR` / `WIDE` MUST 常驻显示。

#### Scenario: 在 Compact 窗口浏览收支账本

- **WHEN** 使用者在 `COMPACT` 窗口打开收支账本
- **THEN** 页面 MUST 以单列流水卡片展示列表，并按月份连续分组
- **AND** 每张卡片 MUST 让金额、交易对方和发生时间易于扫读，且可查看账户、分类、经济类型和适用的来源
- **AND** 筛选区 MUST 固定在屏幕上方；每个月份的汇总与流水 MUST 位于各自独立的容器中
- **AND** 页面 MUST 保留筛选、记一笔、导入账单、分页和当前可执行的批量操作
- **AND** 页面 MUST 不出现横向滚动

#### Scenario: 在 Regular 或 Wide 窗口浏览收支账本

- **WHEN** 使用者在 `REGULAR` 或 `WIDE` 窗口打开收支账本
- **THEN** 页面 MUST 以紧凑表格连续展示日期、流水信息、账户、分类、类型和金额
- **AND** 月份及其收入、支出汇总 MUST 与对应记录分组保持在一起
- **AND** 每个月份 MUST 使用独立容器，并在容器内展示该月列标题和流水
- **AND** 长交易信息 MUST 受限以保持账户、分类和金额可读，完整文本 MUST 可在详情中查看
- **AND** 表格 MUST 保留行选择、详情、分类及适用的来源信息

#### Scenario: 继续使用既有筛选和批量操作

- **WHEN** 使用者在任一窗口等级更改筛选、翻页、选择流水、修改分类、删除已选流水或打开导入
- **THEN** 系统 MUST 保留当前筛选字段、分页游标、选择清理、危险确认、权限和错误恢复语义
- **AND** 页面 MUST 在对应加载、追加加载、空结果、错误及只读状态显示可操作的既有反馈

#### Scenario: 滚动流水列表时筛选区保持固定

- **WHEN** 使用者在任一窗口尺寸向下滚动收支流水
- **THEN** 搜索、快捷类型和详细筛选入口 MUST 保持固定在屏幕上方
- **AND** 流水列表 MUST 在筛选区下方独立滚动，月份容器 MUST 依序显示且彼此分隔

#### Scenario: 滚动列表时月份汇总与表格列标题保持可见

- **WHEN** 使用者滚动任一窗口尺寸的收支账本，使当前月份容器头部离开其原有位置
- **THEN** 当前月份汇总 MUST 固定在筛选卡下方的列表视口顶部
- **AND** `REGULAR` 和 `WIDE` 的表格列标题 MUST 紧随月份汇总固定，`COMPACT` MUST 只固定月份汇总
- **AND** 下一个月份进入顶部时，其月份汇总及适用的列标题 MUST 自然顶替前一个月份，且 MUST NOT 覆盖筛选区

#### Scenario: 使用浮动操作菜单浏览列表末尾

- **WHEN** 使用者在 `COMPACT`、`REGULAR` 或 `WIDE` 中滚动账本列表至末尾
- **THEN** FAB MUST 叠加在列表右下方，列表视口 MUST 延伸到 FAB 后方
- **AND** 最后一笔流水 MUST 可滚动到 FAB 上方并完整查看
- **AND** 页面 MUST NOT 在滚动列表下方为 FAB 固定留出空白区域

#### Scenario: 在桌面表格中浏览对齐的流水行

- **WHEN** 使用者在 `REGULAR` 或 `WIDE` 中查看月份容器内的表格
- **THEN** 每行内容两侧 MUST 各缩进 16 dp，并与月份汇总及列标题对齐
- **AND** 每行分隔线 MUST 横跨月份容器，且选择框和行内操作 MUST 保留在行内容的缩进范围内

#### Scenario: 使用 Regular 或 Wide 账本滚动条

- **WHEN** 使用者在 `REGULAR` 或 `WIDE` 中拖动或点击账本滚动条
- **THEN** 列表右侧预留宽度 MUST 为 16 dp，且月份汇总和列标题 MUST 与该列表内容边界对齐
- **AND** 滚动条可见轨道和滑块 MUST 保持纤细并贴齐列表右边缘，交互热区 MUST 保留 40 dp 且 MUST 不改变列表宽度
- **AND** 列表及固定月份头 MUST 使用缩窄后的内容宽度对齐
- **AND** 滚动条 MUST 继续支持拖动和点击定位
- **AND** `COMPACT` 滚动条 MUST 覆盖列表，且不得缩窄列表视口；滚动时显示，停止 2 秒后渐隐

#### Scenario: Compact 滚动时显示窄滚动条并在空闲后隐藏

- **WHEN** 使用者在 `COMPACT` 中滚动账本列表
- **THEN** 窄滚动条轨道和滑块 MUST 贴齐列表右边缘并在滚动期间显示
- **AND** 40 dp 交互热区 MUST 覆盖列表，不得改变列表视口宽度
- **AND** 停止滚动 2 秒后滚动条 MUST 渐隐

#### Scenario: 使用搜索和快捷筛选定位流水

- **WHEN** 使用者在搜索输入中填写交易对方，或选择「全部」「支出」「收入」「转账」快捷项
- **THEN** 搜索 MUST 复用现有交易对方筛选；快捷项 MUST 复用现有经济类型值并立即更新账本结果
- **AND** 快捷项 MUST 保留其他筛选条件；「全部」MUST 清除经济类型与转账细分筛选
- **AND** 分类及其他详细筛选 MUST 继续通过详细筛选入口访问

#### Scenario: 按窗口尺寸打开详细筛选

- **WHEN** 使用者在 `COMPACT`、`REGULAR` 或 `WIDE` 窗口选择「筛选」
- **THEN** `COMPACT` MUST 打开 Bottom Sheet，`REGULAR` 和 `WIDE` MUST 打开模态弹窗
- **AND** 详细选项 MUST 保留当前日期、账户、分类、币种、金额范围、转账细分和组成筛选值
- **AND** 详细选项 MUST 以常驻标题分为「时间」「金额」「分类」「账户」「其他条件」五组；日期范围归入「时间」，币种和金额范围归入「金额」，分类和账户分别独立成组，资金转移类型与合并状态归入「其他条件」
- **AND** `COMPACT` MUST 按组纵向排列筛选项；`REGULAR` 和 `WIDE` MUST 在组内并排排列日期范围、金额范围，以及其他条件中的可配对选项
- **AND** 分组 MUST 仅改变信息层级和排布，不折叠选项，也不得改变筛选字段、结果语义、关闭保留值或重置语义
- **AND** 模态打开期间账本 MUST 保持可见但不可操作；关闭 MUST 保留已选条件，重置 MUST 清除全部筛选
- **AND** 搜索输入和快捷筛选 MUST 在详细筛选关闭后仍反映当前条件


### Requirement: 新增、详情和编辑共用响应式模态信息面板

使用者从收支账本新建流水、打开收支详情或编辑现有流水时 MUST 使用同一响应式模态信息面板。`COMPACT` MUST 全屏呈现；`REGULAR` 和 `WIDE` MUST 从右侧呈现面板，账本保持可见但不可操作。面板 MUST 隔离背景交互并支持 Escape 或系统返回关闭。Compose 面板 MUST 沿用 Compose 与平台默认焦点行为，不得额外请求初始焦点或在关闭时显式恢复触发入口焦点；此规则只约束共享 Compose 面板，不改变旧 React Web 的抽屉行为，也不移除其他功能（例如导入导航）已有的焦点逻辑。详情摘要 MUST 以金额和币种为视觉重心，交易对方 MUST 为次级识别信息；经济类型和发生时间 MUST 进入下方流水信息字段组，与账户、流水类型、适用的业务细分、分类、备注和来源一起在面板中平铺，默认以标签与值分列组织；受限宽度或字体放大导致分列不可读时 MUST 纵向排列，标签先于值。流水信息 MUST 不使用卡片外框、阴影或替代背景块；凭证成员、组成及退款时间线 MUST 归入相应的信息区域。存在关联事实时，详情 MUST 使用独立的 Material 3 ElevatedCard，以默认 `surfaceContainerLow` 前景角色呈现默认收起的「关联流水」区域；展开内容 MUST 留在该卡片内，并在同一详情面板中分组展示当前流水与关联流水，保留每笔流水的可核对信息和现有关联管理操作。关联卡片 MUST 与平铺信息组相互独立，不得嵌套；详情面板内不得再叠加 Dialog 或 Bottom Sheet。单源收支 MUST 不显示空的凭证或关联区域。编辑 MUST 在当前面板内切换，取消后回到原详情或收支账本，保存后展示更新结果。现有新增、编辑、删除、凭证、关联操作、权限、字段校验、错误、忙碌状态和危险确认语义 MUST 保持不变。

#### Scenario: 从列表打开详情或新增流水

- **WHEN** 使用者在 `COMPACT`、`REGULAR` 或 `WIDE` 窗口打开某条流水详情或选择「记一笔」
- **THEN** `COMPACT` MUST 显示全屏面板，`REGULAR` 和 `WIDE` MUST 显示右侧模态面板
- **AND** `REGULAR` 和 `WIDE` 中的账本 MUST 保持可见但不可操作
- **AND** 打开期间账本保持可见但不可操作

#### Scenario: 从收支详情编辑并返回

- **WHEN** 使用者在详情中选择编辑、修改字段后取消或保存
- **THEN** 编辑表单 MUST 在同一面板内呈现并保留已有字段、校验和权限限制
- **AND** 取消 MUST 返回原收支详情，保存 MUST 返回更新后的详情并刷新账本结果
- **AND** 需要确认关联影响或删除影响时 MUST 保留既有的明确确认流程

#### Scenario: 键盘关闭 Compose 流水面板

- **WHEN** 使用者通过浏览器键盘打开共享 Compose 流水面板并按 Escape
- **THEN** 面板 MUST 关闭，背景账本 MUST 恢复可交互
- **AND** 面板 MUST 不请求专属初始焦点或在关闭后显式恢复焦点到触发入口
- **AND** 其他功能已有的键盘与焦点行为 MUST 保持不变

#### Scenario: 查看单源或有关联流水的收支详情

- **WHEN** 使用者打开单源收支或包含凭证、关联流水的收支
- **THEN** 详情 MUST 首先展示完成核对所需的主要收支信息
- **AND** 摘要 MUST 只保留金额主导及次级交易对方，类型和时间 MUST 在下方流水信息中显示
- **AND** 流水信息 MUST 直接平铺于中性面板 Surface，关联流水 ElevatedCard MUST 继续使用 `surfaceContainerLow` 前景角色，且不得与其他卡片嵌套
- **AND** 主要属性 MUST 默认按标签与值分列展示，受限宽度或放大字体时 MUST 允许标签在上、值在下的纵向排列；来源、凭证成员、组成、退款时间线及关联流水 MUST 在次级区域分组展示，且不得暴露实现层术语
- **AND** 单源收支 MUST 不显示空的凭证或关联区域

#### Scenario: 在详情内展开已关联流水
- **WHEN** 使用者打开包含已接受关系或相关凭证流水的详情并展开「关联流水」区域
- **THEN** 区域 MUST 默认收起，并通过「查看关联流水」及关联数量让其可发现
- **AND** 折叠入口及展开内容 MUST 位于独立的 Material 3 ElevatedCard 内
- **AND** 展开后 MUST 在当前详情面板内分组显示当前流水与每条关联流水的交易对方、金额、发生时间、账户，以及适用的流水类型、分类和备注
- **AND** 展开区域 MUST 保留现有编辑关联流水、修改关系类型、取消关联及危险色解散关系操作
- **AND** 展开 MUST 不打开第二个 Dialog、Bottom Sheet 或路由


## ADDED Requirements

### Requirement: 收支详情以一致的文字层级呈现核对信息

收支详情和展开的关联流水 MUST 按摘要、区域标题、主要数据和辅助数据表达文字层级。主要字段值 MUST 使用正常正文层级，字段名、发生时间、账户和来源 MUST 清晰可读；关联流水的交易对方和金额 MUST 与当前流水、其他流水等分组标题区分。文字大小、行高和字重 MUST 使用现有主题的 Material 3 文字角色，金额 MUST 保留等宽数字及现有精确字符串、币种和颜色语义。

字段名与值 MUST 默认分列，在分列时 MUST 按首行文字基线对齐；受限宽度或放大字体时 MUST 允许按标签先于值纵向排列；长字段、多行备注、分类路径、交易对方、账户和金额 MUST 在可用宽度内完整换行，不得相互遮挡、横向溢出或通过缩小字号隐藏问题。正文 MUST 随内容自然增高，并通过既有滚动区域查看全部内容。

本次排版 MUST 以金额为摘要的主要视觉重心，交易对方 MUST 使用次级层级；类型和发生时间 MUST 移至下方字段组，不再与金额构成三块连续摘要。原摘要类型与流水类型的显示文案相同时 MUST 避免重复，文案不同时 MUST 保留各自的标签和值。流水信息 MUST 在面板中平铺，不使用卡片外框、阴影或替代背景块。默认折叠关联流水区域及其顺序、内容，以及弹窗外框、标题、操作、编辑返回和平台默认焦点行为 MUST 保持。Compose Web、Android 和 iOS MUST 使用相同文字层级及响应式不变量。

#### Scenario: 阅读单笔流水的主要属性

- **WHEN** 使用者在 `COMPACT`、`REGULAR` 或 `WIDE` 打开收支流水详情
- **THEN** 金额 MUST 成为摘要视觉重心，交易对方 MUST 为次级信息，类型和发生时间 MUST 在下方字段组显示
- **AND** 流水信息 MUST 直接平铺于面板中，主要字段值与字段名 MUST 可明确区分
- **AND** Side Sheet 的详情摘要与标题分隔线之间 MUST 保留 24 dp 顶部留白，Compact MUST 保留已有的 24 dp 留白而不叠加；Side Sheet 留白 MUST 随正文滚动
- **AND** 标签与值在分列时 MUST 按首行基线对齐；纵向排列时 MUST 标签先于值，原有字段和数值 MUST 完整保留
- **AND** 单源流水 MUST 继续隐藏空的关联区域

#### Scenario: 核对展开的关联流水

- **WHEN** 使用者展开有关联流水的详情
- **THEN** 当前流水、其他流水的分组标题 MUST 与每笔交易的名称、金额及辅助信息形成明确层级
- **AND** 名称与金额在同排容纳不下时 MUST 重排以完整显示，并保留每笔流水的字段、关联类型和已有管理操作

#### Scenario: 受限宽度及放大字体下阅读长内容

- **WHEN** 使用者在 390 px、768 px 或 1440 px 代表窗口，或在受支持的放大字体设置下查看长备注、分类路径、账户、交易对方和大额金额
- **THEN** 所有数据 MUST 可在正文内完整阅读，字段之间 MUST 不遮挡且页面 MUST 无横向滚动
- **AND** 正文滚动 MUST 保留已有标题栏、底部操作及关闭入口

#### Scenario: 呈现既有详情状态与操作

- **WHEN** 详情加载、加载失败、只有只读权限，或从详情编辑后返回
- **THEN** 既有加载、错误重试、权限、忙碌、危险确认与编辑结果 MUST 保持不变
- **AND** 排版 MUST 不影响新增和编辑表单、关联候选选择以及投资详情的结构与文字角色
