### 现状分析

`CashRecordDetailContent` 当前顺序为摘要 → 流水信息卡 → 默认折叠的关联流水卡，底部固定操作。摘要用 `headlineMedium` 金额、`titleLarge` 交易对方、类型/时间三个独立文字块；前三行缺少统一的视觉重心。新方向为“金额主导摘要 → 平铺流水信息 → 折叠关联流水”，保留模态外框，修改主规格中对主信息卡片及三行摘要的要求。

| 区域 | 当前实现 | 问题与处理 |
| --- | --- | --- |
| 摘要 | 金额 28/36、交易对方 22/28、类型/时间 14/20 三块独立排列 | 只保留金额主导与次级交易对方；类型和时间下放字段组 |
| 流水信息容器 | ElevatedCard，内边距 16 dp | 用户明确要求拆除；改为面板内平铺字段，避免双重留白 |
| 主要字段 | 字段名 `bodySmall` 12/16、值 `bodyMedium` 14/20 | 核心核对数据偏小；分别提升为 `bodyMedium`、`bodyLarge` |
| 字段对齐 | 88–104 dp 标签列、16 dp 列间距、顶部对齐 | 不同文字行高时首行基线偏离；使用首行基线对齐，保留标签列布局 |
| 关联分组和主数据 | 分组、名称、金额均为 `titleSmall` 14/20 | 同一层级过多；分组保留短标题，名称和金额提升到 `titleMedium` 16/24 |
| 时间、账户、来源 | 大量 `bodySmall` 12/16 | 属于核对必需信息；统一为辅助 `bodyMedium` 14/20 |
| 关联记录名称与金额 | 名称占剩余宽度，金额尾端无独立宽度约束 | 长名称和大额金额可能争抢一行；根据实际内容宽度改为双行，允许完整换行 |
| 间距 | 外层 12 dp、卡内 4 dp、关联摘要 2 dp、关联内容 10 dp | 规则分散；用 4/8/16/24 dp 组织摘要、字段和分组，避免全部机械增大 |

## Goals / Non-Goals

**Goals:**

- 让金额成为第一眼的视觉重心，交易对方作为次级识别信息，再核对类型、时间、分类、账户、备注；展开后仍能逐笔比较关联流水。
- 在共享 Compose 中表达稳定的文字层级、基线与自然换行，在三种窗口下保持同一信息顺序。

**Non-Goals:**

- 不改共享模态容器、标题、编辑/新增表单、关联候选选择、全局 Typography 或投资详情。
- 不改变财务计算、数值格式、数据来源、API、权限、存储和关联规则。
- 不新增帮助文字、页面入口、视觉装饰或预建排版框架。

## Decisions

### 1. Hallmark 预检与方向

显式使用 `$hallmark redesign`，按项目规则限定为单个详情任务的排版。现有系统优先于技能的营销页模板、换字体、主题轮换、原型和其他通用建议。

- 字体：`core.tokens.json` 的 Noto Sans SC 和现有平台字体加载，`FinanceTheme.kt:90` 的 M3 `Typography()` baseline；金额沿用 `withTabularNumbers()`。
- 颜色：继续使用 FinanceTheme 的 `onSurface`、`onSurfaceVariant`、`primary`、`error` 及现有卡片容器色。
- 间距：沿用 4 dp 基础尺度与已批准的外框测量；只调整详情正文内部节奏。
- 框架：共享 Compose `commonMain`、Material 3；保持现有关闭和滚动反馈，不加动效。
- 方向：金额主导的两层摘要，类型/时间下移；主信息直接排在中性面板上，以留白、字号、字重和基线表达层级，关联记录逐笔可核对。关联卡沿用默认折叠样式。
- 自查：不叠卡片、不造装饰、不添加说明；字体、颜色和控件继续消费项目主题；自评分见页首，最终 UI 仍需 audit。

### 2. 局部文字角色

| 内容 | 角色 | baseline 字号/行高 |
| --- | --- | --- |
| 摘要金额 | `headlineMedium` + 等宽数字 | 28/36，保持 |
| 摘要交易对方 | `titleMedium` | 16/24，降为次级信息 |
| 信息区域标题、关联记录名称与金额 | `titleMedium` | 16/24 |
| 当前流水/其他流水等组内标题 | `titleSmall` | 14/20，结合分组间距区分 |
| 主要字段值、备注 | `bodyLarge` | 16/24 |
| 字段名、来源、关联摘要中的时间/账户、影响说明 | `bodyMedium` | 14/20 |
| 关联类型、数量等短标注 | `labelLarge` | 14/20 |

上述是当前实现选择；通过角色消费主题，不在调用点写死字号或行高。辅助文字用 `onSurfaceVariant`，主要值用 `onSurface`。金额语义和操作样式保持现有合同。

### 3. 摘要和主要信息平铺

摘要仅保留金额与交易对方，金额沿用 28/36 等宽数字，交易对方降为 16/24，不新增标签或说明。类型和发生时间进入下方流水信息字段组，先呈现类型、发生时间，再呈现账户、分类及适用的业务细分、对方账号和备注，来源位于组尾。原摘要的经济类型与单笔流水类型如显示文案相同，只呈现一次；若不同，必须保留两个含义，分别使用现有“收支类型”和“流水类型”标签，不把二者互相覆盖。

移除流水信息 ElevatedCard，字段组直接使用面板既有 24 dp 水平留白，避免卡片再叠加 16 dp 缩进。不保留空白卡片占位、描边、阴影或替代背景块。与下一组以留白区分；关联流水仍沿用原独立折叠区域。

### 4. 对齐、密度和长文本

字段行的标签和值都使用首行基线对齐；多行内容自然增高，不裁切备注或分类路径，不通过省略号隐藏核对数据。标签列保留现有宽度上限；大字体下如无法保持可读双列，应采用纵向字段排列。流水信息直接沿面板内容边界排列，关联卡保留既有 16 dp 内留白；区域之间 24 dp，组内 4/8/16 dp 按层级选取。Regular/Wide 的 Side Sheet 详情正文在标题分隔线下保留 24 dp 顶部留白，并随正文滚动；Compact 复用容器已有的 24 dp 顶部留白，不重复叠加。此调整只作用于只读详情，不改变新增、编辑或关联选择表单。

关联记录名称和金额只有在可用宽度足够时同排；受限宽度或长内容时按名称、金额、辅助信息顺序重排，既不挤压名称，也不让金额越界。该选择比缩小字体或对金额设省略号更适合核对任务。

### 5. 将删除的冗余信息

移除流水信息卡片的外框、阴影、额外内边距，以及摘要中并列的类型/时间行；类型/时间移入字段区，含义相同的类型显示去重。保留其他业务信息和“查看关联流水／收起”入口，不添加教学说明。

### 6. 跨端与验证边界

- Compose Web：真实 Chromium 检查详情打开、关联展开、编辑返回、错误重试、只读和正文滚动；使用生产演示/预览，390/768/1440 px 截图。
- Native：共享正文受影响；Android 通过实际 Compose 渲染检查中文长字段、基线、三窗口与字体放大，iOS 进行共享编译并如实记录实际客户端验收情况。
- 共享层：仅呈现代码；精确十进制、币种、关系、权限、数据获取和 ViewModel 状态保持原有实现。
- 旧 React/Expo：不受影响，不将其截图或验证结果算作 Compose 验收。

## Risks / Trade-offs

- [类型与时间移入字段及正文增大使首屏内容减少] → 接受正常纵向滚动，保留固定操作，不压缩行高或删字段。
- [长名称/金额与字体放大争抢横向空间] → 独立布局检查与实际长数据验证，容纳不下就重排。
- [共享模态容器也服务其他任务] → 不修改外框、公共 ModalHeader 和 footer，回归新增/编辑/关联候选入口。
- [Compose Web 语义镜像与画布可能不同步] → 对照实际截图、真实点击和网络状态，不只检查 DOM。
- [中文字体需要的行高与 Latin 不同] → 使用当前主题默认行高和自然高度，覆盖中文多行与字体放大；不在本轮手工调整全局语言高度 token。
