## Context

宽屏收支账本已采用固定表格布局，以避免交易信息的固有宽度挤出后续列。当前宽屏覆盖规则同时给账户列设置了省略号，并让金额继承了整行表格的不换行行为；跨币种金额作为内联块内容时会越出自身列。动机与范围见 `proposal.md`，可观察行为见对应的 delta 规格。

## Goals / Non-Goals

**Goals：**

- 维持交易信息省略与固定列布局的现有保护措施。
- 仅为账户与金额建立可换行的宽屏例外，并确保操作列稳定可用。
- 使用真实浏览器尺寸断言验证文字边界与按钮不重叠。

**Non-Goals：**

- 不改变窄屏卡片栅格、数据响应、金额格式或证据详情。
- 不引入新的组件结构、依赖或运行时配置。

## Decisions

### 为账户和金额建立局部换行规则

账户与金额覆盖表格单元格的默认不换行设置，并允许在必要处断行；交易信息、来源和经济类型继续沿用各自既有的截断策略。金额内容不再作为不可换行的内联块，从而能在跨币种两端之间优先换行。

备选方案是把账户和金额放入详情入口或 hover 提示。该方案会增加额外交互且无法解决金额覆盖操作列的问题，因此不采用。

### 调整固定列比例并锁定操作列的单行空间

在保持固定表格布局的前提下，为金额和操作列增加可用比例，操作列显式保持单行。账户列不以扩展表格宽度换取完整显示，而是在其既有列宽内增加行高。

备选方案是取消固定布局。该方案会重新暴露长交易信息推动后续列出界的问题，因此不采用。

### 用浏览器布局边界覆盖回归

端到端夹具提供长账户名称和较长的跨币种金额，断言账户与金额计算样式允许换行、金额内容不越过操作单元格左边界、按钮位于表格容器内且可见。该用例在旧样式下因账户和金额保持不换行或金额越界而失败。

## Risks / Trade-offs

- [长账户会增加单行记录高度] → 账户完整性优先于桌面表格的固定行高，其他列继续垂直居中。
- [极长连续数字可能在数字内部断行] → 仅在列宽不足以容纳完整数字时允许断行，以避免遮挡证据入口。
- [调整列比例可能压缩交易信息] → 交易信息已有省略号和详情入口，且浏览器测试持续验证后续列边界。

## Migration Plan

本次仅更新前端静态资源，无数据迁移。若发现布局回归，恢复宽屏账户、金额和列宽样式即可；收支投影、API 与数据库无需回滚。
