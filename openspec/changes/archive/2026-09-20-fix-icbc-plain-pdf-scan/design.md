## Context

当前现金账单自动识别按固定候选顺序逐个调用完整解析器。对 PDF 而言，工行信用卡文本解析和工行借记卡表格解析都会完整读取同一文件；解析器异常也会被候选探测吞掉，直到所有候选结束后才返回结果。详见 `proposal.md` 和 `specs/statement-import/spec.md`。

这次采用解析器自描述的格式探测契约，而不是在应用服务层增加某个银行的特殊分流逻辑。这样格式证据与具体解析器保持在同一边界，后续增加账单来源时也必须同时提供快速探测能力。

## Goals / Non-Goals

**Goals:**

- 为每个内置现金账单解析器提供 `can_parse(command) -> bool`，只判断输入是否符合该解析器格式。
- 让自动识别先完成所有快速探测，只有唯一匹配时执行一次完整解析；无匹配或多匹配均失败关闭。
- 工行 PDF 的探测只读取 PDF 首页的受控 word stream；不触发全文文本解析、表格提取或流水行构造。
- 让密码错误、格式错误和解析异常沿用现有稳定错误边界，并确保请求结束后页面清除忙碌状态。
- 保持来源账户身份、来源行快照、业务行标识、金额精度、账户映射和持久化事务语义不变。

**Non-Goals:**

- 不改变工行信用卡或借记卡的业务字段解析规则。
- 不新增数据库表、字段、迁移、依赖或密码持久化。
- 不用文件名作为唯一格式证据，也不把完整解析结果作为 `can_parse` 的实现。
- 不新增 Native 导入页面；通过 Cross-platform Impact Check 记录为未覆盖页面，不用伪页面掩盖缺口。

## Decisions

### 1. 解析器提供统一的快速探测契约

`StatementParser` 为每个内置现金来源实现 `can_parse(command)`。该方法只返回布尔匹配结果；如果输入是加密 PDF，则复用既有 `PDFPasswordRequiredError` 或 `PDFPasswordInvalidError`，让调用方保留密码流程。探测不得构造正式流水、解析全部交易行、加载账户映射或写入任何存储。

各格式的探测证据放在对应解析器边界：

- 工行信用卡和借记卡 PDF 检查文件签名并读取首页 word stream，分别识别 `信用卡` 和 `借记账户` 的账单标题。
- 支付宝 CSV 检查受限前缀内的正式表头。
- 微信 XLSX、建行 XLS 和工银亚洲 UTF-16 CSV 检查文件格式及受限表头。

### 2. 自动识别分两阶段执行

应用服务为候选解析器创建临时输入和 `StatementImportCommand`，先依次调用 `can_parse`，但这一阶段不得调用完整 `parse` 或 `parse_source_rows`。探测结果恰好一个时，应用服务只调用该候选一次并继续既有扫描/预览/导入流程；零个或多个时直接返回 `import_channel_unrecognized`，不生成候选流水。

为兼容现有注入式测试解析器，应用服务保留仅供旧测试替身使用的旧接口回退；运行时默认的 `StatementParser` 必须实现 `can_parse`，生产自动识别路径不依赖完整解析来判断格式。新增回归测试直接验证带探测契约的解析器不会被重复完整调用。

### 3. 密码错误在探测边界立即归一化

探测首页时复用既有 PDF 密码错误归一化。未提供密码返回 `PDFPasswordRequiredError`，密码错误返回 `PDFPasswordInvalidError`；上层 Web 合同继续返回 `import_password_required` 或 `import_password_invalid`。密码只作为当前解析调用的内存参数，不写入暂存会话、日志或响应数据。

### 4. 解析失败与唯一匹配分开处理

`can_parse` 只负责格式匹配。唯一匹配后的完整解析失败，沿用当前通用解析失败和来源账户识别错误；不能因为探测匹配就吞掉正式解析异常。零匹配或多匹配不进入完整解析，以避免重复读取和不确定渠道。

### 5. 验证以调用边界和用户流程为主

自动化回归测试使用带 `can_parse` 的受控解析器，断言所有候选先探测、唯一候选只完整解析一次、零匹配和多匹配都不完整解析，并覆盖工行信用卡/借记卡首页格式和密码错误。浏览器 QA 覆盖未加密工行 PDF 成功进入账户映射、密码错误、解析失败、取消和重选；不新增 UI 原型或可见文案，因本次不修改 UI 结构和样式。

## Risks / Trade-offs

- [Risk] 银行调整表头或首页字符布局，探测可能返回未知。→ 探测只作格式判断，不根据文件名猜测；返回可重试的识别失败，并用真实账单回归测试守住已支持格式。
- [Risk] 探测过宽造成多个解析器匹配。→ 采用互斥的格式签名/表头，自动识别对多匹配失败关闭，不选择“第一个成功者”。
- [Risk] 首页 PDF 探测仍可能失败或触发密码异常。→ 只读取第一页并复用统一密码异常；异常直接结束当前请求，不继续消耗其他完整解析器。
- [Risk] 旧的注入式测试替身没有 `can_parse`。→ 保留隔离的兼容回退，并在生产默认解析器和新契约测试中禁止把完整解析当格式判断。

## Migration Plan

无需数据库迁移或数据修复。部署应用版本后，新扫描先执行解析器探测；回滚应用版本即可恢复旧候选探测，不会删除或修改已有账本事实、来源快照、账户映射或导入会话。

## Cross-platform Impact Check

- **Web:** 受影响。现金导入 Web 页面复用服务端扫描结果；成功时进入账户映射，错误时沿用现有错误和重试状态。UI 结构、交互控件和共享文案不变。
- **Native:** 当前 Native 未覆盖现金导入处理页面；本次不伪造覆盖，也不改变 Native 行为。
- **共享层:** 受影响范围限于服务端解析器契约和现金导入响应既有错误边界；不改变共享文案、语义测试 ID、账户映射字段或业务结果。
