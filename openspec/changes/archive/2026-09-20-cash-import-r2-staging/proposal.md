## Why

当前导入向扫描、预览和最终确认重复上传同一份账单；最终确认还会把原文件 Base64、映射和关系决策组成大 JSON。Render 的本地文件系统也不能作为跨请求、重启或扩容可靠的临时来源，因此需要一个不写 Neon 业务表、但能支持跨请求重试的短期导入会话。

## What Changes

- 新增服务端临时导入会话：首次上传账单后保存到私有 R2 Bucket，并返回绑定当前用户和工作区的短期 `import_token`。
- 扫描、密码重试、账户映射预览和关系预览改为引用 `import_token`，不再重复上传原始文件。
- 将扫描结果、映射后的预览和关系候选作为带 TTL 的临时草稿保存到 R2；这些对象不是 Neon 业务数据，也不创建账户、流水、映射或关系。
- 最终确认只提交令牌、账户映射、用户修改的关系决定和幂等键；服务端从 R2 读取来源与预览，在 Neon 中一次事务写入全部业务数据。
- 失败重试使用同一导入会话和幂等键，不重复创建账户、流水、映射、关系或投影；成功后立即删除临时对象，过期对象由生命周期清理。
- R2 访问只允许 Render 服务端使用最小权限凭据；Bucket 默认私有，令牌、原始账单、完整账号和密码不得进入日志。
- 本地和测试环境使用显式的内存临时存储适配器；生产环境必须显式配置 R2，不得静默回退到 Render 本地文件系统。

## Capabilities

### New Capabilities

- `cash-import-session`: 定义账单原始文件、扫描预览和最终确认之间的短期、工作区隔离、可重试临时会话。

### Modified Capabilities

- `statement-import`: 修改现金账单导入的请求边界，使预览引用临时会话，最终提交从临时来源读取并保持单事务写入。
- `transaction-relations`: 修改导入关系决定的保存边界，使扫描和预览只产生临时结果，关系决定只在最终确认事务中发布。

## Impact

- Web API：扩展现金导入扫描、预览和提交接口，新增会话令牌、过期、失效、幂等和存储错误合同。
- Application：新增临时导入会话存储端口、R2 实现和内存测试实现；现金导入服务接收会话引用并在最终提交时读取来源。
- Web：保留现有四步界面与文案，前端状态改为保存 `import_token`，确认请求不再携带文件正文和完整自动关系列表。
- Dependencies：生产增加 S3-compatible R2 客户端依赖；R2 配置通过 Render 环境变量注入。
- Security：新增私有 Bucket、最小权限、随机令牌、工作区绑定、TTL、清理和敏感数据日志审查。
- Testing：增加内存存储合同、Web API 会话流程、过期/越权/重试/幂等测试，并在 SQLite 与真实 PostgreSQL 上验证最终事务等价行为。
- Rollback：保留旧接口兼容窗口；关闭 R2 会话入口前先停止新会话创建，已存在会话自然过期，不影响已经写入的账本数据。
