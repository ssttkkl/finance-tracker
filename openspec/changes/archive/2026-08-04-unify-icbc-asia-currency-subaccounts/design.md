## Context

工银亚洲账单在文件级元数据中提供完整币种子账号；当前解析器把完整账号尾号用于映射路由。对方账号匹配则只支持完整等值或唯一四位尾号，无法把币种子账号识别为同一账本账户。

## Goals / Non-Goals

**Goals:**

- 同一工银亚洲主账号的不同币种子账号进入同一账本账户。
- 保持完整币种子账号与币种的幂等边界。
- 让工银亚洲转出流水能将主账号家族作为已有候选的受控筛选条件。

**Non-Goals:**

- 不自动创建 `account_identifier` 或修改已有别名。
- 不把工银亚洲主账号前缀比较扩展到其他银行或支付渠道。
- 不将主账号、账号原文或命中过程写入关系、日志或来源行快照。

## Decisions

### 以主账号尾号路由，保留完整子账号作业务身份

解析器同时保留完整币种子账号与去除末位后的主账号。前者继续参与业务行键，后者的尾号作为映射路由输入和展示尾号。这样账本账户按资金归属聚合，而导入幂等仍区分实际账单子账号和币种。

不以账单币种直接推导账户名称或创建多币种账户；既有映射配置仍是唯一的路由授权入口。

### 主账号前缀只用于工银亚洲转出候选

对 `icbc_asia_current_account` 的转出流水，先执行现有完整账号和唯一尾号比较。若均未命中，才从唯一映射的 `account_identifier` 得到“去末位主账号”，并检查来源对方账号是否以该主账号开头且仍有后缀。该规则只返回目标账户集合，随后仍需通过金额、币种、方向、时间和记录类型规则。

不将该逻辑作为通用数字前缀匹配，避免将普通银行账号的共享前缀误判为内部转账。

## Risks / Trade-offs

- [主账号前缀碰撞] → 仅在同一工作区唯一映射时采用；多个账户共享主账号时退回既有规则。
- [过短示例或异常账号] → 只有长度大于 4 的完整数字账号才可成为主账号候选；异常元数据保持失败关闭或既有通用路由。
- [映射配置切换] → 新路由使用主账号尾号；文档记录重建库后的配置更新方式，历史事实不改写。
- [账号泄露] → 回归测试只用虚构数字，且断言关系记录不保存匹配过程。

## Migration Plan

1. 更新 `~/.ft/mapping.yaml` 中工银亚洲规则，使用主账号尾号。
2. 新库或重新导入后，不同币种子账号自动写入同一映射账户。
3. 已有库不迁移事实；需要统一历史账户时由用户备份后重建或显式整理账户。
4. 回滚时恢复修改前的映射规则和数据库备份。
