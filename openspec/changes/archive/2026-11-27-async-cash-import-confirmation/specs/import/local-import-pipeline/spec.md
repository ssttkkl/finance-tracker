## MODIFIED Requirements

### Requirement: 端侧提交完整写集

确认导入 MUST 遵守 [离线访问不提交业务写入](../../shared/offline-ledger-cache/spec.md#requirement-离线访问不提交业务写入)。离线解析与核对不等于确认保存；本地计算的预览写集不属于已冻结提交。

端侧 MUST 以一次受理请求发送冻结的完整写集，覆盖本次导入产生的现金流水与组成项、交易关系与候选、entry 与成员、待处理问题、账单账户映射与来源绑定。受理后以同一操作执行，服务端 MUST 在一次财务事务中全成功或全失败，MUST NOT 产生部分导入。

新写集入口 MUST 限于文件导入及其核对选择，不承接无文件的来源事项处理、身份草稿合并、删除或主动关系拆分命令。既有维护命令 MUST 继续由后端按 `shared/ledger-records` 与 `cash-ledger/transaction-relations` 执行，移除物化投影依赖不改变其动作资格。写集 MUST 明确区分本次导入核对的手工编辑与自动计算，MUST NOT 仅以最终人工标记或待删除问题列表代替本次选择。人工公共值与明确清空继续遵守既有合同，不扩大长期保护字段范围。

写集 MUST 分开保留行核对中的前置公共补丁及归并后对整笔收支的公共编辑。前置补丁 MUST 保留字段是否提供、明确空值及旧条目修订／不存在依赖；服务端 MUST 按真实父项所属条目校验该依赖，并保持前置编辑、关系公共选择及协调、最终公共编辑的既有次序，不从最终成员独立值反推本次意图。

端侧 MUST 沿共享账户映射发布规则生成 `statement_account_mappings` 最终增量，保持只有实际采用且未被单笔资金覆盖的选择才保存为以后默认值。服务端 MUST 校验真实工作区账户资格、合法渠道、固定 funding_group_v1、非空目标和来源键、自然键唯一、已有身份及预期修订，保持微信不发布、同值不推进修订或改写确认信息，并与整份导入原子保存。服务端 MUST NOT 为重演端侧发布过程要求额外传输资金组、逐行决定和原资金分配观察。

#### Scenario: 新引用精确命中同值账户映射

- **WHEN** 最终增量中的新映射引用按完整自然键命中已有映射，且目标账户相同
- **THEN** 服务端 MUST 复用实际映射身份，保留确认人、时间与修订，不为该同值映射推进账本版本
- **AND** 新引用及其空预期修订 MUST 保持原义；同键异账户 MUST 拒绝，实际修改仍须携带已有映射身份与原预期修订
- **AND** 重复新声明或新旧引用声明同一实际映射 MUST 拒绝，其余账户资格和整份事务校验仍生效

#### Scenario: 单笔资金覆盖不改变默认选择

- **WHEN** 整组选择账户甲，仅单笔覆盖为账户乙的流水成功，其余行跳过
- **THEN** 端侧写集 MUST 保存该笔账户乙，且 MUST NOT 包含该来源组的新默认映射
- **AND** 共享规则测试 MUST 覆盖该分支，保持原默认保存行为

写集 MUST 另保留关系选择组的合并前公共补丁，并保存本次所有新关系选择组的完整边分区与顺序，不能仅保存接受组或依赖最终关系数组的排列猜测执行顺序。公共补丁 MUST 表达端侧已完成核对的生效选择，包括原自动继承结果；原始用户补丁留在端侧稳定输入。服务端 MUST 核同一联合批次所有接受组的生效补丁字段、presence 及归一化值一致，并覆盖真实旧条目及前置编辑后、该批次原扫描范围内全部正式多成员投影的公共人工字段，明确清空的人工字段也不得遗漏。服务端 MUST NOT 在实际 ID 分配后重新选择自动继承首值，MUST 按原联合分批及逐组顺序执行合并前选择；其父集合 MUST 仅取各组真实边端点，不得扩大为整个旧确认闭包。最终公共编辑 MUST NOT 反授权此前未作出的关系公共选择，相同关系幂等命中 MUST NOT 重复施加该选择。

#### Scenario: 关系公共选择与最终编辑相互独立

- **WHEN** 关系接受阶段选择公共备注 B，归并后又将公共备注改为 D
- **THEN** 写集 MUST 独立表达关系阶段的 B 与最终编辑 D，保留全部新关系选择组及原执行顺序
- **AND** 服务端 MUST NOT 从最终 D 反推 B；生效 B MUST 覆盖可信前置编辑后原扫描范围内的必要公共人工字段，空补丁仅在该集合为空时有效

#### Scenario: 来源备注与两次公共编辑分别保留

- **WHEN** 来源备注为 S，使用者在行核对填写 C，随后在归并结果中把公共备注改为 D
- **THEN** 写集 MUST 能分别表达 C 与 D，不能用来源最终值 S 或最终公共值 D 代替前置补丁
- **AND** 成功归并后来源备注仍为 S，整笔收支备注为 D，该来源成员的独立备注仍为 C

条目增量 MUST 声明最终根、完整成员、公共字段、人工字段及成员独立值，并携带全部受影响旧条目的真实修订依赖，包括最终退休的旧对象。实际条目 ID、数字身份锚点、修订及退休集合 MUST 由服务端在同一事务内沿原规则产生，MUST NOT 接受客户端直接指定这些存储元数据。服务端 MUST 核对完整旧组不跨最终组及三阶段编辑效果，不得仅凭锚点仍存活或请求提供的选中成员推断。该职责不允许服务端改写配对、分组或公共值。

#### Scenario: 存储身份由真实提交确定

- **WHEN** 临时新建条目与已有条目归并，端侧尚不知道实际流水标识及条目 UUID
- **THEN** 端侧 MUST 提交完整业务结果及全部旧依赖，服务端按实际存储标识执行原身份保留规则
- **AND** 结果核实 MUST 返回该次提交保存的实际身份结果，不重新分配身份
- **AND** 服务端实际修订溢出或唯一性失败 MUST 整体回滚，不为对齐预览任意更换存续对象

#### Scenario: 完整写集一次落库

- **WHEN** 端侧提交一份多行账单的写集
- **THEN** 服务端 MUST 在同一事务内写入全部对象，任一失败 MUST 整体回滚

### Requirement: 提交层幂等与结果核实

提交 MUST 接受调用方幂等键，并以用户、工作区与幂等键确定一次提交。相同幂等键和内容的重试 MUST 返回该次操作的当前状态；到达终态后返回原结果。同键异内容 MUST 拒绝。结果未知时系统 MUST 能按原幂等键核实是否已提交，已成功内容 MUST NOT 重复写入。新写集提交的永久收据 MUST 保留该次提交的 `ledger_seq`，并以精确十进制字符串返回；按原键核实或读取旧收据 MUST 保留原提交版本，MUST NOT 代换成读取时的最新版本。旧入口的历史收据可不含该字段。

#### Scenario: 断网重试不重复写入

- **WHEN** 提交请求结果未知，客户端以同一幂等键重试或核实
- **THEN** 服务端 MUST 返回稳定结果，且 MUST NOT 重复写入业务数据

## ADDED Requirements

### Requirement: 现金导入确认可持久受理并以短请求接续

系统 MUST 在完整受理已冻结的现金导入写集后返回可查询的操作身份。受理记录须可在后端重启后恢复。客户端 MUST 将受理状态与实际入账收据分别表示。同一用户、工作区和操作键绑定单一写集与最终结果；同键异内容不能覆盖已受理操作。

#### Scenario: 受理回包丢失后恢复

- **WHEN** 调用方发出确认后断线，随后重新启动
- **THEN** 客户端凭原操作身份核实受理或入账结果；原操作处于执行中时，继续查询同一操作
- **AND** 成功结果对应一次账本提交和同一张收据

#### Scenario: 显式取消与提交竞争

- **WHEN** 已受理的现金导入收到用户的取消请求
- **THEN** 队列中成功撤销或执行中经核实已回滚且不会再运行时，系统方可返回已取消；提交已经完成时返回原收据
- **AND** 只有服务端已持久记录取消才能报告取消处理中。争锁期间不能记录的取消 MUST 明确提示本次未记录并允许按原键重试，后续查询仍返回真实操作状态
- **AND** 关闭页面、退出 CLI 或 HTTP 断开仅结束调用方当次等待

#### Scenario: 重启后复核账本与权限

- **WHEN** 后端在执行中或提交结果尚未向客户端可见时重启
- **THEN** 恢复方先核实原收据，并复核工作区权限和账本基线，再决定能否接续；不得重复入账或将未知结果宣布为拒写
