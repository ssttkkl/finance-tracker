## ADDED Requirements

### Requirement: Web 导入核对入参与确认材料在后台组装

Compose Wasm MUST 在后台从已读取的本地账单与同一已提交账本版本组装核对输入，在明确确认后准备完整冻结材料，并在得到真实收据后整理结果。金额、标识符、来源事实、选择及写集保真，仍由原在线确认、原子冻结、提交和结果恢复流程管理。

#### Scenario: 打开大批账单核对

- **WHEN** 使用者核对已保存的本地账单
- **THEN** Web 客户端 MUST 在后台准备账单与事实的计算输入，显示与相同版本的共享规则一致的结果

#### Scenario: 后台准备确认材料失败

- **WHEN** Worker 在完整确认材料持久化前不可用
- **THEN** 客户端 MUST 保留已保存账单和核对选择，提供现有恢复入口，完整冻结前不得发送写集

#### Scenario: 保存成功后后台整理失败

- **WHEN** 服务端已经确认保存且后台整理不可用
- **THEN** 客户端 MUST 保留原操作身份及真实收据，通过同一操作恢复结果，且不得再次发起已保存的业务写入

## MODIFIED Requirements

### Requirement: Web 现金导入预览按需读取

Compose Wasm MUST 在首次核对时提供摘要、总数、跨月汇总和首屏，后续分页、处理明细和详情按同一预览读取。写集及结果材料在确认时沿现有原子冻结入口准备。

#### Scenario: 核对大量流水

- **WHEN** 使用者首次打开大批账单的核对页
- **THEN** 客户端 MUST 仅为显示取得摘要与首屏，完整计划和写集不得作为首屏消息正文
- **AND** 后续分页 MUST 使用同一快照、计划标识和筛选口径

#### Scenario: 分页暂时不可用

- **WHEN** 预览仍可恢复且某一页的后台读取暂时失败
- **THEN** 客户端 MUST 保留当前核对，在原分页入口重试该页

#### Scenario: 核对已经失效

- **WHEN** 确认所需的后台预览已经失效
- **THEN** 客户端 MUST 保留已保存的核对选择并使用现有重新核对流程，未经完整冻结不得提交

#### Scenario: 冻结服务暂时不可用

- **WHEN** 核对仍有效且 Worker 在冻结前暂时不可用
- **THEN** 客户端 MUST 保留当前核对并允许重试原确认，完整冻结前不得发送写集
