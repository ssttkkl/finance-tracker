## Context

现有 Wasm 导入 Worker 已承接文件解析和核对算法。页面仍从持久化文本重复解码和再编码输入。现金流水的 Kotlin 投影在页面，SQLite 已运行在独立存储 Worker。确认、收据与结果归档已有原子和身份约束。

## Goals / Non-Goals

在三个已确认的位置迁移耗时 CPU 操作。维持 Web 的离线读取与原故障入口、原生实现，以及服务端、数据库、缓存版式与财务语义。

## Decisions

- 继续使用同源 Kotlin/Wasm 计算资源。Web 原样读取现有账单捕获和账本快照文本，后台校验、解码并用共用规则组装入参，页面只编码选择和版本身份。入参文本保留长整型和十进制原值，沿本地存储与现有授权边界流转。
- 流水查询 Worker 按本地缓存所有者隔离，保留同一快照的派生索引，使用原时区规则，传回页面和汇总。快照变化时替换派生索引。版本轮询从缓存元数据读取，终止后可由本地重试重建；身份失效和关闭切断结果。现有加载和重试控件承载错误，保留已显示的同工作区内容。此前结果只读直到新查询成功。
- Web 在确认时借用原计算 Worker 校验并冻结确切请求文本及结果材料。页面继续负责写入资格、快照及核对版本检查、原子保存、持原键提交和核实。恢复只消费原文本和收据。成功后的结果组装沿原校验与归档，失败保留原收据供恢复。
- 保持 Android、iOS 与 Kotlin/JS 的本地执行方式。Web 产物可独立切回上一版本，无迁移和双写。

流水页反馈保留现有顺序、流水位置和操作文案。有可读的现有结果时，使用已有列表旁的错误提示和重试按钮；首次失败使用原列表错误区域。没有新增、替换或删除的页面信息。复用 Material 3 Buttons 的 Text button 及 Paging 官方加载状态规则，重试同一读请求。

## Risks / Trade-offs

大量文本仍需从存储取出并跨线程交付。端侧保留一个原快照文本副本作为当前缓存所有者的输入，首次恢复沿原语义校验快照，原子替换时失效。确切的 HTTP 回执和归档结果明细仍在页面取得和呈现。测试区分文本交付、主线程复制和 Worker 计算，验证主线程长任务、冻结前及保存后的故障、切换工作区、跨时区筛选和精度。线程边界使用既有 CSP 和缓存规则。Worker 不获得会话令牌或存储密钥。
