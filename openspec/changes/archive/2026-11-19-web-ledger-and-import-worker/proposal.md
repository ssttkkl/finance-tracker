## Why

Web 现金导入已经在浏览器后台计算核对，但 3,000 行样本在发往 Worker 前仍出现多次长任务。确认时仍在页面编解码完整写集。现金流水页的投影、排序、筛选和月度汇总也会随本地账本增大而占用页面线程。

## What Changes

- 后台组装用于现金导入核对的账单和账本输入，复用已有本地事实。
- 后台派生现金流水投影、筛选、分页和月度汇总。Worker 不可用时保留当前内容，沿现有入口重试。
- 在后台准备确认材料和整理结果。明确确认、原子冻结、写入原键、收据核实及恢复继续使用现有约束。
- 支持既有离线读取和在线确认。业务规则、存储格式、服务端 API、Android 和 iOS 行为保持原合同。

## Capabilities

### Modified Capabilities

- `import/local-import-pipeline` 增加 Web 核对入参与确认、结果整理的后台执行边界。
- `cash-ledger/cash-ledger-browser` 增加 Web 本地现金流水查询及故障恢复。

## Impact

涉及 Compose Wasm Worker、共享缓存读取和导入提交生命周期。按 A 类验证，原因是覆盖日常读取、核对和写入恢复，需共同验证版本、精度和中断后的行为。验收包括代表性合成账单与多年账本的主线程追踪、真实浏览器故障与恢复、原生回归和无 API 或数据迁移的回滚。
