## 背景

失败原因见 `proposal.md`。当前客户端工作流为 `compose-ci.yml`；`mobile/` 文档说明旧版 Expo 客户端仅作迁移参考。迁移 `20261018_37` 会删除仅供财富归因使用的来源快照和结果，因此其回滚会抛出明确的“从备份恢复”错误。

## 目标与非目标

**目标：** 让工作流调用仓库中的 Gradle wrapper，并让测试断言当前仓库约定。

**非目标：** 恢复已退役的 Expo 工作流、修改迁移行为或改变运行时产品行为。

## 决策

- Android 发布检查继续在仓库根目录运行，改用 `./compose/gradlew -p compose`，保留现有 Gradle task 和生成文件路径。若改为在 Compose 目录运行，还需重写所有生成文件路径；使用 wrapper 实际路径改动更小。
- 删除已退役的 Expo 打包断言，改为检查当前 Compose CI 的 wrapper 路径，以及旧版 Native 文档中的退役说明。保留旧版测试签名插件仅使用专用测试凭据的安全断言。
- 迁移回滚测试匹配 `20261018_37` 当前的不可逆错误信息；运行文档测试识别现有用语“不自动回退”。
- 文档索引 `docs/README.md` 只负责导航，不再参加“运行操作文档”内容断言；这些断言保留在实际运行说明及历史合同文档上。
- 保留 `skip_specs: true`：这些修改只恢复 CI 和测试的一致性，不改变产品能力合同。

## 风险与权衡

- 过时断言可能掩盖真实回归 → 新断言直接覆盖当前工作流、迁移和文档合同，并运行 CI 使用的测试套件。
- GitHub 环境仍可能暴露本地未发现的问题 → 新 PR 的必需 checks 全部通过后才合并；若失败，在本变更内继续修复。

## 发布与回滚

无需数据或部署迁移。将修复推送到针对 `main` 的后续 PR；必需 checks 全部通过后再合并。回滚时撤销本次工作流、测试和 OpenSpec 改动。
