## Why

Compose 的账单导入账户映射在 Web 与 Native 上使用不同的展开方式，Web 下拉选项会撑开映射卡片。映射到共享新账户草稿的多个来源组还会重复显示可编辑表单，难以快速确认每组最终指向的账户。

## What Changes

- 统一 Compose Web、Android 和 iOS 的目标账户与账户类型弹出式下拉交互；菜单浮在内容上方，不改变映射卡片尺寸。
- 账户下拉菜单中的现有账户和可复用新账户草稿都显示名称、类型和币种；选中后，下拉控件本身继续显示完整账户信息。
- 选择「创建新账户」后，控件保持「创建新账户」；仅创建该草稿的映射行在下方显示推导后的名称、类型、币种和「修改」操作。
- 复用其他来源组的新账户草稿时，不在控件下方重复展示账户信息；保留「修改」入口以编辑并同步共享草稿。
- 「修改」打开 Material 3 模态对话框，编辑新账户草稿的名称与类型；币种继续由来源账户组决定。同一共享草稿的修改同步反映到所有引用它的映射行。
- 编辑对话框按表单内容决定高度；账户类型使用 Material 3 `ExposedDropdownMenuBox` / `ExposedDropdownMenu` 弹出，不为菜单预留空白高度，也不改变对话框尺寸。
- 共享 Compose 中所有 `ChoicePicker` 值选择控件统一采用只读文本框锚定的 Material 3 弹出菜单；Web 与 Native 使用同一交互实现，菜单展开不撑开周围布局。
- 编辑新账户时的账户类型复用共享 `ChoicePicker`。FAB、导航等动作菜单不属于值选择控件，本次保持原样。
- 账单导入全流程沿用应用当前 `FinanceTheme` 的浅色/夜间主题，移除应用路由和导入页面的局部浅色覆盖；表面、菜单、编辑弹窗、进度与完成状态在两种主题下保持可读。
- 账单导入页的主要操作按钮保留文字并补充匹配操作含义的图标；主页「导入账单」FAB 菜单改用表达导入的收件箱图标。
- 成功确认账单导入后，返回收支账本时自动重新读取当前筛选下的流水与汇总，并刷新账户等引用数据，无需手动刷新页面。
- 收支账本改为连续滚动列表；接近已加载流水末尾时自动获取下一游标页，追加失败时保留已加载内容并提供重试。
- 收支账本 Regular/Wide 表格按旧 React Web 顺序与宽度排列列；「交易信息」列依次显示交易对方和备注。Compact 卡片也把备注紧接在交易对方下方。
- 保留现有账户映射选项、确认时机和导入规则；不修改旧 React Web、API、持久化或账户业务能力。

## 已确认合同

- 目标账户和新账户类型在 Compose Web 与 Native 使用下拉菜单；菜单选择不撑高映射卡片。
- 现有账户与可复用新账户草稿的菜单选项及已选控件均展示名称、类型和币种；现有账户不再在控件下方重复显示摘要。
- 选择「创建新账户」后控件保持该固定标签，下方显示推导信息和「修改」；复用共享草稿时只在已选控件中显示账户信息，不在下方重复展示，并保留同步编辑入口。
- 「修改」使用 Material 3 模态对话框编辑名称和类型，币种仍由来源账户组决定；共享同一草稿的映射行同步展示修改结果。
- 编辑对话框不使用空白占位撑高；Web 与 Native 使用 Material 3 `ExposedDropdownMenuBox` / `ExposedDropdownMenu`，菜单作为 Popup 不参与对话框布局测量。
- 所有 `ChoicePicker` 调用使用统一的锚定弹出菜单，并保留原有标签、选项、语义 ID、禁用状态和选择回调。
- 不改 FAB、导航和其他命令型动作菜单。
- 导入流程不强制浅色主题，不直接使用浅色专属状态色；导入、映射、预览、关联审查、编辑弹窗及完成状态均响应应用当前主题。
- 导入流程中的主要可点击操作保留可见文字并呈现语义匹配的图标；主页账单导入入口图标表达导入/收件。
- 保留既有账户映射选项、币种缺失提示、确认时机和导入规则；不改旧 React、API、持久化或账户业务能力。
- 验证范围为 Compose Web 的 `COMPACT`、`REGULAR`、`WIDE` 三类窗口；按使用者要求不运行 Native 验证。
- 表格列顺序参照旧 React Web 的桌面表格；Compose Regular/Wide 继续保留行复选框和「查看」操作。

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `shared/cross-platform-presentation`: 规定账单导入账户映射的跨端菜单、已选账户摘要、新账户草稿摘要和编辑对话框呈现合同。
- `cash-ledger/cash-ledger-browser`: 规定成功导入并返回后重新读取账本列表、汇总及引用数据，同时保留当前筛选；接近列表末尾时自动加载下一游标页，并在追加失败时保留重试入口。

## Impact

- 共享 Compose `ChoicePicker` 实现及 35 个调用点，影响工作区、账本、流水详情、导入、分类和投资等 Compose 页面；同时调整导入账户编辑对话框调用点。
- Compose 账单导入全流程的主题适配、主要操作按钮图标与账本主页导入 FAB 图标。
- 导入成功后的账本返回刷新信号及列表回归覆盖；不改变导入写入事务或账本查询 API。
- Compose 共享账本列表使用 Paging Compose 与 LazyColumn 自动加载现有游标页；新增一个客户端依赖，不改变后端分页合同。
- Compose 账本桌面表格列顺序与宽度对齐旧 React Web；交易信息在同一列中分两行展示交易对方及备注。
- 应用入口的 Compose `FinanceTheme` 路由主题选择。
- `docs/feature-map.md` 的 F-05 页面实现说明。
- Compose Web 浏览器 QA：覆盖 `COMPACT`（390 px）、`REGULAR`（768 px）和 `WIDE`（1440 px）的账户映射流程；并在浅色和夜间主题下检查导入关键步骤、操作图标、对比度和溢出。按用户确认不运行 Android/iOS QA。
- 不改变 Application Service、账单账户映射语义、账户写入数据、API、数据库 schema 或旧 React Web；仅在共享客户端成功返回账本时重新读取既有查询。新增的 Paging Compose 依赖仅用于共享客户端列表呈现。
- 回滚方式：还原本 change 的 Compose UI、功能地图和 OpenSpec 文件；无需数据迁移或运行时兼容步骤。
