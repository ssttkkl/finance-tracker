## Context

账单导入映射位于共享 Compose 页面 `CashImportScreen.kt`。共享 `ChoicePicker` 当前有 35 处调用：Web 使用自定义按钮、内容流菜单或 overlay host，Native 使用 Material 3 `DropdownMenu`。账户类型编辑也曾单独实现过 Material 3 exposed menu。新账户草稿由 `CashImportViewModel` 保存在当前导入会话中；`updateNewAccount` 已按稳定的 `draftId` 更新所有引用行。

Material 3 `ExposedDropdownMenuBox` / `ExposedDropdownMenu` 已在共享 Compose 中验证可用。`FinanceTheme` 与既有 Compose 文案资源是当前样式和文案来源。账单账户映射的业务合同以 `openspec/specs/import/statement-import/spec.md` 为准；本变更统一选择控件呈现，并调整导入映射和局部编辑交互，不改变选择值或业务结果。

## Goals / Non-Goals

**Goals:**

- 将全部 `ChoicePicker` 收敛到只读 `OutlinedTextField` 锚定的 Material 3 菜单；Web 与 Native 使用同一弹出式选择交互，菜单不改变周围布局尺寸。
- 让来源信息、目标账户选择器和当前账户摘要形成清晰、紧凑的单向阅读顺序。
- 将新账户名称与类型编辑收进按需打开的 Material 3 模态对话框，并沿用现有共享草稿更新机制；账户类型复用共享 `ChoicePicker`。
- 账单导入的所有步骤、状态与弹出层继承应用当前浅色/夜间 `FinanceTheme`，避免页面局部覆盖主题或引用浅色专属颜色。
- 账单导入主要操作按钮保留文字标签并配有语义匹配的 Material 图标；账本主页导入入口使用收件箱/导入语义图标。
- 导入确认成功后返回账本时自动重新读取当前筛选下的流水与汇总，并刷新账户、分类等引用数据，无需手动刷新页面。
- 收支账本改用 Paging Compose 与 `LazyColumn` 连续渲染；滚动接近已加载流水末尾时自动获取下一游标页，追加失败提供显式重试并保留已有内容。
- 收支账本 `REGULAR` / `WIDE` 表格沿用旧 React Web 桌面列顺序与宽度；交易信息列按交易对方、备注两行展示。`COMPACT` 卡片让备注紧跟交易对方。
- 保留既有币种缺失提示和账户映射确认行为，不引入额外业务状态。

**Non-Goals:**

- 不修改账单导入规则、Application Service、数据库、API 或账户实体。
- 不改旧 React Web 页面，也不创建页面级新设计系统、颜色 token 或 Finance 控件包装层。
- 不做 Android/iOS 运行时 QA；共享代码仍须保持其既有 Native 兼容实现。

## Decisions

### 全部 ChoicePicker 统一使用 Material 3 锚定菜单

`ChoicePicker` 使用 `ExposedDropdownMenuBox` 与 `ExposedDropdownMenu`；只读 `OutlinedTextField` 提供字段标签、当前值和下拉图标，并作为菜单锚点。Web 与 Native 共用这套实现，菜单作为独立 Popup 覆盖页面内容，不参与触发字段或父布局的尺寸测量。菜单项保留稳定语义 ID、选中状态、禁用状态和原有选择回调。FAB、导航等动作菜单不是值选择控件，不纳入本次统一。

现有的 Web 自定义内容流/overlay 分支和 Native 单独菜单分支由共享组件内的 Material 3 锚定菜单替代，避免平台分叉和页面级菜单宿主。

Web 的 `ChoicePicker` 菜单、导航菜单和模态 Escape 处理共享一个最近打开者优先的处理栈。按 Escape 时只调用栈顶处理器；关闭内层菜单后，该处理器随组合生命周期移除，下一次 Escape 才能关闭外层模态或菜单。这样避免多个全局 keydown 监听器相互截断，也无需恢复焦点的专用逻辑。

### 导入页面继承 FinanceTheme 并使用含义明确的操作图标

账单导入页面直接使用应用根部提供的 `FinanceTheme`。从路由级 `darkThemeOverride = false` 和页面局部 `FinanceLightSurfaceTheme` 移除浅色覆盖。卡片和空态表面从 `LocalFinanceColorRoles` 读取当前主题角色；文本、边框、遮罩、菜单、编辑面板及选中/错误状态使用 `MaterialTheme.colorScheme` 或对应主题 token。成功状态的容器改用当前 Material 3 颜色角色，不能直接引用 `GeneratedTokens.Light`；主色上的图标或文字使用对应的 `onPrimary`，避免浅色常量在夜间主题中造成低对比度。

选择文件、移除文件、返回、继续、确认导入、完成、编辑账户、取消/应用，以及关系操作等主要可点击动作使用常见 Material 图标，同时保留原有可见文字标签和语义名称。导入按钮图标表达文件进入应用；账本主页「导入账单」FAB 菜单项使用收件箱/向内箭头图标，避免呈现成向外导出的视觉方向。步骤进度指示器与筛选芯片本身不是动作按钮，不为每个序号/筛选项额外堆叠图标。

替代方案是只在背景加深色而保留强制浅色 Material 颜色方案。它会导致菜单、文本字段、按钮与覆盖层仍呈浅色，形成混杂主题，因此不采用。操作按钮只显示图标也会降低识别度，尤其在文件导入等多步骤流程中，因此保留文字。

### 菜单承担账户身份展示，创建行单独显示推导摘要

现有账户与可复用的新账户草稿在下拉菜单选项中都显示名称、账户类型和币种；选中后控件复用相同的完整标签，让目标身份在选择前后都可见。现有账户不在控件下方重复显示摘要，只在有缺失币种时保留扩充提示。

选择「创建新账户」后，控件继续显示稳定的「创建新账户」标签，不把本行草稿作为额外的「新账户：名称」选项。该创建行在控件下方显示推导名称、类型、币种及「修改」。其他来源行可选择该共享草稿，选中后在控件中显示完整账户标签；行下方不重复展示账户信息，但保留「修改」入口，使共享草稿可从任一引用行编辑并同步。

布局继续使用导入映射的现有结构：`COMPACT` 按来源、目标控件和必要的创建摘要纵向阅读；`REGULAR` / `WIDE` 保留来源信息与目标账户并列，创建摘要紧随目标控件。容器、边框和间距沿用当前 Material 3 与 FinanceTheme token，不为单个映射卡片指定新颜色。

替代方案是在每种选择状态下都显示完整的下方摘要。它会把已在控件内可读的名称、类型和币种重复一遍，因此不采用。

### 模态编辑采用本地副本与一次提交

打开「修改」时，将所选草稿的名称和类型复制到对话框局部状态。账户类型仍通过 `ChoicePicker` 选择；币种只作为只读摘要，不进入编辑状态。点击「完成」后调用 `updateNewAccount(groupId)`，由现有 ViewModel 按 `draftId` 同步所有引用行；点击「取消」关闭对话框且丢弃局部改动。

替代方案是每次输入时立即改写 ViewModel 草稿。这样取消无法恢复打开前的共享状态，也会让重复引用行在对话框仍打开时同步抖动，因此不采用。无需调整 ViewModel 或服务端事务边界。

### 导入成功返回账本后刷新列表

收支账本作为导入次级页面下方的主页面保持同一个 ViewModel；返回时首次初始化 effect 不会再次运行，所以确认导入后的新流水和汇总继续显示旧数据。导入成功时由现有完成回调向应用层发出一次性完成信号；应用层在随后返回账本时递增刷新版本，账本收到新版本后按当前筛选重新读取流水与月度汇总，并重新读取账户、分类和筛选选项。没有成功确认就离开导入页时不触发刷新。

此次回载保留现有筛选条件、分页入口和错误处理，不改查询 API、写入事务或业务数据，也不强制导航离开成功页。用户此前已要求移除与其他特性交互无关的焦点特例，因此同一返回路径去除导入后强制将焦点放回 FAB 的专用逻辑。

替代方案是每次从导入页返回都刷新，包括取消或未确认离开；它会为没有数据变化的路径制造额外请求。替代方案是要求使用者刷新浏览器，仍会让刚导入的流水暂时不可见。故采用仅在成功提交后返回时刷新。

### 收支账本连续滚动加载

收支列表目前由普通 `Column` 组合已取回的行，并在尾部要求使用者点击「加载更多」。保留现有游标 API 和版本一致性检查，将分页源接入 Kotlin Multiplatform 可用的 Paging Compose，再由单个 `LazyColumn` 组合筛选区、月度汇总、表格行、加载和错误尾部。Paging 的预取距离使列表接近已加载内容末尾时自动请求下一游标页；成功后按服务端排序追加，避免重复流水。

首屏错误继续在列表中显示重试入口；追加错误保留已加载行，并提供明确的重试入口。正常加载中显示轻量尾部状态；没有下一游标时不再显示「加载更多」按钮。筛选变化、导入成功返回和列表数据发生写入后重建分页流，从首页重新读取；筛选保持原值。月度汇总与筛选选项仍由第一页响应提供。

分页源持有每个分页流对应的筛选及投影版本快照。续页版本与首页版本不一致时返回 Paging 无效结果，丢弃旧世代并从首页重新加载，延续现有版本冲突恢复语义。用 `LazyPagingItems` 渲染可见项，并用 `peek` 检查相邻月份以插入月度汇总；不会先把所有已加载项目复制成另一个列表来渲染。

替代方案是在现有 `Column` 外手写滚动位置阈值和请求锁。这样要自行处理首次加载、追加错误、并发、筛选重置、版本冲突和重复项，与 Paging Compose 已有状态机重叠，因此本次采用 Paging Compose。官方 `paging-compose` 已发布 Kotlin Multiplatform 目标，项目依赖将使用稳定版并置于共享 `commonMain`。

### 账本表格对齐旧 React Web

`REGULAR` / `WIDE` 使用单一表格列合同：选择框、发生时间、账户、交易信息、分类、流水类型、金额、行操作。Compose 两种尺寸都保留既有行复选框与「查看」入口；列宽沿用旧 React Web 可选择表格的比例：5%、12%、15%、24%、12%、11%、13%、8%。`交易信息` 单元格始终分两行显示加粗交易对方和次级备注；缺失值使用短横线占位。`COMPACT` 继续使用可扫读流水卡片，交易对方与备注相邻呈现。

此调整只统一信息顺序和列比例，不改变排序、筛选、分类、选择、编辑或详情打开行为。桌面 QA 除检查三尺寸溢出外，还验证表头的水平次序及交易对方/备注纵向次序。

模态编辑使用 Material 3 的表面、遮罩、形状、层级和面板语义，并挂载在次级页面现有 overlay 中，而不创建嵌套 Compose `Popup`。浏览器回归发现嵌套 AlertDialog 关闭后页面仍视觉可见，但外层映射卡片的语义节点会消失，无法继续定位或操作；共享 overlay 同时保留页面语义。编辑面板按表单内容决定高度，不使用固定高度或加权空白。账户类型通过共享 `ChoicePicker` 的只读文本框锚定菜单呈现；菜单不参与编辑面板布局测量，也不改变面板尺寸。Escape 先关闭展开的菜单，再关闭编辑面板。

只读币种与取消/完成操作同处于内容末尾的操作行。对话框只受视口可用高度限制；内容超过可用高度时表单区域滚动。菜单按可用视口放置，展开期间覆盖页面内容属于 Popup 行为，选择或关闭菜单后表单与操作恢复可用。

## Risks / Trade-offs

- [替换共享组件会同时改变多个页面的选择控件外观与弹出行为] → 保留各字段标签、值、语义 ID、选中状态、禁用语义和业务回调；在 Web 浏览器中覆盖受影响页面及三类视口。
- [共享草稿的账户类型编辑可能在取消后残留] → 对话框使用局部副本，只在「完成」时调用共享更新；浏览器回归覆盖取消和完成两条路径。
- [窄视口摘要过长] → 允许名称、类型及币种按现有容器宽度换行；三尺寸截图检查无横向溢出和遮挡。
- [本次不运行 Native 运行时验证] → 变更集中于共享 Compose `commonMain`，Web 三尺寸浏览器回归覆盖共享路径；在 `tasks.md` 明确记录未验证风险。
- [锚定菜单可能遮住附近内容] → 使用 Material 3 自带 Popup 定位与滚动边界；浏览器回归覆盖菜单锚点、关闭顺序、父容器几何尺寸和对话框尺寸稳定。
- [移除强制浅色主题后，原有浅色 token 可能导致夜间状态对比度不足] → 清除导入页面 Light-only token 与固定白色前景色，使用当前主题颜色角色；Web QA 在浅色/夜间两种主题检查流程、弹出层、成功状态及文字/图标对比度。
- [导入后账本 ViewModel 保留旧列表] → 由成功回调设置一次性返回刷新版本；浏览器回归确认成功后返回时重新请求并呈现新投影，取消路径不触发刷新。
- [新增图标可能挤压 Compact 操作标签] → 使用 Material 3 默认图标槽，不设置按钮固定尺寸；Chrome `390×844` 下检查标签可读、无裁切和水平溢出。
- [Paging Compose 依赖或分页源改造可能造成 Compose Multiplatform Web/iOS 变体不兼容] → 使用官方稳定版 KMP artifact，运行 Compose Web 生产 Wasm 构建门禁和三尺寸浏览器 QA；Native 运行时验证仍按使用者约定不执行，剩余平台风险记录在 tasks。
- [列表自动预取可能过早加载，或追加失败导致已有行消失] → 以实际滚动至接近末尾作为浏览器验收；追加错误只重试当前分页并保留已有行，同时覆盖筛选变化、写入和导入返回时重置分页。

## Migration Plan

不涉及数据迁移、API 兼容或服务发布顺序。回滚时恢复 `CashImportScreen.kt`、`CashLedgerScreen.kt`、分页依赖、对应字符串资源与功能地图记录，并移除本 change 的浏览器用例和 OpenSpec delta；持久化数据无需处理。

## Open Questions

无。交互、平台范围、取消语义和验收窗口已由使用者确认，取消时丢弃局部未提交编辑遵循模态编辑的既有预期。

## Hallmark 设计方向与自查

- 任务：在账单导入账户映射阶段确认每个来源账户的目标，并只在确有需要时修改新账户草稿。
- 信息顺序：来源账户身份与币种 → 展示完整账户身份的目标账户下拉菜单；选择创建新账户时，控件下方才出现推导摘要与按需修改操作。
- 删除的冗余信息：每个共享新账户引用行重复出现的名称输入、类型下拉和币种独立行；现有账户及共享草稿映射不再重复显示控件中已有的账户摘要。
- 方向：组件级调整，遵循 Hallmark Component-scope；沿用 FinanceTheme、Material 3 默认状态、既有字号与表面 token，不另造颜色、不添加解释文案或预览工程。所有值选择字段采用一致的只读文本框和锚定 Popup；动作菜单继续保持现有实现。
- 自查：所有字段继续表达原标签和当前选择；账户选项仍完整显示名称、类型和币种；「创建新账户」保持固定标签，只有创建行显示推导摘要；长选项可以滚动或换行；菜单展开不撑大字段、卡片、对话框或页面区域；禁用和键盘关闭状态沿用 Material 3 交互。导入流程在浅色/夜间均使用当前 FinanceTheme 角色；主要操作以图标辅助可见标签；主页导入入口使用向内收件语义图标，不改变动作菜单合同。

## Cross-platform Impact Check

- Web：共享 `commonMain` 中 35 个 `ChoicePicker` 调用点都改用 Material 3 锚定 Popup；Chrome 验证受影响页面的菜单打开、选择、关闭和响应式布局，并在浅色/夜间主题下覆盖账单导入关键流程。
- Native：共享 Compose `ChoicePicker` 与账单导入页面同样消费当前 `FinanceTheme` 并显示匹配的操作图标；选项、标签、值、禁用和回调保持一致。按使用者已确认范围，不执行 Android/iOS 运行时验证。
- Shared：`FeatureComponents.kt` 为统一实现；`App.kt` 不再为导入路由强制浅色主题，并传递成功返回账本的刷新版本；`CashImportScreen.kt` 删除局部账户类型下拉并复用 `ChoicePicker`，移除局部强制浅色主题并为导入操作补图标；`CashLedgerScreen.kt` 更新主页导入图标、使用 Paging Compose `LazyColumn` 自动追加游标页、按旧 React Web 顺序呈现宽表格并响应导入成功返回刷新。导入业务状态、API 和服务端业务不变。
- Legacy React：仅作交互参考，不修改。
