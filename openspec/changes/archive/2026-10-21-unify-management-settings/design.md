## Goals / Non-Goals

- 一个管理入口、一份目录和一个正文滚动区；三个窗口等级共享任务、文案、权限和结果。
- 保留工作区与分类各自的 ViewModel、错误与加载状态，不合并业务请求。
- 不修改 API、持久化、财务计算、成员角色或删除语义；不接入新增账户、投资或运维设置。

## Decisions

### 用户任务与信息架构

1. 工作区资料：二级包含基本信息（编辑名称、复制只读 ID）、危险操作（仅管理员可见的删除工作区）。
2. 访问权限：二级包含成员与权限（查看成员、修改其他成员角色、移除成员）、邀请成员（选择角色、创建与复制邀请）。
3. 收支账本：二级包含收支分类（内嵌分类树与搜索，新增/编辑使用模态窗口，保留排序与删除影响确认）。

投资账本待具备实际配置后加入，不显示空分组或占位目录。

目录项只包含角色可见的分组。分类内容很长时不重复标题或固定第二份分类导航。分类更多菜单收纳新增子分类、上移、下移、删除；编辑保留显式文字。

### 将删除的冗余信息

- 独立分类一级入口与重复页标题。
- 大屏分类目录旁无任务时常驻的空编辑区。
- 每行重复的祖先路径文字：用树层级表达，搜索时保留足以区分同名分类的路径。
- 额外功能介绍、影响教学、未来功能占位、常驻字段帮助、卡片套卡片。

### Hallmark 设计动作与预检

- 显式使用项目内 Hallmark 的 Design 动作；范围是管理任务页，非营销页面。保持既有系统，不轮换品牌。
- 字体 token 包含 `Noto Sans SC` 与 `IBM Plex Mono`，来源为 `openspec/specs/shared/design-system/tokens/core.tokens.json`。Compose 页面沿用现有 `FinanceTheme` 的正文与标题字体，不另建字体方案。
- 颜色：蓝色品牌 `#0A63B8`、文字 `#18181B`、白色前景和 `#F5F5F5` 背景，来源为 Git token JSON；危险操作使用现有危险色。Compose 直接消费现有 token，不引入新的生产色板。
- 风格：modern-minimal / utilitarian；结构是分组长页加右侧目录，参考用户 Render 截图的信息分组、分隔、宽度和目录关系；不复制 Render 品牌、服务摘要或浏览器外壳。
- 间距：4 px 基础刻度；正文边距24 dp，分组改为平面容器；组间分隔两侧Compact各16 dp、Regular/Wide各24 dp，组内16 dp，表单最大720 dp；右侧目录独立于正文滚动。
- 动效：目录统一即时定位，不增加装饰动效，也不依赖平台是否映射减少动态效果偏好。
- 自评：Philosophy 5、Hierarchy 4、Execution 4、Specificity 5、Restraint 5、Variety 4；全部不低于 3。前轮真实 Compose 三宽审查为历史记录；Typography修订后必须重新截图和Hallmark audit，结论见 tasks。

### 两级配置结构修订（2026-10-21）

`grill-me` / `grilling` 核对后，用户明确确认上述树和同页两级目录，无待定归属。Hallmark Design 沿用 FinanceTheme 与已有 M3 控件，不新增视觉系统：一级使用 `titleLarge`，二级沿用 `titleMedium`，主要数据与辅助文字维持上一轮角色；目录父项使用原生 TextButton，子项缩进，当前子项有可见标记，所属父项用文字颜色强调，不重复暴露 `selected`。正文只在一级领域之间使用分隔线，领域内保留任务间距，不叠加卡片。

删除的冗余：五项平铺目录；原“工作区资料”与基本信息共用标题造成的层级混淆；不再把危险操作当作独立管理领域。危险操作仍保留既有二次确认与低优先级外观。

实现边界：更新 `ManagementNavigation.kt`、`ManagementLayout.kt`、`WorkspaceScreens.kt`、四份字符串资源、Kotlin/Native/Web 测试与功能地图。不删除生产文件，不改 API、路由、角色或模态。共享 `commonMain` 使 Web/Android/iOS 均受影响；旧 React/Expo 与后端不受影响。

同页定位保持二级锚点稳定；父项定位到其一级标题及首个二级配置，二级项定位自身，滚动同步子项与所属父项。仅管理员包含危险操作，隐藏后不残留空标题或目录。目录顺序与正文始终一致，旧分类链接仍直接定位收支分类，末组补白仍允许顶部定位。两级目录在三种窗口共用，Regular 适度增加目录布局宽度以容纳缩进与英文，Compact 仍单列全屏。

### Compose 实现方案

- `DestinationScaffold` 在管理页 `compact` 工具栏注入目录按钮；以当前工作区为状态边界持有目录开闭与目标分组。
- 管理页面专属单一 `LazyColumn` 或共享 `ScrollState`，不嵌套两个整页 `FeaturePage`。右侧目录是独立固定区域，选择分组滚动正文，滚动反向更新当前项。
- 提取分类无滚动内容，保留其 ViewModel；编辑通过现有模态基础设施按窗口等级呈现，不保留原 WIDE 编辑双栏。
- 保留 `/workspace-management` 路由；`/cash-categories` 渲染同一管理页并设分类初始定位。导航高亮映射到“管理”，保留浏览器历史与工作区切换。初次深链定位在数据和字体布局变化后继续对齐，正文首次指针、滚动、键盘交互或主动目录定位即停止初始锚定，避免编辑或刷新把用户拉回分类。
- 预计修改：`AppShell.kt`、`AppNavigation.kt`、`AppRouting.kt`（如需）、`WorkspaceScreens.kt`、`CashCategoryScreen.kt`、本地化资源、语义 ID、Kotlin 与 Web QA 测试及 `docs/feature-map.md`。必要时新增共享目录与管理布局文件，不删除生产文件。

## Risks / Trade-offs

- 768 px 目录挤压表单 → 目录窄列、正文表单纵排，不形成分类三栏；以实际窗口宽度验证。
- 分组过长、末组不能对齐顶部 → 定位与当前项算法覆盖末页边界；不能仅按第一可见大容器判定。
- 模态关闭后失焦或丢草稿 → 显式焦点恢复、搜索/滚动留在父任务，按工作区隔离状态。
- 分类请求失败遮蔽工作区 → 独立加载、错误与重试，正文分组始终可定位。
- 权限回归 → 继续使用既有 `isAdmin` / `canWrite` 判定并补权限回归；非管理员隐藏危险操作及目录项。
- 共享源码不等于多端已验收 → 真实 API、Compose 语义、Native 系统返回和生产构建须分别记录验证。本轮 Android 三宽实际通过、iOS 仅共享编译；Web 的 Popup 关闭后语义 DOM 同步仍有上游 CMP-10623 限制，实际 Canvas 交互与可见结果分别验证，不能宣称读屏已完整通过。
