## Why

收支账本目前只能沿游标顺序加载，长账本无法通过拖动快速定位；而流水详情的 Compose DTO 与现有后端 JSON 类型不一致，导致详情解析失败，并静默丢失分类和关联组成项信息。

## What Changes

- 为账本当前筛选结果提供准确流水总数、按稳定排序序号定位的读取能力，以及各月份对应的连续序号区间，支持跨所有已筛选流水拖动跳转，同时保留接近列表末尾时的自动追加行为。
- 在所有 Compose 尺寸与平台的账单列表右侧提供 FastScroller 快速滚动条；拖动时显示目标月份，不等待目标流水分页加载，拖动期间节流定位，松手后精确落到目标流水。Compact 默认隐藏滚动条，列表滚动或拖动滚动条时在列表上方显示，停止后等待 2 秒并渐隐；Regular/Wide 常驻显示。
- 将流水详情、候选流水和复用同一 DTO 的读写响应映射对齐到各自既有后端 JSON 合同，包括接口约定的数字/字符串 ID、收支分类、组成项关联 ID 和精确关联金额。
- 增加共享 Compose 与后端响应合同测试，以及 SQLite/PostgreSQL 定位查询验证；不改变账本金额、关系、筛选和排序语义。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cash-ledger/cash-ledger-browser`：新增按当前筛选结果快速拖动定位的行为，并明确完整流水详情数据合同。

## Impact

- Compose 共享账本列表、分页状态、流水详情 DTO/domain mapper 和详情展示。
- 现金投影查询 API、应用查询、关系型查询适配器，以及对应的 SQLite/PostgreSQL 契约与性能测试。
- API 仅增加兼容现有调用方的总数和序号定位能力；不新增数据库迁移，不改变旧游标读取语义。回滚客户端时仍可使用既有游标分页。
