## ADDED Requirements

### Requirement: 导入预览按收支账本语义展示可核对信息

导入处理页面的标准化导入预览 MUST 使用与收支账本一致的可读字段层级：发生时间按浏览器本地时区展示并按本地月份分组，交易信息以交易对方和备注双行展示，流水类型使用面向使用者的中文名称，金额与币种合并展示，并以正负号和方向色区分收入与支出。预览在此阶段 MUST 不展示收支分类、独立币种列、对方账号或来源内部枚举值；未分类状态不作为预览列或占位文案出现。

#### Scenario: 核对导入预览中的正常流水

- **WHEN** 使用者打开包含收入和支出的标准化导入预览
- **THEN** 页面 MUST 将每条发生时间显示为浏览器本地可读日期和时间，并将记录按本地年月插入分组行
- **AND** 交易信息 MUST 以第一行交易对方、第二行备注展示
- **AND** 流水类型 MUST 显示“消费”“收入”“退款”等中文业务名称，而不是 `expense`、`income` 或其他内部枚举值
- **AND** 金额单元 MUST 同时显示正负金额和三位大写币种，并对支出使用支出色、对收入使用收入色
- **AND** 页面 MUST 不渲染分类列或“未分类”占位文本

#### Scenario: 跨时区查看同一份预览

- **WHEN** 两个处于不同时区的浏览器查看同一份导入预览
- **THEN** 两个页面 MUST 按各自浏览器本地时区展示发生时间和月份分组
- **AND** 原始导入时间值、金额、币种、流水类型和行状态 MUST 保持不变

#### Scenario: 长文本不破坏桌面核对表格

- **WHEN** 交易对方或备注超过单元格可用宽度
- **THEN** 桌面预览 MUST 保持账户、流水类型、状态和金额列可读，并限制或截断长文本
- **AND** 使用者 MUST 仍可通过既有详情或来源核对路径查看完整内容

#### Scenario: 小屏查看导入预览

- **WHEN** 使用者在 320、375、390、414 或 768 px 宽度查看预览
- **THEN** 页面 MUST 使用单列记录布局或等价的小屏信息层级，不得产生页面级横向滚动
- **AND** 发生时间、交易信息、方向金额和导入状态 MUST 仍然可见
- **AND** 步骤按钮和其他可操作文字 MUST 保持单行且命中区域不小于 44 px

### Requirement: 导入预览继续保留处理状态和摘要

导入预览 MUST 继续展示全部、待新增、已存在和无法识别的处理摘要，并在每条预览行保留待新增、已存在、暂不支持或无法识别等用户可读状态。视觉重构 MUST NOT 改变这些状态的判定、确认导入条件或后端请求内容。

#### Scenario: 状态摘要与行状态保持一致

- **WHEN** 预览同时包含待新增、已存在和无法识别的行
- **THEN** 顶部摘要 MUST 显示各状态数量
- **AND** 每条行 MUST 在其交易信息或状态位置显示对应的中文状态
- **AND** 确认导入按钮 MUST 继续遵循现有暂不支持和无法识别阻断规则

#### Scenario: 预览状态异常或加载

- **WHEN** 预览正在加载、返回空结果或接口失败
- **THEN** 页面 MUST 分别提供加载、空结果或错误状态的可读反馈
- **AND** 正常、错误、空状态下均 MUST 不出现分类列或内部枚举文本
