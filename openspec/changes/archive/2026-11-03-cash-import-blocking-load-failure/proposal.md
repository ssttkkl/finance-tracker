# 导入页加载失败改为阻塞提示

## 缺陷

现金导入页进入时并行读取账户、分类和账本选项，同时导入账户列表也在恢复。两类读取失败后的表现都不正确：

- 辅助数据失败用 `!auxiliaryReady` 判断，把“加载中”和“加载失败”混为一谈；请求在途时步骤条下方会闪出一个没有说明的“重试”按钮（`CashImportTaskScreen.kt:301`）。
- 账户列表加载失败时 `ready` 保持 false，第 2 步账户选择与“核对”均被禁用；页面只在准备区显示一行错误码，没有重试，也没有可执行的恢复指引（`ImportAccountViewModel.kt:66-67`、`CashImportPreparation.kt:207`）。

## 预期

两类失败都阻塞当前导入流程。明确网络或临时服务故障显示原因与“重试”；程序错误显示“系统错误”，不提供普通重试。加载中不显示失败文案或重试按钮。关闭保留恢复信息，重新进入重新读取。

## 范围

- `CashImportTaskScreen.kt`：拆分辅助数据加载中／失败状态；失败时替代步骤内容渲染阻塞提示，移除原裸重试按钮。
- 账户列表加载失败复用 `ImportAccountUiState.ready/busy/errorCode` 判定为阻塞；不改 `ImportAccountViewModel` 的加载、恢复和账户命令语义。
- 新增阻塞判定单元测试与导入页失败态 Web 冒烟。
- 新增 `shared/cross-platform-presentation` 行为场景。

## 非目标

- 不改第 3 步核对列表整体刷新失败的安全重试；该行为仍遵循 `import/statement-import`「预览加载失败」。
- 不改未导入明细、单条明细、账本列表、工作区访问、邀请预览、投资凭证和关联来源的原位重试。
- 不改接口、字段、数据库、持久化、权限或依赖。
- 不为加载失败增加自动重试、缓存回退或本地降级。

## 能力与影响

修改 `shared/cross-platform-presentation` 的现金导入页失败态呈现。本次为 B 类变更：不新增领域能力，不改金额、币种、持久化、权限、路由、公共契约或依赖。Web、Android、iOS 共享同一 Compose 状态与文案；渲染控件和布局沿用现有页面。

## 验收

- 账户、分类或账本选项任一读取失败后，导入页按原因显示错误及有效出口，程序错误只显示「系统错误」，步骤内容与“下一步”不可操作。
- 导入账户列表在请求结束后仍未就绪且存在错误时，进入同一阻塞态；加载中不进入。
- 正常加载和账户就绪后的操作错误不触发阻塞。
- 阻塞态可通过标题关闭返回；重新进入后重新读取并恢复。
- 受影响单元测试、Web 冒烟、Compose 编译与 OpenSpec strict 校验通过。

## 回滚

恢复辅助数据的单独重试按钮和准备区错误行即可；不涉及数据迁移、接口兼容或部署回滚。

初始加载失败时关闭直接返回并保留已有恢复指针，不发送额外取消请求；重新进入读取同一任务，未知提交仍沿用原保护边界。
