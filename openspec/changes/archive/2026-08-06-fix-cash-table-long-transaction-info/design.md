## Context

宽屏收支账本使用原生表格展示发生时间、账户、交易信息、来源、经济类型、金额和证据入口。当前单元格会继承不换行规则，超长连续英文文本能够以内容固有宽度扩大交易信息列。动机和范围见 `proposal.md`。

## Goals / Non-Goals

**Goals：**

- 让宽屏表格的列宽由布局而非交易信息内容决定。
- 使超长交易对方和备注在既有两行信息层级内可预测地截断。
- 以真实浏览器布局断言覆盖该回归。

**Non-Goals：**

- 不改变窄屏卡片布局、数据查询、无障碍表头关联或证据详情。
- 不增加 hover 提示、复制操作或新的详情入口。

## Decisions

### 使用固定表格布局和列宽比例

宽屏表格使用显式的列宽定义与固定布局，使来源、经济类型、金额及操作列始终保有稳定空间，交易信息列获得剩余的可用宽度。

备选方案是只为交易信息增加 `max-width`。该方案仍允许原生自动表格布局根据其他单元格内容重新分配列宽，无法保证后续列位置稳定，因此不采用。

### 对交易信息主文本和备注使用单行省略号

交易对方与备注各自保持一行，并在溢出时显示省略号。完整字段已在证据详情中提供，不增加隐藏的重复交互。

备选方案是强制换行。连续英文地址或标识可能使单行变得很高，降低账本扫描效率，因此不采用。

### 以浏览器布局尺寸作为回归证据

在宽屏端到端测试中返回超长连续交易对方，并断言表格的 `scrollWidth` 不超过容器 `clientWidth`，同时验证来源、经济类型、金额和证据按钮位于容器内。该断言在旧实现中失败，能直接覆盖本次根因。

## Risks / Trade-offs

- [省略号隐藏了部分交易信息] → 完整字段继续通过既有证据详情可查，且表格优先服务于快速扫描。
- [固定列宽可能在临界宽度压缩文本] → 窄屏在既有断点切换为卡片；宽屏回归测试覆盖主要桌面视口。

## Migration Plan

发布仅包含前端静态资源更新，无数据库迁移。若出现布局回归，恢复列布局样式和列宽定义即可；收支投影数据、API 与证据详情均无需回滚处理。
