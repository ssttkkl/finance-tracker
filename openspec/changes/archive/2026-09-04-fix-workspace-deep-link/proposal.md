# 提案：修复工作区深链接入口

## Why

用户从分享链接或浏览器地址栏直接打开 `/w/<workspace-id>/` 时，应进入指定工作区，而不是先收到 Render 的 `Not Found`。

## What Changes

- 为 Render 静态站点声明 SPA 深层路径 rewrite，将未知前端路径交给 `index.html`。
- 让 Web 应用解析工作区前缀，恢复指定工作区会话，并在应用内导航时保留该前缀。
- 为根路径、工作区根路径和工作区子页面增加回归测试。

## Out of Scope

- 不改变工作区成员权限、会话接口或账本数据行为。
- 不为不存在或无权限的工作区绕过服务端鉴权。
- 不执行 Render 控制台配置同步、部署、提交或推送；这些需要外部授权。

## Acceptance Criteria

1. 静态站点对 `/w/<workspace-id>/` 及其前端子路径返回应用入口文档，不再返回静态站点 404。
2. 已登录用户直接打开可访问的工作区 URL 后，应用选择该工作区、显示账本，并保留规范化的工作区 URL。
3. 在工作区子页面切换账本或工作区时，工作区前缀和当前子路径保持一致。
4. 无权限的工作区仍显示可操作错误，并回到当前有效工作区；既有根路径行为不回归。
