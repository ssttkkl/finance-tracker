## Why

大批现金导入确认会在浏览器页面线程重复编解码保存材料。账本基线变化时，完整结论重算仍会占用页面线程。

## What Changes

- Web 现金导入确认后的批次材料编解码、结果整理及完整快照准备使用现有计算 Worker，并复用已校验的收据与归档。
- Web 收到明确的基线拒绝后，原收据核实优先，完整重算及冻结替换正文由 Worker 执行。
- 保留现有确认、重新核对和故障重试操作。服务器写入、加密库格式、规则及原生端计算合同沿用当前实现。

## Capabilities

### Modified Capabilities

- `import/local-import-pipeline` 的 Web 后台确认收尾与基线过期重算。

## Impact

B 类。影响现有客户端计算入口和加密缓存的原子写入调用方，HTTP、SQL 结构及本地持久化格式不变。浏览器验证真实保存、Worker 故障恢复、基线变更及大批处理。共享实现运行受影响的 Android 与 iOS 编译和单元测试。
