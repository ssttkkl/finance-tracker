## MODIFIED Requirements

### Requirement: Web 导入核对入参与确认材料在后台组装

Compose Wasm MUST 在后台从已读取的本地账单与同一已提交账本版本组装核对输入，在明确确认后准备完整冻结材料，并在得到真实收据后在后台编解码批次材料、核对和归档完整结果及准备更新后的完整缓存快照。金额、标识符、来源事实、选择及写集保真，仍由原在线确认、原子冻结、提交和结果恢复流程管理。

#### Scenario: 打开大批账单核对

- **WHEN** 使用者核对已保存的本地账单
- **THEN** Web 客户端 MUST 在后台准备账单与事实的计算输入，显示与相同版本的共享规则一致的结果

#### Scenario: 后台准备确认材料失败

- **WHEN** Worker 在完整确认材料持久化前不可用
- **THEN** 客户端 MUST 保留已保存账单和核对选择，提供现有恢复入口，完整冻结前不得发送写集

#### Scenario: 保存成功后后台整理失败

- **WHEN** 服务端已经确认保存且后台整理不可用
- **THEN** 客户端 MUST 保留原操作身份及真实收据，通过同一操作恢复结果，且不得再次发起已保存的业务写入
- **AND** 整理完成前重新打开任务时 MUST 保留恢复原批次所需的引用

### Requirement: 基线过期拒绝与稳定输入重派

提交 MUST 携带端侧计算所用的工作区基线版本。基线过期时服务端 MUST 整批拒绝并返回可识别错误；端侧 MUST 基于稳定输入（账单文件、账户映射以及按稳定引用寻址的行、entry 与配对决策）在最新缓存上重派并复用决策，结论指纹一致时 MUST 静默重提交，不一致时 MUST 提示重新核对。

#### Scenario: 无关变更后静默重提交

- **WHEN** 冲突仅来自与本导入无关的变更，且重派结论与使用者已核对的一致
- **THEN** 端侧 MUST 直接重提交，不得要求使用者重新核对

#### Scenario: 结论变化或决策失效

- **WHEN** 重派后行、entry 或配对结论发生变化，或某决策的稳定引用已失效
- **THEN** 端侧 MUST 提示已发生变更并要求重新核对，且 MUST NOT 静默丢弃使用者决策

#### Scenario: Web 后台重算暂时中断

- **WHEN** Web 客户端收到明确基线拒绝、刷新到账本新版本并再次核实原键没有收据
- **THEN** Web 客户端 MUST 在 Worker 使用已保存的账单与核对选择完整重算、比较结论并准备替换正文
- **AND** Worker 故障 MUST 保留原尝试与已保存的选择，沿现有入口继续恢复，未取得完整计算结果时不得退休原尝试或发出新写入
