## Context

Compose Wasm 已有具名请求调度和独立 Kotlin Wasm 计算 Worker。账本会话持有固定凭据、账单材料、加密缓存、恢复锁和代次围栏。

## Goals / Non-Goals

让大批确认的编解码以及基线变化后的完整重算离开页面线程。既有确认、归档、数据库格式、写入接口和业务规则继续使用原合同。结果逐项页面的查询不在本次范围。

## Decisions

- 确认收尾通过原 Worker 准备／读取批次及冻结提交，复用已经校验的归档和收据。工作区会话保留结果分页及逐页边界检查，加密写入后精确回读。原始页在 Worker 执行完整位置及身份核对并归档。
- 导入后刷新沿原凭据读取完整快照，Web Worker 核对工作区及版本并生成已有缓存格式。会话继续验证收据版本下限并原子写入，原生端沿用原 DTO 路径。
- 明确的基线拒绝后，先刷新事实，再核实原幂等键。Web Worker 使用完整事实、原账单、核对选择及原稳定引用执行同一共享重算算法。不一致沿原重新核对流程；仅在结论相同后才由缓存原子生成下一尝试并冻结，沿原上限提交。
- Worker 无权访问凭据、HTTP 或 SQL。已成功整理失败保留收据和原批次引用，重新打开仍可恢复。首次保存权威收据时遇到计算 Worker 传输故障，沿相同编码和原子写入路径保全已知成功，后续整理可继续重试。后台重算故障保留原尝试。取消、会话切换与撤权仍沿原围栏。

## Risks / Trade-offs

维持旧冻结材料、旧式批次文件数组与既有加密结果可读。跨 Worker 的大文本仍有复制开销，用合成大批账单的 Chrome 长任务验证。整组回滚使用上一版客户端产物，缓存无迁移。
