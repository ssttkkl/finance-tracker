## Context

当前工作区创建只写入工作区、成员关系和活动会话；收支查询依赖活动投影数据集，因此新工作区会命中 `projection.unavailable`。投影状态和数据集已有原子发布机制，SQLite 与 PostgreSQL 均需保持相同行为。

## Goals / Non-Goals

**Goals:**

- 让空工作区拥有可读取、版本一致的空投影数据集。
- 保持工作区创建、会话切换和投影初始化的一致性与幂等性。
- 用正常空状态承载“暂无记录”，只在真正失败时显示错误。

**Non-Goals:**

- 不改变现金事实、关系匹配、分类或金额计算规则。
- 不为已有工作区做无关的全量重建或迁移。

## Decisions

- 复用现有收支投影构建/发布边界，为新工作区发布零事实的首个活动数据集；不在查询路径回退读取原始流水。
- 初始化必须在工作区创建成功路径内完成，并保证重复调用不会产生多个活动数据集。
- Web 查询继续把真正没有可用数据集的异常映射为 `projection.unavailable`，但合法空数据集通过正常列表合同表达。
- 以应用服务测试覆盖创建后读取和切换隔离；同一契约在 SQLite 与真实 PostgreSQL 测试库执行。

## Risks / Trade-offs

- [初始化额外写入] → 创建工作区多一次投影状态/数据集写入，但换取首屏可用性；保持单事务或失败补偿，避免半初始化。
- [历史工作区仍未初始化] → 不在本次变更中迁移或补偿；继续返回既有未就绪错误，避免改变历史数据状态。
- [数据库方言差异] → 复用现有 repository 发布逻辑并补双后端契约，避免新增方言 SQL。

## Migration Plan

部署代码后，新建工作区走初始化路径；已有工作区不做迁移或隐式补偿。回滚时保留现有错误合同，不删除已发布数据集。
