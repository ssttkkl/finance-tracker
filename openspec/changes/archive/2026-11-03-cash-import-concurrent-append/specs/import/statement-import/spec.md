## ADDED Requirements

### Requirement: 文件选择步骤允许在上传中追加

现金导入的文件选择步骤 MUST 在上传或其他第一步请求进行中继续允许打开文件选择并追加文件。客户端 MUST 按文件排队，并最多同时提交 3 个上传请求；首个文件 MUST 串行创建会话，其余文件可在会话存在后并行提交。每个文件的成功或失败 MUST 独立呈现，一个文件失败不得阻塞其余文件。客户端 MUST 按最高会话修订合并返回结果，较旧响应不得覆盖较新状态。上传进行中，使用者 MUST 仍能移除已就绪文件：客户端先隐藏该行，把删除请求排队到上传结束后执行，不得取消或阻塞正在进行的上传。Web、Android 和 iOS 共用同一产品合同，渲染控件可不同。

#### Scenario: 上传中继续追加

- **WHEN** 至少一个文件正在上传，使用者再次点击“添加文件”并选择新文件
- **THEN** 文件选择 MUST 可以打开，新文件 MUST 立即显示为待上传项并加入队列
- **AND** 新文件 MUST 在当前并发额度可用时提交，不得要求等待当前上传全部结束

#### Scenario: 上传中移除已就绪文件

- **WHEN** 至少一个文件正在上传，使用者点击另一个已就绪文件的“移除文件”
- **THEN** 该文件 MUST 立即从列表消失，正在进行的上传 MUST NOT 被取消或阻塞
- **AND** 删除请求 MUST 在上传请求结束后执行；失败时 MUST 恢复该行并给出原因

#### Scenario: 首文件创建会话后再并行

- **WHEN** 当前还没有导入会话，使用者一次或连续选择多个文件
- **THEN** 客户端 MUST 先串行提交首个文件以创建会话
- **AND** 会话创建成功后，其余文件 MUST 按最多 3 个并发提交

#### Scenario: 单文件失败隔离

- **WHEN** 并行上传中的一个文件失败
- **THEN** 只标记该文件失败并显示对应原因，其他文件 MUST 继续上传或保留已成功状态
- **AND** 队列排空后页面 MUST 以服务端最新会话为准刷新文件列表
- **AND** 失败文件 MUST 显示“重试”及通用删除按钮，成功文件 MUST 保留
- **AND** 文件选择步骤存在失败或需密码文件时，“下一步” MUST 呈禁用样式且不允许继续；点击 MUST 通过 Snackbar 提示“请先重试或删除失败文件”或“请输入账单密码”，两者并存时先提示密码

#### Scenario: 重试或删除上传失败文件

- **WHEN** 使用者点击失败文件的“重试”
- **THEN** 客户端 MUST 重新上传该文件并显示进度，不重复添加文件条目
- **AND** 使用者点击该文件的删除按钮时 MUST 移除对应失败项，保留其他文件
- **AND** 创建结果未知时 MUST 保留既有重复创建保护

#### Scenario: 任意第一步请求状态可追加

- **WHEN** 文件选择步骤正在刷新会话、移除文件或执行其他第一步请求
- **THEN** “添加文件”入口 MUST 仍可触发
- **AND** 追加结果 MUST 通过服务端合并进入最新会话

#### Scenario: 上限按已上传与待上传合计

- **WHEN** 已上传文件与待上传文件按 `client_file_ref` 去重后的合计达到 20 份
- **THEN** “添加文件”入口 MUST 禁用
- **AND** 未达到上限时 MUST 允许继续追加，即使已有上传在途

#### Scenario: 按最高修订合并响应

- **WHEN** 多个上传请求的响应乱序返回
- **THEN** 客户端 MUST 只接受会话标识相同且修订更高的结果
- **AND** 较旧响应 MUST NOT 覆盖较新会话、文件集合或待上传状态

## MODIFIED Requirements

### Requirement: 受支持账单直接进入统一导入流程

系统 MUST 接收 CSV、XLS、XLSX 和 PDF，多渠道文件分别识别并在同一会话解析一次。完成文件及账户准备后 MUST 用一个预计流水列表核对和一次确认，缺账户及待确认关联可以延后。单文件或单行可预期错误只影响该项，预览不写流水映射关系；独立账户命令立即生效。最终事务发布实际成功项及收据，原文件解析后清理。

#### Scenario: 混合渠道部分可用

- **WHEN** 微信文件可用而另一文件需密码
- **THEN** 服务端保留微信记录并显示另一文件的具体问题；Compose 文件步骤要求先输入密码重试成功或删除该文件，再继续

#### Scenario: 统一核对

- **WHEN** 已得到正常及草稿预览
- **THEN** 同一列表核对并一次提交，不要求逐项补齐或进入独立关系步骤

#### Scenario: 预览后离开

- **WHEN** 未最终确认但期间独立创建账户
- **THEN** 不写流水映射关系，账户已生效，正常退出由前端询问是否安全撤销

#### Scenario: 导入混合渠道文件

- **WHEN** 使用者一次提交来自多个现金导入渠道的一组格式有效账单，并完成账户映射、流水核对和关系确认
- **THEN** 系统 MUST 在一个最终事务中转换并写入全部文件中的有效业务行
- **AND** 返回按文件、渠道和整体批次可核对的导入计数

#### Scenario: 导入受支持文件

- **WHEN** 使用者为当前工作区提交格式有效的受支持账单并完成账户映射、流水核对和关系确认
- **THEN** 系统 MUST 从临时来源读取有效业务行，在一个最终事务中转换并写入当前工作区账本记录，并返回可核对的导入计数

#### Scenario: 预览不写账本

- **WHEN** 使用者只完成文件扫描、会话内账户选择或流水预览，且没有另行提交账户普通命令
- **THEN** 系统 MUST 返回可核对的扫描或预览结果，但不得写入账户、账户币种、账单账户映射、现金流水、交易关系或收支投影；单独提交的账户普通命令按其独立结果生效

#### Scenario: 任一文件未就绪

- **WHEN** 一组文件中有文件需要密码、无法识别渠道或解析失败，同时另有文件已就绪或部分可用
- **THEN** 系统 MUST 返回每个文件的状态并保留有效文件；Compose 文件步骤 MUST 先要求处理失败或需密码文件，再进入账户映射、预览和一次最终确认，具体提示见「文件选择步骤允许在上传中追加」
- **AND** 未就绪文件不得被伪造成可导入业务行；全部文件均无业务行时只显示文件结果

#### Scenario: 导入受支持现金文件

- **WHEN** 使用者为受支持现金导入渠道提交格式有效的账单文件
- **THEN** 系统 MUST 先返回自动识别的导入渠道和来源账户分组
- **AND** 使用者确认完整账户映射后，系统 MUST 返回标准化预览和关系建议
- **AND** 在最终确认导入前 MUST NOT 创建新账户、更新账户支持币种、创建或更新账单账户映射、账本记录、余额、交易关系或收支投影
- **AND** 最终确认后 MUST 把有效业务行转换为当前工作区的账本记录，并返回可核对的导入计数

#### Scenario: 预览后离开导入页面

- **WHEN** 使用者在最终确认导入前关闭或离开导入处理页面
- **THEN** 系统 MUST 丢弃本次未确认的文件、账户映射和关系决定
- **AND** MUST NOT 在数据库中留下新账户、账户支持币种、账单账户映射、账本记录、关系、余额或投影变化
