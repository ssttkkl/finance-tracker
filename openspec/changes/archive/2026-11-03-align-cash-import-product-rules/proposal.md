## Why

当前现金导入存在程序异常被包装为文件失败、行跳过或可重试服务故障的路径，部分客户端错误丢失诊断并继续队列。账户操作未知结果与确定未提交的重试入口也未完整遵守原操作身份和反馈规则。本变更依据已确认的产品编码规范与 UI 规范审查并修正导入全流程。

## What Changes

- 区分真实格式、密码、容量、I/O 故障与程序错误；程序错误保留诊断、停止当前操作，最外层保留安全兜底。
- 未知内部错误使用 HTTP 500 且不声明可自动重试；已识别临时故障保留适用的 503。提交结果未知仍核实原命令。
- 修复上传队列、恢复信息保存、分页合同和账户操作中的异常吞没及错误继续。
- 修复确定未提交的原请求重试入口、账户未决操作重复提交，以及直接相关的反馈位置与动作资格。
- 清空备注保存前明确询问“还原原有备注”或“保留为空”，告知后者会阻止重导／重算自动填回；确认后保留长期空值保护，普通未修改保存不创建新保护。
- 核对文件、账户、预计结果、筛选／汇总、确认、结果和退出流程；有实际触发条件的发现进入任务清单，不为审查增加新页面或通用框架。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `import/statement-import`：文件和行解析的预期拒绝与内部错误边界。
- `import/cash-import-session`：诊断、异常停止、原操作恢复及提交结果确定性。
- `shared/cross-platform-presentation`：共享客户端错误反馈、重试和账户未决操作保护。
- `cash-ledger/cash-ledger-browser`：共用备注编辑的清空确认与未修改保存语义。

## Impact

按 A 类执行：涉及跨层异常、安全诊断和写入恢复，影响 Python 导入服务及共享 Compose。沿用当前 feature worktree 和既有诊断能力；公共详情增加原始备注及其来源校验凭据，恢复请求携带该凭据，客户端和服务端同组发布。必要错误状态与测试随实现同步。无新增依赖或数据库结构迁移，存储相关合同以 SQLite／真实 PostgreSQL 验证；回滚恢复本变更的代码、测试与规格，不修改用户账本。

用户已授权审查及修正；已有文件名、并发追加、加载失败阻断三项 change 保留。备注清空采用用户明确确认的长期选择，不自动删除空值保护，也不迁移旧人工标记；该备注弹窗不自动推广到分类等其他字段。投资导入、全产品设置、无关重构及原生设备 QA 不在本次范围。
