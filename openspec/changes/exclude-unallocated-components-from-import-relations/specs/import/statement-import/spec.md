## MODIFIED Requirements

### Requirement: 支付宝组合支付必须按资金账户安全归一

支付宝来源的 `收/付款方式` MUST 按 `&` 分隔的支付组成项解析。红包、立减、优惠、抵扣、福利金和券等非资金组成项 MUST 不得生成来源账户；分期文本 MUST 归一到基础支付账户；同一基础账户的重复组成项 MUST 去重。归一后恰好一个真实资金账户时，系统 MUST 使用该账户生成来源账户分组，并 MUST 保留原始 `收/付款方式` 在来源行快照中。归一后包含多个不同真实资金账户且来源没有各账户金额时，Web 导入 MUST 在预览中保留该父流水并标记为 `requires_allocation`，显示各真实资金组成项供使用者填写精确分摊金额；系统 MUST NOT 猜测金额。分摊金额 MUST 使用精确十进制语义，且组成金额之和 MUST 等于父流水金额。未完成或金额不守恒时，系统 MUST 阻止最终确认，并 MUST NOT 将该流水或其缺少金额的组成项纳入关系候选。使用者补齐后 MUST 重新请求预览；关系候选 MUST 遵循现有账户上下文和关系规则，且 MUST NOT 以父流水总额替代组成项金额。同一批次内其他可导入行 MUST 保留在预览中。

#### Scenario: 支付宝支付账户带优惠组成项

- **WHEN** 支付宝业务行的 `收/付款方式` 为一个真实账户和红包、立减、优惠、抵扣或券的 `&` 组合
- **THEN** 扫描 MUST 只生成一个真实账户来源分组
- **AND** 该行 MUST 继续保留原始组合文本，标准化流水 MUST 使用使用者确认的系统账户

#### Scenario: 支付宝分期归一到基础账户

- **WHEN** 支付宝账单的 `收/付款方式` 包含 `花呗分期` 或带期数的银行卡分期文本
- **THEN** 扫描 MUST 将其归一到对应的 `花呗` 或基础银行卡来源账户
- **AND** 同一基础账户的普通支付、分期支付和带优惠支付 MUST 共享一个来源账户分组

#### Scenario: 支付宝同一账户重复组成项

- **WHEN** 支付宝业务行的 `收/付款方式` 重复出现同一个真实账户
- **THEN** 扫描 MUST 去重该账户并继续生成一个来源账户分组
- **AND** 不得因为重复文本生成多个系统账户或多个现金流水

#### Scenario: 多账户支付等待使用者分摊

- **WHEN** 支付宝业务行包含多个不同真实资金账户，来源只提供合计金额，且至少一个支付组成项尚无准确金额
- **THEN** Web 预览 MUST 保留父流水、显示 `requires_allocation` 状态和各组成项输入项
- **AND** 该父流水及其缺少金额的组成项 MUST NOT 参与关系匹配，最终确认 MUST 保持不可用
- **AND** 来源账单、账户映射或关系规则 MUST NOT 自动推导各账户金额

#### Scenario: 完成分摊后重新请求预览

- **WHEN** 使用者为多个真实资金账户填写精确组成金额，且金额合计与父流水总额完全相等
- **THEN** Web MUST 使用更新后的映射重新计算预览和关系计划
- **AND** 关系计划 MUST NOT 使用父流水总额代替缺失或不守恒的组成项金额
- **AND** 可生成的关系候选 MUST 继续受现有账户上下文和关系规则约束

#### Scenario: 支付宝只有非资金附加项的零金额行

- **WHEN** 支付宝业务行金额为零且 `收/付款方式` 只包含骑行卡抵扣等非资金附加项
- **THEN** 扫描 MUST 将该行归入支付宝余额来源账户，以保留零金额来源记录
- **AND** 该处理 MUST 不产生余额变化，也不得创建以附加项命名的账户

## REMOVED Requirements

### Requirement: 无法唯一归属的组合支付按入口一致地逐行跳过

**Reason**：Web 导入已有交互式精确分摊流程；把未分摊的组合支付直接作为跳过行，会绕过使用者已确认的分摊语义。CLI 没有该交互，继续按行跳过。

**Migration**：Web 使用 `requires_allocation` 预览并要求完成分摊；CLI 继续遵循下方新增的非交互导入合同。

## ADDED Requirements

### Requirement: 非交互导入跳过未分摊组合支付

没有交互式分摊输入的账单导入 MUST 不猜测组合支付金额。CLI 遇到来源只提供合计金额、无法准确确定各账户金额的支付宝组合支付时，MUST 将该行作为可计数跳过项；同一文件中的其他有效行 MUST 继续导入。Web 交互式导入遵循「支付宝组合支付必须按资金账户安全归一」中的显式分摊要求。

#### Scenario: CLI 跳过支付宝组合支付

- **WHEN** CLI 导入的支付宝账单包含一条无法安全分摊的组合支付和至少一条可映射业务行
- **THEN** CLI MUST 导入可映射业务行并报告组合支付跳过数量
- **AND** 被跳过行不得创建现金流水或来源行快照

#### Scenario: CLI 文件全部为组合支付

- **WHEN** CLI 导入的支付宝账单所有业务行均无法安全分摊
- **THEN** CLI MUST 返回成功的零新增结果并明确报告跳过数量
- **AND** 账户映射、现金流水、交易关系和收支投影 MUST 保持不变
