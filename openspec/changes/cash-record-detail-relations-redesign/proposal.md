## Why

收支详情中的关联流水与账单原文缺少清楚的层级，用户难以核对每条账单及其关系。现有维护入口只处理系统留下的建议，不能由用户搜索导入流水并主动建立关联。

## What Changes

- 保留顶部基础信息，按已确认 HTML 的业务流程、结构及样式含义实现待处理事项、关联流水、关联建议与账单原文。“关联流水”和“账单原文”均为普通标题加正文内容，始终展示，不提供折叠箭头或收起状态。关联区只展示当前流水之外的实际成员，完整显示其基础信息；账单原文包含全部实际成员。
- 账单原文中的当前成员标为“当前流水”，其他成员按实际关系标注同笔支付、退款、转账或适用子类型；所有标签采用相同样式，允许同一成员具有多个关系标签。
- 将 0 到多个备选统一到“关联建议”流程：单备选提供“接受建议”，多个或无备选提供“核对建议”，点击后在弹窗内选择完整备选方案或主动搜索其他流水。完整联合方案、公共信息冲突及选择失效按实际情况呈现。确认和拒绝作用于完整方案或建议，不提供非法的逐边操作。
- 弹窗内备选和搜索流水复用现有账单流水表格，COMPACT 使用同一套流水卡片，不另造简化选择列表。
- 新增从当前详情搜索已保存导入流水并建立同笔支付、退款或转账关联的能力。搜索不受自动匹配时间窗口和候选范围限制；提交仍校验金额、币种、方向、退款额度、关系占用与修订。
- 移除关联置于对应成员附近；实际作用于必要完整组时在确认中明确涉及的全部流水，仅在人工覆写的值与相关流水原有值不同时，列出修改字段及当前值并询问是否保留；无实际差异不额外询问。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cash-ledger/cash-ledger-browser`：详情信息层级、完整成员信息与账单原文标签。
- `cash-ledger/transaction-relations`：搜索导入流水新增关联及既有候选的完整方案操作。

## Impact

A 类变更，涉及后端查询与财务写入合同、共享 Compose DTO／状态／详情及 Web、Android、iOS。依赖当前 `compose-cash-ledger-maintenance` 共享维护基础，本变更承接该 change 原先明确排除的主动新增关联；该排除不再约束本变更，原变更剩余维护验证仍独立完成。

用户已确认 `compose/qa/local-evidence/prototypes/cash-record-detail.html`，本轮实施后端与共享 Compose。关联操作在弹窗中完成，底层详情保持原位；不提供“暂不处理”。原型使用合成数据并保存在 Git 忽略目录，不提交。非目标：修改顶部摘要、支持手动记录参与外部关联、银证转账、改变财务规则、改写账单原文、升级依赖、提交／推送或部署。

验收要求：原型走通搜索、筛选、选择、关系类型、校验失败、信息冲突、预览确认、取消、新增与移除；覆盖各候选形态和单／多成员原文。最终实现另须失败回归、双后端契约、相称跨端编译、真实 Web 冒烟及独立复核。回滚时关闭新增入口并保留已确认关系和原始流水，不恢复旧的直接关系写入接口。
