## 背景

导入预览会把新流水作为选定种子交给完整关系规划器。规划器需要让新导入的入账流水找到既有出账对侧，因此也会检查未选中的负向流水。当前 Phase C 在检查每个负向流水时，先遍历全部活跃流水构造候选，再判断该种子是否与本次所选流水有关；即使候选最终不相关，也承担了全量复制和筛选成本。

完成候选索引后，真实工行信用卡账单预览约 51 秒返回，但提交 360 秒后客户端超时。SQLite 中现金流水与提交批次数未变化，后端仍持续满载。提交路径在缓存关系计划应用前逐条重建相同的已确认候选集合并做投影校验；重协调后，又在每条关系持久化前用相同的完整候选计划重复校验。计划候选包含关系图的全部边，因此在接受集合与投影事实不变时，这些校验可共享结果。

缓存计划共享校验及按组件分组关系边后再次导入仍在 600 秒内未完成。数据库仍未提交任何新行。代码检查发现另有 49 条待审核候选：每条候选都单独调用完整投影校验，并把全部事实及全部已确认候选关系重新构造成投影。

同一导入的付款镜像重协调会为约 1,455 条规范候选构造一次完整替换批次，但 `_validate_automatic_replacement_batch` 仍对批次中的每条候选重复校验这张相同的图；批次通过后，逐条持久化循环又再次调用完整校验。候选替换集合在该持久化循环中不会变化，新增已持久化边已包含在已验证集合内。

## 目标与非目标

**目标：** 对每个负向种子只读取在正式记录子类型、币种、精确金额和时间窗口上可能匹配的正向候选；未选中的既有种子仅在索引候选中包含本次导入的正向流水时参与精确匹配。缓存计划提交时，对相同的完整已确认关系图只做一次投影校验；每条待审核候选仍单独与已确认图校验，但仅重建候选端点所在的已确认关系连通组件；付款镜像规范替换集合整体校验一次，并在持久化时复用结果。现金投影按连通组件一次性分配关系边，再独立校验每个组件，不改变输出投影。

**非目标：** 不调整转账或还款分类、候选唯一性、匹配时间窗口、账户别名语义、关系排序、导入提交事务或任何账单金额。

## 设计决策

- 在 `FactCandidateIndex` 中维护转账候选桶。标准转账按子类型、币种、绝对金额索引，并按发生时间二分查找；个人购汇按正式 `fx_in` 类型和时间窗口查找，再交给原规则校验币种和唯一性。
- 保留原有匹配函数作为最终判断。索引只排除不可能满足金额、币种、类型或时间条件的候选，不直接决定关系状态。
- 预先计算本次选中的正向流水标识。既有负向种子只有在候选桶包含其中一个标识时才继续计算，以保持导入新入账端时对既有出账端的发现能力。
- 对已确认候选批次，所有候选都使用同一组完整陪同关系；完整投影校验只计算一次，并将同一结果用于该批次每条候选。待审核候选仍按各自增量分别校验。
- 缓存计划应用前，把已确认候选集合构造一次；合法性检查对该集合只校验一次，对待审核候选分别与已确认集合合并校验。
- 缓存计划完成付款镜像和退款关系重协调后，使用当前已接受关系与完整缓存计划做一次投影校验。随后每条候选复用该结果，仍按现有逐条顺序执行持久化和退款剩余金额更新；若整张图非法，仍逐条记录相同的脱敏告警并跳过自动候选。
- `build_cash_projections` 先完成并查集连通组件，再用事实到组件的映射把每条已确认关系边分配到其端点所在组件。每个组件只接收自己的关系边，按既有 ID 顺序进入相同校验逻辑；无关系单例继续生成独立投影。
- 已确认关系图整体通过投影校验后，对待审核候选在父级流水图中查找其两个端点所在的已确认连通分量，只把这些分量的事实、已确认关系和已确认候选提供给原投影校验器，并加入当前待审核候选。若端点分属两个分量，则校验二者合并后的局部图；基图其他分量已独立通过校验且不会被该候选连接，因此可省略。
- 付款镜像重协调使用 `_validate_automatic_replacement_batch` 校验规范候选的完整替换集合。通过后，持久化循环直接调用相同的 `_persist_proposal`，不再为每个已验证候选重建整张投影图；循环内向活动关系列表追加的候选已存在于被校验的集合中。
- 查询时间边界包含少量额外余量，再由原匹配函数按既有整数秒规则过滤，避免索引边界漏掉合法候选。

## 风险与回滚

- 主要风险是索引窗口边界导致漏配、共享投影校验结果时把依赖不同接受关系状态的图误当作相同、局部待审核校验漏掉候选可达的关系边，或组件关系分组遗漏边。缓存计划合法性检查在应用前运行；提交持久化的共享校验在所有关系重协调完成后运行；待审核候选从已验证基图的端点连通分量扩展；分组通过同一连通组件中的关系端点映射，每条接受关系恰好分配一次。回归用例覆盖窗口内外、同额异币、不同子类型、选中入账端发现既有出账端、已确认/待审核校验次数、局部待审核校验范围、提交阶段共享校验，以及每个投影组件只接收自身关系边。
- 若发现候选结果偏差，撤销候选索引调用并恢复全量候选即可；数据库无需迁移或回滚。

## 跨端影响

Compose Web 与 Native 共用同一现金导入 API，因此都获得相同预览性能改进。无界面、文案、导航或交互合同变化，功能地图不新增页面或对齐事项。
