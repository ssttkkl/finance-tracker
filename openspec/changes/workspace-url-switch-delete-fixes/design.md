## Context

当前认证服务把活动工作区保存在 `user_sessions.active_workspace_id`，而 React 认证壳只把工作区选择结果写回会话状态；统一账本壳及其页面组件不会因为该状态变化而重新挂载。账本导航仍使用 `/`、`/cash-import` 和 `/investment-events` 等顶级路径，无法表达工作区上下文。

工作区删除目前依赖数据库外键级联。`cash_transactions`、`cash_projections`、`cash_projection_members`、现金—投资资金关系和账户/分类之间存在 `RESTRICT` 约束；直接删除 `WorkspaceModel` 时，已导入现金流水会先被这些依赖挡住。删除接口已经要求名称精确匹配并用集合更新清理活动会话指针，这些合同继续保留。

## Goals / Non-Goals

**Goals:**

- 让规范 URL、会话活动工作区和页面读取上下文保持同步，并支持可授权深链接。
- 在不改变账本记录或投影业务语义的前提下，安全删除包含导入现金流水的工作区。
- 通过失败回归测试锁定前端即时重载、URL 隔离、删除顺序和双后端等价行为。

**Non-Goals:**

- 不把 URL 工作区 ID 直接传给账本 API 作为信任边界，不改造 CLI 的 `FT_WORKSPACE_ID` 合同。
- 不修改金额、币种、来源行快照、幂等键、关系匹配或投影规则。
- 不新增恢复站、回收站、工作区转移所有权或历史数据迁移。

## Decisions

### 1. 使用固定 ID 的工作区 URL 前缀

规范形式为 `/w/<encoded-workspace-id>/<child-path>`；根页面使用 `/w/<id>/`，现有子页面映射为 `/cash-categories`、`/cash-import`、`/investment-holdings`、`/investment-events` 和 `/workspace-management`。工作区 ID 已固定且名称可编辑，因此不使用名称生成 slug。统一路由工具负责解析、编码和组合路径，避免各组件手写前缀。

旧顶级路径只作为兼容入口：认证壳读取会话后把它规范化到当前活动工作区前缀，保留子页面语义。工作区管理和邀请链接也使用当前工作区前缀；邀请 token 仍只通过查询参数传递，不把会话令牌放入 URL。

备选方案是为每个页面复制一套带工作区参数的路由，或只在查询字符串放置 `workspace_id`。复制路由会让导航和当前态分叉，查询参数不利于稳定层级 URL，均不采用。

### 2. 深链接选择工作区但不扩大授权边界

认证壳先读取当前会话；如果 URL 含工作区 ID 且与活动工作区不同，则调用既有工作区选择接口。该接口仍在服务端验证成员关系，所有账本 API 继续从会话活动工作区装配服务。选择成功后才挂载账本壳；选择失败时保留可访问的旧会话，不渲染目标工作区数据，并将 URL 恢复为旧工作区的同一子路径或显示错误。

备选方案是让每个账本 API 接收并校验 URL 工作区 ID。它会把工作区上下文复制进全部 API，并增加 URL、会话和服务装配三者不一致的风险，拒绝采用。

### 3. 成功切换以状态、URL 和组件生命周期为一个原子用户动作

工作区选择控件继续使用受控值，不做乐观切换。接口成功后按当前子路径组合新 URL，派发 `popstate`，并以新的活动工作区 ID 作为账本壳的 React `key`；重新挂载会触发收支、分类、导入和投资页面按新工作区重新读取。接口失败不改变 state、URL 或 key，因此旧页面继续可用。

统一 `App` 保留无认证单元测试所需的顶级路径兼容模式；认证壳传入工作区 ID 后，内部导航统一通过路由工具生成带前缀的路径。工作区管理删除成功后根据返回会话选择新工作区根路径；没有剩余工作区时进入创建工作区流程。

### 4. 删除事务先解除受限依赖，再删除工作区

在名称、权限和当前工作区再次校验成功后，删除事务按以下顺序处理当前工作区：

1. 以单条集合更新清理所有指向当前工作区的 `active_workspace_id`。
2. 删除收支投影的成员、关系和投影行/数据集，解除它们对现金流水、关系和账户的 `RESTRICT` 引用。
3. 删除现金—投资资金关系，再删除现金流水和投资事件，解除对账户的受限引用。
4. 删除工作区级分类目录（同一工作区内的父子约束一起处理），以及仍有受限依赖的估值、生命周期和财富读模型行。
5. 删除 `WorkspaceModel`，让数据库级级联清理成员、邀请、映射、状态和其余工作区数据；在删除后为当前用户选择按创建时间排序的第一个剩余成员关系。

所有显式清理都按 `workspace_id` 限定，且在同一 `begin()` 事务中执行；任何一步失败都由事务回滚。不会逐行加载现金流水，也不会改变单独删除账户或流水时的 `RESTRICT` 语义。

备选方案是把账户、分类和现金流水的复合外键全部改成 `CASCADE`。这会改变账户级删除的既有安全边界，可能使删除账户连带删除财务记录，风险高于在工作区删除边界内显式解除依赖，拒绝采用。

### 5. 用契约测试和真实浏览器验证闭环

后端增加含 `source_type="wechat"`、账户、分类、投影及关系的删除回归，并以相同 Application Service 合同覆盖 SQLite 与可用的 PostgreSQL `_test` 数据库。前端增加切换成功/失败、深链接、旧路径规范化和删除后的 URL 状态测试；生产预览使用真实浏览器覆盖主流程、错误状态、键盘焦点及 320/375/390/414/768/1440 px 宽度。

## Risks / Trade-offs

- [显式清理表清单可能随模型增长] → 将删除顺序集中在访问服务边界，使用 FK 约束检查、工作区残留断言和双后端契约测试；新增工作区级受限表时必须补充该清单和测试。
- [深链接在选择请求完成前短暂显示认证页或加载态] → 认证壳在工作区解析完成前不挂载账本 API 页面，并保留可操作错误状态。
- [旧顶级路径与新路径并存造成链接分叉] → 旧路径只做一次规范化，所有新导航、邀请链接和删除回跳都生成 `/w/<id>/...`。
- [删除大工作区的额外集合清理增加耗时] → 保留现有活动会话索引，使用集合 `DELETE`/`UPDATE`，并以固定规模性能样本监测 p95。

## Migration Plan

1. 先部署包含前端路由和后端删除顺序的同版本，确保旧顶级路径仍能规范化。
2. 观察深链接选择失败、切换错误和工作区删除错误日志；不得记录令牌或来源行快照。
3. 回滚时同时回滚前端和 API 版本；旧路径仍可使用会话活动工作区，已成功删除的数据不提供恢复保证。

## UI Prototype and Hallmark Pre-check

- 原型路径：`prototype/index.html`，只依赖本地 HTML/CSS，不连接生产路由、API 或凭据。
- 核心流程：工作区选择后 URL 与内容同步、直接打开工作区 URL、无权访问错误、删除确认与删除失败。
- 状态覆盖：加载、正常、空工作区、切换失败、无权深链接、删除确认、删除失败和删除成功后的回跳。
- 响应式自检：原型在 320、375、414、768 px 下无横向滚动；最终实现需补 390 和 1440 px 截图。
- Hallmark 预检沿用现有 Cobalt 工作台的字体、颜色和间距 token；本次不新增页面视觉层级，不增加常驻帮助文案或卡片套卡片。
- 最终 UI 形成后对认证壳、统一路由壳和工作区管理页执行 Hallmark `audit`；critical/major finding 修复后重新审查。
