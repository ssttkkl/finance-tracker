## Purpose

定义登录后工作区在浏览器 URL 中的稳定上下文、切换和删除行为，使深链接、页面重载与工作区数据隔离遵循同一份用户可见合同。

## ADDED Requirements

### Requirement: 登录后的工作区页面使用规范 URL 上下文

系统 MUST 使用 `/w/<workspaceId>/` 作为登录后工作区页面的规范 URL 前缀，其中 `<workspaceId>` MUST 是固定工作区 ID 而不是可编辑名称；收支、分类、导入、投资和工作区管理页面 MUST 保留各自的子路径。

#### Scenario: 切换工作区更新规范 URL

- **WHEN** 使用者在当前页面从工作区 A 切换到有权访问的工作区 B
- **THEN** 浏览器 URL MUST 在保持当前子页面的前提下切换到 `/w/<B>/...`，页面 MUST 立即显示工作区 B 的内容

#### Scenario: 旧顶级路径规范化

- **WHEN** 已登录使用者打开没有工作区前缀的既有账本路径
- **THEN** 系统 MUST 将其重定向到当前活动工作区对应的 `/w/<workspaceId>/...` 路径，并保持原页面语义

### Requirement: 工作区深链接先完成成员校验再读取账本

系统 MUST 在处理带工作区 ID 的深链接时先确认当前会话用户是该工作区成员，并通过会话选择该工作区；URL 中的工作区 ID MUST NOT 单独成为账本 API 的授权依据。无权访问时系统 MUST 不得读取目标工作区数据，并 MUST 保留或恢复到当前用户仍可访问的工作区上下文。

#### Scenario: 直接打开可访问工作区

- **WHEN** 已登录使用者直接打开其成员工作区 B 的 `/w/<B>/investment-events`
- **THEN** 系统 MUST 在请求投资事件前选定工作区 B，并只返回 B 的投资事件

#### Scenario: 直接打开无权工作区

- **WHEN** 已登录使用者直接打开不属于其成员关系的 `/w/<X>/`
- **THEN** 系统 MUST 拒绝工作区选择，不得返回 X 的任何账本或成员数据，并将页面保持在可访问的工作区或显示可操作错误

### Requirement: 工作区删除必须能处理已导入现金流水

当前工作区管理员在输入名称完成二次确认后，系统 MUST 在一个事务中永久删除当前工作区及其成员、邀请、现金流水、导入映射、关系和投影数据；已导入的微信流水 MUST 随工作区删除，不得因现金流水引用账户、分类或派生投影而阻断删除。

#### Scenario: 删除包含微信流水的工作区

- **WHEN** 管理员确认删除一个包含已导入微信现金流水及其收支投影的工作区
- **THEN** 删除请求 MUST 成功返回删除后的会话状态，且该工作区、微信流水、账户、关系和投影数据 MUST 不再存在

#### Scenario: 删除过程失败回滚

- **WHEN** 工作区删除在清理依赖数据或删除工作区时发生数据库错误
- **THEN** 系统 MUST 回滚整次删除，不得留下部分删除的工作区、现金流水或会话状态

### Requirement: 工作区上下文在双后端保持等价

系统 MUST 在 SQLite 与 PostgreSQL 上对规范工作区 URL、成员校验、切换结果和工作区删除返回等价的用户可见结果；PostgreSQL 验证 MUST 使用名称以 `_test` 结尾的专用数据库。

#### Scenario: 双后端切换与删除结果一致

- **WHEN** 两个后端使用相同成员、工作区 URL 和去标识化现金流水夹具执行切换及删除
- **THEN** 两个后端 MUST 返回相同的活动工作区选择结果，并完整移除被删除工作区的数据
