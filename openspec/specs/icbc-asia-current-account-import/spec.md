# 工银亚洲活期账户导入规格

## Purpose

让使用者可以将工银亚洲活期账户导出的 CSV 安全导入为现金流水，在不丢失对方账号和原始业务行的前提下复用现有账户路由、幂等与关系检查流程。

## Requirements

### Requirement: 工银亚洲活期账户 CSV 可作为现金账单导入

系统 MUST 支持以 `--source icbc-asia` 导入工银亚洲活期账户导出的 `currentaccounthistory*.csv`，并在文件名匹配时推断同一来源。系统 MUST 仅接受 UTF-16 编码、制表符分隔且包含 `序號`、`交易時間`、空字符串时间列、`起息日期`、`業務類型`、`摘要`、`收入金額`、`支出金額`、`餘額`、`對方賬號`、`對方戶名`、`憑證號`、`匯率`、`備註`、`交易場所` 的唯一交易表头。系统 MUST 逐行使用交易日期与无标题时间列组成发生时间，使用文件级币种信息生成三位大写币种，且每笔交易的收入金额与支出金额必须恰有一个非空；`業務類型` 为 `新開戶` 或 `新开户` 且金额为零的开户提示行 MUST 跳过，不得写入正式事实。任何其他格式、币种、金额或行列数不符合要求时，系统 MUST 整批失败且不得写入正式事实。

#### Scenario: 导入收入和支出流水

- **WHEN** 使用者导入同时包含收入、支出及有效文件级币种的工银亚洲活期账户明细
- **THEN** 系统 MUST 以精确十进制写入正收入和负支出，并以账单中发生的日期和时间作为流水发生时间

#### Scenario: 拒绝无法识别的账单

- **WHEN** 使用者导入编码、交易表头、币种、金额方向或交易行列数不符合该格式的文件
- **THEN** 系统 MUST 返回可操作的错误并回滚该文件的全部导入结果

#### Scenario: 跳过零金额开户提示行

- **WHEN** 用户导入一行 `業務類型` 为 `新開戶` 或 `新开户` 且收入或支出金额为零的账单行
- **THEN** 系统 MUST 跳过该行，不得创建现金流水或来源行快照

### Requirement: 工银亚洲来源行和对方账号保持可审计

系统 MUST 对每条工银亚洲现金流水将交易表头到对应原始单元格的完整映射写入 `source_payload`，包括空值列及键为 `""` 的无标题时间列；文件级银行名称、下挂账户、账户类型、日期范围和币种信息不得进入该 JSON。系统 MUST 将原始 `對方賬號` 原样保存到 `counterparty_account`，将 `對方戶名` 保存到 `counterparty`；缺少任一原始值时对应正式字段 MUST 为空字符串，不得根据本账户、备注或文本猜测补值。

#### Scenario: 对方账号与无标题时间列完整保留

- **WHEN** 用户导入一条带有对方账号、对方户名和无标题时间列的交易行
- **THEN** 该事实的 `source_payload` MUST 与交易行的所有原始列和值完全一致，`source_payload[""]` MUST 等于原始无标题时间单元格，且 `counterparty_account` 与 `counterparty` MUST 分别等于原始对方账号和对方户名

### Requirement: 工银亚洲账户路由与业务行幂等

系统 MUST 优先从工银亚洲文件级 `銀行賬號`（兼容 `银行账号`）提取完整币种子账号；只有该字段缺失或不含可用账户标识时，才可以从 `下掛賬戶` 提取。系统 MUST 将完整币种子账号的末位视为币种区分位，并用同长度且末位标准化为 `0` 的规范账号尾号匹配 `icbc_asia_<规范账号尾号>` 加 `*` 规则，使同一规范账号的不同币种子账号路由到同一账本账户；两个字段均未提供可用账户标识时，系统 MUST 以 `icbc_asia` 和账单内工银亚洲活期账户标识路由；不得接受整文件账户覆盖。系统 MUST 以完整币种子账号（如有）、已解析的三位账单币种、已解析的账本账户和除导出序号外的原始交易内容确定 `source_type=icbc_asia` 的业务行键，使重叠导出的同一业务行不重复入账，而不同币种或不同完整币种子账号的流水不得互相去重。若同一文件中有多条在完整币种子账号、账单币种和除导出序号外原始交易内容上完全相同的交易行，系统 MUST 失败关闭，不得静默跳过其中任意一条。

#### Scenario: 同一规范账号的币种子账号路由到同一账户

- **WHEN** 两份工银亚洲账单的完整币种子账号仅末位不同，且其末位标准化为 `0` 后的规范账号相同
- **THEN** 系统 MUST 使用同一个规范账号尾号映射规则，并将两份账单的流水写入同一账本账户，各自保留账单币种

#### Scenario: 跨币种相同行不冲突

- **WHEN** 同一完整币种子账号的两份账单包含除导出序号外完全相同的交易行，但文件级账单币种不同
- **THEN** 系统 MUST 为两行生成不同业务行键，并分别以各自账单币种入账

#### Scenario: 银行账号优先于下挂账户

- **WHEN** 一份账单同时提供尾号不同的 `銀行賬號` 和 `下掛賬戶`
- **THEN** 系统 MUST 使用 `銀行賬號` 所属规范账号的尾号匹配账户映射，并以该完整币种子账号参与业务行键计算

#### Scenario: 重叠导出不重复入账

- **WHEN** 同一完整币种子账号的两份重叠导出文件仅交易序号不同，且包含相同的业务行
- **THEN** 第二次导入 MUST 跳过已存在的业务行，不得重复发布现金流水

#### Scenario: 账户映射未命中

- **WHEN** 可用的账单规范账号尾号和工银亚洲活期账户标识均未命中 `~/.ft/mapping.yaml`
- **THEN** 系统 MUST 整批失败，不得写入未知账户或部分事实

#### Scenario: 双后端等价

- **WHEN** 将同一份工银亚洲账单分别导入 SQLite 与 PostgreSQL 工作区
- **THEN** 两个后端的正式金额、币种、业务行键、`source_payload`、`counterparty_account`、路由账户和幂等结果 MUST 等价，允许代理键和时间戳字面差异

#### Scenario: 既有工银亚洲流水迁移渠道键

- **WHEN** 数据库升级前存在活跃的 `source_type=icbc_asia_current_account` 工银亚洲现金流水
- **THEN** 迁移后其 `source_type` 与以旧渠道前缀开头的 `record_id` MUST 改为 `icbc_asia`，且若会与任一活跃业务行冲突，迁移 MUST 失败且不得部分改写
