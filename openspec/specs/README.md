## 定位与维护约定

- 主规格路径为 `openspec/specs/<module>/<capability>/spec.md`，完整能力 ID 是 `<module>/<capability>`。目录使用英文，导航使用中文。
- 未完成变更的 delta 使用相同相对路径：`openspec/changes/<change>/specs/<module>/<capability>/spec.md`；proposal 中的能力 ID 也必须一致。
- 查询示例：`openspec show cash-ledger/cash-ledger-browser`。校验使用 `openspec validate --all --strict`。
- 新需求先检查对应模块及相关能力；只有缺少独立能力时才新增子目录，并更新本索引与模块导航。
- 跨模块合同只有一个主归属，其他模块使用链接；投资账单导入和连接器同步归入导入，银证转账归入投资，认证与工作区访问的现有混合规格整份归入认证。
- 目录调整不改变规格语义，也不代表未完成变更已实现。主规格继续只描述当前行为。
- 历史归档与 `legacy/` 保持原样；旧路径通过 [迁移对照](../MIGRATION.md) 查找。

## 本次整理的范围与验收

2026-09-29 经需求澄清确认：采用以上 8 个业务模块及两级目录，保留现有子能力名称与规格语义；只调整归属、导航、当前引用和未完成变更的能力路径。非目标为需求合并、业务规则改写、产品代码调整、归档或发布。

验收标准：24 份主规格、180 条需求和 440 个场景保持完整；主规格与 delta 正文逐字节一致；未完成变更使用完整能力 ID；OpenSpec 能发现、读取、校验并定位对应同步目标；新增导航链接有效，归档历史不变。执行与审查证据见 [迁移记录](../MIGRATION.md)。
