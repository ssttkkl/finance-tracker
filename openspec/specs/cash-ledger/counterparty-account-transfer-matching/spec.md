# 功能规格：对方账号转账匹配

## Purpose

让转账、提现和还款关系在不暴露账号原文的前提下，使用用户显式登记的本人账户标识和账单直接提供的对方账号收敛候选。

## Requirements

### Requirement: 本人账户标识登记与解析

系统 MUST 仅使用当前工作区 `account_aliases` 中用户显式登记的本人账户标识匹配导入期生成的 `counterparty_account` 与 `counterparty_account_attrs`。`account_identifier` 表示完整数字账号，`card_tail` 表示恰好四位数字的账号尾号。`full` 属性允许完整数字值精确匹配唯一 `account_identifier`，不存在完整命中时允许以最后四位匹配唯一 `card_tail`；`tail` 属性只允许四位值匹配唯一 `card_tail`；`masked` 属性只允许可见数字前后缀匹配符合掩码形态的已登记完整账号，或以明确可见的四位后缀匹配唯一 `card_tail`；`masked` 与 `reconstructed` 组合允许重建后的完整数字值按完整账号规则匹配。掩码规则 MUST 要求至少一个被隐藏字符，并在多个别名命中不同账户时判定为不唯一。

系统 MUST 验证属性值、顺序、组合和账号表示一致；不得根据账号长度、掩码字符、导入渠道、账单文本或来源快照推断属性。一个账户可登记多个不同 `card_tail`，这些别名都指向同一账户。系统 MUST NOT 从账户名称、账户映射、备注、对方名称或其他账单列自动创建本人账户标识。

#### Scenario: 显式完整规范账号命中
- **WHEN** 用户为一个现金账户登记唯一 `account_identifier`，且转出流水保存相同完整数字账号和 `["full"]`
- **THEN** 系统 MUST 将该账户作为目标账户，且不得向来源行快照写入别名或规范化值

#### Scenario: 唯一尾号命中
- **WHEN** 转出流水保存四位账号尾号和 `["tail"]`，且对应 `card_tail` 在当前工作区只绑定一个账户
- **THEN** 系统 MUST 识别该账户为唯一尾号目标

#### Scenario: 掩码账号唯一命中
- **WHEN** 转出流水保存掩码账号和 `["masked"]`，且可见数字前后缀只匹配一个账户的完整账号或四位后缀只匹配唯一 `card_tail`
- **THEN** 系统 MUST 识别该账户为唯一掩码目标，但不得保存匹配过程或补全来源账号

#### Scenario: 属性缺失或矛盾
- **WHEN** 非空对方账号的属性为空、未知、重复、顺序非法，或 `tail` 属性对应的值不是四位数字
- **THEN** 系统 MUST NOT 根据该账号选择目标账户或提高关系置信度

#### Scenario: 尾号或掩码冲突
- **WHEN** 同一尾号或掩码形态命中多个不同账户
- **THEN** 系统 MUST NOT 选择任一目标账户或自动确认关系

#### Scenario: 显式完整账号命中
- **WHEN** 用户为一个现金账户登记唯一 `account_identifier`，且转出流水的来源直接对方账号以相同完整数字标识出现
- **THEN** 系统 MUST 将该账户作为对方账号命中的目标账户，且不得向来源行快照写入别名或规范化值

#### Scenario: 尾号冲突或未登记
- **WHEN** 对方账号尾号未登记，或同一 `card_tail` 绑定多个账户
- **THEN** 系统 MUST NOT 根据该尾号选择目标账户或提高关系置信度

### Requirement: 对方账号约束转账候选

系统 MUST 只在资金移动转出方同时具有非空 `counterparty_account` 和合法 `counterparty_account_attrs` 时应用本人账户标识证据。完整、尾号、掩码或重建账号唯一命中时，系统 MUST 只保留落入该目标账户且满足标准记录类型、子类型、金额、币种和时间条件的候选；该证据不得绕过既有候选条件或单独创建关系。只有目标唯一的转出可使用最长 7 天的专用候选窗口，并按时间差全局一对一分配；同币种必须使用精确 Decimal 等额，跨币种不比较金额。候选账户具有已登记本人账户标识而其标识均与对方账号不匹配时，系统 MUST 排除该候选。没有可用账号归属的候选保持同一套标准字段规则；若筛选后没有候选，系统 MUST 不创建转账关系。

#### Scenario: 对方账号消除同金额候选歧义
- **WHEN** 一条转出流水有多个既有合格候选，且其带合法属性的对方账号唯一命中其中一个候选账户
- **THEN** 系统 MUST 仅使用该账户的候选继续结构化规则评估，其他候选不得形成该转出流水的关系

#### Scenario: 缺少可用对方账号证据
- **WHEN** 转出流水的 `counterparty_account` 为空，或非空账号没有合法属性
- **THEN** 系统 MUST 按标准记录字段继续评估短窗口候选，不得读取来源、账单文本或来源快照补造账号证据，也不得启用唯一账号目标的 7 天窗口

#### Scenario: 掩码命中不绕过金额条件
- **WHEN** 掩码账号唯一命中一个候选账户，但该账户中的流水不满足既有金额、币种、时间、方向或记录类型条件
- **THEN** 系统 MUST 不创建该两条流水之间的 `transfer_pair`

#### Scenario: 对方账号排除已登记但不匹配的候选
- **WHEN** 一条转出流水的候选账户均已登记本人账户标识，但其对方账号不匹配任一候选账户
- **THEN** 系统 MUST 不为该转出流水创建 `transfer_pair`

#### Scenario: 缺少对方账号保持兼容
- **WHEN** 转出流水的 `counterparty_account` 为空字符串
- **THEN** 系统 MUST 保持既有标准字段转账候选行为，且不得启用唯一账号目标的专用窗口

### Requirement: 对方账号匹配的隐私边界

系统 MUST 只在本次候选筛选中使用完整账号或尾号的命中结果，不得将命中结果或账号原文写入关系、CLI 输出、异常和日志。

#### Scenario: 关系不保留账号匹配过程
- **WHEN** 对方账号命中促成一条转账关系
- **THEN** 已创建关系 MUST 不包含来源对方账号、本人账户标识或其命中种类
