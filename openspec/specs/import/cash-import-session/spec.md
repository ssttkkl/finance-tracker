# cash-import-session Specification

## Purpose

为账单导入提供一个短期、工作区隔离且可重试的临时会话，使扫描和预览不重复上传原始账单，同时不在最终确认前写入 Neon 业务数据。
## Requirements
### Requirement: 临时导入会话保存来源但不写入业务账本

系统 MUST 在每次上传请求内解析文件并删除原始输入，不将原文件或密码保存至会话；只保存有 TTL 的解析行、当前会话分组数据和本次选择。一个会话最多 20 份文件，每份最多 100 MB。公开 API 和临时会话 MUST NOT 包含用户填写的 `source_scope_label`。微信和支付宝来源账户可返回本次会话有效的分组引用和显示标签；昵称、脱敏标签、文件名及分组引用不得成为长期身份或持久映射。各渠道已有的稳定来源身份继续依其渠道合同处理；微信不得使用昵称或来源名称建立跨导入映射。预览 MUST 不写流水、来源绑定、映射或关系；账户普通命令独立立即生效。

#### Scenario: 首次上传及删除输入

- **WHEN** 上传受支持账单
- **THEN** 返回绑定操作者和工作区的不透明会话及逐文件结果；再次预览只读解析结果，原文件不能下载或重读

#### Scenario: 独立账户生效

- **WHEN** 在导入内创建或修改账户成功
- **THEN** 该账户立即可查询和选择，退出导入不自动撤销

#### Scenario: 首次提交多份文件创建会话

- **WHEN** 使用者为当前工作区提交一组格式受支持的账单文件进行扫描
- **THEN** 系统 MUST 返回不透明的 `import_token`、批次摘要、按文件返回的摘要与识别状态，以及合并后的来源账户扫描结果
- **AND** Neon 中不得出现本次导入的业务写入

#### Scenario: 部分文件需要密码

- **WHEN** 一组文件中有一个或多个加密账单尚未提供密码
- **THEN** 系统 MUST 在同一会话保留已解析文件的结果，并只把加密文件标记为需要密码；有效文件仍可进入账户映射、预览和一次最终确认
- **AND** 密码文件需由使用者连同当次密码重新上传解析；系统不得保存原文件或密码

#### Scenario: 预览引用既有多文件会话

- **WHEN** 使用者提交有效的 `import_token` 和账户映射以请求流水预览
- **THEN** 系统 MUST 从临时会话读取已解析文件中的有效业务行并返回合并预览，保留各文件状态；需要密码的文件只有重新上传后才能加入预览

#### Scenario: 用户来源名称不进入会话

- **WHEN** 用户上传、重传或更新微信文件并读取导入会话
- **THEN** 请求、响应和会话 MUST NOT 提供或保存 `source_scope_label`，也不得提供按文件修改微信来源范围的操作

#### Scenario: 账号分组只在当前会话有效

- **WHEN** 当前会话包含多个微信昵称或支付宝账号的文件
- **THEN** 相同微信昵称或相同支付宝账号的来源资金方式可共用本次分组引用；缺少昵称或账号时按文件分别分组
- **AND** 分组引用、昵称、脱敏显示标签和文件名 MUST NOT 进入来源绑定或跨导入账户映射，且随会话到期；其他渠道可按各自既有合同继续使用可信来源身份

### Requirement: 会话必须绑定工作区并在期限后失效

会话、不可变计划和临时重试内容 MUST 绑定操作者和工作区且有限期；每次文件或选择改变 MUST 比较修订并使旧计划失效。读取不得隐式无限续期，过期返回安全可识别错误；已经提交的收据不随会话过期。文件变化后，系统 MUST 保留必要的选择重验证明，使未受影响的延后／忽略决定能继续校验；旧计划仍不可读取或提交，证明不得授权新的对侧。

#### Scenario: 跨工作区访问

- **WHEN** 另一工作区或操作者使用会话标识
- **THEN** 拒绝且不泄漏内容

#### Scenario: 两个请求重预览

- **WHEN** 两个请求使用相同会话修订
- **THEN** 最多一个发布成功，提交只接受当前最新计划

#### Scenario: 完整选择经历连续文件变更

- **WHEN** 用户已有配对决定，再追加、替换、移除文件或修改文件来源
- **THEN** 旧计划失效；新的完整预览能重验保留的决定，不因旧证明丢失整体失败，不清空无关决定以恢复自动确认

#### Scenario: 跨工作区使用多文件令牌

- **WHEN** 使用者把一个工作区创建的 `import_token` 用于另一个工作区的预览或提交
- **THEN** 系统 MUST 拒绝请求且不得返回任何原始文件、扫描结果、预览流水或关系候选

#### Scenario: 文件集合发生变化

- **WHEN** 预览或提交请求对应的文件摘要集合、文件顺序或批次摘要与会话不一致
- **THEN** 系统 MUST 拒绝请求并要求重新扫描整组文件
- **AND** MUST 不写入部分账户映射、现金流水、交易关系或投影

#### Scenario: 会话过期

- **WHEN** `import_token` 超过配置的临时会话有效期
- **THEN** 系统 MUST 返回可识别的会话过期错误，并删除或异步清理该会话的临时对象

### Requirement: 关系决定只在最终确认时提交

关系决定 MUST 通过服务端计划管理；Compose 统一预计流水列表及详情只读，HTTP／Agent 可以按当前计划合法候选接受、延后、忽略和选择共同值，流水、映射及关系只有一次最终提交。未确认关系默认作为草稿保存；强建议拟确认也不得提前写入。单项详情 MUST 按当前冻结计划的明确引用提供当前组及候选的真实只读成员字段，不用预计合并摘要代替；旧选择失效后，用户对最新计划中的当前组明确重选 MUST 能生效；未重选的受影响组仍待确认，旧选择或旧指纹恢复不能自动确认。

#### Scenario: 暂不处理关联

- **WHEN** 两条正式流水的关联未确认并点击确认导入
- **THEN** 两笔正式流水及草稿关联一起保存，两项分别展示并统计

#### Scenario: 保留旧输入并明确重选当前组

- **WHEN** 完整输入同时带旧失效选择及用户从最新计划明确选择的合法当前组
- **THEN** 当前组采用新的接受／忽略决定，其余失效组继续延后，不受数组顺序影响；最终关系校验照常执行

#### Scenario: 预览阶段修改关系

- **WHEN** HTTP／Agent 在当前计划接受、忽略或选择合法关系候选但尚未点击「确认导入」
- **THEN** 系统 MUST 不创建或修改 当前显式数据库中的交易关系及收支投影

#### Scenario: 模型版本变化
- **WHEN** 未消费计划在关系模型或合法性版本变化后提交
- **THEN** 系统 MUST 要求重新核对，不能静默转换旧决定；已成功提交的同键请求仍返回原收据

### Requirement: 最终确认必须幂等且可安全重试

最终确认 MUST 消费服务端不可变计划，按操作者、工作区、幂等键和唯一上下文防重复消费。可执行流水、来源证据、账户映射、关联、余额、投影及收据 MUST 在同一外层事务原子发布。预览已知的文件问题、业务跳过和合法缺项草稿不阻止确认；提交重验发现计划依赖变化或任何新增执行异常 MUST 拒绝整次提交并回滚，不将其变成逐行跳过、局部成功或新增待处理问题。已明确未进入提交调用的失败 MUST 返回 `commit_state=not_committed`；提交结果无法确定时 MUST 保留原命令核实。成功收据保留 `commit_outcome` 的实际写入事实；旧收据缺省字段不推算。

#### Scenario: 响应丢失后重试

- **WHEN** 相同计划与幂等键再次提交
- **THEN** 返回原收据，不重跑，即使临时会话已清理

#### Scenario: 不同键重复消费

- **WHEN** 已成功消费会话再次使用另一个键
- **THEN** 不写入并返回有权访问的收据引用

#### Scenario: 账户或关系依赖发生变化

- **WHEN** 普通账户映射失效、流水修订变化或已核对关系不再合法
- **THEN** 本次提交拒绝，全部业务写入回滚且不发布收据；提示重新核对，不自动换账户或逐项继续

#### Scenario: 任一业务保存失败

- **WHEN** 流水、来源证据、关系、映射、余额、投影或收据保存发生异常
- **THEN** 本次全部写入回滚；确定未提交时返回安全错误及 `not_committed`，无法确定结果时核实原请求

#### Scenario: 内部配对发现异常

- **WHEN** 预览的配对扫描发生非预期异常
- **THEN** 预览失败，不递归拆分重跑、不发布可提交计划，也不生成持久待处理问题

#### Scenario: 预览已知问题

- **WHEN** 用户确认的计划已显示文件失败、固定字段冲突或合法缺项草稿，提交没有新增异常
- **THEN** 原子保存全部可执行项及实际摘要，不把已知问题误报为提交新增异常

#### Scenario: 多文件导入网络错误后重试确认

- **WHEN** 最终确认请求在客户端收到超时或 `503`，随后使用同一会话和幂等键重试
- **THEN** 系统 MUST 只执行一次包含全部文件流水和关系决定的数据库事务
- **AND** MUST 返回稳定的导入计数与关系结果

### Requirement: 临时来源遵守隐私和清理边界

解析内容 MUST 仅由受控服务存储，来源正文、密码、令牌和路径不得进入日志；成功提交后临时内容及时清理，失败提交沿用原会话及到期时间。永久收据 MUST 不保存原账单正文或完整差异。生产临时存储未配置时失败关闭。系统 MUST NOT 创建失败子集正文、重试胶囊、派生子会话或成功项消费链；公开 API 和共享客户端移除逐项失败派生重试。原请求幂等重放、结果核实及历史收据读取 MUST 保留。

#### Scenario: 提交失败后处理

- **WHEN** 本次提交明确未保存
- **THEN** 用户可重新核对当前会话或重新选择账单；不保留失败子集派生能力，不延长原 TTL

#### Scenario: 历史收据读取

- **WHEN** 读取已有部分完成收据
- **THEN** 保留真实历史摘要和归属，不重写账本，也不依据旧重试字段开放派生入口

#### Scenario: 成功确认后的多文件清理

- **WHEN** 最终 Neon 事务成功提交
- **THEN** 系统 MUST 清理会话内全部文件及扫描、预览和结果对象，并使原 `import_token` 不能再次提交

#### Scenario: 存储配置缺失

- **WHEN** 生产环境未配置 R2 会话存储所需的完整凭据或 Bucket
- **THEN** 系统 MUST 失败关闭并返回可操作的服务配置错误，不得把原始账单静默写入 Render 本地文件系统

### Requirement: 文件级扫描状态可分别重试且有效文件可继续

文件 MUST 分别返回就绪、部分可用、需密码或失败；可处理文件及可辨认业务行 MUST 不被其他文件问题阻塞。重试需原文件及当次密码，删除或替换文件只改变对应临时解析内容。全部无业务行时只显示文件结果。

#### Scenario: 某文件无法解析

- **WHEN** 一份文件失败而其他文件有可辨认行
- **THEN** 允许预览并导入其余记录，显示失败原因且不伪造整文件草稿

#### Scenario: 单行解析异常

- **WHEN** 可定位的一行解析失败
- **THEN** 该行跳过并返回安全原因，继续处理其他行

#### Scenario: 所有文件扫描完成

- **WHEN** 会话内每个文件都已成功识别并解析
- **THEN** 系统 MUST 返回合并后的来源账户分组并允许进入账户映射

#### Scenario: 部分文件失败仍可继续

- **WHEN** 会话内至少一个文件无法识别渠道或解析失败，且另有文件已就绪或部分可用
- **THEN** 系统 MUST 返回失败文件的可操作错误，并允许已就绪文件进入账户映射、预览和一次最终确认
- **AND** 不得为失败文件伪造草稿或业务结果；全部文件均无业务行时只显示文件结果

#### Scenario: 密码只在当前请求使用

- **WHEN** 使用者重新上传一个或多个加密文件并在该次解析请求提交密码
- **THEN** 系统 MUST 按文件将密码仅用于当前受限请求
- **AND** 密码 MUST NOT 写入临时会话对象、响应、日志、浏览器持久化或业务数据

### Requirement: 导入只应用通过关系图校验的自动候选

现金导入会话 MUST 保持现有关系匹配规则和业务含义，只把自动匹配结果中已经通过当前工作区完整关系图校验的候选带入预览、确认计划和最终确认。匹配器内部产生但未通过校验的结果 MUST 在接受边界被丢弃并记录服务端脱敏警告，不得以自动关系或自动 `pending_review` 关系保存到临时会话、确认请求或最终业务数据库，也不得向用户展示告警原因。确认阶段 MUST 对仍存在的自动候选重新校验当前关系图、工作区、预览上下文、精确金额和幂等键；校验失败时不得自动替换对侧、补齐关系或静默降级关系状态。

#### Scenario: 完整退款钻石按既有匹配语义进入确认

- **WHEN** 既有匹配结果包含消费镜像、退款镜像和两端 `refund_offset`，且完整关系图通过投影校验
- **THEN** 临时会话 MUST 按现有关系语义保存这些自动关系决定
- **AND** 最终确认 MUST 在同一事务中应用完整关系结果，投影 MUST 将镜像退款只计算一次

#### Scenario: 非法自动结果只告警且不进入导入流程

- **WHEN** 自动匹配内部结果加入当前关系图后会造成关系冲突、未折叠退款超额或投影非法
- **THEN** 临时会话 MUST 不保存该结果为自动关系或自动 `pending_review` 决定
- **AND** 预览、确认请求和最终数据库 MUST 不包含该结果
- **AND** 服务端 MUST 记录脱敏警告，页面和接口响应 MUST 不展示警告原因
- **AND** 其他合法现金流水 MUST 仍可被确认导入

#### Scenario: 合法但不唯一的关系保持待审核语义

- **WHEN** 自动匹配结果存在多个合法对侧或证据不足，但候选本身通过完整关系图校验
- **THEN** 导入会话 MUST 按现有业务语义展示和保存待手动配对决定
- **AND** 系统 MUST NOT 因合法性闸门自动选择、补齐或重排对侧

#### Scenario: 合法自动候选进入确认

- **WHEN** 自动候选在预览时通过完整关系图校验，且确认时导入会话、工作区、账本事实和活动关系未发生变化
- **THEN** 系统 MUST 在最终事务中按原端点、原关系类型和既有匹配语义原子应用该候选
- **AND** 事务提交后的关系图和收支投影 MUST 继续通过同一合法性约束

#### Scenario: 预览后的关系图使自动候选失效

- **WHEN** 预览完成后当前工作区的账本事实或活动关系发生变化，使缓存的自动候选不再满足关系图约束
- **THEN** 系统 MUST 拒绝使用该缓存候选并要求重新生成关系建议
- **AND** 系统 MUST 记录内部脱敏警告
- **AND** 系统 MUST NOT 选择另一条流水、补齐缺失关系或把它保存为非法待审核关系

#### Scenario: 非法候选不阻塞合法导入重试

- **WHEN** 相同导入会话以相同幂等键重试，且其中一个自动候选已被关系图校验排除
- **THEN** 系统 MUST 保持该候选排除状态并按告警去重或聚合规则记录
- **AND** 合法业务行和合法关系决定 MUST 按幂等语义返回相同结果，不得因被排除的候选产生投影校验错误

### Requirement: 导入预览每笔只接受一个有效行决定

导入预览 MUST 对同一共同来源操作最多接受一个 `row_choices` 决定，即使重复行提交相同内容也不得将多个决定合并为业务跳过。`keep_existing` MUST 仅适用于已有对应流水；新流水、无法对应的来源行及无可执行操作的行不得选择它。显式行补丁的字段、值、分类及动作组合 MUST 在预览输入边界校验。非法决定 MUST 在预览阶段以 `plan_input_invalid` 拒绝，不发布新计划或写入业务账本，也不把输入错误降为逐行跳过；账单本身不可解析或财务事实冲突仍由既有行级规则处理。未提供行决定时继续采用当前默认规则，已有流水的合法保留决定仍可用。

#### Scenario: 同笔来源行提交多个决定

- **WHEN** 两份账单中的行共同指向一笔操作，客户端分别为两行提交决定，无论内容相同或不同
- **THEN** 预览拒绝整个输入并返回 `plan_input_invalid`，不把该笔及其别名记为跳过

#### Scenario: 新流水选择保留当前

- **WHEN** 尚无对应现有流水的来源行提交 `keep_existing`
- **THEN** 预览拒绝该选择并返回 `plan_input_invalid`，不生成“未选择导入”的结果

#### Scenario: 已有流水只作一项保留决定

- **WHEN** 已对应现有流水的一组同批来源行只提交一项 `keep_existing`
- **THEN** 预览保留该已有流水值，同批别名按共同操作处理，不额外创建流水

#### Scenario: 显式补丁含无效字段或值

- **WHEN** 客户端在行决定中提交不可编辑字段、无效流水类型、不属于当前工作区的分类、不可用的显式账户或互相矛盾的完整分摊
- **THEN** 预览拒绝输入并返回 `plan_input_invalid`，不把该行记为业务跳过；移除非法补丁后，其余合法来源行仍按原规则规划

#### Scenario: 冻结后的显式输入失效

- **WHEN** 预览时有效的显式行补丁在提交重建时因账户停用等当前事实变化而不再合法
- **THEN** 提交返回 `plan_changed` 和 `commit_state=not_committed`，不写入任何流水或收据，用户重新核对后重试；已提交请求仍优先返回原收据

### Requirement: 导入整笔公共修改具有明确计划目标

预计详情 MUST 返回服务器授权的完整收支编辑引用 `entry.edit_ref`；`entry_choices` 仅接受该目标可编辑的公共字段及明确清空。选择与来源行决定独立，不能借公共编辑改变来源采用、保留、延后或原文。目标绑定完整预计成员及既有对象／关系依赖，上次计划未授权或目标已变化 MUST 拒绝，不猜测首个来源行。文件变化清除计划时同步清除旧整笔选择；相同有效计划可以恢复原选择。

#### Scenario: 混合新旧成员整笔编辑

- **WHEN** 预计合并含新流水和无本次来源操作的既有成员，用户修改公共备注
- **THEN** 预览显示共同值，确认后只修改最终完整公共对象，来源原文不变；实际写入计入 `updated_entries` 及业务保存事实

#### Scenario: 目标依赖保存失败

- **WHEN** 被编辑预计对象的必要来源操作或合法关系保存失败，即使最终成员未扩大
- **THEN** 整次命令回滚且不发布成功收据；提交前已权威排除旧消费且尚未开始提交时返回 `commit_state=not_committed`，不误标数据库提交后的未知结果

### Requirement: 导入账户选择按当前资金资格重验

导入预览和提交 MUST 按稳定账户 ID、当前工作区、存在、启用、允许类型及最终父流水和全部支付组成项实际需要的币种重验。导入选择携带的账户修订 MUST NOT 单独作为拒绝条件；名称、纯修订及无关币种变化不使有效选择失效。来源映射或显式行补丁的账户失去所需资格时，MUST 拒绝整次提交；尚未写入时返回确定未提交，已开始事务的业务写入全部回滚。普通账户命令的严格修订约束不变，既有正式流水普通可变字段更新不新增账户启用要求。

#### Scenario: 展示变化不阻止保存

- **WHEN** 选择账户后，仅账户名称、纯修订或无关币种发生变化，当前所需资格仍满足
- **THEN** 新流水、草稿转正式及人工资金补丁均可继续预览和提交，不要求用户重新选择

#### Scenario: 最终分摊账户失效

- **WHEN** 预览后，一条未显式修改资金字段的流水所映射账户被删除、停用或移除所需币种
- **THEN** 整次提交拒绝并提示重新核对，不发布部分成功收据或改变为另一种草稿结果

### Requirement: 微信来源选择不阻塞普通导入

微信账单 MUST 使用该工作区固定的内部 `source_scope_key`，不得由用户在页面、请求、文件或会话中设置来源名称或来源范围。固定来源范围 MUST NOT 阻止普通账单导入；昵称只可用于当前会话的资金账户分组，不能决定来源身份。

#### Scenario: 微信账单不要求来源名称

- **WHEN** 用户上传一个或多个微信账单文件
- **THEN** 无来源设置入口或来源范围修改命令，所有文件使用工作区固定的 `source_scope_key` 并继续进入正常账户选择流程
- **AND** 昵称只区分当前会话中的账号组，不改变来源身份

### Requirement: 提交结果未知可以权威终结

系统 MUST 提供按键收据查询和提交状态核实。未查到收据不代表未提交；核实与提交使用同一工作区同步边界，只有确认计划永久不可执行且无收据才返回未提交。

#### Scenario: 过期计划且无收据

- **WHEN** 在途提交退出同步边界后计划已永久过期且没有收据
- **THEN** 返回未提交，允许重新导入；旧请求不得之后再执行

#### Scenario: 同一会话由另一计划完成提交

- **WHEN** 客户端保留旧计划的未知请求，而同一操作者已用同会话的新计划完成提交
- **THEN** 核实返回该会话的确定提交结果；客户端接收实际结果，丢弃旧预计信息，不重复提交或永远停在未知状态；其他会话及普通任意收据不能借此绕过归属检查

#### Scenario: 明确未提交后的退出

- **WHEN** 原请求已明确未提交或核实为可重试，使用者选择结束导入
- **THEN** 客户端保留原冻结请求及恢复键，先取消同一会话；只有服务端确定取消或会话已结束且本机清除成功后，才允许账户退出补偿

#### Scenario: 原计划被替换后退出

- **WHEN** 核实旧计划未提交，但同一会话已有新的可执行计划
- **THEN** 旧计划未提交不代表会话已关闭，退出仍须取消当前会话；若提交抢先成功，读取实际收据后再决定账户处理

### Requirement: 旧导入收据迁入统一结果而不伪造证据

旧导入提交结果 MUST 保留原 ID、归属、键、时间、实际非负计数及账户计数，迁入同一命令收据结构后移除旧表及旧写入。旧摘要 MUST NOT 伪装成新上下文消费证明，不补造逐项结果或失败重试正文，不保存原文件及技术正文；缺失的结果字段不猜测。特殊旧键 MUST 可在原用户和工作区范围内按原值查询，读取兼容不放宽新写入键规则，日志不得暴露查询键。目标碰撞及不合法摘要 MUST 在迁移前完整拒绝，不丢结果或改键。已有旧收据迁入后，不能还原技术字段的降级 MUST 在修改 schema 前拒绝；无旧收据时可恢复空旧表。

#### Scenario: 多个旧键共用文件摘要

- **WHEN** 两个合法旧收据具有同一摘要但不同键
- **THEN** 都保留真实结果，不触发新上下文唯一消费冲突，也不生成逐行结果

#### Scenario: 特殊旧键与其他用户

- **WHEN** 原用户按包含斜杠或 Unicode 的旧键查询，或另一用户使用相同键
- **THEN** 原用户取得自己的安全摘要，另一用户不能读取该结果，访问日志不出现键

#### Scenario: 迁移碰撞或坏计数

- **WHEN** 旧收据与目标 ID／用户键碰撞，或包含不合法计数
- **THEN** 升级失败且保留迁移前数据，不部分迁入或静默跳过

#### Scenario: 有损降级被拒绝

- **WHEN** 统一收据中已有迁入的旧结果，尝试降至旧结构
- **THEN** 修改 schema 前拒绝，原收据及账本不变，不通过删收据强行降级

### Requirement: 意外导入错误提供统一且准确的来源定位

文件读取、格式转换、行规划、批量写入、关系发现或提交、余额、当前列表及最终数据库提交未被业务规则处理的异常，以及提交重验和关系确认的已知冲突，MUST 经过统一诊断边界。响应或临时文件错误 MUST 包含随机错误编号、处理阶段、定位精度和有界的来源位置；精确输入记录、相关范围、文件和整次命令 MUST 区分。CSV／TSV 使用来源记录序号，Excel 使用工作表行；PDF 只在已有证据时给页／表／行，不猜物理行。无法定位时 MUST 明确只给阶段，不为定位拆批重放或指定某行背锅。诊断 MUST NOT 改变原子回滚、幂等或未知结果核实。

客户端 MUST 仅接收白名单诊断字段，不接收异常原文、SQL、路径、密码或账单正文。服务端 MUST 使用同一错误编号记录异常类型与完整调用帧，不记录异常文本、SQL 参数、局部变量、文件名、原幂等键或原始内容；重复包装只记录一次，诊断记录失败不能掩盖原异常。文件诊断仅随原临时会话 TTL 保存；不新增永久诊断表或成功收据中的异常正文。

#### Scenario: 某条转换器出现内部异常

- **WHEN** 转换某文件的已定位来源记录时发生内部异常
- **THEN** 文件错误携带转换阶段、该文件及记录位置和错误编号；服务端同编号记录调用帧，不把异常降成静默单行跳过

#### Scenario: 批量 SQL 或关系组保存失败

- **WHEN** 某批写入或完整关系组保存异常，现有上下文只能确定相关多条流水
- **THEN** 整次回滚，错误标记相关范围并返回有界成员位置及总数，不认定其中任一行为根因，也不拆分重跑

#### Scenario: 最终数据库提交响应无法确定

- **WHEN** 最终提交调用异常且不能确定数据库是否生效
- **THEN** 返回整次命令阶段和诊断号，保持 `commit_state=unknown`，不附虚构行号或直接重新导入

#### Scenario: 日志与公开信息不泄漏原文

- **WHEN** 底层异常包含密码、来源字段、SQL 参数或路径
- **THEN** 前端和诊断日志均不含这些原文；日志只保留异常类型与模块／函数／行号组成的调用帧，且日志失败不影响回滚及原错误响应

#### Scenario: 关系或流水修订在提交重验时变化
- **WHEN** 提交重验或关系确认因已知修订或占用变化拒绝
- **THEN** 系统保留原有冲突状态码、安全原因及明确未提交证明，并返回对应阶段、可证实相关范围和错误编号
- **AND** 普通表单校验与密码状态不因此产生内部故障日志或额外处理流程

### Requirement: 导入步骤与账户分组只呈现一次当前步骤

导入任务 MUST 只用一个层级表达当前步骤名称，步骤条使用“文件／账户／核对”，MUST 区分已完成、当前和未开始。步骤条、内容列和底部操作 MUST 使用一致的水平对齐基准。本次账单仅含一种来源渠道时，MUST 直接列出来源账户，不显示渠道标题或“合并不同渠道的同名账户”；至少含两种来源渠道时，MUST 按渠道分组并显示该开关。渠道种类依据来源账户的 `sourceType` 判断，不依据文件数量。

#### Scenario: 当前步骤名称

- **WHEN** 使用者进入账户准备步骤
- **THEN** 页面 MUST 不重复显示同一句步骤标题
- **AND** 步骤条 MUST 能识别已完成、当前和未开始步骤

#### Scenario: 对齐与分组

- **WHEN** 在桌面宽度查看导入准备步骤
- **THEN** 步骤条、内容列和底部操作 MUST 对齐到同一 720 dp 内容列边界
- **AND** 各账户分组 MUST 使用一致的标题结构

#### Scenario: 单渠道包含多个来源账户

- **WHEN** 本次账单的多个来源账户都属于同一种来源渠道
- **THEN** 页面 MUST 直接列出账户名称和对应账户选择控件，不显示渠道分组标题或跨渠道同名合并开关
- **AND** 账户行 MUST 保留本次来源的昵称或脱敏账号以区分同名资金账户，不因隐藏分组标题丢失来源身份

#### Scenario: 多渠道账户

- **WHEN** 本次账单的来源账户含至少两种不同 `sourceType`
- **THEN** 页面 MUST 按渠道分组账户，并显示“合并不同渠道的同名账户”开关

### Requirement: 导入核对列表与账本行保持一致

导入核对列表 MUST 复用账本与关联搜索的瀑布流组件，包括时间分组表头、吸顶表头、右侧滚动条、分组容器、行与列标题。月度收支合计 MUST 在导入核对启用，基于整份预计结果中具有统计资格的收支，按当前筛选、本地月份、币种及收入／支出经济类型汇总；退款按其支出经济类型抵减支出，转账及未知金额不虚构金额。不得只对已加载分页求和。连续记录只由分隔线区分。桌面“流水类型”列 MUST 首行显示预计主流水类型及适用的子类型，下一行显示具体待处理原因的有底色标签；普通已确认记录 MUST NOT 常驻状态标签。待处理行 MUST 使用警告色底色。Compact 卡片的待处理原因 MUST 留在记录信息区。桌面行 MUST 整行可打开详情，不显示行尾小眼睛。

#### Scenario: 核对列表的状态和分组

- **WHEN** 用户在桌面核对同一月份的普通记录与待确认记录
- **THEN** 连续记录 MUST 使用一致的分组圆角与行间分隔
- **AND** “流水类型”列 MUST 显示主流水类型及适用的子类型，下一行显示“草稿待补充”“配对建议”或“账单更新待核对”等具体原因的有底色标签
- **AND** 待处理行 MUST 使用警告色底色，普通已确认行不显示常驻状态标签

#### Scenario: 核对列表滚动与打开

- **WHEN** 使用者滚动导入核对列表并打开一笔收支
- **THEN** 当前时间分组表头与可选收支合计 MUST 固定在列表顶部，右侧滚动条 MUST 保持可用
- **AND** 桌面行 MUST 通过整行打开详情，末尾不得显示小眼睛或预留空列

#### Scenario: 待确认筛选下的月度合计

- **WHEN** 本次预计结果跨多个分页，用户从全部切到待确认
- **THEN** 每月收支合计 MUST 依据整份计划中对应筛选的有统计资格项目计算，不受当前已加载页数影响
- **AND** 退款 MUST 按支出抵减，转账和金额未知的草稿 MUST 不产生虚构合计

#### Scenario: 已保存计划缺少本次展示合同

- **WHEN** 旧导入计划缺少月度汇总依据或主流水类型字段
- **THEN** 读取预计结果、翻页或确认导入 MUST 返回 `plan_changed`，不得把缺失字段当成空汇总或空类型展示；核实未提交的原命令 MUST 返回 `not_committed`，携带旧计划标识和当前会话修订重新预览 MUST 能生成完整的新计划
