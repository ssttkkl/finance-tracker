# 投资账单导入

## Purpose

定义券商 CSV、PDF 和其他受支持文件导入为统一投资事件时的来源动作映射、核对、来源说明和安全处理行为。

## Requirements

### Requirement: 受支持券商账单导入为统一投资事件
系统 MUST 支持已声明的券商账单格式，并将交易、资金、收入、支出、认购、调整和快照映射为统一投资事件。每个导入渠道必须声明可接受的文件结构、编码、必需字段、币种和动作映射，未知结构必须整批失败。

#### Scenario: 导入东方证券账单
- **WHEN** 使用者提交结构和字段均符合合同的东方证券账单
- **THEN** 系统 MUST 导入交易与非交易业务行，保留来源净现金和可安全识别的交易总费用

#### Scenario: 导入 IBKR 或 Charles Schwab 账单
- **WHEN** 使用者提交受支持版本的 IBKR Activity CSV 或 Charles Schwab Transaction History CSV
- **THEN** 系统 MUST 按对应来源合同生成统一投资事件，并拒绝未声明的列结构或动作

### Requirement: uSmart HK 加密月结单可安全导入
系统 MUST 支持使用显式密码解密并导入受支持的 uSmart HK 月结单 PDF，解析交易明细、非交易资金、期末余额和持仓核对信息。密码和原始账单隐私不得进入日志或仓库证据。

#### Scenario: 成功导入加密月结单
- **WHEN** 使用者提供有效密码和受支持版本的 uSmart HK 月结单
- **THEN** 系统 MUST 生成统一投资事件和核对结果，并保留业务行级来源证据

#### Scenario: 密码错误或 PDF 结构变化
- **WHEN** 密码错误、PDF 无法解析或表格结构不符合已声明版本
- **THEN** 系统 MUST 整批失败且不创建任何投资事件

### Requirement: 来源动作和来源说明保持独立
导入器 MUST 保存来源原生动作以支持审计和受控重建，同时把面向使用者的原始描述、备注、动作或旗标保存为来源说明。来源说明不得写入业务行标识、系统校准文案或派生费用，也不得参与后续分类、关系匹配和投影计算。

#### Scenario: 来源没有可读说明
- **WHEN** API 或账单业务行没有面向使用者的描述、备注、动作或旗标
- **THEN** 投资事件的来源说明 MUST 为空字符串，不得以记录 ID 或金额摘要填充

### Requirement: 投资导入保留完整来源行快照
每个账单派生投资事件 MUST 保存导入渠道、业务行标识、完整来源行快照和未提升为正式字段的扩展业务信息。正式字段可以由来源行派生，但不得反写到来源行快照。

#### Scenario: 来源动作被规范化
- **WHEN** 一个来源动作被映射为规范投资事件记录类型
- **THEN** 来源行快照 MUST 保留原始动作，正式记录类型单独保存规范值

### Requirement: 期末余额和持仓核对不伪造交易
账单提供的期末现金余额或持仓 MUST 作为明确的快照或核对证据处理，不得为消除差异而静默发明交易。无法解释的差异必须以可见核对结果或受控调整表达。

#### Scenario: 账单期末持仓与重放结果不一致
- **WHEN** 导入业务行重放所得持仓与账单期末持仓不同
- **THEN** 系统 MUST 暴露差异并按来源合同决定是否生成明确快照，不得修改既有交易数量来隐藏差异

### Requirement: 券商导入保持行级幂等和双后端等价
相同业务行在重复文件和重叠导出中 MUST 只产生一个投资事件。PostgreSQL 与 SQLite 必须对相同去标识化账单产生等价事件、来源证据、余额和持仓结果。

#### Scenario: 重叠券商导出
- **WHEN** 第二份券商账单包含已经导入的业务行和新增业务行
- **THEN** 系统 MUST 只新增未存在的投资事件，并保持既有事件不变
