# 投资连接器同步

## Purpose

定义投资连接器从加密交易所和 Polymarket 等数据源增量读取活动、保护凭据并幂等写入统一投资事件的行为。

## Requirements

### Requirement: 加密交易所活动同步为统一投资事件
系统 MUST 允许受支持连接器读取交易所的私有交易和资金账本活动，并把数据源记录 ID 保存为稳定业务行标识后映射为统一投资事件。连接器不得引入数据源专用的第二套账本模型。

#### Scenario: 同步交易和资金活动
- **WHEN** 使用者为受支持交易所配置有效凭据并执行同步
- **THEN** 系统 MUST 导入游标范围内的新活动，保留数据源 ID 和来源证据，并返回处理计数

### Requirement: Polymarket 活动使用稳定资产标识
系统 MUST 将 Polymarket BUY 和 SELL 活动映射为 `trade(security)`，使用稳定市场与结果标识表达预测市场资产，并保留 Activity ID 作为业务行标识。

#### Scenario: 同步 BUY 活动
- **WHEN** Polymarket 返回一个具有唯一 Activity ID 的 BUY 活动
- **THEN** 系统 MUST 生成从现金资产换入对应市场结果资产的 `trade(security)`，且重复同步不得生成第二条事件

### Requirement: 连接器凭据保持最小暴露
连接器 MUST 从仓库外受控配置读取所需凭据，验证缺失或非法配置，并确保日志、错误、来源行快照和导出不包含 secret、Token、私钥或完整认证头。

#### Scenario: 凭据缺失
- **WHEN** 使用者执行需要私有 API 的同步但未提供必需凭据
- **THEN** 系统 MUST 在发起外部请求前失败，并只说明缺失的配置名称

#### Scenario: 数据源返回认证错误
- **WHEN** 外部数据源拒绝认证
- **THEN** 系统 MUST 返回脱敏错误，不得回显凭据或签名材料

### Requirement: 同步游标只优化读取范围
连接器 MUST 可以保存同步游标以缩小后续读取范围，但游标不得替代业务行幂等。游标丢失、回退或重放时，既有数据源记录必须通过业务行标识去重。

#### Scenario: 游标丢失后全量重放
- **WHEN** 本地同步游标丢失且连接器重新获取已经导入的历史活动
- **THEN** 系统 MUST 不创建重复投资事件，并恢复到新的可继续游标

#### Scenario: 同步部分失败
- **WHEN** 外部请求成功但正式提交前发生错误
- **THEN** 系统 MUST 不推进游标，也不得发布部分事件

### Requirement: 同步后持仓可及时核对
成功提交的新投资事件 MUST 能被既有持仓重放和查询读取。数据源提供当前现金或持仓校准能力时，校准必须以明确快照表达，不得覆盖历史事件或伪造交易。

#### Scenario: 同步后查询持仓
- **WHEN** 一次同步成功导入新的交易事件
- **THEN** 后续持仓查询 MUST 基于这些事件返回更新后的数量和成本

#### Scenario: 校准 Polymarket 当前现金
- **WHEN** 使用者执行受支持的 Polymarket 现金校准
- **THEN** 系统 MUST 写入明确现金快照或校准事件，并保留来源和发生时间
