# 收支账本浏览

## Purpose

定义收支账本基于已确认关系生成投影、筛选、分页、证据详情和可访问 Web 浏览体验时的完整行为，确保关系影响、金额、来源与时间在双后端和不同浏览器环境中保持可核对。

## Requirements

### Requirement: 收支账本展示关系处理后的投影

系统 MUST 让每条活动现金流水恰好归属一个收支投影。没有生效关系的流水形成单源投影；同笔支付只展示一次；退款冲销原消费；内部转账显示但不计入收入、支出和月度汇总；全额退款、全额平台退回和余额校准投影保留但不出现在列表中。部分退款和部分平台退回只抵扣原始支出的剩余金额。Web API MUST 只为当前已登录成员的选定工作区返回投影。

#### Scenario: 浏览同笔支付
- **WHEN** 两条现金流水通过已确认 `payment_mirror` 表示同一笔消费
- **THEN** 收支账本 MUST 只显示一个消费投影，并在证据详情中展示相关记录

#### Scenario: 浏览银证转账
- **WHEN** 收支投影对应已确认现金—投资资金调拨关系
- **THEN** 列表和详情 MUST 显示“银证转账”及其现金与投资账户两端金额，且不得计入外部收支

#### Scenario: 浏览已确认平台退回
- **WHEN** 支付平台退回与原始出账通过已确认 `refund_offset` 组成全额冲销
- **THEN** 收支账本 MUST 不得把退回显示为独立收入；证据详情 MUST 保留两条关联现金流水及其来源

### Requirement: 证据详情只展示可核对业务信息

收支详情 MUST 优先展示金额、交易对方、发生时间、账户、收支分类路径和备注；来源、原始账单和关联记录等核对信息必须进入详情的次级区域或默认折叠区。收支分类必须作为整笔收支详情的共享字段查看和修改，不得把成员流水展示为互相冲突的分类。界面不得暴露投影、数据库代理键、分类 ID 路径、底层审计表结构或不存在的角色。

#### Scenario: 查看单源投影
- **WHEN** 使用者打开没有采用关系的单源投影
- **THEN** 详情 MUST 展示该记录自身字段和收支分类或无分类状态，导入渠道进入次级核对信息，且不得显示空的关联记录区域

#### Scenario: 查看关系投影
- **WHEN** 使用者打开采用同笔支付或退款关系的投影
- **THEN** 详情 MUST 显示整笔收支详情共享的分类，并在次级核对信息中逐条显示关联记录，不得用实现术语解释组成方式

### Requirement: 投影发布和分页保持一致
收支投影 MUST 以工作区为边界原子发布一致版本。分页游标必须绑定投影版本、排序键和筛选条件；源数据或关系变化导致版本更新后，旧游标必须明确失效。

#### Scenario: 连续翻页
- **WHEN** 投影版本和筛选条件保持不变
- **THEN** 连续翻页 MUST 不重复或遗漏同一排序范围内的投影条目

#### Scenario: 使用旧版本游标
- **WHEN** 使用者在投影版本更新后继续提交旧游标
- **THEN** API MUST 返回可识别的游标失效错误并要求从当前版本重新读取

### Requirement: 筛选树由当前可见投影生成
系统 MUST 从当前工作区、当前筛选范围内的可见投影生成经济类型与内部转账子类型筛选树。一级筛选项只包含实际存在的经济类型，二级筛选项只出现在所属内部转账类型下；前端不得写死与数据不一致的子类型清单。

#### Scenario: 当前只有普通内部转账和银证转账
- **WHEN** 当前活动投影不包含换汇或信用账户还款
- **THEN** 筛选树 MUST 只在内部转账下提供普通转账和银证转账子类型

#### Scenario: 切换一级筛选
- **WHEN** 使用者从内部转账切换到消费
- **THEN** 已选择的内部转账子类型 MUST 被清除或禁用，不得继续影响消费查询

### Requirement: 列表保留来源、账户和金额可读性
收支账本 MUST 标示单源或关系投影的全部导入渠道。宽屏表格中的长交易信息必须被限制或截断，同时保持账户和金额列可读；完整信息必须可通过证据详情访问。

#### Scenario: 长交易信息
- **WHEN** 一条投影包含很长的交易对方或备注
- **THEN** 宽屏表格 MUST 不挤压账户和金额至不可读，且详情中必须保留完整文本

### Requirement: 浏览器本地时区只影响展示和日期筛选
API MUST 提供可无歧义解析的时间值；Web 必须按浏览器本地时区展示发生时间和月份分隔。日期筛选必须把浏览器本地日期边界转换为后端 UTC 区间，不得改变账本记录保存值。

#### Scenario: 浏览器不在中国时区
- **WHEN** 使用者在另一个时区打开同一现金流水
- **THEN** 页面 MUST 按浏览器本地时区显示时间和月份分隔，但证据指向的后端时间保持不变

### Requirement: Web 浏览支持键盘和响应式布局

列表、筛选、分页和模态证据抽屉 MUST 可通过键盘操作，具有可见焦点和正确语义。抽屉打开时背景不可交互，关闭后焦点回到原入口；在 320、375、414 和 768 px 宽度不得出现页面级横向滚动或关键信息溢出。生产 Web 页面在移动设备上 MUST 禁止使用者通过双指手势缩放页面。

#### Scenario: 键盘打开并关闭证据抽屉
- **WHEN** 使用者通过键盘在投影条目上打开详情并按 Escape 关闭
- **THEN** 背景 MUST 在打开期间不可交互，关闭后焦点必须回到原详情入口

#### Scenario: 移动端双指缩放
- **WHEN** 使用者在生产 Web 页面上通过双指执行放大或缩小手势
- **THEN** 页面 MUST 保持当前视口比例，不得因该手势改变页面缩放级别

### Requirement: 导入配对阶段在移动端使用关系卡片

导入处理页面在视口宽度小于 821 px 时 MUST 以一条配对建议一张纵向卡片的方式展示关系审查内容，不得要求使用者在配对列表内部横向滚动。每张卡片 MUST 保留当前配对列表已经展示的状态、关系类型、现金流水、对侧流水、金额和拒绝或撤销操作。配对列表 MUST 按筛选结果的原始顺序连续展示，不得出现分页器或要求使用者切换页码。

#### Scenario: 窄屏查看待处理配对

- **WHEN** 使用者在 320 px、375 px、390 px、414 px 或 768 px 宽度打开包含待处理关系的配对步骤
- **THEN** 页面 MUST 为每条可见关系渲染独立卡片
- **AND** 现金流水与对侧流水 MUST 以可读的双行信息展示，对方、账户、时间和金额不得被表格横向滚动隐藏
- **AND** 页面 MUST 不出现页面级或配对列表内部的横向滚动

#### Scenario: 连续浏览全部配对卡片

- **WHEN** 筛选结果数量超过原有每页数量
- **THEN** 页面 MUST 继续在同一连续列表中展示筛选结果，不显示上一页、下一页或页码控件
- **AND** 卡片顺序 MUST 与筛选结果的原始顺序一致

#### Scenario: 宽屏查看配对

- **WHEN** 使用者在 1440 px 宽度打开配对步骤
- **THEN** 页面 MUST 保持现有配对表格的信息顺序和桌面布局
- **AND** 移动卡片改造 MUST NOT 改变桌面端的关系类型、候选选择、拒绝操作语义；桌面表格 MUST 连续展示全部筛选结果

### Requirement: 移动端关系卡片保持原有配对决定语义

移动端关系卡片 MUST 使用现有关系数据和决定合同，不得因布局变化改变自动配对、待手动配对、已配对、已拒绝、暂不处理、筛选或确认导入的行为。关系类型和对侧候选控件在移动端 MUST 保持可操作、可感知且适合触控。配对筛选 MUST 使用与“核对流水”一致的可点击摘要卡片表达，并保留 `全部`、`自动`、`待处理` 的数量和选中状态。

#### Scenario: 卡片内选择对侧流水

- **WHEN** 使用者在待处理卡片中选择一个合法对侧流水
- **THEN** 卡片 MUST 立即展示选中的对侧流水并反映现有的已配对状态
- **AND** 确认导入时 MUST 发送与桌面表格相同的关系决定，不得新增或改写关系字段

#### Scenario: 卡片内拒绝和撤销拒绝

- **WHEN** 使用者点击卡片中的“拒绝配对”或“撤销拒绝”
- **THEN** 页面 MUST 以现有关系决定更新状态、禁用或恢复对应控件，并提供至少 44 px 的触控命中区
- **AND** 可见操作名称和键盘焦点 MUST 清楚表达当前动作

#### Scenario: 自动配对卡片

- **WHEN** 关系建议为自动配对
- **THEN** 卡片 MUST 显示自动状态、现有关系类型、现金流水、已绑定对侧流水和金额
- **AND** 不得允许使用者编辑自动关系的只读字段

### Requirement: 配对移动视图覆盖响应式状态与无障碍交互

配对步骤的移动视图 MUST 继续提供现有正常、加载、空结果、错误和确认完成状态，并使筛选摘要卡片、关系类型控件、候选控件和拒绝或撤销按钮具有可见键盘焦点、可读无障碍名称及不小于 44 px 的交互命中区。配对视图 MUST 不渲染分页控件。

#### Scenario: 配对列表状态

- **WHEN** 配对步骤处于加载、无关系、请求错误或导入完成状态
- **THEN** 页面 MUST 展示对应的现有状态内容，不得渲染空白或横向滚动的关系表格

#### Scenario: 键盘审查配对

- **WHEN** 使用者只通过键盘浏览移动配对视图
- **THEN** 筛选摘要卡片、关系类型、对侧候选和拒绝或撤销控件 MUST 按可理解的顺序获得焦点
- **AND** 当前焦点 MUST 有可见样式，禁用控件 MUST 不可触发关系决定

### Requirement: 双后端返回相同浏览合同
PostgreSQL 与 SQLite MUST 对相同工作区账本和关系输入返回等价的投影、筛选树、证据详情、精确金额、时间值和分页顺序。

#### Scenario: 比较双后端浏览响应
- **WHEN** 两个后端使用相同去标识化账本与关系夹具
- **THEN** 除内部代理键外，列表和详情响应 MUST 等价

### Requirement: 收支账本展示并按分类树筛选
收支账本 MUST 为每个可见投影展示当前收支分类的可读路径或无分类状态。分类筛选必须来自当前工作区分类目录；选择父分类时必须包含直接使用该分类和使用任意后代分类的投影，并提供独立的无分类筛选。收支分类筛选不得替代或改变经济类型与内部转账子类型筛选。

#### Scenario: 选择父分类筛选
- **WHEN** 使用者选择父分类“餐饮”，且当前投影分别使用“餐饮”“餐饮 / 工作餐”和“交通”
- **THEN** 列表 MUST 返回前两类投影并排除“交通”，同时保持其他筛选条件有效

#### Scenario: 筛选无分类
- **WHEN** 使用者选择无分类
- **THEN** 列表 MUST 只返回 `category_id` 为空的可见投影

#### Scenario: 同名叶子分类
- **WHEN** 不同分支存在同名叶子分类
- **THEN** 分类筛选器和列表 MUST 提供足以区分它们的完整可读路径

### Requirement: Web 支持明确选择和批量分类
收支账本 MUST 允许使用者逐项勾选已加载的可见投影，并通过批量操作栏把选中项改为一个分类或无分类。表头选择只作用于当前已加载结果；继续加载后可以追加选择，但不得提供隐式选择全部筛选结果。修改筛选条件、投影版本刷新或批量成功后必须清空选择。

#### Scenario: 选择已加载条目
- **WHEN** 使用者在当前已加载结果中勾选多笔收支详情
- **THEN** 页面 MUST 显示选中数量、修改分类和取消选择操作，且键盘使用者能够完成同一流程

#### Scenario: 修改筛选后清空选择
- **WHEN** 使用者已经勾选条目后修改日期、账户、分类或其他筛选条件
- **THEN** 页面 MUST 在读取新结果前清空选择，不得把旧结果带入批量请求

#### Scenario: 批量请求因版本失效
- **WHEN** 批量分类因投影版本变化被拒绝
- **THEN** 页面 MUST 保留可执行的错误说明、重新读取列表并要求使用者重新选择，不得显示部分成功

### Requirement: 账本分类交互使用最小必要文案
收支账本在正常状态 MUST 只展示筛选、列表、分类、金额和当前可执行操作，不得增加功能介绍、操作影响或系统实现说明。分类路径可以用于同名消歧；批量操作栏只显示选中数量、修改分类和取消选择。错误、空状态、成功反馈和版本失效说明必须按需出现。

#### Scenario: 勾选多条流水
- **WHEN** 使用者勾选一条或多条已加载收支详情
- **THEN** 操作栏 MUST 只显示选中数量、修改分类和取消选择，不得常驻解释选择范围或事务行为

#### Scenario: 正常查看收支详情
- **WHEN** 使用者打开收支详情且没有错误或危险确认
- **THEN** 页面 MUST 不显示投影、来源快照、后端规则、AI 用途或重复解释分类共享行为的文案

### Requirement: 收支账本导入使用独立四步处理页面

收支账本 MUST 将导入入口导航到独立的导入处理页面，而不是在右侧浮窗中完成导入。页面 MUST 按“选择文件”“映射账户”“核对流水”“关系配对”四个步骤组织内容，并明确当前步骤、可返回的上一步和最终确认导入入口。

#### Scenario: 从收支账本进入导入处理页面

- **WHEN** 使用者点击收支账本中的“导入账单”
- **THEN** 浏览器 MUST 进入独立导入处理页面
- **AND** 收支账本背景和旧导入抽屉 MUST 不再承载该流程

#### Scenario: 步骤间返回

- **WHEN** 使用者从账户映射、流水核对或关系配对返回上一步
- **THEN** 页面 MUST 保留仍然有效的文件、扫描结果、映射选择和预览结果
- **AND** 返回后修改文件或账户映射时 MUST 清除所有受影响的后续步骤状态

#### Scenario: 选择文件步骤继续

- **WHEN** 使用者在选择文件步骤已经选中文件
- **THEN** 页面 MUST 将底部主操作显示为“下一步”，文件选择控件仍作为唯一的选文件入口
- **AND** 无密码文件扫描成功后 MUST 自动进入账户映射步骤
- **AND** 需要密码的文件 MUST 停留在当前步骤，点击“下一步”时才提交密码并继续扫描
- **AND** 从账户映射返回后点击“下一步” MUST 复用保留的扫描结果，不得重复扫描
- **AND** 本地识别为受保护的 PDF 时 MUST 在开始服务端扫描前显示密码输入，不得要求等待一次失败扫描后再出现

### Requirement: 账户映射步骤支持逐组核对和确认

导入处理页面 MUST 在文件识别后先展示来源账户分组。每组 MUST 显示来源账户名称或掩码证据、涉及币种、流水数量和当前工作区账户选择；匹配规则、历史映射来源、别名命中和冲突数量 MUST 保持为隐形规则，不得以标签、列或说明暴露。选择现有账户后如需新增支持币种，页面 MUST 在该映射行的系统账户选择下方以小字说明账户币种扩充草稿；选择“创建新账户”后 MUST 在该行同一位置以小字说明新账户草稿，并提供行内修改入口。

#### Scenario: 确认完整账户映射

- **WHEN** 使用者为每个来源账户分组选择合法账户并触发“确认映射”
- **THEN** 页面 MUST 进入流水核对步骤并展示应用选择后的标准化账户字段
- **AND** 该操作 MUST NOT 单独显示数据库保存成功或写入账本

#### Scenario: 映射尚未完成

- **WHEN** 至少一个来源账户分组未选择合法账户
- **THEN** “确认映射” MUST 保持禁用并提供可访问的阻断原因
- **AND** 键盘焦点 MUST 能到达对应账户选择和错误文本

#### Scenario: 账户扫描状态

- **WHEN** 页面正在扫描、没有识别到可导入业务账户或发现账户选择需要调整
- **THEN** 页面 MUST 分别显示加载、空结果或对应状态，并提供重新选择文件或修改账户选择的可操作入口
- **AND** 页面 MUST NOT 自动跳过账户映射步骤

#### Scenario: 支付宝组合支付无法唯一归属

- **WHEN** 账单扫描发现支付宝一条业务行同时包含多个真实资金账户，且来源没有提供分摊金额
- **THEN** 页面 MUST 在扫描结果中显示无法识别行数，并允许其他来源账户进入映射
- **AND** 流水预览 MUST 将该业务行标记为“无法识别”，明确确认时跳过该行；其他可映射流水仍可进入关系配对和最终确认
- **AND** 页面不得为该行展示或提交一个猜测的系统账户；若整份文件都无法识别，才显示错误并阻断后续步骤

#### Scenario: 账户草稿只在最终确认生效

- **WHEN** 使用者在映射步骤选择创建新账户，或选择币种不足的现有账户
- **THEN** 页面 MUST 允许继续到流水核对，并在各自映射行的系统账户选择下方小字显示待创建账户或待新增币种
- **AND** 账户和币种配置 MUST 直到最终“确认导入”才允许写入

### Requirement: 导入处理页面支持标准字段核对和关键状态

导入处理页面 MUST 为流水预览提供标准化字段表格、四项数量摘要、加载、空结果、识别失败、解析失败、暂不支持、确认中和确认成功状态。页面 MUST 不展示来源账单原始列或来源账户规范键；桌面和窄屏都 MUST 能访问完整标准字段。

#### Scenario: 键盘完成导入确认

- **WHEN** 使用者仅使用键盘选择文件、确认账户映射、查看预览、跳过待手动配对并确认导入
- **THEN** 焦点顺序 MUST 按四个步骤自然前进，当前步骤和错误状态具有可访问名称
- **AND** 确认按钮在请求期间 MUST 显示加载状态并阻止重复提交，成功后 MUST 显示导入结果摘要

#### Scenario: 小屏核对账户映射和预览

- **WHEN** 使用者在 320、375、414 或 768 px 宽度打开导入处理页面
- **THEN** 页面 MUST 无页面级横向滚动，四步导航、来源账户分组、摘要、流水和底部操作均不得溢出视口
- **AND** 桌面账户映射表在窄屏 MUST 改为逐组字段和值布局，主要按钮 MUST 保持至少 44 px 命中区域且文字不得换行

#### Scenario: 大量关系建议分页浏览

- **WHEN** 导入会话产生数百或数千条自动配对或待手动配对建议
- **THEN** 第四步 MUST 以紧凑列表展示关系，并提供全部、自动和待处理筛选
- **AND** 使用者 MUST 能切换每页显示数量并通过分页器浏览关系，不得要求一次渲染全部建议
- **AND** 每条关系行末 MUST 保留拒绝图标按钮，拒绝后通过同一位置的撤销图标恢复；非自动关系的关联类型和合法对侧流水 MUST 支持行内选择，自动关系类型只读

### Requirement: 导入入口和结果保持双后端等价

同一工作区和同一导入输入在 SQLite 与真实 PostgreSQL 中 MUST 返回等价的自动识别、来源账户分组、账户映射建议、标准化预览、数量摘要、配对建议、确认结果、精确金额、幂等结果和错误边界；页面不得根据数据库后端选择不同流程。

#### Scenario: 比较 SQLite 与 PostgreSQL 导入会话

- **WHEN** 两个显式选择的后端处理相同去标识化现金账单、账户、账户别名和既有账单账户映射
- **THEN** 自动识别渠道、来源账户分组、建议优先级、预览行标准字段、四项摘要、关系建议和确认后的账本结果 MUST 等价

### Requirement: Web 导入关系建议与 CLI 关系结果保持等价

现金导入 Web 四步流程 MUST 使用与现金导入 CLI 相同的标准化流水、关系阶段顺序、结构化退款证据、精确金额比较、工作区关系约束和决定应用语义。相同工作区、相同账单输入、相同账户映射和相同规则版本下，Web 预览与确认后的关系结果 MUST 与 CLI 等价，除内部代理键外不得因入口不同产生不同配对。

#### Scenario: 比较微信账单结果

- **WHEN** Web 和 CLI 导入同一份包含平台退款双行及其他同额流水的去标识化微信账单
- **THEN** Web 第四步展示的自动关系 MUST 与 CLI 导入后生成的关系端点和规则 ID 等价
- **AND** Web 不得将其他商户的同额流水自动匹配为该退款

#### Scenario: Web 预览保持只读

- **WHEN** 使用者在 Web 中反复进入预览和关系步骤但未确认导入
- **THEN** 账本流水、活动关系、待审核关系和收支投影 MUST 保持不变

#### Scenario: 双后端导入关系结果

- **WHEN** SQLite 与 PostgreSQL 使用相同工作区、去标识化账单和关系夹具执行 Web 或 CLI 导入
- **THEN** 两个后端 MUST 返回等价的关系建议、确认状态、精确金额、幂等结果和投影结果

#### Scenario: 预览确认不因时间表示陈旧

- **WHEN** 账单包含无 offset 的中国本地时间，且预览后没有事实、映射或关系上下文变化
- **THEN** Web 确认 MUST 使用与预览相同的规范时间和稳定事实顺序
- **AND** 不得仅因为数据库事实带有 UTC offset 而返回关系计划陈旧错误

### Requirement: 导入关系变化回到配对确认

收支导入处理页面收到重新确认配对结果时，MUST 保留当前导入会话，清除先前的配对决定，刷新配对建议并回到配对步骤。页面必须以可操作的业务文案说明相关流水已变化、需要重新确认配对，不得仅显示技术错误、要求重新选择账单文件或要求重新映射账户。

#### Scenario: 配对建议需要重新确认

- **WHEN** 使用者点击确认导入后，服务端返回重新确认配对结果
- **THEN** 页面 MUST 显示新的配对建议并让使用者重新确认，且本次失败前的账单和账户映射选择仍可继续使用

### Requirement: 已完成导入从新会话重新开始

导入完成页的步骤导航允许使用者回到“选择文件”开始下一次导入时，页面 MUST 丢弃已完成会话的文件、扫描、映射、预览、配对决定、令牌和幂等键；常规未完成导入的“上一步”行为不受影响。

#### Scenario: 成功后回到选择文件

- **WHEN** 使用者在导入完成页点击第 1 步“选择文件”
- **THEN** 页面 MUST 要求重新选择文件，且不得将已完成导入会话的令牌发送到预览或确认接口
### Requirement: Native cash ledger mirrors the Web presentation contract

收支账本的 Native 渲染 MUST 复用 Web Compact、Regular 或 Wide 对应的页面区域和语义标识：页面标题、工作区上下文、筛选、列表/记录区、空状态、错误状态和主要操作 MUST 保持相同顺序与业务含义。Native 可以把 Web 表格渲染为触控列表，但不得改变投影、金额、来源或证据详情语义。

#### Scenario: View the cash ledger on a phone

- **WHEN** Native 窗口宽度小于 `600`
- **THEN** 页面 MUST 以单列方式展示 Web Compact 的标题、筛选、现金流水列表和新增/导入操作
- **AND** 每条流水 MUST 可打开与 Web 证据详情等价的凭证信息

#### Scenario: View the cash ledger on a tablet

- **WHEN** Native 窗口宽度为 `600` 或以上
- **THEN** 页面 MUST 按 Web Regular 或 Wide 的结构展示导航、筛选、记录区和操作区
- **AND** 不得因为使用 Native 列表而隐藏 Web 已展示的账户、分类、金额、来源或错误反馈
