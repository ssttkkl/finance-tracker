# 功能规格：对方账号转账匹配

## Purpose

让转账、提现和还款关系在不暴露账号原文的前提下，使用用户显式登记的本人账户标识和账单直接提供的对方账号收敛候选。

## Requirements

### Requirement: 本人账户标识登记与解析

系统 MUST 仅使用当前工作区 `account_aliases` 中用户显式登记的本人账户标识匹配对方账号。`account_identifier` 表示完整账号的精确数字标识；`card_tail` 表示恰好四位数字的账号尾号。系统 MUST 在比较前仅移除账号格式分隔符，并且仅当来源对方账号未被掩码且其完整数字标识与唯一 `account_identifier` 一致时视为精确命中；当来源值可提取四位尾号且该尾号只映射到一个账户时视为唯一尾号命中。系统 MUST NOT 从账户名称、账户映射、备注、对手方名称或其他账单列自动创建本人账户标识。

#### Scenario: 显式完整账号命中
- **WHEN** 用户为一个现金账户登记唯一 `account_identifier`，且转出流水的来源直接对方账号以相同完整数字标识出现
- **THEN** 系统 MUST 将该账户作为对方账号命中的目标账户，且不得向来源行快照写入别名或规范化值

#### Scenario: 唯一尾号命中
- **WHEN** 转出流水的来源直接对方账号仅包含尾号，且对应 `card_tail` 在当前工作区只绑定一个账户
- **THEN** 系统 MUST 识别该账户为唯一尾号命中的目标账户

#### Scenario: 尾号冲突或未登记
- **WHEN** 对方账号尾号未登记，或同一 `card_tail` 绑定多个账户
- **THEN** 系统 MUST NOT 根据该尾号选择目标账户或提高关系置信度

### Requirement: 对方账号约束转账候选

系统 MUST 只在转账、提现或还款的转出方已经具有来源直接提供的 `counterparty_account` 时应用本人账户标识证据。精确命中或唯一尾号命中时，系统 MUST 只保留落入该目标账户的既有金额、币种、时间和记录类型合格候选；该证据不得绕过既有候选条件或单独创建关系。候选账户具有已登记本人账户标识而其标识均与对方账号不匹配时，系统 MUST 排除该候选。没有已登记标识的候选保持既有行为。若筛选后没有候选，系统 MUST 不创建转账关系。

#### Scenario: 对方账号消除同金额候选歧义
- **WHEN** 一条转出流水有多个既有合格候选，且其对方账号精确命中或唯一尾号命中其中一个候选账户
- **THEN** 系统 MUST 仅使用该账户的候选继续既有规则评估，其他候选不得形成该转出流水的关系

#### Scenario: 对方账号排除已登记但不匹配的候选
- **WHEN** 一条转出流水的候选账户均已登记本人账户标识，但其对方账号不匹配任一候选账户
- **THEN** 系统 MUST 不为该转出流水创建 `transfer_pair`

#### Scenario: 缺少对方账号保持兼容
- **WHEN** 转出流水的 `counterparty_account` 为空字符串
- **THEN** 系统 MUST 保持既有转账候选和置信度行为

### Requirement: 对方账号匹配的隐私边界

系统 MUST 只在本次候选筛选中使用完整账号或尾号的命中结果，不得将命中结果或账号原文写入关系、CLI 输出、异常和日志。

#### Scenario: 关系不保留账号匹配过程
- **WHEN** 对方账号命中促成一条转账关系
- **THEN** 已创建关系 MUST 不包含来源对方账号、本人账户标识或其命中种类
