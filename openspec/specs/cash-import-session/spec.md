# cash-import-session Specification

## Purpose

为账单导入提供一个短期、工作区隔离且可重试的临时会话，使扫描和预览不重复上传原始账单，同时不在最终确认前写入 Neon 业务数据。

## Requirements

### Requirement: 临时导入会话保存来源但不写入业务账本

系统 MUST 在首次提交一组账单文件进行扫描时，为当前用户和工作区创建一个短期临时导入会话，并按选择顺序把每个原始账单及必要的扫描预览草稿保存到受控临时存储；同一会话最多保存 20 份文件，每份文件不得超过 100 MB。创建、扫描、映射和预览阶段 MUST NOT 创建或修改账户、账户支持币种、账单账户映射、现金流水、交易关系或收支投影。

#### Scenario: 首次提交多份文件创建会话

- **WHEN** 使用者为当前工作区提交一组格式受支持的账单文件进行扫描
- **THEN** 系统 MUST 返回不透明的 `import_token`、批次摘要、按文件返回的摘要与识别状态，以及合并后的来源账户扫描结果
- **AND** Neon 中不得出现本次导入的业务写入

#### Scenario: 部分文件需要密码

- **WHEN** 一组文件中有一个或多个加密账单尚未提供密码
- **THEN** 系统 MUST 保留整组文件在同一个临时会话中
- **AND** MUST 只把对应文件标记为需要密码，不得把已经完成扫描的文件写入业务账本或单独进入账户映射

#### Scenario: 预览引用既有多文件会话

- **WHEN** 使用者提交有效的 `import_token` 和账户映射以请求流水预览
- **THEN** 系统 MUST 从临时来源读取该会话的全部文件并返回合并预览，不得要求浏览器再次上传原始账单

### Requirement: 会话必须绑定工作区并在期限后失效

临时导入会话 MUST 绑定创建它的认证用户、工作区、按顺序排列的文件摘要集合、批次摘要和每个文件识别出的渠道。令牌 MUST 使用不可预测值并具有有限有效期。工作区、用户、文件集合、批次摘要或渠道集合不匹配，以及会话过期、已确认或不存在时，系统 MUST 拒绝读取和提交。

#### Scenario: 跨工作区使用多文件令牌

- **WHEN** 使用者把一个工作区创建的 `import_token` 用于另一个工作区的预览或提交
- **THEN** 系统 MUST 拒绝请求且不得返回任何原始文件、扫描结果、预览流水或关系候选

#### Scenario: 文件集合发生变化

- **WHEN** 预览或提交请求对应的文件摘要集合、文件顺序或批次摘要与会话不一致
- **THEN** 系统 MUST 拒绝请求并要求重新扫描整组文件
- **AND** MUST 不写入部分账户映射、现金流水、交易关系或投影

#### Scenario: 会话过期

- **WHEN** `import_token` 超过配置的临时会话有效期
- **THEN** 系统 MUST 返回可识别的会话过期错误，并删除或异步清理该会话的临时对象

### Requirement: 关系决定只在最终确认时提交

系统 MUST 允许浏览器在会话内修改关系类型、对侧流水和驳回决定，但这些决定在最终确认前只能保存在浏览器或临时会话草稿中；最终确认 MUST 同时提交账户映射和关系决定。

#### Scenario: 预览阶段修改关系

- **WHEN** 使用者在关系步骤接受、驳回或替换关系候选但尚未点击「确认导入」
- **THEN** 系统 MUST 不创建或修改 Neon 中的交易关系及收支投影

### Requirement: 最终确认必须幂等且可安全重试

最终确认 MUST 接受调用方提供的幂等键，并以当前用户、工作区、多文件临时会话和幂等键确定一次提交。相同幂等键的重试 MUST 返回第一次成功结果或同一业务错误，不得重复创建任何业务数据；幂等范围 MUST 覆盖该会话内所有文件、所有流水和所有关系决定。

#### Scenario: 多文件导入网络错误后重试确认

- **WHEN** 最终确认请求在客户端收到超时或 `503`，随后使用同一会话和幂等键重试
- **THEN** 系统 MUST 只执行一次包含全部文件流水和关系决定的数据库事务
- **AND** MUST 返回稳定的导入计数与关系结果

### Requirement: 临时来源遵守隐私和清理边界

临时对象 MUST 只允许应用服务端通过受控存储凭据访问，默认不得公开访问；对象、文件路径、密码、令牌和批次正文 MUST 不进入日志。成功确认后系统 MUST 删除或标记删除该会话的全部原始账单、扫描结果和预览草稿，未确认对象 MUST 在 TTL 到期后自动清理。

#### Scenario: 成功确认后的多文件清理

- **WHEN** 最终 Neon 事务成功提交
- **THEN** 系统 MUST 清理会话内全部文件及扫描、预览和结果对象，并使原 `import_token` 不能再次提交

#### Scenario: 存储配置缺失

- **WHEN** 生产环境未配置 R2 会话存储所需的完整凭据或 Bucket
- **THEN** 系统 MUST 失败关闭并返回可操作的服务配置错误，不得把原始账单静默写入 Render 本地文件系统

### Requirement: 文件级扫描状态必须可重试且全部就绪后才能继续

多文件扫描 MUST 为每个文件返回 `ready`、`password_required` 或可操作的 `error` 状态。只要仍有文件不是 `ready`，系统 MUST 阻止账户映射、流水预览和最终确认；密码重试 MUST 只针对对应文件，文件替换或删除后 MUST 重新扫描剩余文件集合。

#### Scenario: 所有文件扫描完成

- **WHEN** 会话内每个文件都已成功识别并解析
- **THEN** 系统 MUST 返回合并后的来源账户分组并允许进入账户映射

#### Scenario: 任一文件解析失败

- **WHEN** 会话内任一文件无法识别渠道或解析失败
- **THEN** 系统 MUST 返回该文件的可操作错误并阻止进入账户映射
- **AND** 不得把其他已成功解析的文件单独提交或显示为可确认导入

#### Scenario: 密码只在当前请求使用

- **WHEN** 使用者为一个或多个加密文件提交密码进行扫描、预览或确认
- **THEN** 系统 MUST 按文件将密码仅用于当前受限请求
- **AND** 密码 MUST NOT 写入临时会话对象、响应、日志、浏览器持久化或业务数据
