# 账单导入

## Purpose

定义受支持账单从来源文件进入账本时的账户路由、完整性、行级幂等、来源行快照、时间解释和原子失败合同。

## Requirements

### Requirement: 受支持账单直接进入统一导入流程
系统 MUST 允许受支持的 CSV、XLS、XLSX 和 PDF 账单作为原始输入，经解析、验证和账户路由后写入当前运行时数据库。原始文件只能作为输入证据，不得成为运行时账本、迁移载体或数据库不可用时的回退。

#### Scenario: 导入受支持文件
- **WHEN** 使用者为受支持导入渠道提交格式有效的账单文件
- **THEN** 系统 MUST 把有效业务行转换为当前工作区的账本记录，并返回可核对的导入计数

### Requirement: 导入账户由来源行和映射规则解析
账单导入 MUST 根据来源行中的支付方式、账号、卡号、账户产品档案或明确映射规则解析目标账户。对于工行借记卡 PDF，来源账户身份 MUST 使用来源表格的本方账号字段；交易渠道只能作为该流水的业务字段，不能作为来源账户身份。通用导入命令 MUST NOT 依赖调用方提供一个覆盖整份多账户账单的 `--account` 参数，且导入与转换流程必须使用相同的账户解析语义。

#### Scenario: 多支付方式账单
- **WHEN** 一份支付平台账单包含映射到不同账户的业务行
- **THEN** 一次导入 MUST 将各行分别写入对应账户，不得把整份账单强制写入同一账户

#### Scenario: 工行借记卡同账户多渠道流水
- **WHEN** 工行借记卡 PDF 的多条流水具有相同本方账号但交易渠道分别为快捷支付、网上银行或手机银行
- **THEN** 系统 MUST 将这些流水归入同一个来源账户映射组，并保留每条流水各自的交易渠道

#### Scenario: 工行借记卡多账户文件
- **WHEN** 一个工行借记卡来源文件包含不同本方账号的业务行
- **THEN** 系统 MUST 按本方账号分别生成来源账户身份并要求分别映射，不得按交易渠道合并或拆分

#### Scenario: 账户无法唯一解析
- **WHEN** 一个业务行无法从受控来源字段和映射规则唯一解析到账户
- **THEN** 系统 MUST 失败并说明缺少的映射证据，不得根据自由文本猜测账户

### Requirement: 每个来源业务行都有明确处理结果
支持范围内的每个来源业务行 MUST 满足以下结果之一：写入账本记录、命中文档化且可计数的白名单跳过，或使整批导入明确失败。系统 MUST NOT 静默跳行、吞掉解析异常或以成功状态掩盖未处理行。

#### Scenario: 白名单提示行
- **WHEN** 来源文件包含该导入渠道明确允许忽略的非业务提示行
- **THEN** 系统 MUST 计入白名单跳过数量且不创建账本记录

#### Scenario: 未知业务行
- **WHEN** 来源文件包含不符合任何已声明业务行或白名单结构的记录
- **THEN** 系统 MUST 使整批导入失败，并不得写入该文件的部分账本记录

### Requirement: 账本记录保留完整来源行快照
每条账单派生的账本记录 MUST 保存导入渠道、业务行标识和完整来源行快照。来源行快照必须保留该业务行的原始列名和值，包括空值和无标题列，且不得混入账户映射、格式规范化、关系检查或其他派生字段。

#### Scenario: 来源包含空值和无标题列
- **WHEN** 来源业务行包含空值字段和一个无标题列
- **THEN** 来源行快照 MUST 保留对应键和值，并使用空字符串作为该无标题列的键

#### Scenario: 来源存在重复列名
- **WHEN** 一个表格来源的同一业务行结构包含重复列名
- **THEN** 系统 MUST 拒绝整批导入，不得编造列名或覆盖先出现的值

### Requirement: 业务行标识提供跨文件幂等
导入幂等 MUST 以当前工作区、导入渠道和业务行标识共同判断，不得以文件摘要或数据库内部代理键作为账本真实性。重复导入同一文件、重叠时间范围文件或完整重导时，只允许新增尚未存在的业务行。

#### Scenario: 重复导入相同文件
- **WHEN** 使用者再次导入已经成功处理的同一份账单
- **THEN** 系统 MUST 不创建重复账本记录，并报告新增行数为 `0`

#### Scenario: 导入重叠账单
- **WHEN** 第二份账单与第一份账单包含部分相同业务行并新增其他行
- **THEN** 系统 MUST 保留既有记录不变，只写入新的业务行

### Requirement: 来源时间在导入边界解释
导入器 MUST 按来源合同解释业务时间：自带 offset 的时间使用该 offset，无 offset 的时间使用该导入渠道明确规定的来源时区。解释后的时间必须进入统一后端时间边界，且不得由浏览器时区或服务器本地时区重新解释。

#### Scenario: 无 offset 的中国账单时间
- **WHEN** 中国账单来源提供无 offset 的本地时间
- **THEN** 导入器 MUST 按该来源声明的中国时区解释后再提交，不得按运行服务器时区解释

### Requirement: 导入失败不泄露敏感来源数据
解密、解析、映射、精度、币种、时间或持久化错误 MUST 使导入失败关闭，错误信息不得记录账单密码、完整账号、Token 或整行来源数据。

#### Scenario: 加密 PDF 密码错误
- **WHEN** 使用者提供的 PDF 密码无法解密账单
- **THEN** 系统 MUST 返回明确失败且不创建账本记录，日志不得包含密码或账单正文
