# 现金—投资资金调拨关系

## Purpose

本能力以来源无关的规范字段识别收支账户与投资账户之间的外部资金移动，保存可审计的候选、决定和关系证据，并避免把内部资金调拨误计为收支。

## Requirements

### Requirement: 基于规范语义扫描外部资金调拨
系统 MUST 只扫描工作区内 `funding(external)` 投资事件，以及方向相反的可匹配收支账户资金流水。扫描 MUST 从投资事件现金部分确定资金方向：入金只匹配此前 7 个 UTC 自然日内的收支支出，出金只匹配其后 7 个 UTC 自然日内的收支收入。普通候选使用记录类型、记录子类型、账户类型、精确十进制金额和币种；对预先受控的投资导入渠道，券商机构名称可以作为附加确认信号，不读取或写死收款账号、账户名称或自由备注。

#### Scenario: 不同银行和券商的同类外部入金
- **WHEN** 收支账户转出流水与不同导入渠道的现金流入 `funding(external)` 投资事件具有相反方向、相同币种、相同精确金额且在允许业务日窗口内
- **THEN** 系统按同一套规则生成资金调拨候选，不因渠道名称不同而改变候选资格

#### Scenario: 内部子账户调拨不进入候选
- **WHEN** 投资事件为 `funding(subaccount)`
- **THEN** 系统不得为它生成收支账户资金调拨候选

### Requirement: 候选确认必须唯一且可审计
系统 MUST 仅在方向正确且候选唯一时自动确认资金调拨关系。普通候选还 MUST 同币种且精确金额相等；已命中受控机构名称的候选可以金额或币种不同。业务日窗口、候选数量、记录类型、匹配键和规则 ID MUST 作为受限证据持久化，不得保存对方账号或原始备注。候选不唯一或端点已被已确认资金调拨关系占用时，系统 MUST 保留待审核关系或不创建关系，不得猜测确认。

#### Scenario: 唯一的同币种资金调拨
- **WHEN** 一笔外部入金在候选窗口内只有一条金额、币种和方向均匹配的收支流水
- **THEN** 系统自动确认一条关系，并在重复扫描时返回同一关系而不重复创建

#### Scenario: 金额相同的多个候选
- **WHEN** 一笔外部出金在候选窗口内匹配多条收支账户入账流水
- **THEN** 系统创建或更新待审核候选，且不得自动确认任一端点

#### Scenario: 唯一的跨币种机构名称候选
- **WHEN** 一笔外部入金在此前 7 个自然日内只有一条方向相反的收支转出，且该流水对手方命中该导入渠道的受控机构名称
- **THEN** 系统自动确认关系，即使两端金额或币种不同，并仅记录机构名称匹配这一受限证据

#### Scenario: Charles Schwab 含手续费的同币种入金
- **WHEN** 一笔 `schwab_csv` 的 USD `7,980` 外部入金在同日仅有一笔 USD `8,000` 的 `transfer_out`，且对手方包含 `Charles Schwab`
- **THEN** 系统 MUST 将该银行转账与投资事件确认为资金调拨关系，并仅记录机构名称、方向和业务日窗口证据；不得为 USD `20` 差额创建手续费关系或推导费用事实

### Requirement: 人工决定与关系端点互斥
系统 MUST 允许使用者确认或驳回待审核的资金调拨关系，并记录决定者、决定时间、稳定原因和有限候选标识。已确认关系的收支流水端点与投资事件端点 MUST 在同一工作区内分别唯一；后续扫描不得覆盖人工决定。

#### Scenario: 人工确认待审核候选
- **WHEN** 使用者从待审核候选中确认一条收支流水与投资事件
- **THEN** 系统在同一事务内校验工作区、两端方向、单向业务日窗口、端点可用性，以及同币种精确金额或受控机构名称信号，保存决定并触发受影响收支投影维护

#### Scenario: 更强规则替代系统候选
- **WHEN** 重扫发现一条系统生成、未人工决定的待审核候选已不满足当前窗口或被唯一机构名称候选替代
- **THEN** 系统将旧候选标为已驳回并记录稳定的系统原因，保留人工决定与已确认关系不变

### Requirement: 双后端关系持久化与溯源
系统 MUST 在 SQLite 与 PostgreSQL 中等价地持久化资金调拨关系、状态、端点、规则 ID、受限证据和人工决定。关系表 MUST 通过工作区约束和外键阻止跨工作区端点；关系不得复制或暴露完整来源行快照、账户隐私或任意原始备注。

#### Scenario: 双后端重复扫描
- **WHEN** 对相同去标识化输入在 SQLite 与 PostgreSQL 重复执行资金调拨扫描
- **THEN** 两个后端产生相同的候选、状态、端点、规则 ID 和受限证据，且不产生重复关系

### Requirement: 资金调拨窗口使用明确 UTC 日历

现金—投资资金调拨候选的时间窗口 MUST 基于 UTC aware 时间计算；带 offset 的现金流水和投资事件 MUST 先归一化为 UTC，再判断自然日窗口，且不得固定使用 `Asia/Shanghai`。

#### Scenario: 不同 offset 的候选按 UTC 窗口判断

- **WHEN** 现金流水和投资事件带不同合法 offset，且归一化后的 UTC 日期差在允许窗口内
- **THEN** 系统 MUST 保留该候选并在两个正式数据库后端得到相同匹配结果
