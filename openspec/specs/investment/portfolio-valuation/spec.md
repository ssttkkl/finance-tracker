# 投资组合估值

## Purpose

定义持仓查询所使用的行情报价、汇率折算、估值状态、批量请求、有界预算和局部失败合同，使不完整数据被明确呈现且一个数据源失败不会隐藏其他持仓结果。

## Requirements

### Requirement: 每项非零持仓返回明确估值状态
持仓查询 MUST 为每项非零持仓返回计价币种单价、计价币种市值和 `complete`、`stale`、`partial` 或 `unsupported` 状态。现金持仓单价必须为 `1`；不可用金额必须为空，不得以假 `0` 伪装成功估值。

#### Scenario: 行情可用
- **WHEN** 非现金持仓具有有效行情报价
- **THEN** 系统 MUST 以精确十进制返回单价、计价币种、市值和相应估值状态

#### Scenario: 标的不受支持
- **WHEN** 没有数据源支持一个非现金标的
- **THEN** 该持仓 MUST 返回 `unsupported` 及原因，单价和市值不得填入 `0`

### Requirement: 展示币种折算保持显式和可审计
指定展示币种时，系统 MUST 使用明确汇率把计价币种市值折算为展示币种，并保留原计价币种金额。缺少汇率时必须返回受限状态和空折算市值，不得使用隐式汇率或默认币种。

#### Scenario: 汇率可用
- **WHEN** 持仓计价币种为 USD、展示币种为 CNY 且具有有效 USD/CNY 汇率
- **THEN** 系统 MUST 同时返回 USD 计价币种市值和精确 CNY 折算市值

#### Scenario: 汇率缺失
- **WHEN** 行情报价可用但计价币种到展示币种的汇率不可用
- **THEN** 计价币种市值 MUST 保留，折算市值必须为空并返回 `partial` 或等价受限状态

### Requirement: 行情查询在共享预算内批量执行
持仓查询 MUST 先收集并规范化全部非零可估值标的，同一标的一次查询只获取一次行情。系统必须在共享总预算内使用受控批量或有界并发，超出预算后不得继续无限提交外部工作。

#### Scenario: 多账户包含重复标的
- **WHEN** 多个账户持有同一规范化标的
- **THEN** 一次持仓查询 MUST 只向对应数据源请求一次该标的行情，并把结果用于所有相关持仓

#### Scenario: 大量持仓
- **WHEN** 工作区包含至少 30 项非零持仓和多个数据源
- **THEN** 系统 MUST 在既定总预算内返回全部持仓及确定状态，不得创建不受控制的线程或请求数量

### Requirement: 数据源局部失败不得阻塞其他持仓
一个数据源超时、限流、返回空数据、部分数据或错误时，系统 MUST 保留其他独立数据源和同批成功标的的结果。失败影响范围不得扩大到无关持仓。

#### Scenario: 一个数据源持续超时
- **WHEN** 一个数据源在总预算内未返回，但其他数据源成功
- **THEN** 超时数据源的相关持仓 MUST 返回受限状态，其他持仓必须保留成功或过期行情结果

#### Scenario: 批量请求部分成功
- **WHEN** 同一数据源的批量响应只包含部分标的
- **THEN** 已返回标的 MUST 保留各自结果，缺失标的必须单独标记失败或不支持

### Requirement: 估值数值和诊断信息保持安全等价
PostgreSQL 与 SQLite 上的持仓查询 MUST 对相同行情和汇率输入返回等价的精确十进制结果与状态。诊断信息不得记录凭据、完整账户隐私或整份持仓明细。

#### Scenario: 双后端估值合同
- **WHEN** 两个后端使用相同持仓、行情和汇率夹具
- **THEN** 单价、市值、币种、折算市值和估值状态 MUST 等价
