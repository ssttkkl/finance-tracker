# 时间语义

## Purpose

定义来源时间进入账本、后端保存与比较、日期筛选以及浏览器展示之间的时间边界，避免本地时区和无时区值产生歧义。

## Requirements

### Requirement: 后端时间值必须明确且可比较
后端写入和读取的账本发生时间、关系决定时间、投影版本时间和估值时间 MUST 使用明确时区语义，并在持久化边界规范为 UTC。系统不得把无时区数据库值与有时区值直接比较，也不得依赖进程本地时区补全含义。

#### Scenario: PostgreSQL 与 SQLite 时间往返
- **WHEN** 同一带 offset 时间分别写入两个后端并再次读取
- **THEN** 两个后端 MUST 返回表示同一瞬间的 UTC 规范值

#### Scenario: 拒绝歧义时间
- **WHEN** 应用边界收到没有来源时区合同的无 offset 时间
- **THEN** 系统 MUST 拒绝该值，不得使用服务器本地时区猜测

### Requirement: 来源时间只在导入边界解释
自带 offset 的来源时间 MUST 使用该 offset；无 offset 的来源时间 MUST 使用对应导入渠道明确声明的来源时区。解释完成后必须以统一时间值进入账本，后续层不得再次按浏览器或服务器时区解释。

#### Scenario: 来源时间带 offset
- **WHEN** 账单来源提供 `2026-08-07T10:00:00+08:00`
- **THEN** 导入器 MUST 保留该瞬间并规范为等价 UTC 时间

### Requirement: 前端按浏览器本地时区展示
Web 页面 MUST 使用浏览器本地时区展示后端返回的明确时间值，包括日期、时间和月份分隔；API 不得预先格式化为固定地区时间字符串。

#### Scenario: 两个浏览器时区查看同一记录
- **WHEN** 两个浏览器处于不同时区并读取同一账本记录
- **THEN** 两个页面 MUST 显示各自本地时间，但记录身份和后端时间必须相同

### Requirement: 日期筛选绑定浏览器本地日历
使用者提交的页面日期范围 MUST 按浏览器本地时区解释为半开 UTC 区间后发送给后端。结束日期必须覆盖该本地自然日，且夏令时切换日不得按固定 24 小时假设计算。

#### Scenario: 夏令时开始日筛选
- **WHEN** 浏览器所在时区的一个自然日只有 23 小时
- **THEN** 日期筛选 MUST 使用该本地日的实际 UTC 起止边界，不得多查或漏查相邻日记录

### Requirement: 业务时间窗口声明自己的日历
财富趋势分桶、交易关系候选窗口和现金—投资资金调拨窗口 MUST 明确使用 UTC 或特定业务日历，并基于规范时间比较。浏览器展示时区不得改变相同后端查询的候选资格或归因结果。

#### Scenario: 资金调拨窗口跨浏览器时区
- **WHEN** 不同时区的浏览器触发相同规范数据范围的资金调拨扫描
- **THEN** 系统 MUST 产生相同候选集合

#### Scenario: 财富日桶
- **WHEN** 同一组账本记录生成财富日趋势
- **THEN** 日桶归属 MUST 由财富能力声明的规范边界决定，不得随查看者时区变化
