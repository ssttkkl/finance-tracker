# 后端设计评审

## 目的

判断设计复杂度是否由实际需求支持，寻找保持必要行为的更简单方案。不是格式检查，不以字段、表、接口或类型数量越少越好。

检查项见 `docs/design-review/backend/rules.md`。

## 工作方式

- 增量：从 change 的需求和 diff 出发，识别受影响的业务概念；搜索已有实现、调用方和测试，只关注本次新引入、加重或与正确性直接相关的问题；无关历史问题单独标记，不扩大重构。
- 全量：先建立“业务概念 → 表/字段 → 模型 → 接口 → 调用方”的映射，按业务概念跨层审；明确未覆盖区域，不把局部抽样声明为全量完成。
- 由独立上下文执行，评审者不修改实现；规范与实现冲突时指出冲突，不预判哪方正确。

## 输出

自由格式。写清审查范围、基线、证据、发现、建议改法和未覆盖项。需要记录时写入 `tasks.md` 第 5 阶段或 `design.md`；不要求固定报告文件、等级或状态。
