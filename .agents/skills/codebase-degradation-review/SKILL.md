# 代码库防劣化检查

## 目的

在代码 change 的审查阶段，判断本次变更涉及哪些设计面，调度对应的专项审查，避免遗漏，也不重复检查。

本技能只做范围判断、调度和汇总，不定义具体检查项。

## 范围判断

读取 change 的需求、diff、相关 artifacts 和代码，判断：

- 涉及数据库、表、字段、迁移、领域模型、DTO、请求／响应或后端接口 → 调度 `$contract-design-review`。
- 涉及 UI 组件、布局、主题 token 使用或用户可见交互 → 调度 `$ui-reuse-review`。
- 两者都不涉及 → 在 `tasks.md` 第 5 阶段说明不适用，不调度。
- 两者都涉及 → 分别调度，分别执行，最后合并发现。

## 调度方式

- 每个子审查由独立上下文执行，评审者不修改实现。
- 按子技能自己的规则和输出方式执行；本技能不复制它们的检查项。
- 汇总时保留子审查的范围、证据、发现、建议改法和未覆盖项；不要为了统一格式而删减证据。
- 子审查之间冲突或重复的发现合并说明，不重复计数。

## 不包含

Hallmark audit、独立设计复核、视觉/对比度/间距/动效/无障碍/响应式检查仍由现有 UI 门禁负责，不进入本调度。

## 输出

自由格式。写清本次触发了哪些子审查、各自范围和结论、合并后的发现、未覆盖项。记录在 `tasks.md` 第 5 阶段或 `design.md`；不要求固定报告文件、等级或状态。
