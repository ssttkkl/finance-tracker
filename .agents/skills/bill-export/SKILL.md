# 账单导出

将本技能作为支付账单导出的统一入口。先识别账单来源，再分别加载渠道流程和执行后端：渠道文件完整定义应用内业务操作，后端文件只定义如何控制设备界面。

## 输入参数

- `账单来源`：`微信支付`、`支付宝`或已支持的其他渠道。可同时指定多个。
- `时间范围`：默认`最近三个月`。平台实际选项不同时，按渠道文件的映射处理。
- `交易类型`：默认全部交易或全部账单。
- `保存位置`：默认使用所选后端可直接控制的设备本地文件空间。
- `转交`：默认`否`。仅在用户明确授权并指定目标设备或渠道时执行。

## 渠道路由

开始操作前，根据用户用词和目标应用确定账单来源，并完整读取对应文件：

| 用户意图或目标应用 | 渠道文件 |
| --- | --- |
| 微信、微信支付、零钱、微信账单、账单流水文件 | [references/wechat.md](references/wechat.md) |
| 支付宝、支付宝账单、交易流水证明、我的账单 | [references/alipay.md](references/alipay.md) |

路由规则：

1. 用户明确指定渠道时，直接路由到该渠道。
2. 用户同时指定多个渠道时，按用户顺序逐个执行；为每个渠道独立记录业务状态、时间范围、文件名和保存位置。
3. 用户只说“导出账单”且上下文无法确定渠道时，才询问需要导出哪个平台。
4. 不得根据当前打开的应用擅自替换用户指定的渠道。
5. 渠道尚未支持时，说明缺少该渠道的路由文件，不要套用其他渠道流程。

## 后端选择

渠道确定后，选择执行后端并完整读取对应文件：

| 控制方式 | 后端文件 |
| --- | --- |
| Computer Use + macOS iPhone 镜像 | [references/computer-use-iphone-mirroring.md](references/computer-use-iphone-mirroring.md) |

选择规则：

1. 优先服从用户指定的设备、平台或控制方式。
2. 用户未指定时，选择已连接、可见、可操作对应已登录账号，并能完成申请、认证交接、状态确认、下载和保存的后端。
3. 同一渠道请求只选择一个后端。后端断开时先检查业务状态，再恢复或停止；不要盲目重复申请。
4. 不得擅自切换到云真机、模拟器、其他账号或其他渠道。
5. 后续增加 Android + ADB 等方式时，新增通用后端文件并在本节登记；不要把任何支付渠道的业务路径写进后端文件。

## 通用状态契约

各渠道使用相同的顶层状态语义；只有页面入口和细节由渠道文件决定：

1. **未开始**：确认渠道、时间范围、交易类型、保存位置和转交参数。
2. **后端已选择**：确认后端能力满足请求，并加载渠道指定的后端文件。
3. **等待用户认证**：到达身份验证页面后立即暂停，由用户在设备上完成验证。不得读取、输入、复述、保存或推测密码、面容、指纹或设备认证信息。
4. **申请已提交**：仅在页面明确显示提交成功后进入。此后不得重复申请。
5. **等待生成**：保留已提交状态，等待平台消息或申请记录更新，不通过重复申请催促生成。
6. **文件可下载**：确认消息或申请记录与本次渠道和参数匹配，并明确显示文件已生成。
7. **文件已保存**：确认下载文件与渠道、时间范围匹配，且保存界面成功关闭。
8. **转交已完成**：仅在用户授权转交且目标匹配，并看到明确发送成功证据后进入。

## 多渠道执行

一次请求包含多个渠道时：

1. 分别执行各渠道的完整状态机，不把一个渠道的提交成功或文件生成当作另一个渠道的证据。
2. 遇到需要用户认证的渠道时暂停；用户完成后从该渠道原状态继续，再执行剩余渠道。
3. 下载时核对平台、时间范围、文件类型和最新申请记录，避免保存旧文件或其他渠道文件。
4. 一个渠道失败不自动重做已成功渠道；记录失败状态后继续处理不依赖该失败项的其他渠道。

## 安全边界

- 未获得单独授权时，只保存到用户指定或后端默认的本地位置，不通过邮件、聊天、云盘或其他渠道发送。
- 不擅自修改账号、身份、时间范围、交易类型、接收方式、文件名或保存位置。
- 不读取、复制或披露账单中的交易金额、交易对方、账号标识等敏感内容；只核对完成任务所需的渠道、时间范围、文件类型和状态。
- 转交前再次核对目标设备或渠道；目标不一致或需要额外授权时暂停。

## 交付报告

按渠道分别简要报告：

- 使用的后端；
- 时间范围、交易类型和接收方式；
- 申请、生成、下载、保存是否完成；
- 文件保存位置；
- 是否执行转交及结果；
- 未完成项或需要用户处理的步骤。

不要在报告中包含账单内容或认证信息。
