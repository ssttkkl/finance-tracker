# 支付账单方向审计

本说明用于验证 statement parser 的方向语义，不包含文件账本修复流程。

## 审计步骤

1. 使用去标识化原始 fixture 调用对应 parser。
2. 按 provider 原始状态、方向和交易分类统计输出 category 与金额符号。
3. 对每个风险分支建立独立 parser test，并通过 PostgreSQL statement-import test 验证 lineage 与回滚。
4. 金额断言使用 `Decimal`，不得先转 float 或依赖展示舍入。

## 支付宝

- `交易关闭`、`已关闭`、`还款失败`：没有资金事实，跳过。
- `不计收支` 且金额为 0：跳过。
- 账户提现、转出、投资理财转入/买入：从支付账户视角是流出。
- 收益发放、转出到银行卡的入账流水：按 provider 方向保留。
- 成功退款保留退款事实及 offset 证据，不在 parser 中静默删除原消费。

## 微信

- 中性交易必须结合交易类型与收支方向判断；不能只按描述关键词决定金额符号。
- 退款和原消费都保留来源标识，关系作为 metadata 进入正式导入。

## 银行卡

- 信用卡消费通常形成负债增加；还款/冲正不能按普通消费处理。
- 借记卡收入和支出按带符号金额保留。
- PDF 中出现多个卡尾号时，尾号属于来源证据；当前命令仍由用户显式选择目标账户。

任何无法确定的格式变化必须失败关闭并指出来源记录，不得静默丢行或猜测账户。
