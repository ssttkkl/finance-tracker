# 去重审核检查清单

## 1. 退款配对检查
- 找出所有退款记录（status含"退款"、或方向为"收入"且分类为"退款"/描述含"退款-"）
- 配对：同商户 + 同金额 + 退款日 >= 消费日
- 信用卡退款 → transfer（冲减贷款）
- 现金退款 → expense（正数金额冲减原始expense），不应为 income

## 2. 信用卡还款检查
- icbc_credit中 category=transfer 的记录分两类：
  - **商户退款入账**（小额，如¥1.5/¥5/¥60.9等）→ 对应支付宝/微信侧的退款记录
  - **真实还款**（大额，如¥3,731.77/¥6,259.79/¥10,362.47等）→ 对应借记卡转出记录
- 借记卡转出（amount<0, category=transfer）必须有对应的信用卡转入（amount>0, category=transfer）
- 退款入账不需要借记卡侧匹配（退款本身已抵消信用卡上的消费）

## 3. 跨来源双记检查
- 支付宝/微信(expense) + 借记卡(expense) — 同日同金额 → 双记风险
- 支付宝/微信(transfer) + 信用卡(expense) — 正常，允许
- 检查：同一天、同金额、不同来源、都标记为expense

## 4. 资产调拨检查
- 含"购汇"/"基金"/"证券"/"银证"/"跨境"/"外汇"关键词 → 应为transfer
- 不应出现在 expense 或 income 中

## 5. 借出/赠与检查
- 明确标注"出借" → transfer，归借款账户
- 否→ expense（赠与性质）
- "是我小转转啊"等个人往来需人工判断

## 6. 金额完整性
- 各来源expense之和 = 总expense
- 各来源income之和 = 总income
- transfer 净额 = 0（有出必有进）

## 7. 异常值
- 金额0 → 应已跳过
- 正金额在expense中 → 退款冲减，检查合理性
- 负金额在income中 → 不可能，应修复
- 超过¥100,000 → 人工确认

## 8. 退款时间顺序
- 每笔退款日期 >= 对应消费日期
- 退款日期 < 消费日期 → 数据异常

## 9. 相同交易重复
- 数据库中完全重复行 → 0组
- 同来源/同日/同金额/同商户重复 → 判断是正常重复消费还是CSV重复行
