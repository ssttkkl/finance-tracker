# 建行储蓄卡 XLS 格式

建行个人活期账户交易明细导出为 XLS（老格式 Excel，xlrd 解析）。

## 列结构（9 列）

| 列 | 名称 | 示例 |
|---|---|---|
| 0 | 序号 | 1, 2, 3... |
| 1 | 摘要 | 消费 / 充值 / 消费退货 / 无卡自助交易 / 有卡自助消费 / 银联入账 / 转账支取 / 证转银 / 银转证 / 利息存入 / 缴费 |
| 2 | 币别 | 人民币元 / 美元 |
| 3 | 钞汇 | 钞 |
| 4 | 交易日期 | YYYYMMDD（无分隔符） |
| 5 | 交易金额 | -13.99 / 100.00（已带符号） |
| 6 | 账户余额 | 1,879.94（逗号千分位） |
| 7 | 交易地点/附言 | 始终 `***` |
| 8 | 对方账号与户名 | `账号/名称` 格式，名称常脱敏 |

## 卡号提取

第 2 行（row index 1）：`卡号/账号:621700******2820`

正则：`卡号/账号[：:](\d+)`，末 4 位只保留为来源证据；目标账户由 `ft import --account` 显式指定。

## 脱敏数据

绝大多数消费的对方户名被银行脱敏：

| 原始 | 脱敏后 |
|---|---|
| 星巴克咖啡 | `***咖啡` |
| XX公司 | `***公司` |
| [姓名] | `*震` |
| 微信转账 | `**转账` |

退款记录使用**真实未脱敏名**（如「[姓名]」「[商户名]」），但原消费是脱敏名，因此 counterparty 匹配不可靠。

## 退款配对限制

- **只做精确等额配对**（金额相等 + 30 天窗口 + 末位字符辅助信号）
- **不做部分退款**——脱敏数据下部分退款匹配不可靠（一笔 22.23 退款能匹配任意 >22.23 的消费）
- 孤退款保留为 income

## 退款关键词

建行用「消费退货」而非「退款」或「退货」——退款过滤器需同时匹配 `"退款" or "退货"`。

## 测试 fixture 模板

```python
import xlwt, tempfile, os

def _make_xls(card: str, rows: list[tuple]) -> str:
    """rows: [(摘要, 币别, 钞汇, 交易日期, 交易金额, 账户余额, 交易地点, 对方账号与户名), ...]"""
    wb = xlwt.Workbook()
    ws = wb.add_sheet("Sheet0")
    ws.write(0, 4, "中国建设银行个人活期账户全部交易明细")
    ws.write(1, 1, f"卡号/账号:{card}")
    ws.write(1, 3, "客户名称:[姓名]")
    ws.write(1, 5, "起始日期:20260101")
    ws.write(1, 7, "结束日期:20260609")
    ws.write(2, 1, "当前时间段收支金额合计：")
    headers = ["序号", "摘要", "币别", "钞汇", "交易日期", "交易金额", "账户余额", "交易地点/附言", "对方账号与户名"]
    for ci, h in enumerate(headers):
        ws.write(3, ci, h)
    for ri, row in enumerate(rows):
        ws.write(4+ri, 0, ri+1)       # 序号自动编号
        for ci, val in enumerate(row):
            ws.write(4+ri, ci+1, val)
    tmp = tempfile.NamedTemporaryFile(suffix=".xls", delete=False)
    tmp.close()
    wb.save(tmp.name)
    return tmp.name
```
