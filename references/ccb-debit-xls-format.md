# 建行借记卡 XLS 格式

建行个人活期账户明细由 `src/ft/importers/ccb_debit.py` 读取，使用 `xlrd` 处理 XLS 工作簿。格式探测会检查第 4 行表头中是否包含序号、交易日期、交易金额和账户余额字段。

## 当前字段读取

解析器保留原始表头和值作为单条来源流水的 `source_payload`。当前记录读取以下字段：

| 位置 | 用途 |
|---:|---|
| 第 0 列 | 序号 |
| 第 1 列 | 摘要 |
| 第 2 列 | 币别 |
| 第 4 列 | 交易日期，通常为 `YYYYMMDD` |
| 第 5 列 | 已带正负号的交易金额 |
| 第 6 列 | 账户余额 |
| 第 7 列 | 交易地点或附言 |
| 第 8 列 | 对方账号与户名 |

列 3 的含义和每份导出表的表头以实际 `headers` 为准。解析器不会要求交易地点必须是占位符；支付源和交易对手会结合交易地点、摘要及对方信息推导。

## 账户与退款

工作簿中的卡号末四位作为来源账户证据，导入时由来源账户映射关联到工作区账户。卡尾号只是来源证据之一，账户匹配还要结合银行和卡类型。

正金额记录可根据摘要识别退款信号。退款候选由共享关系匹配逻辑进一步约束，包括来源账户、剩余可抵销金额、日期范围及候选证据；不应假设系统只接受全额退款或仅按固定天数、金额相等配对。无法唯一确认的候选保留给关系审查。

## 解析边界

- 表头缺失、重复或不完整会报错，因为无法构造可靠的原始来源行。
- 不可解析的交易金额会跳过该行；此行为是当前适配器实现，不能概括为所有账单解析器的通用策略。
- 解析行为和退款匹配由 [`ccb_debit.py`](../src/ft/importers/ccb_debit.py)、[`convert.py`](../src/ft/convert.py) 及 [`test_ccb_debit.py`](../tests/test_ccb_debit.py) 定义。
