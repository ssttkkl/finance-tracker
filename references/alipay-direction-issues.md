# 支付宝 CSV 收支方向问题

## 问题

支付宝 CSV 导出的 `收/支` 列有三种值：

| 值 | 含义 | 当前处理 |
|----|------|---------|
| `支出` | 资金流出 | ✅ 识别 |
| `收入` | 资金流入（老版本账单退款也用此值） | ✅ 识别 |
| `不计收支` | 资金流出但不计入收支统计（新版账单退款、预授权、转出到银行等） | ❌ 被 `else: continue` 静默丢弃 |

## 数据分布（2026-01~2026-06 账单）

```
388  支出
 31  不计收支  ← 包含 22 条退款
  6  收入
```

31 条 `不计收支` 中：
- 22 退款（金额 ¥1.80 ~ ¥2,598.95）
- 3 转出到网商银行（自转账）
- 3 预授权/解冻（金额=0）
- 2 交通出行（1 条退款 ¥5.29，1 条预授权金额=0）
- 1 支付宝转入余利宝

## 修复

```python
# 修改前
elif direction == "收入":
    pass
else:
    continue  # ← 不计收支 被跳过

# 修改后
elif direction in ("收入", "不计收支"):
    pass
else:
    continue
```

## 测试陷阱

1. 测试全通过
2. 但真实数据（新版格式）的退款一条都没进去
3. 退款配对逻辑在真实数据上是死代码

缺少实测 `不计收支` 方向的测试。
