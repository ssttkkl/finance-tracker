# 支付宝退款识别重构设计

## 背景

当前 `src/ft/convert.py` 对支付宝退款的入口识别过度依赖 `交易分类` / `商品说明` 文本，导致两类问题：

1. `交易状态=退款成功` 但 `交易分类!=退款` 的真实退款需要靠 description 兜底才能进入配对。
2. 仅靠 `商品说明` 中出现“退款”字样命中的记录置信度偏弱，不适合直接自动核销。

基于 `.ft/bills/支付宝交易明细(20230614-20240613).csv`、`.ft/bills/支付宝交易明细(20240614-20250613).csv`、`.ft/bills/支付宝交易明细(20250614-20260613).csv` 三份真实账单，支付宝退款识别应改为“结构化强信号优先、description 文本弱信号进 AI”。

## 目标

- 重建支付宝退款入口识别，不再以“描述里有退款”作为主入口。
- 让结构化强信号命中的退款继续走脚本自动配对，并在唯一候选时直过。
- 让主要依赖 description 退款语义的记录保留为弱信号，进入 pending / AI 审查。
- 不修改微信、工行信用卡、工行借记卡、建行借记卡的退款入口策略。

## 样本驱动规则

### 非退款直接排除

满足任一直接视为非退款，不进入退款候选：

- `交易状态 in {交易关闭, 已关闭, 还款失败}`
- `收/支 = 支出`
- `收/支 = 不计收支 且 金额 = 0` 且没有结构化退款信号

说明：关闭类记录在真实样本中经常与后续真正退款共享商家订单号，但它本身不是退款入账记录。

### 强信号退款

满足任一视为支付宝强信号退款：

1. `交易状态 = 退款成功`
2. `交易分类 = 退款 且 收/支 = 不计收支`

强信号仅负责“进入退款候选集合”，是否直过仍由现有 `_pair_refunds()` + `_classify_refund_match()` 决定。

### 弱信号退款

满足以下条件时视为弱信号退款：

- `商品说明` 含退款语义（例如 `退款-...`、`买入退款`）
- 但不满足强信号退款条件
- 且不是关闭类记录

弱信号记录允许进入 `_pair_refunds()`，但由于来源信号不强，配对结果必须标记为 `weak`，进入 pending / AI 审查，不直接自动核销。

## 代码层设计

### 1. 新增支付宝退款信号分类 helper

在 `src/ft/convert.py` 中新增 helper，用于基于单行原始字段判定支付宝退款信号类型，返回：

- `alipay_status`：`交易状态=退款成功`
- `alipay_category_nocount`：`交易分类=退款 且 收/支=不计收支`
- `alipay_desc`：仅 description 命中退款语义
- `""`：不是退款信号

该 helper 只负责入口识别，不负责配对强弱决策。

### 2. 调整 `_read_alipay_raw()` 的退款候选收集逻辑

当前逻辑：
- 先写 `_refund_signal`
- 再用 `amount > 0 and ("退款" in txn_type or "退款" in description)` 收集 `refunds`

改造后：
- 每行通过 helper 计算 `_refund_signal`
- `refunds` 集合改为：`amount > 0 and _refund_signal != ""`
- description 只作为 `alipay_desc` 弱信号来源，不再直接充当主入口条件

### 3. 调整强/弱信号判定

在 `_refund_signal_is_strong()` 中：

- 保留 `alipay_status` 为强信号
- 新增 `alipay_category_nocount` 为强信号
- 不把 `alipay_desc` 计入强信号

这样一来：
- `退款成功`
- `分类=退款 且 不计收支`

都会在唯一候选、非 fallback、时间窗合适时直过；
而 description-only 命中的退款会被 `_classify_refund_match()` 自动判为 `weak`。

## 预期行为

### 直接自动处理

以下场景可继续脚本自动核销：

- `交易状态=退款成功` 的高德打车、12306、拼多多、Steam、淘宝闪购等退款
- `交易分类=退款 且 收/支=不计收支` 的基金买入退款等异常状态场景

### 进入 AI 审查

以下场景不再视为强规则：

- 主要依赖 `商品说明` 中“退款”字样才能怀疑是退款的记录
- description fallback / gross candidate / 多候选竞争 等原有弱匹配场景

## 测试要求

至少补充/调整以下测试：

1. `交易状态=退款成功` 且 `交易分类!=退款` 的支付宝退款进入强信号配对。
2. `交易分类=退款 且 收/支=不计收支` 且 `交易状态=交易成功` 的基金买入退款进入强信号配对。
3. 仅 description 命中退款语义的支付宝记录仍进入 pending，`rule_hint` 保持 `refund_desc_fallback` 或候选匹配路径，但 `match_strength=weak`。
4. 现有 `交易关闭/已关闭/还款失败` 跳过逻辑不回退。

## 非目标

- 不在本次改动中重写 `_pair_refunds()` 的配对策略。
- 不在本次改动中处理 0 元退款审计追踪。
- 不修改其他账单渠道的退款入口。
