# 现金导入临时存储配置

现金导入只暂存解析行、来源范围、选择及计划，不保存原文件或密码。R2 与显式启用的进程内存储共用配置；暂存不是账本事实，账户通过独立命令立即生效，流水和关系在最终确认时一起提交。当前公开接口见 [导入合同](cash-import-redesign-contracts.md)，原文件会话及其存储实现已移除。

客户端尚在迁移，当前后端不得单独部署到旧客户端环境。旧会话不续用；发布时停止旧写入、作废旧临时上下文，并按已授权的精确对象命名空间处理旧原文件对象。删除代码不代表远端旧对象已经清理。

## R2 配置

设置 `FT_IMPORT_STAGING_BACKEND=r2`，并提供：

- `FT_R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com`
- `FT_R2_BUCKET=<private-bucket-name>`
- `FT_R2_ACCESS_KEY_ID=<scoped-access-key>`
- `FT_R2_SECRET_ACCESS_KEY=<scoped-secret-key>`

可选配置：

- `FT_R2_PREFIX=cash-import`：对象键前缀。
- `FT_IMPORT_STAGING_TTL_SECONDS=1800`：会话有效时间，范围为 1–1800 秒。

凭据应限制在暂存 bucket 所需的对象读、写和删权限。bucket 不应公开访问；不要将凭据写入仓库、日志或浏览器响应。可配置对象生命周期清理作为应用清理的兜底，保留期限不得超过业务允许的账单暂存周期。

部署平台、数据库和对象存储的选择由运行环境决定；本文不假设特定生产供应商。

## 本地与测试

内存后端必须显式选择并允许：

`FT_IMPORT_STAGING_BACKEND=memory`
`FT_IMPORT_STAGING_ALLOW_MEMORY=1`

内存适配器适用于本地开发或测试，不具备跨进程持久性。未显式配置暂存后端、R2 配置缺失或无效时，应用应启动失败，不应静默切换到其他存储。

## 解析存储的清理运行条件

运行期在同一显式后端配置下构造新解析存储及必需清扫器。除上述权限外，R2 凭据必须允许列出暂存前缀和读取对象元数据（HEAD）。新对象位于私有 `parsed/<digest>/session` 子路径；对象元数据只附固定的 `expires-at`，修改不续期。清扫不下载解析正文，也不删除该路径之外的对象。

- `FT_IMPORT_STAGING_SWEEP_SECONDS=30`：一轮结束后的等待秒数，范围为 1–60。
- `FT_IMPORT_STAGING_SWEEP_PAGE_SIZE=100`：每页最多检查的对象数，范围为 1–200；有下一页时继续，不等待用户请求。
- R2 客户端连接／读取超时分别为 3／5 秒，至多两次尝试；关闭服务时通知正在进行的清扫，在当前远程操作结束后停止。

启动首轮清扫失败时不接受请求；后续故障设置不健康状态、记录 `cash_import_cleanup_unavailable` 并按周期重试，日志不含对象键、来源正文或供应商错误。健康及最后一页的数量可通过服务内 `app.state.parsed_import_cleanup` 供运行检查使用，不向客户端暴露临时对象地址。

TTL 到达即禁止访问；物理删除受扫描、网络和服务运行状态影响，不能将 TTL 声称为停机期间仍有精确删除时刻。服务恢复后重新扫描。部署时仍须配置私有存储生命周期作为兜底，并监控清扫健康；当前只完成内存和模拟 R2 合同，尚未执行真实 R2 部署验证。
