# 研究记录：现代化收支账本界面

## R-001：展示层重构边界

- **决定**：仅重构 React 展示组件和页面样式；保留 `CashLedgerPage` 的请求编排、`AbortController`、请求序号、游标栈、投影更新处理、证据焦点恢复，以及现有 API 调用与类型。
- **理由**：021 的事实源只允许改变既有能力的呈现。将数据读取或状态机一并重写，无法证明筛选、稳定分页、版本更新和证据行为没有变化。
- **备选方案**：只修改 `web/src/styles.css`；因无法充分改善筛选、状态和证据详情的阅读层级而拒绝。重写 API 或后端；因违反 feature 边界而拒绝。

## R-002：Hallmark 设计方向的适配

- **决定**：采用 Hallmark 的 `modern-minimal` 类型、`Workbench` 宏观结构与 Cobalt 的冷色、精确、工具化语言；但不采用 Cobalt 面向营销页的命令面板、代码 hero、虚构导航、页脚或字体替换要求。
- **理由**：收支账本是既有单页核对工具，不是营销页。Cobalt 的冷灰纸面、单一蓝色强调、细边线、紧凑圆角和数字优先适合本 feature；命令面板、代码演示和多目的导航会新增用户工作流，违反 FR-001 与 FR-015。
- **备选方案**：完整照搬 Cobalt；会新增命令面板和字体依赖。仅使用“技术感”描述而不采用可检查的视觉契约；会导致实现结果不可复核。两者均拒绝。

## R-003：字体与令牌

- **决定**：继续使用已安装的 `Noto Sans SC` 作为中文正文与界面文本、`IBM Plex Mono` 作为金额、发生时间、标识和筛选/状态微标签。令牌只在 `web/tokens.css` 和 `web/src/styles.css` 中定义，并全部通过 `var(--...)` 使用。
- **理由**：现有字体支持中文并已进入构建；新增 Space Grotesk、Inter 或 JetBrains Mono 会违背不新增依赖的范围，并可能使中文回退字体破坏信息密度。IBM Plex Mono 保留数值稳定对齐的价值。
- **备选方案**：加载 Cobalt 原始字体组合；拒绝，因新增依赖和中文覆盖风险。组件内硬编码颜色/字体；拒绝，违反 Hallmark 令牌纪律。

## R-004：状态与动效

- **决定**：保留已有加载骨架、状态文字、错误重试、详情抽屉和筛选 `<details>`；仅添加明确的 hover、active、disabled 与 focus-visible 样式。抽屉只允许 `transform` 与 `opacity` 过渡，并在 `prefers-reduced-motion: reduce` 时静止或压缩为不超过 150 ms 的非空间反馈。
- **理由**：状态、焦点和键盘行为是 020 的已验证合同。视觉改造不能用庆祝式 toast、滚动动画或色彩唯一提示改变用户对状态的理解。
- **备选方案**：统一页面 reveal 动画；拒绝，账本核对场景不需要装饰性运动，且会增加回归面。

## R-005：响应式与语义

- **决定**：保留 1024 px 以上的列表/证据并列布局与 767 px 以下的投影卡片呈现；新增 Hallmark 检查宽度 320、375、414、768 px。`html` 和 `body` 都使用 `overflow-x: clip`，所有可点击文本保持单行，卡片化表格继续保留 `<thead>`、`<th scope="col">` 与 `<caption>`。
- **理由**：现有 390 px 浏览器测试已证明移动主路径；Hallmark 宽度可发现更窄尺寸的截断、重叠与焦点问题。`overflow-x: hidden` 会破坏固定/粘性布局，不可使用。
- **备选方案**：用 `display: none` 隐藏表头；拒绝，辅助技术失去字段关联。只依赖 `data-label` 伪元素；拒绝，不能替代原生表格语义。

## R-006：视觉快照

- **决定**：在 Playwright 使用固定去标识化数据为 1440 × 900、1024 × 768、768 × 1024、390 × 844 截取并比较主流程、加载、空、错误和证据详情快照；将 320、375、414、768 px 用于 Hallmark 响应式人工/浏览器检查。快照通过受版本控制的基线图或明确允许的更新流程维护。
- **理由**：DOM 和角色断言无法覆盖字体密度、金额截断、详情并列比例和移动卡片可读性。固定 fixture 使快照差异可复现。
- **备选方案**：只使用现有 E2E；拒绝，无法证明视觉重构的质量。为快照增加新的 API mock 或数据能力；拒绝，应复用现有 `mockLedger` fixture。

## R-007：范围静态边界

- **决定**：021 允许修改 `web/src/pages/`、`web/src/components/`、`web/src/styles.css`、可选 `web/tokens.css`、`web/tests/` 和 021 artifacts。禁止修改 `web/src/api/`、`src/ft/`、`migrations/`、依赖清单、020 artifacts 与 022 artifacts。
- **理由**：限制实现者只能消费已存在的数据和事件，并让最终 diff 审核能够直接证明未新增领域/API/持久化能力。
- **备选方案**：为视觉组件提取跨 feature 包；拒绝，属于提前建设设计系统。

## R-008：实施基线

- **决定**：在 020 当前未提交改动完成其自身收敛前，不启动 021 实施。设计讨论时记录的候选基线是 `3e1e4b3`；真正的 implementer worktree 必须从包含 020 收敛结果的明确提交创建，并在 `plan.md` 的实施交接处更新 SHA。
- **理由**：020 和 021 会触及相同的前端文件。缺少冻结基线时，无法分辨视觉重构与 020 行为修复。
- **备选方案**：在当前工作树直接继续实现；拒绝，违反独立 feature 与工作树隔离要求。
