# Feature Specification：现代化收支账本界面

**Feature Branch**：`021-modern-web-ui-design`

**Created**：2026-07-30

**Status**：Draft

**Input**：在 `020-cash-ledger-browser-web` 已实现的界面功能上，采用技术感、工具化的现代视觉语言改造收支账本；不得新增产品功能。

**Context**：本 feature 仅改造 `020-cash-ledger-browser-web` 已实现的收支账本页面、筛选条、收支投影列表、分页、加载/空/错误/更新状态和证据详情的视觉层级、信息密度及响应式呈现。它不新增月度收支摘要、现金流判断、日期范围以外的新工作流、导航入口或任何后端、API、数据与领域能力。

## 澄清记录

### Session 2026-07-30

- Q：本 feature 是否包含月度分币种收支摘要、净现金流判断或新的导航能力？→ A：否。仅在 020 已实现的 UI 功能上做界面改造，不新增产品功能。
- Q：界面设计应遵循什么流程？→ A：必须使用 `$hallmark` 完成现有界面的设计预检、现代化视觉设计、响应式验证和反模式检查；其设计结论必须回写本 feature artifacts，不得只留在对话中。

## 用户场景与测试

### 用户故事 1：高效筛选并浏览收支账本（优先级：P1）

使用者在日常记账和线上核对时，使用更清晰、紧凑且具有工具感的界面筛选收支投影、浏览列表并继续分页查看结果。

**为何优先**：筛选和浏览是当前收支账本最常用的主流程。现代化改造应提高扫读效率，但不能改变既有筛选或分页行为。

**独立测试**：在已有去标识化收支投影中，依次应用 020 已支持的筛选条件、翻页并清除筛选，确认视觉层级变化后请求参数、列表字段、结果、分页位置和键盘操作与改造前一致。

**验收场景**：

1. **假如** 使用者进入收支账本，**当** 其查看页面，**那么** 页面以清楚的标题、筛选工具、投影列表和分页组织信息，且不显示虚构指标、图表或新增业务模块。
2. **假如** 使用者使用日期、账户、交易对方、分类、币种、金额、经济类型或组成方式筛选，**当** 筛选条件变化，**那么** 页面保留 020 已定义的筛选语义、请求范围和起始分页行为。
3. **假如** 使用者浏览收支投影列表，**当** 其扫读金额、发生时间和交易对方，**那么** 金额保持等宽右对齐，时间、文本和操作入口具有清楚层级，且列表仍按 020 规定的字段顺序呈现。

---

### 用户故事 2：打开证据详情完成线上核对（优先级：P1）

使用者从现代化的收支投影列表打开证据详情，阅读投影结果、主记录、投影成员、已采用关系、未生效关系提示和退款时间线，并在关闭后继续原位置的核对。

**为何优先**：证据详情是收支投影可审计性的用户入口。视觉改造必须强化阅读层级，不能弱化现有内容、焦点管理或核对上下文。

**独立测试**：打开任一投影的证据详情，确认全部既有证据内容可读；通过关闭按钮和 `Escape` 关闭后，确认焦点回到原“查看”入口，筛选和分页上下文保持不变。

**验收场景**：

1. **假如** 使用者从列表打开证据详情，**当** 详情出现，**那么** 宽屏中列表与详情可并列核对，详情内的投影结果和证据分组更易扫读，但不遗漏或重命名 020 已定义的证据内容。
2. **假如** 使用者关闭证据详情，**当** 页面回到列表，**那么** 筛选条件、当前列表位置和键盘焦点与打开前一致。
3. **假如** 证据读取中断或不完整，**当** 使用者查看详情，**那么** 页面沿用既有可操作的文字状态，不能只通过颜色、图标或动效表达问题。

---

### 用户故事 3：在不同屏幕和输入方式下完成核对（优先级：P2）

使用者在桌面或手机上使用鼠标、触摸或键盘，完成筛选、分页、打开和关闭证据详情。

**为何优先**：现代化界面不能以牺牲窄屏信息可读性、表格语义或键盘可访问性换取视觉效果。

**独立测试**：分别在 1440 × 900、1024 × 768、768 × 1024 和 390 × 844 视口中，以键盘完成筛选、分页和证据详情开关，确认没有横向溢出、内容遮挡、焦点丢失或触控目标过小的问题。

**验收场景**：

1. **假如** 使用者在宽屏打开证据详情，**当** 其核对投影，**那么** 列表与详情保持并列，关键金额、操作和文字不被遮挡。
2. **假如** 使用者在窄屏浏览列表，**当** 其查看投影条目，**那么** 卡片化视觉呈现保留原生表头和字段语义关联，备注、金额和“查看”入口均可读可操作。
3. **假如** 使用者只使用键盘或辅助技术，**当** 其操作筛选、分页和证据详情，**那么** 所有交互元素具有可访问名称、可见焦点和非颜色唯一的状态说明。

---

### 边界与失败场景

- 当收支投影加载、账户目录读取、证据读取或分页失败时，页面必须保留 020 已定义的稳定、脱敏且可操作的文字提示；视觉改造不得把失败误导为无数据。
- 当收支投影版本更新时，页面必须保留 020 已定义的关闭旧详情、回到第一页、保留筛选、提示刷新和焦点移动行为。
- 当窄屏表格转换为卡片呈现时，视觉隐藏的表头不得使用 `display: none`，也不得只依赖 CSS 生成的标签替代表头语义。
- 当使用者偏好减少动效时，页面不得用运动效果传达关键状态；已有详情过渡必须保持静止或降级为非空间效果。

## 需求

### 功能需求

- **FR-001**：系统必须仅改造 `020-cash-ledger-browser-web` 已实现的收支账本、筛选、收支投影列表、分页、状态视图和证据详情的视觉与交互呈现；不得新增产品功能、领域行为、读取范围或用户工作流。
- **FR-002**：系统必须使用 `$hallmark` 设计技能完成设计预检、现代化界面设计、令牌约束、响应式检查和反模式检查；Hallmark 的设计方向、保留项和验证结果必须回写本 feature 的 `spec.md`、`plan.md` 或 `tasks.md`，不得只保留在对话记录中。系统还必须在固定视口为既有主流程保存并比较视觉快照，快照仅验证展示层，不得引入新的用户功能、API 或数据状态。
- **FR-003**：系统必须以技术感、工具化的视觉语言组织现有页面，使用清晰的信息层级、紧凑但可读的间距、精确的分隔关系和克制的交互反馈，帮助使用者优先识别筛选范围、投影条目、金额和证据入口。允许重排既有控制项与改变其视觉容器；不得新增筛选动作、默认筛选值、持久化偏好、URL 状态、导航目的地、确认步骤或需要学习的新操作。
- **FR-004**：系统必须保留页面名称“收支账本”、现有说明文字的业务含义，以及 020 已定义的加载、无数据、账本更新、投影不可用、请求失败和证据不完整状态。
- **FR-005**：系统必须保留现有日期、账户、交易对方、分类、币种、最低金额、最高金额、经济类型和组成方式筛选的字段、选项、请求语义及筛选变化后回到第一页的行为。
- **FR-006**：系统必须保留收支投影列表的字段顺序：发生时间、账户、交易对方、备注、分类、金额、来源和证据入口；“组成方式”只能保留为筛选维度和证据详情中的关系信息，不得恢复为列表列或关系摘要文本。
- **FR-007**：系统必须继续使用等宽数字呈现金额和发生时间，金额右对齐，并通过文本、正负号和颜色共同表达收入与支出；不得只依赖颜色区分金额含义。
- **FR-008**：系统必须保留稳定分页、筛选变化时游标失效、请求取消、迟到响应保护和收支投影版本更新处理的既有行为。
- **FR-009**：系统必须在不删除证据字段、不改变字段含义、顺序语义、脱敏范围或错误合同的前提下，强化投影结果、主记录、投影成员、已采用关系、未生效关系提示和退款时间线的阅读层级。若需优化用户可见标题或说明文字，必须先经 `$domain-glossary` 与 `$chinese-documentation` 审校，并补充相应回归测试。
- **FR-010**：系统必须保留证据详情的焦点圈定、关闭按钮自动获焦、`Escape` 关闭、背景不可交互和关闭后焦点恢复到原入口的行为。
- **FR-011**：系统必须在宽屏支持收支投影列表与证据详情并列核对，在窄屏保留顶部导航、可展开筛选、无横向溢出的列表和全屏证据层。
- **FR-012**：系统必须保留原生表格语义、`caption`、列头和字段关联；窄屏卡片化展示不得降低辅助技术读取列头和字段的能力。
- **FR-013**：系统必须使导航、筛选、分页、证据入口、重试和状态确认操作保持键盘可用，具有可访问名称、清楚的焦点样式和至少 44 px 的窄屏触控目标。
- **FR-014**：系统必须保留并使用现有 `Noto Sans SC` 正文与 `IBM Plex Mono` 数值字体；可引入仅服务于 021 页面样式的有限 CSS 自定义属性，以统一颜色、间距、边界、字体与动效，但不得新增 UI 库、图表、动画库、主题切换、跨 feature 组件库或完整设计系统。
- **FR-015**：系统不得新增月度收支摘要、现金流判断、跨币种汇总、汇率折算、预算、预测、编辑、删除、导入、关系操作、投资账本入口、认证、云同步或任何后端、API、数据模型与持久化能力。
- **FR-016**：系统必须遵循项目既有术语：面向使用者的页面使用“收支账本”“投影条目”“证据详情”等表达；内部的“收支投影”不得被机械地替换为面向使用者不易理解的术语。

### 关键实体

- **账本工作台**：将当前已实现的收支账本标题、筛选、投影条目列表、分页、状态提示和证据详情组织为便于日常核对的只读界面。
- **投影条目**：收支账本中可独立浏览和核对的既有结果，保持 020 对字段、金额、筛选和证据的定义。
- **证据详情**：针对投影条目展示投影结果、主记录、投影成员、生效关系、未生效关系提示和退款时间线的既有只读审计内容。

## 成功标准

### 可衡量成果

- **SC-001**：在至少包含 100 条投影条目的去标识化工作区中，使用者可在 2 分钟内完成筛选、连续翻页、打开证据详情和返回列表，且筛选条件、列表结果与证据内容与改造前的既有合同一致。
- **SC-002**：自动化回归确认所有既有筛选条件、请求参数、稳定分页、投影版本更新、证据详情字段和错误状态的行为保持一致，回归失败数为 0。
- **SC-003**：自动化浏览器验收在 1440 × 900、1024 × 768、768 × 1024 和 390 × 844 视口中确认收支账本没有横向溢出、文字重叠、被遮挡的金额或关键操作。
- **SC-004**：自动化浏览器验收确认仅使用键盘即可完成筛选、分页、打开和关闭证据详情；详情关闭后，焦点恢复到原证据入口的成功率为 100%。
- **SC-005**：自动化无障碍验收确认表头、字段关联、可访问名称、焦点样式和状态文字保持可用；关键状态仅依赖颜色、图标或动效表达的次数为 0。
- **SC-006**：自动化验收确认本 feature 不新增月度汇总、现金流判断、投资请求、跨币种计算、写入操作或新的后端读取合同，出现次数为 0。
- **SC-007**：Hallmark 交付前检查确认在 320、375、414 和 768 px 宽度不存在横向溢出、双行可点击文字、无语义表头或不可见焦点；反模式检查发现的未解决问题数为 0。
- **SC-008**：在 1440 × 900、1024 × 768、768 × 1024 和 390 × 844 视口中，固定去标识化数据的主流程、加载状态、空状态、错误状态和证据详情均具有经人工确认的视觉快照；未经确认的视觉差异数为 0。

## 非目标

- 月度收支摘要、净现金流判断、对比月份、跨币种汇总、汇率读取或展示币种折算。
- 修改收支投影构建、关系确认、退款冲销、内部转账分类、金额精度、投影版本、稳定分页、隐私脱敏或错误合同。
- 新增或修改后端、Web API、数据模型、数据库 schema、迁移、持久化、查询语义或运行时配置。
- 编辑、删除、导入账单、关系确认、驳回、预算、余额预测、资金建议、认证、云同步或多用户能力。
- 投资事件、持仓、持仓估值、行情报价、投资账本页面或其导航入口；这些能力属于 `022-investment-ledger-browser-web`。
- 完整设计系统、通用组件库、营销页面、虚构指标、统计卡片、图表或装饰性图形。
- 将 `020-cash-ledger-browser-web` 尚未完成的领域、语义或验收工作并入本 feature。

## 假设

- `020-cash-ledger-browser-web` 在本 feature 实施前已收敛，且提供稳定的只读收支投影、筛选、分页、证据、可访问性和双后端合同基线。
- 使用者在受信任的本机环境中使用只读收支账本；本 feature 不改变运行位置、访问边界或数据来源。
- 现代化界面优先服务精确读数、筛选和证据核对，不以动画、插画、营销内容或新增交互替代业务信息。
- 视觉改造可在不改变既有用户可见业务文案的前提下优化排版和层级；若必须调整文案，应先按项目术语表和中文文档规范审校。
