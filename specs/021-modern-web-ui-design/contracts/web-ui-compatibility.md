# Web 界面兼容性合同

## 目的

Feature 021 只改变既有收支账本 Web 的展示层与连续浏览控制。本合同定义必须保持的读取、筛选、稳定 `cursor`、证据和无障碍边界。

## 不变的读取接口

| 读取目的 | 既有调用 | 不变要求 |
|---|---|---|
| 账户目录 | `fetchCashAccounts` | 请求时机、账户选项和失败重试不变 |
| 收支记录列表 | `fetchCashPage` | 筛选参数、`cursor`、版本更新、加载/空/错误状态不变；自动连续加载仅可改变调用时机和次数 |
| 证据详情 | `fetchEvidence` | 证据标识、字段、脱敏、失败重试和焦点恢复不变 |

不得新增、替换或修改 `web/src/api/` 调用，不得新增 API 端点、请求参数、读取范围、后端 route、DTO、查询、持久化或外部请求。自动连续加载仅可改变既有 `fetchCashPage` 的调用时机和次数。

## 筛选与连续加载合同

- 字段：开始日期、结束日期、账户、交易对方、分类、币种、最低金额、最高金额、经济类型、组成方式。
- 筛选默认折叠；展开、填写或收起不增加应用、清除、保存偏好或 URL 状态等动作。
- 枚举选项与传输值保持不变。
- 任一筛选变化后：取消当前首批或追加请求，递增请求代次，清空已加载收支记录与下一个 `cursor`，从 `null` 游标读取首批；其余筛选条件保持。
- 列表使用返回的 `next_cursor` 自动连续加载，并始终提供“加载更多”按钮作为键盘、辅助技术、浏览器不支持自动触发与自动加载失败时的回退；不提供上一页或下一页。
- 同一 `cursor` 同时最多一个请求；成功追加的收支记录按服务端排序保留，并按 `projection_id` 去重。
- 追加失败不清空已显示收支记录，不自动循环重试；显示可操作文字错误与“重试加载更多”。无 `next_cursor` 时显示已显示全部记录。
- 列表不得展示“组成方式”列或关系摘要；组成方式仅存在于筛选与证据详情的既有关系信息中。

## 列表与证据合同

### 收支记录

- 桌面 DOM 列顺序固定为：发生时间、账户、交易对方、备注、分类、金额、导入渠道、证据入口。
- 主列表标题、caption、加载和空状态不得向使用者展示“投影”“投影条目”“主记录发生时间”、`source_type` 或 cursor 等技术说明；页面名称保持“收支账本”。
- 窄屏记录卡必须以真实文本显示分类和导入渠道，不能只依赖 CSS 伪元素。
- 金额继续显示 API 提供的精确十进制字符串和币种；不得使用浏览器浮点运算重新计算。
- `<caption>`、`<thead>`、`<th scope="col">` 保持存在；窄屏不得以 `display: none` 隐藏表头。
- “查看”入口的可访问名称必须含对应交易对方或“该记录”。

### 证据详情

- 展示投影结果、主记录、来源行快照、投影成员、已采用关系、未生效关系提示和退款时间线。
- 不删除字段，不改变字段含义、脱敏范围、错误合同或顺序语义。
- 打开后关闭按钮自动获焦；`Escape` 关闭；Tab 与 Shift+Tab 不离开详情；背景不可交互；关闭后焦点回到原触发入口。

## 版本更新与失败合同

| 情形 | 既有结果 |
|---|---|
| `projection.updated` | 取消追加、关闭旧详情、保留筛选、清空已加载收支记录，从首批重新读取，显示更新提示并将焦点交给确认按钮 |
| `projection.unavailable` | 明确提示收支账本暂不可用，不回退显示原始现金流水 |
| `invalid_filter` / `invalid_cursor` | 使用既有可修正的中文错误说明 |
| `storage.*` / 请求失败 | 使用脱敏的可操作错误说明和重试入口 |
| 追加读取失败 | 保留已加载记录，显示文字错误和“重试加载更多”入口 |
| 证据不完整 | 显示明确的详情不完整状态和重试入口 |

## 视觉快照合同

使用现有去标识化 Playwright fixture，分别捕获以下固定视口的快照：

- 1440 × 900：默认折叠筛选、展开筛选、连续加载状态、并列证据详情。
- 1024 × 768：并列详情临界布局、加载更多或追加失败状态。
- 768 × 1024：顶部导航、折叠筛选、列表重排。
- 390 × 844：卡片列表中的分类与导入渠道、展开筛选和全屏证据详情。
- 同一 fixture 的首批加载、追加加载、空、错误、已显示全部记录和证据详情状态。

快照更新必须人工检查，确认差异只来自批准的展示层改造。任何 API 请求、字段含义、焦点或业务状态变化都不是允许的“视觉更新”。
