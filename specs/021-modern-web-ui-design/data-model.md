# 界面状态模型：现代化收支账本界面

本 feature 不新增持久化实体、领域实体、API DTO 或数据库 schema。本文件只记录展示层必须保留和重新编排的既有状态，以及视觉令牌的受限范围。

## 1. 既有页面状态

| 状态 | 来源 | 可重构的呈现 | 不可改变的行为 |
|---|---|---|---|
| 账户目录加载成功 | `fetchCashAccounts()` | 筛选控件的密度、标签、边界和布局 | 账户选项、错误提示和重试行为 |
| 账户目录失败 | 账户目录请求失败 | 错误容器和重试按钮的视觉层级 | 文字含义、`role="alert"` 与重试调用 |
| 投影加载中 | `status === "loading"` | 骨架、状态文案和表格表面的视觉 | 保留表头、骨架单元格和文字状态 |
| 投影就绪 | `status === "ready"` | 工作台布局、表格行、金额、连续加载与证据入口 | 8 列字段顺序、金额内容、基于稳定 `cursor` 的读取语义 |
| 收支记录追加中 | 已加载首批且正在读取下一个 `cursor` | 列表末端加载提示与“加载更多”禁用状态 | 保留已加载记录；同一 `cursor` 不并发请求 |
| 收支记录追加失败 | 已加载首批且读取下一个 `cursor` 失败 | 列表末端文字错误与重试入口 | 保留已加载记录；不自动循环重试；重试仍读取同一 `cursor` |
| 已显示全部记录 | `next_cursor` 不存在 | 列表末端终止提示 | 不再请求下一批，不显示上一页或下一页 |
| 无匹配投影 | `status === "empty"` | 空状态表面、文字排版 | “当前筛选没有匹配的收支投影。”的业务含义 |
| 投影请求失败 | `status === "error"` | 错误容器、重试按钮和强调方式 | 脱敏错误文案、`role="alert"` 和重试调用 |
| 投影已更新 | `projectionUpdated === true` | 更新提示的视觉和确认按钮 | 关闭旧证据、回到第一页、保留筛选、焦点交给确认按钮 |
| 证据加载中 | `selected` 且 `evidenceState === "loading"` | 审阅区加载状态 | 关闭按钮自动获焦、背景不可交互 |
| 证据就绪 | `evidenceState === "ready"` | 证据分组、定义列表、列表密度与标识显示 | 证据字段、字段含义、脱敏范围和顺序语义 |
| 证据失败/不完整 | `evidenceState === "error"` 或缺少主记录 | 失败容器、重试按钮与说明层级 | `role="alert"`、重试、关闭与焦点恢复 |

## 2. 页面交互状态

```text
页面初始加载
  ├─ 账户目录：成功 ────────────────┐
  └─ 账户目录：失败 → 可重试 ───────┤
                                    ▼
投影请求 → 加载中 → 就绪 ─────────→ 筛选 / 连续加载 / 打开证据
                    ├→ 追加中 → 追加成功 / 追加失败 → 人工重试
                    ├→ 无匹配投影
                    ├→ 可操作错误 → 重试
                    └→ 投影已更新 → 关闭证据、清空已加载记录、重置 `cursor`、保留筛选、刷新

打开证据 → 详情加载中 → 详情就绪 / 详情失败 / 详情不完整
     │                                                 │
     └──────────── Escape 或关闭按钮 ←──────────────────┘
                            │
                            └→ 焦点恢复到原“查看”按钮
```

禁止状态变化：

- 视觉重构不得添加月份、摘要、图表、投资入口、写入或新的筛选状态。
- 视觉重构不得绕过请求取消、请求序号或投影更新处理。
- 详情打开时不得允许背景重新获得指针或键盘操作。

## 3. 视觉令牌

令牌必须定义在 `web/tokens.css`（若创建）或 `web/src/styles.css` 顶部，并且页面样式只能通过 `var(--...)` 引用。令牌只服务当前页面，不构成跨 feature 设计系统。

| 令牌组 | 角色 | 约束 |
|---|---|---|
| `--color-paper*` | 冷色浅表面及分层表面 | 使用带轻微蓝色倾向的 OKLCH 值；不得使用纯白作为主表面 |
| `--color-ink*` | 主要、次要和弱化文字 | 保持正文与背景至少 4.5:1 对比度 |
| `--color-rule*` | 表格、输入框和区域边界 | 以 1 px 边界提供层级，不以堆叠阴影代替 |
| `--color-accent` / `--color-accent-ink` | 单一钴蓝操作与其文字 | 仅用于焦点、当前页、主要操作和少量状态强调；填充表面必须指定 `--color-accent-ink` |
| `--color-income` / `--color-expense` | 收入和支出辅助色 | 必须与正负号、文本或标签共同表达，不能单独传达含义 |
| `--font-body` / `--font-mono` | 中文正文与数值信息 | 固定为已有 `Noto Sans SC` 与 `IBM Plex Mono` 回退链 |
| `--space-*` | 4 px 间距节奏 | 所有新增间距从命名比例中选择 |
| `--radius-*` / `--rule-*` | 紧凑圆角与边界 | 控件使用紧凑半径；不得采用胶囊式全圆角 |
| `--dur-*` / `--ease-*` | 过渡 | 只允许 `transform` 与 `opacity`；焦点环即时出现 |
| `--z-*` | 层级 | 详情层、固定导航和提示使用命名层级，禁止临时大数值 |

## 4. 组件状态样式

所有交互控件需定义以下呈现，而不改变其现有事件或属性：默认、hover、`:focus-visible`、active、disabled、loading、error、success。

- 原生筛选输入和 select：边框宽度始终为 1 px；focus 用即时 outline，不得引起布局位移。
- 按钮：窄屏最小高度 44 px；hover 仅允许一个细微信号；active 允许 1 px 向下位移。
- 重试与确认：文本保持单行，状态不只用颜色。
- 详情关闭：保留现有焦点与 Escape 行为，样式不改变其可访问名称。

## 5. 响应式布局状态

| 宽度 | 布局行为 | 必须验证 |
|---|---|---|
| 1440 × 900 | 侧栏 + 账本；打开详情后账本与详情并列 | 金额右对齐、详情不遮挡账本、连续加载和筛选可操作 |
| 1024 × 768 | 既有桌面并列详情临界布局 | 主区最小宽度、详情最小宽度、无横向溢出 |
| 768 × 1024 | 顶部导航、筛选重排、列表仍可读 | 控制项单行可点击、焦点顺序、表格语义 |
| 390 × 844 | 顶部导航、收支记录卡、全屏证据层 | 备注/金额/查看入口、44 px 触控目标、无溢出 |
| 320 / 375 / 414 / 768 px | Hallmark 响应式检查 | 无横向滚动、可点击文案不换行、焦点可见、表头语义存在 |
