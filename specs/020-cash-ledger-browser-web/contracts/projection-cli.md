# 收支投影维护命令合同

## `ft projections rebuild`

使用 `FT_DATABASE_URL` 和 `FT_WORKSPACE_ID` 对当前工作区执行全量重建：

1. 锁定投影状态并创建暂存数据集。
2. 读取全部有效现金流水和已确认双边现金关系。
3. 使用当前规则版本构建投影。
4. 验证每条有效现金流水恰好归属一次、关系依据完整以及金额不变量。
5. 在同一事务内发布新数据集、增加投影版本，并把旧数据集标记为 `retired`。

相同输入可重复执行；业务结果必须相同。命令成功时退出码为 0，并输出工作区、投影版本、规则版本、
投影条目数、成员数和耗时，不输出原始财务数据。

失败时退出码非 0，输出稳定错误码和可操作摘要：

- `projection.invalid_relation`：关系方向、币种、退款累计、端点或组合非法。
- `projection.incomplete`：成员归属存在遗漏或重复。
- `projection.concurrent_update`：来源在构建期间发生不兼容变化。
- `storage.*`：沿用存储错误合同。

有活动数据集时，失败不得替换它；没有活动数据集时保持投影不可用。命令不得自动修复、驳回或取代
关系。

## `ft projections status`

只读返回：工作区、可用性、活动数据集、投影版本、来源版本、规则版本、最近构建状态、开始/结束时间、
投影条目数、成员数、稳定错误码和脱敏失败摘要。

状态检查必须仅以既有数据库的严格只读连接执行：SQLite 不得触发构建、迁移、后端回退、文件创建、日志
模式切换或旁路文件写入；PostgreSQL 必须在数据库级 `READ ONLY` 事务内执行。目标不存在、不可读或连接
失败时返回稳定 `storage.*` 错误。没有状态行时按 `uninitialized` 返回，而不是报出驱动异常。

## 事务内增量维护

现金流水新增、逻辑删除、已确认关系新增/失效和待审核关系确认会在原 Unit of Work 内调用条件增量维护：

- 工作区存在活动投影版本时，读取变更前后的完整已确认关系连通组。
- 对候选关系先构建验证，再持久化关系状态。
- 替换活动数据集中的受影响投影、成员和关系依据。
- 增加投影版本后与事实源一次提交。
- 工作区尚未建立活动投影版本时，合法事实源写入可以提交，但不生成或维护投影；必须通过显式 `ft projections rebuild` 发布首个活动数据集。

任一步失败都回滚事实源和投影。`ft transfer` 已明确知道两端属于一次内部资金移动，必须在创建两条现金
流水时同步创建已确认 `transfer_pair` 关系，再生成隐藏的内部转账投影。

命令必须捕获 `projection.*`、`storage.*`、SQLite 快照与引擎清理错误，向标准错误输出稳定错误码和脱敏摘要，
并以非零状态退出；不得输出 traceback、绝对源码路径、SQL、数据库 URL 或原始财务数据。
